# data-store（L2 / Rust）

已实现固定版本日线扫描、累积分区合并/核对/读取、内置数据类型与标准表编码、来源端口、分钟时段绑定和固定资料的身份目录构造。目录查询、导入、预览和采集等应用编排在 Rust `services/data`；同步发布、覆盖/质量报告及研究准备仍有 Python 实现。当前范围不代表整个数据领域完成。

## 累积分区

`merge(store, MergeRequest)` 在调用方的发布事务内执行（数据库锁与父版本查询由调用方负责）。`futures.daily`、`futures.calendar` 按月分区，`futures.minute` 按交易日分区；其他类型拒绝。规则：同一主键按来源观测时间择新；更早的观测计入 `stale_ignored` 不回滚；观测时间相同而内容不同则拒绝；未返回的行不删除；未触及的分区按引用复用，不重写。日历类型另外按父版本缺口与新观测日期更新 `coverage_gaps`。

分区值只允许字符串、整数和空值（`Cell`）。写出时每列按值确定类型：全空为 Null，整数为 Int64，文本为 Utf8，同列混用即拒绝；Snappy 压缩。这与此前 pyarrow 写出的分区类型一致，新旧分区可互读。父版本分区的字段集合必须与本次采集完全一致。

分区文件按内容寻址写入 `artifacts/<sha256>.parquet`，索引写入 `datasets/<任务>/partitions/<sha256>.json`，均经 L1 `ArtifactStore` 一次写入；过期的旧尝试只会产生新文件，不会改写已提交版本引用的字节。结果中的 `metrics` 报告本次实际解码的旧分区键与字节数，不写入版本清单。

`read_index` 要求索引工件与版本记录的 `partitions` 完全一致；`read_partition` 按记录的摘要与大小核验后整体解码；`verify_version` 流式核验索引与全部分区字节而不解码。备份核验使用只读授权（`ArtifactStore::reader`）。

## 日线扫描


`DailyScan` 从 L1 `ReadRoot` 获得受限只读句柄。清单与选中文件以同一描述符校验 SHA-256，按清单顺序、文件原行序读取；请求列后附合约身份与来源证据。按分区日期和有效行组统计裁剪，缺失统计时解码后筛选。身份目录只构建一次，调用 instrument-catalog 的唯一解析实现。金额等原列保持 Arrow 类型与精度，数据批次不经过 JSON 或 Python 逐行循环。

绑定使用官方 `arrow-pyarrow` 的安全 Arrow C Data 接口。读取和筛选释放 GIL；每批前后检查固定存储、插件和任务生命周期，失败、完成或显式 `close()` 均释放读取句柄；未开始的迭代器也能关闭。取消标志在校验读取和批次筛选过程中检查。调用者保留已返回 Arrow 批次时，其缓冲区仍由调用者拥有。

预算：请求 1–4096 行/批、1–30 列、1–1000 合约；元数据 JSON 64 MiB、分区索引 16 MiB、默认文件授权 1 GiB、Parquet footer 8 MiB、128 列、10000 行组/分区、声明行数 1 亿；每个声明行组、单次读取和返回批次 64 MiB，字符串值 64 KiB。支持当前产物使用的 Snappy 与无压缩；超限或未知格式明确失败。Arrow/Parquet 第三方解码器不是恶意文件的分配器沙箱，这些预算不承诺进程 RSS 上限。

`metrics()` 仅报告实际行为：打开的数据文件数、已开始解码的行组数、已解码行数、完成校验的压缩文件与索引字节数、关闭状态。完整校验仍须读取全部选中文件；裁剪节省解码工作，不消除校验 I/O。尚无生产吞吐、峰值内存或 p95/p99 提速结论。

L1 新端口只提供 `open_file / len / check / read_at / verify_sha256`，没有 Arrow 或期货语义，也不向 Python 暴露裸描述符。前后 inode、内容元数据和目录项检查拒绝观察到的替换/变化，不宣称提供原子文件系统快照。
