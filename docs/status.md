# 现状与下一步

## 已可用

| 模块 | 状态 |
| --- | --- |
| 桌面链路 | Electron + Node-API + C++ 编排，启动检查、自动升级、设置窗口、中英文 |
| 实时行情 | CTP 全市场目录与订阅、期货全景、自选、五档、分时、分钟 K 线、1 分钟涨速、增量同步 |
| 历史数据 | Tushare 分钟线与日线下载、分页图表（均线、MACD） |
| 模拟交易 | 单合约账本、历史撮合、交易前限额、手动结算、崩溃恢复 |
| 研究 | 持久化任务、SMA 回测、动量因子评价、数据发布、结算表 |
| 策略 | 可信 SMA 策略宿主、授权交接、重启重放 |
| 服务管理 | 本机 launchd Agent、远程 Linux SSH 引导与 mTLS、健康监督、自动升级 |

## 已知限制

- 界面不能新建成交数据集：历史数据只来自数据源，而目前接入的数据源（CTP 实时、Tushare K 线）都不产生逐笔成交数据集。模拟交易、回测和因子只能使用已有的发布版本。
- 实盘交易未开放；CTP 交易插件没有接入授权与风控链。
- 账本是单合约、单币种；没有组合账户和跨品种风险。
- 没有交易所规则库：保证金、手续费由用户填写；没有自动日终结算和跨日续接。
- 分钟线只来自行情服务运行期间的观测，服务重启后从头开始；不是历史分钟档案。
- 回测和因子只支持单合约、最多 10000 笔成交；下载的 K 线尚不进入回测。
- 期货全景的境外行情、指数行情条、金融期货基差没有数据源。
- `Decimal` 范围约 ±922 亿，足够单账户，不适合累计成交额等大数。
- Terminal 命令共用一把操作锁，长时间的部署操作会阻塞其他命令。
- 本机 launchd 之外的系统服务、多物理机器网络只在容器和回环环境验证过。

## 下一步

1. **成交数据来源**：行情服务把 CTP 实时成交按合约录制成可发布的数据集。
2. **界面**：统一为极简、科技感、未来感的视觉语言（见 [终端界面](terminal.md)）。
3. **编排层**：按领域拆分 Terminal 命令与锁，只读查询全部移出操作锁。
4. **组合账本**：多合约账户、组合保证金与风险，回测和模拟共用。
5. **交易所规则**：交易日历、保证金率、手续费、自动结算与跨日续接。
6. **实盘**：授权、账户风控、CTP 回报与恢复，完整执行链验收后再开放。
