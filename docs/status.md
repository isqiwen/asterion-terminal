## 已知限制

- 历史数据只来自数据源，生产历史插件目前只有 Tushare。已支持具名固定版本的数据组合和显式跨下载拼接；已支持手动预览增量及原范围重取缺口，尚无定时自动更新及依赖清理；覆盖核对只比较整日缺口，不证明日内完整性。
- 动态 ABI 已接入历史数据、连接验证和订单限额风控；策略、存储、CTP/执行和分析工具仍为静态 C++ 插件，仅按具体扩展需求迁移。远程插件配置界面、多风控组合及任意风控配置编辑器未开放。
- 实盘只有限价单，风控为订单限额加价格检查（每笔委托查询一次行情，约多等 1 秒）；只在测试用 CTP SDK 替身上验证，未在真实券商或仿真环境验证。
- 组合账户只支持单币种，保证金按合约相加，没有跨品种保证金优惠或相关性风险；普通组合内合约必须覆盖共同交易日；主力连续的月份可只覆盖其交易区间，无当日结算价的月份必须无持仓。
- 没有交易所规则库：回测的保证金和手续费由用户填写或从费率模板填入（模板可来自实盘账户的券商费率），最小变动价位和合约乘数在有 CTP 合约目录时自动带入；费率按已固定版本的生效日期切换，尚无历史费率自动获取、盘中调整或返佣规则。
- 分钟线只来自行情服务运行期间的观测，服务重启后从头开始；不是历史分钟档案。
- 回测合计最多 200000 根 K 线。因子任务只有一种：一条序列评价单个合约或一个品种的主力连续，3–20 条序列在共有观测上做截面评价（合计同样最多 200000 条）；只有价格动量一种因子，没有分组收益和中性化。
- 期货全景的境外行情、指数行情条、金融期货基差没有数据源。
- `Decimal` 范围约 ±922 亿，足够单账户，不适合累计成交额等大数。
- 节点管理操作（SSH、上传、部署和升级）显式串行接纳；Native 状态与 I/O owner 在等待时仍推进查询和账户控制。批量读取、响应编码、管理工作各有固定容量。已验证最大 20 万条因子输入和 Native 3 万条数据选择/提交的资源占用；未测量多账户真实回报峰值、物理内存压力或全节点同时满载，不承诺硬 RSS 上限或未定义的吞吐目标。
- Linux 桌面（2026-10-09 起）在 Debian 13 / GNOME X11 上完成构建、全部 C++ 测试、原生 Electron 宿主测试、真实 systemd 用户服务验收和 Debian 包的解包验收，见[整改记录](reviews/audit-progress.md)；Debian 包未签名，真实安装只在 Ubuntu 26.04 容器中验证过（没有图形会话和用户服务管理器）；Wayland、其它发行版和桌面环境未验证。
- Linux 当前构建与回归基线为 Ubuntu 24.04 x86_64。真实 SSH/SFTP、systemd 和隔离虚拟机器重启已有注明程序基线的验收记录；物理节点、宿主内核/物理整机重启与多机器网络未验收。macOS 本机 launchd 已完成隔离的升级与恢复测试。
- 每个任务服务最多接纳 1,000 个活动任务，完成、失败或取消后释放活动名额，保留历史记录、固定输入和结果。Data 私有授权目录包含已提交下载的供应商令牌，Task 不保管令牌；冷备份必须包含固定配对的两份服务目录及其依赖。管理员文件级冷备份已通过隔离副本的原路径恢复验收；没有在线备份、自动依赖收集或跨路径恢复接口。见[下载凭据](market-data.md#下载凭据)与[任务管理](tasks.md)。

具体架构实施、源码指纹、通过的测试与未验证范围以[架构实施进度](reviews/architecture-implementation.md)和[整改记录](reviews/audit-progress.md)为准；阶段通过不代表完整发行验收完成。

## 下一步

[已授权架构改造](reviews/architecture-implementation.md)已完成本轮实现与隔离验收。当前 macOS 测试 DMG 的安装副本桌面验收及 Linux 服务包校验通过；以下真实环境与正式交付验收仍是独立要求，排在新功能之前。

1. **券商仿真验收**：按 [验收清单](acceptance/ctp-simulation.md) 用提供商的仿真账户核对登录、结算确认、报单、撤单、成交回报、未确认委托核实和断线恢复；SDK 替身通过不等于此项通过。需要账户持有人在本机操作。
2. **持续集成保持通过**：以 GitHub CI（Linux GCC/sanitizer 与 macOS）为完成标准，本机 Clang 通过不算完成。
3. **持续运行**：在仿真环境跨交易日运行，记录重连、授权与策略运行的延续、服务重启和账本恢复结果。
4. **交付验证**：在真实 Linux x86_64 节点验证部署、升级和恢复；macOS 完成开发者签名与公证。
5. **因子数据管线**：K 线与日线已共用一种因子任务、输入输出和分步计算（特征、未来收益标签、分段、只用前段选窗口、评价），并支持多合约的截面评价，见 [因子分析](factors.md)。尚未实现：更多因子、在训练段上拟合并固定的预处理、分组收益，以及分块读取。
6. **策略接入 CTP 账户**：与回测相同的四条规则（多空、只做多或只做空）已能在已授权的 CTP 账户上运行（账户级独占、跨断线与交易日延续、停止时撤销策略挂单，见 [交易](trading.md) 的“策略运行”），只在测试用 CTP SDK 替身上验证过。下一步在仿真柜台（如 SimNow）实测整个交易时段；之后再考虑用历史数据预热、1 分钟以外的周期和更多策略。

历史数据的引用检查保持现有范围（各数据服务、本窗口选择），在开放物理删除之前不再扩展；删除前一致性检查留到删除功能立项时一起设计。
