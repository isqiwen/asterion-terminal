# 当前能力与限制

Terminal、Market、Warehouse、Lab 与 Trading 已打通行情、历史数据管理、策略研究与实盘账户执行的全流程。真实数据源核验、正式部署与长周期仿真验收按[开发计划](plan.md)推进。

## 当前能力

| 应用 | 使用者可以做什么 |
| --- | --- |
| [Terminal](terminal/README.md) | 在 macOS（Apple Silicon）或 Linux x86_64 上看盘、编写策略与因子、运行研究、管理历史数据与交易账户；支持简体中文与英文 |
| [Market](market/README.md) | 接收 CTP 实时行情与合约目录，向多个 Terminal 分发 |
| [Warehouse](warehouse/README.md) | 采集并融合多源历史行情、交易参数与期货基本面（仓单、会员持仓、库存周报），统计覆盖并发布不可变固定版本数据集 |
| [Lab](lab/README.md) | 基于固定数据版本与冻结源码运行日线/分钟回测、参数扫描、滚动验证、因子评价、防过拟合诊断与实盘回测对账，并比较与复现研究记录 |
| [Trading](trading/README.md) | 发布策略包、启停与热重启策略实例、现场预热、授权交易、手动下单、暂停新增、平仓与脱机告警；独立于 Terminal、Lab、Market 和 Warehouse 运行 |

## 当前限制

- **部署与客户端平台**：Market、Warehouse、Trading 仅部署于 Linux x86_64；无 Web、移动端、Windows 或独立 CLI 客户端。
- **数据源边界**：仅接受真实数据源。客户端只消费单一统一数据集，来源选择与补缺全部留在 Warehouse 内部。
- **回测与因子模型**：回测与因子评价均支持日线与分钟线。多空保证金率与手续费取固定数据集中的交易所每日结算参数（平今费率缺失时仅在当日产生平今成交时报错停止），滑点、风控限额与权重预算由运行配置提供；日线涨跌停价双侧齐全时启用封板撮合约束，仅缺一侧时报错，双侧均缺失时不施加该约束。暂不建模盘口排队与冲击成本，组合按单币种核算。
- **历史最小变动价位**：由 Warehouse 内置的六家交易所生效区间表提供（见[历史最小变动价位](warehouse/README.md#历史最小变动价位)），公开来源用于增量核验新品种与规则变更；参数缺失或冲突的区间禁止回测，因子评价不依赖该参数。
- **交易执行范围**：Trading 仅发送限价单，每个账户同时运行一个策略实例；支持固定月份合约、主力自动换月与跨时段组合，单策略与组合的连续仿真验收见[开发计划](plan.md#真实验收)。
- **不完整 K 线处理**：回测与历史预热排除含缺失分钟的 K 线；Trading 按品种交易时段聚合实时行情，跳过启动首根及受断线或累计成交量回退影响的 K 线，详见[实时 K 线与现场预热](trading/README.md#实时-k-线与现场预热)。
- **授权与未确认委托**：Trading 重启后必须重新授权；结果不明的委托不自动重发，须由使用者在柜台核实，详见[交易规则](safety.md)。

后续推进与真实验收条件见[开发计划](plan.md)，冷备与恢复见[服务与部署](services.md#备份与恢复)。
