## 已知限制

- 历史数据只来自数据源，生产历史插件目前只有 Tushare。已支持具名固定版本的数据组合和显式跨下载拼接；已支持手动预览增量及原范围重取缺口，尚无定时自动更新及依赖清理；覆盖核对只比较整日缺口，不证明日内完整性。
- 2026-10-15：分钟版本可按供应商交易日检查记录数、首末时间和未知归属计数；缺少交易日标记时不生成整日补齐计划。首尾交易日覆盖与日内完整性仍明确标为未验证，不能按固定根数判完整。
- 按合约的日线下载已移除；日线图表、回测、因子和覆盖核对统一读取全市场日线表。旧下载任务只保留摘要、不执行或读取结果；旧日线档案计为不支持读取，原文件保留。当前改造的验证进度见整改记录。
- 历史行情支持“分钟档案”和“日线合约”两个入口。日线按交易所、品种、月份选择固定快照中的合约，不依赖分钟下载或实时 CTP 目录；合约目录不代表行情覆盖完整。图表与目录使用同一快照，支持日、周、月、季、年周期。F13 的实时/历史连续拼接与日内质量证据仍待实现。
- 回测按笔统计使用账户实际费用，展示闭合交易的毛盈亏、手续费和净盈亏，未闭合持仓费用单列。已提供按实际合约的已平仓贡献，以及按月的账户净盈亏、费用和可相加的总收益率贡献。结果校验拒绝读取缺少费用证据的结果并保留文件；精确持有期、含未平仓部分的合约总收益归因和换月成本分解仍待补齐。按月功能的验证范围见[交付记录](reviews/backtest-monthly-contributions-2026-10-15.md)。
- 全市场数据表只读已经结束的交易日；不含大商所月均价期货等统一合约身份还表示不了的合约；没有对已入库分区的重新取数、定时更新和删除。数据源并非每张表都有全部历史（结算参数、仓单日报、排名在部分交易所只有近几年的数据，能源中心没有原油的排名），数据源没有的交易日一直算作缺少，每次按起始日期补齐都会再问一遍。
- 结算参数按数据源发布的口径保存，各交易所单位不同；郑商所、大商所、广期所、中金所的手续费只有一个数，数据里没有说明它是每手金额还是成交额比例，所以这张表目前只能直接给出保证金率，不能单独给出这四家的手续费。
- 动态 ABI 已接入历史数据、连接验证和订单限额风控；策略、存储、CTP/执行和分析工具仍为静态 C++ 插件，仅按具体扩展需求迁移。远程插件配置界面、多风控组合及任意风控配置编辑器未开放。
- 实盘只有限价单，风控为订单限额加价格检查（每笔委托查询一次行情，约多等 1 秒）；只在测试用 CTP SDK 替身上验证，未在真实券商或仿真环境验证。
- 组合账户只支持单币种，保证金按合约相加，没有跨品种保证金优惠或相关性风险；普通组合内合约必须覆盖共同交易日（有结算价的交易日，当天有没有 K 线都算）；主力连续的月份可只覆盖其交易区间，无当日结算价的月份必须无持仓。
- 没有交易所规则库：回测的保证金和手续费由用户填写或从费率模板填入（模板可来自实盘账户的券商费率）；费率按已固定版本的生效日期切换，尚无历史费率自动获取、盘中调整或返佣规则。合约乘数取自合约表，用日线表的成交额核对，交易单位改过的旧合约（2018 年以前的燃料油等）被拒绝；最小变动价位按交易日从成交价推出（见[合约单位](market-data.md#合约单位)），不是交易所公告，一个品种新旧合约同一天按不同价位交易时得到的是两者的公约数。
- 回测没有涨跌停：数据源不提供涨跌停价和幅度，封板日回测仍会在涨停价成交买单、在跌停价成交卖单。待办：每个合约可填涨跌停幅度，按“昨结算价 ×（1 ± 幅度）”得到涨跌停价，在涨停价不成交买单、跌停价不成交卖单；维护者决定先用真实数据开始研究，结果里出现封板日的成交时再做。
- 分钟线只来自行情服务运行期间的观测，服务重启后从头开始；不是历史分钟档案。
- 回测合计最多 200000 根 K 线。因子任务只有一种：一条序列评价单个合约或一个品种的主力连续，3–100 条序列做截面评价，每个观测上比较当时有数据的序列（合计同样最多 200000 条）；只有价格动量、期限结构和波动率三种因子；截面评价给出每侧 K 个的分组收益（等权、不含成本），没有中性化。各段的均值对截面等权、不按参与的序列数加权；不活跃的品种不会自动排除。从全市场数据表读多个品种时，成立晚于起始日期的交易所从它第一个上市日起读取；读不出的品种让任务被拒绝，但一次全部列出，需要手工移除。十年范围的真实核对里 89 个品种读成功 88 个，共 167,582 个收盘价，已接近一个任务 200000 个的上限。
- 期货全景的境外行情、指数行情条、金融期货基差没有数据源。
- `Decimal` 范围约 ±922 亿，足够单账户，不适合累计成交额等大数。
- 节点管理操作（SSH、上传、部署和升级）显式串行接纳；Native 状态与 I/O owner 在等待时仍推进查询和账户控制。批量读取、响应编码、管理工作各有固定容量。已验证最大 20 万条因子输入和 Native 3 万条数据选择/提交的资源占用；未测量多账户真实回报峰值、物理内存压力或全节点同时满载，不承诺硬 RSS 上限或未定义的吞吐目标。
- Linux 桌面（2026-10-09 起）在 Debian 13 / GNOME X11 上完成构建、全部 C++ 测试、原生 Electron 宿主测试、真实 systemd 用户服务验收和 Debian 包的解包验收，见[整改记录](reviews/audit-progress.md)；Debian 包未签名，真实安装只在 Ubuntu 26.04 容器中验证过（没有图形会话和用户服务管理器）。2026-10-11 在 Ubuntu 26.04 / GNOME Wayland（GCC 15）上完成构建、Debug 与 Release 的全部 C++ 测试、Electron 宿主测试、全量端到端和 Debian 包的解包验收；在那里没有做真实 systemd 用户服务验收和 `dpkg` 安装。其它发行版和桌面环境未验证。
- Linux 当前构建与回归基线为 Ubuntu 24.04 x86_64。真实 SSH/SFTP、systemd 和隔离虚拟机器重启已有注明程序基线的验收记录；物理节点、宿主内核/物理整机重启与多机器网络未验收。macOS 本机 launchd 已完成隔离的升级与恢复测试。
- 每个任务服务最多接纳 1,000 个活动任务，完成、失败或取消后释放活动名额，保留历史记录、固定输入和结果。Data 私有授权目录包含已提交下载的供应商令牌，Task 不保管令牌；冷备份必须包含固定配对的两份服务目录及其依赖。管理员文件级冷备份已通过隔离副本的原路径恢复验收；没有在线备份、自动依赖收集或跨路径恢复接口。见[下载凭据](market-data.md#下载凭据)与[任务管理](tasks.md)。

具体架构实施、源码指纹、通过的测试与未验证范围以[架构实施进度](reviews/architecture-implementation.md)和[整改记录](reviews/audit-progress.md)为准；阶段通过不代表完整发行验收完成。

## 下一步

[已授权架构改造](reviews/architecture-implementation.md)已完成本轮实现与隔离验收。当前 macOS 测试 DMG 的安装副本桌面验收及 Linux 服务包校验通过；后续按[功能评估](reviews/functional-completeness-2026-10-14.md)继续研究优先的功能迭代；以下真实环境与正式交付验收是对应使用阶段的独立要求。

1. **券商仿真验收**：按 [验收清单](acceptance/ctp-simulation.md) 用提供商的仿真账户核对登录、结算确认、报单、撤单、成交回报、未确认委托核实和断线恢复；SDK 替身通过不等于此项通过。需要账户持有人在本机操作。
2. **持续集成保持通过**：以 GitHub CI（Linux GCC/sanitizer 与 macOS）为完成标准，本机 Clang 通过不算完成。
3. **持续运行**：在仿真环境跨交易日运行，记录重连、授权与策略运行的延续、服务重启和账本恢复结果。
4. **交付验证**：在真实 Linux x86_64 节点验证部署、升级和恢复；macOS 完成开发者签名与公证。
5. **数据层**（[设计](reviews/history-tables-design.md)）：全市场数据表的第 1–3 步已完成（六张表；因子任务读日线表）。因子的截面已按“每个观测用当时有数据的序列”评价。回测和因子的 K 线数据集已从日线表取每个交易日的结算价、主力选月的持仓量和日线周期的 K 线（单个合约，或按品种的主力连续）；分钟线已按返回行数分页（非交易日不再单独请求）。一条主力连续不再受 20 个月份的限制（十年的螺纹钢 33 个月份、铜 128 个都可以回测）。全市场十年的截面评价可以一次提交（成立晚的交易所从它的第一个上市日读起，读不出的品种一次列出）。要交易的主力连续最迟在月份的最后交易日换下，换月的两条腿按开盘价成交：股指期货可以回测十年。数据集的交易日是合约有结算价的每一天，没有 K 线的交易日（停牌、没有成交）持仓照常结算，主力月份不因当天没有成交而换下：沪镍可以回测过 2022 年 3 月。合约乘数和最小变动价位来自数据（乘数取合约表、用成交额核对；最小变动价位按交易日从成交价推出，黄金、塑料等 9 个品种十年里改过）：89 个品种里 75 个读得出十年的日线主力连续。接下来依次是：保证金率来自数据（结算参数表要先补齐历史，约一万五千次请求；手续费还需要“各品种按哪种方式收费”的来源）；分钟线按交易日记完整性、下载范围按交易日起算。
6. **因子数据管线**：K 线与日线已共用一种因子任务、输入输出和分步计算（特征、未来收益标签、分段、只用前段选窗口、评价），并支持多合约的截面评价，见 [因子分析](factors.md)。截面评价已给出分组收益，因子有价格动量、期限结构和波动率三种。尚未实现：更多因子（偏度、持仓量变化等）、在训练段上拟合并固定的预处理，以及分块读取。
7. **策略接入 CTP 账户**：与回测相同的四条规则（多空、只做多或只做空）已能在已授权的 CTP 账户上运行（账户级独占、跨断线与交易日延续、停止时撤销策略挂单，见 [交易](trading.md) 的“策略运行”），只在测试用 CTP SDK 替身上验证过。下一步在仿真柜台（如 SimNow）实测整个交易时段；之后再考虑用历史数据预热、1 分钟以外的周期和更多策略。

历史数据的引用检查保持现有范围（各数据服务、本窗口选择），在开放物理删除之前不再扩展；删除前一致性检查留到删除功能立项时一起设计。

## 2026-10-15：F06 按合约已平仓贡献

回测结果按实际月份合约汇总已闭合交易轮次的笔数、毛盈亏、账户实际手续费和净盈亏，复用当前统计插件的 Decimal 结果，不新建账本或改写任务。未闭合持仓的费用仍单列，不把已平仓贡献当作账户总收益。持有期需要先补齐成交时间证据；按时间段归因与换月成本解释仍待实现。当前验证见 [整改进度](reviews/audit-progress.md)。

## 2026-10-15：F04 日线因子流动性筛选

至少 3 个品种/合约的全市场日线截面可显式开启历史流动性筛选，固定此前连续观测数量和上一观测成交/持仓量阈值。每日资格与排除原因保存到结果；候选选参、IC 和分组收益按资格筛选完整评价成员，暂时不合资格不截断价格预热。界面可逐日区分资格与实际评价人数，输入和结果按当前结构核验；详细口径和未覆盖的历史发布证据、动态回测退出持仓语义见 [因子文档](factors.md#f04-日线截面产品接入2026-10-15)。

## 2026-10-15：F05 日线因子显式复用首批

当前兼容的日线因子结果可按原参数创建独立新任务；用户必须选择原固定快照或当前服务明确展示的快照。原固定数据重新解析后须与原 revision 一致，原结果身份及参数在复用前重新核对；不一致、不支持或数据缺失时拒绝，原实验不变。固定与新修订路径已通过真实隔离链路核验。回测复用、参数编辑、名称备注、少量实验并排比较及导出仍未实现，F05 整项不宣告完成。
