# 数据规范、文件导入与连接实例

本文记录历史数据的文件导入与数据源连接契约。当前导入、来源连接和配置由 Rust `services/data` 实现，HTTP 入口在 `services/server`；Tushare 为顶层 `adapters/provider-tushare` 的内置 Rust 实现。实时连接的状态语义由固定 L2 `connections` 管理，历史与实时连接尚未合并。见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。

## 统一语义与来源边界

文件导入已由 Rust 实现（2026-09-25）：字段映射、校验、标准表与图表写入在 [imports.rs](../services/data/src/imports.rs)，数据类型与表格编码在 L2 `kernel/futures/data-store`；入口提供 `/imports`、`/imports/preview`、`/snapshots` 与图表接口，并自行执行导入任务（按任务类型领取，内部 worker 不领取导入任务），发布在持有租约的同一事务内登记 RAW/STANDARD 版本与图表快照，失败时任务以原因失败、不留下版本。集合与版本标识沿用 `json.dumps(sort_keys=True)` 规范文本的 UUIDv5，已有数据集保持同一标识。API 同步准入与采集已为 Rust，发布仍在 Python。文件导入和 API 同步共用数据类型注册表、校验器、RAW / STANDARD 目录和不可变版本。`source` 是获取通道或内置来源；`origin` 保存获取方式、来源名称、来源标识或连接实例。文件来源名称是用户声明，系统不将其当作供应商认证证据。

数据集身份包含类型、来源、范围、模式版本、频率。具名 API 连接将 `connection_id` 纳入范围；新文件导入将 `source_id`、合约集合与频率纳入范围。因此同名来源不会跨连接覆盖，不同频率不会被合并。文件来源标识稳定时，修改显示说明不会新建数据集。原文件、映射配置、校验后的标准数据都可追溯。

当前不会自动合并多个供应商，也不会将文件数据覆盖到某供应商的日线中。跨源补齐与冲突裁决需要独立的派生数据集协议，尚未实现。

## 已实现的 CSV 规范

以下CSV仅展示字段格式，不提供可执行身份/时段依据；实际导入还须选择固定目录及适用版本。UTF-8 CSV，可带 BOM；最大 2 MB。拒绝重复/空表头、列数不一致、重复主键及无效数值。额外文件列保留在原文件中，不自动成为标准字段。支持显式字段映射，或对同名标准列自动匹配。

### 期货日线 `futures.daily`

频率必须为 `1d`，一次文件限定一个实际合约。

```csv
contract,trading_day,open,high,low,close,vol,amount,oi,settle
SHFE.rb2610,2026-01-05,3200,3220,3190,3210,100,,,3205
```

必填字段为 `contract,trading_day,open,high,low,close,vol`。`amount`、`oi`、`settle` 可为空；`settle` 为元计的结算价，逐日结算研究必须提供有效值，不用收盘价补齐。合约采用 `交易所.合约代码`，交易所与合约代码由标准标识拆出。交易日规范化为 YYYY-MM-DD。价格单位元、成交量和持仓量单位手、成交额单位万元；目前不自动换算外部口径。日线价格必须满足现有图表的有限正数和精度约束。

与接口日线共用 `futures.daily` 类型，按 `(contract,trading_day)` 校验唯一性。文件当前发布为采集范围版本，不累积拼接；接口日线仍保持既有累积语义。

日线日期不是事件时间。图表使用交易日标签；本次任务提交时间作为本次可获知时间，不证明历史可用性，不得据此声称无前视偏差。

### 带时间的 K 线 `futures.bars`

```csv
contract,event_time,available_at,trading_day,open,high,low,close,volume
SHFE.rb2610,2026-01-05T09:01:00+08:00,2026-01-05T09:01:01+08:00,2026-01-05,3200,3220,3190,3210,100
```

交易日列可省略，由时间版本推导；提供时须一致。其余字段必填，时间携带时区；`available_at` 不早于 `event_time`；事件时间精确到秒。按 `(contract,event_time)` 校验唯一性。新导入必须声明 `1m/5m/15m/30m/1h` 和 K 线开始/结束时间戳口径；校验单条 K 线不跨时段，但不据此证明全天行情齐全。日线请使用专用日线类型。

所有导入请求和任务必须携带 `options`，其中 `identity` 必须包含完整目录、内容指纹、信息截止时间和每个文件代码的显式来源映射。缺少规范的输入明确拒绝，不推断旧数据的类型、频率或来源身份。

## 导入操作

选择类型 → 下载模板或选择文件 → 填写稳定来源标识与说明 → 识别字段 → 调整映射 → 预览校验 → 提交任务。

预览最多显示 10 行，但校验整个文件。预览不创建任务；提交、worker 执行和发布重新按相同规范验证。修改任何输入后，界面要求重新预览。字段映射可按类型保存在本机浏览器配置中，不包含数据源凭据。当前每个类型保存一份映射，尚非可共享的模板库。

入口：`POST /api/v1/imports/preview`、`POST /api/v1/imports`。请求的 `options` 包含 `identity,type_id,frequency,source_id,column_mapping`，日内还须提供时间版本及时间戳口径；映射方向为标准字段到文件列名。

## 插件与连接实例

供应商插件负责协议、配置规范、采集与标准化；连接实例负责名称和独立配置。通过设置中的“新增连接”创建同一插件的多个实例，随后在同步页选择连接。

每个内置插件提供一个默认连接；具名连接 ID 为服务器生成的 `c_...`。这些数据源连接使用修订配置与加密快照。新连接不继承其他连接的凭据。

`POST /api/v1/data/connections` 创建实例；现有配置接口中的标识支持默认插件 ID 与连接 ID。同步请求仍使用真实 `provider` 插件 ID，并可带 `connection_id`。服务端验证二者匹配；任务固定实例配置快照，后续修改配置不影响既有任务。快照绑定连接 ID，不能跨连接借用；缺少实例快照时不能回退默认凭据。

同步日线覆盖核对自动查找同连接的参考版本；显式指定其他连接的参考也会拒绝。缺口补齐继续使用原连接，避免意外切换账户或权限。

当前支持新增、配置、测试、重命名、停用、归档、恢复及查询连接。删除及凭据快照回收尚未实现。合约资料、日历、逐笔数据的文件导入映射，单位换算、自动跨来源代码映射及多源派生数据集属于后续扩展，不由当前 CSV 导入隐式完成。

## 连接状态和验证记录

连接名称和状态使用独立修订号，变更支持 CAS 并发检查。停用/归档阻止新的同步、重试及补齐提交，但保留已有任务、固定配置快照和数据；同一 command_id 的原请求重放仍返回原任务。归档连接默认从设置列表隐藏，可勾选“显示归档连接”恢复。同步页只列出启用连接；旧数据仍可按归档连接筛选。

连接、配置与验证记录由 Rust 数据服务（`services/data` 的 connections、configuration、credentials）实现，入口直接提供 `/data/providers`、`/data/connections` 及配置读取、保存、测试和验证接口；来源探测在数据库事务之外执行。尚在 Python 的同步流水线经绑定调用同一实现固定和读取配置。“测试当前配置”仅验证草稿，不写已保存配置验证记录。“验证已保存配置”记录对应配置修订、成功/失败与时间；配置变化后显示过期。同一连接的并发验证按请求开始时间排序，较早请求的迟到结果不会覆盖新结果。验证记录只存结构化状态，不存凭据或提供方原始异常。Tushare 当前探测交易日历接口，不代表所有接口均有权限；历史验证成功也不是实时连接保证。

## 产品入口与数据详情

“数据同步”只列出真实数据源连接，工具栏独立“导入数据”按钮进入文件导入，支持返回同步。数据集详情集中展示来源连接、频率、范围、覆盖说明、结构校验、固定版本与采集任务，可展开 API 采集分段记录并追溯原始版本。覆盖未核对、仅返回数据和已结构校验不能替代完整性结论。

本地日线可在数据集详情或研究页显式关联已同步的固定日历和合约资料，填写关联说明后核对。报告保留外部依据来源，不改写文件数据来源；通过后支持严格模式回测。缺口须修正文件后重新导入，不自动跨源补齐。详见 [本地回测](local-backtesting.md)。

日内导入必须选择 [交易时间版本](trading-time.md)，明确频率和时间戳表示 K 线开始还是结束。完整区间必须落在同一连续交易时段，交易日与归属结果须一致。日线导入可绑定时间版本校验日期；研究时绑定为必需。

## 固定实际合约身份

文件日线用于研究前，必须显式选择固定日历、合约资料、参考来源的完整合约代码及关联说明。覆盖报告冻结目录身份；不会自动按大小写、后缀或月份猜测文件代码与来源代码的关系。文件发布现已强制绑定完整身份目录和显式代码映射；覆盖必须与导入时的实际身份一致。

导入前先在“合约资料 → 合约目录”发布资料目录，再在导入表单选择该固定版本，填写文件代码并选择明确对应的目录来源代码。每个文件代码只能映射一次；多代码的日内文件逐项添加映射。目录、代码关联或 CSV 改变后必须重新预览，未完成身份选择不能提交。原始 CSV 保留，身份信息保存到版本清单；数据集范围包含解析得到的实际合约 ID，不合并复用代码下的不同生命周期。
