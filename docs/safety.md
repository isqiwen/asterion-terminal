# 交易安全契约

本文规定任何能产生委托的路径都必须遵守的不变量，适用于手动下单和策略运行，适用于柜台仿真和实盘。
回测使用同样的风控语义，但不涉及授权与柜台。实现可以替换，规则不变；修改规则需要使用者明确决定，并在本文中修改。
当前实现细节见[交易与风控](trading.md)。2026-11-01 确认自主交易与现场预热设计；本契约包含尚待实现的目标约束，不能据此声称已完成安全验收。

## 1. 唯一执行路径

- 每个 CTP 账户由一个交易进程拥有：授权、风险占用、交易记录和柜台连接都只在这里。
- 每笔委托按同一顺序检查：授权有效且账户已同步 → 合约在可交易清单内，数量和价格在最小单位上 →
  用当前柜台行情做价格检查 → 内置风控 → 写入交易记录 → 一次性发送许可 → 调用柜台。任何一步失败都不发送。
- 界面、策略、研究服务和管理进程都不能绕过这条路径调用柜台。
- 同一个外部资金账户在任何时刻只能有一个执行者。

## 2. 授权

- 行情已连接、账户已登录都不等于可以交易；发送委托需要在该账户上显式授权。
- 授权只存在于交易进程内存中。交易服务重启、修改风控政策、交易记录需要恢复时授权失效；使用者可以随时撤销，未连接时也可以。
- 研究结论、仿真成功或过去的授权都不能代替本次授权。
- 柜台环境是仿真还是实盘由使用者确认；程序无法证明资金性质。

## 3. 风控

- 每个账户必须配置风险限额：单笔数量、每个合约的潜在总持仓、在途委托数和价格偏离。缺少或无效配置时拒绝执行。
- 限额由使用者填写，软件不预填可交易的默认值。
- 风险占用按柜台持仓、柜台未成交的开仓委托和尚未确认的委托合计；多空不相互抵消。
- 超限时仍允许减仓。风控拒绝不自动改量、改价或重试。
- 策略自己的预算、止损和仓位上限只能比账户限额更严，不能放宽账户限额。

## 4. 记录与重发

- 委托和撤单都先持久写入交易记录，写入成功后才发送；写入失败就不发送。
- 断线、超时、进程重启和结果不明都不会触发自动重发。同一请求编号重复提交只确认原记录。
- 结果不明的委托标为“未确认”，继续占用风险额度，直到使用者在柜台核实并显式标记；换日不会自动释放。
- 撤单请求被受理不等于已经撤单；以柜台回报为准。

## 5. 交易事实

- 提交意图、柜台受理、成交和撤销是不同的事实。资金、持仓和成交以柜台回报为准。
- 重复回报不能重复计算成交和资金；互相冲突的回报明确拒绝。
- 关闭窗口、断开连接或停止服务都不代表撤单，也不代表平仓。
- 已授权策略由交易主机自主运行。Terminal 关闭或监控端断线不停止策略、不撤销授权、不撤单、不平仓，也不因桌面失联暂停新增交易。显式控制命令与关闭窗口严格区分；交易主机独立执行风控并记录故障与告警。

## 6. 策略

- 策略包由 Terminal 发布到交易主机，由 Trading 加载已部署版本并管理独立策略子进程。策略不读取开发机器源码，不经 Terminal/Lab/Market 转发执行目标，也不持有交易凭据。
- 每次实例启动只使用启动后实际接收的实时数据现场预热；不读启动前历史或旧窗口，不要求提供预热数据。启动时不完整 K 线不参与；策略按实际参数与状态报告就绪，账户在就绪前拒绝该实例执行目标。
- 实例重启重新预热不清除账户持仓、未终结委托或未确认风险；就绪不替代账户对账与授权。Trading 重启不恢复授权的规则不变。
- Trading 自己连接执行行情与柜台，按合约身份、交易日、连接状态和时效检查行情。执行行情失效不能继续发送依赖它的委托；撤单和撤销授权仍可用。中心 Market 或 Terminal 失联本身不构成执行行情失效。

- 策略只输出目标仓位或权重，不调用柜台，也不持有发送许可。内核把目标换算成委托，每笔委托都走第 1 节的路径。
- “暂停新增”“停止并撤单”“平仓”是三个不同的动作，各自确认。停止策略不等于平仓。
- 策略失败时，包括异常、进程退出、行情中断、风控拒绝和柜台拒绝，结束该策略的运行，并对它尚未终结的委托各请求一次撤单；
  持仓保留，由使用者决定是否平仓；不自动重启。
- 策略运行期间，同一账户的手动新增委托被拒绝；撤单、撤销授权和停止策略始终可用。
  多策略账户里手动委托如何与策略共存，在成交归属规则确定时一起决定，确定之前保持互斥。
- 一个账户运行多个策略时，由账户层合并目标，并保留每笔成交和费用的归属。归属规则必须确定、可以复算。

## 7. 数值、身份与资料

- 价格、数量和金额使用定点 `Decimal`；展示舍入不改变下单价格、风险判断或账务金额。
- 来源不能唯一识别合约时不下单。连续合约只用于信号，成交始终落在真实月份合约上。
- 未知、缺失和零分别表达，缺失的行情或金额不能显示成零。
- 交易密码和授权码在交易主机本地隐藏输入，按账户保存为 systemd 加密凭据；解密后只用于交易进程，不经 Terminal，不写入日志、普通配置、交易记录、界面存储或聊天。服务重启登录不恢复交易授权。
- Market 的行情密码和授权码只在 Market 主机输入并存为 systemd 加密凭据，Terminal 只保存服务地址和证书指纹；不与 Trading 共用凭据。Market 历史供应商 token 同样由主机以 systemd 加密凭据管理；Terminal 已移除供应商凭据输入、保存及向 Lab 发送的入口，不读取或自动上传原有桌面凭据。
- 不静默改写、迁移或删除交易记录、任务或数据集；删除前说明对象与影响。
- 不伪造行情。生产数据只来自真实来源，夹具只用于测试。

## 8. 实盘前必须完成

真实资金账户第一次发送委托之前，下列各项都要完成并留有验收记录。

| 项目 | 要求 |
| --- | --- |
| 仿真浸泡 | 在 SimNow 上连续运行目标策略两周，每天的成交、持仓和资金与柜台逐笔一致 |
| 穿透式认证 | 通过期货公司的穿透式认证，取得本程序的 AppID 与授权码 |
| 唯一执行 | 同一外部资金账户的两份配置、两个节点并发请求时只有一个执行者；旧节点失联不能被接管，恢复后也不能发送旧意图 |
| 自主运行与监控失联 | 关闭 Terminal、断开桌面网络及停止 Market/Lab，已授权交易继续；交易侧行情/柜台/策略故障独立检测并按本契约处理，告警在主机记录。重连只读取实际状态，不补发目标；Trading 重启仍须重新授权 |
| 成交归属 | 多策略账户的部分成交、费用、人工介入和策略退出都有确定的分配规则，并有守恒算例 |
| 风险基准 | 日内亏损与回撤基准正确处理入金、出金、日切、重启和重新授权；重启不能重选有利基准，也不能丢失暂停状态 |
| 告警与总开关 | 策略停止、委托被拒、未确认委托、连接中断、风控触发和对账不一致都会推送告警；“停止全部策略并撤单”演练通过 |

## 验证

- 当前账户执行规则由交易进程测试在柜台替身上覆盖；本次新增的策略部署、现场预热和自主运行规则须随 M3.1–M3.3 补充验证，尚未验收。替身只能证明软件契约，不能证明真实柜台行为。
- 真实柜台行为按 [CTP 仿真验收](acceptance/ctp-simulation.md) 在仿真柜台核对。
