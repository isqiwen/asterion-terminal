# 日线逐日结算

当前执行器为 `daily-session-settlement.v6`。L2 Rust 插件 `execution` 独占单实际合约日线做多/空仓账户：余额、持仓、手续费、结算、保证金、事件和结果曲线均由它计算。L3 Python `research/engine.py` 只选择策略、传入固定日线、提供收盘意图；服务、worker、研究包和备份复算共用这一账本。此切片不代表完整 F4 实盘账户、订单恢复或独立 `backtest` 应用拆分已完成。见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。

L0 `foundation::decimal` 提供规则和账户共用的有限十进制计算。账户每次运算按 40 位有效数字、half-even 舍入，保留输出比例位、科学计数法和带符号零；不受 Python 全局 Decimal 上下文影响。迁移使用 85 组冻结完整输出与 SHA-256 校验，包含保证金拒单、资金不足平仓、按手/成交额计费及尾随零；当前输出语义和引擎标识保持一致，仓库不保留 Python 第二账本。

每个账户会话须依次完成“输入日线 → 收盘意图”，最多 5,000 根，交易日严格递增并属于所选实际合约。错误或未完成日线不能生成结果。工厂关闭、插件授权撤销或任务资源作用域结束后，已有会话的下一次调用在 Rust 中拒绝执行。

## 输入与固定依据

研究区间的每根标准日线必须带有 `settle`，包括预热日。值必须是有限正数、不超过 1e12，最多八位小数。Tushare 日线直接保留供应商 `settle`；本地日线导入提供同名可选列及列名映射。数据可用于图表而没有结算价，但不能用于逐日结算研究；缺失时明确要求补齐后选择新版本，绝不用收盘价填充。

结算价与 OHLC、来源证据一起冻结并参与输入校验和、重跑、复现包和备份校验。结算价不要求处于 OHLC 范围内。模型从空仓开始，跨日使用上一根固定日线的结算价，不依赖来源 `pre_settle`；探索模式存在交易日缺口时，盈亏跨越缺口，不能推断缺失日期的结算与强平过程。

## 每日资金账

信号仍只接收收盘价，下一根日线开盘执行。昨日持仓先按上次结算价至本日开盘计算开盘权益，开仓资金检查只使用此时已知价格；当日结算价不参与开盘订单决策。成交价包含不利滑点，手续费独立扣减。

- 开仓日：结算盈亏 =（结算价 − 买入成交价）× 手数 × 乘数。
- 继续持有：结算盈亏 =（结算价 − 上次结算价）× 手数 × 乘数。
- 平仓日：结算盈亏 =（卖出成交价 − 上次结算价）× 手数 × 乘数。
- 结算余额 = 期初余额 + 结算盈亏 − 手续费。
- 结算保证金 = 结算价 × 日终持仓 × 乘数 × 当日规则保证金比例。
- 可用资金 = 结算余额 − 结算保证金。保证金是占用，不是损失，不再从权益扣一次。
- 收盘估值差额 =（收盘价 − 结算价）× 日终持仓 × 乘数；收盘权益 = 结算余额 + 收盘估值差额。

结算后的持仓损益已转入余额；收盘估值差额只是另一价格口径的展示，不再次入账。主权益、收益及最大回撤采用每日结算余额；日内回撤不在范围。期末不强制平仓，结算后仍保留持仓及保证金，不预扣将来平仓费用。

结算后保证金不足，下一可执行日线开盘尝试平仓，即使次日开盘恢复资金也执行该模型的平仓意图。开盘跳空引起的保证金不足也触发平仓。不是经纪商实际强平或补资流程。

## 报告与边界

研究界面“每日结算与资金账”列示结算价、期初余额、结算盈亏、手续费、结算余额、收盘估值差额、收盘权益、持仓、保证金和可用资金。结果 ZIP 包含 `settlements.csv`；独立实验、后续区间验证、按原输入重跑与离线复现共用该执行器。

不支持已被替代的执行器，不自动改写历史输入或结果。历史事实保留，不能用新算法冒充原运行。

当前仍是单合约多头/空仓模型，没有平今区分、涨跌停封单、盘中撮合、多合约、换月、交割、出入金或经纪商附加保证金规则。规则版本的生效期间仍由已冻结的规则决定；结算价记账并不证明供应商规则在历史时点已知。

语义依据：[上期所交易规则](https://www.shfe.cn/regulation/exchangerules/rules/202606/t20260603_831934.html)对收盘价与结算价的区分，以及[每日无负债结算制度](https://edu.shfe.com.cn/LearningCorner/FuturesFundamentals/81.html)。本模型只实现上述明确列出的研究范围。
