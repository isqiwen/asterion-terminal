# 行情与数据

本文说明当前实时行情与历史数据能力。`asterion-market-data` 管理实时观测，独立的 `asterion-data-service` 管理历史版本、具名数据集、下载授权及共享额度。`asterion-task-service` 管理执行尝试与计算结果；下载任务的状态、容量和恢复见[任务管理](tasks.md)。

## CTP 实时行情

`asterion-market-data` 通过 `plugins/data/ctp` 连接 CTP 行情前置，只读。

- **连接**：使用行情账户（设置 → CTP 账户里标为“用于行情”的那一个，见下），输入密码和授权码。勾选“保存密码和授权码到本机钥匙串”后连接，可将两者保存在 macOS 钥匙串或 Linux Secret Service 密钥环；后续连接或查询目录时留空即可复用，无需重复输入。可通过“清除已保存的登录凭据”移除。保存的凭据绑定本机环境、账户身份及两个前置地址；修改这些连接信息或删除账户会清除对应凭据，改名不会。行情凭据不用于交易登录。
- **合约目录**：连接行情后用行情账户的交易前置、AppID 和本次输入的授权码自动加载全市场合约并全部订阅；只查询合约，不开通交易。
- **CTP 账户**：期货公司给的柜台信息在「设置 → CTP 账户」填写一次，六项都必填：名称、经纪商代码、投资者账号、AppID、交易前置、行情前置。可以保存多个账户，各自在交易页独立连接和交易；行情只使用其中一个，在账户卡片上标为“用于行情”。第一个保存的账户自动成为行情账户，删除它之后不自动改选。更换行情账户前须断开行情，不影响正在交易的账户。账户开通交易后，经纪商代码、投资者账号、AppID 和交易前置不能再修改。账户保存在本机服务管理器目录的 `ctp-connections/`，不含密码和授权码；每次保存生成新修订号。
- **自选**：最多 50 个实际月份合约，独立于全市场订阅。
- **报价字段**：最新价、买卖一及 2–5 档、开高低、昨结算、昨收、涨跌停、持仓量及日增仓、成交量、交易日、单位均价。缺失值保持缺失，不补零。
- **事件流**：服务保留有界的有序报价事件（断档、断线和乱序都会标记），供分钟线和最近报价曲线使用。单个订阅的确认或拒绝只记录该合约的状态，不重复复制全市场订阅；会话变化仍记录完整订阅状态。

行情服务的合约目录按独立修订号发布为不可变快照。每条持续连接首先取得完整目录，后续只有目录版本变化才再次传输；重连重新取得完整目录，Terminal 拒绝无法对应当前服务实例与已持有版本的省略响应。心跳只读取连接阶段，不复制报价与目录。持续连接的首帧与订阅集合重置包含全部报价；其余帧携带前一帧序号和变化的合约行。Feed 只扫描轻量行修订号，分钟聚合有独立修订号，晚于报价生成的涨速及中断后的清空也会单独发布。Terminal 校验连续基线和合约身份，按索引更新缓存；后台发布与界面轮询均先按修订号筛选，再复制变化行。命令响应仍提供完整快照，交错到达的旧行情帧不会回退已发布状态。事件流的断档标记与容量限制保持有效。

### 当前服务线程与接入

客户端连接由一条非阻塞 I/O 线程接收和发送；请求、目录结果发布、自选集合与分钟聚合由一条
行情状态线程串行处理。查询快照不再触发全市场订阅，目录修订到达后由状态线程应用乘数和订阅。
普通连接最多 64 条，持续推送最多 32 条，私有监督通道另有 4 条连接；请求队列分别限于 64 和 4 项。
持续推送每次只生成一帧，发送完成后再生成下一帧，正常更新间隔 250 毫秒。慢客户端不积压待发送快照，
单帧发送超过 2 秒会断开；重新连接必须从完整基线开始。

停止时 I/O 线程关闭接入，完成已接纳回复并结束持续推送，再由状态线程释放资源。
正常退出等待资源完成；400 毫秒期限用尽后直接结束进程，不提前销毁仍被 SDK 使用的对象。
实时 Feed 和合约目录共用一条固定 SDK 线程，拥有动态库加载、API 创建、初始化、请求和释放。连接请求
先接纳，再通过状态报告初始化结果；旧 API 释放完成后才建立下一实例，等待期间状态与 I/O 线程继续工作。
SDK 回调只复制带实例代次和入口接收时间的固定供应商结构体；行情线程每轮至多转换 1,024 条。
原始队列最多 65,536 条，满额或入队失败会使事件流永久标记为不完整、停止更新报价，须重启行情服务；
不把丢失原始事件伪装成正常完整行情。归一报价、订阅状态、事件序号和分钟聚合均由行情线程写入。

合约目录使用增量查询：SDK 回调入队，SDK 线程每轮至多处理 1,024 条目录事件，等待供应商响应时
释放执行容量给 Feed。先过滤非期货及非活动合约，目录原始队列限于 32,768 条，最终目录最多
20,000 个活动期货合约；溢出明确失败。Feed 和目录各最多一项在途 SDK 工作，共享执行器排队容量为 2。
缓存读取、验证与写入也在 SDK 线程进行；初始化期间健康可应答，普通请求及推送首帧等待缓存完成。
损坏缓存明确报告错误且保留文件。SDK 调用或释放本身仍可能阻塞该线程，I/O 与行情状态继续推进。

完整服务固定为 I/O、行情状态、SDK 三条应用线程，不因连接、目录查询或请求数量增设线程。
供应商自建线程另计。详细执行进度健康与总资源字节预算仍待补齐，物理线程数不代表全部架构验收。

### 均价

CTP 的 `AveragePrice` 在郑商所是单位均价，其他交易所是成交额／成交量（含合约乘数）。服务用合约目录中的乘数归一；乘数未知或当日无成交时不报告均价。

### 当日分钟线与 1 分钟涨速

服务从有序事件流构建每个合约当日的 1 分钟线（`core/domain/intraday_bars`）：

- 开高低收取最新价；分钟成交量是累计成交量的差值，交易日第一条观测只作为基准。
- 事件断档、断线或累计量回退时标记“曾中断”；换交易日重新开始。
- `first_observation_ms` 标明服务开始观测的时间，更早的分钟未知，不补齐。
- 1 分钟涨速 = 最新价相对同一交易日内至少 60 秒前最近一次观测的百分比；不足 60 秒或中断后为空。

分钟线只保存在服务内存中，服务重启后从头观测。终端通过只读命令 `market.minutes` 查询。

### 分时横轴

分时图按 `config/futures-sessions.json` 的交易时段排布横轴，左轴价格、右轴相对昨结算百分比。未列入该配置的品种只按已观测分钟排列。

## 统一历史数据契约

历史数据使用 Asterion 的版本化模型，数据源字段在插件边界转换。公共协议使用 `contract_id`、`source` 和 `source_instrument`（来源映射证据），不使用 `ts_code`。Core 的 `HistoryIdentity` 由交易所、规范化小写品种、完整交割年月组成，例如 `SHFE/cu/2024-03`。交易所短代码仅用于展示与交易，不能作为长期历史身份；郑商所跨年代相同短代码对应不同历史合约。

- `HistoricalBar`：UTC 纳秒标签、精确 OHLCV、成交额、持仓量，以及可缺失的交易日。
- `HistoricalDailyBar`：交易日、精确 OHLCV、成交额、持仓量，可缺失的昨收、昨结算、结算价。日线不伪造数据源成交时间。
- `HistorySemantics`：来源、规范化版本、时区、标签语义、成交额与数量单位。价格使用 8 位小数 Decimal，超过精度拒绝，不经 double 归一。
- 缺失交易日与缺失结算价不能用相邻记录补齐。回测与因子的 K 线序列必须有明确的交易日和对应结算价。

## 插件与服务边界

`HistoricalBarPort` / `HistoricalDailyPort` 返回统一类型和来源语义。`plugins/data/registry` 是已安装历史数据源的组合入口，负责创建插件和加载目录；供应商鉴权、代码映射、字段与请求规则保留在供应商插件中。Terminal 通过数据服务的 Protobuf IPC 查询目录，不链接 Tushare。

`asterion-data-pipeline` 仅作为 Agent 托管的下载工作程序运行。任务定义不含凭据；凭据独立存储在当前用户可读文件中。Terminal 关闭后任务继续运行。取消、重试与完成发布仍由任务服务的执行令牌和状态机控制。

## 下载凭据

Terminal 提交下载前，先向配对 Data 服务固定授权。Data 将实例配对、任务 ID、准确下载定义、
供应商插件摘要与当时的供应商令牌一起保存为 `authorizations/<引用>.pb`，文件权限为 `0600`。
该记录包含明文令牌，文件权限限制读取，不是加密。对外响应只返回非秘密授权元数据。

Task 只接收授权引用，通过同节点私有 Data 通道确认持久授权，固定定义和插件摘要后再接纳任务。
Task 的协议、目录、日志和结果均不保管供应商令牌。Task 为尝试分配 Data 目录后，worker
按固定 Data/Task 实例与尝试身份直接从 Data 私有通道领取原凭据；没有目录分配的尝试不能领取。
取消与执行尝试仍由 Task 控制，领取凭据不转移任务协调权。

相同任务身份重复授权核对原定义和秘密，返回原插件版本，不用新设置或插件升级覆盖原记录。
即使原供应商已被禁用，仍可确认已持久的同一授权；首次捕获则必须通过当前供应商验证。
显式重试继续引用原授权；需要更换令牌时，在供应商处撤销旧令牌、更新本机设置，再建立新任务。
清除 Terminal 设置或钥匙串不清理 Data 中已提交的授权。授权先于任务接纳持久化，因此即使
任务接纳失败，也可能保留已捕获授权；当前不按状态或时间自动删除，不能手工改写已有授权来换身份。

下载前，在数据源设置或下载面板使用“应用共享额度”，给当前数据实例明确分配每分钟请求份额。
保存 Terminal 凭据只是本机设置，提交任务也不会自动修改共享额度。同一供应商插件、同一令牌的
分钟线、日线及下载所需交易日历请求共用额度；单任务请求速率只会进一步放慢该任务。
额度按滚动 60 秒计算，服务端持久保存政策；调整政策保留已发放记录，重启后的首个完整窗口
不发放新额度，防止重启重置计量。额度窗口由数据服务的 I/O 状态线程独占；配置经过串行持久写入后才生效，等待期间原配置继续有效。配置提交结果不确定时停止发放，重启后从已保存政策恢复并等待完整静默窗口。未配置额度或许可 RPC 失败时停止下载，不绕过许可、不自动重试外部请求。

worker 在实际 HTTP 请求前通过 Data 私有通道取许可，等待可取消。文件存储只负责分页与持久化，
不再按页估算请求数。保证范围为当前数据实例管理的下载；合约目录查询、手工连接验证和其他软件
不在此下载预算内。多个实例使用同一账号时，必须分别配置份额。额度是用户分配值，应用支持的
上限不是供应商账号权限的自动探测结果；权限和限流错误仍按来源错误处理。
任务格式已更新，不自动迁移或删除旧 Task 凭据。完整服务目录冷备份与恢复见[任务管理](tasks.md#备份与恢复)。

## 独立历史仓库

仓库实现位于 `plugins/storage/filesystem/history_*`，通过 `HistoryStorePort` 提供统一版本目录。行情数据存为 Parquet（`plugins/storage/parquet`，由内嵌 DuckDB 读写，zstd 压缩）：价格列为 `DECIMAL(18,8)`，成交量、成交额、持仓量为 `DECIMAL(38,8)`，与内部 `Decimal` 精确对应，可直接用 DuckDB、pandas 等工具只读分析。manifest 为 JSON，仓库索引为 Protobuf。这些是数据源下载后的内部格式，不提供本地 JSON/CSV/Parquet 行情导入。

每个进程只拥有一个共享 DuckDB 引擎和一条串行查询通路，内部线程数固定为 1。
引擎缓冲内存上限为 128 MiB，关闭临时磁盘溢写及扩展自动下载；容量不足明确失败。
此额度覆盖 DuckDB 管理的缓冲，不包括调用方持有的行情、协议对象和其他分配，不能视为
进程 RSS 上限。存储逐页/段读写，最大合法分钟段为 31 天、44,640 行，日线页为 366 行。

主力连续合约先逐月验证选定版本，只保留决定换月所需的合约条款、交易日、结算价和
持仓量，再按确定的换月区间重新读取不可变版本。不会同时保留所有月份的完整分钟
行情，也不复制整份行情后再裁剪。最终各段（包括换月交接需要的重叠行情）合计最多
200,000 条；Task 汇入多个合约输入时也在保留下一份输入前检查同一总量限制。

```text
<data-directory>/history/
  SHFE/cu/2024-03/tushare.fut_daily/daily/<acquisition-id>/
    daily.json            manifest v4
    daily-0.parquet       每个约 366 天的请求页一个文件
  SHFE/cu/2024-03/tushare.ft_mins/1m/<acquisition-id>/
    minutes.json          manifest v4：逐日行数与分段清单
    minutes-0.parquet     每 31 个日请求页合成一个分段
    minutes-31.parquet
  index/<manifest-sha256>.pb
```

数据位于仓库内，独立于任务日志和执行结果目录。来源、合约、周期隔离；manifest 包含请求范围、来源映射、规范化语义、各块摘要、行数与下载完成标记。数据版本为完整 manifest 的 SHA-256，规范化规则变化会产生新版本。不同来源不自动拼接，不静默覆盖历史修订；同一完整版本重复发布可以复用索引；新的取得操作保留独立时间证据。

数据服务按授权、下载尝试和版本身份顺序接纳准备与提交。同一对象的后续操作等待原提交完成；
目录枚举只观察通过持久屏障的发布，其他已发布版本可独立读取。重复确认已有索引或具名数据集
仍须完成目录同步，不能仅凭文件存在确认持久成功。具名数据集最多保管 1,000 个，容量由
数据服务状态线程在写入前检查；同一内容重复保存不增加计数。

分钟线按天请求数据源，抓取的页暂存在内存，满 31 页、下载结束、取消或数据源出错时写成一个 Parquet 分段（先同步临时文件再改名），然后推进 manifest；取消时正在读取的那一页丢弃。中断后从 manifest 已记录的页继续，未写入 manifest 的分段重新抓取。候选校验后仍不公开；任务服务先持久保存发布决定，数据服务依据该决定发布索引，版本可查询后任务才确认成功。恢复只继续或查询同一发布决定，不重跑下载；发布可重复确认。分页读取只校验并加载涉及的分段（SHA-256），回测与因子输入读取验证完整数据。文件锁排除写入与读取竞争。

仓库支持按交易所、品种、完整合约和来源检索，并可按品种做“覆盖核对”：数据服务校验文件摘要后，按每一对固定分钟／日线版本分别统计交易日，不合并来源、周期或修订。列表显示双方版本与分钟周期，列出分钟线实际起止范围内日线有而分钟线没有的交易日。这个结果不证明日内完整性。分钟与日线分页、因子与回测的数据选择均直接引用已发布的数据版本，无须依赖下载任务条目。Terminal 的“历史数据仓库”可筛选、查看来源、覆盖请求范围和固定版本。`complete` 只说明请求分段处理完毕，不证明交易所没有缺失数据。

## 当前 Tushare 适配

- 分钟线：1、5、15、30、60 分钟，按请求范围分段，可恢复。可按品种一次提交全部月份合约，每个合约一个任务；最多同时运行 2 个，通过数据服务共享同一授权的滚动请求额度。
- 日线：交易日与可缺失结算价；图表可聚合为周、月、季、年。
- 合约目录要求供应商提供 `d_month` 完整交割年月，同时保留供应商合约代码映射；不依据当前年份猜测年代。[供应商目录字段](https://tushare.pro/document/2?doc_id=135)
- 分钟标签按 K 线结束时间（`bar_end`）保存。下载时核对：商品期货 1、5 分钟 K 线出现 10:30:00 标签（开始于 10:15–10:30 休盘内）即判定不是结束时间并拒绝。
- 交易日来自 Tushare 交易日历（`trade_cal`，按交易所、按年请求并缓存）：白天 K 线的日期必须是开市日；18:00 以后及次日 06:00 以前的夜盘 K 线归属开盘当晚之后的第一个开市日，且开盘当晚必须是开市日（周五夜盘归下周一，长假前的夜盘归节后首日）。日历未发布或与数据矛盾时拒绝，不猜测。
- 带交易日的分钟线可与同一合约的日线结算价组成回测与因子使用的 K 线数据集。
- 日线计算继续使用来源交易日和结算价。日线计算的排序坐标仅是执行模型坐标，不代表数据源提供了日内成交路径。

图表分页可以附加均线和 MACD；这些显示指标从数据集起点计算，不改变原始记录。生产历史数据源目前仍只有 Tushare，测试中的替代数据源只验证隔离，不进入生产注册表。

## 历史时间与可知性

行情标签时间、交易日、来源公布或可知时间、系统取得完整版本的时间是不同概念。
分钟与日线 manifest v4 固定 `source_availability: "unknown"`：当前提供者没有可核验的
历史公布时刻，不能从交易日、日线的 15:00 排序标签或下载时间推断。部分下载的
`acquired_at_ns` 为 `"0"`；最后一批数据完成时，与完整 manifest 一起持久发布系统 UTC
纳秒时间。恢复部分下载只在完整版本发布时记时；已经完整的版本重开不改写该值。
此时间表示整版在本系统可用，不证明每条记录最初何时取得，也不证明供应商当时公布过。

新取得操作即使返回相同行情字节，也有自己的取得证据和 manifest 身份。行情内容摘要
仍只描述合约、周期、K 线与结算日；取得证据不会改变相同字节的内容摘要。
Data 解析输入时，将行情与结算版本的并集按身份排序，各携带一次取得证据，随固定输入
交给 Task；因子的日线序列携带单一来源证据。BarDataset 与 DailyFactorDataset 当前均为 v2。
任务文件摘要固定全部证据，结果读取原输入，不能用当前时间补写或由 UI 猜测。
不支持的 manifest 或缺少证据的旧输入明确拒绝，原文件保留，不自动迁移。

回测与因子结果展示取得证据和结论范围：可作事后统计及既定模型下的回放，不能据此
声称验证严格历史可交易性。支持有公布时间证据的来源需要新的实际提供者契约；当前
不提供空的逐行 PIT 存储、自动历史修订或推测公布时刻。

## 数据集输入

日线和分钟线都可用于回测与因子分析；分钟数据必须具备交易日、`bar_end` 标签语义和对应日线结算价，Tushare 分钟线的交易日来自交易所交易日历。数据集会列出结算日历中存在、但所选 K 线缺失的交易日（覆盖缺口），选择时明确提示，不自动补齐。

在 K 线数据选择区可将已选合约保存为具名数据集；保存合约单位、日期区间和行情／结算的全部固定档案版本。“拼接更多下载”可显式组合同合约、同周期、同口径的分段下载；重复记录去重，冲突拒绝，不覆盖原始档案。恢复会先核验整组输入，全部成功后再替换当前选择。已有任务的参数与结果保持固定；同名不同输入产生独立版本，不覆盖旧记录。数据集属于当前数据服务，切换服务后需要选择该服务中的数据集。存储边界与限制见下文。

下载任务确认成功并发布历史仓库后，任务摘要中的 `history_dataset_id` 指向已发布版本。
回测与因子的 K 线序列请求使用 `source_dataset_ids` 和 `settlement_dataset_ids` 列表（manifest SHA-256），每类 1–32 份，排序后固定，拒绝重复标识；单份输入也使用列表。旧的单值字段和任务 ID 请求被拒绝，不自动迁移持久化输入。
因子的序列有两种来源，属于同一种因子任务：日线序列直接引用一个日线版本；K 线序列和回测一样固定所选行情及日线结算的全部版本。
提交时再次读取、校验并固定输入，不根据后来新增的下载重新选择数据。
Terminal 从历史数据仓库或下载完成条目进入回测或因子分析。只有一个日线候选时自动匹配；存在多个候选时显式选择，日线行情默认使用自身结算。
切换数据服务或在读取期间修改已选数据会使旧选择响应失效；读取仓库与校验数据不持有 Terminal 全局操作锁。
“研究”工作区的 K 线数据选择区支持“保存当前选择”，并可从“已保存数据集”恢复，用于回测和因子的 K 线序列。
命名数据集由数据服务保存于 `history/named-datasets/<sha256>.pb`，包含合约、日期区间、计量参数、行情／结算的档案版本及已解析内容摘要，不复制行情文件。
记录不可变：同名同输入重复保存复用记录，同名不同输入创建独立版本；数据服务重启后仍保留。名称最多 120 UTF-8 字节，界面最多 40 个字符；最多保存 1000 个版本，每个最多 20 合约、共计 200000 根，交易日必须一致。
保存时重新验证全部档案；使用时重新解析并核对每个内容摘要，再一次性替换 Terminal 当前选择。读取失败或数据服务连接／当前选择在读取中改变时，拒绝替换。已有任务和账本的固定输入不受影响。
选择一个来源后，可以展开“拼接更多下载”，勾选同合约、同周期的其他 K 线下载，并选择补充日线结算。默认只使用当前选择，不自动合并仓库中的新下载。界面显示每类输入份数，实验详情记录全部版本。
拼接在数据服务内完成：每个输入核验摘要、合约、完整状态，各角色内部要求相同数据源、标准化版本、时区、标签和计量语义；K 线周期也必须相同。先按所选交易日裁剪，再按时间排序；相同时间戳的计算输入的 K 线字段完全一致才去重，交易日或 OHLCV 不同则拒绝。相同交易日的结算价必须一致（缺值也不能被另一份隐式补写），不采用“最后写入优先”规则。跨来源拼接、连续合约换月、自动修订均不支持。
拼接后按唯一 K 线统计容量；结算日历内缺失整日 K 线继续列出，不声称日内完整。具名数据集固定全部分段版本，恢复时重新解析并检查内容摘要；新增下载不会改变已保存输入。旧格式仅拒绝读取，原文件不删除或改写。
历史仓库提供“下载后续数据”和覆盖核对中的“补齐缺口”，都先预览准确的请求范围，再创建普通下载任务。日线从所选版本原始请求结束日的下一日开始；分钟线从原请求结束后的下一秒开始，分数秒边界会重取该秒以避免遗漏。结束日期最多为上海时区已结束的日期。这是相对单个固定版本的增量，不会扣除其它下载范围，也不保证该合约在所选日期有数据。

补齐按选定分钟／日线版本核对整日缺口，并重新下载原分钟版本的完整请求范围。日线档案没有完整交易时段，因此不推算缺失交易日的夜盘起止；预览明确展示完整范围和待核对日期。数据源可能仍不返回缺失记录，完成后需要重新核对覆盖，不宣称数据已经完整。

预览固定基础版本、日线参照版本、限速和请求范围的摘要；提交时 Terminal 重新核对计划，Data 固定输入授权，Task 按授权接纳。供应商凭据、凭据快照、限速、进度及显式重试沿用普通下载任务；新任务持久化实际下载参数，不额外保存基础版本的派生关系。完成后生成独立历史版本，原文件及已保存数据集不变，用户检查后显式拼接或选择。该入口使用当前节点固定配对的数据与任务服务。

仓库每个版本的“使用情况”合并当前任务服务中的来源下载、回测、因子任务引用，以及当前数据服务中的已保存数据集引用。来源下载标记为下载产物，计算任务引用分别标记为行情或结算输入；同一记录的多个角色合并展示。任务处于完成、失败或取消状态也不会丢弃来源关系。Terminal 另外显示查询时本窗口回测与因子草稿的引用；刷新会重新核对，版本切换或服务切换后的旧响应不得覆盖当前结果。读取失败时清空旧结果并报错，不显示成无引用。



已连接节点上的其他数据与任务服务也参与检查，本机走 IPC、远程走 mTLS，不创建轮询客户端、不切换当前数据服务或草稿。当前数据服务端点在本机按 Socket 与会话、远程按地址、会话和 TLS 身份去重；其余服务按节点和服务分别展示任务／已保存数据集引用，同名任务不跨服务合并。服务按固定版本标识扫描持久输入，不要求本地保存对应历史文件副本；无副本也可能存在引用。停止的远程服务、清单失败、认证失败、损坏记录和超时明确标为未检查，不启停服务、不访问远端文件。其他运行中数据服务的每次网络查询最多 5 秒，所有节点的数据引用查询共用 20 秒截止时间；Agent 清单刷新沿用节点时限，回放检查沿用上述时限。只代表已连接且可核对的服务，不是全局依赖索引。

停止的本机任务服务仅在 Agent 清单给出的账本与当前环境 `services/<service>/ledger` 完全匹配且路径无符号链接时检查。复用任务服务的当前持久化格式校验，以已有 `manager.lock` 的共享只读锁阻止与服务独占写入并行；缺锁、服务占用或路径不符直接拒绝，不补建锁。SQLite 使用只读连接与读取事务，不建表、不改变运行中任务状态、不重算回测／因子结果、不重新发布历史版本。下载产物通过已提交结果记录的摘要和固定源版本标识核对引用，不扫描全部历史 K 线，也不宣称数据或结果可恢复。停止的数据服务明确显示未检查，尚不提供离线命名数据集引用扫描。离线检查上限为 100000 条记录及 256 MiB 原始记录，活动任务仍限 1000 个，终态历史不计入该活动上限；文件读取不属于上述网络超时承诺。SQLite 自身可能生成 WAL/SHM 协调文件，但任务记录、账本内容与历史文件不改写。检查期间显式启动服务可能遇到锁冲突，需要稍后重试。

本机登记目录中的未连接节点（包括尚未完成登记的名称）单独列为本次未检查。仅枚举名称，不读取证书、私钥或登记文件内容，不自动连接；清单无权限、符号链接或超限时显示范围不完整。尚未登记、仅保存在设置表单中的草稿配置不属于此清单。查询前后登记名称变化会拒绝过期结果。

这些结果是本次查询的分段观察值，不是全局依赖快照或删除许可。本机自选目录、停止的远程账本、未连接的节点、停止的远程数据服务、其他窗口的回测与因子草稿不在扫描范围内，跨服务复制的数据来源也没有全局反向索引。当前物理删除入口保持关闭，不会因查询无结果而允许删除，也不会自动修改任务、具名数据集或行情文件。

定时自动更新、精确交易时段补齐、未连接节点的引用核对、删除和依赖清理尚未实现；因子的日线序列仍直接选择单个档案版本。
