# 行情与数据

本文说明当前实时行情与历史数据能力。`asterion-market-data` 管理实时观测，独立的 `asterion-data-service` 管理历史版本、具名数据集、下载授权及共享额度。`asterion-task-service` 管理执行尝试与计算结果；下载任务的状态、容量和恢复见[任务管理](tasks.md)。

## CTP 实时行情

`asterion-market-data` 通过 `plugins/data/ctp` 连接 CTP 行情前置，只读。

- **连接**：使用行情账户（设置 → CTP 账户里标为“用于行情”的那一个，见下），输入密码和授权码。勾选“保存密码和授权码到本机钥匙串”后连接，可将两者保存在 macOS 钥匙串或 Linux Secret Service 密钥环；后续连接或查询目录时留空即可复用，无需重复输入。可通过“清除已保存的登录凭据”移除。保存的凭据绑定本机环境、账户身份及两个前置地址；修改这些连接信息或删除账户会清除对应凭据，改名不会。行情凭据不用于交易登录。
- **合约目录**：连接行情后用行情账户的交易前置、AppID 和本次输入的授权码自动加载全市场合约并全部订阅；只查询合约，不开通交易。
- **CTP 账户**：期货公司给的柜台信息在「设置 → CTP 账户」填写一次，六项都必填：名称、经纪商代码、投资者账号、AppID、交易前置、行情前置。可以保存多个账户，各自在交易页独立连接和交易；行情只使用其中一个，在账户卡片上标为“用于行情”。第一个保存的账户自动成为行情账户，删除它之后不自动改选。更换行情账户前须断开行情，不影响正在交易的账户。账户开通交易后，经纪商代码、投资者账号、AppID 和交易前置不能再修改。账户保存在本机服务管理器目录的 `ctp-connections/`，不含密码和授权码；每次保存生成新修订号。
- **自选**：最多 50 个实际月份合约，独立于全市场订阅。
- **报价字段**：最新价、买卖一及 2–5 档、开高低、昨结算、昨收、涨跌停、持仓量及日增仓、成交量、交易日、单位均价。缺失值保持缺失，不补零。
- **事件流**：服务保留有界的有序报价事件（断档、断线和乱序都会标记），供分钟线和最近报价曲线使用。单个订阅的确认或拒绝只记录该合约的状态，不重复复制全市场订阅；会话变化仍记录完整订阅状态。

行情服务的合约目录按独立修订号发布为不可变快照。每条持续连接首先取得完整目录，后续只有目录版本变化才再次传输；重连重新取得完整目录，Terminal 拒绝无法对应当前服务实例与已持有版本的省略响应。心跳只读取连接阶段，不复制报价与目录。持续连接的首帧与订阅集合重置包含全部报价；其余帧携带前一帧序号和变化的合约行。Feed 只扫描轻量行修订号，分钟聚合有独立修订号，晚于报价生成的涨速及中断后的清空也会单独发布。Terminal 校验连续基线和合约身份，按索引更新缓存；后台发布与界面轮询均先按修订号筛选，再复制变化行。命令响应仍提供完整快照，交错到达的旧行情帧不会回退已发布状态。事件流的断档标记与容量限制保持有效。

### 当前服务线程与接入

客户端连接由一条非阻塞 I/O 线程接收和发送；请求、目录结果发布、自选集合与分钟聚合由一条
行情状态线程串行处理。查询快照不再触发全市场订阅，目录修订到达后由状态线程应用乘数和订阅。
普通连接最多 64 条，持续推送最多 32 条，私有监督通道另有 4 条连接；请求队列分别限于 64 和 4 项。
持续推送每次只生成一帧，发送完成后再生成下一帧，正常更新间隔 250 毫秒。慢客户端不积压待发送快照，
单帧发送超过 2 秒会断开；重新连接必须从完整基线开始。

停止时 I/O 线程关闭接入，完成已接纳回复并结束持续推送，再由状态线程释放资源。
正常退出等待资源完成；400 毫秒期限用尽后直接结束进程，不提前销毁仍被 SDK 使用的对象。
实时 Feed 和合约目录共用一条固定 SDK 线程，拥有动态库加载、API 创建、初始化、请求和释放。连接请求
先接纳，再通过状态报告初始化结果；旧 API 释放完成后才建立下一实例，等待期间状态与 I/O 线程继续工作。
SDK 回调只复制带实例代次和入口接收时间的固定供应商结构体；行情线程每轮至多转换 1,024 条。
原始队列最多 65,536 条，满额或入队失败会使事件流永久标记为不完整、停止更新报价，须重启行情服务；
不把丢失原始事件伪装成正常完整行情。归一报价、订阅状态、事件序号和分钟聚合均由行情线程写入。

合约目录使用增量查询：SDK 回调入队，SDK 线程每轮至多处理 1,024 条目录事件，等待供应商响应时
释放执行容量给 Feed。先过滤非期货及非活动合约，目录原始队列限于 32,768 条，最终目录最多
20,000 个活动期货合约；溢出明确失败。Feed 和目录各最多一项在途 SDK 工作，共享执行器排队容量为 2。
缓存读取、验证与写入也在 SDK 线程进行；初始化期间健康可应答，普通请求及推送首帧等待缓存完成。
损坏缓存明确报告错误且保留文件。SDK 调用或释放本身仍可能阻塞该线程，I/O 与行情状态继续推进。

完整服务固定为 I/O、行情状态、SDK 三条应用线程，不因连接、目录查询或请求数量增设线程。
供应商自建线程另计。详细执行进度健康与总资源字节预算仍待补齐，物理线程数不代表全部架构验收。

### 均价

CTP 的 `AveragePrice` 在郑商所是单位均价，其他交易所是成交额／成交量（含合约乘数）。服务用合约目录中的乘数归一；乘数未知或当日无成交时不报告均价。

### 当日分钟线与 1 分钟涨速

服务从有序事件流构建每个合约当日的 1 分钟线（`core/domain/intraday_bars`）：

- 开高低收取最新价；分钟成交量是累计成交量的差值，交易日第一条观测只作为基准。
- 事件断档、断线或累计量回退时标记“曾中断”；换交易日重新开始。
- `first_observation_ms` 标明服务开始观测的时间，更早的分钟未知，不补齐。
- 1 分钟涨速 = 最新价相对同一交易日内至少 60 秒前最近一次观测的百分比；不足 60 秒或中断后为空。

分钟线只保存在服务内存中，服务重启后从头观测。终端通过只读命令 `market.minutes` 查询。
返回的序列写明是哪个行情服务、哪个实例观测的（`service`、`instance_id`，与快照里行情部分的同名字段一致）；查询期间行情服务的选择变了，这次查询以冲突拒绝，不把原服务的序列交给界面。分时图和分钟 K 线按“合约 + 行情服务 + 实例”认定一条序列：换了行情服务或服务重启后清空重读，同一时刻只有一个查询在途，写着别的服务的应答不采用。

### 分时横轴

分时图按 `config/futures-sessions.json` 的交易时段排布横轴，左轴价格、右轴相对昨结算百分比。未列入该配置的品种只按已观测分钟排列。

## 统一历史数据契约

历史数据使用 Asterion 的版本化模型，数据源字段在插件边界转换。公共协议使用 `contract_id`、`source` 和 `source_instrument`（来源映射证据），不使用 `ts_code`。Core 的 `HistoryIdentity` 由交易所、规范化小写品种、完整交割年月组成，例如 `SHFE/cu/2024-03`。交易所短代码仅用于展示与交易，不能作为长期历史身份；郑商所跨年代相同短代码对应不同历史合约。

- `HistoricalBar`：UTC 纳秒标签、精确 OHLCV、成交额、持仓量，以及可缺失的交易日。
- `HistoricalDailyBar`：交易日、精确 OHLCV、成交额、持仓量，可缺失的昨收、昨结算、结算价。日线不伪造数据源成交时间。
- `HistorySemantics`：来源、规范化版本、时区、标签语义、成交额与数量单位。价格使用 8 位小数 Decimal，超过精度拒绝，不经 double 归一。
- 缺失交易日与缺失结算价不能用相邻记录补齐。回测与因子的 K 线序列必须有明确的交易日和对应结算价。

## 插件与服务边界

`HistoricalBarPort` / `HistoricalDailyPort` 返回统一类型和来源语义。`plugins/data/registry` 是已安装历史数据源的组合入口，负责创建插件和加载目录；供应商鉴权、代码映射、字段与请求规则保留在供应商插件中。Terminal 通过数据服务的 Protobuf IPC 查询目录，不链接 Tushare。

`asterion-data-pipeline` 仅作为 Agent 托管的下载工作程序运行。任务定义不含凭据；凭据独立存储在当前用户可读文件中。Terminal 关闭后任务继续运行。取消、重试与完成发布仍由任务服务的执行令牌和状态机控制。

## 下载凭据

Terminal 提交下载前，先向配对 Data 服务固定授权。Data 将实例配对、任务 ID、准确下载定义、
供应商插件摘要与当时的供应商令牌一起保存为 `authorizations/<引用>.pb`，文件权限为 `0600`。
该记录包含明文令牌，文件权限限制读取，不是加密。对外响应只返回非秘密授权元数据。

Task 只接收授权引用，通过同节点私有 Data 通道确认持久授权，固定定义和插件摘要后再接纳任务。
Task 的协议、目录、日志和结果均不保管供应商令牌。Task 为尝试分配 Data 目录后，worker
按固定 Data/Task 实例与尝试身份直接从 Data 私有通道领取原凭据；没有目录分配的尝试不能领取。
取消与执行尝试仍由 Task 控制，领取凭据不转移任务协调权。

相同任务身份重复授权核对原定义和秘密，返回原插件版本，不用新设置或插件升级覆盖原记录。
即使原供应商已被禁用，仍可确认已持久的同一授权；首次捕获则必须通过当前供应商验证。
显式重试继续引用原授权；需要更换令牌时，在供应商处撤销旧令牌、更新本机设置，再建立新任务。
清除 Terminal 设置或钥匙串不清理 Data 中已提交的授权。授权先于任务接纳持久化，因此即使
任务接纳失败，也可能保留已捕获授权；当前不按状态或时间自动删除，不能手工改写已有授权来换身份。

下载前，在数据源设置或下载面板使用“应用共享额度”，给当前数据实例明确分配每分钟请求份额。
保存 Terminal 凭据只是本机设置，提交任务也不会自动修改共享额度。同一供应商插件、同一令牌的
分钟线、日线及下载所需交易日历请求共用额度；单任务请求速率只会进一步放慢该任务。
额度按滚动 60 秒计算，服务端持久保存政策；调整政策保留已发放记录，重启后的首个完整窗口
不发放新额度，防止重启重置计量。额度窗口由数据服务的 I/O 状态线程独占；配置经过串行持久写入后才生效，等待期间原配置继续有效。配置提交结果不确定时停止发放，重启后从已保存政策恢复并等待完整静默窗口。未配置额度或许可 RPC 失败时停止下载，不绕过许可、不自动重试外部请求。

worker 在实际 HTTP 请求前通过 Data 私有通道取许可，等待可取消。文件存储只负责分页与持久化，
不再按页估算请求数。保证范围为当前数据实例管理的下载；手工连接验证和其他软件
不在此下载预算内。多个实例使用同一账号时，必须分别配置份额。额度是用户分配值，应用支持的
上限不是供应商账号权限的自动探测结果；权限和限流错误仍按来源错误处理。
任务格式已更新，不自动迁移或删除旧 Task 凭据。完整服务目录冷备份与恢复见[任务管理](tasks.md#备份与恢复)。

## 独立历史仓库

仓库实现位于 `plugins/storage/filesystem/history_*`，通过 `HistoryStorePort` 提供统一版本目录。行情数据存为 Parquet（`plugins/storage/parquet`，由内嵌 DuckDB 读写，zstd 压缩）：价格列为 `DECIMAL(18,8)`，成交量、成交额、持仓量为 `DECIMAL(38,8)`，与内部 `Decimal` 精确对应，可直接用 DuckDB、pandas 等工具只读分析。manifest 为 JSON，仓库索引为 Protobuf。这些是数据源下载后的内部格式，不提供本地 JSON/CSV/Parquet 行情导入。

每个进程只拥有一个共享 DuckDB 引擎和一条串行查询通路，内部线程数固定为 1。
引擎缓冲内存上限为 128 MiB，关闭临时磁盘溢写及扩展自动下载；容量不足明确失败。
此额度覆盖 DuckDB 管理的缓冲，不包括调用方持有的行情、协议对象和其他分配，不能视为
进程 RSS 上限。存储逐页/段读写，最大合法分钟段为 31 天、44,640 行，日线页为 366 行。

主力连续合约先逐月验证选定版本，只保留决定换月所需的合约条款、交易日、结算价和
持仓量，再按确定的换月区间重新读取不可变版本。不会同时保留所有月份的完整分钟
行情，也不复制整份行情后再裁剪。最终各段（包括换月交接需要的重叠行情）合计最多
200,000 条；Task 汇入多个合约输入时也在保留下一份输入前检查同一总量限制。

```text
<data-directory>/history/
  SHFE/cu/2024-03/tushare.fut_daily/daily/<acquisition-id>/
    daily.json            manifest v4
    daily-0.parquet       每个约 366 天的请求页一个文件
  SHFE/cu/2024-03/tushare.ft_mins/1m/<acquisition-id>/
    minutes.json          manifest v4：逐日行数与分段清单
    minutes-0.parquet     每 31 个日请求页合成一个分段
    minutes-31.parquet
  index/<manifest-sha256>.pb
```

数据位于仓库内，独立于任务日志和执行结果目录。来源、合约、周期隔离；manifest 包含请求范围、来源映射、规范化语义、各块摘要、行数与下载完成标记。数据版本为完整 manifest 的 SHA-256，规范化规则变化会产生新版本。不同来源不自动拼接，不静默覆盖历史修订；同一完整版本重复发布可以复用索引；新的取得操作保留独立时间证据。

数据服务按授权、下载尝试和版本身份顺序接纳准备与提交。同一对象的后续操作等待原提交完成；
目录枚举只观察通过持久屏障的发布，其他已发布版本可独立读取。重复确认已有索引或具名数据集
仍须完成目录同步，不能仅凭文件存在确认持久成功。具名数据集最多保管 1,000 个，容量由
数据服务状态线程在写入前检查；同一内容重复保存不增加计数。

分钟线按分段向数据源请求：一个分段是连续的最多 31 个自然日，仓库一次向数据源要一整段，数据源适配器在这一段里按接口的返回行数上限翻页（Tushare `ft_mins` 每次 8000 行，用 `limit`／`offset`；一次返回不满 8000 行即这一段结束），所以请求数取决于实际的 K 线数量而不是自然日数：1 分钟线一段约 2 次请求，5 分钟及以上一段 1 次，非交易日不单独请求。取回的一段按自然日切成页（存储格式不变），写成一个 Parquet 分段（先同步临时文件再改名），然后推进 manifest。取消或数据源出错时正在读取的那一段整段丢弃，已写入的分段保留；中断后从 manifest 已记录的页继续，未写入 manifest 的分段重新抓取。候选校验后仍不公开；任务服务先持久保存发布决定，数据服务依据该决定发布索引，版本可查询后任务才确认成功。恢复只继续或查询同一发布决定，不重跑下载；发布可重复确认。分页读取只校验并加载涉及的分段（SHA-256），回测与因子输入读取验证完整数据。文件锁排除写入与读取竞争。

仓库支持按交易所、品种、完整合约和来源检索，并可按品种做“覆盖核对”：数据服务校验文件摘要后，把每个分钟线版本分别与全市场日线表（当前快照）对照，不合并来源、周期或修订。对照的是分钟线实际起止范围内日线表已经入库的那一段：列出其中这个合约有竞价成交、分钟线却没有的交易日；日线表还没有入库的日子不对照，表里这一段有缺的交易日时拒绝并列出日期。这个结果不证明日内完整性。分钟与日线分页、因子与回测的数据选择均直接引用已发布的数据版本，无须依赖下载任务条目。Terminal 的“历史数据仓库”可筛选、查看来源、覆盖请求范围和固定版本。`complete` 只说明请求分段处理完毕，不证明交易所没有缺失数据。

## 全市场数据表

按合约下载适合看一个合约；研究横截面需要的是整个市场。全市场数据表以“表 × 交易所 × 周期”为单位取数和保存：数据源的日线接口一次请求返回一个交易所一天的全部合约，所以日线一个交易日是 6 次请求，与当天有多少合约在市无关；四张按日的表全选时一个交易日约 24 次请求（2026 年的数据量）。设计依据与方案比较见[全市场数据表设计](reviews/history-tables-design.md)。

因子分析可以直接读取日线表（见[读取](#读取)）。回测的 K 线输入仍然读取按合约下载的版本，尚未改读数据表。

### 表

表的列由领域层定义（`core/domain/history_tables`），对所有数据源相同。除主键外每一列都可以缺失：数据源给了什么就存什么，无成交日没有开高低收就是缺失，不补零。

| 表 | 一个分区 | 主键 | 列 |
| --- | --- | --- | --- |
| `futures.contracts` 合约表 | 一个交易所的全部合约 | 合约 | 数据源合约代码、名称、上市日、最后交易日、最后交割日、合约乘数、每手数量、交易单位、报价单位、最小变动价位说明、交割方式说明、交易时间说明 |
| `futures.calendar` 交易日历 | 一个交易所的一年 | 日期 | 是否开市、上一交易日 |
| `futures.daily` 日线 | 一个交易所的一个交易日 | 合约 | 开、高、低、收、结算、昨收、昨结算、成交量、成交额、持仓量、持仓量变化、交割结算价 |
| `futures.settlement` 结算参数 | 一个交易所的一个交易日 | 合约 | 交易手续费率、交易手续费、平今手续费、交割手续费、买/卖投机保证金率、买/卖套保保证金率 |
| `futures.receipts` 仓单日报 | 一个交易所的一个交易日 | 品种、行号 | 品种名称、仓库、仓库编号、地区、年度、等级、品牌、产地、折算仓单、昨日仓单量、今日仓单量、增减、单位、升贴水 |
| `futures.rankings` 成交持仓排名 | 一个交易所的一个交易日 | 合约或品种、会员 | 成交量及其变化、持买仓量及其变化、持卖仓量及其变化 |

列类型与 Parquet 的对应：

| 类型 | 说明 | Parquet |
| --- | --- | --- |
| 文本 | 非空 UTF-8，不含控制字符，至多 1024 字节 | `VARCHAR` |
| 合约 | 统一合约身份，交易所必须是分区的交易所 | `VARCHAR` |
| 日期 | `YYYY-MM-DD` | `DATE` |
| 布尔 | 0 或 1 | `BOOLEAN` |
| 小数 | 精确小数，至多 18 位有效数字；价格 8 位小数、成交额 2 位、手数 0 位 | `DECIMAL(18, 小数位)` |

成交额以元为单位、保留到分，最大约 1 亿亿元。按合约下载的日线把成交额存进 8 位小数的 `Decimal`（最大约 922 亿），主力合约的单日成交额会超过它；数据表按列的量纲选精度，没有这个限制。

入库只做结构校验：类型、精度、主键不重复、合约属于该交易所、日历的日期属于该年。超出精度或范围的值拒绝，不舍入。“最高价不低于最低价”这类合理性不在入库时判断，由使用数据的一方决定并报出具体的行。

合约表保存数据源的原始字段。数据集的合约乘数由数据服务从其中的合约乘数、每手数量、交易单位和报价单位推出；表里的最小变动价位说明只是现在的值，数据集不用它，见[合约单位](#合约单位)。

Tushare 的日线在 2020 年以前按双边统计成交量和持仓量，之后是单边（来自其接口说明）；数据表原样保存，不做折算。

#### 结算参数

交易所每天结算后公布的每个合约的手续费和保证金率。**数值按数据源发布的口径原样保存，不换算单位**，因为各交易所的口径不同，其中四家的手续费仅凭这张表无法确定是哪一种：

| 交易所 | 交易手续费率 / 交易手续费 | 平今手续费 | 交割手续费 | 保证金率 |
| --- | --- | --- | --- | --- |
| SHFE、INE | 两列分开：费率是成交额的千分比（铜 0.05），手续费是每手金额（黄金 20、天然橡胶 3）；一个品种只有其中一列不为 0 | 空 | 多为 0 | 小数（0.15 即 15%） |
| CZCE | 费率为空，手续费是一个数（苹果 5、棉花 4.3、甲醇 1） | 一个数；2015 年出现过 −1 | 一个数 | 小数 |
| DCE、GFEX | 费率为空，手续费是一个数（豆粕 1.5、鸡蛋 1.5、铁矿石 1、聚丙烯 1） | 一个数，多与手续费相同 | 空 | 小数 |
| CFFEX | 两列是同一个数（股指 0.23、国债 3） | 一个数（2015 年 100、2019 年 1500、2026 年 1000；国债为 0） | 一个数 | 百分数（12 即 12%） |

郑商所、大商所、广期所、中金所的品种有的按每手金额收费，有的按成交额比例收费，而数据源对它们只给一个数、不说明是哪一种。所以这张表可以直接给出保证金率（注意中金所是百分数），**不能单独给出这四家交易所的手续费**：还需要“该品种按哪种方式收费”的信息。上表的数值取自 2015–2026 年抽查的交易日；对单位的解释来自数值的形态和交易所通行的收费方式，没有逐一对照交易所公告。

结算价不在这张表里：数据源在同一个接口里也给结算价，抽查 2026-10-09 的 824 行与日线表逐一相同（中金所为空），只保留日线表里的那一份。

只保存当天在市的合约。数据源对中金所的回答里混有已经摘牌的合约（2026-10-09 的 56 行里有 28 行是 5 月到 9 月到期的合约），这些行不入库。

#### 仓单日报

交易所每天公布的注册仓单，**逐行保存报表**。报表不是有主键的表：区分两行的东西因交易所和品种而异（仓库、地区、年度、等级、品牌），有些行在数据源给出的全部属性上完全相同（2026-10-09 郑商所 839 行里有 159 行分成 40 组，每组内无法区分，其中甲醇厂库的行最多）。所以一行的身份只是“当天报表里该品种的第几行”：

- 行号从 1 起，按数据源返回的顺序，只在当天有效；不同日期之间不要按行号对应，按需要的属性（品种、仓库……）汇总。
- 数量的单位各不相同，见“单位”列：上期所是吨（黄金、白银是千克），能源中心是吨或桶，大商所、广期所是手，郑商所是张。
- “年度”等属性原样保存：数据源在没有年度时填 0，在大商所 2026 年填的是日历年份。
- 抽查的日期里没有见到“合计”“小计”行；没有对全部历史核对。
- 中金所没有实物仓单，不提供这张表。

上期所的报表里，国际铜（能源中心的品种）列在铜的名下、以品种名称“铜(BC)”区分，入库时归到能源中心的 `bc`；厂库的行有时把地区和企业名填在对调的两列里，原样保存。

#### 成交持仓排名

交易所每天公布的会员成交量、持买仓量、持卖仓量排名，数据源把三项排名合并成“每个会员一行”。“合约或品种”一列是一个合约（`SHFE/cu/2026-11`）或整个品种（`SHFE/cu`）：

- 合约级：每个交易所都有。某个会员没有进入其中一项排名时，该项为空或为 0，因交易所和年代而异（2026-10-09 上期所、能源中心是 0，其余四家为空）。
- 品种级的含义因交易所和年代而异：郑商所一直是按品种的会员排名；大商所在 2019 年及以前有，2021 年以后没有；上期所 2015 年是“活跃合约合计”的会员排名，2017 年以后是“期货公司 / 非期货公司”两类会员的合计，不是排名；中金所偶有一两行全为 0 的类别行。
- 会员名称原样保存，名称会随时间变化（2024 年以后郑商所带“（代客）”后缀）。
- 只保存期货：中金所回答里的股指期权（如 `IO2610`）不入库。
- 能源中心的排名不全：抽查的 5 个交易日（2021–2026 年）里从未有原油（`sc`）的排名，集运指数（`ec`）2024-06-17 有、2026-10-09 没有，而这两个品种当天都在日线表里。原因未查明。

### 存储、修订与快照

```text
<data-directory>/tables/
  ledger.sqlite                      分区登记，只追加
  objects/<前两位>/<对象摘要>.parquet   一个分区一次入库的内容，不可变，zstd
```

- 一个**序列**是（表、列定义版本、来源）。来源是数据源声明的标识，代表供应商和它的映射规则；规则变了就是另一个序列，不与原来的数据混在一起。列定义变了同理，旧定义的分区留在磁盘上但不再读取。
- 每次入库追加一条登记：序号、分区、内容摘要、对象摘要、行数、字节数、取得时间、数据源插件摘要、快照标识。内容摘要是对规范化后的行算的 SHA-256，与 Parquet 编码无关；对象摘要是文件字节的 SHA-256，读取时核对。
- 同一分区再次入库，内容相同则什么都不追加；不同则追加一条新修订，原修订和它的文件保留。
- **快照**是登记的一个前缀：`快照 n = SHA-256(快照 n−1, 第 n 条登记)`。在一个快照下，每个分区取序号不超过它的最新修订。任务记下快照标识就固定了它读到的全部数据。

没有删除入口，也不合并文件。六个交易所每个交易日 6 个日线文件，十几年约两万五千个；用合成数据测得读完全部历史约 1.7 秒（单线程）。

### 更新

在「数据 → 全市场数据」发起，或用命令 `data.tables.update.submit`。一次更新是一个任务，定义只有四项：数据源、要更新的表、起止日期、请求速率。读哪些分区在任务运行时由数据服务算出：

1. 先读每个交易所的合约表（每次都读，新合约每天都可能上市）。内容没变不产生新修订。
2. 再读交易日历：从该交易所最早的上市日所在的年份起，范围内还没有的年份，以及今年和以后的年份。交易所成立以前的年份不读——数据源没有那些年的日历，起始日期可以早于任何一个交易所的成立日。
3. 最后读交易日：范围内、日历上开市、不早于该交易所最早的上市日、上海时间已经结束、尚未入库的交易日，从早到晚。
4. 起始日期留空表示接着已有数据往后取，每张表每个交易所各自从自己已有的最后一天接着取；某张表在某个交易所还没有任何数据时，这一组不参与，并在结果里说明需要起始日期。结束日期留空表示到上海时间已经结束的最后一天。

每一步都依赖上一步入库的内容：合约表给出交易所从哪天开始，日历给出哪些天开市。合约表或日历读不到（被拒绝，或数据源返回 0 行），依赖它的交易日就无从计划，任务失败并说明是哪一个分区。

只读已经结束的日期，所以当天的数据要到次日才取得；这样不会把数据源只发布了一半的一天当成最终结果。

**分区在数据服务校验通过时就入库并可读，不等任务结束。** 任务取消、失败或被中断都不撤回已入库的分区；再次更新只取剩下的。任务进度按百分比报告。

每个分区有四种结果，写在任务结果里：

| 结果 | 含义 |
| --- | --- |
| 新入库 | 得到一条新修订 |
| 没有变化 | 分区已经保存着同样的内容 |
| 未能入库 | 数据不能用，附原因，精确到行和列，例如 `futures.daily DCE 2026-09-18: row 7 "DCE/i/2027-01" column amount: "1.5e3" is not a plain decimal number` |
| 数据源未返回数据 | 0 行；可能尚未发布，也可能数据源没有这段历史。不登记为“空”，下次更新再取 |

未能入库的分区达到 10 个时任务失败，以免映射规则有系统性错误时耗尽请求额度。凭据无效、没有接口权限、限流、网络错误让任务立即失败，失败原因来自数据源插件自己写的说明，不含凭据和供应商的报错原文。

凭据、共享额度和插件摘要的处理与按合约下载相同，见[下载凭据](#下载凭据)。

### 读取

计算任务不直接打开分区文件，向数据服务要“序列”：一个合约的收盘价，或一个品种的主力连续。请求给出快照标识、日线表和日历的来源标识、起止日期和 1–100 个品种或合约（`SHFE/rb` 或 `SHFE/rb/2026-10`），数据服务只读这个快照持有的数据，所以同一个请求永远得到同一批序列。

- 范围内的交易日以同一快照下的日历为准；日历没有覆盖的年份、日历上开市而日线没有入库的日子，都让请求被拒绝并指明是哪个分区或哪几天，不会跳过。一个请求只有一个范围：成立晚于起始日期的交易所，由提交方为它另发一个从它第一个上市日开始的请求（见[因子分析](factors.md#全市场数据表上的序列)）。
- 范围是完整的、而某个品种或合约仍然读不出时（范围内没有收盘价，或品种在某一天没有任何月份有数据），请求被拒绝，所有读不出的连同原因一起列出，不是只报第一个。
- 一个交易所范围内的全部日线分区用一次查询读完，只取需要的四列（合约、收盘价、结算价、持仓量）和属于所要品种的行，每个文件先核对摘要。600 个交易日、每天 240 个合约的合成数据上，逐个分区读取用 1.0 秒，一次查询读一个品种用 0.06 秒（Debug 构建）。
- 品种的主力月份、换月日和复权比例由数据服务按[主力连续](factors.md#全市场数据表上的序列)的规则从持仓量和结算价算出，连同每个月份在主力期间的收盘价一起返回。
- 一次请求合计最多 200000 个收盘价。

使用序列请求的是因子任务（`FactorSeriesRequest.tables`），见[因子分析](factors.md#全市场数据表上的序列)。按合约下载选合约也读这张表的合约表（`data.tables.contracts`）：给出快照、要下载的数据源和品种，数据服务读这个数据源所属插件自己的合约表（下载请求里的供应商代码是这个插件的），列出有上市日、退市日和供应商代码的月份合约；不向数据源发请求。下载按同一快照再读一次合约表，取供应商代码和存续期，未到期的合约下载到读取合约表时回复里给出的时刻（`cutoff_ns`），重新提交仍是同一范围。合约表没有入库时不能选合约，页面给出更新全市场数据的入口。回测和因子的 K 线数据集从同一张表、按同样的规则读结算价、持仓量和日线周期的 K 线，见[数据集输入](#数据集输入)。界面列出可选品种用 `data.tables.products`：一个快照的合约表里每个交易所有哪些品种、各有多少合约、最早上市日和最晚的最后交易日。

### 查看

「全市场数据」页列出每张表每个交易所的范围、分区数、行数、相对交易日历缺少的交易日和最近取得时间，可以翻看任一分区的内容。对应的只读命令是 `data.tables.coverage` 和 `data.tables.page`。缺少的交易日按提供该表的数据源的日历计算；日历没有入库时不给出数字。

行情页的历史 K 线在日 K、周线、月线、季线和年线上读这张表（`data.tables.daily`），不需要按合约下载：一个合约在当前快照里、从合约表的上市日到退市日之间已入库的交易日中，有竞价成交的每天一根；周线按周一至周日，月线、季线和年线按自然月、季、年聚合，标在期间最后一个有成交的交易日；MACD 从第一根起算。没有竞价成交的交易日和没有入库的交易日都不画、也不补，图上看不出这些空缺（缺少的交易日见上面的覆盖情况）。合约表没有入库、合约表里没有这个合约（合约表早于它上市时）或没有它的上市和退市日期时，请求被拒绝。分钟周期仍读按合约下载的分钟线。

## 当前 Tushare 适配

- 分钟线：1、5、15、30、60 分钟，按请求范围分段，可恢复。可按品种一次提交全部月份合约，每个合约一个任务；最多同时运行 2 个，通过数据服务共享同一授权的滚动请求额度。
- 日线：交易日与可缺失结算价；图表可聚合为周、月、季、年。按合约的日线要求每一行都有开高低收、成交量、成交额和持仓量，并把成交额存为 8 位小数的 `Decimal`：2026-10-11 用真实数据试探，无成交的合约（CZCE/jr/2026-07、DCE/bb/2026-09）和成交额大的合约（SHFE/rb/2025-10、CFFEX/if/2026-09）下载失败，冷门月份（SHFE/rb/2025-11）成功。全市场数据表没有这两个限制。
- 全市场数据表：合约表（`fut_basic`）、交易日历（`trade_cal`）、日线（`fut_daily`）、结算参数（`fut_settle`）、仓单日报（`fut_wsr`）、成交持仓排名（`fut_holding`），都按交易日和交易所读取。成交额由万元换成元；其余数值不换算。
- 仓单日报和成交持仓排名一天的行数超过接口的单次上限（1000 行和 2000 行），按上限分页读完；其余接口一次读完，行数达到上限时拒绝该分区，因为数据源在上限处截断而不提示。
- 数据源把能源中心的仓单和排名放在上期所的回答里，以能源中心为条件查询则没有数据：读一次上期所的回答，按品种分给两个交易所。
- 合约代码按合约表解析。郑商所自己的代码只有三位数字（一位年份），数据源补成四位时个别接口补错了年代：2019-06-17 的结算参数把 2020 年 3 月的苹果合约写成 `AP1003`。郑商所的代码在当天没有对应的在市合约时，按“字母加后三位数字、当天在市”的那个合约解析；合约表里这样的合约在任何一天至多一个。
- 排名里的品种写法有多种，都解析为品种：只有字母（`CF`）、中文名加字母（`尿素UR`，2023 年的郑商所）、`PTA`（郑商所对 TA 的称呼，仓单日报里也这样写）、字母加 `ACTV`（`CUACTV`，2015 年的上期所）。小写的合约代码（广期所）按大写处理。出现没有见过的写法时拒绝该分区，并在原因里列出这些写法，不猜测也不丢弃。
- 数据源并非每张表在每个交易所都有全部历史。2026-10-11 通过应用抽查了 11 个交易日（1996-06-17、2010-06-17、2012-06-15、2015-06-15、2017-06-15、2019-06-17、2021-06-15、2022-12-23、2023-06-15、2024-06-17、2026-10-09），下表是每张表在每个交易所**有数据的最早抽查日**所在的年份，不是确切的起点：

  | 表 | SHFE | INE | DCE | CZCE | CFFEX | GFEX |
  | --- | --- | --- | --- | --- | --- | --- |
  | 日线 | 1996 | 2019 | 2010 | 2010 | 2010 | 2022 |
  | 结算参数 | 2021 | 2021 | 2012 | 2012 | 断续：2015、2019、2021、2024、2026 有，2017、2022、2023 没有 | 2023 |
  | 仓单日报 | 2015 | 2019 | 2010 | 2019 | 不提供 | 2024 |
  | 成交持仓排名 | 2010 | 2021 | 2010 | 2010 | 2010 | 2024 |

  合约表里最早的上市日是上期所 1995-04-17，大商所、郑商所 1999-01-04，中金所 2010-04-16，能源中心 2018-03-26，广期所 2022-12-22；更早的日期没有数据可取。
- 没有竞价成交的合约没有当天的开、高、低价：数据源对上期所、能源中心给空值，对郑商所、大商所、广期所给 0。开、高、低、收为 0 一律存为缺失，不作为价格。少数合约当天有成交量（交割月和期转现的非竞价成交）而没有开高低价，同样处理。
- 代码不是“一到三个字母加三到四位数字”的行不入库：数据源自己编的主力、连续代码，大商所的月均价期货（如 `L2605F`），能源中心的结算价交易代码（如 `SCTAS2102`）。月均价期货是真实的合约，但统一合约身份还表示不了它，暂不支持；读取合约表时被排除的个数和例子记在数据源日志的 `contracts.outside_identity` 里。
- 合约目录要求供应商提供 `d_month` 完整交割年月，同时保留供应商合约代码映射；不依据当前年份猜测年代。[供应商目录字段](https://tushare.pro/document/2?doc_id=135)
- 分钟标签按 K 线结束时间（`bar_end`）保存。下载时核对：商品期货 1、5 分钟 K 线出现 10:30:00 标签（开始于 10:15–10:30 休盘内）即判定不是结束时间并拒绝。
- 交易日来自 Tushare 交易日历（`trade_cal`，按交易所、按年请求并缓存）：白天 K 线的日期必须是开市日；18:00 以后及次日 06:00 以前的夜盘 K 线归属开盘当晚之后的第一个开市日，且开盘当晚必须是开市日（周五夜盘归下周一，长假前的夜盘归节后首日）。日历未发布或与数据矛盾时拒绝，不猜测。
- 带交易日的分钟线与全市场日线表里同一合约的结算价组成回测与因子使用的 K 线数据集；日线周期的数据集整个取自全市场日线表（见[数据集输入](#数据集输入)）。
- 日线计算继续使用来源交易日和结算价。日线计算的排序坐标仅是执行模型坐标，不代表数据源提供了日内成交路径。

图表分页可以附加均线和 MACD；这些显示指标从数据集（日线图是合约的第一根日线）起点计算，不改变原始记录。生产历史数据源目前仍只有 Tushare，测试中的替代数据源只验证隔离，不进入生产注册表。

## 历史时间与可知性

行情标签时间、交易日、来源公布或可知时间、系统取得完整版本的时间是不同概念。
分钟与日线 manifest v4 固定 `source_availability: "unknown"`：当前提供者没有可核验的
历史公布时刻，不能从交易日、日线的 15:00 排序标签或下载时间推断。部分下载的
`acquired_at_ns` 为 `"0"`；最后一批数据完成时，与完整 manifest 一起持久发布系统 UTC
纳秒时间。恢复部分下载只在完整版本发布时记时；已经完整的版本重开不改写该值。
此时间表示整版在本系统可用，不证明每条记录最初何时取得，也不证明供应商当时公布过。

新取得操作即使返回相同行情字节，也有自己的取得证据和 manifest 身份。行情内容摘要
仍只描述合约、周期、K 线与结算日；取得证据不会改变相同字节的内容摘要。
Data 解析输入时，将行情与结算版本的并集按身份排序，各携带一次取得证据，随固定输入
交给 Task。
任务文件摘要固定全部证据，结果读取原输入，不能用当前时间补写或由 UI 猜测。
不支持的 manifest 或缺少证据的旧输入明确拒绝，原文件保留，不自动迁移。

回测与因子结果展示取得证据和结论范围：可作事后统计及既定模型下的回放，不能据此
声称验证严格历史可交易性。支持有公布时间证据的来源需要新的实际提供者契约；当前
不提供空的逐行 PIT 存储、自动历史修订或推测公布时刻。

## 数据集输入

日线和分钟线都可用于回测与因子分析；分钟数据必须具备交易日和 `bar_end` 标签语义，Tushare 分钟线的交易日来自交易所交易日历。

**分钟 K 线来自档案版本；日线 K 线和每个交易日的结算价来自全市场日线表。** 结算价是[全市场数据表](#全市场数据表) `futures.daily` 里这个合约当天那一行的结算价，按选择数据时日线表的快照读取，之后入库或更正的数据不改变已经选好的数据集、已保存的数据集和已提交的任务。主力连续选月份用的持仓量也取自同一张表。不需要、也不能再为结算价另选一份“按合约的日线下载”；按合约的日线下载也不能选作 K 线（`bar source must be a completed minute download`）。规则：

- 读取的范围是所选的起止交易日。分钟线留空的一端取 K 线的第一个或最后一个交易日；日线没有档案版本来界定范围，起止交易日都必须给出（`daily bars of the daily table require a begin and an end day`）。范围内交易日历标为开市的每一天，日线表都必须已经入库，缺一天就拒绝并列出交易所和日期（`futures.daily is missing trading days of the range: SHFE 2026-09-24`），不会绕开缺的那天；范围内的日历年份没有入库同样拒绝。先在「数据 → 全市场数据」把范围补齐。
- 有 K 线的交易日在日线表里没有这个合约的结算价时拒绝（`futures.daily has no settlement price for SHFE/rb/2026-10 on 2026-09-23`），不补、不沿用前一天的。
- **数据集的交易日是这个合约在范围内有结算价的每一天，不只是有 K 线的那些。** 合约当天没有成交、停牌，或分钟线缺这一天的下载时，这一天没有 K 线，仍然是数据集的一个交易日：回测在这一天不能成交，持仓照常按当天的结算价结算。选择时写明这样的交易日有多少个、是哪几天（主力连续只算主力月份的），不自动补齐。数据集格式是第 5 版（合约单位来自数据，并记下最小变动价位的改动）；更早版本保管的任务输入和已保存数据集只拒绝读取，不改写。
- 合约乘数和最小变动价位来自数据，见下面的[合约单位](#合约单位)。K 线的四个价格是它那个交易日的最小变动价位的整数倍。结算价不受这个限制：它是交易所公布的数，不是委托价。股指期货最后交易日的结算价是交割结算价，取到两位小数——2026-09-18 的 IF2609 是 4508.38，而它的最小变动价位是 0.2。
- 数据集记下日线表的快照、日线来源、日历来源和合约表来源，以及所读日线分区中最晚的取得时间；实验参数和“历史可知性”里都能看到。

### 合约单位

数据集的合约乘数和最小变动价位来自数据，选择数据的表单里没有这两项；选好的数据下面写着它们（最小变动价位改过的写出改动的日期，例如“最小变动价位 0.05、2019-12-10 起 0.02 · 合约乘数 1000”），实验参数里也有。

- **合约乘数取自合约表。** 按同一个快照读合约表（`futures.contracts`）里这个合约那一行：合约乘数（没有时为 1）乘每手数量；报价单位是“每 500 千克”而交易单位是吨时（鸡蛋）再乘 2。报价单位和交易单位的其它组合不认识时拒绝并指明合约（`the contract table's units of … cannot be read`），不猜，现有的 89 个品种里没有这样的组合；合约表里没有这个合约（`the contract table has no SHFE/rb/2026-10`）或这个交易所的合约表没有入库（`the contract table of SHFE is not stored`）时同样拒绝。
- **合约乘数用成交额核对。** 合约表给的是合约现在的交易单位，交易单位改过的品种的旧月份对不上。一天的成交额除以成交量是一手值多少钱，除以当天的结算价就是成交额所说的乘数。所读的交易日里，有成交额的那些要有一半以上与合约表推出的乘数相差不到 5%，否则拒绝并给出成交额推出的数：2018 年改为 10 吨一手之前的燃料油月份就是这样（`the contract multiplier does not match the turnover of SHFE/fu/2017-09: its days imply about 50`），改后的 `SHFE/fu/2019-01` 按 10 读得出。容许 5% 和“一半以上”是因为交割月的成交额里有不在当天价格上成交的部分。日线表里没有成交额的交易日不参加核对，一天也没有时不核对。分钟线数据集同样核对，用的是它那些交易日在日线表里的行。
- **最小变动价位按交易日从价格推出。** 合约表里的最小变动价位说明是现在的值，而交易所改过：黄金 2019-12-09 以前是 0.05，现在是 0.02；塑料和 PVC 2021-10-29 以前是 5，现在是 1。一个交易日的最小变动价位是这个品种价格的最大公约数：取它所有月份有竞价成交的开、高、低、收价，在它有成交的交易日里，截至当天的 20 个和从当天起的 20 个各求一次最大公约数，取较大的那个。当天的价格在两段里都有，所以结果总能整除当天的每一个价格；跨过一次改动的那一段只剩新旧两档的公约数，另一段整段在当天这一档上，较大的就是当天的。几天的价格可能碰巧都在更粗的格子上，二十天的从来没有（用全部日线核对过，见[整改记录](reviews/audit-progress.md)）。
- 读的不只是数据集的范围，还有它前后各 20 个已入库的交易日，所以同一天在不同范围里读出的最小变动价位相同；入库数据的开头和末尾不足 20 天时用最前或最后的 20 天，品种在读到的交易日里一共不足 20 天有成交时用全部。一天在日线表里没有这个品种的竞价成交价、却有分钟线 K 线时拒绝（`futures.daily has no auction prices of SHFE/rb on 2026-09-25`）。
- 数据集记下第一根 K 线那天的最小变动价位和此后每次改变的日期与新值。回测按 K 线所在交易日的最小变动价位撮合、计算滑点；因子和策略看到的主力连续复权价也取到当天的最小变动价位上。

### 日线 K 线

日线数据集不引用任何档案版本（`source_dataset_ids` 为空），周期记为 0，数据源记为日线表的来源标识（如 `tushare.fut_daily.v3`），没有档案的取得证据，只有日线分区的取得时间。

- **有竞价成交的交易日是一根 K 线。** 合约当天那一行有开、高、低、收和成交量，就是一根 K 线，时间标签是该交易日 15:00（上海）；这个标签只用来排回放次序。
- **没有竞价成交的交易日没有 K 线。** 日线表在这样的日子没有开、高、低价（见[当前 Tushare 适配](#当前-tushare-适配)）：全天无人成交的，以及只有非竞价成交的——交割月里常有“有成交量而没有开高低价”的行，2026-10-09 的 `DCE/j/2026-10`（10 手）和 `GFEX/ps/2026-10`（20 手）就是。这两种日子都没有一个订单可以成交的价格，所以不造 K 线，也不拿收盘价（此时等于结算价）充当。合约当天有结算价时，这一天是数据集里一个没有 K 线的交易日。
- 范围内一根 K 线都没有时拒绝（`no bars fall inside the requested trading days`）。
- **按品种的主力连续。** 请求给出交易所、品种和起止交易日（`ProductBarsRequest`），不列月份：数据服务把这个品种在范围内的全部月份合约一次读出，范围内有过竞价成交的月份参加，按[主力连续与换月](backtest.md#主力连续与换月)的同一套规则排出换月日程。参加的是范围内有过 K 线的月份；谁是主力按各月份在日线表里的结算价和持仓量排，当天有没有成交不影响。一个月份最迟在日线表里它有结算价的最后一天被换下；被换下的月份保留到它从换月日起的第一根 K 线（持仓在这根的开盘价平掉）和再下一根。返回的各月份数据集，与单独按该合约、同一段交易日读出的逐字节相同，所以任务固定输入之后的重读和校验与普通合约没有区别。范围内成交过的月份不足两个时拒绝。

在 K 线数据选择区可将已选合约保存为具名数据集；保存合约、日期区间、K 线的全部固定档案版本和读取结算价与合约单位的数据表快照。“拼接更多下载”可显式组合同合约、同周期、同口径的分段下载；重复记录去重，冲突拒绝，不覆盖原始档案。恢复会先核验整组输入，全部成功后再替换当前选择。已有任务的参数与结果保持固定；同名不同输入产生独立版本，不覆盖旧记录。数据集属于当前数据服务，切换服务后需要选择该服务中的数据集。存储边界与限制见下文。

下载任务确认成功并发布历史仓库后，任务摘要中的 `history_dataset_id` 指向已发布版本。
回测与因子的 K 线序列请求使用 `contract`（如 `SHFE/rb/2026-10`）、`source_dataset_ids` 列表（manifest SHA-256，分钟线 1–32 份，排序后固定，拒绝重复标识，单份输入也使用列表；日线为空）和 `daily`（数据表的快照、日线来源、日历来源、合约表来源）。K 线数据集的格式是第 5 版；此前的格式不再读取，不自动迁移持久化输入。
因子任务里，数据表序列读全市场日线表；K 线序列和回测一样固定所选 K 线的全部版本和日线表的快照。
提交时再次读取、校验并固定输入，不根据后来新增的下载重新选择数据。按品种的日线主力连续在提交时由数据服务按同一个快照重新找出月份，固定进任务的是找到的各月份数据集和换月日程，不是“品种”这个请求。

Terminal 的数据选择区每次显示一种添加数据的方式，各是一张独立的表单：

| 方式 | 填什么 | 命令 |
| --- | --- | --- |
| 日线合约 | 合约（`SHFE/rb/2026-10`）、起止交易日 | `data.dataset.daily` |
| 日线主力连续 | 品种（`SHFE/rb`）、起止交易日 | `data.dataset.product` |
| 分钟线合约 | 一份或几份分钟线下载、可选的起止交易日 | `data.dataset.select` |
| 分钟线主力连续 | 同一品种至少两个月份的分钟线下载 | `data.dataset.series` |
| 已保存数据集 | 一个具名数据集 | `data.dataset.use` |

日线的两种方式不需要下载任何按合约的数据，只要求全市场日线表覆盖所选范围。从历史数据仓库或下载完成条目点“用于回测”进入时打开的是“分钟线合约”，并已选好那份下载；只有分钟线下载有这个入口。结算价不需要选择：页面显示日线表在该交易所已入库的范围和读取所依据的快照；日线表里还没有该交易所的数据时不能使用，并提示先更新全市场数据。最早和最晚的入库日说明不了中间缺不缺：范围内还有交易日没有入库时，页面在这句下面给出个数；范围内的交易日历没有全部入库、数不出来时，说明无法判断。两种情况都不妨碍选择——用到没有入库的交易日时请求会被拒绝并列出日期。
切换数据服务或在读取期间修改已选数据会使旧选择响应失效；读取仓库与校验数据不持有 Terminal 全局操作锁。
“研究”工作区的 K 线数据选择区支持“保存当前选择”，并可从“已保存数据集”恢复，用于回测和因子的 K 线序列。
命名数据集由数据服务保存于 `history/named-datasets/<sha256>.pb`，包含合约、日期区间、K 线的档案版本、数据表快照及已解析内容摘要，不复制行情文件；格式是第 4 版。另一版本保存的数据集留在原处、不再列出，列表下方给出它们的数量；需要重新选择数据并保存。
记录不可变：同名同输入重复保存复用记录，同名不同输入创建独立版本；数据服务重启后仍保留。名称最多 120 UTF-8 字节，界面最多 40 个字符；最多保存 1000 个版本，每个最多 20 合约、共计 200000 根，交易日必须一致。
保存时重新验证全部档案；使用时重新解析并核对每个内容摘要，再一次性替换 Terminal 当前选择。读取失败或数据服务连接／当前选择在读取中改变时，拒绝替换。已有任务和账本的固定输入不受影响。
选择一个来源后，可以展开“拼接更多下载”，勾选同合约、同周期的其他 K 线下载。默认只使用当前选择，不自动合并仓库中的新下载。界面显示 K 线的份数，实验详情记录全部版本。
拼接在数据服务内完成：每个输入核验摘要、合约、完整状态，并要求相同数据源、标准化版本、时区、标签和计量语义；K 线周期也必须相同。先按所选交易日裁剪，再按时间排序；相同时间戳的计算输入的 K 线字段完全一致才去重，交易日或 OHLCV 不同则拒绝，不采用“最后写入优先”规则。结算价只有日线表一个来源，不存在拼接。跨来源拼接、连续合约换月、自动修订均不支持。
拼接后按唯一 K 线统计容量；合约有结算价而没有 K 线的交易日继续列出，不声称日内完整。具名数据集固定全部分段版本，恢复时重新解析并检查内容摘要；新增下载不会改变已保存输入。旧格式仅拒绝读取，原文件不删除或改写。
历史仓库提供“下载后续数据”和覆盖核对中的“补齐缺口”，都先预览准确的请求范围，再创建普通下载任务。日线从所选版本原始请求结束日的下一日开始；分钟线从原请求结束后的下一秒开始，分数秒边界会重取该秒以避免遗漏。结束日期最多为上海时区已结束的日期。这是相对单个固定版本的增量，不会扣除其它下载范围，也不保证该合约在所选日期有数据。

补齐按全市场日线表核对整日缺口（与覆盖核对相同：表中这个合约有成交、分钟线版本却没有的交易日），并重新下载原分钟版本的完整请求范围。日线表没有交易时段，因此不推算缺失交易日的夜盘起止；预览明确展示完整范围和待核对日期。数据源可能仍不返回缺失记录，完成后需要重新核对覆盖，不宣称数据已经完整。

预览固定基础版本、日线表快照、限速和请求范围的摘要；提交时 Terminal 重新核对计划，Data 固定输入授权，Task 按授权接纳。供应商凭据、凭据快照、限速、进度及显式重试沿用普通下载任务；新任务持久化实际下载参数，不额外保存基础版本的派生关系。完成后生成独立历史版本，原文件及已保存数据集不变，用户检查后显式拼接或选择。该入口使用当前节点固定配对的数据与任务服务。

仓库每个版本的“使用情况”合并当前任务服务中的来源下载、回测、因子任务引用，以及当前数据服务中的已保存数据集引用。来源下载标记为下载产物，计算任务和已保存数据集引用的版本标记为行情输入；同一记录的多个角色合并展示。日线数据集不引用档案版本，所以按合约的日线下载只在被因子的日线序列直接读取时才算被引用。任务处于完成、失败或取消状态也不会丢弃来源关系。Terminal 另外显示查询时本窗口回测与因子草稿的引用；刷新会重新核对，版本切换或服务切换后的旧响应不得覆盖当前结果。读取失败时清空旧结果并报错，不显示成无引用。



已连接节点上的其他数据与任务服务也参与检查，本机走 IPC、远程走 mTLS，不创建轮询客户端、不切换当前数据服务或草稿。当前数据服务端点在本机按 Socket 与会话、远程按地址、会话和 TLS 身份去重；其余服务按节点和服务分别展示任务／已保存数据集引用，同名任务不跨服务合并。服务按固定版本标识扫描持久输入，不要求本地保存对应历史文件副本；无副本也可能存在引用。停止的远程服务、清单失败、认证失败、损坏记录和超时明确标为未检查，不启停服务、不访问远端文件。其他运行中数据服务的每次网络查询最多 5 秒，所有节点的数据引用查询共用 20 秒截止时间；Agent 清单刷新沿用节点时限，回放检查沿用上述时限。只代表已连接且可核对的服务，不是全局依赖索引。

停止的本机任务服务仅在 Agent 清单给出的账本与当前环境 `services/<service>/ledger` 完全匹配且路径无符号链接时检查。复用任务服务的当前持久化格式校验，以已有 `manager.lock` 的共享只读锁阻止与服务独占写入并行；缺锁、服务占用或路径不符直接拒绝，不补建锁。SQLite 使用只读连接与读取事务，不建表、不改变运行中任务状态、不重算回测／因子结果、不重新发布历史版本。下载产物通过已提交结果记录的摘要和固定源版本标识核对引用，不扫描全部历史 K 线，也不宣称数据或结果可恢复。停止的数据服务明确显示未检查，尚不提供离线命名数据集引用扫描。离线检查上限为 100000 条记录及 256 MiB 原始记录，活动任务仍限 1000 个，终态历史不计入该活动上限；文件读取不属于上述网络超时承诺。SQLite 自身可能生成 WAL/SHM 协调文件，但任务记录、账本内容与历史文件不改写。检查期间显式启动服务可能遇到锁冲突，需要稍后重试。

本机登记目录中的未连接节点（包括尚未完成登记的名称）单独列为本次未检查。仅枚举名称，不读取证书、私钥或登记文件内容，不自动连接；清单无权限、符号链接或超限时显示范围不完整。尚未登记、仅保存在设置表单中的草稿配置不属于此清单。查询前后登记名称变化会拒绝过期结果。

这些结果是本次查询的分段观察值，不是全局依赖快照或删除许可。本机自选目录、停止的远程账本、未连接的节点、停止的远程数据服务、其他窗口的回测与因子草稿不在扫描范围内，跨服务复制的数据来源也没有全局反向索引。当前物理删除入口保持关闭，不会因查询无结果而允许删除，也不会自动修改任务、具名数据集或行情文件。

定时自动更新、精确交易时段补齐、未连接节点的引用核对、删除和依赖清理尚未实现；因子的日线序列仍直接选择单个档案版本。
