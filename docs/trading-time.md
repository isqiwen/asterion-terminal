# 交易时间与交易日归属

固定时间契约、日历校验和时间解析已由独立 L2 Rust 插件 `trading-calendar` 实现；Python `asterion.trading_time` 保留版本持久化与 HTTP 用例，使用生成类型和原生索引。通用机制不解释交易所和节假日。见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。

## 唯一当前契约

`TimeSpec` schema 1、`TimeVersion {id,spec}` 为完整、不可变、内容寻址的时间依据。版本由规范 JSON 的 SHA-256 标识，保存幂等，修改生成新版本，不自动覆盖、升级或修复旧记录。

- 时区固定为 `Asia/Shanghai`。时间戳必须携带时区；可接收 UTC，再转换为交易所当地时间。自然日、交易日分别保留。
- 一个版本对应一个交易所和品种代码，不以合约月份匹配时段，不跨交易所或跨品种回退。
- `calendar` 按自然日连续排列，包含周末和节假日。每行必须明确 `is_open` 和 `night_open`，没有默认值或“按周一至周五生成交易日”的代码。
- `night_open` 表示**该自然日晚上**是否开放夜盘，不能理解为该行交易日是否含夜盘。关闭的自然日不能设置夜盘开放。没有夜盘的品种使用空 `night` 时段，即使交易所当天开放其他品种夜盘也不会生成该品种夜盘。
- `periods` 按**目标交易日**连续生效，分别列出日盘、夜盘时段，显式声明结束是否跨一个自然日及阶段 `auction` / `continuous`。同一品种历史上发生夜盘增减或收盘时间变化，通过新生效期间表达。
- `exceptions` 按目标交易日替换整天的日盘与夜盘安排，带独立依据；可表示临时停盘、提前收市、节后日盘集合竞价。空时段表示该品种停盘，不更改其他品种。
- 日历必须包含规则生效起日前的开市日，并完整覆盖全部期间。缺失、重复、重叠、错品种、未知范围、错误指纹明确拒绝。

日历开休市与夜盘安排是不同依据。Tushare `trade_cal` 没有夜盘停开字段，不能据此自动认定节前夜盘开放。配置必须提供日历来源、夜盘安排来源和各期间依据；这些来源文本是配置者声明，不是自动认证的交易所公告。

## 归属算法

对于每个目标开市交易日 T，找到固定日历中前一个开市自然日 P：

1. 当 P 的 `night_open=true` 且目标交易日对应的品种规则有夜盘时，将夜盘时段锚定在 P；跨午夜的结束时间锚定在 P+1。
2. 日盘锚定在 T。所有生成的绝对时段排序并验证不重叠。
3. 输入时间戳在绝对时段中唯一匹配时，返回交易日、日/夜盘标记及集合竞价/连续交易阶段。不匹配明确拒绝；不会滚动到“最近交易日”。

因此正常周五晚和周六凌晨可以归属于周一，但周日晚不因此成为周一夜盘。节前最后开市日若明确关闭当晚夜盘，节后第一个交易日只生成其日盘；节后当晚开放的夜盘归属下一个开市交易日。调休周末是否交易完全以固定交易所日历为准，不能使用行政工作日历替代。

事件时间使用 `[开始,结束)`；K 线结束标记使用 `(开始,结束]`。分钟/小时线输入可省略 `trading_day` 列，由固定时间版本推导；提供该列时必须与推导结果一致，错误标签不自动改写。分钟/小时线导入须明确 `bar_start` 或 `bar_end` 及频率，校验完整时间区间位于一个连续交易时段内，不能跨午休、闭市、集合竞价或交易日。仅校验一个端点不足以接收该 K 线。

## 现有产品接入

- 时间版本保存、列举、事件归属查询、交易日时段查询由 Rust 入口的 `/trading-time` 接口（[trading_time.rs](../services/server/src/trading_time.rs)）直接调用 L2 交易日历实现，受账户认证与功能请求范围约束；版本表 `trading_time_versions` 由入口按当前声明校验或创建，结构不符拒绝启动。已保存版本不符合当前契约时明确拒绝（409），不改写。离线备份核验仍在 Python 读取该表（随切片 7 移出）。
- 数据导入与规则编辑均有时间版本选择、配置及文件导入/导出。基础配置可填写单个生效期间、日夜盘时段与完整自然日日历；复杂历史分段与临时例外通过规则文件定义。
- 日内 CSV 导入强制绑定时间版本、频率、时间戳口径；Worker 和发布端重新校验，不能绕过预览。时间版本随导入任务及目录 `import_options` 固定保存。
- 原始供应商日线没有逐笔事件时间；同步保留供应商 `trade_date`。本地日线可在导入时选定时间版本检查开市日期；未选时只是保存来源声明。研究则**必须**通过合约规则绑定时间版本，并检查全部行情交易日、请求范围及品种。
- 研究固定覆盖报告中的开休市状态与时间版本日历冲突时拒绝执行，包括重跑、发布与离线复现。交易时段不是对原始日线内部夜盘完整性的证明。
- 研究当前唯一引擎 `daily-session-settlement.v6`：信号在交易日日盘最后连续时段结束后计算，下一存在日线的第一个连续时段开盘执行，可能发生于该交易日标签之前的夜盘。成交记录同时记录交易日与带时区的模拟成交时间；资金账记录时段起止、时间版本。
- 日线开盘价解释为整个交易日首个连续时段开盘价。日线数据不能证明逐笔的可成交性，不能从日线重新验证所有夜盘分钟是否齐全；来源聚合口径必须核对。探索模式允许日线缺口，但时间依据缺失不能绕过。
- 时间版本嵌入规则、草稿、固定任务、复现包及 `rules.json`。`fills.csv` 包含成交时间，`settlements.csv` 包含时段起止与时间版本。独立时间版本库也参与备份恢复校验。

尚未实现自动采集、认证并维护全市场历史时段公告。系统支持六家交易所代码及可声明的品种时段，不等于内置了所有品种、全部历史期间的权威规则。没有有效配置的范围明确不可用，不自动补成同一套夜盘规则。当前没有逐笔/分钟回测、实盘撮合或时段公告自动升级。

## 配置示例及验证

[RB 固定验收时间规则](../examples/validation/rb-trading-time.json)只覆盖 2025-01-06—17，并包含前置自然日日历；不作为其他品种、年份的默认值。真实 Tushare 验收会重新获取包含前置开市日的日历，并与时间规则逐日比较后执行及复现。

专项覆盖：跨周末和跨午夜、UTC 转换、节前夜盘关闭、节后首日与恢复夜盘、无夜盘品种、午间休市、临时品种停盘、目标交易日的历史时段变更、集合竞价与 K 线结束边界、缺失/重复日历、时段重叠、错交易日、错品种、认证及指纹篡改。

设计依据：[上期所交易规则](https://www.shfe.cn/regulation/exchangerules/rules/202606/t20260603_831934.html)、[交易时间](https://www.shfe.cn/services/calenderandholidays/tradinghours/)、[2025 年休市安排](https://www.shfe.com.cn/publicnotice/notice/202412/t20241223_824109.html)。验收样例夜盘时段参照[2022 年螺纹钢期权上市通知](https://www.shfe.cn/publicnotice/notice/202212/t20221220_799651.html)中与标的期货一致的说明；样例不构成全历史规则认证。
