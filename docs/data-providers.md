# 数据源配置与 Tushare

本文记录当前历史数据采集契约（来源适配已为 Rust，采集编排仍在 Python，迁移进度见[进度](ROADMAP.md)）。目标中业务连接/配置由 L2 Rust 插件 `connections` 管理，采集用例为 L3 `data-ingest`，来源实现为独立 L3 适配器（如 `provider-tushare`）；秘密操作消费 L1 公开机制。目标尚未实施，见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。通用版本/存储/归档规则见[数据生命周期](data-lifecycle-design.md)，文件导入与具名实例见[数据与连接管理](data-import-and-connections.md)。

## 使用与配置

在设置的“数据源”配置 Tushare 连接，再到“数据 → 数据同步”选择连接、交易所、能力和范围。合约资料取普通合约；日线、结算及分钟使用实际月份合约，角色映射使用来源明确支持的主力代码。文件导入使用独立“导入数据”入口。任务中心负责进度、取消、重试和采集证据；数据集负责固定版本、预览、图表与覆盖。

“测试当前配置”不保存草稿；Tushare 测试仅探测交易日历接口，不证明其他接口权限。缺少必需配置不能提交任务，历史验证成功也不代表当前可用。实际权限和限流由来源控制，离线夹具不能替代真实联调。

配置由 Rust 数据服务（`services/data`：configuration、credentials）校验、加密与读取，Python 只经绑定句柄使用，不持有运行密钥或加密原语。配置加密保存在 `.credentials/configurations/<ref>.enc`，目录0700、文件0600，数据库保存修订和引用；ref绑定配置、修订及本机密钥。任务固定配置引用/schema，不含秘密明文，公开产物也不含秘密。界面保存后清空秘密输入，不写浏览器持久存储。缺少固定配置或密钥时失败，不改用当前或其他连接凭据。

修改、停用或归档连接保留已接受任务和加密快照；停止既有任务须取消。密钥丢失不能用新配置修复旧快照，回收与轮换不能删除历史依赖。当前加密不防御同系统用户权限的代码，完整备份包含解密密钥，处理要求见[备份文档](backup-and-restore.md)。

## 当前提供方边界

来源端口为 L2 `domain/data-store` 的 `provider`（API v2）：来源声明配置、能力、数据类型、范围、周期和采集约束；适配器负责外部协议、单位及代码解释，不写数据库或直接发布。所有计划经同一准入检查（`checked_plan`：分段有界、日期连续且恰好覆盖请求）。内置来源表在 `services/data`（`providers`），Tushare 适配器为 `services/adapters/provider-tushare`（Rust，含 HTTPS 拉取与重试）。同步流水线尚在 Python 时，`providers/public.py` 的请求与分段模型及 `Tushare` 类只经绑定调用 Rust 实现，不另有第二份计划或映射逻辑。数据类型负责标准字段、单位、主键与校验。同步任务由入口的采集执行器执行（`services/data` 的 collect）：认领任务，续传核验通过的分段，其余分段在数据库事务之外向来源拉取，每段观察在租约内登记并续租、上报进度；拉取失败时登记受控错误类别的失败证据并以 `<类别>：采集失败…` 结束任务。采集完成后，入口以 worker 身份把证据交给尚在 Python 的发布（`/jobs/{id}/publish-data`），发布拒绝时以其原因结束任务。Python worker 不再认领同步任务。

正式内置来源为 Tushare；数据源只能是随发行版编译的 Rust 实现，不能安装、停用或替换。测试不再注册非内置来源：Python 测试以 Tushare 适配器加固定样例响应代替网络拉取，Rust 测试以测试内构造的来源声明检验连接与配置逻辑。`demo=true`资料不能转为真实市场数据或研究输入。

| 能力 | 当前范围与语义 | 官方字段依据 |
|---|---|---|
| 合约资料 | 普通合约；单次返回触及上限拒绝，不能把截断资料当完整目录 | [fut_basic](https://tushare.pro/document/2?doc_id=135) |
| 交易日历 | 按最多31自然日分段；当前声明五家交易所，不猜GFEX支持；不提供夜盘开闭证据 | [fut_trade_cal](https://tushare.pro/document/2?doc_id=467) |
| 实际合约日线 | 单合约、最多31自然日分段；标准OHLC、成交/持仓与结算字段 | [fut_daily](https://tushare.pro/document/2?doc_id=138) |
| 每日结算参数 | 实际合约日期范围快照；数值原样保留，单位/生效与适用性需显式确认 | [fut_settle](https://tushare.pro/document/2?doc_id=141)、[规则契约](contract-rules.md#每日结算参数与明确研究假设) |
| 主力映射 | 固定日期范围的 `futures.role_mapping`，不是价格序列，不猜历史发布时间或次主力 | [fut_mapping](https://tushare.pro/document/2?doc_id=189)、[角色契约](contract-roles.md) |
| 多周期分钟 | 直接下载供应商1/5/15/30/60分钟，单实际合约、单交易日，不做本地聚合 | [ft_mins](https://tushare.pro/document/2?doc_id=313) |

日线成交量和持仓量为手、成交额为万元；分钟成交额为元。日线图表的UTC零点是交易日标签，`frequency=1d`、`time_semantics=trading_day_label`，不是收盘事件时间。来源观测/可知时间保持真实采集口径，不回填到历史日期。合约资料乘数/单位原值保留，映射规则见[合约规则](contract-rules.md)。

非法数值、重复键、越界日期/合约和OHLC冲突拒绝发布；当前图表只接受有限正价格及整数手。日历要求请求中的每个自然日都有记录；合约和日线仅声明返回行通过检查。空响应不能解释成休市或无成交，全部为空时失败。

暂时网络故障、HTTP429/5xx最多请求三次；权限、额度、结构错误使用受控信息，不回显上游原始异常。同步单次最多十年，发布体上限8MB、Worker在7.5MB提前拒绝；预览默认100行、最大500，图表最多1,000行。大文件上传、每日调度、自动补齐及孤儿回收尚未实现。

## 固定合约身份准入

合约资料当前schema4保留币种、完整交割年月、上市/最后交易日和最后交割日；Tushare从`d_month`读取完整年份，不按短码或当前年份猜测。资料以交易所、来源代码和上市日期区分生命周期。缺失完整身份的原始观察可保留，不能发布为可执行目录；发布方式见[合约目录](reference-data.md)。

`POST /api/v1/data/sync` 使用 `SyncSubmission`，由入口直接提供；请求约束、准入（分钟时段与窗口、合约身份目录）、任务身份校验、提交载荷与按 `command_id` 幂等的提交由 Rust 数据服务（`services/data` 的 sync）实现，身份目录由 L2 `domain/data-store`（identity）从固定合约资料构造。研究准备、历史计划、补齐与角色批量等尚在 Python 的调用方经绑定使用同一实现；重试接口因研究准备任务仍在 Python，暂由 Python 提供，但提交走同一实现。日线、结算和分钟能力必须提供 `contracts_version_id`，其他能力不接受非空值；宿主准入字段不传入供应商请求。界面显式选择同来源、同连接、同交易所的固定资料，变更相关输入后清空选择，不自动选最新或转换代码大小写。

入队前完整读取并校验来源文件，构造唯一身份目录并确认请求处于同一实际合约生命周期。`contract_identity`保存目录、指纹及信息截止时间，规范ID进入数据集范围。提交、Worker、发布、重试/补齐和恢复分别核验；发布重建固定资料并逐行比对，不能重算外层hash后伪造身份。缺少依据不入队，不自动补字段或重解释原记录。

研究准备中的待执行计划尚不可执行，资料发布后才能构造合格日线任务。文件导入使用显式 `ImportIdentity` 映射。当前已实现链路的F1范围见[身份验收](validation/f1-identity.md)，不代表尚未实现的正式交易已验收。

## 采集证据与续传

观察证据的记录、续传核验、列表、预览与发布前核对由 Rust 数据服务（`services/data` 的 observations）实现，下表前四个接口由入口直接提供；分钟行记录与交易时段的绑定属于 L2 `domain/data-store`（minute）。尚在 Python 的发布经绑定调用同一核对。每段观察以规范 JSON（排序键、紧凑分隔、Python 浮点表示）保存至 `sources/<job_id>/<attempt>/<index>/<checksum>.json`，摘要与迁移前记录一致，文件先持久化，再在有效租约内登记。接收状态为RECEIVED或EMPTY_UNCONFIRMED；失败只保留受控类别。后续失败、取消或标准化拒绝不删除已确认观察，取消时未确认写入的响应不保证留存。

这些观察不是已发布RAW数据集，也不是完整HTTP报文。当前保留插件返回的声明字段、固定参数、分段和采集时间，不保留被适配器拒绝的响应体或每次内部网络重试。标准发布必须与当前领取次数已登记证据一致；文件完整落盘后才事务登记RAW/STANDARD与来源边，失败孤儿尚不自动清理。

| 接口 | 用途 |
|---|---|
| `GET /api/v1/data/jobs/{id}/observations` | 按领取次数分页查看分段、状态、时间、hash |
| `GET /api/v1/data/jobs/{id}/observations/{attempt}/{index}` | 校验文件后分页预览原始行 |
| `POST /api/v1/jobs/{id}/observations/{index}` | 持有租约者用X-Lease-Token提交，单段最多8MB，相同段重传内容须相同（入口采集器在进程内调用同一实现） |
| `POST /api/v1/jobs/{id}/resume` | 持有租约者取得服务端核验通过的可复用分段 |
| `POST /api/v1/data/jobs/{id}/retry` | 用户重试；resume控制是否续传，默认false |

用户查询须满足会话及账户/PIN要求，Worker写入须满足任务授权和租约。任务中心展示采集详情，不能直接以这些观察供研究执行。

“继续同步”重验明确前序任务或同任务旧尝试的文件、请求、插件/类型版本，重新规范化并校验，保留原observed_at和reused_from。空、失败、截断、损坏或不符合当前契约的分段重新采集；日历缺日不能复用。“全部重新同步”重新观察原范围，才能取得供应商可能的新修订。旧任务记录保留，两种操作均创建新任务。

发布合并、行级来源和图表投影统一遵守[生命周期规则](data-lifecycle-design.md#采集发布与修订)。日线返回记录有效不等于没有缺口。

## 日线覆盖核对与手动补齐

在累积日线详情核对固定版本或明确选择最新版本，范围最多十年且不超过今天。当前同源核对可解析同连接/交易所最新日历和合约资料，也可显式指定；报告固定实际采用的版本，后续更新不改写报告。文件需显式关联外部依据，见[本地回测](local-backtesting.md#本地文件的外部依据关联)。

报告区分已有、缺口、休市、生命周期外、依据不足、当日未完成和冲突。资料不足不推断缺口，未结束当日不补取，冲突阻止补齐；结论不证明来源权威或历史可知。

“补齐确认缺口”只授权原报告确认的历史日期。提交时沿用其日历/资料重查最新行情并跳过已补日期，相邻缺口只能跨明确休市日合并。整批与命令幂等入队，失败不留下部分任务；网络重发原命令返回原任务。完成后显式核对新版本，不自动采用进研究输入。没有后台定时补齐或批次级取消。

## 一次准备研究数据

选择实际合约日线并勾选“同时准备研究依据”，一次冻结连接配置，在同一事务登记准备批次、日历/合约资料任务和待执行日线计划。合约资料发布后，从该确切版本生成身份，将资料发布、身份固定和日线入队纳入同一租约事务；不通过后台找最新资料补偿。

资料合法但身份不完整时保留资料结果，批次标记身份失败且不提交日线。新命令要求连接可用；已接受批次后续任务使用原配置。继续同步保留原请求、配置、身份和批次，同一尝试只有一个后继；要改配置须新建批次。最多读取200次尝试，超限或读取失败时暂停相关重试/核对。

界面恢复最近10批已落盘记录，不自动重发。各项成功且结果唯一后，“核对覆盖并查看数据”使用本批确切输出和原日期生成报告；成功采集不保证覆盖通过，不自动运行研究或替换草稿。数据任务为本机共享域，研究草稿按账户隔离；不支持跨连接借依据或定时调度。

## 多周期分钟实际合约采集

分钟任务必须固定资料、单交易日和 `TimeVersion`，明确bar_start/bar_end及其来源依据；不能凭官方示例自动认定bar_end。自然时间窗口由已确认时段生成，夜盘按固定版本归属，使用交易所时区。缺时段、错身份、休市记录、重复时间、非法OHLC或触及来源8,000行上限均拒绝发布。

能力声明frequencies，任务的 `minute_context.frequency` 与供应商请求、标准行、集合范围及版本类型保持一致；`1m/5m/15m/30m/60m`转换为接口的`1min/5min/15min/30min/60min`，不默认一分钟。周期和时间口径不同不得合并。

标准 `futures.minute` 保留event_time、trading_day与实际采集available_at，按交易日累积，补下载生成新版本，旧工件不变。1分钟覆盖按固定时段列出缺失；其他周期未核验跨休市和短柱规则，返回UNVERIFIED，expected/missing为null。缺失不自动补零，也不直接认定丢包；独立质量制品尚未持久化。

真实来源时间标记、夜盘边界和无成交分钟行为仍待验；用户权限声明不是联调证据。多日/多合约分钟计划、研究分钟扫描及千万行基准未完成，详见[分钟验收范围](validation/minute-downloads.md)。实时行情是独立市场用例，不经过历史发布，见[连接接入](broker-connections.md)。
