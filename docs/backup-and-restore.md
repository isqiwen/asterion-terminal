# 本机备份与恢复

本文为当前本机维护契约。[固定 Rust 内核](../kernel/src/file_archives.rs)负责有界流式归档、文件校验与提取，[目录提交机制](../kernel/src/directories.rs)负责完整目录一次性发布；[恢复机制](../kernel/src/recovery.rs)执行通用恢复操作的完整性、一次性执行和声明校验。备份内容的语义验证属于领域插件，物理备份格式与数据库、服务协调属于产品装配。完整模块边界见[架构设计](architecture.md)。

在桌面设置中打开“备份与恢复”，点击“创建备份并验证”。程序短暂停止本机后台，取得启动/监督进程锁，确认 PostgreSQL 已停止后复制数据库、行情文件和本机密钥配置。复制完成后恢复此前的服务状态，再在临时新目录实际启动独立 PostgreSQL 验证。此前已停止的服务不会被备份操作自动启动。

成功后显示备份完整路径、SHA-256、恢复后可读的数据版本与研究结果数量。默认存放在本机状态目录旁的 `Asterion Backups` 文件夹，文件名含唯一时间戳，不覆盖旧备份。数据量大时暂停与验证时间会增长，需预留备份压缩包及一次完整恢复的磁盘空间。源数据仍保留；复制失败后也会尝试恢复此前运行的服务，若后台未连接可在“本机服务”重新启动。

## 内容与边界

- PostgreSQL 物理快照：数据目录、覆盖报告、版本归档状态、任务、研究运行/草稿/模板/复现包、账户及 PIN 等数据库记录。
- `data` 下的行情、RAW 证据、累积分区、导入文件与加密凭据；`data/backups` 下的历史备份排除，避免递归复制。
- `desktop.json`：数据库认证配置与解密凭据所需的本机主密钥。备份 ZIP **未加密**，凭据密文和解密密钥同时在包内，应视为敏感文件；权限为当前用户读写（0600）。不要当作研究复现包分享。
- 不含前端浏览器偏好、窗口布局、服务日志、应用程序或 PostgreSQL 可执行文件；现有数据库外部表空间、符号链接和特殊文件不支持备份。

当前为格式 1 的本机物理备份，仅支持相同操作系统、CPU 架构和 PostgreSQL 主版本，推荐使用相同应用构建；不提供跨平台逻辑迁移、增量/WAL 连续备份、密码加密、云端上传或自动保留期清理。上限为 500 GiB 解压内容、一百万文件和一百万目录；清单及归档索引各限 128 MiB，生成与读取使用相同预算，本机配置读取限 64 KiB。备份只协调本程序管理的写入，不能同时用外部程序手工修改状态文件。

## 恢复到新目录

填写备份 ZIP 的完整路径及**尚不存在**的新目录，点击“验证并恢复到新目录”。只恢复可信的自有备份；逐文件校验和不认证备份提供者。恢复会检查当前清单结构、路径穿越、重复或额外文件、链接、长度、哈希及平台/数据库要求，拒绝包含数据库运行 PID 的在线快照。验证全部通过后，完整暂存目录才原子发布；并发创建的目标同样不会被覆盖。

验证失败且数据库已确认停止时清理暂存目录。若数据库停止超时、状态无法确认或清理过程被中断，则保留私有恢复现场并在错误中给出路径，目标目录尚未发布；先排查该隔离数据库，不能将现场视为完成恢复。目标已发布后发生的持久化或后续错误会明确报告，保留已发布数据，不执行删除回滚。

验证实际启动隔离端口的 PostgreSQL，启动参数固定使用暂存数据目录并核对数据库返回的实际路径，不接受备份配置将数据目录重定向到外部。只运行校验器，不启动 API 或 worker。校验包括读取数据库、全部已发布版本文件及其共享分区哈希、数据血缘引用、研究输入/结果指纹、内置引擎重新计算结果以及凭据解密。外部策略仅检查输入、结果和工件完整性，不自动执行；报告以 `research_external_not_recomputed` 计数。目录中的额外文件也按备份清单验证。

恢复目录的 QUEUED/RUNNING 任务改为 CANCELLED 并标注恢复隔离原因，租约清除，防止自动重复采集；原备份及当前环境不改变。登录会话清除，账户密码和 PIN 保留；数据库/API 端口重新分配，解密主密钥保留。恢复记录 `restore-report.json` 与完整目录一并发布，保留实际读取的备份 SHA-256、校验时间和数量。

恢复结束后数据库停止，**当前工作台不会自动切换**。确认目标后，使用下面的正式切换入口。不要在应用运行时手工覆盖原目录。归档不等于备份；只有复制到独立介质并验证恢复后才能抵御原磁盘故障。

## 正式切换与回滚

“使用恢复环境”显示当前目录、上一个环境以及最近已验证的保护备份。恢复成功后自动填写目标路径，点击“保护备份并切换”才开始正式切换，也可填写之前完成恢复的目录。

1. 独占宿主维护锁，拒绝同时备份、恢复或切换；多个窗口启动按序等待。目标必须完整、独立、离线，没有符号链接；新恢复环境必须具有当前格式的成功验证记录。
2. 持久化待切换记录，停止原服务，为原环境创建完整保护快照，并在临时目录实际恢复验证。空间不足或验证失败不会提交切换。
3. 再次实际校验目标数据库、行情文件、研究结果和凭据，不仅依赖旧恢复报告。目标的未完成任务取消、登录会话清除，分配新端口。
4. 启动目标 API 与 worker，确认两者就绪后原子保存活动环境。桌面宿主清除共享账户会话并重新加载所有窗口，用户重新登录。

固定宿主目录保存私有 `environment.json` 与维护锁；活动数据目录通过记录选择，不移动、覆盖或删除原目录。重开应用、服务详情、备份和停止服务都使用活动环境。目标目录不可用时会报错，不自动建立空环境。窗口布局仍保存在宿主目录，不随数据切换；未保存的界面编辑会因重新加载而丢弃，请先保存。

点击“保护备份并回滚”可返回上一个环境。回滚同样备份当前环境、验证目标并检查启动状态；切换后新增记录留在原目录和保护包中，不会合并进回滚目标。每次成功切换记录一个上一个环境，因此回滚后也可以再次返回。目标环境的未完成任务同样取消，避免无意恢复旧采集任务。

启动失败会停止目标并尝试重新启动原环境。进程意外中断时，下一次启动服务先根据待切换记录恢复原环境，再提供会话；若回退也失败，保留记录与两个数据目录供下次重试，不宣称已恢复连接。只协调此宿主管理的服务；不要对同一目录同时运行外部监督进程或另一份宿主控制器。

## 维护命令

正常用户优先使用设置界面。开发环境可执行以下命令；所有路径请替换为实际绝对路径：

```sh
uv run asterion desktop-backup --state /absolute/state --pg-root /absolute/runtime/postgres --output /absolute/backups/snapshot.zip
uv run asterion desktop-restore --state /absolute/host-state --pg-root /absolute/runtime/postgres --archive /absolute/backups/snapshot.zip --target /absolute/new-recovery
uv run asterion desktop-activate --state /absolute/host-state --pg-root /absolute/runtime/postgres --target /absolute/new-recovery
uv run asterion desktop-rollback --state /absolute/host-state --pg-root /absolute/runtime/postgres
uv run asterion desktop-environment --state /absolute/host-state --pg-root /absolute/runtime/postgres
```

`desktop-backup` 管理已运行服务的暂停/恢复并验证临时恢复；仅在本应用服务管理器管理的状态目录使用。`desktop-snapshot` 参数同上，仅创建离线快照，要求服务与 PostgreSQL 已停止，不宣称已经实际恢复验证；供打包烟测和维护使用。恢复命令不会调用服务管理器或切换工作台。

备份、恢复、切换和环境状态命令输出只含路径、摘要和数量，不打印密钥、凭据或数据库连接 URL。`desktop-info` 和 `desktop-bootstrap` 是原生宿主内部会话接口，包含本机会话令牌，不应分享其原始输出。命令失败时备份包可能已创建但尚未通过恢复验证，不能仅凭 ZIP 存在判定成功，应重新执行隔离恢复校验。

维护命令的 `--state` 始终传固定宿主目录；切换后也不要改成恢复目录。命令行切换不会通知已经打开的原生窗口，请先关闭桌面窗口，完成后重新打开应用。

## 固定领域依据校验

恢复校验包含全部覆盖报告的当前结构、嵌入身份目录的内容指纹、日线/日历/合约版本存在性，以及目录固定输入的来源与校验和。损坏证据拒绝恢复，不重建目录或改写报告；研究输入仍由研究插件独立核验。

文件导入的 `import_options.identity` 同时接受恢复校验：目录指纹、固定资料输入、来源与校验和必须一致，标准文件中的每行交易日必须能按原映射解析。恢复过程不重新选择目录，也不补齐缺失身份。

研究准备日志保存待执行日线计划、依赖阶段与固定来源身份。恢复校验检查计划与原请求、阶段与身份证据的一致性，以及身份所引用资料的存在性；同步版本的固定身份还须通过实际标准文件逐行校验。恢复不会重新选择最新资料或重新提交等待任务。
