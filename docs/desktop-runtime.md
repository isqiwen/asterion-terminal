# macOS / Linux 桌面运行协议

## 点击启动

原生应用使用打包后的 React 资源，不启动 Vite 或浏览器。Tauri 通过受限本机命令启动已安装环境的 `python -I -m asterion.runtime.cli desktop-bootstrap`，后台就绪后将当前会话通过原生 IPC 交给界面。浏览器访问不能调用此命令。

首次运行生成应用专用本地配置（目录权限 0700、会话文件 0600）。macOS 注册 `~/Library/LaunchAgents/me.asterion.terminal.backend.plist`。plist 保存受控可执行文件路径和状态路径，不保存口令或会话令牌。

macOS 由 launchd、Linux 由 systemd 用户服务启动 supervisor；supervisor 使用平台提供的 PostgreSQL 程序初始化独立集群，建立目录，再启动 serve/worker。PostgreSQL 使用本机回环 TCP 和 SCRAM 密码认证。每个业务进程的配置通过环境传入，无需读取项目 `.env`。

## 首次设置

首次设置在独立的 800×640 窗口布局展示，支持中英文，必须点击“开始设置”才下载。步骤为准备系统数据库与安装工具、安装 Python、创建隔离工作区、安装运行依赖、验证运行环境。网络下载以清单字节总量报告进度，解压和依赖安装没有可靠总量时显示不定进度，不伪造百分比。成功后点击“进入工作台”；之后启动直接使用本机环境，不联网安装。点击开始后，底部显示本次尝试的耗时、实时下载/上传速度及最近 40 秒下载折线。Linux 读取 `/sys/class/net` 下具有物理设备的网卡收发字节，使用采样单调时间差计算速度；这是本机物理网卡总流量，包含其他应用，不代表安装器独占流量。排除回环、网桥和虚拟网卡以避免重复计数。依赖安装、解压期间仍持续采样；初次采样、接口集合变化、计数下降或读取失败时显示“—”。macOS 尚未接入系统网卡统计，显示“—”，不回退到另一种流量口径。计时使用单调时钟，停止后移除统计，重试重新计时。按钮下显示依赖处理阶段、当前包名和已安装／总数。总数来自当前解释器与平台的 uv 解析结果；只在收到实际安装完成结果后更新已安装数，下载完成不计入。uv 并行下载、批量安装，数量可能从 0 直接变为总数；不人为逐个增加。计数不含 Python、uv、系统 PostgreSQL 或项目自身 wheel，安装项目时另行显示。

通用原生安装机制位于 `runtime_setup.rs`，安装清单由发行版构建层生成。核心不识别交易、数据或研究插件 ID，也不替业务插件下载市场数据。既有扩展点需要可用 Python 才能执行，无法表达安装 Python 之前的下载、校验、文件锁与进度，因此增加此原生机制。

环境固定在应用数据目录的 `runtime/`，下载缓存位于 `cache/`。清单摘要只保存于内部就绪记录，不用于目录命名；每次启动仍检查记录与清单是否一致。相同合法摘要直接复用；摘要变化且已发布环境完整时进入本次安装，独占安装锁后通过当前生命周期接口停止后台，再撤销就绪记录、清理安装器拥有的程序目录并在同一 `runtime/` 中安装。原生后台调用持有共享安装锁，更新期间不能重新启动旧服务。停止失败保留程序和记录，安装中断保持未就绪并允许重试，不回退执行上一版。非法标记或缺失的已发布程序仍拒绝且保留原文件。界面仅显示简短的用户数据根目录文字，不提供路径按钮或悬停提示。文件锁避免多个进程同时安装，安装子进程继承锁，桌面退出后直到该命令结束才允许重试；uv、Python 下载按 SHA-256 和大小校验；PostgreSQL 由 apt（Linux）或 Homebrew（macOS）验证和管理，依赖以 `uv pip sync --require-hashes --only-binary :all:` 安装，项目 wheel 按包内摘要校验。仅验证通过才写就绪标记，未完成的环境不用于启动后台。重试复用已校验下载缓存，重建本次未发布的环境；不清理数据库、历史结果或其他运行环境。下载中断的部分文件会在重试时重新下载，不声称支持 HTTP 断点续传。

不再生成或发布数据库附件。Linux `.deb` 通过 `postgresql-17` 依赖交给 apt 安装；macOS 的安装清单使用 `homebrew` 来源及固定 `postgresql@17` 配方，首次设置复用已验证的程序，缺失时执行标准 Homebrew 路径下的 `brew install postgresql@17`。缺少 Homebrew 时提示官方安装指引，失败保留错误及重试入口；不提权、不执行 `brew services`，不操作 Homebrew 默认集群。只接受当前平台的声明；未知来源、其他配方或非法路径明确拒绝。Python 和 uv 使用官方上游；不执行网络 shell 安装脚本、不依赖用户全局 Python、不回退到随包冻结后台。原生外壳仍需要操作系统提供 WebKitGTK 等桌面依赖。

## 生命周期

bootstrap 文件锁防止窗口同时执行初始化；supervisor 锁与固定服务名称 保证同一用户只有一个本机环境。多个窗口只获取已有会话，不重复创建环境。初始化使用暂存集群，成功后改名；初始化被中断后下一次可重新建立尚未发布的暂存集群。

关闭窗口和退出桌面进程不会停止后台服务。用户在独立“设置 → 本机服务”窗口点击“停止后台服务”时停止后台服务（macOS 卸载 launchd 服务，Linux 停止 systemd unit），等待 supervisor 停止子进程和 PostgreSQL；数据保留。“启动后台服务”再次注册并附着环境。

用户数据不在 `.app` 内，替换应用不会清空数据。当前运行契约固定 PostgreSQL 17；不自动转换旧数据库格式，不受支持的目录明确拒绝。

## 打包与验证

`scripts/build_desktop.py` 是开发构建入口。构建成功后仅将本平台最终安装包文件复制到根目录 `release/`，并输出产物路径；Tauri 原始产物和编译缓存保留在默认目录。轻量包仅携带 `setup/manifest.json`、带哈希的 `requirements.txt` 和项目 wheel。Python、uv 从 Astral 官方固定版本地址下载；PostgreSQL 及其动态库直接使用系统包管理器的安装结果，不复制或重新签名系统数据库程序。macOS 使用标准前缀 `opt/postgresql@17/bin` 和 `opt/postgresql@17/share/postgresql`，Linux 使用系统 PostgreSQL 17 布局。

`scripts/smoke_desktop_runtime.py` 通过 `--runtime` 指定首次安装后的环境，在新目录及仅含系统命令的 PATH 中运行实际 Python 后台，验证新数据库初始化、worker 子进程、快照发布与固定精度查询。不会依赖开发 venv 或使用已有开发数据库。

macOS 只导出本机架构 `.dmg`，内置系统安装器 `.pkg`；安装位置固定为 `/Applications/Asterion Terminal.app`，包标识固定 `me.asterion.terminal`，禁止重定位、关闭按版本号跳过替换的行为、以整包替换移除旧程序文件。安装前关闭标准路径下的桌面进程，等待退出失败则中止；用户数据不在安装器载荷内。Tauri 先为 `.app` 本地签名，随后生成 PKG 和 DMG，导出前展开镜像中的 PKG 并严格验签。Linux 只导出本机架构 `.deb`。Windows 格式固定为机器级 NSIS `.exe`，允许最后安装的版本号较低，不生成 MSI，但运行时和后台服务尚未适配，构建入口拒绝 Windows；配置目标不代表平台可运行。构建命令、依赖和 VS Code 任务见 README。Developer ID 签名、公证、Windows、AppImage 和 RPM 尚未交付。

## 独立设置窗口

设置使用固定窗口标识 `settings`，可从 macOS 菜单、⌘, 或全局设置图标打开；重复调用聚焦现有窗口。设置窗口只读取已有本机会话，不因为查看设置而启动已停止的服务。窗口不挂载业务工作区或任务目录。外观偏好通过同源存储通知其他窗口，业务对象和工作区布局不变。原生工作区以宿主 `workspace.json` 为唯一持久化来源；不从浏览器旧布局导入。只接受当前布局规范，格式不支持时保留原文件并显示错误。

## Linux 服务与打包

Linux 使用 `$XDG_CONFIG_HOME/systemd/user/me.asterion.terminal.backend.service`（默认 `~/.config/systemd/user/`）。unit 不包含秘密；ExecStart 对空格、美元符号和百分号转义。后台通过用户级 systemd 启动，`Restart=always` 恢复异常退出，`KillMode=mixed` 先通知 supervisor，再由它停止 API、worker 和 PostgreSQL。停止操作等待服务退出；下次打开应用可再次启动。未启用登录自启动，退出登录后的行为遵循系统的用户服务生命周期。

数据由 Tauri 的 app_data_dir 提供，默认 `~/.local/share/me.asterion.terminal/`；日志写入该目录下的 `service.log`。启动/停止需要真实用户 systemd 会话，无会话时返回诊断错误。没有 systemd 的环境仍可手动运行开发服务。

Linux 使用 Debian/Ubuntu 包布局：程序位于 `/usr/lib/postgresql/17/bin`，共享资源位于 `/usr/share/postgresql/17`。`.deb` 声明 `postgresql-17` 依赖，用户通过 `apt install ./安装包.deb` 安装；数据库包和安全更新由系统仓库管理。首次设置校验程序可运行且主版本为 17，不下载数据库副本，不自动添加软件源或提权运行 apt。仓库不提供 17 时须先配置 PostgreSQL 官方 PGDG 软件源。当前实测 Debian 13，不承诺其他发行版未经验证可用。

系统包可能管理自己的集群，星枢不使用或修改该集群；仍以普通用户在应用数据目录创建自己的集群，独立端口与 SCRAM 认证。数据库程序缺失或版本不符时拒绝设置。

Linux 采用安装位置稳定的 `.deb`；当前不支持从 AppImage 临时挂载目录运行持久后台。下载清单严格核对当前平台、架构与 schema；不接受其他平台或不支持的清单。数据库主版本仍固定为 17，不自动迁移已有集群。

## 应用更新后的后台版本核对

启动工作台时按实际运行文件的内容 SHA-256 识别运行版本，不以产品版本号、安装路径或修改时间判断。安装环境的指纹覆盖独立 Python、虚拟环境内全部模块/策略源码和 PostgreSQL 运行目录（Linux 仅数据库的版本目录与共享资源，不遍历整个 `/usr`）；开发模式覆盖 `asterion` 与公共插件 SDK 源目录。临时 `__pycache__` 和 `.pyc` 不参与；用户数据与安装在数据目录中的外部插件不纳入应用指纹。

这是运行宿主的通用生命周期机制需求：既有插件扩展点不能替换已运行的宿主进程。实现位于 `runtime/build_identity.py` 与 `runtime/desktop.py`，不识别业务插件 ID、不导入功能实现、不修改数据或插件契约。

macOS LaunchAgent 和 Linux 用户 unit 写入无秘密的 `ASTERION_RUNTIME_BUILD`。内容变化时配置随之变化，先停止当前服务，等待原 supervisor 释放数据库所有权，再登记并启动当前运行包；停止失败时保留原配置并报错。相同内容复用现有服务，多窗口调用仍由维护锁和启动锁串行化。

Supervisor 启动时独立计算内容指纹；与服务配置声明不一致时拒绝初始化数据库，提示重新打开应用。运行状态报告保存该次启动捕获的 `build_id`，不会因磁盘文件后来改变而冒充新进程。桌面 bootstrap 只有在 API 健康、Worker 就绪、状态时间有效且实际运行身份等于当前包时才返回会话。

切换沿用现有进程停止和任务租约机制，可能中断正在执行的任务；不承诺无中断热升级。任务输入、状态和已发布结果不删除，未完成任务按现有租约到期规则回收，当前执行契约不支持的输入明确失败，不迁移或降级运行。数据库主版本或数据契约不匹配仍按当前规则拒绝启动。本机自动重启不等于实现在线交易节点升级协议。

核对在打开工作台时发生，不是后台自动下载安装更新，也不持续监控安装目录。Linux 的配置与错误处理已通过测试，本轮实际服务切换验收在 macOS 完成。

安装界面使用三个英文句点 `...`；完成行显示绿色 `DONE`（中文为“完成”），进度条保持橙色。下载按字节比例、依赖按实际已安装／总数、最终验证按三个已完成检查项计算百分比；无法量化的阶段仍显示进行中，不人为模拟连续百分比。

## 包管理器数据库依赖

数据库依赖检查在撤销已发布 Python 环境前进行，包管理器失败不能清除可用环境或业务数据。只执行已声明的配方安装，禁用附带自动更新、安装后清理和依赖方更新；最终检查 PostgreSQL 主版本 17 以及启动、备份、恢复所需程序。不启动包管理器的默认服务。缺少系统程序时安装完成标记仍保留，但环境不可用于后台调用，修复依赖后可重试。

这是操作系统运行依赖的通用宿主机制；在 Python 环境可用之前完成，现有 Python 功能插件无法承担该阶段。范围限于原生依赖安装、清单校验、安装锁和后台路径，不引入市场或交易业务分支。Windows 的数据库获取工具确定为 WinGet；Windows 安装与服务适配仍待独立交付。
