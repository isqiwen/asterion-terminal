# 固定事件集合与Research交接实施合同

本页细化已批准的数据通路，对应[FR-INT-SRV-01-02/03及02-04](requirements/modules/intelligence/services.md)。本页首条有界路径已实现生产者、Research正式消费、精确引用、客户端交接及三域独立恢复，并通过真实进程与浏览器验收；不代表完整事件库、变量研究算法或订阅已完成。单事件更正/撤回和Research独立后继观察已有实际验证，见[实施矩阵](reviews/data-paths-implementation-2026-10-21.md)。

## 目标与第一条路径

Intelligence固定筛选、模式、截止、当时事件关系、所选已发布陈述、排除原因、用途和实际方法；Data确认不可变集合字节后Intelligence才确认可交接。Research从固定集合身份取得数据，持久保留自己的输入/引用并执行受限的集合证据与时点审阅。后来更正或撤回不改旧集合或旧结果。此处不实现收益预测、事件因子有效性或交易执行。

首条路径只处理已有人工计划保证金公告事件、同一Intel所有者、明确列出的至多16个事件及一个UTC截止。事件身份不能用标题或合约替代。已有事件目录提供可选择的稳定身份；第一条不自动合并事件族、不把已选择集合说成覆盖所有市场事件。最终协议仍须承载选择范围，后续增加字段过滤不能静默扩大旧集合。

模式沿用严格实际历史与事后研究。前向观察、提取评测有自己的方法与证据要求，未实现时不能换名为现有模式。用户明确命名集合及声明研究用途；不创建必需中央Storage、全局新任务框架或部署级Data绑定。

## 预览与固定

请求固定操作ID、名称、用途、事件Object清单、模式、截止、发布规则与目标DataOwner。按稳定事件Object排序，重复事件、不同Owner混合、无效/未来截止拒绝，不能随机选择一个版本。预览的实际观测时间与查询截止分开。

| 记录情况 | 预览与集合行为 |
| --- | --- |
| 事件在截止后才首次可用 | 排除并注明事件当时尚不可用，不把现在的初始陈述回填 |
| 更正在截止后发布 | 采用截止前的事件头及原陈述；后来变化不成为旧时点输入 |
| 截止前已撤回 | 排除正式可用成员，保留撤回身份、证据和排除原因 |
| 严格实际历史缺来源发布时间、时间链矛盾或仅声明事后用途 | 排除并列确切原因，不补时间、不提升资格 |
| 事后研究满足明确用途但未知原发布时间 | 可纳入受限事后成员，保留全部限制；不称当时可交易 |
| 某成员内容、固定源或用途不可核对 | 报阻塞/未知，不能静默按空集合或无事件处理 |
| 没有可纳入成员 | 返回明确空预览及排除清单；首条研究交接要求至少一个成员 |

Intelligence在自己的串行边界选择固定事件状态；预览读取实际Data内容以核对依赖可读，不把目录登记当完整性证明。正式准备固定所选版本；预览后来源新增变化，不重算/替换原准备。若用户要新条件，使用新操作身份重新预览。时点精度和同毫秒的稳定事件内序号保留，不伪造更早可用时间。

集合成员复用已发布内容和变化的完整Object/版本、保存回执、事件头及时间/用途限制，不复制原件或整张基础表。集合保存是语义引用复用，不是全局去重、透明同步或分布式事务。单个集合字节仍受现有1MiB固定内容上限，超限明确失败，不截断成员。

## 所有者与存储

| 对象 | 所属域及格式 | 依据/访问 |
| --- | --- | --- |
| 查询与固定准备 | Intel既有ledger.sqlite中的类型化Protobuf记录 | 固定请求及实际方法程序；未确认准备不能正式消费 |
| 固定集合内容 | Data既有intelligence-content不可变对象/保存回执，明确集合语义kind | 与普通公告/变化内容共用基础文件机制；读取按确切类型，不猜解析器 |
| 可交接集合 | Intel语义发布记录及固定Object | 只有Data回执与固定意图一致后确认实际可用时间 |
| Research集合审阅输入/结果 | Research原TaskStore和正式输入/结果目录，类型化领域证据 | 复用原接纳/尝试/取消/重启机制；独立领域种类，不增加服务或每任务进程 |
| 消费关系 | Intel既有源消费者账本与Research自有接纳/放弃证据 | PREPARED/CONFIRMED都保留；未知/失联不解除；正式证据继续保留 |

目标DataOwner是这次集合对象的位置，不是Research/Intel部署配对。多个候选不随机选，失联不静默换源。首条本机实现仅接目标Data已保存全部成员内容的路径；混合DataOwner内容的传输若未实现必须明确受阻，不能过滤掉这些成员假称完整，也不能把该限制写成目标架构永久配对。跨业务节点权限/传输仍单独列缺口。

稳定对象身份与安装版本、当前端点和进程无关。正式集合内容由所属Data决定保存，语义发布由Intel决定；Research仅写自有审阅输入/结果。Manager/Agent只发现和管进程，不转发集合或接管任务。

## 接纳、恢复与依赖

沿用准备→Data保存→Intel语义确认；保存失败不返回可用集合。保存前后或最终提交前后中断，按原操作身份核实/续办；同ID不同条件冲突，已确认原操作重放不再取源或制造第二集合。无回执残留保留未确认字节，不自动发布或清理。

Research请求固定集合Object、用途及自己的任务ID，按原Owner发现直接读取Intel证明及实际Data字节。固定输入纳入精确集合、成员关系、模式/截止、质量限制与实际Research程序；先保留再接纳/确认。取消或中断不释放正式证据；未接纳准备的持久放弃沿现有精确源证明解除，不按在线扫描判断。

资源目录列实际准备/内容/发布和Research输入/结果；目录可重建，不是删除权威。Intel/Data/Research冷备须包含集合固定字节、原发布/变化、材料/程序及双侧消费者依赖。独立恢复核查成员关系、时间/用途和引用闭包；缺权威或缺依赖报错/缺项，不静默重建或称可完整复现，不启动服务/下载/计算。

## 第一条验收矩阵

| 旅程 | 必须实际证明 |
| --- | --- |
| P→同事件R→C→W | C前集合仍选P；C后/W前选R；W后排除；旧集合身份/字节不变 |
| 严格与事后 | 未知原发布时间不进入严格成员，事后保留限制；排除原因可见，不伪造完整历史 |
| 固定保存 | 实际Data保存回执后才可交接；同ID复用及不同条件冲突；保存/确认故障后原身份恢复 |
| Research消费 | 真实进程接纳、固定输入/程序、原消费者关系、真实审阅结果；取消/重启不换集合 |
| 无配对/离线 | Research无选中Data或Intel部署配对仍按任务Owner访问；来源失联明确阻塞，已拥有结果可读 |
| 用户页面 | 明确预览/用途/模式/截止/排除；确认固定集合→交给Research→查看受限结果 |
| 三域冷备 | 实际依赖闭合与独立恢复；原件不可用时仍核验固定集合/结果；不恢复外部资格 |

完成上述路径之后再推进变量定义/研究评价和订阅。集合列表不是订阅；订阅另须实际验证条件预览、变化去重、最后确认位置、断档、显式区间补取与历史补取标签。人工公告不代表完整事件库或模型能力。

所有实验使用隔离合成材料及模拟供应商，不调用真实额度或交易。正式Research完整结果物理删除、A02唯一执行与A03失联政策继续待决，不借集合实现擅自决定。
