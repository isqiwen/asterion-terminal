# 期货历史模拟交易

本阶段交付 Asterion Terminal 的单合约历史模拟闭环：导入 CSV → 创建模拟账户 → 回放行情 → 下单/撤单 → 成交、持仓和资金变化 → 从交易服务记录恢复。沿用原工作台、主题和面板控件。没有在线行情、券商连接或实盘入口。

## 本机部署使用

1. 在「数据」导入真实的实际月份合约历史逐笔数据，填写合约规格。模拟会话支持 1–10000 笔；预览仍支持最多 250000 笔，超出模拟上限时不截取数据创建会话。
2. 在「交易」选择已经存在的专用空目录，输入初始模拟资金、每手固定保证金与保证金率、每手开仓/平今/平昨手续费及对应费率（费率默认 0）。数据和参数复制到会话，不依赖源 CSV 后续存在或不变。
3. 点击「回放下一笔」建立当前价格，然后提交限价模拟委托。新委托只参与之后的行情，不使用下单前的行情成交。
4. 继续逐笔回放，查看资金、持仓、委托和成交。尚未成交的委托可撤销；回放到结尾后不能新增委托，但仍可撤单。
5. 关闭会话或退出应用后，选择原目录点击「恢复会话」。恢复包含未成交委托、冻结、成交记录、账本和回放进度。不会自动查找、升级或改写旧格式。

## 领域与撮合语义

- 单币种、单合约、正价格、整数手数。资金权威值使用八位 Decimal，溢出与无法精确表达的运算拒绝，不使用 JS Number 计算账本。
- 模拟参数由用户提供，不代表交易所保证金或手续费。保证金 = 手数 × 每手保证金 + 名义金额 × 保证金率；手续费 = 手数 × 每手费用 + 名义金额 × 费率，开仓、平今、平昨分别设置。名义金额 = 价格 × 手数 × 合约乘数；比例部分按分四舍五入（远离零），每手部分精确。持仓保证金按最新标记价计算（结算后即结算价），委托冻结按限价计算。
- 平仓规则按交易所（`ClosePolicy`）：上期所、能源中心及未核实的交易所要求显式“平今/平昨”；中金所“平仓”先平今后平昨；大商所、郑商所、广期所“平仓”先平昨后平今。非显式交易所只接受“平仓”，由规则分配今昨仓并分别计费；统一平仓委托按两种费用中较高者冻结。规则表需按交易所最新规定核对。
- 开仓按剩余手数冻结保证金和手续费；平仓冻结对应方向、今昨仓的数量和手续费。重复平仓不能占用同一份持仓。
- 平仓按同方向、同今昨桶的 FIFO 逐笔成本计算已实现盈亏。买入平空、卖出平多；买入/卖出开仓可分别建立多空持仓。
- 权益 = 账面资金 + 浮动盈亏；可用资金 = min(账面资金, 权益) − 持仓保证金 − 委托冻结。浮盈不能用于增加开仓额度，浮亏会降低额度。开仓资金不足拒绝；有效平仓不因可用资金不足被阻止，严重亏损允许负余额并如实展示。
- 每笔历史成交按委托到达顺序，跨委托共享成交手数。成交价穿过限价时直接以该笔价格成交；恰好等于限价时，委托需先消耗排在它前面的量：若下单时上一笔成交正是该价位，则以那笔成交量作为排队量，否则排队量为 0。这是在只有逐笔成交、没有盘口数据时的估计，不是真实队列。成交量向合约手数步长向下量化，不凭空增加流动性。部分成交后保留剩余冻结；行情推进后可用资金为负时取消符合撮合条件的开仓委托。
- 这是明确的简化模型：没有买卖盘口、排队优先级、冲击成本、滑点、强平、自成交识别或真实成交概率。并非行情逐笔中出现成交价就意味着真实订单一定能成交。
- 整个输入作为一个交易日模拟，不自动推断夜盘/交易日。回放结束且无活动委托时可手动结算：用户输入正数结算价，浮动盈亏计入资金，持仓成本重置、今仓转昨仓。没有交易日历、自动日终结算或下一交易日续接。Core 账本支持平昨，Terminal 当前会话不提供跨日继续下单流程。
- `FuturesAccount` 对下单、撤单、成交、标记和结算提供强异常保证；成交 ID 在账户生命周期内唯一，同一回报精确重发幂等，内容冲突拒绝。

新增执行、存储插件使用公开 C++ Plugin/ExecutionPort/JournalPort 契约，当前由应用会话显式拥有与管理生命周期，是可信内置组件。交易会话在独立 C++ 进程运行，由 Terminal 通过 Protobuf 本机 IPC 或 TCP+mTLS 调用，Rust 不实现账本。进程和 CLI11 边界见 [进程架构](process-architecture.md)。JournalPort 为本用例的存储边界，不虚构已经实现通用数据库查询 StoragePort。余额/持仓约束是账本基础检查；独立 RiskPort 和官方订单限额插件现已接入同一提交路径，详见 [交易前风险](pre-trade-risk.md)。风险配置必须随会话显式持久化；实盘授权与券商回报链尚未实现。

## API 与恢复

当前请求仍为 `{version: 1, method, params}`，经 C ABI 和 Runtime 的 `paper.manage` 能力进入。方法：

- `paper.connect`：`host, port, session, mode, ca_file, certificate_file, private_key_file` 均为字符串，当前 mode 只接受 paper；连接并附着远程会话。
- `paper.reconnect`：空参数，重新连接当前远程配置并核对权威快照，不重发交易操作。
- `paper.create`：`directory, deposit, margin_per_lot, open_fee, close_today_fee, close_yesterday_fee, max_order_quantity, max_gross_quantity, max_working_orders` 全部为字符串。远程已连接时不传 directory，由服务端决定存储位置。使用当前完整校验的预览数据创建。
- `paper.open`：`directory`。恢复已有会话；无自动创建或格式降级。
- `paper.close`（远程仅断开连接，服务继续运行）：空参数，释放文件锁，不删记录。
- `paper.act`：每个操作带唯一 `request_id`；`action=advance` 无其他字段；`submit` 带 `order_id, side, offset, quantity, price`；`cancel` 带 `order_id`；`settle` 带 `price`。未知字段拒绝。
- `runtime.snapshot` 包含 `paper`（无会话时 null），`execution=paper_only`；所有金额和纳秒时间为字符串。未开放任何实盘命令。

操作先在候选账本执行校验，再持久化，最后发布内存状态。精确重复 request_id 不再次执行；同 ID 不同内容拒绝，重启后仍有效。UI 不自动重试交易命令；失败后重新查询状态，避免响应丢失导致重复操作。

目录中 `00000000.json` 是日志格式 2 的头记录：`format`、引擎语义标识 `engine`（当前 `asterion.paper-futures.v2`）与完整输入 `manifest`。后续按连续序号记录成功操作，每条为 `{command, outcome}`，`outcome` 是执行后的账本指纹（回放进度、余额、手续费、已实现盈亏、冻结、标记价、委托/成交数、多空数量、授权与日程状态）。

日志记录的是命令，恢复时由当前代码重算。为避免升级后用不同规则静默改写历史：撮合、费用/保证金算术、风控或命令语义的任何可能改变结果的修改都必须提升引擎标识；恢复遇到不同标识、格式 1 日志或任一条重放指纹不一致时明确拒绝，目录保持原样，不自动迁移。

每条先写 `pending.tmp`、同步，再原子改名提交。恢复只读取已提交序号，忽略未完成的普通临时文件，并逐条通过同一账本重放验证。损坏、缺号、未知字段/版本/文件会拒绝，已有日志不被重写。没有防恶意篡改的签名或远端复制。

Linux/macOS 使用 flock 与 fsync，Windows 使用独占文件句柄、FlushFileBuffers 和 MoveFileExW。系统在进程退出时释放锁，不依赖删除锁文件；一个目录只允许一个写入实例。只承诺本地文件系统范围，NAS/网络盘的锁与同步语义未验收，不能据此宣称 NAS 支持。写入异常可能已经提交，必须关闭再恢复核对，当前会话拒绝继续写入。

命令就地执行：每个引擎操作都有强异常保证，引擎维护变更序号；被拒绝的命令若序号未变即无需回滚，多步命令中途失败或日志提交失败时，会用内存中已提交的命令序列重建引擎，界面始终显示已提交状态。正常路径不再在每条命令前复制整个账本。尚未实现周期快照与分段日志：当前恢复为线性重放、每条命令开销很小，下述容量是产品限制而非性能瓶颈；若需放宽容量再引入快照。

容量：最多 10000 个订单、20000 条操作；首条记录最多 16 MiB，后续每条最多 64 KiB，提交文件累计最多 64 MiB。达到上限拒绝，不静默清理。恢复为全量重放，未做大规模性能验收。

## 验收范围

GoogleTest 覆盖冻结、部分成交、重复与冲突回报、平仓占用、资金不足、亏损后的减仓、空头结算、共享成交量、撤单、严格输入、独占锁、损坏拒绝、写入失败与会话恢复。C ABI 测试销毁并重建运行时，删除源 CSV 后仍能恢复。

`paper_process_recovery` 启动真实 C++ 桌面开发桥和独立交易进程，下单成交后强杀交易进程（无析构），验证宿主仍能返回明确断线状态；保留不完整 pending 文件，再启动进程恢复、重发请求验证幂等并完成平仓。这验证进程崩溃与系统锁释放；不等价于断电、磁盘故障或任意写入指令点故障注入。

Playwright 在原工作台通过真实 C++ 后端完成导入、创建、开仓成交、平仓、检查手续费与资金、关闭并恢复。浏览器刷新测试不是原生窗口重启测试。各平台实际执行结果见 ROADMAP 和 terminal-validation。

## 远程模拟交易

设置 → 连接支持 TCP+mTLS 的独立模拟交易服务；连接后在交易工作区使用当前 CSV 初始化远程会话。记录目录由服务器启动参数决定，不填写 Terminal 本机目录。断开只释放连接，服务继续持有账本；重新连接获取权威快照，命令不自动重发。部署、证书与单客户端限制见 [进程架构](process-architecture.md)。


## 计划回放的结算与持仓续接机制

`PaperExecution::settle_before_next(boundary_ns, price)` 为显式日历驱动的回放提供事件间结算。调用方提供边界和结算价：至少已消费一笔事件且仍有下一笔，边界严格晚于上一笔、不得晚于下一笔，必须严格晚于本实例上次结算边界。相同时间的一组事件不能被该边界拆开；重复或倒退边界拒绝。账户仍要求没有未完成委托，非法价格或边界均不改变账户或回放位置。结算不会隐式撤单，不读取下一笔价格作为结算价。

已有的 `settle(price)` 保留为整段历史回放完成后的显式手动结算；事件间接口目前是插件能力，尚未向手工交易命令开放。两者复用 Core 账户的结算语义，结算价盈亏入账、成本重置、今仓转昨仓。

目标多头持仓调整支持同时持有今仓与昨仓。非显式交易所生成一笔“平仓”委托，由交易所规则分配今昨仓；显式交易所明确采用模拟器的“先平昨、再平今”规则，不宣称是交易所规则或手续费最优策略。需要两个开平标志时生成 `.yesterday` 与 `.today` 子委托；只需一个标志时使用调用方订单 ID。每个子委托通过相同风控和账户检查，共享逐笔流动性并保留各自手续费。所有撤单及新委托先在候选账户执行，任一子委托失败则整个替换不生效。空头仍不属于 long/flat 目标策略支持范围。

该能力已接入 BacktestInput 版本 5 的多交易日回测、每日结算输入、结果证据及 Terminal 多日表单，见 research-tasks.md。手工模拟交易命令仍不开放事件间结算，两者边界不同。

## 绑定日程的历史会话

新命令 replay_calendar 在未推进、无订单/持仓且尚未授权策略的账户上绑定完整 CalendarPublication；只允许绑定一次。合约、摘要、事件时段、每个交易日成交与模拟结算价约束在写入前校验。原始 CSV 不参与恢复，完整发布物作为命令证据保存在同一日志。

绑定后 advance 无法越过尚未结算的交易日；时段最后一笔历史事件处理后取消剩余委托，禁止再提交跨时段委托。strategy_target 在时段末仍确认意图序号，但不生成委托。replay_settle 只接收下一待结算的 day_index，且游标必须处于该日最后事件；价格与边界取绑定日程，不能另传价格。最后一日也需要结算。旧手工 settle 在绑定账户上拒绝。

结算经候选账本、日志提交和原命令身份去重；同 request_id 相同命令只确认已完成操作，新身份重复同日拒绝。重启重放还原绑定、结算计数、持仓今昨桶与账本。授权撤销不解除日程。ReplayPlan 版本 2 已携带相应日程证据并自动提交日终结算；Terminal 选择、进度和手动接管已接入；独立进程的更多日终中断点验收仍待扩展。

协议公共 Decimal/Contract/Tick 提取为 domain.proto，使 data.proto 与 trading.proto 使用相同领域消息且无循环依赖；字段编号和命名空间保持不变，没有别名或协议转发。
