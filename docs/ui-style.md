# 终端统一视觉规范

本文件是颜色与控件的现行规范；工作区、命令、配置和可扩展交互的目标见 [终端体验](terminal-experience.md)。架构 v2 延续当前黑橙风格。

启动、登录/注册/验证、业务工作台和独立设置窗口共用 `apps/terminal/src/theme/tokens.css`。组件不得自行增加品牌色、蓝灰背景或另一套字体；Canvas 行情图表也读取这些 CSS 变量。

- 底色：近黑画布、黑灰面板与层次轻微的标题栏。
- 强调：统一橙色，用于当前导航、主操作、标题和输入焦点。主按钮使用橙色文字、深橙底色和细边框。
- 字体：SFMono-Regular / Menlo / Consolas 与中文回退；表格数字使用等宽及等宽数字。
- 控件：直角、1px 边框、统一控件高度。保持现有紧凑/舒适密度偏好。
- 网格：启动、账号入口与业务空态共用细网格；数据表和行情图保持独立清晰的数据绘制背景。
- 语义：成功为绿色、错误为红色。行情涨跌继续遵循用户的红涨绿跌/绿涨红跌偏好，不使用品牌橙色替代业务含义。
- 设置仍是独立原生窗口，视觉组件和导航选中态与主工作台一致。

新增界面先复用主题变量和已有控件，再补充必要的局部布局样式。

### Dashboard 工作总览

2026-09-21 按维护者决定优先落地 Dashboard。内置 `overview` 插件以分区工作台展示已有能力：历史行情预览、固定数据版本、任务与异常、最近完成和期货/交易能力状态。局部标题栏提供进入对应业务的操作，证据与状态不能被统一的在线指示替代。历史行情明确标记来源、日期和非实时属性；未接入交易网关不展示虚构资产与盈亏。首版为固定分区，组件增删、自由拖拽和布局保存仍待实现。实机参考与验证范围见 [Fincept 体验记录第八节](fincept-interaction-review.md#8-维护者调整与-dashboard-首切片)。

### 可点击控件反馈

按钮、侧栏入口、工具栏、状态栏入口、折叠标题和文件选择入口应具有一致的悬停背景高亮与按下加深反馈。选中项保留橙色强调，服务状态保留语义色；键盘聚焦显示明确边框。禁用控件降低对比度，不显示可点击的悬停高亮。反馈只改变颜色，不改变控件尺寸或位置。

### 信息层级与操作效率

维护者要求终端保持简洁、干净、高效。主视图围绕业务结果组织；后台机制完整不意味着每一步都需要独立的表单、按钮和解释段落。

| 层级 | 默认内容 | 展开内容 |
|---|---|---|
| 业务主视图 | 当前对象、关键结果、适用交易日、更新状态、主要操作 | 必要的业务选择 |
| 配置 | 当前已选配置的简短摘要 | 连接、规则和候选范围；提交前明确影响执行的选择 |
| 任务中心 | 进度或异常摘要，由业务入口可达 | 各子任务、错误与可执行恢复操作 |
| 检查器或详情 | 用户主动打开 | 来源、候选排除、历史版本、校验依据、完整标识及复制操作 |

禁止用收起详情掩盖阻断错误或未知信息。后台刷新、数据更新和重新计算须明确区分；同一页面减少重复刷新按钮和重复状态表格。交易日、生效时间和更新时间具有不同含义，不为缩短标签而混淆。

### 三个参考项目的借鉴范围

2026-09-20 复核以下官方架构/工作流文档，属于文档核对，不是三个应用的实机交互测评，也不证明它们实现了本站国内期货角色更新流程。

- [Fincept Terminal](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/docs/ARCHITECTURE.md)：参考金融工作台、多窗口停靠、业务界面与服务分离以及共享数据分发。信息取舍遵循本项目目标，不照搬全部功能入口。
- [Qlib Workflow](https://qlib.readthedocs.io/en/latest/component/workflow.html)：参考用一次执行编排数据、模型与评估，并保留执行记录。产品应用是把多个内部步骤组合为一个明确的用户操作；其配置接口不是桌面界面模板。
- [NautilusTrader Architecture](https://nautilustrader.io/docs/latest/concepts/architecture/)：参考数据、执行、风控、组合与生命周期职责分离。产品应用是让后台组件协作支撑简洁操作；引擎组件不逐个映射成菜单。

### 角色界面的下一步收敛

2026-09-21 对本机 Fincept v5.0.3 的实机观察、交互取舍、当前代码对照及建议验收路径见 [Fincept 实机体验与星枢交互取舍](fincept-interaction-review.md)。该记录补充上面的文档核对；其中组件搜索与部分页面切换已实际体验，多窗口、完整恢复和真实回测结果仍未验证，建议不代表已实现。

当前角色面板已接通批量采集与续算，但仍偏诊断用途，以下为待实现的交互目标，不代表已经改完：

- 主视图优先展示品种、主力、次主力、适用交易日与更新状态；来源报告与自行计算保持明确区别。
- 使用“更新主力角色”等业务入口；提交处说明将获取候选日线并计算，连接与规则按需查看或选择。
- 采集/计算过程显示简短阶段和异常摘要；完整候选任务详情复用统一任务入口，避免在页面另建一个任务中心。
- 固定版本、算法校验和、候选排除及原始 JSON 保留在详情，默认不显示完整技术标识和成段机制说明。
- 更新规则必须保留当前的交易日、身份、来源、可知性和幂等校验；界面精简不得降低正确性。

### Dashboard 组件化与导航（2026-09-21 最新决定）

主导航固定左侧，可折叠为图标；顶部为本会话已打开工作区标签，页面工具栏就近放置业务操作。新工作区默认进入总览。Dashboard 采用 Fincept 式组件网格和右侧 Pulse；全部约定组件提供入口，无来源时呈现真实不可用原因，不伪造行情、资产或评分。

业务插件通过 `dashboard.widgets` 提供组件，overview 管理目录与布局，默认排列由发行版声明。同一插件可提供多张独立卡片，不要求一张卡片对应一个插件。保存、移除、重排仅修改视图，不启动业务任务。已保存的不支持布局不自动迁移或覆盖，缺失插件保留引用占位。实现与验证边界见 `fincept-interaction-review.md` 第九节。

2026-09-21 补充：Dashboard 默认全宽，状态信息复用底栏；提醒通过工具栏铃铛按需展开覆盖抽屉。异常数量与直接错误提示不能被折叠隐藏。仅用户主动固定时保留右栏，空态不设置撑高整列的最小高度。

最新首页原则：默认只选择行情、账户概览、持仓与风险概览；同一缺失能力只提示一次，无数据时提供一个开始入口。可选资讯组件只在用户添加后出现。日常工具栏保留提醒、刷新与编辑入口，布局控件只在编辑模式显示；默认关闭紧凑模式。相关替换及证据以 `fincept-interaction-review.md` 第十一节为准。

最新修正：无数据不隐藏 Dashboard。默认保留行情、账户与持仓、风险概览三块；账户区采用上方资金摘要、下方持仓表。未知金额用 `—`，不能用 0 暗示已确认零资产；未知持仓不能显示成已确认空仓。同一接入入口只出现一次，编辑操作仍按需展示。

总览行情仅展示实时来源；未接入网关时保留表头和来源状态，不能以历史快照填充。历史数据在市场/研究工作区使用。合约标识、版本、联动和检查器等对象控件只在贡献声明 `objectTools` 的工作区显示。

总览默认以约 6:4 的主次分栏呈现：实时行情在左，账户与持仓、风险概览在右；按容器可用宽度折为单列。表格行数增加时组件内滚动，表头固定，数值右对齐；空态不撑满窗口。编辑布局可选择左栏、右栏、通栏，业务组件使用公开贡献声明位置。

主导航展开宽度为 104px，收起为 52px；展开显示图标与文字，收起通过图标及悬停说明识别入口。

实时报价表的最新价与涨跌幅使用同一涨跌语义色（相对昨结算），跟随外观中的红涨绿跌/绿涨红跌偏好；平盘、未知基准及缺失值使用中性色，正负号和时效状态保留。

行情红/绿采用 `#ff3b30` / `#00c853`，替换原偏粉/偏青色值；涨跌方向仍遵循外观偏好。成功、错误等其他状态色不受影响。

报价列依次为合约、最新价、涨跌额、涨跌幅、最高、最低、成交量、持仓量、行情时间、状态。仅最新价和涨跌额/幅使用涨跌色，日内极值及数量不着色；账户中持仓/平仓盈亏同样按正负着色，其他余额和比例保持中性。

主导航展开宽度 64px，收起宽度 40px；图标 16px，文字 12px，行高 40px。减少横向留白，保持双字标签完整与键盘焦点反馈。
