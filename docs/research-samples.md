# 独立研究样本与时间角色

依据 [REQ-ANA-EDA-02](requirements/modules/analysis/exploration.md#req-ana-eda-02)、[FR-ANA-EDA-03-01](requirements/modules/analysis/exploration.md#fr-ana-eda-03-01) 和[统一数据通路](data-paths.md)。组800—830已实现单合约标准固定数据→独立样本→原始收盘价统计→页面读取及双域冷备；不是完整EDA，也没有独立样本服务。

## 为什么需要独立样本

现有统计能引用同Research的成功单序列固定窗口因子原行，已经解决43个同期特征、42个未来标签与40个评价配对不能混用的问题。但“先成功计算因子”不能成为探索原始数据的产品前提。下一条从用户明确选定的Data固定版本直接建立Research样本，再由统计任务引用；不运行伪因子、不制造标签，不把Data的命名数据集当Research业务记录。

首条限定单个实际合约、明确的分钟版本组合或固定日表快照、原始close列、原观察顺序和全样本/开发角色；不包含连续价、动态持仓/成交筛选、多序列、多周期或训练模型。原始价格允许真实零和负值，统计不采用只适用于正价格的收益公式。后续其它字段需明确单位，不能把手数塞成价格指数。

## 所有权与现有机制

- Data仍拥有来源/标准数据/版本和发布；Research拥有样本声明、资格解释、固定角色、统计及人工判断。
- 用现有Research持久任务建立样本，复用队列、准备记录、程序留存、取消/发布/显式恢复与任务SQLite。不新建Task进程、样本调度平台或中心Storage服务。
- 客户端提交任务ID、用途、精确DataOwner和现有BarDatasetRequest、实际观察角色边界；不得上传市场行或任意本地路径。默认用现有Manager/Agent发现选中的本机Data，多个候选明确选择，不永久配对Research，不随机换源。
- Research向Data直连读取固定请求，沿现有Data保留PREPARED/CONFIRMED机制在接纳时持有精确版本。不可变样本输入保存当前受控Protobuf证据，源版本与本域位置分开。首份跨域取得后的拥有副本用于断源恢复，不把后续统计复制成另一个源数据副本。
- 正式对象为Research的sample固定输入与sample_result输出，稳定Owner/id/内容版本。后续统计同域引用原样本，扩展原派生准入而非复制另一账本；源样本与统计自身programme分别固定。其它任务的同种输入复用继续保留，跨种类引用不能误硬链接输入字节。

## 时间、覆盖和角色

当前Data协议HistoryVersionEvidence明确只有SOURCE_AVAILABILITY_UNKNOWN；acquired_at_ns是本地完整版本首次发布，不是历史来源发布时间。日表的取得时间同样不能倒推历史可知时间。样本必须保留原证据并显示“历史可得性未知/事后探索”，不能通过本次架构授权擅自发明发布延迟或严格历史合格值。

每条实际观察保留合约、原观察时间、交易日/来源映射、原close与单位、角色及资格原因。按实际观察序号定义零基半开角色区间，不生成缺失交易日或夜盘自然日映射；交易日来自Data，显示时间保持原精度。开发及留出边界明确，留出不进入探索统计；更换范围或角色产生新样本身份，原检查结论不沿用。

第一批只采用显式静态合约选择，不利用未来收益、当日收盘事实、全期成交/持仓排行决定早盘成员。若请求依赖当前没有的历史可得证据、动态资格或连续映射，返回具体阻止项；用户可另建明确事后范围，不静默降级原声明。覆盖报告区分实际观察、已知缺口与无法证明完整的范围；不能把所见资料冒充完整历史。当前Data的observation_archive及其ObservationCapture独立于minute_version/BarDatasetRequest，保存first_observation_ms和interrupted；本首条只接受标准固定分钟/日表来源，不给观察归档加别名或丢掉它的覆盖证据。直接消费观察归档须另接明确类型，不能把它冒充标准历史版本。当前BarDataset要求至少一行完整OHLC/volume；无返回行或缺字段保持明确阻止项，不伪造空成功或补零。

## 输出、引用与生命周期

样本结果保存声明/方法/来源、实际行和角色、已知覆盖边界及未知原因。统计只能读取已正式发布、Owner/版本精确的原样本行；选择raw close不需要未来标签。不能为了沿用现有feature筛选代码而补造收益或因子值。统计列/单位合同须同时更新当前Protobuf、Native、UI和测试，不能新增旧接口别名。

源样本的新引用与退役仍在同一Research串行准入边界；活动/准备/持有未知不得释放。取消不发布正式样本，恢复只使用固定版本，不改读最新。逻辑退役保持全部正式证据，物理结果删除仍待决。统计只持有源样本，Data保留由样本任务负责，避免统计再登记另一套Data来源权威。

联合冷备必须闭合Data实际版本、Research样本输入/结果和programme，以及引用它的统计原件；恢复后的Owner与内容版本不变，不启动任务、不恢复授权。缺源版本/程序/角色证据明确不完整，不能用当前Data或当前程序补历史。资源索引可重建，不代替引用账本。

## 交付顺序与实证

1. 核对当前Data固定读取及覆盖接口、资格/单位结构和现有任务恢复点，以当前原合同实现首个raw-close样本，不通过成功因子绕路。
2. 真实Data→Research样本接纳/发布/取消/显式恢复，固定来源、事后标记、角色和完整性边界；有缺口给可定位原因。检查通过不表示假设成立。
3. 扩展现有统计源选择消费该正式样本，保存原列/单位及实际行，负值/零/缺失不误当价格收益；新统计不改变源样本。
4. Native、分析工作区、只读资源目录、任务聚合与双域冷备一起接通；统计中明确已计算报告与待编辑条件，不能以新标题解释旧结果。
5. 合成隔离数据验证：无任何因子结果也能建立样本→统计；固定版本而非最新；真实零/负值保留；角色外不泄露值；未知历史可得性不升级；同ID冲突、停源重启、引用阻退役及移开原目录后的联合恢复。

该链完成后仍不等于动态成员资格、连续序列说明、多列关系/时间结构/事件窗口、模型训练或策略包已完成。按全项目矩阵继续独立业务，不以阶段验收停止；不提交推送部署、不操作真实数据/供应商/服务/交易，物理删除与A02/A03继续待决。
