# 情报订阅、交付位置与明确补取实施合同

细化[FR-INT-SRV-02-02/03](requirements/modules/intelligence/services.md#fr-int-srv-02-02)。首条人工保证金事件的显式订阅、持久交付、暂停补取和应用内确认已实现并通过实际进程与浏览器验收；范围与尚未实现项见文末。沿既有Intelligence业务进程、语义SQLite账本、Agent发现及直连Protobuf协议，不引入独立Task、通知业务代理、中央Storage或新供应商。

## 首条范围与所有权

只对已实现的人工保证金事件，按明确合约清单、规则、用途及新增发布/更正/撤回类型建立应用内订阅。至多16个合约，条件必须预览后显式启用；未实现自然语言解释、任意字段表达式、外部消息、操作系统推送或策略自动消费，不生成模拟事实。未发布候选不进入交付。实际发布仍必须先有Data保存确认。

Intelligence拥有匹配、启用/暂停、持久交付及源变化身份；Terminal仅呈现提醒并明确确认交付位置。已读、静音、Research任务接纳与交易执行分别记录，不能互相代替。不向Slack/邮件或其他人发送消息。事件集合交接仍为固定任务输入，不随订阅更新原Research结果。

## 已发布变化流

在原发布/更正/撤回的同一语义提交事务内，追加源所有者内单调位置和精确变化Object、事件Object、合约、规则、用途、类型及实际可用时间。Data成功但Intel未提交不能出现在流中；语义确认失败不提前交付；原操作重放不增加位置，两个不同更正各有独立位置与身份。普通后续陈述的发布与将其应用为事件头的更正是两个不同已发布变化；每条保留事件初始发布身份。条件明确是否包含未应用为事件头的后续陈述，普通事件提醒不默认包含这些陈述，因此P重复及后继C是两条变化/一个事件，不把R的先行保存发布无区别地当第三次事件提醒。用户可显式查看完整陈述发布流，不能只按标题合并。

位置为原稳定IntelOwner下的顺序，不依赖墙钟排序、进程ID、安装版本或绝对路径。流及其最后位置由同一所有者持久保存，不从可重建资源目录猜测。读取仅接明确起止位置、条件及有界页；非匹配区间也返回实际扫描到的位置。空匹配、读取失败、权威缺失和位置断档分别表达，不能因过滤为空自动确认未知区间。

## 接纳、交付与暂停

订阅保留原操作ID、名称、明确条件、消费者用途、创建起点及启用状态；同ID不同定义冲突。服务端以发布事务内持久变化流和固定订阅条件提供有界拉取交付，通知呈现不成为源发布的前置条件。实际提供的交付批次、最后确认位置及提醒持久保存；提醒唯一键使用订阅与源变化身份，重复投递不产生第二个提醒，不同更正不去重成旧提醒。已保存定义不因页面离开或进程重启消失。

Terminal按已保存订阅读取有界交付页，显示源事件/陈述/变化、原件入口、可用时间、交付用途、当前最后确认位置和待核对范围。确认只前移至实际提供的连续范围；不能跳过未读未知区间，重放同一确认幂等。条件改变形成显式的新订阅定义，不以原ID改写已交付语义或自动回填全历史。

暂停停止后续提醒接纳，保留历史及最后确认位置；源变化流继续留存。恢复必须先显示暂停期间的明确范围，按用户选择补取或显式选择新的前向起点，不能静默认为已追平。订阅停止不删除历史或源证据。

## 断连与历史补取

客户端中断后保留原最后确认位置，当前来源不可用显示未知范围。恢复连接仅取得新的源位置，不把积压提醒或缺口标已确认。显式补取固定原订阅、起点、终点和操作ID，分页有界，历史补取标签持久保留；同源变化跨实时/补取重复不生成第二个同身份提醒。补取期间新发布超出原终点，另列后续待处理范围，不能延长用户已确认范围。

服务重启恢复源位置、订阅状态、提醒与确认记录；崩溃前后同发布操作仍只产生一个位置/提醒。保留实际处理和交付时间，不把补取时间当首次公开时间。订阅交付确认仅表示收到该范围，不表示严格历史资格、Research已拥有数据或策略/交易已执行。

## 存储、冷备与协议边界

现有ledger.sqlite增加当前类型化变化流/订阅/提醒/位置记录及必要查询索引；不新增默认数据库服务器。权威表缺失或不支持的结构明确拒绝，保留原文件，不迁移、重建或清理既有真实账本。所有测试仅用隔离合成文件。

业务请求沿Intel直连端点；Manager/Agent只发现服务。读写分在原有有界读线程/串行状态与事务边界，控制请求不被无限扫描阻塞。预览只读；启用、暂停、确认、明确补取具有固定操作身份。错误区分条件无效、位置冲突、源不可用、范围未覆盖、容量及恢复错误；超时不据此推断写入未执行，应查询原操作。通知读取不访问真实供应商，也不触发Data下载或Research计算。

冷备须保存发布流连续位置、订阅条件/状态、精确源引用、提醒与确认/历史补取标签。独立恢复核查原发布/变化及Data依赖闭包，不启动服务或恢复外部授权；缺源不能宣称完整。资源索引只展示实际对象，不决定删除。正式Research结果物理删除、A02/A03仍为独立待决事项。

## 验收顺序

1. 实际P/P重放/R/C/W产生单调且不重复的精确已发布变化；提交故障回滚，重启位置不变，空匹配与断档区分。
2. 条件预览→显式启用→真实新发布匹配提醒→原位置确认；重复变化不重复，不同更正分别呈现。
3. 暂停无新提醒而历史保留；恢复显示范围，明确历史补取/去重，确认前不宣称缺口已闭合。
4. Native/页面完整操作与源证据入口，来源失联/恢复、所有者切换及迟到响应不串到另一订阅。
5. 冷备/独立恢复保留条件、位置、提醒、原源依赖及历史补取标签。以实际进程和浏览器证明，不用接口或列表数量代替业务验收。
