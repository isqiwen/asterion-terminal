# 实施进度

更新：2026-09-20。唯一架构基线为 [当前架构](architecture.md) 与 [AGENTS.md](../AGENTS.md)。本页按当前能力组织，不再保留被替代的阶段设计和兼容路线；过去提交可从版本历史查看。验证范围见 [验收索引](VALIDATION.md)。

基本架构原则：机制核心承载通用能力，所有产品功能通过内置或外部插件实现。现有功能已接入内置插件清单、依赖检查与宿主生命周期；本地受信 Python 数据源与声明式表格已通过固定包和独立进程接入；同用户执行不等于恶意代码安全隔离。

## 当前已实现

- 桌面：原生启动、独立设置、多窗口会话与布局修订、图表拆出/归并、分栏与视口恢复；服务详情区分 API、worker、数据库和数据源验证状态。
- 身份：本地账号、注册 PIN、跨窗锁定、密码重设、会话与业务接口鉴权。账号必须具有注册时建立的完整安全状态。
- 任务：命令幂等、租约、心跳、取消、发布事务与可信处理器注册；worker 子进程提供故障隔离。
- 数据源：生产仅注册 Tushare；配置声明生成表单、草稿测试、修订 CAS、加密配置快照、固定任务输入；具名连接、停用/归档、验证记录。
- 数据：统一类型、RAW/STANDARD 目录、逐段证据与续传、日线/日历累积月分区；本地 CSV 显式类型/来源/频率/映射及预览校验。
- 覆盖：固定日历/合约资料核对、显式外部依据、手动缺口补齐及持久化重试追踪；同连接研究准备先发布资料，再原子提交固定身份的日线任务。
- 研究：单合约日线模型、固定输入、严格/探索模式、结果对比与原输入重跑；账户隔离草稿/模板、结果 ZIP、当前契约复现包及核验。
- 生命周期：直接引用展示、可恢复归档、当前格式一致备份、隔离 PostgreSQL 恢复验证、受保护环境切换/回滚及中断恢复。
- 工程：Python/TypeScript/Rust 单元验证、PostgreSQL 并发验证、浏览器回归及冻结运行包冒烟脚本。合成提供方只在 tests 中。

- 外部扩展：固定 ZIP、内容摘要、原子安装回执、显式信任启用、精确依赖、停用撤销、保留工件移除；独立 Python 进程支持数据源、声明式表格和逐根收盘策略，公开 SDK 与可复制样例落盘。
- 插件化：后端按清单装配路由、任务、诊断和备份校验，跨插件端口声明提供者、消费者与类型，研究通过注入的数据读取能力协作；启动资源由发行版逐项授权，任务端口限制任务类型，异常处理器通过声明登记，数据和身份服务通过操作端口使用加密与摘要能力；Worker 处理器仅接收输入及声明的执行资源，上报绑定当前任务与租约；备份校验仅消费领域输入与受限只读文件能力，恢复清理通过一次性领域操作与任务取消共享事务，遗漏或失败统一回滚；前端插件贡献工作区、面板、设置和任务展示，面板与设置按声明 scope 接收资源、通过明确操作更新工作流，数据/研究/任务通过不含凭据的受限请求客户端调用服务，工作台外壳不依赖业务插件；Rust 窗口策略由内置插件注入。见 [接入说明](builtin-contributions.md)。

## 当前契约约束

配置、任务、导入、账号与布局均按当前完整结构校验。测试从当前合法输入构造缺字段、未知版本和非法值，不维护历史格式样例或废弃接口清单。校验失败明确报错，不改写用户数据。具体边界见 [当前契约校验](validation/current-contract-cleanup.md)。

## 后续顺序

维护者已将期货领域基础指定为第一优先级。唯一实施顺序和验收条件见 [期货领域基线](futures-domain.md)，基础未验收前不优先扩展外围产品功能。

| 顺序 | 尚待交付 | 验收重点 |
|---|---|---|
| F1 | 统一实际合约身份、来源标识、时间与规则所有权 | 全链路引用一致，删除重复领域模型，生命周期和来源歧义拒绝 |
| F2 | 主力/次主力等角色映射 | 固定证据、候选集、可知时间与生效时间；无未来信息 |
| F3 | 连续序列与复权 | 固定换月血缘和因子，信号价格与实际成交价格分离 |
| F4 | 正式交易规则、持仓、订单资金账 | 双向、今昨、部分成交、费用、结算、冻结及风险校验 |
| F5 | 多合约换月与恢复 | 双腿非原子执行、失败敞口、重复回报、重启对账 |
| F6 | 端到端领域验收 | 真实来源跨月研究、复现、恢复、冻结包与模拟交易；实盘单独验收 |
| 后续产品扩展 | 更多策略、优化、布局增强、AI、市场分发、远程计算 | 基础验收后按真实需求安排 |

核心权限、插件生命周期、事务与故障正确性回归贯穿上述阶段；发现影响安全或数据正确性的问题及时修复。当前研究功能保持其已声明的有限范围，不代表 F1–F6 已完成。

贯穿阶段的开源准备：许可证与品牌、贡献维护责任、独立样例、SDK 当前契约测试、可复现构建、私密问题渠道。本地受信插件可安装；在线市场和不可信代码 OS 沙箱不在当前交付范围。

## 明确边界

已有 Tushare 单日、单合约的历史在线验证记录，见数据工作流验收；更大范围的账户权限、限流和数据权威性仍待验收。本轮使用隔离数据，自动测试不代表真实交易已验收。多显示器热插拔、其他机器分发、Windows 支持仍待专项验证。自动补齐调度、永久删除与磁盘回收尚未实现。备份密码加密按维护者决定暂不开发；不建设旧格式自动迁移。

### 2026-09-20：每日结算参数

## 日线研究策略插件

双均线与收盘动量以独立内置插件贡献，研究目录经声明能力注入，Worker 经声明资源使用相同目录。策略元数据驱动选择和整数/小数/开关/枚举参数表单；运行固定 ID、版本、源码摘要和参数，重跑/复现拒绝身份不匹配。成交、费用与保证金仍由研究引擎统一执行，无核心策略分派分支。外部 ZIP 策略安装、显式信任启用和独立进程会话已实现；OS 安全沙箱、第三方依赖环境、多合约执行尚未实现。见 [策略插件契约](strategy-plugins.md)。

## 后台运行版本核对

已按运行文件内容识别后台构建，应用更新后首次启动自动切换后台，相同版本复用；启动必须核对实际 supervisor 身份与 API/Worker 状态。macOS 实际切换和不重复重启已验证，保留任务输入与结果。Linux 实际服务升级、运行中任务跨版本切换和交易节点升级协议仍需专项验收。见 [桌面运行时](desktop-runtime.md#应用更新后的后台版本核对)。

### F1 进展：实际合约生命周期身份

### F1 进展：来源无关的规则依据

规则插件已移除 Tushare 品牌判断、专属路由与后缀/乘数解释；通过标准合约和结算资料消费任意符合当前契约的来源。Tushare 的字段解释归其数据源适配器，`futures.contracts` 当前 schema 4 包含标准行情代码及带说明的乘数建议。非 Tushare 来源及不透明外部代码已由用例验证；当前生产内置源仍只有 Tushare。规则和结算证据使用目录生命周期身份，按规范 ID 核验。

### 本地插件安装流程

本轮按维护者明确要求完善安装体验：选择 ZIP 后预检和确认，点击一次完成安装并启用，缺失依赖给出具体版本要求，成功提示配置或使用入口。没有增加在线市场、自动依赖下载或一键更新；后续继续按期货领域基础优先级推进。

### 本地插件拖放

安装区域支持单个 ZIP 拖放，复用文件选择的预检与信任确认。增加文件类型、数量、空文件及并发输入校验，错误后可重试。尚未实现自动下载依赖或一键版本替换；不改变后端安装契约。

### F1 进展：同步资料到固定身份目录

已接通当前标准合约资料的预览与目录发布，保留完整交割年月、上市/最后交易/最后交割日期、来源版本和 SHA-256。目录不再重复保存交易规格。界面可从已同步资料选择来源代码发布，固定资料引用纳入版本详情与备份校验；通用发布路径不识别 Tushare 品牌。

真实 Tushare SHFE 3592 条资料及 RB2505 身份解析通过；行情同步、导入、覆盖、研究与规则已强制绑定固定身份。
