# 多合约历史下载验收（2026-09-22）

已接通数据插件 API：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/data/history` | 最近 20 个已提交计划摘要，用于重新打开恢复 |
| `POST /api/v1/data/history/plan` | 固定资料、日历、代码和日期，预览实际合约月份任务 |
| `POST /api/v1/data/history` | 完整校验后一次性提交，原命令重发幂等 |
| `GET /api/v1/data/history/{command_id}` | 读取原计划、原任务及失败重试链 |
| `POST /api/v1/data/history/{command_id}/coverage` | 针对该批固定输出核对覆盖并汇总 |

请求字段为 `command_id`（UUID）、`provider`、`connection_id`、`exchange`、`contracts_version_id`、`calendar_version_id`、`symbols`、`start`、`end`。缺少固定依据应先通过现有同步完成日历与合约资料；不隐式选最新。任务取消、错误详情和重试继续复用任务中心及原 API。接口受账户和数据权限保护，研究权限不能直接提交历史批次。

`tests/test_history_downloads.py` 使用隔离 SQLite、真实插件装配/API、任务租约和 Parquet 发布，供应商输入为明确的合成记录，不连接网络：

- 两个实际合约、两个月拆成四个任务；按上市日裁剪，统计 64 个合约交易日。
- 无日历覆盖、未知代码或第三个任务校验失败时零任务入队。
- 原请求重发返回相同任务，修改日期复用命令冲突；原始配置在响应丢失重发时保持不变。
- 两个线程同时提交同一请求，最终仅四个任务。
- 任务全部成功但某合约缺一天，汇总为 GAPS；缺口仍保留且可追溯报告。
- 失败任务经现有接口重试后仍归属原计划，完成后覆盖通过；新服务实例能够读取计划。
- 备份证据包含计划，缺失固定日历拒绝校验，版本检查器显示历史计划引用。
- 无凭据及错误权限拒绝访问；数据权限可预览、提交、重发、查询和核对。

桌面接入范围见下节。未执行真实供应商批量下载、PostgreSQL 并发或大规模覆盖性能验收，未生成安装包。接口和离线流程通过不等于期货领域 F2/F3 已获得真实数据验收。
