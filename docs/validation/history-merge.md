# 历史月分区增量合并验收（2026-09-22）

本轮验证数据功能插件的增量发布，不是供应商下载吞吐、完整研究或分钟历史库验收。机制核心未增加业务规则；没有访问、转换或删除用户历史数据。

## 可重复基准

```bash
uv run python scripts/benchmark_history_merge.py seed --root /tmp/asterion-history-benchmark --months 120 --contracts 500
uv run python scripts/benchmark_history_merge.py measure --root /tmp/asterion-history-benchmark --output /tmp/asterion-history-result.json
```

根目录必须新建，测量只接受该工具生成的合成夹具；报告不能覆盖。建库与测量分进程，峰值 RSS 包含解释器与运行库、不含建库阶段；测量的目录事务回滚，工件保留在独立夹具目录。仅供开发基准，不是真实合约来源证据。测试符号不代表通过实际合约身份验收。

每月 20 个日期、500 个合成合约，修订最后一个月的一条记录。120 个月为 120 万行、12 个月为 12 万行，每次触及 1 万行的月份。数据重复度高，120 万行 Parquet 总量约 1.6 MB，不能代表真实数据压缩率或磁盘吞吐。Linux x86_64、Intel i7-14700K、28 逻辑 CPU、Python 3.13.5；OS 页缓存未清空，以下为单次测量，不承诺固定加速比。

| 实现/历史量 | 分区读取数 | 分区读取字节 | 合并耗时 | 进程峰值 RSS |
|---|---:|---:|---:|---:|
| 修改前，120 万行 | 120 | 1,660,550 | 8.607 秒 | 1,578,320 KiB |
| 修改后，120 万行 | 1 | 13,838 | 0.092 秒 | 120,612 KiB |
| 修改后，12 万行 | 1 | 13,838 | 0.091 秒 | 120,164 KiB |

三次各写入一个 13,641 字节的新分区。前后 120 万行试验生成的完整分区清单逐字节相同，均保留 120 万行且仅修订一条记录。清单本身随分区数增长（120 月 24,875 字节、12 月 2,519 字节），元数据工作量未消失。

原始本机报告：`.state/history-merge-before-120m.json`、`.state/history-merge-after-120m.json`、`.state/history-merge-after-12m.json`。修改前通过本轮修改前保存的代码做独立基准，没有把旧实现作为运行回退保留在项目中。

## 正确性与边界

回归覆盖：新月份不读取旧分区、同月修订仅读取该月份、旧版本重读不变、图表延迟投影与逐行可知时间、迟到观测、等时冲突、日历跨月/闰日缺口补齐、磁盘写入失败不推进版本及重试、来源身份、备份全部工件校验和投影引用篡改拒绝。现有图表价格与成交量校验继续在触及月份执行。

未修改月份按已发布清单复用，因此发布不是全库磁盘巡检。未消费分区事后损坏会在读取或备份检查时拒绝；触及的损坏分区当次合并就拒绝。不得将成功增量发布展示为全库完整性审计通过。

SQLite 与真实 FastAPI 离线流程已验证；PostgreSQL 并发测试需要显式独立测试数据库，本轮环境未配置，因此相关用例跳过。未运行真实供应商采集、实际 PostgreSQL 并发或分钟千万行基准；后续研究日线批次读取已接入，范围见 [扫描验收](history-scan.md)。
