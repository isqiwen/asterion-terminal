# 日线与结算同步身份准入验收

## 当前契约

数据管理插件拥有 `SyncSubmission`、`SourceIdentity` 和共享任务检查；机制核心没有市场规则或供应商分支。供应商 `SyncRequest` 仅包含采集参数。

- 日线与结算用户入口必须显式选择同源、同连接的合约资料版本，不自动选择最新依据或转换来源代码大小写。
- 内部 `DataSync.submit`、普通重试、准备重试、覆盖补齐均检查固定身份；缺失身份不能创建新任务。
- Worker 采集前检查能力类型、身份、来源代码、交易所及请求生命周期；发布再核对固定资料文件、完整目录内容及逐行实际合约。不能通过篡改任务类型或保留资料校验和却改写目录来绕过。
- 发布范围包含规范合约 ID；备份恢复要求供应商日线与结算携带同一身份依据。文件导入按 `ImportIdentity` 显式映射契约独立验证。
- `submission_payload` 是准备流程的未入队模板，不代表已通过身份准入。资料依赖就绪后才提交完整任务，模板不能直接通过 Worker/发布检查。
- 不符合当前契约的记录保持原样，拒绝执行，不补字段、不迁移、不改变既有数据集身份。

## 测试构造

真实期货流程的自动测试先发布明确的合约资料，再通过当前准入提交任务。虚构 SIM 行情归属独立测试类型 `testing.synthetic`，只在 opt-in 测试注册表中登记，不进入生产注册或桌面包，也不能冒充 `futures.daily` 进入期货覆盖/研究。生产校验没有 demo 例外。

用例覆盖缺失身份、错误连接/代码、跨生命周期、资料文件损坏、伪造目录、任务类型篡改、重试与补齐不得重新入队、发布规范身份、恢复校验失败不改写文件，以及文件导入独立身份契约。界面验证日线与结算均选择固定资料，修改代码后清空选择并保留大小写。
