# 终端体验与可组合工作台

状态：目标设计，2026-09-19。本文约束后续界面与交互实施，不代表功能已经交付。
总体边界见 [系统架构](architecture.md)，当前交付证据见 [实施进度](ROADMAP.md)，色彩和控件依据 [视觉规范](ui-style.md)。

## 1. 产品目标与现状

Asterion 应当让用户从安装、获得数据、验证想法到运行策略拥有连续的工作环境，也让开发者通过扩展组成自己的终端。
“现代、科技、未来感”体现为明确的对象关系、即时反馈、可组合面板、稳定恢复和可追溯结果，不靠装饰动画或堆叠入口表达。
默认体验面向一台机器、一个本地工作环境；多机器、多账户、复杂研究流水线按需要出现。

| 能力 | 当前实现 | 本文目标 |
| --- | --- | --- |
| 视觉 | 黑橙主题、等宽数字、紧凑/舒适密度 | 组件与插件共享语义令牌及交互规范 |
| 导航 | 六个固定业务区，研究/交易/情报为未接入空态 | 按已启用能力登记导航、对象入口和命令 |
| 工作区 | 行情/图表停靠、图表拆出归并、A/B/C 联动 | 通用面板树、命名布局、模板导入导出 |
| 身份 | 本地账号、PIN、宿主多窗口会话 | 本地身份独立于可选云账号，默认使用不依赖云 |
| 设置 | 独立原生窗口；数据源按字段声明生成表单，草稿测试与配置修订 | 可搜索、分级披露、当前规范校验和配置导入导出 |
| 数据流程 | 同步、任务、版本、证据、覆盖核对及手动补齐 | 完整流程导航和可恢复工作上下文 |
| 扩展界面 | 业务组件直接组合，暂无通用 UI 扩展宿主 | 声明式贡献点及受控组件接口 |

## 2. 可验收的终端气质

1. 工作台的主体是图表、表格、编辑器和结果；每个面板只有一个主操作，次要动作进入工具栏或菜单。
2. 当前对象、数据时间、来源状态始终可辨认；历史数据标明“历史”，合成数据标明“演示”，不得借视觉造成实时行情印象。
3. 交易面板固定显示账户与模拟/实盘环境；品种联动不得切换账户或环境，布局恢复不得触发业务提交。
4. 状态同时使用文字、形状或图标，不只依赖颜色；未知、未配置、无数据、无权限和失败使用不同空态及下一步动作。
5. 现有 `theme/tokens.css` 是黑橙色彩的唯一实现来源。品牌橙色表示选中、焦点与主操作；涨跌颜色遵循用户偏好。
6. 插件复用字体、边框、间距、密度和状态令牌；不得加入另一套全局主题或把品牌色用作盈亏含义。
7. 所有主流程支持键盘操作；焦点可见，面板和分隔线有名称，菜单关闭后焦点返回触发位置。
8. 紧凑模式提高信息密度，舒适模式扩大行高与点击区域；不得通过压缩字体使错误、单位或账户标识不可读。
9. 小窗口允许按优先级折叠次要工具；数据表内部滚动，避免整页和多层容器同时抢夺滚动。
10. 动画仅解释切换、加载和完成，支持减少动态效果；后台刷新不得闪烁整表、改变用户选中项或夺取焦点。
11. 错误先说明影响和下一步，例如“凭据无权限，已保存的版本仍可查看”；技术详情与关联标识可展开和复制。
12. 路径、端口、服务角色、版本哈希等进入详情或诊断；只有需要用户作决定时才出现在主流程。

## 3. 对象导航与统一命令

业务区是默认工作模板，不是互不相通的页面岛。面板围绕品种、合约、数据集、版本、研究运行、策略发布和账户打开。
导航使用稳定对象引用，例如 `{ kind, id, revision? }`；显示名和中文标签不参与持久化主键。
数据版本、研究输入等要求固定身份的引用必须包含明确版本；“最新”只作为查询选择，并在执行前解析成固定输入。

目标登记表包含以下贡献：

| 贡献 | 必需信息 | 宿主职责 |
| --- | --- | --- |
| 命令 | 命名空间 ID、标题、参数 schema、适用上下文、执行能力 | 菜单、命令面板、快捷键调用同一入口 |
| 面板 | 类型 ID、标题、可接受对象、状态 schema、默认尺寸 | 打开、聚焦、停靠、错误边界、状态恢复 |
| 对象动作 | 对象类型、动作 ID、可用条件 | 统一检查器和上下文菜单 |
| 导航入口 | 能力要求、默认面板或工作模板 | 按启用能力展示，维护选中与返回路径 |

全局搜索区分“对象”与“命令”，支持按类型过滤；命令面板建议使用 `⌘/Ctrl+K`，最终快捷键在统一登记表定义。
同一命令 ID 只能登记一次；快捷键冲突由宿主展示并允许用户重绑定，不按插件加载顺序静默覆盖。
不可用命令给出原因与可行入口；搜索和菜单中的禁用状态必须一致。
快捷键执行以当前焦点面板为上下文；输入框内不得拦截普通文字编辑快捷键。
所有长期操作返回任务引用，显示“已受理”，随后按任务状态更新；刷新和再次打开面板只附着已有任务。
可观察的命令状态包括未提交、提交中、已受理、执行中及终态；网络超时不得直接当作执行失败或自动换命令 ID 重发。

## 4. 面板树与状态所有权

通用布局应是带 `schema_version` 的文档，由 `Workspace → Window → split/tabs/panel` 构成。
工作区、窗口、面板实例分别拥有稳定 ID，面板类型使用扩展命名空间，例如 `asterion.market.chart`。
逻辑布局保存面板内容与比例；显示器、坐标和 DPI 偏好按设备保存，不导入另一设备的绝对位置。
逻辑布局不携带认证会话、凭据、任务结果、订单状态或大规模行情数据。

| 状态类别 | 内容示例 | 权威位置 |
| --- | --- | --- |
| 视图状态 | 分屏比例、选中标签、排序、筛选、时间范围、联动组 | 工作区与面板状态文档 |
| 用户偏好 | 密度、涨跌颜色、快捷键 | 本地偏好设置，允许安全导出 |
| 业务状态 | 已发布版本、任务、研究运行、账户与委托 | 对应业务服务，面板保存引用 |
| 临时输入 | 尚未提交的参数草稿 | 面板草稿；需区分已保存和未保存 |

面板状态独立声明当前 schema；不受支持时保留原始状态并说明原因，不自动迁移或删除整个工作区。
卸载或禁用插件后，其面板变为“扩展不可用”占位；保留类型 ID 和状态，用户可安装符合当前契约的版本或明确删除占位。
拆出与移动使用“保存状态 → 目标确认挂载 → 源释放”的协议；目标失败则源面板保持可用。
布局更新需有修订检查；冲突时合并可独立的视图字段或要求重新应用，不能静默覆盖另一窗口的修改。
每个联动组显式声明对象、时间范围、游标等主题；面板可锁定接收，锁定不等于停止业务任务。
视图挂载和恢复必须没有业务写入副作用；启动策略、提交回测、下单均需要明确命令。
窗口关闭释放自己的订阅；共享订阅由协调层按消费者管理，UI 显示节流不得改变策略输入。

## 5. 开箱与渐进配置

默认安装包负责本机运行环境准备，普通用户不需要安装 Python、PostgreSQL 或编辑环境变量。
正式产品的入门路径是“连接真实数据源”与“导入本地文件”，不包含合成示例入口、演示工作区或启用开关。
合成数据仅用于开发与自动化测试，测试工具不进入正式运行包。已有历史示例产物保留明确标记，不自动删除或视作真实行情。

身份层面，本地工作环境的使用权与未来可选云账号分开。云账号仅在用户启用同步、协作或远程服务时出现。
本地账号确认不能成为云端已验证身份，也不能据此声称拥有邮箱；云端能力需独立认证。
当前注册必须设置 PIN；不为缺少安全状态的旧账号补设。未来简化本地入门须明确新的账号和锁定契约。
现有本地账号共享工作区，不是多租户隔离；界面不能把账号切换描述为切换独立数据空间。

设置保留独立窗口，按“常用 → 高级 → 开发者”披露字段；默认表单只要求完成当前动作的必要输入。
数据源只问来源与它声明的凭据；远程机器、并发限制、代理和存储策略在启用对应能力后出现。
设置可搜索，每个字段显示默认值、当前生效来源和是否需要重新连接或重启；业务操作留在业务面板。
统一配置 schema 定义类型、默认值、范围、帮助、敏感级别、展示分组及适用能力，表单与服务端校验引用同一契约。
配置作用域明确区分用户偏好、工作区、连接、执行环境；禁止隐式让一个插件覆盖另一个插件的设置。

schema 可采用 JSON Schema 2020-12，展示分组等 UI 元数据使用受控扩展；可用字段类型与校验子集在 SDK 中固定，并以相同 fixture 验证前后端行为，不能让客户端自定义脚本成为校验器。[JSON Schema 规范](https://json-schema.org/draft/2020-12)
每个字段声明允许覆盖的作用域。通常按“内置默认 → 已应用连接/环境配置 → 本次运行显式参数”解析，运行记录保存最终值及来源；工作区偏好不能覆盖账户授权或系统风险上限。开发环境变量单独显示来源，不悄悄压过桌面已保存配置。配置中的秘密引用固定用途与版本，轮换影响由宿主处理并可追溯。

配置生命周期采用 `draft → test → apply`：

1. 编辑产生草稿，不立即影响运行任务；测试针对明确草稿修订，并展示测试范围及检查时间。
2. 凭据测试经宿主受控暂存，不回显秘密；暂存有期限，取消或应用后按策略清理。
3. 应用携带 `expected_revision`，服务端校验并返回新配置修订；冲突显示差异，不能覆盖他人的新修订。
4. 测试成功只证明所列检查通过，不表示所有接口、未来网络或实盘连接可用；应用时重新检查必要条件。
5. 运行任务绑定已应用修订，修改默认配置只影响后续任务；涉及重启和运行中策略时，先显示实际影响再执行。

配置文档仅保存 `CredentialRef`。导出默认脱敏，删除秘密、账号标识及本机路径等私有绑定，并列出待重新配置项。
导入先校验 schema 与扩展依赖并预览差异；不执行任意命令、不自动启用交易、不自动恢复陌生机器连接。
工作模板允许分享面板布局、参数结构与扩展依赖；数据和第三方授权不随模板隐式分发。

## 6. 插件界面的贡献边界

第一阶段优先支持宿主渲染的声明式配置表单、表格列、检查器区块、对象动作、图表数据层和工作模板。
复杂自定义面板走独立、版本化的 UI 扩展接口；当前没有安全加载任意第三方 React 组件的机制。
在隔离宿主尚未实现时，只接受经过审查并随应用构建的可信 UI 扩展，不把动态导入或 React 错误边界称为安全沙箱。
UI 扩展只获得宿主提供的上下文、授权查询、命令提交和面板状态接口；不接收全局会话令牌或凭据明文。
扩展不得直接访问 Tauri 任意命令、宿主 DOM、数据库和其他扩展状态；真实隔离与权限执行由扩展运行架构实现。
声明式能力中的读写范围、账户、环境与数据空间由宿主确认；隐藏按钮不能替代服务端权限检查。
插件不能自建与宿主矛盾的任务、身份、设置、错误展示和交易确认体系，也不能绕过业务校验直接发布结果。
主题扩展只能覆盖允许的语义令牌；需要单独预览、恢复默认和可读性校验，不接受任意全局 CSS 注入。
扩展停用后撤销入口并释放订阅；已启动的持久任务仍由任务服务负责，并显示扩展不可用对后续操作的影响。
界面贡献先由内置面板使用同一接口验证；添加业务面板通过插件登记完成，不修改工作台外壳的分派逻辑。

## 7. 核心用户流程的验收

| 流程 | 预期操作与完成证据 |
| --- | --- |
| 首次体验 | 安装、启动、进入合成演示、打开图表；无需外部凭据或终端命令，演示标识始终可见 |
| 获取历史数据 | 选择来源并配置、测试、同步、在任务中观察进度、打开固定版本；失败定位到来源、权限或分段 |
| 核对及补齐 | 选定版本和日期、核对依据、提交确认缺口、查看任务、重新核对；未知日期不能显示为齐全 |
| 研究运行 | 从固定数据版本进入研究、选择策略与参数、查看已解析输入、提交、比较结果；正式引擎交付前不开放假完成流程 |
| 组合工作台 | 添加面板、设置联动、拆出、保存命名布局、重开；对象与视图恢复且没有重复任务 |
| 安装扩展 | 查看兼容性与能力、按支持渠道安装、启用、打开贡献入口、禁用；不兼容状态可解释且可恢复 |
| 故障恢复 | 断连后保留最后可信信息、标注时效、重连读取权威状态；不把重连当作重新提交操作 |

每条流程配一份无私有凭据的可重复演示和契约测试；需要真实提供方或经纪商的验收单独记录环境及证据。
文档和空态必须区分“已交付”“可配置但待验证”“规划中”，不能用入口数量代表产品完成度。

## 8. 异常与恢复

面板异常只隔离该面板，提供重试和诊断关联 ID；不能使任务中心、设置和其他面板失去响应。
断连时显示最后更新时间和断连状态；重新连接后先读快照，再按可恢复事件协议继续，缺失区间不得假装已补全。
下单与执行状态未知时保持未知，交由业务对账；普通网络“重试”按钮不能创建新的交易意图。
账号退出或 PIN 锁定统一屏蔽业务内容和接口操作；解锁后恢复布局并重新加载已授权数据。
本机服务启动失败提供可理解的步骤、重试和脱敏诊断；查看设置不得意外重启用户已停止的后台服务。
保存布局失败明确提示“当前布局未保存”；不能继续展示成功，也不能因此中断已受理的后台任务。
缺失显示器时将窗口收回可见区域；快捷键或设置提供“恢复所有窗口”，不依赖用户找回离屏窗口。

## 9. 建议指标与实施顺序

以下是待基准环境确认的验收目标，当前未测量，不作为已实现的性能承诺。

| 指标 | 建议目标与测量条件 |
| --- | --- |
| 本地命令检索 | 1,000 条登记命令，已加载索引时 P95 ≤ 100 ms |
| 交互响应 | 默认工作台切换、选中与输入反馈 P95 ≤ 100 ms；网络耗时单独显示 |
| 长任务反馈 | 本地提交后 200 ms 内显示提交中；任务受理时间单独统计，不能伪造进度 |
| 工作台恢复 | 10 个面板在后台健康、数据缓存可用时，P95 ≤ 2 s 出现可交互布局 |
| 大表格 | 10 万条查询结果使用分页或虚拟化；渲染量受视口限制，不一次挂载全部行 |
| 初次演示 | 产品验收者从安装完成到看到演示图表 ≤ 3 分钟，不含系统授权与首次冷启动下载 |

先抽取命令、面板和设置登记表，让现有内置功能沿同一接口运行，再建设通用面板树与当前状态校验。
随后交付合成演示和声明式设置，补齐配置修订与脱敏模板；同时用第二个真实扩展验证接口是否通用。
开放第三方复杂 UI 前，完成兼容性、权限执行、隔离、禁用恢复和无凭据开发样例；市场分发不是首个前提。
每个阶段以表内核心流程和失败恢复作为退出条件；保持可用的默认工作台，避免要求用户先理解全部模块才能开始。

### 服务连接详情

工作台左下角的「● 服务」入口（悬停提示「查看服务状态」）可展开服务状态面板，每 5 秒更新，也可手动重新检测。

- 本机 API：本次状态请求是否可达；数据库：实际执行轻量查询。
- 任务执行器：使用桌面 supervisor 最近 5 秒内的进程观测；观测缺失或过期显示「无法确认」，进程存在不代表任务必然成功。
- 数据源：区分未配置、配置异常、本地示例可用与已配置按需连接。保存凭据不代表外部接口可用，需进入数据源设置主动测试。
- 实时行情、交易网关：尚未接入时明确标示，不与本机后台状态混合。
- 状态请求失败后清除旧结果，不保留绿色正常状态。接口使用本机会话鉴权，并遵守账户与 PIN 访问限制。
