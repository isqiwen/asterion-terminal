# 券商仿真验收

本清单用于提供商明确标识为仿真的 CTP 环境。前置地址、账户和交易时间以提供商配置为准；实际验收结果记录在报告中。

## 准备

- 使用当前 macOS 或 Linux Terminal 安装包及独立 Linux 服务包，记录 Git 提交、安装包 SHA-256、操作系统版本、CTP SDK 版本、运行时间和交易日。
- 只在对应 Market/Trading 主机的安装脚本中输入密码和授权码，不写进报告、截图、终端命令或源码。报告中的账户、前置地址和委托编号脱敏。
- 创建一个命名的专用测试账户，系统自动管理记录目录；保留全部原有账户。选定可交易的实际月份合约；核对最小变动价位、乘数、价格限制和一手风险限额。
- 在交易主机配置明确标记为仿真的账户，Terminal 只读取该身份；核对账号及前置地址，系统无法自动验证资金性质。
- 可先运行 `python3 tests/acceptance/ctp_market.py --help`，按参数提供已登记的客户端证书目录和 Market 服务证书指纹，连接只读行情；该工具使用隔离 Terminal 连接已有 Market，不收取密码、不报单。工具成功不能代替下列交易验收。
- 交易的自动验收见下文“自动验收脚本”。它会向你指定的柜台发送真实委托，只能用于仿真环境。

## 首次配置

先在交易主机安装交易服务并登记连接，再完成 CTP 连接。

1. 从仿真服务提供商取得同一环境的行情前置、交易前置、经纪商代码、投资者账号、AppID、密码和授权码。地址和可交易时段以提供商为准。
2. 在 Market 主机安装 `Asterion-Market-<版本>-linux-x86_64.sh`，输入行情所需配置与凭据。在 Trading 主机独立配置专用仿真账户与凭据，登记 Terminal 证书指纹。
3. Terminal 的 **设置 → 数据源 → Market 行情服务** 保存 Market 地址，连接后读取目录。在 **设置 → 交易连接** 保存 Trading 地址和服务证书指纹，选择账户。
4. 从目录选取待验收的实际月份合约，设置单笔数量、总持仓、在途委托上限和价格偏离比例，核对摘要后创建账户政策。凭据不进入桌面表单。
5. 等待 **已就绪**，核对资金、持仓和账户费率。保持未授权，完成核对后确认账户并点击 **允许发送委托**，按下表验收。

Market 与 Trading 由 systemd 独立启动。关闭 Terminal 或客户端连接不会停止服务，也不会自动撤权、撤单或平仓。
重连读取原服务状态；Trading 重启后须重新授权。主机安装见[Market](../market/deployment.md)与[Trading](../trading/deployment.md)。

只读行情脚本要求全部合约收到报价，关闭并重新连接后服务实例仍相同，随后清理隔离 Terminal；不停止 Market。
报告含服务地址，分享前须脱敏，不包含柜台密码。

## 顺序与通过条件

| 检查 | 操作 | 通过条件与证据 |
| --- | --- | --- |
| 连接同步 | 连接仿真柜台，等待认证、登录、结算确认和账户同步 | 到达“已就绪”；资金、持仓与柜台客户端一致；记录耗时与错误码 |
| 账户费率 | 查询选定合约的保证金与手续费 | 与柜台费率一致；缺失返回明确显示，不补造；保存来源和交易日 |
| 未授权拒单 | 就绪但未授权时尝试提交 | 提交入口禁用；柜台无新增委托 |
| 风控拒单 | 授权后，测试超单笔限额或非法价格单位 | 返回明确拒绝；柜台无新增委托；资金和冻结未变 |
| 报单与撤单 | 在仿真柜台提交一手合法限价单并撤销未成交部分 | Trading 与柜台的方向、开平、价格、手数、状态相符；撤单或已成交竞争有明确终态 |
| 成交核对 | 在仿真环境完成一手成交，按交易所开平要求减仓 | 成交不重复，委托剩余量正确；资金、持仓、手续费与柜台一致 |
| 连接中断 | 存在在途委托时中断测试连接并重连 | 授权保留，同步完成前不能发送；不会自动重发；重新同步后委托、成交相符；不明确的委托保留为未确认 |
| 进程恢复 | 重启专用仿真账户的交易服务并恢复 | 重新连接、重新授权；已记录命令不重发；相同命令编号不产生第二笔订单 |
| 跨交易日 | 保留仿真环境允许的持仓跨交易日并重新同步 | 授权保留；昨日未成交的委托列为未确认，不重发；今昨仓、结算、费率与柜台一致 |
| Terminal 关闭 | 关闭窗口，再打开并连接原服务 | 交易服务独立存活；无重复服务或自动补发交易命令 |

报单、撤单、成交、断线测试需要在柜台可交易时段进行；不能以“当前无行情／不在交易时间”记为通过。遇到未确认委托先到柜台核实，不自动重试。完成后撤销授权，核实剩余委托及持仓，保留日志目录。

## 自动验收脚本

`tests/acceptance/ctp_trading.py` 用隔离 Terminal 连接已部署的 Market 与专用 Trading 仿真账户。
它复制指定 Terminal 的 TLS 身份与连接引用，不创建第二个 Trading 进程；凭据仍留在服务主机。
脚本会实际报单，必须显式提供 `--simulation`，并核对账户的环境、前置、经纪商和投资者身份。

```sh
python3 tests/acceptance/ctp_trading.py --simulation \
  --terminal-directory <Terminal安装目录>/terminal --trading-connection <连接ID> \
  --market-host <Market主机> --market-port 7450 \
  --market-fingerprint <Market服务证书SHA-256指纹> \
  --trade-front tcp://<仿真交易前置> \
  --broker <经纪商代码> --user <投资者账号> \
  --instrument SHFE:rb2610 --report ctp-trading-report.json
```

- 在可交易时段运行，验证行情、同步、未授权拒单、挂单与撤单、重连和撤权；不是策略运行器或现场预热验收。
- 使用专用仿真账户，运行前核实它没有此合约的持仓或挂单，避免与其他客户端并发操作。
- 结束时不平仓，保留服务端记录和报告；未知结果必须到柜台核实，不自动重发。

## 记录

每项记录 `通过 / 失败 / 未执行`、操作时间、预期与实际结果、脱敏截图或日志位置。报告同时标记仍未验证的柜台行为；任何失败都保留原始数据，修复后重新运行相应步骤。

## 隔离环境恢复回归

真实柜台验收前，先在 Linux 上已构建的工作区重复运行以下检查。所有进程测试经 CTest 注册的隔离包装器运行；CTP 使用测试 SDK，临时账本不接触正常环境。该测试覆盖三日柜台模型、重连丢失委托、迟到查询回报、服务崩溃与无客户端监督。

```sh
python3 tests/support/recovery_gate.py --build build/Release
```

脚本先从当前构建的 CTest 清单逐项核对六个完整测试名，缺失或重复注册立即失败；随后每项重复三次，任何失败都使命令失败，跳过也不能算通过。覆盖交易日/重连授权、迟到查询、交易服务恢复及独立健康通道。完整输出保存在构建目录的 `recovery-repeat.log`，JUnit 保存在 `recovery-repeat.xml`；JUnit 汇总不能单独代替三轮执行记录。长时柜台运行还需按上表完成实际时段、重连和跨交易日对账。
