# CTP 仿真验收

本清单适用于服务商明确标识为仿真的 CTP 环境。前置地址、账户与可交易时段均以仿真提供商为准，所有验收结果如实写入验收报告。

## 准备

- 使用当前版本的 macOS / Linux Terminal 安装包与独立 Linux 服务安装包，记录 Git 提交号、安装包 SHA-256、操作系统版本、CTP SDK 版本、执行时间与交易日。
- 密码与授权码仅在 Market / Trading 主机的安装脚本中隐藏输入，绝不写入报告、截图、命令历史或源码；验收报告中的账号、前置地址与委托编号均须脱敏。
- 创建专用命名仿真测试账户（由系统自动管理数据目录，保留其他已有账户），选定可交易的实际交割月合约，预先核对最小变动价位、合约乘数、涨跌停与一手风控限额。
- 在 Trading 主机明确将环境标记为 `simulation`，Terminal 仅读取该身份；须人工复核账号与前置地址，系统无法自动甄别账户资金性质。
- 可先运行 `python3 tests/acceptance/ctp_market.py --help`，传入已登记客户端证书目录与 Market 服务端指纹进行只读行情核验（脚本通过隔离 Terminal 连接已有 Market，不收密码、不报单；但只读通过不能替代下文交易验收）。
- 交易自动验收脚本见下文“自动验收脚本”，该脚本会向指定柜台发送真实报单，**严禁用于实盘账户**。

## 首次配置

先在服务主机完成安装与证书登记，再在 Terminal 建立连接：

1. 从仿真提供商获取同一环境的行情前置、交易前置、经纪商代码、投资者账号、AppID、密码与授权码。
2. 在 Market 主机安装 `Asterion-Market-<版本>-linux-x86_64.sh` 并配置独立行情账户；在 Trading 主机安装 `Asterion-Trading-<版本>-linux-x86_64.sh` 并配置专用仿真账户；分别登记 Terminal 客户端证书指纹。
3. 在 Terminal“设置 → 行情服务”保存 Market 地址与指纹并确认目录读取；在“设置 → 交易服务”保存 Trading 地址、端口、账户名与服务端指纹。
4. 从目录勾选待验收的实际月份合约，填写五项必填限额（单笔手数、单合约持仓、账户总持仓、在途委托上限、价格偏离上限百分数）及可选四项资金/撤单硬风控（日内亏损、最大回撤、保证金率上限、单合约日撤单上限），核对摘要后开通账户（凭据不进入桌面表单）。
5. 等待账户到达**已就绪**，核对资金、持仓与账户费率；此时保持未授权，核实无误后勾选确认账户并点击**允许下单**，按顺序执行下表核验。

Market 与 Trading 由 systemd 独立托管。关闭 Terminal 或断开连接不会停止服务，也不会撤权、撤单或平仓；重连自动读取服务端原状态，Trading 重启则必须重新授权。主机部署详见[Market 部署](../market/deployment.md)与[Trading 部署](../trading/deployment.md)。

只读行情脚本要求全部指定合约均收到报价，关闭并重连后仍为同一 Market 服务实例，随后清理隔离 Terminal 且不停止 Market；输出报告包含服务地址，对外分享前须脱敏。

## 顺序与通过条件

| 检查项 | 操作 | 通过条件与证据 |
| --- | --- | --- |
| 连接同步 | 连接仿真柜台，等待认证、登录、结算确认与账户同步 | 到达“已就绪”；资金、持仓与柜台客户端完全一致；记录耗时与错误码 |
| 账户费率 | 查询所选合约的保证金率与手续费率 | 与柜台费率一致；柜台缺失项明确展示、不伪造；记录来源与交易日 |
| 未授权拒单 | 就绪但未授权时尝试下单 | 下单按钮禁用；柜台无新增委托 |
| 风控拒单 | 授权后尝试提交超单笔限额或非法价格单位的委托 | 返回明确拒因；柜台无新增委托，资金与冻结未变 |
| 报单与撤单 | 提交一手合法限价单并撤销未成交部分 | Trading 与柜台的方向、开平、价格、手数、状态一致；撤单与成交竞争有明确终态 |
| 成交核对 | 完成一手成交并按交易所开平规则减仓 | 成交不重复，剩余手数准确；资金、持仓、手续费与柜台一致 |
| 连接中断 | 存在在途委托时中断柜台连接并重连 | 授权保持有效，同步完成前禁止发送；绝不自动重发；重连同步后委托与成交一致，不明委托保留为未确认 |
| 进程恢复 | 重启专用仿真账户的 Trading 服务并恢复 | 重新连接并重新授权；已记录命令不重发；相同 `request_id` 不产生第二笔委托 |
| 跨交易日 | 保留仿真环境允许的持仓跨交易日并重新同步 | 授权保持有效；昨日未成交委托列为未确认且不重发；今昨仓、结算与费率与柜台一致 |
| 关闭 Terminal | 关闭桌面窗口后重新打开并连接原服务 | 交易服务独立存活；无重复实例或自动补发交易命令 |

报单、撤单、成交与断线检查必须在柜台可交易时段完成，不得以“无行情/非交易时段”记为通过。遇到未确认委托须先到柜台核实，绝不自动重试。验收完成后点击**停止下单**，核对剩余挂单与持仓，并保留日志目录。

## 自动验收脚本

`tests/acceptance/ctp_trading.py` 启动隔离 Terminal 连接已部署的 Market 与专用 Trading 仿真账户（仅复制指定 Terminal 的 TLS 身份与连接引用，不拉起第二个 Trading 进程，凭据始终留在服务主机）。脚本会发出真实委托，必须显式传入 `--simulation`，并核对账户环境、前置地址、经纪商与投资者身份：

```sh
python3 tests/acceptance/ctp_trading.py --simulation \
  --terminal-directory <Terminal安装目录>/terminal --trading-connection <连接ID> \
  --market-host <Market主机> \
  --market-fingerprint <Market服务证书SHA-256指纹> \
  --trade-front tcp://<仿真交易前置> \
  --broker <经纪商代码> --user <投资者账号> \
  --instrument SHFE:rb2610 --report ctp-trading-report.json
```

- 须在可交易时段执行，依次验证实时行情、账户同步、未授权拒单、挂单与撤单、断线重连及撤销授权（不覆盖策略运行器或现场预热）。
- 必须使用专用仿真账户，运行前确认该合约无既有持仓或挂单，避免与其他客户端并发干扰。
- 脚本结束时不平仓，完整保留服务端记录与验收报告；遇到未知结果须到柜台核实，绝不自动重发。

## 记录

逐项记录 `通过 / 失败 / 未执行`、操作时间、预期与实际结果、脱敏截图或日志位置，同时标注尚未覆盖的柜台行为。任何失败均保留原始现场数据，修复后复测对应步骤。

## 隔离环境恢复回归

进入真实仿真柜台验收前，先在 Linux 已构建工作区执行隔离恢复回归门禁。全部进程测试通过 CTest 隔离包装器运行，使用测试 CTP SDK 与临时账本，不接触真实环境；覆盖三日柜台模型、重连丢失委托、迟到查询回报、服务崩溃与无客户端运行：

```sh
python3 tests/support/recovery_gate.py --build build/Release
```

脚本先从当前构建的 CTest 清单精确校验 6 个必测用例（缺失或重复注册立即失败），随后每项连续执行 3 轮，任一失败或跳过均导致门禁失败。完整日志写入构建目录的 `recovery-repeat.log`，JUnit 结果写入 `recovery-repeat.xml`（JUnit 汇总不能单独替代三轮执行日志）。长周期运行仍须按上表完成真实时段、断线重连与跨交易日对账。
