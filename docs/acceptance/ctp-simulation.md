# 券商仿真验收

本清单用于提供商明确标识为仿真的 CTP 环境，不代表已通过真实柜台验收。测试 SDK 仅验证软件契约，不能证明真实柜台报单、成交或恢复行为。前置地址、账户和交易时间以提供商给出的配置为准。

## 准备

- 使用当前 macOS Terminal 安装包，记录 Git 提交、安装包 SHA-256、macOS 版本、CTP SDK 版本、运行时间和交易日。
- 在本机界面输入仿真账户密码和授权码，不写进报告、截图、终端命令或源码。报告中的账户、前置地址和委托编号脱敏。
- 创建一个命名的专用测试账户，系统自动管理记录目录；保留全部原有账户。选定可交易的实际月份合约；核对最小变动价位、乘数、价格限制和一手风险限额。
- 从 **交易 → CTP 交易** 添加账户，可直接查询合约目录。连接前手动选择 **CTP 仿真** 并核对账号及前置地址；系统无法自动验证资金性质。
- 可先运行 `python3 tests/acceptance/ctp_market.py --help`，按参数连接只读行情；该工具使用隔离节点，密码在本机交互输入，不报单。工具成功不能代替下列交易验收。
- 交易与策略的自动验收见下文“自动验收脚本”。它会向你指定的柜台发送真实委托，只能用于仿真环境。

## 首次配置

先使用本机默认部署完成 CTP 连接，再单独验证远程 Linux；连接柜台不要求先安装远程节点。

1. 从仿真服务提供商取得同一环境的行情前置、交易前置、经纪商代码、投资者账号、AppID、密码和授权码。地址和可交易时段以提供商为准。
2. 在 **设置 → CTP 账户** 新建账户，填写经纪商代码、投资者账号、AppID、仿真交易前置和行情前置，并确认它标为“用于行情”。然后在 **交易** 页左侧选中该账户，完成“开通交易”。默认自动管理记录目录，需要指定目录时展开高级选项。
3. 点击 **下一步**，从合约目录添加待验收的月份合约；目录未加载时可在当前步骤输入密码和授权码，点击 **获取合约列表**。查询只读，不授权交易；凭据仅用于本次请求。
4. 填写单笔数量、总持仓、在途委托上限及价格偏离比例。仿真单合约验收可先将三个数量上限设为 `1`；偏离比例按该环境的验收需要设定，例如 `0.02` 表示 `2%`。
5. 点击 **下一步** 核对摘要，再点击 **创建 CTP 账户**。在账户页选择 **CTP 仿真**，勾选 **我已核对账户与柜台环境**，输入密码和授权码连接。
6. 等待 **已就绪**，核对资金、持仓，并展开 **账户费率与模板** 查询费率。此时保持未授权；核对完成后，确认发送账户并点击 **允许发送委托**，再按下表逐项验收。

环境标签代表用户确认，不能代替提供商核实。已开通交易的账户随 Terminal 启动而启动交易服务，日常在交易页左侧选中账户后输入密码登录；**断开账户** 会退出柜台连接，不会自动撤单。服务失联时用 **重新连接交易服务** 恢复。远程节点配置步骤见 [服务与部署](../services.md#远程-linux)。

只读行情脚本仅在全部合约收到行情、正常断开且隔离进程完成清理后报告通过。脚本报告含前置地址和经纪商代码，分享前须脱敏；不包含密码。

## 顺序与通过条件

| 检查 | 操作 | 通过条件与证据 |
| --- | --- | --- |
| 连接同步 | 连接仿真柜台，等待认证、登录、结算确认和账户同步 | 到达“已就绪”；资金、持仓与柜台客户端一致；记录耗时与错误码 |
| 账户费率 | 查询选定合约的保证金与手续费 | 与柜台费率一致；缺失返回明确显示，不补造；保存来源和交易日 |
| 未授权拒单 | 就绪但未授权时尝试提交 | 提交入口禁用；柜台无新增委托 |
| 风控拒单 | 授权后，测试超单笔限额或非法价格单位 | 返回明确拒绝；柜台无新增委托；资金和冻结未变 |
| 报单与撤单 | 在仿真柜台提交一手合法限价单并撤销未成交部分 | 本机与柜台的方向、开平、价格、手数、状态相符；撤单或已成交竞争有明确终态 |
| 成交核对 | 在仿真环境完成一手成交，按交易所开平要求减仓 | 成交不重复，委托剩余量正确；资金、持仓、手续费与柜台一致 |
| 连接中断 | 存在在途委托时中断测试连接并重连 | 授权保留，同步完成前不能发送；不会自动重发；重新同步后委托、成交相符；不明确的委托保留为未确认 |
| 进程恢复 | 使用专用会话目录重启交易服务并恢复 | 重新连接、重新授权；已记录命令不重发；相同命令编号不产生第二笔订单 |
| 跨交易日 | 保留仿真环境允许的持仓跨交易日并重新同步 | 授权保留；昨日未成交的委托列为未确认，不重发；今昨仓、结算、费率与柜台一致 |
| 策略运行 | 授权后启动均线策略，观察若干根 1 分钟线 | 手动报单被拒；K 线按分钟增加，满慢线周期后出现目标；策略委托的限价等于对应 K 线收盘价；未成交时先撤后挂 |
| 策略做空与反手 | 持仓方向选“多空”启动，观察到快线低于慢线、再高于慢线各一次 | 快线低于慢线时目标为负，委托为卖开；随后快线高于慢线的那根 K 线只报买平（上期所、能源中心为平今/平昨），成交后的下一根 K 线才报买开；柜台持仓任何时刻都只有一个方向；保证金、手续费与柜台一致 |
| 策略停止 | 运行中点“停止策略并撤单” | 策略挂单撤销，持仓与授权保留，无未确认委托 |
| 策略延续 | 运行中断开并重连；另留一次运行跨交易日 | 重连后不需授权，策略继续；换日后行情与账户交易日一致时继续下单，记录两者切换的先后 |
| Terminal 关闭 | 关闭窗口，再打开并连接原服务 | Agent 和交易服务独立存活；无重复服务或自动补发交易命令 |

报单、撤单、成交、断线测试需要在柜台可交易时段进行；不能以“当前无行情／不在交易时间”记为通过。遇到未确认委托先到柜台核实，不自动重试。完成后撤销授权，核实剩余委托及持仓，保留日志目录。

## 自动验收脚本

`tests/acceptance/ctp_trading.py` 在隔离节点里用随包的厂商 SDK 依次执行：行情报价、账户同步、未授权拒单、一笔远离市价的限价单挂出并撤销、断开重连后授权保留、启动策略并观察若干分钟（手动报单被拒、分钟线、目标、策略委托价格与 K 线收盘价核对）、停止策略。策略的持仓方向由 `--sides` 指定（`both`、`long`、`short`，默认 `both`）；脚本只核对出现的目标与委托价格，不保证观察期内一定出现做空或反手。三项凭据分别在本机提示输入，不写入磁盘、日志或报告；必须显式加 `--simulation` 表示已核对前置属于仿真环境。

```sh
python3 tests/acceptance/ctp_trading.py --simulation \
  --market-front tcp://<行情前置> --trade-front tcp://<交易前置> \
  --broker <经纪商代码> --user <投资者账号> --app-id <AppID> \
  --instrument SHFE:rb2610 --minutes 8 --report ctp-trading-report.json
```

- 在可交易时段运行。默认快线 1、慢线 2，约三四分钟后出现第一个目标；测试政策为单笔 1 手、总持仓 1 手、在途 1 笔。
- 账户里该合约已有持仓或挂单时，跳过“挂出并撤销”一步并记为未通过，其余步骤照常。
- 结束时该合约的持仓原样保留并打印手数，脚本不平仓。
- 脚本使用自己的临时节点和交易记录，不接触正常安装的账户目录，也不与正常安装的交易服务争用账户归属锁。因此运行脚本时不要让 Terminal 同时登录同一个柜台账户：两边互不知道对方的委托。
- 脚本覆盖不到的仍需人工：真实网络中断、进程恢复、跨交易日、Terminal 关闭。把 `--minutes` 设得足够长可以让一次运行跨过收盘和换日，输出里每根 K 线都带账户交易日。
- 用测试替身空跑只能验证流程（替身行情不走分钟、替身柜台立即成交），不代表通过。

## 记录

每项记录 `通过 / 失败 / 未执行`、操作时间、预期与实际结果、脱敏截图或日志位置。报告同时标记仍未验证的柜台行为；任何失败都保留原始数据，修复后重新运行相应步骤。当前仓库不含账户凭据，也没有真实柜台验收结果。

## 隔离环境恢复回归

真实柜台验收前，先在已构建的 macOS 工作区重复运行以下检查。所有进程测试经 CTest 注册的隔离包装器运行；CTP 使用测试 SDK，临时账本不接触正常 Agent。该测试覆盖三日柜台模型、重连丢失委托、迟到查询回报、服务崩溃与无客户端监督，不代表真实交易时间跨度或真实柜台规则。

```sh
python3 tests/support/recovery_gate.py --build build/Release
```

脚本先从当前构建的 CTest 清单逐项核对八个完整测试名，缺失或重复注册立即失败；随后每项重复三次，任何失败都使命令失败，跳过也不能算通过。覆盖交易日/重连授权、迟到查询、任务固定费率与结果校验、交易服务恢复、Agent 任务恢复及独立健康通道。完整输出保存在构建目录的 `recovery-repeat.log`，JUnit 保存在 `recovery-repeat.xml`；JUnit 汇总不能单独代替三轮执行记录。长时柜台运行还需按上表完成实际时段、重连和跨交易日对账。
