# 固定模型策略包与明确回测交接

## 原问题与依据

固定行情模型模拟已使用普通BACKTEST和同一账户引擎，但既有StrategyDefinition只接受CTA规则。只保存模型任务不能表达下游究竟使用哪份模型定义、原时间计划、映射和数量/方向/处理时钟政策。目标来源为requirements/modules/strategy/README.md的统一对象与正常操作5–6、delivery.md的REQ-STR-DLV-02及FR-STR-DLV-02-01/02，logic.md的FR-STR-LOG-02-04/03-04。模型、规则应交付同一种固定候选，不能另造模型包服务或让分析任务代管账户。

## 最小方案与替代

方案一是在现有StrategyDefinition增加互斥模型内容，复用StrategyPackage、StrategyDelivery、StrategyUse和原固定回测复用请求；方案二另建模型候选库/交付协议。选择方案一，只有实际策略内容可变，所有者、命令回执、弃用、源持有、备份、交付及回测接纳仍由现有Research机制承担。保留当前CTA和规则内容，不引入格式版本、兼容别名或第二账本。

首条以已发布且核验完整的单合约显式单折模型回测为参考。固定包引用原不可变ModelReplayDefinition（原映射/时间计划/成熟训练选择/固定程序/原模型结果身份和attempt/整数手数/方向/处理延迟/预算/可得性假设）、真实合约/周期和原风险程序。完整行情、资金、成本、风险仍归实际回测输入，包不复制结果或接管Data。语义摘要包含全部模型定义；改动映射、数量、折、延迟等不能复用原候选验证结论。正式参考结果及输入保留原样，参考证据不自动成为独立样本外结论。

## 流程与边界

1. 用户读取实际模型模拟结果，命名并固定候选；Research校验原输入/结果/实际模型证据、Owner、程序和依赖。固定不重训、不改映射、不产生交易委托。
2. 复用现有交付命令明确生成回测目标任务草稿，显示原定义/原数据/原资金成本风险及历史可得未知限制；交付本身不运行。
3. 显式接纳现有固定输入复用请求，候选/交付/原参考身份必须匹配，实际输入字节及原风险和计算程序严格相符。原Data按任务发现，既有引用保护与最终接纳重核保持；多源不猜测，无永久配对。
4. BACKTEST执行同一模型时钟/成熟训练投影/预测/次bar风控撮合与账户结果机制。结果记录实际StrategyUse；重启和精确重放不新发任务。同ID不同内容拒绝，弃用禁止新交付/接纳，已接纳和正式证据保留。
5. 原策略包目录、源持有、独立Research冷备与Data联合闭包涵盖固定映射/时间计划/原结果/程序；恢复不依赖原绝对路径，缺依赖或身份错配显式拒绝或报告，不能伪造完整闭包。

本阶段仅交付现有离线BACKTEST能力，不实现交易准备/账户启动，也不把POST_HOC/历史UNKNOWN转换成可交易资格。A02/A03和正式证据删除不在此决定。多折连续账户、多特征、混合分支和独立最终留出另按矩阵推进，不作为本阶段额外框架。
