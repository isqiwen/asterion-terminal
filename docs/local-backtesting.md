# 固定版本本地日线回测

研究页提供单一实际交割合约的日线策略做多/空仓模型，用于可重复、可核对的第一阶段研究。它不连接交易柜台，也不证明策略具备实际可交易性。

## 操作

1. 在数据模块同步或导入标准 `futures.daily` 数据（文件导入前须选择固定身份目录并明确代码映射）；研究页选择数据集和固定版本。
2. 选择策略及其参数、日期、初始资金和手数。预热包含在所选日期区间内；需要超过策略预热条数的数据。
3. 选择已保存的合约规则版本，或用“从 Tushare 创建”读取已同步的固定合约资料并补全规则；也可点击“新建规则”填写合约、来源依据、乘数、最小变动价位和生效期间。各期间分别填写保证金比例、收费方式及开平仓费用。保存后版本不可覆盖，修改使用“复制并修改规则”。滑点跳数仍作为实验参数。详见 [合约规则](contract-rules.md)。
4. 点击“核对所选版本覆盖”。默认严格模式需要该版本、该日期范围的覆盖通过报告。缺失日线或依据不足时，应补齐后选择新版本重新核对；探索模式需要明确填写接受不完整数据的原因，也必须具有可验证的合约身份目录。数据冲突不能绕过。确认历史收盘可用假设后再提交。
5. 在研究页查看运行、每日权益与回撤、成交、持仓和资金事件。任务中心负责运行状态与取消。
6. “按原输入重跑”复制保存的完整输入；“载入参数修改”生成独立实验。可选择另一运行并列查看指标；不同资金、区间或数据版本不能直接当成同条件策略优劣比较。

当前界面分别最多显示 100 个数据集、100 个历史版本及最近 100 次研究运行。单个源版本最多 5000 行，只接受标准日线、真实合约代码及非演示数据；不支持主连、指数或多合约。

## 明确的计算语义

- 策略通过插件贡献；当前提供双均线 `builtin.sma-long` 和收盘动量 `builtin.momentum-long`，均为 `1.0.0`，每次运行固定实际源码摘要。引擎版本 `daily-session-settlement.v6`，统一执行下一开盘做多/空仓。详见 [策略插件契约](strategy-plugins.md)。
- 信号仅使用当日及以前收盘价，在所选版本下一根日线开盘执行。最后一根日线产生的信号没有下一开盘，不执行。
- 买入价 = 开盘价 + 滑点跳数 × 最小变动价位；卖出价反向扣减。滑点可能位于日内价格范围外，这是固定不利滑点的模型边界。
- 现有持仓先按上日结算到本日开盘计价；在开盘变更持仓并扣除滑点及单边费用；新持仓再按开盘到结算价计价。使用 Decimal 固定精度计算。
- 多头保证金为价格 × 乘数 × 手数 × 保证金比例。开仓后资金不足则拒单。前一结算或当前开盘保证金不足时，在本次可执行开盘模拟平仓；不承诺能按真实市场强平规则成交。
- 主权益为逐日结算余额；最大回撤基于初始资金与每日结算权益，不是盘中回撤。期末不强平，不计未来平仓费用，单独显示期末持仓。
- 支持固定规则期间的保证金变化及按成交额计费；不实现平今费率、涨跌停封单、零成交/容量限制、部分成交、移仓换月和经纪商实际强平规则。

## 数据可用性与覆盖

此版本只提供用户显式接受的 `historical-close-unverified-calendar` 模式：假设历史日线在对应收盘之后可用。真实采集时间或版本创建时间仍随输入保留，不能据此把事后采集或修订的数据声明为历史时点已知。严格 point-in-time 回放尚未实现。

引擎按存在的下一根日线执行。提交时绑定覆盖报告完整内容，并核对日线版本、起止日期及报告有数据的日期集合。默认 `coverage_policy=require_complete` 要求报告 `COVERED`；选择 `allow_incomplete` 必须提供非空 `coverage_note`，仍会拒绝错版、错范围和 `CONFLICT` 报告。缺失日线会改变执行日期和均线，探索结果不能等同完整数据研究。

覆盖结论仅相对于报告中的同源日历和合约资料版本，不是交易所权威认证，也不证明历史时点可得性。界面显示缺失、未知、未结束日期及原因，并展示固定日历/合约版本。改变数据版本或日期后，不再使用不匹配的报告。

同步生成的累积日线使用同源、同连接的覆盖依据。本地文件日线须在研究页或数据详情显式选择同交易所的固定日历与合约资料版本，并填写关联说明；不会自动挑选外部来源。报告通过后可以进入严格模式；还必须明确填写参考来源的合约代码；没有身份依据时不能提交研究，包括探索模式。非累积且未关联外部依据的数据不支持覆盖核对。

覆盖报告随参数、标准行、版本清单一起进入输入指纹和任务快照，按原输入重跑保留旧报告，不重新解析最新日历。探索模式也必须绑定含合约身份目录的报告；只允许接受完整性缺口，不能省略身份依据。运行缺少当前固定参数或覆盖字段时明确拒绝执行，不自动补充探索原因。

## 架构与可重复性

`research/engine.py` 是无数据库、无网络、无时钟依赖的纯计算域；`research/service.py` 承担提交冻结与租约发布；`research/routes.py` 提供账户/PIN 保护的研究 API。通过可信内置 `TaskHandler` 注册 `research.backtest`，通用 worker 无需增加业务分支。

提交时验证不可变版本文件校验和，过滤单合约与日期，冻结标准价格行、逐行来源/采集信息、公开版本清单、完整参数、策略/引擎版本及模型边界。固定输入以 canonical JSON SHA-256 标识，保存在任务 payload；新增数据与后续修订不改变已提交任务。

worker 只计算；API 在当前有效租约下用冻结输入复核结果，原子保存 `research_results` 和任务成功状态。过期/取消/被接管的租约不能发布。发布重试必须使用原 token 和完全一致的结果。查询结果复核 checksum。任务列表只返回摘要，完整曲线与成交通过独立研究详情读取。

“按原输入重跑”不重新查询最新数据，也不要求重新读取源文件。但这不是通用数据引用删除保护：任务 payload、结果数据库及备份仍需保留。更改算法必须更新引擎/策略版本；只支持当前执行契约，不保留旧执行器。不受支持的历史运行保留原输入与结果，明确拒绝重跑；不能在同一版本名下改变计算语义。

策略目录通过声明能力注入研究插件，Worker 使用相同装配清单。当前已支持两种策略及独立贡献契约测试，但不是第三方策略安全沙箱；严格可用性模型和外部策略执行隔离尚未实现。


## 在研究页处理缺口

“查看对应数据与报告”定位到原日线版本与确切报告，不自动加载另一份最新报告。“返回研究（保留参数）”保留当前窗口中的实验参数；草稿自动保存与模板支持见下节。

可直接“补齐确认缺口”，复用服务端幂等补齐协议，只提交已确认缺口；未确认日期和冲突不被视作可补缺口。界面显示本次任务状态、分段进度及失败原因。“继续补齐”创建新的续传任务，并保留旧任务在任务中心供检查。网络失败重试使用相同命令 ID，防止重复提交。

研究草稿恢复固定覆盖报告后，界面按报告从数据库读取补齐批次和当前任务状态，不依赖最近 100 项任务列表或浏览器内存。刷新、重开、从数据页返回以及提交响应丢失后，都能找回已经落盘的任务；读取操作不会提交或重试任务。报告关联随已保存草稿恢复，草稿尚未保存时仍可打开原报告查看。

重试保留前序任务关系，研究页展示未被后续尝试替代的任务；原失败记录仍在任务中心可查。重试关系统一使用 retry_of；resume_from 只用于授权证据复用，不作为前序关系的回退字段。历史数据任务与报告属于本机共享数据域，草稿仍按账户隔离，查询仍要求账户和 PIN 解锁。

状态读取失败时保留已显示进度并暂停提交、重试和采用版本，自动重新读取成功后恢复操作。单报告最近最多读取 200 条尝试；超限明确提示并暂停相关操作，不把截断列表当作全部完成。补齐记录为后台事实，不把页面重开当作再次授权采集。

任务结束后点击“检查补齐后的版本”。界面仅展示候选版本，不修改研究输入。点击“采用此版本并重新核对”才读取候选版本，并使用原报告固定的日历、合约资料及原日期范围重新核对；行情与参数在等待中发生变化时拒绝应用过期响应。新报告仍有缺口或冲突时，严格模式继续阻止运行。确认成功后需要重新勾选数据假设，才能提交新回测。既有研究运行完全不变。

补齐完成不等于覆盖已通过：空响应、部分失败、提供方修订等仍可能留下缺口。若已无可补缺口但当前版本较旧，也可显式检查并采用新版本。按原输入重跑始终保留原版本与旧报告。


## 实验模板与研究草稿

研究页进入时读取当前登录账户的本机草稿，恢复策略参数、固定数据版本、日期范围、匹配的覆盖报告及选中的研究运行。恢复会重新读取原版本文件和报告；缺失或不匹配时保留参数并提示，不选择最新版本代替。原版本读取失败时不能提交回测。数据假设勾选状态不持久化，恢复或载入模板后必须重新确认，不自动运行。

输入修改后约 800 毫秒自动保存，页面显示“未保存 / 正在保存 / 已保存”。“立即保存草稿”可主动提交。只有“已保存”确认的修改保证进入数据库；在保存完成前关闭窗口可能丢失最后一段输入。允许保存尚未选择规则或填写完整日期的草稿，保存草稿不等于参数已通过回测校验。

展开“实验模板管理”可命名保存为新模板、载入、更新/重命名所选模板或删除模板。模板包括固定数据版本与参数，不会自动跟随最新数据；载入后成为当前草稿。删除模板不删除数据、运行或当前草稿。模板保存与草稿保存相互独立。

数据库表 `research_documents` 按服务端认证账户隔离；单账户有一个当前草稿和多个命名模板。无账户的开发模式使用独立 `local-development` 所有者。客户端同时携带预期账户，避免跨窗口切换登录期间把旧页面内容写入新账户。账户/PIN 鉴权不因草稿功能放宽。

每次保存携带 `expected_revision`。多窗口修改冲突时暂停自动保存并保留本地输入；可先另存模板，再点击“载入服务器草稿”取回其他窗口版本。网络响应丢失后的相同内容重试幂等。模板删除保留内部墓碑，防止旧窗口重放创建请求使已删除模板重新出现。当前没有模板撤销删除界面。

草稿格式为 schema version 1，不包含凭据、租约 token、同意勾选或可执行代码。补齐任务从草稿固定报告关联的后台记录恢复；未提交的随机命令 ID 不写入草稿，也不会在重开时自动发送。


## 结果导出与复现包

已完成运行可展开“导出结果与复现依据”。结果 ZIP 包含权益/结算回撤、持仓/保证金、成交、事件和指标 CSV，以及 Markdown 回测报告、完整规则快照 rules.json；绑定覆盖报告时另附 coverage.json。CSV 使用 UTF-8 BOM，并转义可能被表格软件当作公式的文本。

复现包是 `asterion.research` schema version 1 的 JSON，最大 8 MB。默认包含固定参数（含完整规则快照及指纹）、引擎/策略版本、数据版本引用、覆盖报告、完整结果及 SHA-256，不包含行情。勾选“附带回测所用行情（OHLC）”后额外包含本次计算使用的交易日、合约、开高低收六个字段；不打包原始供应商响应、凭证、本机路径或整个数据目录。结果和参数本身仍是研究信息，请按需分享。

“导入复现包”只保存到当前认证账户并核验，不自动运行。服务端检查格式、包/行情/结果校验和、价格及日期范围、单合约及预热、覆盖一致性，再用当前支持的内置引擎重新计算并比对结果。界面区分可复现、缺少行情、版本不支持和核验失败。引用包优先使用本机原运行冻结行情，否则要求匹配校验和的固定版本；缺少时需提供附带行情的包。勾选模型假设并点击“启动复现回测”才通过通用任务系统提交，发布阶段再次比对结果指纹。

包内行情只是研究快照，不自动发布为本机数据集；导入运行支持原输入重跑，但不直接载入为可编辑数据版本。数值复现一致不认证数据来源或历史可得性，也不是数字签名。此版本不携带可执行策略、插件、Python 环境或依赖镜像；不支持的引擎版本不会降级执行。默认引用包仍依赖原任务或本机数据的保留，未提供通用引用删除保护。

客户端下载和上传保留原始 JSON 文本，避免 JavaScript 将 `1.0` 改为 `1` 后破坏内容指纹。不要通过会重写数值的工具编辑复现包。


## 本地文件的外部依据关联

“关联外部核对依据”提供已发布标准版本候选，也可粘贴历史版本 ID。日历和合约资料均须属于文件合约对应交易所；服务端验证类型、结构版本、文件校验和与行内容。用户须显式填写参考来源的完整合约代码（如 `RB2610.SHF`），目录按来源命名空间与原始代码精确解析实际合约；不忽略大小写、不剥离后缀、不推断跨来源代码等价。资料中无唯一匹配合约、缺少到期日或日历日期时保留未确认，文件在休市或上市区间外有行情则标记冲突。

关联说明、日历/合约固定 ID、来源、连接 ID 和文件校验和进入不可变报告身份；研究冻结完整报告，后续资料更新不改变旧结果。新导入文件必须选择其新版本并重新核对。这里只声明用户选定依据适用于文件，不认证文件出处，也不自动统一不同来源行情。

文件报告保留逐日缺口，但 `refill_supported=false` 且不给出自动补取区间。界面提示修正文件后重新导入；服务端拒绝自动补齐接口，不会把 Tushare 数据混入文件数据集。关联信息随已生成报告进入研究草稿、模板和复现包；尚未生成报告的关联输入只在当前窗口保留。


## 数据归档与研究引用

数据详情“引用保护与归档”可查看直接引用汇总并归档/恢复版本。归档不改变文件、输入指纹、覆盖报告或原输入重跑；不会释放空间。研究页默认数据目录不列出最新版本已归档的数据集，已固定草稿/模板和历史运行仍可读取原版本。新采集版本默认重新可见。所有版本目前均禁止永久删除；引用展示不等于已实现共享分区垃圾回收或备份恢复。

逐日结算输入、账目公式和报告字段详见 [日线逐日结算](research-settlement.md)。

## 固定实际合约身份（2026-09-20）

研究输入逐根冻结 `contract_id`，报告固定完整身份目录及内容指纹。单次研究必须属于同一个实际合约生命周期，并与交易时间版本的品种一致。摘要、成交、权益和资金事件导出携带实际身份；复现包保留 `coverage.json` 及逐根身份，引用本机行情时也按包内固定目录重新解析。即使外层校验和重算，身份与目录不一致仍拒绝执行。

文件的覆盖依据还须与导入发布时的实际合约身份一致；换一份资料不能重解释原文件。目录或生命周期有误时，应纠正依据并重新导入为新的不可变版本。
