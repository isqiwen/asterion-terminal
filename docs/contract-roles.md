# 合约角色：供应商证据、排名诊断与时点解析

角色版本、可知性与时点解析已由 固定 L2 Rust 领域模块 `role-registry` 实现；Python `asterion.contract_roles` 保留排名、算法制品、来源核验、发布编排与持久化用例，其中排名与计算方法将迁入固定 L2 `role-registry`，来源核验、发布编排及持久化迁入 Rust L3 服务。见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。主力 `main`、次主力 `secondary` 是实际合约的角色，不是可下单代码或连续行情。角色发布与查询不授予交易资格。

## 供应商报告契约

`RoleSpec` schema 1 固定品种、完整候选身份目录、交易时间版本、供应商名称、来源版本/校验和、观测时刻及逐交易日角色记录。该报告契约只接受 `origin=provider_report`，表示从固定标准映射快照生成的供应商报告。预览与保存均通过数据模块公开能力读取并验证来源文件校验和，再按同源合约资料逐行解析规范身份；不能手填校验和冒充已经采集的来源，也不将供应商结果冒充本地算法结果。

每条记录明确交易日、角色、规范实际合约 ID、解释依据及可空的 `available_at`。历史发布时间未知时须为 null，不能从交易日、下载日期或当前时间补造。已声明的可知时刻不得晚于本次观测时刻；这项结构校验不证明声明真实。

记录按交易日和角色排序；同一交易日同一角色只能出现一次，主力与次主力不能选择同一合约。目标必须属于固定目录中的同一品种，交易日在其生命周期内且存在已确认交易时段。映射可以存在缺口，但查询缺口必须失败，不沿用前值。

版本 ID 为整个规范内容的 SHA-256；持久化只追加，同内容幂等。读取校验结构及指纹；备份恢复还从事务内冻结的版本元数据和校验和通过的来源文件重建角色并比较完整内容，不自动迁移或改写已有记录。声明的来源版本与目录资料输入进入数据引用统计。

## 时点查询

`RoleQuery` 必须明确固定版本、角色、带时区的事件时间、信息截止时间、查询模式及说明。先以固定时段确定事件所属交易日，再查该日的精确角色记录，因此周五夜盘可以使用周一交易日映射，节前停夜盘不会被自然日加一规则替代。

- `as_known`：信息截止时间不能晚于事件时间；角色声明的历史可知时间必须存在且不晚于截止时间，合约和品种资料的可知时间也必须满足截止时间。仅按提供证据核验，不认证来源真实性。
- `retrospective`：必须填写明确的回溯说明，截止时间不能早于本次映射观测时间，也不能早于所用合约和品种身份资料的可知时间。允许查看历史可知性未知的声明，不获得当时可知资格。

结果冻结规范合约、所用记录、时段、版本与查询说明，始终为 `execution_authorized=false`。角色解析不代替交易准入、账户或风控检查。

## 下一生效开盘

`NextOpening` 固定品种、时间版本、观测窗口结束时刻和结果可知时刻。结果不得在完整观测结束之前可知。只在已确认时段中选择：严格晚于观测结束，且不早于结果可知时刻的**交易日第一个连续交易时段开盘**。

这不是下一自然日，也不是盘中休息后的重新开盘。若夜盘已开后结果才到达，不回填到夜盘开盘，也不改用同交易日日盘开盘，而选择下一个已确认交易日开盘。节前停夜盘、周末及特殊停盘由交易时间领域模块解释。观测时刻或下一开盘超出固定时间覆盖时明确失败。

该机制同时用于时间诊断、自行排名诊断和经过来源核验的计算角色发布。计算版本额外检查实际发布时间，不将迟到发布回填到过去开盘。

## 已接入接口

全部接口由角色应用模块注册，沿用账户/PIN 保护：

- `GET /api/v1/contract-roles`：分页读取固定版本，默认 50、上限 100。
- `GET /api/v1/contract-roles/{id}`：精确读取。
- `POST /api/v1/contract-roles/source/preview`：提交固定 `mapping_version_id`、`contracts_version_id` 和 `trading_time`，生成待保存角色。
- `POST /api/v1/contract-roles`：提交完整角色，重新读取固定来源并比较后幂等保存。
- `POST /api/v1/contract-roles/resolve`：解析已保存版本。
- `POST /api/v1/contract-roles/next-opening`：下一生效开盘诊断。
- `POST /api/v1/contract-roles/ranking/diagnose`：独立的自行排名诊断，不写入角色版本。

供应商报告公开能力为 `contract_roles.read`，计算版本为 `contract_roles.computed.read`；存储与备份验证等当前仍由待删除的 Python 内置宿主注册；这是迁移现状，不是新增扩展点的依据。静态前端面板提供“数据 → 合约角色”面板，分别查看供应商报告与计算角色，并提供按需展开的首次计算和后续采集入口。发行版按具体端点授予角色 scope 的读取、预览、及时首发及后续采集权限，不授予历史存档或修改数据源、交易时间的权限；角色内容没有放入工作台核心。面板展示候选范围、排除依据、连续确认、生效开盘和来源摘要，未知公布时间明确显示未知。

## Tushare 固定来源接入

2026-09-20 核对 [fut_mapping 官方文档](https://tushare.pro/document/2?doc_id=189)：接口按连续代码和日期返回对应月合约，上限 2000 行，没有历史公布时间字段。Tushare 适配器 1.5.0 的 `mapping` 能力仅接受 `RB.SHF` 这样的主力代码，不把实际合约、其他连续序列或指数当作主力角色，也不猜测次主力。

同步按最多 31 个自然日分段，保留 RAW 请求/返回证据，标准类型为 `futures.role_mapping` schema 1，普通日期范围快照，完整性为 `RETURNED_ROWS_ONLY`。空缺不补齐、不前值填充、不累计成行情。标准行保存品种、角色来源代码、目标来源代码、交易日和可空的历史可知时刻。重复日期、错误品种/交易所、日期越界和触及接口上限均拒绝发布；该数据没有价格字段，不能作为实际合约行情进入研究引擎。

用户可在数据同步选择“主力合约映射”。角色预览使用完整固定映射和同源合约资料，精确关联供应商目标代码，逐交易日检查上市生命周期与时段；支持一个版本中出现多个实际合约，但不通过代码后缀或当前年份猜测身份。不透明代码的独立标准数据源同样走此公开契约。

## 自行排名诊断契约

`RankingRequest` schema 1 与供应商 `RoleSpec` 分离。请求明确品种、固定身份目录和交易时间、完整候选 ID 集、初始主力（null 表示本窗口首次选择）、连续观测交易日、逐合约成交量与持仓量、来源版本/校验和及可知时间。`evidence_scope=unverified_diagnostic` 与非空解释为必填；服务器此诊断入口不读取这些行情来源，不能认证调用者声明。未知可知时间不得补造；Tushare 历史下载不能因此获得历史执行资格。

`RankingPolicy` 所有参数必须明示，没有产品默认公式：

- 指标为 `volume` 或 `open_interest`，单位为 `contracts`；数值有限且非负，最多 24 位有效十进制数字及 12 位小数（换月阈值采用相同精度上限）。输入须已标准化为该单位，诊断不推测单边/双边或来源单位。
- 降序排名；同值按 `earlier_delivery` 或 `later_delivery` 决定月份顺序，同月份最终按规范 ID 字典序。已持有角色时，同值不会触发换月。
- `missing=reject`：每个观测日精确覆盖指定候选集合中当日全部存续合约。候选范围由调用方显式声明，诊断不认证其覆盖整个市场。日期必须在固定时段中连续，不跨缺口累计确认。
- `no_trade=reject|exclude`：成交量为零时拒绝或排除，即使按持仓量排名也执行此政策；最终不足两个有效候选则拒绝。
- 候选必须在观测日和生效日均处于生命周期内。原主力失效或无成交时拒绝，需要显式处理，不能静默强制换月。
- 换月需要挑战者指标**严格大于**原主力指标乘以 `(1 + switch_margin)`；使用精确有理数比较，不依赖进程 Decimal 精度。相同挑战者连续满足 `confirmations` 次才切换；不满足或挑战者改变重新计数。
- `allow_backward=false` 禁止主力回到更早交割月份；次主力独立采用 `best_remaining`，从排名中排除最终主力，不受主力换月确认次数影响。

完整交易日的观测窗口从首个时段（含集合竞价）到最后收盘。日线可知时间不能早于收盘，合约和品种资料的可知时间也纳入最晚信息时点；下一生效时间调用交易时间公开机制。有效范围只覆盖所选交易日，查询时仍须判断具体交易时段；不向后延续填补缺口。多个延迟观测落到同一或倒序生效日时拒绝整次诊断，不能覆盖已有决定。

结果记录算法标识 `daily-role-ranking.v1`、完整请求摘要、逐日排名、每个未入排名候选的排除原因、主力/次主力、挑战者及确认次数、选择原因、观测和生效时间。相同输入可重放；请求摘要不等于来源认证或可离线运行的算法制品。输出始终 `publishable=false`、`execution_authorized=false`。诊断本身不持久化，也不能将结果提交供应商报告发布接口。

该诊断入口继续接受未认证输入；下述发布入口从固定来源重建输入，两者使用同一排名实现。自行计算的真实连续采集换月验收尚未完成，F2 不标记完成，也未实现持仓换月。

## 来源核验后的计算角色发布

`ComputedRequest` schema 1 明确固定合约资料版本、必填候选范围 `candidate_scope`、品种、交易时间、完整算法参数、初始主力、逐交易日所选日线版本及说明。供应商报告和计算记录是不同证据，不共用 `RoleSpec`，也不允许把诊断输出提交为供应商报告。

数据模块的公开 `fixed_daily_evidence` 能力负责当前标准日线语义：读取完整校验和通过的 Parquet 或累积分区，校验单位为手、非演示已发布状态、逐行实际合约身份、唯一日线，以及与固定合约资料重建结果一致。角色计算模块不访问数据模块私有表或供应商实现。当前发布入口要求带 `SourceIdentity` 的同步日线；文件导入身份契约尚未接入，不猜测或补全缺失身份。缺少持仓量明确失败，不填零。

本机可知时间取日线版本创建时间、版本采集/可知时间、逐行采集时间和绑定身份信息时点的保守上界；候选目录资料可知时间继续参与排名时点计算。累积快照含早期记录不代表整个新快照过去已可知。历史补下载可能因时间覆盖不足、合约已失效或多个观测落入同一生效日而被拒绝；不自动改成假定历史发布时间。结果明确 `availability_basis=local_observation`、`historical_publication_attested=false`，不是对交易所发布时间的认证。

`ComputedSpec` 固定来源请求、候选及排除证据 `candidates`、重建排名输入、完整结果与算法制品。制品包含排名、下一开盘、交易时间、身份与规范序列化源码及 Python/Pydantic 版本，并有规范内容 SHA-256。它是可审计的算法源码制品，不是独立操作系统环境；重放要求与当前执行器制品完全一致并精确比较结果，不执行记录携带的代码，不恢复旧执行器。只有数学重放不等于重新认证外部来源；发布和备份校验另行读取固定来源并完整比较。

计算接口（均要求账户/PIN）：

- `GET /api/v1/contract-roles/ranking/algorithm`：当前算法制品。
- `POST /api/v1/contract-roles/computed/preview`：从固定来源重建待发布计算记录。
- `POST /api/v1/contract-roles/computed/start`：单日首次连续发布，重验来源并要求不晚于生效开盘；相同内容重试保留首次发布时间，迟到新结果不落库。
- `POST /api/v1/contract-roles/computed`：重新验证制品、重放与来源后原子保存；同内容幂等，保留首次发布时间。
- `GET /api/v1/contract-roles/computed` 与 `GET /api/v1/contract-roles/computed/{id}`：分页列表与精确读取不可变记录。
- `POST /api/v1/contract-roles/computed/replay`：离线数学重放，不授予来源认证或执行资格。
- `POST /api/v1/contract-roles/computed/resolve`：使用 `RoleQuery` 精确版本与 `as_known` 模式解析本机已发布角色；不接受假定历史回填。

计算记录独立持久化到 `computed_role_versions`，版本 ID 覆盖完整规范内容，服务器另行记录真实 `published_at`；发布时间不能早于输入可知时间。查询既检查输入可知时间，也检查发布时间不晚于信息截止时间，而且该日角色必须在计划开盘前或同时发布。迟到发布不能当日盘中启用，也不能回填过去夜盘。过去计算结果可以存档和读取，但这不授予过去查询资格。集合竞价早于计算生效连续开盘时拒绝；日间休市和缺口仍拒绝。

资料和日线引用进入数据引用统计；备份端口在同一事务冻结元数据，逐文件、逐分区验证校验和和行数，重建计算内容后比对。来源损坏不改写已存记录，读取仍保留原计算事实，重发布和备份来源校验会失败。计算结果始终不授予下单、风控或真实持仓换月资格。

## 候选范围与排除证据

`CandidateScope` 必须明确 `mode` 和 `symbols`：

- `explicit`：至少两个不重复的来源代码，标记 `explicit_subset`。手动选择不证明品种覆盖完整。
- `product_catalog`：`symbols=[]`，由数据模块读取指定版本中该品种的全部实际合约。完整读取、版本身份、当前标准资料契约与校验和必须通过，不能把截断结果当作完整目录。范围标记 `fixed_source_product`，只声明这份固定来源资料，不认证交易所全市场完备。

`POST /api/v1/contract-roles/candidates/preview` 接受固定资料版本、品种、范围以及 `start/end` 观测窗口，不写入数据。计算发布自行按日线窗口重新构造相同证据；保存及备份也重建比较，不相信调用者提交的候选清单。

目录保留全部所选身份；窗口前已到期、窗口后才上市的合约分别记录 `expired_before_window`、`listed_after_window`，其余纳入窗口候选。逐日必须完整提供所有当日存续候选的日线，不能通过漏传行情排除候选。逐日决策另外保存尚未上市、已到期、生效前到期、无成交的原因。规则仍禁止原主力失效时自动强制换月。

计算排名输入中的 `candidates` 固定为所选资料目录的全部规范身份（显式子集只含明确选择的身份），不使用首日存续子集。`CandidateEvidence.included/excluded` 仍描述当前观测窗口的生命周期投影；逐日排名、后续采集计划和同步依赖准入按固定集合及当天生命周期确定所需日线。这样，目录中已知但后续才上市的合约能在上市当日纳入，已到期合约不再采集，前序决定及确认计数无需重置。缺失新上市合约日线仍拒绝，不能退回首日子集。固定目录以外的新身份、目录修订及规则切换仍需另建计算窗口，不静默更新固定输入。

离线验收覆盖连续两日来源重建和分别在各自开盘前发布：第一日等待确认，第二日切换；第二次发布不能回填第一日开盘。此用例验证当前算法及发布边界，不能代替真实跨多日采集和市场换月验收。

## 连续发布与追加观测日

角色应用模块提供两个受账户/PIN 保护的接口：

- `POST /api/v1/contract-roles/computed/continue-preview`：提交 `previous_version_id`、仅一个新交易日的 `daily_inputs` 和说明。服务端读取已发布记录，重验来源及发布时间，保留原始初始主力、规则、资料、候选、日历和历史输入，再追加观测、重算完整窗口。返回 `ComputedSpec`，仍通过已有计算发布接口保存，不增加另一套发布逻辑。
- `POST /api/v1/contract-roles/computed/sequence/verify`：提交按先后顺序排列的 `version_ids`（2–50 个，不能重复）和明确的 `minimum_switches`。逐次重建来源并核验发布时间；必须从单日发布起步，每次仅追加一个连续交易日。报告实际角色切换次数；不足要求直接失败，无换月不能冒充换月验收。

连续确认通过重放原始窗口保持，不通过每日重置 `initial_main` 或复制未认证的计数实现。历史日线即使数据相同，替换其固定版本也会失败；改变策略、身份资料、候选集合、时间版本或算法制品，需要新的独立验收窗口，不能拼入同一链。本切片不实现跨规则变更的运行状态交接。

每个版本仅以其新增观测日的角色决定核验当次开盘前发布；后一个累计版本不能替代前一个版本的历史发布时间。前一版本虽含历史资料，也不能给后续版本补造当时已知资格。来源损坏时验收失败，原记录保留。接口不会调度采集、下单，也不会将离线模拟标成真实多日采集。

迟到采集尤其需要注意：当前真实样本是在周日采集周五日线，其计划生效开盘可能与周一正常采集后的决定相同。该样本可用于单日验收，不能直接充当按时逐日发布链的首日。续算遇到重叠生效日明确失败，不改写原采集或发布时间、不覆盖先前决定。真实连续验收需在覆盖范围内按时采集，从合格首日开始逐日保留固定输入与发布版本。

离线接口集成已验证连续两日等待确认后切换、无切换门槛拒绝、缺日/缺合约、规则与初始状态改变、历史版本替换、迟到重叠、倒序与来源篡改。真实连续多日采集和真实自算换月仍待市场时间上的验收；接口存在不等于已完成该项。

## 采集与持续发布

角色应用模块贡献 `contract_roles.continue` 任务：用户提交、查询和重试受账户/PIN保护；Worker发布使用任务授权与租约。提交冻结来源，发布重验并与任务成功原子登记。

`computed/sync-workflows` 固定前序版本、下一观测日和全部同步任务，经公开 `data.sync_dependencies` 校验；消费事务内发布通知，全部成功后冻结并入队续算。登记与前序版本纳入备份，依赖纳入引用保护。`computed/sync-batches` 将候选同步准入和该登记合为一个事务，经 `data.daily_sync_batch` 批量入队；相同命令复用回执，不同输入冲突，不按供应商接口名分派。

“数据 → 合约角色 → 首次计算”显式选择资料、时间、观测日、候选、固定日线及全部排名参数；预览不落库。开始发布后重试保持原载荷，成功可进入后续采集与续算。连接选择、批量提交和进度恢复已接通，没有定时采集。权限不包含修改数据源/时间规则或历史存档授权。

操作、接口和故障恢复详见[连续发布链](validation/role-publication-sequence.md)。界面模拟与FastAPI离线测试不是按市场时间真实连续采集验收。
