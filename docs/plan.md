# 开发计划

基础设施与核心工程加固已完成，后续聚焦需要真实账户、凭据、签名或部署环境的真实验收，以及按独立项推进的新功能（Feature）与日常维护。产品目标见[产品说明](product.md)，交易要求见[交易规则](safety.md)。

## 设计约定

- 研究读取 Warehouse 合成的固定研究数据集，分区来源规则见 [Warehouse](warehouse/README.md#仓库与固定版本)；极少变动的交易所合约规格（如历史最小变动价位、历史计费单位切换日）维护为内置经核验数据表，公开接口仅作增量核验。
- 分钟 K 线按品种交易时段与时钟边界聚合；回测与实盘均排除断线或缺失导致的不完整分钟线。
- 每个 CTP 账户只运行一个策略实例；多策略组合在 Python 研究层合成为单一组合权重策略运行，或按独立 `asterion-trading@<账户>` 进程物理隔离，不在 C++ 单账户内拆分子账本或与手动新增委托混跑。
- 执行路径冻结后依次进入真实数据回测、SimNow 单策略与组合仿真浸泡及小资金实盘验收。
- 实例重启只重放 Trading 本地记录的行情或随实例显式固定版本并校验摘要的预热历史，账户授权遵守[交易规则](safety.md)。

## 新功能（Feature）与日常迭代

新功能与日常维护独立推进，互不阻塞真实验收：

- **新功能（Feature）**：按独立功能项规划、实现与验收，完成即从计划文档移除，设计决策沉淀到对应主题文档；涉及多步实施的较大功能在执行顺序表中登记。
- **提交前缀约定**：`feat:`（新功能）、`ui:`（界面与交互调整）、`fix:`（缺陷修复）、`ops:`（安装/运维脚本与开发工具）、`refactor:`（无行为变化的结构整理）、`docs:`（文档更新）。
- **安全边界**：所有改动同样遵守[交易规则](safety.md)；涉及下单、撤单、风控限额或账户并发执行路径的改动须明确范围并跑完回归测试。

## 真实验收

### 研究数据权限、覆盖与报告口径（使用者）

- 验证新版 Warehouse 在每日定时时点触发的更新全批完成。
- 核实来源返回空的历史边界：DCE/CZCE 的 2002 年会员持仓、INE/GFEX 上市初期的会员持仓、SHFE 的 2014 年库存周报；确认 CFFEX 2010～2014 年日历未返回日期的开闭市口径。入口见[真实研究数据验收](acceptance/research-data.md#仓单会员持仓与库存)。
- 在 research 部署仓单历史日期解析与葵油 `CZCE/so` 最小变动价位规则，重启 Warehouse 后重采 2014 年仓单并验证葵油的完整覆盖。

### 数据仓库与多年真实回测验收（使用者）

- Mac 解锁后，在 Terminal 核对最新六所日线、一年分钟线回测的结果页，以及更新后的数据覆盖与浏览视图。
- 核实[待定问题](#待定问题)中的分钟成交量、空 OHLC、黄金涨跌停价和合约日期差异，明确受影响数据的研究使用范围。

### 单策略柜台单日联调与两周 SimNow 仿真浸泡（使用者）

- 在 Linux 主机独立运行部署后的 `Market`（切换为实时行情前置）与 `Trading`（SimNow 账户），复核全部文档与实现一致，完成 [CTP 仿真验收](acceptance/ctp-simulation.md) 单日清单及 `ctp_trading.py` 自动验收：连接超时与 CTP 7／8 恢复、夜盘日期归一、持仓明细、分页委托／成交导出，以及从冻结回测发布并预热启动。
- 用固定月份合约策略在 SimNow 连续运行两周，期间完成五项演练：关闭 `Terminal`（核验主机 Webhook 脱机告警）；停止 `Market` 和 `Lab`（实例继续运行）；行情断线重连；`Trading` 重启后热重启并重新授权；柜台断线恢复。
- 每天收盘后导出快照与柜台结算单核对成交、持仓、资金及每个合约的撤单数，并用 Lab 对账工具核验 `Trading` 录制的实时 K 线与 `Warehouse` 统一数据一致。

### 多品种主力组合仿真浸泡、穿透式监管认证与桌面签名公证（使用者）

- 多品种主力连续截面组合在 SimNow 按日／盘中调仓连续运行两周（覆盖跨时段开盘调仓与换月），每天收盘与柜台对账一致。
- 通过期货公司实盘柜台的穿透式监管认证，取得正式 `AppID` 与授权码；从上期技术/期货公司下载官方测评版与生产版 CTP SDK，经 `scripts/prepare_ctp.py --local-dir ... --record-origin ...` 替换 `conan/ctp/sources.json` 的镜像条目并以 `ASTERION_CTP_REQUIRE_OFFICIAL=1` 重新打包；完成 macOS 桌面安装包的签名与公证（可与组合浸泡并行）。

### 一个月小资金实盘验收（使用者）

真实资金账户首次下单前确认以下记录齐全：

- 单策略与多品种组合两周仿真浸泡每天对账一致，并按浸泡数据在风控设置中设定资金与撤单硬风控阈值；
- 穿透式认证与桌面签名公证通过；
- 实机演练“停止策略并撤单”、跨主机冷备接管及脱机 Webhook 告警通过。

随后以小资金连续实盘运行一个月，每天与期货公司结算单对账，无未解释差异。

## 外部事项（使用者）

- Market：当前行情前置回放旧交易日行情，单策略仿真浸泡前切换为实时行情前置；需调整账户、前置地址或来源凭据时由使用者在主机操作。
- Trading：准备 SimNow 账户与后续期货公司实盘账户，确认前置维护时间窗，配置脱机告警 Webhook 凭据。
- 桌面：Apple 开发者证书与公证凭据配置（桌面签名公证前）。

## 待定问题

- 策略上下文保留全部历史：Linux 容量夹具中，64 个品种各 131,072 根 K 线后的扩容触及 Trading 的地址空间上限。需确定显式历史保留长度与完整前缀因子的支持方式，再实施有界存储；复测入口见[历史容量夹具](acceptance/research-data.md#历史容量夹具)。
- 组合策略目前只记录合成后的目标，需确定子策略就绪状态、原始权重与合成贡献的展示范围。
- `LivePanel.test.tsx` 的“a split close keeps only remaining lots…”在 2026-11-21 偶发失败一次，随后完整单元测试连续 8 次、该文件单独 10 次通过；需在复现时定位时序原因。
- UI 全量单测在默认并行下出现超时及随后 DOM 查询失败，限定 2 个 worker 后通过；需定位并行运行的时序问题。
- macOS 按品种、按合约及分批发布的三个长区间采集用例在全量并行时超过 40 秒等待上限，串行复测通过；需定位并行采集耗时。
- macOS 的 `cross_session_portfolio_process` 在分钟和日线组合场景存在偶发的持仓等待超时，需定位跨时段调仓的时序原因。
- `SHFE/rb/2027-01` 的新浪分钟量在 2026-11-16 多出 4,161 手；合并集合竞价后，11 月 19、20 日仍分别比 Tushare 少 12,099、183,085 手。需确定公开补缺源的质量门槛与异常分区处理方式。
- Tushare 分钟量在 `SHFE/rb/2026-01` 的 2025-12-25、`SHFE/rb/2026-02` 的 2026-01-26、`SHFE/rb/2026-07` 的 2026-06-24 分别比交易所日线少 14,821、774、22,496 手，重采后不变；2026-02-02 的 11 个螺纹钢分钟分区在各来源仍返回空，需核实来源缺失与成交量口径。
- 2023～2026 年六所日线中有 1,318 条有成交量但 OHLC 全空的记录，其中 344 条在最后交易日；另有 69 条黄金涨跌停价未对齐 0.02 元价位，抽样重采后不变。需核实原始来源，确定可用范围。
- `CZCE/so/2027-05` 的 Tushare 最后交易日为 2027-05-19，郑商所合约参考文件为 2027-05-14；需核实合约日期来源。
- 自动更新将各所缺口起点合并为最早日期，INE、DCE、CZCE、GFEX 的日线因而回补到原有区间之前；需明确是否按各所已采集起点限制回补范围。
- 策略未来若需用到 Tick 或五档盘口时，购买历史数据还是开始录制。
- 行情页主连的 1 分钟图在回放行情下价格上下剧烈跳动：待切换实时行情前置后确认是否为旧回放源在同一 `TradingDay` 内混播多日行情所致。
