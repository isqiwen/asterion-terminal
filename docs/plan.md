# 开发计划

本计划列出开发顺序、当前状态和各阶段的验收条件。产品目标见[产品说明](product.md)，交易要求见[交易规则](safety.md)。标记“使用者”的事项需要真实账户、凭据、签名或部署环境。

## 设计约定

- 研究读取 Market 合成的固定研究数据集，分区来源规则见 [Market](market/README.md#仓库与固定版本)。
- 分钟 K 线按时钟边界聚合；支持周期见[通信协议](protocol.md#4-公共类型)。
- 仿真浸泡先使用固定月份合约，自动换月在多品种组合阶段之前完成。
- 实例重启只重放该实例自己的行情记录，账户授权遵守[交易规则](safety.md)。

## 第 3 阶段：仿真运行验收

### M3.4 客户端收敛

页面已使用生成的 Protobuf 类型，原生层通过 `trading.call`、`market.call` 和 `market.watch` 管理连接并转发消息。隔离桌面验收和模拟全市场性能检查已完成。

剩余验收：连接真实 Market，在开发桌面打开全市场行情，记录消息大小、界面处理耗时和交互响应，确认持续更新时界面流畅。

### M3.6 两周仿真浸泡（使用者）

- 在 SimNow 用固定月份合约的策略连续运行两周，每天收盘后核对成交、持仓和资金。
- 期间演练：关闭 Terminal；停止 Market 和 Lab；行情断线（实例应继续运行）；Trading 重启后热重启并重新授权；柜台断线。
- 每天记录对账结果，以及每处不一致和原因。

第 3 阶段完成条件：浸泡期间每天对账一致；上面的演练都按预期运行。

## 第 4 阶段：多品种组合

### M4.0b 实盘换月

目标：实盘实例可以交易主力连续（例如 `SHFE/rb`），合约到期前自动移仓；策略看到的连续历史与研究一致（M4.0a 的复权）。

- 换月判断与研究相同：前一交易日持仓量最大的合约，只向后换。实盘从 Trading 自己的行情读取持仓量。换月日先平旧合约、再开新合约，都走同一条执行路径。
- 下一个月份必须在账户白名单内；不在时，换月前结束实例并提示。

完成标准：实盘隔离测试跨过一次换月后，持仓在新合约上，策略历史连续。

### M4.1–M4.4 多因子组合

| 编号 | 内容 |
| --- | --- |
| M4.1 截面研究 | 多品种日线面板、因子合成、样本外检验 |
| M4.2 组合构建 | 在权益、价格、乘数和保证金约束下配置权重，确定调仓阈值和时点 |
| M4.3 一个账户多个策略 | 账户层合并目标，确定成交和费用的归属，以及与手动委托共存的规则 |
| M4.4 组合仿真 | 多品种组合在 SimNow 按日调仓两周，每天对账一致 |

M4.2 之前评估多合约执行耗时：当前按分支依次发送并等待持仓查询，需要确定互不影响的分支能否并行执行。

## 第 5 阶段：小资金实盘（M5）

真实资金账户第一次下单前，以下各项都要完成并留下记录：
- 仿真浸泡（M3.6、M4.4）每天对账一致。
- 通过期货公司的穿透式认证，取得 AppID 和授权码。
- 同一个资金账户，无论有几份配置、在几台主机上，都只有一个执行者。
- 日内亏损和回撤限额：正确处理出入金、换日、重启和重新授权。
- 告警覆盖实例结束、委托被拒、未确认委托、连接中断、风控触发和对账不一致；“停止全部策略并撤单”演练通过。

然后用小资金连续运行一个月，每天对账，没有解释不了的差异。

## 外部事项（使用者）

- Market：在主机配置 Tushare token；处理大商所、郑商所部分归档返回的 HTTP 412；正式部署（systemd、加密凭据、开机启动），录满一个完整的日盘和夜盘，记录数据量和合并耗时。
- Trading：正式部署；准备 SimNow 账户；确认 SimNow 和期货公司柜台前置的维护时间，供 M3.6 验收安排参考。
- 桌面：macOS 签名和公证。

## 待定问题

- 风控是否增加资金/保证金占用、日内亏损和撤单次数限制（M5 之前决定）。
- 跨主机唯一执行者的外部隔离措施及人工换机验收（M5 之前完成）。
- Tushare 分钟线是否把集合竞价和收盘 tick 并入相邻 K 线，与实盘和录制的分钟 K 线是否一致（M4.0b 之前核实）。
- 回测排除不完整分钟，Trading 仍交付跨越行情中断的 K 线；需明确统一规则，并验证断线前后策略输入（M4.0b 之前决定）。
- 端到端场景 `research-lab` 偶尔在全量运行时找不到两次运行的对比列，单独运行稳定通过（M3.6 之前查明）。
