# 合约规则与固定输入研究

## 归属与契约

规范市场规则已由独立 L2 Rust 插件 `market-rules` 实现，负责固定规则、有效期、费用计算和结算证据换算；Python `asterion.contract_rules` 保留来源核验、HTTP 与持久化用例。当前仍是有限研究模型，完整账户执行约束尚待 `execution` 实现，领域能力不得反向导入来源应用。见[模块与层级](architecture.md#层级与模块)和[当前代码归属](engineering-structure.md#当前代码归属)。当前插件提供账户/PIN保护的 `GET/POST /api/v1/contract-rules` 和 `contract_rules.read`，研究通过声明能力读取；缺少必需能力拒绝运行。

规则为环境内共享的研究数据，不是账户私有经纪商配置。凭据不得填写在来源说明中。所有已解锁账户可查看或添加规则；没有修改、删除、默认替换或自动选取最新版本的接口。

`RuleSpec.contract` 保存完整实际合约身份对象（规范 ID、品种、完整交割月、上市和最后交易日、最后交割日及来源证据），并包含名称、规则来源依据、合约乘数、最小变动价位和最多 100 个生效期间。规范 ID 的形式为 `SHFE.RB.202405.20230516`，规则与行情按该身份匹配；同名行情代码不能跨上市生命周期共用规则。交易时间版本的品种必须与合约身份一致，研究请求不得超出合约生命周期。乘数和价位在整个版本固定；不同取值需创建独立研究规则，当前不模拟持仓跨乘数调整。

每个期间包含首尾日期（均含）、保证金比例、收费方式及开平仓费用。期间必须按时间升序、连续且不重叠。新回测要求规则覆盖整个请求区间，并属于行情唯一的实际合约。没有适用规则时拒绝运行，包括探索模式。

- `per_lot`：费用为成交手数 × 开仓或平仓每手费用（元）。
- `notional`：费用为成交手数 × 模拟成交价 × 乘数 × 开仓或平仓费率（0—1 比例）。
- 保证金为估值价格 × 持仓手数 × 当日保证金比例 × 乘数。

费用以 Decimal 在引擎固定精度下计算，不额外模拟经纪商分币舍入。这里是可解释的研究模型，不是结算账单。

## 不可变与复现

规则版本为 `{id, spec}`；`id` 是规范 JSON 内容的 SHA-256。独立表 `contract_rule_versions` 仅追加，重复保存同一内容幂等；复制修改产生另一指纹。读取、提交、恢复及复现时验证内容指纹。

新运行提交完整选中规则，服务端核对已保存版本并冻结到研究请求。草稿、模板、任务输入指纹均包含该快照；未选规则可保存草稿，但不能提交回测。规则编辑过程中的未保存字段不属于研究草稿。

原输入重跑直接使用冻结规则，不重新查询目录。复现包自带规则快照，另一环境不需要事先登记该规则；包内声明不被自动加入共享目录，也不证明来源真实。当前固定输入契约不完整时明确拒绝，不补默认值、不执行旧模型、不改写已有记录。

引擎身份为 `daily-session-settlement.v6`。成交记录包含规则版本、适用期间开始日期、收费方式及实际费率；每日曲线记录保证金比例。界面展示规则依据和生效期间；导出 ZIP 包含 `rules.json`，成交 CSV 包含上述计费证据。

规则插件通过只读备份证据验证每条存储的内容指纹。研究备份继续校验输入和复算结果；规则与数据在同一个环境备份中保留。

## 当前产品边界

入口在研究页的“合约规则”。用户从已发布目录选择实际合约并手动填写规则参数，或从数据源固定资料创建；无随产品交付的示例合约参数；自动测试使用明确离线构造规则。真实数据源仍管理行情、日历与合约资料版本，规则通过规范合约身份和研究冻结输入与它们关联，现已支持从固定 Tushare 合约资料生成待补全的规则草稿，详见下节。

仍为单合约日线做多/空仓、下一根日线开盘撮合、按结算价逐日结算并单列收盘估值。日线模型没有同日开平仓，因此仅区分开仓和平隔夜仓；已有固定品种时段、夜盘归属和显式节假日例外校验；没有平今费率、涨跌停成交约束、交易所强平、组合保证金、换月和实盘柜台。日线仍保留来源交易日，研究以固定时间版本核对；日内导入按带时区时间戳校验交易日归属。详见 [交易时间](trading-time.md)。不得以当前结果声称已完成正式交易模型。

## 标准合约资料映射

使用步骤：设置 → 数据源配置 Tushare 连接；数据 → 数据同步选择“期货合约资料”及交易所并等待完成；研究 → 合约规则 → “从合约资料创建”，选择固定资料版本（也可填写历史 ID），填写目录中的规范合约 ID，读取预览后点击“采用资料并补全规则”。已有选中规则时可带入其规范 ID；行情展示代码不用于猜测身份。不会默认选择最新资料，也不会在预览时联网同步。

资料读取使用数据插件的公开 `data.versions` 能力，由数据插件验证文件校验和。接受任意来源符合当前契约的非演示 STANDARD `futures.contracts` schema 4，完整读取且唯一匹配实际合约；最多 10000 行。资料保留 `multiplier` 与 `quote_unit_desc`；不符合当前结构的资料应重新同步，不补造字段或迁移原版本。

Tushare 数据源侧转换规则依据 [Tushare fut_basic 官方字段](https://tushare.pro/document/2?doc_id=135)，2026-09-20 核对：

- 合约名称用于规则草稿；合约身份由标准资料中的交易所、品种、完整交割月和上市日期生成，缺失或歧义拒绝映射。供应商代码只作为来源证据保留。
- 商品报价单位明确为 `元/` 或 `人民币元/` 加交易计量单位时，以正数 `per_unit` 建议每手研究乘数；其他单位关系留空。
- CFFEX 的 IF/IH/IC/IM 合约使用正数 `multiplier` 提供建议。国债报价存在不同计价基础，本映射不从每手数量或乘数猜测换算。
- `quote_unit_desc` 作为原始说明显示，不把自由文本猜测为最小价位；用户核实后填写数值。
- 上市与最后交易日限制实际合约生命周期，不自动生成规则生效区间。最小价位、费用、保证金及生效期间仍须填写；预览不产生可执行规则。

规则 `basis` 是必填的可空字段。手工规则明确为 null；映射规则保存固定资料版本 ID、校验和、源连接 ID（提供方直接配置可能为 null）、规范 `contract_id` 和相关原始字段。资料中的上市/最后交易日必须与合约身份一致；保存时重新核验完整合约对象与该快照，防止客户端修改来源证据。用户可调整建议乘数并补充实际依据，最终数值和原资料分开保留，不能以映射成功声称已核验交易所完整规则。

`basis` 随规则指纹进入草稿、任务、结果和复现包；来源后续更新不改变已有规则，重跑与附带行情的复现不重新读取供应商。数据引用统计包含规则、研究运行、草稿/模板和包对资料版本的引用；归档不会删除资料。包内来源声明仍未经独立认证。

## 每日结算参数与明确研究假设

数据同步的“每日结算参数”，调用 [Tushare fut_settle](https://tushare.pro/document/2?doc_id=141)。2026-09-20 核对官方文档：单次上限 1600 行；按实际合约、最长 31 个自然日分段，触及上限拒绝发布。标准类型 `futures.settlement` schema 1 为日期范围快照，不拼接为日线或自动累计。保留交易日、全部声明的费用/保证金原值、源连接、配置快照、采集时间与 RAW 版本；缺失值保留 null，完整性仅为已返回行。重复键、错合约、越界日期、非法数值不能发布。

官方[数据更新时间说明](https://tushare.pro/document/1?doc_id=108)注明盘后更新。接口没有历史公布时刻，费用字段描述也不足以直接确定比例换算。`observed_at` 是本机采集时刻，绝不当成历史生效时刻。

研究规则编辑器每个期间可展开“从结算参数填写此期间”，选择固定版本与参数交易日，查看原值。用户必须明确选择 `trading_fee` 的元/手，或 `trading_fee_rate` 的比例、百分数、千分数、万分数；买投机保证金须明确比例或百分数。系统不根据数值大小猜单位，不默认选字段或单位。

采用前须填写生效首尾日期、解释依据，并明确确认：所选普通费用同时适用于多头开仓和非平今平仓，期间内数值不变。当前只支持单一收费方式，不能组合按手与按金额收费。不能确认这些适用性时，应保留快照、另行查证或依据已知规则手动填写；不能把此映射当作经纪商账单。

开始日期必须严格晚于来源交易日；拒绝把盘后参数用于当日或更早开盘。这个限制仅防止显然的同日信息前视，**不证明历史时点可获知性**：后续修订、延迟发布等仍未知，必须保存 `availability_assumption=after_source_day` 和解释依据。系统不会自动生成下一交易日或自动延长有效期间。

期间包含必填可空 `settlement_basis`：手工期间为 null；映射期间冻结来源版本/校验和/连接/采集时间/原始行以及所选单位和适用假设。预览与确认使用 `data.versions` 校验文件；保存再次核对来源，期间本身验证换算结果和时间关系。已采用参数在编辑器中锁定，调整需重新确认，或显式解除依据后按手工规则编辑。

API：`POST /contract-rules/settlement/preview` 读取固定行；`POST /contract-rules/settlement/confirm` 返回完整已确认期间；只有保存整个规则才追加不可变版本。两个接口沿用规则插件身份与权限保护。核心无新增业务分支。

结算依据进入规则指纹、研究输入、草稿/模板、结果 ZIP 和复现包；版本引用统计覆盖规则与研究记录。离线复现直接读取冻结值，不访问 Tushare，也不要求源版本仍在目录中；包内来源声明不等于经外部认证。此规则映射中的结算价、交割费用、套保/卖空保证金和平今费率只保留为资料；研究逐日结算使用固定日线版本的 `settle`，详见 [逐日结算](research-settlement.md)。

## 来源无关的规则依据

合约和结算依据中的 provider 是非空来源标识，不限定 Tushare。规则插件通过已声明的 `data.versions` 能力读取经校验和验证的固定版本；保存时重读核对，不接受客户端伪造来源和原值。`POST /contract-rules/source/preview` 读取标准合约资料。界面列出所有符合数据类型的标准版本，来源名来自证据。

`futures.contracts` schema 4 必须包含 `contract`（当前标准行情代码）、`suggested_multiplier`（每点每手金额的正数文本或 null）、`multiplier_note`（解释依据），以及品种、币种、完整交割年月（可明确缺失）、最后交割日（可明确缺失）等合约资料字段。目录身份不持有乘数和最小价位的另一套副本。外部 symbol 原样保留，不要求 Tushare 后缀。各数据源在 normalize 中解释其单位并生成这些字段；规则只展示建议，最终参数仍需用户确认。无法可靠解释时建议为 null，并说明缺失，不默认填 1。

结算预览请求使用 `contract_id` 与 `trading_day`，按数据版本冻结的 `SourceIdentity` 解析实际合约，核对来源、交易所、全部行身份及生命周期，再读取唯一交易日。`SettlementEvidence.contract` 冻结完整身份；原始行保留来源 symbol 与行情展示代码，不以代码相同作为身份相同。标准结算字段和单位确认约束对所有提供方相同；能返回相同名字但语义不同的字段，不等于符合此契约。来源不受品牌白名单限制，不代表免除完整性、来源版本及单位校验。

规则、来源映射、结算证据、研究提交与 Worker、离线复现、导出和备份均使用当前规范身份契约。界面新建规则从已发布目录选择实际合约；来源映射锁定合约对象。当前执行器为 v6，不保留替代协议或旧执行器。
