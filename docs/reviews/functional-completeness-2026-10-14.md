评估日期：2026-10-14。基线：主 checkout 的 `main`，HEAD `bacf29d`，以及阅读时已有的未提交改动。初始评估时，工作树正在删除按合约日线下载及对应 ABI、协议、存储和测试，未完成整组验收；初始评估只做功能核对与文档记录。随后用户授权继续实施，F01 的实现与当前验证进度记录在[整改进度](audit-progress.md)。没有运行真实账户或请求供应商数据。

**判断：项目已具备日线为主的期货研究主链路，可以取数、分析因子、比较参数并做组合回测；距离持续高效的研究工作台，主要还差数据质量、历史成本、实验复用和结果解释。实盘具备基础手动交易与单合约策略执行，但研究侧的组合能力尚未完整接入实盘，真实柜台和长期运行证据也不足。**

不按文件数、页面数或测试数给出“完成百分比”：项目没有冻结的完整产品需求清单，研究、人工交易和无人值守交易的完成标准不同。下面区分当前能力、待实现功能、当前改造收尾、验收工作与条件性扩展。

## 评估依据与排序原则

对照了[架构设计](architecture-design-review.md)、[实施记录](architecture-implementation.md)、[整改进度](audit-progress.md)、[现状](../status.md)及行情、数据、任务、因子、回测、策略、交易、插件、服务和 Terminal 文档，并核对对应 Native 命令、UI 入口、Protobuf 定义与服务实现。负向判断限于现行公开入口和已检查的实现，不表示逐行证明整个仓库不存在其他问题。

按整改进度中 **2026-10-10“研究优先”** 的已记录决定排序：先让本地因子和策略研究可靠、可重复，再扩展自动化交易与正式交付。`docs/status.md` 中“真实验收排在新功能之前”的概括与该决定不一致；本报告把真实交易和发行验收作为对应使用阶段的门槛，不阻塞纯本地研究。

| 优先级 | 含义 |
| --- | --- |
| P0 | 完成正在进行的功能收敛，建立可验证的当前基线；此处不是漏洞严重性评级 |
| P1 | 直接改善当前研究结论的可信度或频繁研究操作，应作为下一批核心功能 |
| P2 | 主链路可信后，提高研究能力、容量、日常效率或运维便利性 |
| P3 | 只有出现明确策略、供应商或部署需求才立项 |
| 使用前门槛 | 真实交易、无人值守运行或正式发行前必须完成；不等于当前研究迭代的最高优先级 |

2026-10-13 评估的 R1–R7 已有后续修复与整改记录，本轮代码核对也可见撤权入口、预热目标合并、行情重启停止、均线计算、图表来源绑定、节点身份更换和任务执行资源保留等实现。它们不再作为尚未实现的功能重复列入清单。后续改动仍需使用自己的源码基线验证。

## 撮合真实性的条件性优先事项

### F15 涨跌停和无法成交状态

当前撮合已有下一根 K 线、限价约束、成交量比例、滑点与真实月份换月，但没有回测涨跌停成交限制。因此“某日有成交量且价格触及限价”不足以证明策略在封板方向能成交。

这是影响结论的真实缺口，但现状明确记录维护者选择：先做真实数据研究，结果出现封板日成交时再实现。本报告保持这一决定：**当前列为 P2 条件项；研究结果依赖这些成交时，提升为该结果采信前的 P1。**

最小实现应固定每合约适用日期的涨跌停参数或有来源的涨跌停价、昨结算与价格步长舍入规则，并明确禁止的成交方向。固定一个全历史比例无法覆盖临时调整，只能作为显式假设；K 线数据也无法还原队列位置，不把保守规则宣传为真实撮合。无需先引入 Tick 回放或全订单簿引擎。

证据：[回测约束](../backtest.md)、[已记录的延期决定](../status.md)、[撮合入口](../../apps/services/task-service/backtest/engine.cpp)。

## 2026-10-15：F05 单实验固定参数与结果证据导出 v1

首版是单个已完成因子/回测的 UTF-8 JSON 文件，格式标识 `asterion.research.evidence`、外层版本 `1`、scope 为 `verified_parameter_summary_and_complete_result`。内容字段为：

- `source`：Task 实例、任务 ID、类型、执行次数、原结果 Protobuf SHA-256、已公开的原输入 SHA-256 及风险实现摘要。回测提供完整原 Input 摘要；因子接口未公开 Input 摘要，明确写为 null，不伪造或用参数摘要替代。
