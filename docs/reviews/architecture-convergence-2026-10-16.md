## 设计与范围

既有 Market/Data/Task/Trading/Agent/worker 分工、Domain → Kernel → Foundation 依赖、
原生实例 RAII、C ABI 和任务摘要绑定符合目标，继续沿用。UI 插件为统一构建的工作区贡献，
数据和风控按实际需求动态交付，内部策略、存储及工具不因目录名称而强制动态化。

本轮具体修正：

1. 改造前原生插件的可选资格由 UI 和 Native 各自解释能力 ID/版本，曾造成表格插件漏选。
   选择 Native 统一计算并随目录返回 `selectable`，UI 仅消费结果；提交时 Native 再以当前
   目录验证，已部署且本机源文件缺失的固定副本仍按现有规则保留。
   另一方案是前后端生成共享能力常量，但仍保留两套判断且增加构建机制，因此不采用。
2. 内置 UI 插件与宿主共同编译，不需要额外的运行时 API 版本计数。删除该字段及拒绝分支，
   保留类型契约、身份冲突检查、声明命令范围和 React 生命周期。外部动态 ABI 检查不变。
3. 当前产品文档含重复的阶段日志和过时路线图。将现行能力、限制、职责和使用方式整理到
   对应主题；有日期的验收事实继续以 reviews 为证据，不将历史测试改成当前测试结论。

不增加新服务、全局服务定位器、事件总线、任意热卸载、第三方 UI 包或新的持久格式。
不改用户数据、交易发送规则、任务生命周期与既有服务选择。不修改 NMR。
