# 非必要哈希清理

非必要哈希及校验，并在 `AGENTS.md` 禁止 AI 无依据添加。

## 判断与实现

检索并沿调用链核对 `core/`、`protocol/`、`plugins/`、`apps/`、`scripts/`、CMake、
测试及现行文档中的 SHA、digest、fingerprint 和 hash。以具体消费者、失败场景及
所有权边界区分内容身份、密码学用途、部署校验和没有消费者的额外校验，不按名称批量删除。

| 位置 | 处理 | 原因 |
| --- | --- | --- |
| 桌面分析运行时 | 删除源码摘要、完整依赖文件哈希清单及遍历复算，删除签名前后的两套哈希检查分支 | 普通启动无需重新验证整套本机依赖；打包脚本的文本变化不应阻止启动。保留平台及可执行入口检查，锁定依赖与显式构建负责资源准备，集成测试验证真实调用 |
| Linux 服务源码指纹输入 | 排除 `plugins/tools/analytics` | Python 助手仅随桌面分发，不属于远程服务；修改它不应导致服务包失配 |
| 插件目录与安装预览 | 复用 `NativeLibrary::sha256()`，删除外围重复计算与比较 | 统一加载器已拥有加载前后的文件身份检查。目录扫描仍需取得坏插件的摘要，用于用户明确卸载观察到的损坏副本 |
| 单实验与比较导出 | 删除导出 JSON 的额外 SHA-256 生成、回执字段和界面展示 | 该哈希只用于展示，没有产品读取或校验消费者。保存状态、字节数、文件不覆盖及文档内部固定输入/结果身份保留 |
| 导出测试与报告 | 文件内容直接比较，删除额外导出哈希记录，更新回执断言 | 验证实际参数、结果、矩阵和保存行为即可，不为测试报告装饰生成哈希 |

比较了“保留原检查但忽略错误”和“删除无消费者的生产/检查链”。采用后者，不添加绕过开关、
旧契约分支、替代版本计数或新的自动恢复逻辑。

`AGENTS.md` 新增全仓库约束：新增或保留检查须能解释实际需求、可达失败、消费者及所属边界；
不得以泛化安全理由添加哈希；不得重复扫描已验证输入或仅为日志/展示生成摘要；代码、字段、
测试和现行文档同时更新。原先笼统保留 build/artifact identities 的要求也改为按实际需求判断。

## 保留的必要用途

| 用途与代码边界 | 具体约束 |
| --- | --- |
| Conan/pnpm/uv 锁及 `prepare_ctp.py` | 获取的依赖必须对应已锁定内容；不是每次启动扫描本机资源 |
| Data/Task、历史文件存储与原文观测 | 固定输入/结果及数据修订被持久引用，重放、比较、发布不能换成另一份同名内容；需求 `common/contracts.md` 明确要求内容身份及依赖 |
| SQLite 日志归档与 Task 只读预验 | 活跃/归档事件归属、断点恢复和读写所有权交接不能混用不同内容；不删除账本一致性约束 |
| Agent 程序/插件安装、传输与升级 | 内容寻址文件、用户确认的候选程序、正在执行及账本固定的插件必须一致；上传、复制、升级之间存在真实文件变化边界 |
| 远程服务包与发行验收 | 本地 Terminal 和单独构建的 Linux 服务包必须来自匹配的服务/协议输入；验收记录必须绑定实际安装包。保留匹配与传输完整性，不再纳入桌面 Python 实现 |
| TLS、钥匙串命名、账户所有权和下载限额键 | TLS 的密码学签名、稳定私有命名和唯一账户/配额归属有实际消费者，不是额外文件校验 |

保留类别不构成以后无限添加同类校验的许可。现有“跨用户确认/复制/进程/持久读取”的校验
不能仅因算法相同就视作重复；反之，单纯增加一个哈希不能替代结构与领域检查。

- 插件检查的预期摘要验证集中到 `NativeLibrary`，在 `dlopen` 前完成；Agent父进程删除

  使用同一加载边界，删除外层重复哈希。插件ABI、能力、平台及加载期间文件变化检查保留。
- 客户端删除插件目录选择后的立即复算；上传流程用已有计算结果核对预期摘要，在发送前

  仍分别校验不同文件。没有新增长期验证缓存或额外重试。
- 删除任务服务启动时对三个工作程序的提前扫描。程序部署和实际派发仍验证内容身份，

## 按简洁性规则复查（2026-10-20）

按用户澄清重新检查前五轮差异：目标是删除没有必要的校验，而非减少哈希调用数。
检查必要性、责任边界、接口与状态数量，以及是否引入额外读取、复制和分支。

发现并撤回两处为避免哈希而扩大实现的改动：

- **远程发布双模式**：第五轮让 `expected` 同时表示正文和摘要，通过类型判断选择比较与
  复制算法。它没有删除任何校验，却增加了分支和整文件读取。恢复统一流式摘要发布；
  现有安装不被不同内容覆盖、权限、原子发布和持久化语义保持。比较了保留双模式与统一
  实现，选择后者；不再以少算小文件摘要作为增加第二套处理方式的理由。
- **原文返回包装**：`TableResponse` 把已验证摘要带到上层，确实省去回复编码时的计算，
  但为此改变了存储、观测、保证金和原文核对接口。当前没有性能证据要求这项跨层优化。
  删除包装，恢复直接返回 `SourceResponse`；协议中的原文摘要仍按现有契约生成，
  没有新增校验门槛。保留第三轮在存储函数内部复用摘要的简化，不为复用扩大返回契约。

保留有明确收益且不增加替代校验的改动：
