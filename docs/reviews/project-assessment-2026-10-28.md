# 项目评估与路线

日期：2026-10-28。评审基线：`ce20b5c6`（`main`）。

状态：方向已由使用者于 2026-10-28 确认，取代 2026-10-25 的评估与重构计划。**当前处于第 1 阶段**，第 0 阶段尚余 M0.1 与 M0.5。

本文回答三个问题：项目离目标有多远，最终形态是什么，按什么顺序走过去。
产品定义见[产品说明](../product.md)，交易不变量见[交易安全契约](../safety.md)。
第 9 节是执行状态，每完成一个工作包更新一行。

## 0. 结论

- 工程很严谨，但力气用错了地方。交易安全链、定点小数、期货账本和行情界面是对的，保留。
- 量化终端最核心的两件事还没做成：使用者不能自己写策略；产品从没在真实数据和真实柜台上跑过。
- 大部分代码花在“可追溯证据”、按任务复制的固定输入和多机部署上。它们让研究变慢、让 CI 变慢，还把内部模型暴露给了使用者。
- 方向：**C++ 管钱和单子，Python 管想法。** 策略是 Python 代码，回测、仿真柜台和实盘调用同一个接口；
  数据以自录 CTP 行情为主，存为 Parquet；进程按故障范围划分，删除管理层的大部分机制。
- 顺序：先接触现实，再换数据底座，再换策略与回测，再换实盘运行，最后是多因子组合和小资金实盘。
  每个阶段都用真实数据或仿真柜台验收。

## 2. 评价

### 2.1 保留

- **交易安全链。** 先记录后发送、一次性发送许可、结果不明不重发、授权和风控必经、每个账户一个独立进程。
- **期货领域细节。** 定点运算、逐日结算、保证金与手续费版本、主力换月、夜盘交易日归属，以及本根收盘决策、下一根成交。
- **行情界面。** 分组报价表和分时、K 线双窗格，已经是能用的看盘终端。
- **基础机制。** 持久写入、本机 IPC 与 TLS 通道、日志、Electron 安全加固，以及“每份状态只有一个拥有者”的原则。

### 2.2 问题，按严重程度

1. **策略不能自己写。** 使用者只能从写死的规则里选一个、填参数。策略页的“规则”只支持双均线；因子只有动量、期限结构、
   波动率三个，外加一个只能用收盘价的小表达式，而且已冻结。研究终端的核心价值基本缺失。
2. **从没接触过现实。** 交易文档写明只在测试用 CTP 替身上验证过，仓库里没有任何仿真柜台验收结果，本机开发节点没有下载过行情。
   正确性全部是对着夹具证明的。
3. **“可复现”做成了贯穿全栈的仪式。** 每个任务复制全部 K 线，于是有了 20 万根上限；螺纹钢一年的 1 分钟线就有约 8 万根，
   跨品种分钟研究放不下。快照、摘要、来源证据这些内部概念直接出现在界面上。
4. **部署拓扑按机房和团队设计。** Node Manager、SSH 远程登记、远程升级、联合卸载、冷备和制品摘要，一个人都用不上，
   却让 CI 变慢、故障面变大；Linux SSH 系统服务验收是 CI 里反复失败的一项。
5. **自动交易还不能真用。** 一个账户只能运行一个策略、一个合约；预热只用行情服务当天现场看到的 K 线，不读历史；
   行情服务或交易服务一重启策略就结束且不恢复；实时分钟线只在内存里，从不落盘。
6. **界面是表单向导，不是终端。** 回测是三步向导，结果是一长串折叠项，回测与评估分在两个模块；没有策略编辑入口，
   K 线上没有买卖点，没有参数敏感性图。
7. **需求写成了监管规范。** 2.6 万行、293 项功能需求、1,002 条验收，并规定“优先级不是排期、不自动删减范围”。
   一个人核对不了，AI 代理把它当法律执行，就会不停生成证据和校验机制。第 3、4 条的根源在这里。本次已删除，见第 8 节。
8. **反馈太慢。** 主干一个月没有全绿，一次 CI 一两个小时，累计改动量是现存代码的五倍多。代码产出远快于验证。

## 3. 目标形态

### 3.1 原则

- **C++ 管钱和单子：** 行情网关与录制、账户进程、风控、回测撮合与期货账本。
- **Python 管想法：** 策略、因子与研究、数据采集与整理。
- **策略只输出目标仓位或权重。** 换算整数手数、风控、记录、发送和全部金额计算都在 C++ 内核完成，规则见[交易安全契约](../safety.md)。
- **复现靠自动记录。** 每次运行记下数据版本、策略提交号、参数、引擎版本和依赖锁摘要，平时收在结果详情里。
- **只有一份契约。** 服务之间和界面都用 Protobuf；TS 类型和客户端由 proto 生成，不再手写 JSON 映射。
- **每个新机制都对应一个使用场景。**

### 3.2 进程

| 进程 | 语言 | 职责 | 来源 |
| --- | --- | --- | --- |
| 行情 | C++ | CTP 行情、Tick 录制、分钟合成，向策略和界面分发 | 扩展现有 `asterion_market` |
| 账户，每账户一个 | C++ | 授权、风控、先记录后发送、对账；接收策略目标并合并 | 扩展现有 `asterion_trading` |
| 策略，每个运行中的策略一个 | Python | 加载策略版本，历史预热，接收实时 bar，输出目标 | 新建 |
| 研究服务，每节点一个，暂名 `asterion_lab` | Python | 数据采集与仓库、回测与因子任务、运行记录、策略仓库索引；计算放子进程并行 | 新建，替换 Data 与 Research |
| 节点守护，每节点一个 | C++ | 拉起和监督上述进程、服务发现、远程节点的单一 TLS 入口 | 由 Node Agent 精简而来 |
| Terminal | Electron + React | 主进程持有服务连接，界面用生成的 TS 客户端 | 删除 Node-API 原生编排层 |

远程节点就是同一套程序在 Linux 上用安装包加 systemd 部署，Terminal 用一次性令牌配对。
Node Manager、SSH 登记、远程升级和联合卸载都删除。分析助手 `plugins/tools/analytics/report.py` 已有 Python 端的
Protobuf 帧读写，可作为研究服务的起点。

### 3.3 数据

- **自录行情。** 行情进程按交易日把订阅合约的 Tick 写成 Parquet，并用同一份聚合代码合成 1 分钟线；目标是全市场。
  重启后续写，缺口如实记录，不补造。录制放在全天运行的 Linux 节点上。
- **Tushare。** 日线、合约表、交易日历和权限允许的历史分钟线，由研究服务采集。
- **存储。** Parquet 按数据类型、交易所、品种和交易日分区，DuckDB 查询。价格保留精确值，研究侧可读成浮点，账本只用定点。
- **数据集版本。** 一份分区文件清单。摘要在写入时计算一次，作为身份；任务只引用版本，不复制数据，也不设条数上限。
- **日历与交易时段。** 都带生效日期；夜盘的交易日归属按交易所规则。
- **主力连续。** 换月依据、换月时点和价格调整方式分别声明。连续序列只用于信号，成交落在真实合约上；
  调整后的价格和收益序列各有用途，不能混用。
- **多品种决策截点。** 多个品种一起决策时，哪些成员必须到齐、按谁的日历、迟到的 bar 怎么处理，写成确定规则，
  历史回放与实时运行一致，不默默用前值补齐。

### 3.4 策略与回测

- 策略放在使用者自己的 Git 仓库里，用任何编辑器和 AI 助手编写。策略版本就是提交号；工作区有未提交改动时另记差异摘要。
  Terminal 监视这个仓库，负责运行、展示、比较和上线。
- 接口初稿如下，M2.1 定稿：

  ```python
  class MaCross(Strategy):
      params = {"fast": 5, "slow": 20, "lots": 1}

      def on_bar(self, ctx, bar):
          closes = ctx.history(bar.symbol, "close", self.params["slow"])
          if len(closes) < self.params["slow"]:
              return
          up = closes[-self.params["fast"]:].mean() > closes.mean()
          ctx.target(bar.symbol, self.params["lots"] if up else -self.params["lots"])
  ```

  只在完整 bar 上决策，目标在下一根 bar 执行，与现有引擎一致。组合策略输出权重，
  内核按权益、价格和合约乘数换算成整数手数，向零取整，余量不自动分配。
- 回测：现有撮合与账本编成 Python 扩展模块，由 Python 驱动事件循环；参数扫描在多个子进程里并行。
- 快速研究：因子和信号探索直接用 Polars 和 NumPy 向量化计算；事件驱动回测负责验证。
- 运行记录：每次运行一份记录；权益、成交、委托、持仓和逐日结算存 Parquet，列表和指标存 SQLite。

### 3.5 实盘运行

- 策略进程启动时从数据仓库加载历史预热，再接实时 bar；实时 bar 和历史 bar 由同一份聚合代码生成。
- 账户进程接受已登记策略实例的目标，合并为账户目标并保留归属；每笔委托走安全契约第 1 节的路径。
- 订单管理：限价、超时撤单重挂、最大追价跳数，按策略版本配置。
- 恢复：账户进程恢复交易记录，策略状态由预热重建；授权不跨重启。
- 监控：交易页的运行面板、桌面通知和可选推送；账户级和全局的“停止全部策略并撤单”。

### 3.6 界面

- 一级入口收为行情、研究、交易、数据四个，加设置。分析、策略、回测、评估四个一级入口删除。
- **研究页**：左侧策略和数据集，中间图表，右侧运行配置，底部运行记录。结果一屏看到核心指标、权益与回撤、
  带买卖点的 K 线、月度收益和参数热力图；回测、评估与比较在同一处；复现信息收在详情里。
- **交易页**：资金、持仓、委托、成交，以及运行中策略的面板：目标与实际仓位、最近信号、盈亏、风控占用、连接状态。
  “暂停新增”“停止并撤单”“平仓”分开确认。
- **数据页**：品种乘日期的覆盖矩阵、录制状态、采集任务。
- 文案使用量化术语：数据集、策略、参数、费用、结果。“固定输入”“来源证据”“内容摘要”这类内部概念不出现在主界面。
- 行情页保留现有设计。

### 3.7 文档

- 目标与不变量只有三份：[产品说明](../product.md)、[交易安全契约](../safety.md)和本文。
- 其余主题文档只描述当前代码，跟代码走：替换或删除代码的同一提交里更新或删除对应文档。
- 每个阶段开始时，把本文该阶段的验收清单细化成可执行步骤；阶段结束时在第 9 节记录真实验收结果。

## 5. 路线

每个阶段的出口条件都要求真实使用；只有夹具测试通过不算完成。

### 第 0 阶段：接触现实，1 至 2 周

目标：知道现有链路在真实环境里哪里会坏，并得到可信的 CI。不加功能。

| 工作包 | 内容 | 完成判据 |
| --- | --- | --- |
| M0.1 SimNow 交易验收 | 使用者提供 SimNow 账户；按 [CTP 仿真验收](../acceptance/ctp-simulation.md) 在交易时段运行 `tests/acceptance/ctp_trading.py`，再人工完成连接中断、进程恢复、跨交易日和 Terminal 关闭几项；只修验收暴露的问题 | 一份逐项记录通过、失败、未执行的验收记录；每个失败项都有修复提交或登记的已知问题 |
| M0.2 真实数据 | 用使用者的 Tushare 账号更新一年全市场日线，权限允许时下载一个主力合约一个月的 1 分钟线；在现有界面各做一次日线和分钟线回测 | 下载和回测的记录，含权限、额度和失败；暴露的问题修复或登记 |
| M0.3 CI 两档 | 快速检查在每次推送时运行，目标约 15 分钟：格式、类型检查、lint、界面单测、`ctest -L unit` 和交易进程测试；完整检查每晚和手动触发时运行现有全部作业 | 快速检查连续一周全绿；完整检查的每项失败都登记到工作包 |
| M0.4 已知失败 | 处理第 1 节列出的 CI 失败。属于第 2、3 阶段要删除部分的测试，先隔离并登记，不深挖 | 完整检查只剩已登记的隔离项 |
| M0.5 外部条件 | 使用者咨询穿透式认证流程，确认 Tushare 分钟线权限，准备一台全天运行的 Linux 主机 | 三项各有结论，写入第 6 节 |

### 第 1 阶段：数据底座，2 至 3 周

| 工作包 | 内容 |
| --- | --- |
| M1.1 Python 运行时 | 按决定 D1 选定分发方式；Python 与依赖由 uv 锁定；macOS 和 Linux 在没有系统 Python 的机器上都能运行 |
| M1.2 研究服务骨架 | Python 服务，沿用现有 Protobuf 帧格式与本机 Unix socket，远程沿用 TLS；由 Agent 监督；健康检查与日志 |
| M1.3 生成的 TS 客户端 | 由 proto 生成 TS 类型与客户端，Electron 主进程持有连接；第一个使用者是新的数据页，之后新增界面一律走这条路径 |
| M1.4 Tick 录制 | 行情进程按交易日写 Tick 与 1 分钟线的 Parquet；重启续写；缺口如实记录；实测每个交易日的数据量 |
| M1.5 数据仓库 | 分区 Parquet 与 DuckDB；数据集版本清单；Tushare 日线、合约表与交易日历采集；带生效日期的交易时段；主力连续构造 |
| M1.6 数据页 | 覆盖矩阵、录制状态、采集任务 |

完成判据：在 Linux 节点连续录制一周，每个缺口都有原因；任意品种任意区间的分钟线查询在秒级返回；
数据集版本能被引用且不复制数据；自录分钟线与 Tushare 分钟线抽样对照一致，前提是有分钟权限。
本阶段旧 Data 服务继续支撑现有研究页面，第 2 阶段删除。

| 工作包 | 内容 |
