本文只保留当前架构、有效工作包和未完成的验收。产品范围见[产品说明](../product.md)，进程与状态归属见[架构](../architecture.md)，所有交易行为遵守[安全契约](../safety.md)。

**当前阶段：第 3 阶段，推进 M3.3 实例操作与监控。** M3.0、M3.1 的代码与隔离验证已完成，真实供应商、柜台及正式部署仍待验收。当前授权范围是代码和隔离验证，不配置真实账户，不执行正式部署。

## 架构与实施边界

| 部分 | 当前职责 |
| --- | --- |
| Terminal | macOS Apple Silicon / Linux x86_64 桌面；看盘、研究操作、策略包发布、账户控制与监控；只启动和看护本机 Lab |
| Market | 独立 Linux C++ 服务进程；实时接入、录制、历史采集、正式仓库与版本发布，多客户端共享唯一数据，连接和读取进度独立 |
| Lab | 本机 Python 研究服务；读取 Market 固定版本、只读缓存、策略与因子、回测、扫描、报表与研究记录；准备列明源码的策略包 |
| Trading | 每账户一个独立 Linux C++ 进程；直接连接柜台行情与交易前置，拥有授权、风控、委托、对账与策略子进程 |
| 策略子进程 | 从 Trading 主机已部署包运行，只接收实例启动后的完整 K 线现场预热，输出目标手数或权重；没有订单接口 |

Market 和 Trading 分别由 systemd 看护，Terminal 关闭不影响它们。Trading 不依赖 Terminal、Lab 或 Market 执行交易；重启不恢复授权或策略实例。
Market 不包含 Python 运行时或采集子进程。Lab 首次启动安装研究运行时；Trading 的独立 Linux 发布包携带离线策略运行时。
远程 Market/Trading 均使用双向固定证书指纹 TLS，供应商凭据只在对应主机管理。本机 Lab 使用 Unix socket。

策略包和实例分开，格式见[交易说明](../trading.md#策略包与本机加载)。同名同版本包不可覆盖；发布不启动、不授权。
实例从空窗口开始，启动时半根 K 线不参与预热；日线策略等待实际完整交易日，不能以历史预载加速。
已有持仓、未终结与未确认委托由账户拥有，策略重启不会将它们清零。授权、执行行情时效、风控和持久记录都在 C++ 唯一执行路径上检查。

#### 第 3 阶段完成条件

1. Market 多客户端、真实录制、固定版本研究读取及正式部署验收通过。
2. Trading 从本机包启动，启动前历史与半根 K 线不参与现场预热；未就绪或未授权无委托。
3. 用实例实际接收的输入回放并核对目标；不使用另一条行情连接代替该输入。
4. 目标经唯一执行路径下单；策略故障后账户仍能接收回报、撤单和对账，未确认委托继续占用风险。
5. 关闭 Terminal、断开桌面网络、停止 Market/Lab 后已授权交易继续；Trading 重启不恢复授权或旧实例。
6. SimNow 连续两周每日成交、持仓、资金对账一致。以当前实现完成验收，不沿用已替换执行实现的结论。
