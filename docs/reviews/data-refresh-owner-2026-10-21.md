## 交付链路与所有权

已入库日分区的显式重取，由所选 Data 实例完成预览、授权、接纳、执行、持久状态、取消、显式重试、修订发布及结果读取。该路径不再要求 Task 进程在线。Data 专用 `RefreshTaskRequest/Response` 只开放本业务的授权引用接纳和任务观察/控制，不转发通用 Task 请求，不新增任务框架、worker 或 Agent 任务接口。

`RefreshTasks` 在 Data 的既有串行写线程上复用 `tasks::Store` 的固定输入、尝试令牌、接纳上限、日志、结果验证和中断恢复。自己的任务存储位于 Data 业务目录的 `refresh-tasks/`；单实例当前串行执行一个重取，既有有界线程池负责取数。共享下载算法抽为静态目标，Data 使用既有私有通道和分区发布机制，来源额度仍由 Data 的 DownloadBudget 统一核算。没有把整个 TaskHost/Store 搬入 Core，没有复制状态机或建立中央任务库；共享机制目前仍复用现有实现目录，未完成更广目录收敛。

刷新授权的执行实例绑定 Data，分配时核对授权与执行实例；相应授权排序键使用实际所有者。Task 在提交、显式重试和恢复调度边界拒绝刷新，普通分钟下载、缺失表补齐和研究任务继续原路径。原 Task 开发记录不自动迁移或删除，不提供兼容读取或静默改写。

前端刷新面板直接观察 Data 任务，提交、取消、重试及结果读取携带 Data 连接身份；切换服务后旧控制不能作用于新服务中的同名任务。观察轮询不重叠，不发起供应商请求；来源范围、额度、旧修订及显式确认流程保留。任务被接纳后离开页面不取消，重开按 Data 的持久记录恢复观察。通用任务中心的跨服务聚合尚未迁移。

## 完成、取消与恢复

同一接纳身份的重复提交复用已有任务，不再次执行或发布。修订发布继续核对固定旧目标，已发生的其他更正不能被旧目标覆盖；相同内容不新增修订，空响应保留原数据。取消先进入请求状态，实际取数返回后才确认终态，在途已取得的事实不撤销。

Data 崩溃重启将未确认执行标为中断，保留已确认结果，不自动重试。显式重试遵守已有预算恢复的一分钟静默窗口，未缩短、跳过或清空预算。维护排空冻结新接纳和重试，让已经接纳的取数及发布完成；仍有执行时明确拒绝维护停机。普通异常终止与升级排空保持区别。

预期的不存在任务、非法重试和身份冲突返回业务拒绝，不把 Data 标为持久化故障。实际接纳文件已创建但未完成时保留证据并明确要求恢复；真正的持久化异常继续进入故障边界。
