# 项目自有命名去除实现版本号

日期：2026-10-20。主 checkout 的 `main`，基于当前未提交工作树；保留此前功能和哈希清理。

## 范围与设计

用户要求清理代码、作用域和目录中的实现版本号。只维护当前实现，不用递增名称区分新旧，
不添加兼容入口。必要 ABI 检查、外部依赖版本和数据身份不属于实现命名。

协议有两个可行选择：把生成类型并入业务命名空间，或者保留按职责命名的生成类型作用域。
选择后者，用 `proto` 明确区分传输类型和领域类型，避免为去掉版本号而混淆边界。
不改变消息字段、字段编号、数值枚举、传输机制或持久化布局。

## 完成的修改

- 11份 Protobuf 从 `protocol/proto/asterion/v1/` 移到 `protocol/proto/asterion/`。
  包名末级由 `v1` 改为 `proto`；同步 C++ 引用、导入、CMake、Python 生成路径和分析助手。
- 插件类型改为 `AstPlugin`、`AstPluginEntry`、`AstHistory`、`AstHistoryTables`、
  `AstHistoryConnection`、`AstHistoryResponse` 和 `AstRisk`。能力常量与能力字符串采用稳定名，
  导出入口为 `asterion_plugin_entry`。同步宿主、生产插件、纯C夹具和 macOS 导出符号配置。
- 主机助手检查回复采用 `asterion-host`，初始化器、SSH引导和测试使用同一契约。
- 更新现行架构与插件文档；删除本地构建目录中已被替代的 Protobuf 生成目录。
  不保留旧类型别名、转发头文件、旧入口或双协议包。

ABI版本字段、函数表大小和不支持能力的拒绝行为保持；固定插件摘要仍要求当前产物。
重新构建插件和宿主，不尝试让旧插件通过新入口加载。远程安装的主机助手不会自动更新，
后续部署须使用当前初始化器与服务包；旧助手回复不匹配时仍明确失败。

## 保留的版本标识

- 供应商归一化/来源修订、原文格式、日志与快照摘要域，以及对应的数据夹具。
  它们决定持久数据含义和身份，不能为了名称清理换值。
- 用户已存的关注列表、费用模板、SSH机器资料的存储键。改键会使已有配置不可见，
  本次不重写、不迁移，也不创建另一个存储入口。
- 依赖锁、发行版本、第三方API/标准（如 SQLite、IP、cgroup、Matplotlib缓存格式）及工具选项。
- 有日期的历史审计记录保留当时名称；当前实现和验证以本记录为准。

本次不改变用户数据、服务配置或远程主机，不提交或推送。
