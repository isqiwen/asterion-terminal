# 开源准备与生态治理

> 2026-09-20 开发原则更新：只按维护者当前最新架构与设计实现，绝不为旧设计、代码、协议、插件或格式做兼容。此前关于向后兼容、弃用过渡及旧格式迁移的设计要求已撤销；执行规则以仓库 [AGENTS.md](../AGENTS.md) 为准。平台条件校验、当前协议适配与业务历史记录保留不构成旧设计兼容承诺。

设计日期：2026-09-19。状态：目标与发布门槛，不代表已经具备公开分发许可、插件市场或社区支持承诺。主设计见 [架构 v2.1](architecture.md)，当前开发入口见 [贡献指南](../CONTRIBUTING.md)。

## 1. 开源要交付的产品

目标是让使用者保留自己的数据、配置、策略和工作区，让开发者通过稳定扩展点增加能力，并能基于核心构建自己的终端。默认发行版提供一套可用体验；社区发行版可以选插件、主题与工作区预设，无需复制或修改核心业务状态机。

终端应支持三条完整路径：安装后通过格式模板与导入说明理解流程；连接自己的数据并完成可复现研究；用独立仓库开发一个插件并装入测试终端。开源就绪不能只用仓库是否公开判断。

### 四类交付物

| 交付物 | 包含什么 | 不包含什么 |
|---|---|---|
| 核心源码与默认发行版 | 桌面、控制服务、数据与研究/交易基础、内置扩展 | 用户数据、密钥、未经许可的行情、未核对再分发权利的连接器 |
| Python / TypeScript SDK | 最小公共类型、宿主客户端、开发用测试工具 | 内部 ORM、私有表结构、宿主主令牌、全部研究依赖 |
| 示例和模板 | 合成数据源、纯加工器、声明式面板、示例策略、锁定依赖 | 真实账户、承诺盈利的结果、必须付费才能完成的入门路径 |
| 社区发行配置 | 核心版本、插件包 hash、布局、主题、脱敏配置 | 可导出凭据、隐式实盘授权、覆盖核心风险约束的开关 |

当前源码提供标准库 Python SDK 与独立日历/表格样例，可打包并安装；尚未向公共包索引发布，不能声称已有公开生态。

## 2. 许可与来源

当前尚未选定并落盘项目 LICENSE；本轮不替维护者选择或发布许可证。公开发布前需要明确核心、SDK、示例、文档、品牌和二进制的授权范围。公开源码本身不等于获得开源再分发权利；开源许可应符合 [OSI 开源定义](https://opensource.org/osd)。

选择标准先写清：是否允许社区发行、商业插件和闭源外围服务；是否要求对核心修改回馈；是否允许更换品牌；贡献者如何确认提交权利。SDK 应便于独立插件采用，核心与 SDK 采用不同许可时须逐项检查兼容性。许可证名称、贡献签署方式与商标规则由维护者决策，正式决定后写入 LICENSE 和贡献文档，不在多处留下不同版本。

发布清单应覆盖 Python、npm、Rust、打包数据库、图表库、字体、图标、示例数据与原生 SDK。为每项记录版本、来源、许可、NOTICE 要求和实际打包内容。代码许可不自动授予行情或经纪商 SDK 的再分发权限；默认示例使用项目生成、标注清晰的合成数据。连接器可要求用户提供自己的合法安装与账号。

## 3. 社区可维护的边界

核心仓库接受影响多个模块的不变量、公共协议、默认体验和官方适配器。专门数据源、研究方法和个人视图优先独立插件仓库。核心维护者不承担每个第三方数据源的账号支持或策略结果承诺。

| 变更 | 最低评审要求 |
|---|---|
| 文案、样式、普通视图 | 对应行为截图或说明、无障碍与现有流程检查 |
| 新插件能力或公共 schema | 简短设计说明、至少两个使用场景、当前契约、破坏性变更范围及契约测试 |
| 数据发布、任务与迁移 | 并发/中断/重试证据、回收与恢复影响 |
| 撮合、风控、账务与恢复 | 领域评审、固定输入回放、故障场景和未覆盖假设 |
| 原生系统权限或外部代码执行 | 能力范围、跨平台限制、资源约束、故障与越权测试 |

新增架构决定用短记录说明问题、选项、决定、代价、迁移及验收，分配稳定编号；被替代的决定保留关联。早期由维护者承担角色，不虚构委员会或已有响应团队。未来建立 CODEOWNERS 时必须填真实且愿意承担责任的人。

Issue 模板要求版本、平台、可复现步骤、预期/实际结果和脱敏诊断；PR 模板要求用户行为变化、验证及破坏性变更影响。插件模板和 good-first-issue 应能离线跑通。贡献者不应为了修一个表格先构建完整桌面安装包。

## 4. 版本与当前契约政策

项目不承诺旧设计、旧 API、旧 SDK、旧插件、旧配置或旧持久化格式的兼容，也不设置弃用过渡期。版本用于标识发布内容、数据语义和运行依据，不用于要求新实现适配历史设计。

契约变化时同步更新调用方与文档，删除被替代的代码；不符合当前契约的内容在执行前明确拒绝。发行说明列明当前支持平台、契约、破坏性变更与验证范围，不隐含自动升级或迁移旧格式的能力。

既有数据、研究结果和来源记录不得静默改写或删除；不再受支持的历史运行明确标为不可执行，不保留旧执行器，也不改用最新输入冒充原结果。当前格式的备份、恢复和中断保护仍须经过实际验证。

## 5. 发布与用户数据保护

发布流水线目标：锁定依赖 → 静态/契约/业务测试 → 平台构建 → 全新安装 → 当前格式备份恢复与当前契约校验 → 产物 hash 与依赖清单 → 签名验证 → 发布说明。平台支持必须依据实际验收矩阵；有 Linux 构建脚本不等于所有 Linux 桌面已验收。

运行包替换前，在暂存目录校验包、当前数据库契约与空间，生成当前格式备份和操作计划，再停止必要写入并切换。遇到旧格式明确拒绝，不增加自动迁移或旧执行器。健康检查通过才提交切换，失败按已执行阶段恢复符合当前契约的环境；不得以切回旧代码冒充状态已恢复。

安装外部插件默认展示来源、许可、权限范围、平台支持与状态。官方、社区和本地开发来源分别标识；签名说明来源和完整性，不意味着逻辑正确。先支持本地开发目录和固定包导入，再考虑索引服务；在线市场不阻塞首个开源版本。

插件卸载保留被任务、实验和策略引用的运行包与数据。用户主动清理时展示实际引用者及可回收内容。第三方扩展不得提供跳过核心引用检查的删除入口。

## 6. 隐私、诊断与问题响应

默认不上传行情、研究源码、模型、账户信息或使用遥测。需要在线服务的插件在连接时说明发送的数据种类和目的；凭据只供批准的连接使用。云同步若建设，先提供明确范围、冲突处理、导出和退出路径，本机研究不依赖云在线。

诊断包可预览并选择导出，包含版本、平台、配置修订、相关任务/事件 ID、脱敏错误与资源概况；默认不包含 Token、账号密码、原始行情、策略源码或本机完整路径。请求 ID 贯穿 UI、API、任务、插件及发布，方便社区复现问题而不暴露业务数据。

公开发布前设置有效的私密漏洞报告渠道并测试可达，公布支持版本和维护责任。尚未建立渠道时不创建虚假的 SECURITY.md 邮箱。凭据或交易相关缺陷先控制受影响能力，保留数据与审计，再发布修复和迁移说明。

## 7. 开源发布门槛

以下均为待验收目标，不因本文件存在而自动通过：

- [ ] LICENSE、依赖/二进制/示例数据来源清单和再分发范围明确。
- [ ] 新贡献者仅按 README/CONTRIBUTING 在干净环境跑通合成数据闭环，无私有服务依赖。
- [ ] 至少一个外部数据源样例、一个加工器及一个声明式面板在独立仓库开发并通过契约测试。
- [ ] 插件暂停、崩溃、不兼容、权限升级、离线安装和卸载不破坏核心工作台及固定结果。
- [ ] 全新安装、当前配置/布局恢复、旧契约拒绝、一致性备份和恢复有实际记录。
- [ ] 文档、Issue/PR 模板、支持平台表、维护责任、行为准则与私密问题渠道齐全。
- [ ] 默认发行版展示真实已交付能力，实验性功能清楚标识；不把研究预览描述为可实盘系统。

开源发布可先限定为数据与研究预览版，交易未完成不阻塞这个范围的源码发布；完整交易版另按交易阶段验收。当前交付可信内置扩展和用户明确认可的本地 Python 插件；不能宣传任意第三方恶意代码安全安装。
