# Python 研究服务（lab）

`asterion_lab` 是本机的 Python 服务，代码在 `apps/services/lab/`，用第一次启动时安装的 Python 运行时以
`python3 -I -B -m asterion_lab` 运行，由 Terminal 启动和看护（见[本机服务](services.md#本机服务)）。它负责全部历史数据与研究：
期货数据仓库与采集、可同时使用的数据源、策略与因子、回测与参数扫描、运行记录，以及行情页的历史图表。

## 数据源插件

插件由 `asterion_lab/sources/catalog.py` 统一登记，声明可提供的表、交易所及配置要求。
同一能力可有多个提供者：每次查询和采集必须指定 `provider`，不设全局排他的数据源，
不自动替换或混合来源。每个来源允许一个采集任务，不同来源可同时采集、独立取消。
任务开始时固定连接配置；修改配置只影响后续任务。

| 来源 | 能力 | 配置 |
| --- | --- | --- |
| `tushare` | 日线、交易日历、合约表、合约的 1 分钟线 | 钥匙串中的凭据和请求额度；分钟线需要账号有期货分钟线权限 |
| `akshare` | 六家交易所日线 | 无；可用性取决于交易所网站 |
| `recorder` | 已录分钟线及观测区间 | 录制服务的主机与 TCP 端口 |
| `shfe`、`ine`、`czce` | 对应交易所按日发布的保证金、手续费参数 | 无 |

交易所参数不是期货公司账户保证金。未接入的交易所专项数据不声称支持，网站缺失或拒绝
访问明确报错，不用其他来源补齐。AKShare 未核实各交易所成交额单位，`amount` 留空；
无成交价格留空。录制分钟线保留 `partial` 和观测区间，区间属于录制服务整体，
不是单合约完整性的证明。未知覆盖范围不表示完整，也不推断交易日历。

Tushare 数据仍位于原来的 `warehouse/`，其他来源分别在 `sources/<provider>/warehouse/`。
新数据集清单包含来源。已有文件与版本不迁移；同一天不同来源的数据不覆盖。
重新采集需明确选择 `refresh`，产生新版本，旧版本仍可复现。研究数据选择应固定来源和
数据集版本；不同来源的同类数据对比不改变原数据。

Terminal 数据覆盖页可切换来源、选择能力与交易所、查看该来源的任务和仓库，按开始日期
直接查询来源并预览前 50 行（日历返回该年，合约表返回当前目录）。日线与结算参数按交易所采集，分钟线必须指定标准合约
（例如 `SHFE/rb/2027-01`）。Tushare 凭据和录制主机地址都在“设置 → 数据源”保存在 Terminal（凭据在系统
钥匙串，地址在 `terminal/data/recorder.json`），每次使用该来源前由原生层的 `lab.source.configure` 交给 lab，
lab 只保留在内存里；数据覆盖页不再单独填写地址。

## 协议

请求与回复是 `protocol/proto/asterion/lab.proto` 中的 `Request` / `Response`，经本机 Unix socket 以
4 字节大端长度分帧，每个请求带 `service_id` 和 `correlation_id`。

| 请求 | 作用 |
| --- | --- |
| `health` | 实例、版本、运行时长，以及内存中持有凭据的数据源 |
| `configure_source` | Tushare 只由 Terminal 原生层发送（命令 `lab.source.configure`）：从钥匙串读出已保存的 Tushare 凭据和每分钟请求上限交给服务。凭据只留在服务内存，不经过界面，服务重启后需再次发送 |
| `sources` / `source_read` / `source_coverage` | 数据源能力目录、统一单日查询、来源已知覆盖范围；查询返回来源与统一列、空值及录制观测区间 |
| `acquire` | 指定 `provider`、`table`（日线、分钟线或结算参数）；Tushare 日线同时采集 `[begin_day, end_day]` 内各交易所的日历、合约表和日线；可只选部分交易所，`refresh` 为重新读取已入库的日子（映射规则修改后用），新版本替换这些日子的行，旧版本保留原样 |
| `tasks` / `cancel` | 采集任务的进度与取消 |
| `summary` | 指定来源的当前数据集版本及各表行数、分区数和日期范围 |
| `coverage` | 指定来源每个品种每个月有日线的天数和交易所开市天数 |
| `daily_bars` | 一个合约在一段日期内的日线，数值为精确小数文本 |
| `stored_contracts` | 一个来源已入库的合约（可只问一个），各自日线与分钟线的首末日和天数，以及合约表里的名称 |
| `chart_bars` | 行情页历史图：一个合约的分钟线按 1–60 分钟或日线按日、周、月、季、年聚合，附 MACD（`asterion_lab/chart.py`，仅供显示） |
| `dominant` | 一个品种在一段日期内的主力连续：每天的主力合约、所选复权方式下的价格，以及换月记录 |
| `sessions` | 一个品种在一段日期内每个交易日的日盘与夜盘时段，以及所依据的交易所文件 |
| `cross_check` | 用第二来源核对：`settlement` 为交易所结算参数对 Tushare，`daily` 为 AKShare 日线对仓库；只报告，不存储 |
| `strategies` | 列出使用者策略仓库里的策略与因子、参数及默认值、当前提交号和未提交改动的摘要，以及导入失败的模块（见下文“策略”） |
| `backtest` / `runs` / `cancel_run` | 在子进程中回测策略仓库里的一个策略（见下文“回测”），列出运行记录的状态与指标，取消运行中的回测（记为 `interrupted`） |
| `sweep` / `sweep_runs` / `cancel_sweep` | 参数扫描：按参数取值的全部组合展开为多次回测（至多 10000 组），并行运行，列出各组的参数、状态与指标及按留出前夏普比率选中的一组；取消时未开始的不再开始，运行中的记为中断 |
| `run` | 一次运行的结果：状态与指标、`run.json` 原文、逐笔权益、逐日结算、成交，供研究页结果显示 |
| `run_report` | 一次已完成运行的 QuantStats 指标（索提诺、Omega、尾部比率、溃疡指数、日 VaR 与 CVaR），在子进程中从逐日结算计算，研究页展开时才问 |
| `factor` | 在子进程中评价策略仓库里的一个因子函数（见下文“因子”），直接回复 IC、分组收益与换手，不留运行记录 |

界面用生成的 TS 类型直接请求服务，由 Electron 主进程（开发浏览器中是开发服务端）转发字节，
见[架构](architecture.md#terminal)。数据工作台的“数据覆盖”页显示当前数据集版本、各表汇总、采集任务
和品种 × 月份的日线覆盖；Tushare 开始采集前经 `lab.source.configure` 交出已保存的凭据。

## 数据仓库

位于 lab 实例的数据目录 `<根>/lab/data/lab/` 下的 `warehouse/`（[安装目录](architecture.md#安装目录)）：

```
warehouse/files/<表>/<交易所>/<分区>-<摘要>.parquet
warehouse/versions/<版本>.json
warehouse/current
```

| 表 | 分区 | 内容 |
| --- | --- | --- |
| `daily` | Tushare 为交易所 × 月；AKShare 为交易所 × 日 | 每个合约每个交易日一行：开高低收、结算、前收、前结算、成交量、成交额（元）、持仓及变化、交割结算价 |
| `calendar` | 交易所 × 年 | 每个自然日是否开市、前一交易日 |
| `contracts` | 交易所 | 带交割月份的合约：合约标识 `交易所/品种/YYYY-MM`、上市与退市日、乘数、单位、报价与交割说明、交易时间说明 |
| `minutes` | 交易所 × 日 × 合约 | 分钟线：录制的保留不完整标记；Tushare 的按交易日归属（夜盘归下一个开市日），标签是分钟结束时间，没有均价 |
| `settlement` | 交易所 × 日 | 当日发布的交易所保证金及手续费参数 |
| `observations` | 交易所 × 日 × 合约查询 | 该次查询附带的录制服务整体观测区间，不代表合约覆盖 |

- 分区文件写入后不再改动，文件名带内容的 SHA-256 前缀；写入经临时文件、落盘、改名发布。
- 数据集版本是全部分区文件及其摘要的清单，版本号是清单本身的 SHA-256。`current` 指向最新版本。
  旧版本和它引用的文件保留，不改写、不删除。
- 数值以 `DECIMAL(28, 6)` 保存。直接 JSON 来源按十进制读取；AKShare 已解析成浮点的值按其十进制字符串接入，不能恢复上游已丢失的精度。超过 6 位小数的值让采集失败，
  不做舍入。
- 查询用 DuckDB 直接读取当前版本的文件。只有采集写入仓库，而且只通过提交新版本写入。

## 采集

同一时间只运行一个采集任务，在独立线程中执行：

1. 每个交易所每年的日历：没有存过的年份，以及当年，各请求一次。
2. 每个交易所的合约表各请求一次，按当天快照保存。
3. 区间内每个开市日、每个交易所请求一次日线，已入库的日子跳过。来源当天还没有数据的日子不算入库，
   下次再请求。每完成一个交易所的一个月就提交一个版本；任务失败、取消或服务停止时，已经读到的日子
   仍写入，只丢失尚未提交的部分。

没有日历的来源（AKShare、交易所结算参数、录制分钟线）逐个工作日请求，周末不请求。节假日由来源回答：
AKShare 和录制服务返回空，交易所对没有文件的日子返回 404，都记为空的日子、不算入库，下次再请求；
其他错误让任务失败。

请求经同一个每分钟额度发出，额度来自已保存的设置。规则与旧 Tushare 插件一致：

- 只保留带交割月份的合约代码；Tushare 自己的主力、连续代码和月均价合约不保存。
- 郑商所代码的年份只有一位，十年重复一次，Tushare 补的年代并不总对；对不上时按“字母加末三位、
  当天在市”找到所指合约。
- 当天没有连续竞价成交的合约，上期所、能源中心给空值，郑商所、大商所、广期所给 0；两者都存为空值。
  开盘、最高、最低都为空时收盘价也存为空：郑商所当天无成交的合约，交易所文件里收盘价为 0，
  Tushare 却填入了结算价（与交易所文件核对时发现）。
- 分钟线按合约逐个交易日入库：第一次请求某天时取回从那天起 27 天的 1 分钟线（`ft_mins`，夜盘从前一交易日 18:00 起），
  按交易日分组后留在内存，之后的日子直接取用，一个月约一次请求。标签是分钟结束时间：商品交易所出现 10:30 的 1 分钟标签
  说明标签是开始时间，整批拒绝；代码不符、时间不是整分、重复或成交量不是整数也拒绝。
- 成交额按万元发布，存为元。
- 返回行数达到接口上限的答复可能不完整，整个任务失败，不存部分结果。
- Tushare 的拒绝分为凭据无效、无权限、达到频率上限和其他错误；错误与日志不含 token。

## 主力连续

三部分分别声明：

- **换月依据**：当天有结算价的当月及以后合约中，前一交易日持仓量最大者；只向后换，不回到更早的月份。
- **换月时点**：次日生效，所以区间的第一天要读前一交易日（查询自动多读请求起始日之前 31 天）。
  用于交易的序列（`traded`）不能持有合约过最后一天，在合约最后一天就换给其他月份中持仓最大者，并要求
  旧合约在换月日及之后仍有 K 线；只读的序列没有这两条。
- **复权**：`none` 为原价；`ratio` 为比例后复权，最后一段保持原价，更早的每段乘以其后每次换月时
  “新合约 / 旧合约”在换月前一交易日的结算价之比。比例与系数为 8 位小数、四舍五入，与 C++ `Decimal` 相同。

任何一天没有可选的主力、换月前一天缺少两个合约的结算价，或交易序列的旧合约在换月日后没有 K 线时，
查询失败，不做推测。连续序列只用于信号，成交落在真实合约上。

## 策略

策略写在使用者自己的私有 Git 仓库里（决定 D5），接口在 `asterion_lab/strategy.py`：

```python
from asterion_lab.strategy import Strategy

class MaCross(Strategy):
    """Long while the fast average of closes is above the slow one, short below it."""
    params = {"fast": 5, "slow": 20, "lots": 1}

    def on_bar(self, ctx, bar):
        closes = ctx.history(bar.symbol, "close", self.params["slow"])
        if len(closes) < self.params["slow"]:
            return
        up = closes[-self.params["fast"]:].mean() > closes.mean()
        ctx.target(bar.symbol, self.params["lots"] if up else -self.params["lots"])
```

- 仓库根目录下 `strategies/` 中每个模块定义的 `Strategy` 子类是一个策略，标识为 `<模块>.<类>`，说明取类的文档字符串。
  模块可以从仓库根目录导入其他代码（例如共用的因子函数）。示例在 `apps/services/lab/examples/`。
- `params` 给出每个参数和默认值，类型只能是 bool、int、float、str；运行时只能改成同类型的值（整数可作 float），
  未知参数或类型不符直接拒绝。
- 只在完整 bar 上决策：`on_bar(ctx, bar)` 每根 bar 一次；多品种规则改写 `on_bars(ctx, bars)`，同一时刻完成的
  各品种 bar 一起给出，没有 bar 的品种不在其中，不用前值补齐。价格在研究侧是浮点。
- `ctx.history(symbol, field, count)` 是截至当前 bar 的最近 `count` 个值（只读 NumPy 数组）；
  `ctx.target(symbol, lots)` 要求整数手数，`ctx.weights({symbol: weight})` 给出全部组合，未列出的品种为 0。
  一个策略只用其中一种。目标从下一根 bar 起执行；`ctx` 不提供下单函数，手数换算、风控和全部金额由 C++ 引擎计算。
- 策略版本是提交号；工作区有未提交或未跟踪的改动时另记差异摘要（`git diff HEAD` 与未跟踪文件内容的 SHA-256）。
  需要本机安装 Git。
- 列出策略时在子进程中导入使用者代码（30 秒超时），每次都读当前文件，模块打印的内容不影响结果；导入失败的模块单独报告，
  其他策略照常列出。

## 因子

因子是策略仓库根目录下 `factors/` 中各模块自己定义的公开函数，标识为 `<模块>.<函数>`，说明取函数的文档字符串；
没有插件体系，策略可以直接导入同一个函数。实现与时点约定在 `asterion_lab/factor.py`：

```python
import numpy as np

def momentum(close, lookback: int = 20):
    """Return over the last `lookback` bars."""
    result = np.full(len(close), np.nan)
    result[lookback:] = close[lookback:] / close[:-lookback] - 1
    return result
```

- 参数名是 bar 字段（open、high、low、close、volume、open_interest）的接收数据，其余参数是设置，必须有 bool、int、float
  或 str 默认值；否则这个模块按导入失败报告。
- 每个品种调用一次，输入是该品种全部 bar 的只读数组，正是策略的 `ctx.history` 会看到的值（主力连续为复权到最新月份的价格，
  每个品种单独回放）；返回与 bar 数等长的一组值，NaN 表示没有值。某根 bar 的值只能用这根和之前的 bar。
- 品种写合约、品种主力连续，或只写交易所（该交易所在区间内有日线的全部品种；连不成主力连续的品种列为未参与并说明原因）。
- 每个交易日，有值的品种按因子值与此后 `h` 根 bar 的收益（收盘到收盘）求 Spearman 秩相关（IC），至少 3 个品种才计；
  每个持有期给出 IC 均值、标准差、IR（均值除以标准差）、t 值（IR 乘天数平方根）与 IC 为正的占比。
- 第一个持有期上，每天按因子值从低到高（相同值按品种名）分成若干等组，各组平均下一期收益逐日累乘；最高组减最低组另成一线。
  换手是每组每天新成员的占比的均值。
- 评价在子进程中进行，25 秒内必须完成（Terminal 等待回复 30 秒），超时时提示缩小品种或区间。上期所全部品种两年日线约 8–11 秒。

## 回测引擎

`asterion_engine` 是 `core` 中 `Replay` 的 Python 扩展（`apps/services/lab/engine/`，pybind11），回放规则：
本根 K 线决策、下一根执行，挂单只在一根 K 线内有效，主力换月，日末撤单与结算。Python 逐个时刻调用 `next()`，
把目标手数交给 `want()` 与 `decide()`，日末调用 `settle()`；结束后读取权益、结算、持仓、风控拒绝、委托与成交。
金额与价格以 8 位定点小数的整数原始值跨边界，不经浮点。

**换月日发生什么。** 换月在前一交易日收盘后就已确定。它是把序列的持仓从一个月份搬到另一个月份，不是一次交易决定，所以两条腿都**按所在 K 线的开盘价成交，不等价格**（每根 K 线都碰得到自己的开盘价；滑点照常让出）：

- 旧月份从换月日起，在自己的每一根 K 线上按这根的开盘价平掉持仓，直到平完。一根 K 线最多成交它成交量的一成（见[回测撮合模型](trading.md#回测撮合模型)），1 手的回测一根就平完。
- 新月份在本序列其余月份都已平掉之后，自己的下一根 K 线上按这根的开盘价建立序列当时的目标持仓。不同时持有两个月份。

日线上两条腿都落在换月日当天，先平旧月、再开新月，各按自己的开盘价。分钟线上是换月日各自的第一根 K 线；旧月份的第一根比新月份的晚时，新月份等到它平掉之后的下一根。旧月份在换月日没有 K 线时（当天没有成交），持仓留到它的下一根 K 线，中间的交易日照常结算，新月份等它平掉。

各月份的数据因此这样取：新月份从它成为主力的前一个交易日开始——账户要先有一个合约的价格（一根 K 线或一次结算）才接受它的委托，那一天它不交易；旧月份保留到它从换月日起的第一根 K 线和再下一根，后一根只用于前一根的成交量没有平完的部分。旧月份的数据用完时持仓还在，回测失败并指明月份（`a position remains in a contract on a day it has no settlement price`），不替它平仓。

三处细节：序列的第一个月份没有可接手的持仓，从头按普通委托交易；换月日当天策略本来就要平仓的，旧月份同样在开盘价平掉，新月份不开仓；新月份开仓时被成交量限制没有买够的部分，之后按普通委托补（限价是上一根的收盘价）。

**为什么换月不挂限价。** 普通委托挂在上一根 K 线的收盘价，等价格触及；换月原先也是这样。日线一天只有一根 K 线：在 2016–2026 年量过的七个品种（IF、IH、IC、T、黄金、铜、螺纹钢）成交最多的月份里，当天的价格区间不包含前一日收盘价的交易日占 11%（螺纹钢）到 33%（黄金），沪深 300 股指期货是 26%，连续两天都不包含的占 1.5%–11%；这些日子里朝不利方向跳开的，限价单当天不成交。而股指期货的换月大多落在旧月份的最后一个或倒数第二个交易日（沪深 300 十年 76 次换月里有 53 次），之后已经没有 K 线可以等。挂在上一根收盘价的换月还占了便宜：价格朝有利的方向跳开时按更好的开盘价成交，朝不利的方向跳开时不成交、第二天再挂。

换月的成本是两腿各自的手续费和滑点；两个月份之间的价差不是盈亏，因为持有的始终是真实合约。


## 回测

`backtest` 请求在子进程中运行一次回测（`asterion_lab/backtest.py`）：服务先确认运行配置（缺少或不是数字的金额、限额与费用按名称报错）
和策略仓库是 Git 工作树，子进程写入运行记录后服务才回复已接受，所以回复之后即可读到这次运行；子进程在写入记录前就结束时，
回复带它的错误。之后失败时记为 `failed` 并带错误，被取消或被外部结束的记为 `interrupted`。品种写作合约（`SHFE/rb/2027-01`）或品种的
主力连续（`SHFE/rb`，用于交易，信号读比例后复权价）。数据这样从数据仓库读出：

- 合约在某个交易日有竞价成交（开、高、低都有）且有结算价，这一天是一根 K 线，时间标签为该交易日 15:00（上海）；
  区间内交易所日历的每个开市日都必须已入库，否则拒绝并列出缺的日子。
- 合约乘数取自合约表（乘数乘每手数量，报价按 500 千克而交易按吨时再乘 2），区间内有成交额的日子过半要与之相差不到 5%。
- 最小变动价位按交易日从该品种全部月份的竞价价格推出：截至当天与从当天起各 20 个有成交的交易日，各求最大公约数取较大者。
- 主力连续的换月按“主力连续”一节；新月份提前一个交易日加入（账户先有它的价格），交出的月份保留到换月日起的第一根 K 线及再下一根。

手续费与保证金（每个品种八项：每手保证金、开仓、平今、平昨手续费，保证金率和三项手续费率）、滑点跳数与委托限额
（单笔手数、总手数、在途委托数）以及权重预算（总权重与净权重上限）由运行配置给出并记入 `run.json`，不从数据推断。
`ctx.target` 的手数一直有效，每根 K 线按其收盘价重新挂出；`ctx.weights` 只在给出时按当时各品种所交易月份的收盘价换成整数手
（权益乘权重除以每手价值，向零取整），超过权重预算时运行失败。
指标由 `core` 的 `performance` 计算：总收益、最大回撤、上涨日占比、年化收益与波动、夏普与卡玛比率；年化与夏普
需要运行配置给出每年期数并明确无风险利率为零，否则缺省。给出留出日时另记留出日之前（`development_`）与留出段（`holdout_`）各自的指标。

`apps/services/lab/examples/strategies/` 是示例和测试用策略：均线（`ma_cross`）、通道突破（`breakout`）、
动量（`momentum`）、均值回归（`reversion`）与截面动量排名（`momentum_rank`）。均线按 8 位定点整数精确比较均值；截面排名按权益的权重持有。


## 参数扫描

`sweep` 给出一次基础回测和若干参数的取值，按组合展开，每组一次回测、一份运行记录（编号为“扫描编号-序号”），
组与参数取值记在 `runs.sqlite` 的 `sweeps` 表。同时运行的子进程数可设，默认处理器数减一，其余排队。
`sweep_runs` 的 `active` 表示还有组（或滚动验证）未开始或未结束，研究页据此继续刷新。
给出留出日时，选中留出日之前夏普比率最高的一组，相同时取先列出的；
没有一组有夏普比率时不选。

扫描也可以改用滚动验证（`walk_forward`，与留出日二选一）：
各组先单独回放全部交易日；每一轮只读其训练段（至少 20 个交易日，以训练段前一日的结算权益为起点）选夏普比率最高的一组，
相同时取先列出的，都没有夏普比率时这一轮不跟随；每轮向后移验证天数，至多 100 轮。全部组成功后，服务另起一个子进程，
让一个账户在每一轮的验证段采用当轮选中那组的目标（所有组照常读每根 K 线；第一轮之前不持仓；换轮时按新选中组前一日收盘后的
目标调整），记录为“扫描编号-rolling”：`run.json` 的 `statistics.rolling` 记各轮各组的训练段夏普与选择，指标另有样本外
（第一轮验证起）的 `out_of_sample_`。有一组未成功时不做滚动验证。只支持用 `ctx.target` 的策略。

lab 停止时子进程随之结束（子进程每秒检查父进程）；下次启动把仍为“运行中”的记录标为中断，已完成的组保留，
未开始的不再开始，都不自动重跑。

## 运行记录

每次回测一份记录，位于 lab 数据目录：

```
runs/<运行>/run.json            策略仓库、标识、提交号与差异摘要、参数、数据来源与数据集版本、品种与区间、
                                引擎版本与依赖摘要、费用与风控参数；开始时写入，之后不改
runs/<运行>/<表>.parquet        equity、orders、fills、positions、settlements，成功时写入
runs.sqlite                     每次运行的状态（running、succeeded、failed、interrupted）、错误和指标
```

金额与价格为 `DECIMAL(19, 8)`，与 C++ `Decimal` 一致。依赖摘要是当前解释器已安装包名与版本列表的 SHA-256。
表结构见 `asterion_lab/runs.py`。

## 限制

- 回测与因子只读日线；分钟线只供查看。
- 采集任务只在内存中登记，服务重启后列表清空；已提交的数据保留，重新提交同一区间只补缺。
- lab 只在本机运行。
