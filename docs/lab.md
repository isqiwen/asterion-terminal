# Python 研究服务（lab）

`asterion_lab` 是本机的 Python 服务，代码在 `apps/services/lab/`，用随包 Python 以
`python3 -I -B -m asterion_lab` 运行，由 Terminal 启动和看护（见[本机服务](services.md#本机服务)）。它按计划逐步接管
历史数据与研究；现在负责期货数据仓库和可同时使用的数据源插件。旧的 Data 服务在过渡期间照常工作，两边互不读写。

## 数据源插件

插件由 `asterion_lab/sources/catalog.py` 统一登记，声明可提供的表、交易所及配置要求。
同一能力可有多个提供者：每次查询和采集必须指定 `provider`，不设全局排他的数据源，
不自动替换或混合来源。每个来源允许一个采集任务，不同来源可同时采集、独立取消。
任务开始时固定连接配置；修改配置只影响后续任务。

| 来源 | 能力 | 配置 |
| --- | --- | --- |
| `tushare` | 日线、交易日历、合约表 | 钥匙串中的凭据和请求额度 |
| `akshare` | 六家交易所日线 | 无；可用性取决于交易所网站 |
| `recorder` | 已录分钟线及观测区间 | 录制服务的主机与 TCP 端口 |
| `shfe`、`ine`、`czce` | 对应交易所按日发布的保证金、手续费参数 | 无 |

交易所参数不是期货公司账户保证金。未接入的交易所专项数据不声称支持，网站缺失或拒绝
访问明确报错，不用其他来源补齐。AKShare 未核实各交易所成交额单位，`amount` 留空；
无成交价格留空。录制分钟线保留 `partial` 和观测区间，区间属于录制服务整体，
不是单合约完整性的证明。未知覆盖范围不表示完整，也不推断交易日历。

Tushare 数据仍位于原来的 `warehouse/`，其他来源分别在 `sources/<provider>/warehouse/`。
新数据集清单包含来源。已有文件与版本不迁移；同一天不同来源的数据不覆盖。
重新采集需明确选择 `refresh`，产生新版本，旧版本仍可复现。研究数据选择应固定来源和
数据集版本；不同来源的同类数据对比不改变原数据。

Terminal 数据覆盖页可切换来源、选择能力与交易所、查看该来源的任务和仓库，按开始日期
直接查询来源并预览前 50 行（日历返回该年，合约表返回当前目录）。日线与结算参数按交易所采集，分钟线必须指定标准合约
（例如 `SHFE/rb/2027-01`）。Tushare 凭据和录制主机地址都在“设置 → 数据源”保存在 Terminal（凭据在系统
钥匙串，地址在 `terminal/data/recorder.json`），每次使用该来源前由原生层的 `lab.source.configure` 交给 lab，
lab 只保留在内存里；数据覆盖页不再单独填写地址。

## 协议

请求与回复是 `protocol/proto/asterion/lab.proto` 中的 `Request` / `Response`，经本机 Unix socket 以
4 字节大端长度分帧，每个请求带 `service_id` 和 `correlation_id`。

| 请求 | 作用 |
| --- | --- |
| `health` | 实例、版本、运行时长，以及内存中持有凭据的数据源 |
| `configure_source` | Tushare 只由 Terminal 原生层发送（命令 `lab.source.configure`）：从钥匙串读出已保存的 Tushare 凭据和每分钟请求上限交给服务。凭据只留在服务内存，不经过界面，服务重启后需再次发送 |
| `sources` / `source_read` / `source_coverage` | 数据源能力目录、统一单日查询、来源已知覆盖范围；查询返回来源与统一列、空值及录制观测区间 |
| `acquire` | 指定 `provider`、`table`（日线、分钟线或结算参数）；Tushare 日线同时采集 `[begin_day, end_day]` 内各交易所的日历、合约表和日线；可只选部分交易所，`refresh` 为重新读取已入库的日子（映射规则修改后用），新版本替换这些日子的行，旧版本保留原样 |
| `tasks` / `cancel` | 采集任务的进度与取消 |
| `summary` | 指定来源的当前数据集版本及各表行数、分区数和日期范围 |
| `coverage` | 指定来源每个品种每个月有日线的天数和交易所开市天数 |
| `daily_bars` | 一个合约在一段日期内的日线，数值为精确小数文本 |
| `dominant` | 一个品种在一段日期内的主力连续：每天的主力合约、所选复权方式下的价格，以及换月记录 |
| `sessions` | 一个品种在一段日期内每个交易日的日盘与夜盘时段，以及所依据的交易所文件 |
| `cross_check` | 用第二来源核对：`settlement` 为交易所结算参数对 Tushare，`daily` 为 AKShare 日线对仓库；只报告，不存储 |

界面用生成的 TS 类型直接请求服务，由 Electron 主进程（开发浏览器中是开发服务端）转发字节，
见[架构](architecture.md#terminal)。数据工作台的“数据覆盖”页显示当前数据集版本、各表汇总、采集任务
和品种 × 月份的日线覆盖；Tushare 开始采集前经 `lab.source.configure` 交出已保存的凭据。

## 数据仓库

位于 lab 实例的数据目录 `<根>/lab/data/lab/` 下的 `warehouse/`（[安装目录](architecture.md#安装目录)）：

```
warehouse/files/<表>/<交易所>/<分区>-<摘要>.parquet
warehouse/versions/<版本>.json
warehouse/current
```

| 表 | 分区 | 内容 |
| --- | --- | --- |
| `daily` | Tushare 为交易所 × 月；AKShare 为交易所 × 日 | 每个合约每个交易日一行：开高低收、结算、前收、前结算、成交量、成交额（元）、持仓及变化、交割结算价 |
| `calendar` | 交易所 × 年 | 每个自然日是否开市、前一交易日 |
| `contracts` | 交易所 | 带交割月份的合约：合约标识 `交易所/品种/YYYY-MM`、上市与退市日、乘数、单位、报价与交割说明、交易时间说明 |
| `minutes` | 交易所 × 日 × 合约 | 录制分钟线，保留不完整标记 |
| `settlement` | 交易所 × 日 | 当日发布的交易所保证金及手续费参数 |
| `observations` | 交易所 × 日 × 合约查询 | 该次查询附带的录制服务整体观测区间，不代表合约覆盖 |

- 分区文件写入后不再改动，文件名带内容的 SHA-256 前缀；写入经临时文件、落盘、改名发布。
- 数据集版本是全部分区文件及其摘要的清单，版本号是清单本身的 SHA-256。`current` 指向最新版本。
  旧版本和它引用的文件保留，不改写、不删除。
- 数值以 `DECIMAL(28, 6)` 保存。直接 JSON 来源按十进制读取；AKShare 已解析成浮点的值按其十进制字符串接入，不能恢复上游已丢失的精度。超过 6 位小数的值让采集失败，
  不做舍入。
- 查询用 DuckDB 直接读取当前版本的文件。只有采集写入仓库，而且只通过提交新版本写入。

## 采集

同一时间只运行一个采集任务，在独立线程中执行：

1. 每个交易所每年的日历：没有存过的年份，以及当年，各请求一次。
2. 每个交易所的合约表各请求一次，按当天快照保存。
3. 区间内每个开市日、每个交易所请求一次日线，已入库的日子跳过。来源当天还没有数据的日子不算入库，
   下次再请求。每完成一个交易所的一个月就提交一个版本；任务失败、取消或服务停止时，已经读到的日子
   仍写入，只丢失尚未提交的部分。

没有日历的来源（AKShare、交易所结算参数、录制分钟线）逐个工作日请求，周末不请求。节假日由来源回答：
AKShare 和录制服务返回空，交易所对没有文件的日子返回 404，都记为空的日子、不算入库，下次再请求；
其他错误让任务失败。

请求经同一个每分钟额度发出，额度来自已保存的设置。规则与旧 Tushare 插件一致：

- 只保留带交割月份的合约代码；Tushare 自己的主力、连续代码和月均价合约不保存。
- 郑商所代码的年份只有一位，十年重复一次，Tushare 补的年代并不总对；对不上时按“字母加末三位、
  当天在市”找到所指合约。
- 当天没有连续竞价成交的合约，上期所、能源中心给空值，郑商所、大商所、广期所给 0；两者都存为空值。
  开盘、最高、最低都为空时收盘价也存为空：郑商所当天无成交的合约，交易所文件里收盘价为 0，
  Tushare 却填入了结算价（与交易所文件核对时发现）。
- 成交额按万元发布，存为元。
- 返回行数达到接口上限的答复可能不完整，整个任务失败，不存部分结果。
- Tushare 的拒绝分为凭据无效、无权限、达到频率上限和其他错误；错误与日志不含 token。

## 主力连续

规则与旧 Data 服务（`apps/services/data/dominant_plan.cpp`）一致，三部分分别声明：

- **换月依据**：当天有结算价的当月及以后合约中，前一交易日持仓量最大者；只向后换，不回到更早的月份。
- **换月时点**：次日生效，所以区间的第一天要读前一交易日（查询自动多读请求起始日之前 31 天）。
  用于交易的序列（`traded`）不能持有合约过最后一天，在合约最后一天就换给其他月份中持仓最大者，并要求
  旧合约在换月日及之后仍有 K 线；只读的序列没有这两条。
- **复权**：`none` 为原价；`ratio` 为比例后复权，最后一段保持原价，更早的每段乘以其后每次换月时
  “新合约 / 旧合约”在换月前一交易日的结算价之比。比例与系数为 8 位小数、四舍五入，与 C++ `Decimal` 相同。

任何一天没有可选的主力、换月前一天缺少两个合约的结算价，或交易序列的旧合约在换月日后没有 K 线时，
查询失败，不做推测。连续序列只用于信号，成交落在真实合约上。

## 交易时段

`asterion_lab/reference/trading_sessions.json` 是人工核对过的交易时段表，目前覆盖决定 D4 的首批 20 个品种
（上期所 ag au cu al zn ni sn rb ru、能源中心 sc、大商所 i jm p m y、郑商所 ma ta sa、广期所 lc、中金所 if）。

- 每条规则写明交易所文件（标题、链接、发布日期、所引原文）和生效日期，并标明依据：`start` 是文件宣布了
  从这天开始，`confirmed` 只是文件证明这天起在执行、更早的情况未知。没有规则覆盖的日子返回未知，不推测。
- 夜盘属于下一交易日，在前一交易日晚上进行；前一交易日之后、本交易日之前有工作日休市（法定节假日）时，
  当晚没有夜盘，双休日不影响。2020 年疫情期间暂停夜盘，只查到郑商所 2020-05-06 晚恢复的通知，
  2020-01-24 至 2020-05-05 的晚间一律为未知。
- 大商所官网拒绝程序读取，大商所规则所引原文来自搜索引擎索引，文件中已注明。
- 尚未查到出处的变化：螺纹钢夜盘由 01:00 改为 23:00 的日期、郑商所夜盘改为 23:00 的日期、原油与镍锡夜盘
  更早的文件、上期所与大商所日盘时段的早期文件。这些时段现在都返回未知。

## 来源核对

AKShare（锁定 1.19.1）只用于核对，不作为数据来源。2026-10-28 的核对结果：

- 结算参数：2026-10-19 至 10-23，上期所、能源中心、郑商所的保证金率与手续费与交易所文件一致。Tushare
  没有上期所和能源中心的平今手续费；郑商所手续费只给数字、不给按比例还是按手收取，两者都只能按原数比对。
  大商所、广期所、中金所没有可读取的官方结算参数文件。
- 日线：2025 年 11 月、2026 年 3 月、2026 年 8 月和 2026-10-19 至 10-23 共 68 个交易日，五家交易所的开高低收、
  结算、前结算、成交量、持仓逐值一致（修正上述收盘价规则并重新采集郑商所后）。AKShare 批量读取时偶尔漏掉
  广期所一个品种，单独重读即恢复；核对把它列为单边，而不是差异。大商所无法读取。

## 限制

- 只有日历、合约表、日线、主力连续和首批品种的交易时段；分钟线和录制尚未接入。
- 采集任务只在内存中登记，服务重启后列表清空；已提交的数据保留，重新提交同一区间只补缺。
- lab 只在本机运行。
