# 单次后续区间验证

本功能属于研究插件，复用日线回测、任务事务、参数校验和复现包，不修改核心调度或成交模型。它记录一次选定参数后的后续时间区间验证，不保证用户或插件此前从未接触过验证数据。

## 使用流程

1. 选择同时包含研究与后续验证日期的固定单合约日线版本，并确保所选不可变规则覆盖两个区间；先只在研究日期范围内开展参数实验。
2. 等待全部研究组合结束，或取消尚未完成的组合。选择一项成功运行，填写选择依据。
3. 在上方回测配置选择后续验证日期并核对该区间覆盖，重新确认研究假设。验证开始日期必须严格晚于研究结束日期，不允许重叠或倒序。
4. 点击“冻结选择并验证”。上方仅提供日期与覆盖设置；策略 ID/版本/完整工件摘要、参数、资金、手数、费用/保证金规则和滑点从所选研究运行复制，不接受另传参数。
5. 查看研究与验证的收益、回撤、费用和成交次数。验证成功后导出 ZIP，其中 `selection.json` 保存选择及边界，`research.json` 与 `validation.json` 可分别导入现有复现入口核验、重放。

每个实验仅允许一个不可变验证选择。重复相同请求返回同一任务；改选参数、日期或依据均拒绝，不覆盖已有记录。取消或失败也保留选择，不能重新挑选参数冒充原验证；单项运行仍可通过已有原输入重跑功能诊断。工作台共享研究运行的访问规则不因验证分组而改变。

## 预热与统计边界

研究与验证分别从相同配置的初始资金和空仓开始，不继承研究期仓位、现金盈亏或策略会话。验证只读取验证区间内的行情。

设策略需要 N 根收盘数据预热：验证区间前 N 根只更新策略状态，不成交，权益保持初始资金；第 N 根收盘的意图最早在第 N+1 根开盘执行。验证区间必须至少有 N+1 根有效日线。记录实际预热首末交易日与实际交易统计首末交易日，不用自然日推测交易日。

现有权益曲线保留预热的平坦段；收益、费用、回撤和成交来自后续交易，预热没有虚构成交。期末持仓仍按收盘估值，不强制平仓。研究与验证持续时间可能不同，不能把绝对收益直接当成同周期排名。

## 固定证据与接口

`GET/POST /research/experiments/{id}/validation` 查询或冻结选择。提交包含 `source_run`、`start/end`、完整覆盖设置及 `reason`，不接受策略/参数/规则替换字段。`POST .../validation/cancel` 取消未完成任务；`GET .../validation/export` 导出成功后的复现 ZIP。

新表 `research_validations` 由研究存储授权持有，唯一键为实验 ID，记录账户、时间、验证任务、选择内容、研究输入/结果摘要与实际验证边界，并保存整体校验和。选择与任务在一个事务中创建，失败全部回滚；账户与源实验归属校验在插件中完成。备份验证选择结构、校验和及实验/任务引用，不自动执行外部策略。

验证沿用当前数据可用性假设与领域边界：同一固定数据版本、同一合约、日线做多/空仓。它不是历史时点可得数据证明；不含滚动验证、自动择优、多合约或实盘能力。

## 固定实际合约身份（2026-09-20）

后续验证区间也必须重新核对覆盖并冻结其身份目录，即使选择探索模式。来源运行的报告不能直接用于另一个日期范围；验证仍须属于单个实际合约生命周期。
