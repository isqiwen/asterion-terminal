# 因子研究：成交序列动量

`asterion-factor` 已具备首条独立计算链路：读取类型化 `research.v1.FactorInput`，调用可信因子插件，计算评价标签与相关性，把输入和结果写入独立文件日志。已接入 Task Service、Agent 调度和 Terminal 因子页面。Agent 按任务类型启动短生命周期 Factor 进程，与 Backtest 共用每个研究服务最多两个工作进程的限制；不常驻空转。

## 职责与数据

- `core/include/asterion/domain/factor_port.hpp` 定义流式因子公开契约。因子只接收当前及过去的成交事件，返回无量纲研究特征；不是账本金額或下单意图。
- `plugins/tools/factor_analysis/` 提供动量工具插件与相关性算法。工具插件属于既定七类之一；计算因子不等于因子交易策略，后者应通过 StrategyPort 产生持仓意图。
- `apps/services/factor/` 装配插件、校验单合约期货输入、对齐未来标签、汇总结果并持久化。
- `protocol/proto/asterion/v1/factor.proto` 为类型化输入与输出。数据快照只包含实际合约及有序成交，不要求填写本金、保证金或手续费。

输入要求：实际月份期货合约、明确价格/数量步长和乘数、正价格、正且步长对齐的数量、非递减纳秒时间戳、最多 10000 笔成交。数据版本使用规范化合约及完整成交序列计算 SHA-256；窗口参数属于实验配置，不改变数据版本。版本错误、摘要错误、缺失字段、未知 Protobuf 字段和不合法数据均拒绝。

成交快照使用 protocol/data 的统一 TradeDataset 内容摘要。回测输入版本 4 与因子输入版本 4 使用相同算法；交易日是回测约束，不属于内容身份。数据发布另有 publication ID 绑定来源记录，二者不能混用。详见 [数据发布](data-publication.md)。

## 计算语义

在事件索引 `i`，回看窗口为 `N`、标签步长为 `H`：

- 因子：`price[i] / price[i-N] - 1`。
- 评价标签：`price[i+H] / price[i] - 1`。
- 前 `N` 笔为预热；末尾 `H` 笔无完整标签，不纳入评价。
- 全样本模式有效样本数为 `总笔数 - N - H`，要求至少 30 个有标签样本。该下限是输入约束，不代表统计显著。

窗口按**成交事件数**计，不是分钟、交易日或等间隔 bar。相同时间戳按输入顺序处理。输入中的隔夜间隔和停盘间隔不被自动切断；价格变化照实进入结果。只接受同一个实际合约，不自动处理连续合约拼接、换月或复权。

因子插件的公开输入没有未来标签。只有评价宿主在因子已生成后读取未来价格。结果逐项记录事件索引、当前时间、标签结束时间、因子和收益，便于复核对齐。

Pearson 相关性先缩放再中心化；Spearman 使用并列值的平均秩。任一序列零方差时相关性未定义，Protobuf optional 字段缺省、JSON 为 null，不伪造零值。原始价格使用 Decimal；比率和统计使用浮点数，仅作为研究统计，不进入权威交易账本。

当前支持**单合约全样本、时间顺序留出或固定窗口滚动验证**，不是横截面 IC，没有显著性检验或年化指标。重叠标签可能存在自相关，不按独立样本推断可靠性。已支持固定动量算法的显式回看窗口比较；尚未实现多算法因子搜索、因子组合或策略转换。

## 独立程序

```sh
asterion-factor --input /absolute/input.pb --directory /absolute/empty-result-directory
```

输入必须是最多 16 MiB 的普通 Protobuf 文件，结果目录必须预先存在且日志为空。成功后写入 `factor.result` 记录，包含不可变输入、算法版本、参数、逐条结果及相关性。拒绝覆盖已有结果；输入/目录符号链接拒绝。任务执行模式支持取消、进度、租约与显式重试；独立文件模式仍由调用者控制生命周期。

## 时间顺序留出评价

FactorInput / FactorResult 当前版本为 4，使用显式评价契约：`evaluation` 必须是 `{"mode":"full_sample"}`，或 `{"mode":"holdout","split_index":S}`。也支持下述 walk_forward 模式。Protobuf 用 oneof 表达，full_sample 必须为 true；缺失、非法模式、旧版本均拒绝，不推断默认模式、不迁移已有任务。数据身份仍使用统一 TradeDataset 摘要，不因窗口或分界改变；任务身份去重比较完整输入。

`S` 是留出段首个事件的零基索引，也是界面中填写的“前段成交笔数”。前段覆盖 `[0,S)`，留出段覆盖 `[S,count)`。要求分界两侧时间戳严格分离，不把同一时间戳内事件拆到两段。给定共同预热 N（单窗口为该窗口，多窗口为最大候选窗口）和标签步长 H：前段有效样本为 `[N,S-H)`，留出段为 `[S,count-H)`；每段至少 30 个有标签样本。前段的 H 个跨界标签从逐条样本与统计中剔除，并记录 purged_count。

因子仍按原始顺序仅消费历史价格；留出段因子可使用此前历史预热，不重置因子或抹去可用过去信息。只有评价宿主读取未来标签，前段任一保留标签均早于留出段起点。两段分别计算相关性，不提供混合的“样本外”汇总值。全样本模式只有一个 full_sample 分段。

当前动量不训练模型，前段不是虚构的训练过程。用户需在检查留出结果前固定参数；系统不保证用户未反复查看、调参或使用其他数据。同一留出段反复选参会失去独立评价意义，当前仅有固定动量窗口选参，没有锁定研究协议或自动统计推断，因此不将一次留出相关性称为策略盈利能力。

Task Service 重算完整确定性结果，拒绝篡改分段范围、统计、样本数或剔除数。结果与输入持久化，服务恢复后保留评价方式与分界，不由当前界面表单重新解释。

## 动量参数比较

输入以 `lookbacks` 数组代替单值 lookback，要求 1..32 个严格递增、不重复、1..10000 的整数。只指定一个窗口时为固定参数评价；多窗口只允许显式时间留出模式，不允许用全样本自动选参。窗口顺序不被自动排序，重复值不被静默去重；旧输入版本不兼容。

官方工具插件 `plugins/tools/factor_analysis/` 提供选择规则，应用负责执行和持久化，不把规则加入 Core。每个候选仅消费分界点之前的事件，所有候选从最大窗口预热后的同一事件索引开始评价，使用相同标签范围。选择前段 Spearman 绝对值最大的窗口；完全相同时选择较小窗口。相关性未定义的候选不参加选择，若全部未定义则任务明确失败；固定单窗口的未定义统计仍按 null 展示。

选定后才计算该窗口的完整分段结果。结果保留选中窗口、选择规则、共同预热数量，以及各候选的前段 Spearman 和样本数；不计算或展示未选候选的留出成绩。选中窗口的前段统计也使用相同共同预热范围，可直接核对候选成绩。符号保持原始值，按绝对值选择不自动生成反向策略或交易指令。

Task Service 的任务进度总量为 `候选数 × 前段事件数 + 全部事件数`（固定单窗口仍为全部事件数），有界且单调，候选计算过程中可取消。候选证据和选中参数与结果一起持久化，服务端完整重算验证，拒绝伪造选择结果。单次比较不等于完整因子挖掘平台，也不解决用户反复查看留出段后改参数导致的数据窥探问题。

## 固定窗口滚动验证

FactorInput / FactorResult 统一升级为版本 4，不读取或迁移版本 3 的持久任务。`evaluation={"mode":"walk_forward","training_events":T,"validation_events":V}` 明确使用固定长度训练窗口；这里的训练是前段选参，动量公式本身没有拟合权重。输入完整性和候选窗口约束保持不变。

第 k 轮（从 0 开始）训练 `[kV,kV+T)`，验证 `[kV+T,kV+T+V)`。必须有 2–16 轮，`(count-T)` 必须能被 V 整除，不静默丢弃尾段；各窗口边界不得切开相同时间戳。训练和验证分别至少有 30 个有标签样本。所有候选共享最大回看窗口 N，训练样本数为 T-N-H，验证样本数为 V-H。训练末尾 H 个跨界标签剔除，验证末尾 H 个缺少本轮完整标签的事件不评价。每轮因子只用本轮训练与其后验证数据；后续验证数据不能影响此前选参。前轮验证区间可以成为后轮已知历史的一部分，符合时间推进语义。

窗口规划策略归 `plugins/tools/factor_analysis/walk_forward.*`；应用编排每轮复用现有留出引擎和相同动量/选参工具。只记录验证段的逐条样本，索引对应原始完整输入；逐轮保留训练/验证区间、候选前段分数、选中窗口与两段统计。没有虚构全局选中参数，不拼接不同轮次相关系数；原始数据摘要与实验窗口参数分开保存。取消检查跨轮保留，进度按实际扫描工作量累积。Task Service 重算完整结果，篡改窗口、分数或样本拒绝提交，重启恢复逐轮证据。

Terminal 提供中英文滚动验证入口、训练/验证笔数和逐轮结果表；详细候选证据、原始实验配置及样本默认折叠。滚动验证仍不是交易收益，不包含交易成本、统计显著性、多算法搜索或研究者反复调参的偏差控制。

## 价格窗口与输入语义

工具插件中的 `PriceMomentum` 管理 1–10000 条正价格观测的有界窗口，使用既有精确 Decimal 差分收益计算；不拥有合约、成交数量或时钟，也不创建成交事件。现有 `MomentumFactor` 先执行合约、数量、时间和生命周期校验，再使用此窗口，重启清空历史。无效价格在窗口变更前拒绝。

这是为真实 K 线研究输入拆分计算与来源语义的第一步，当前已有成交因子立即复用，公式和持久化输入／结果版本不变。分钟／日线研究任务、来源摘要、Bar 时间语义及 Terminal 提交流程尚未实现，当前产品仍只接受成交事件因子输入。


日线样本构建 `daily_momentum_samples` 已在工具插件实现：输入为真实 HistoricalDailyBar 序列，按严格递增的供应商交易日期验证，动量为当前收盘价相对 lookback 条之前收盘价的收益，标签为 horizon 条之后收盘价相对当前的收益。窗口按已有观测条数，不填充缺失交易日期，不合成 UTC 成交时间。最多 10000 条，正收盘价，至少一条预热与尾部剔除后样本；统计评价所需样本下限由后续评价层规定。输出分别保存特征与标签交易日期，支持进度和取消，不返回取消后的部分结果。

当前仅完成内部算法及测试，尚未接入 Task Service 的持久化日线因子任务或 Terminal 提交页；不能据此宣称日线因子功能已交付。后续需要来源任务／摘要绑定、不可变输入、独立结果契约、统计评价与产品链路验收。


## 日线因子输入与评价引擎（接入进行中）

独立的 DailyFactorInput / DailyFactorResult v1 使用 DailyFactorDataset，绑定来源任务 ID、tushare.fut_daily 身份、供应商合约代码、已下载清单摘要与完整精确日线。内容版本覆盖这些来源字段及全部 OHLC／量额／持仓与可选结算字段，分析参数不进入数据版本。拒绝缺字段、非法数量、非正收盘价、乱序日期、图表 MACD 混入及内容摘要不一致。公共日线协议转换复用于行情分页，不复制 Bar 校验。

Factor 的 run_daily 已实现固定窗口的全样本和显式留出评价，每个有效分区至少 30 个样本；跨留出边界的标签剔除，特征仍使用当时可知的历史。结果保存供应商交易日期及标签日期、观测索引、Pearson／Spearman；常量相关性缺失，不填零。verify_daily_result 重算并比较完整结果。引擎标识为 asterion.factor.daily-close-momentum.v1，成交模型契约不变。

Task Service 的来源快照构造已实现：调用方传入从 Store 复制的已完成日线任务及结果，在同一个共享文件锁内读取并验证完整数据、清单摘要、请求范围、合约和行数，再复制精确日线到研究输入。此耗时步骤应在业务锁外执行，界面不能提交自报来源证据。快照不包含本机路径或凭据，构造后无需再次读取来源文件。

DailyFactorRequest 只包含来源任务 ID、窗口和评价参数。Task Service 已在锁内准备来源、锁外校验与构造快照、回锁后复核任务身份再持久化，并重新检查升级静默状态。DAILY_FACTOR 与成交因子是不同任务类型，使用同一 Factor 程序的显式 --daily-factor 工作模式；调度标记由 Task Service 产生，Node Agent 校验角色与模式后启动。独立文件模式不接受此标记，客户端不能提交完整日线输入冒充来源。

任务输入保存为独立 daily-factor.task 清单，结果重新计算校验后持久化；取消、重试、旧尝试令牌拒绝和服务重启恢复已验证。真实 Task Service／Factor 子进程测试验证了服务端提交、错误工作模式无法领取、正确模式完成以及结果重启恢复。

Terminal 原生桥接已支持 research.daily-factor.submit，严格接收来源任务 ID、窗口、标签跨度与评价边界；日线结果 JSON 转换核对版本、来源版本、完整样本序列、交易日／标签日、分区数量和范围，非有限数值或错误证据拒绝展示，缺失相关性保持 null。提交和 research.result 的服务 I/O 在全局操作锁外执行，返回时检查研究连接代次；连接已切换时拒绝发布旧结果，不自动重发。

Terminal 研究工作区已提供独立“日线因子”模式：选择当前研究服务中已完成的日线下载，设置固定窗口、未来观测跨度和全样本／时间留出评价，再通过任务系统执行。没有日线来源时显示空状态和历史下载入口；不从本机文件导入，不把日线送入成交事件回测。参数和来源草稿保留，失败提交保留请求 ID 供确认状态。

结果展示实际来源日期、输入／有效／剔除数量、分区 Pearson／Spearman，逐日特征和标签分页显示，每页 50 行；任务 ID、源清单摘要和内容版本位于详情。中英文 1440／800 像素布局与模式切换草稿验证通过。macOS Electron 使用明确隔离日线样例完成界面提交、真实 Agent 调度、113 个有效样本／1 个跨界剔除、分页及研究服务重启后的结果读取，见 build/native-daily-factor/native-daily-factor.png。真实 Tushare 账户权限和联网数据下载未在该 UI 测试中验证；分钟 K 线研究、日线回测、多窗口日线选参和日线滚动验证仍未实现。
