# Trading固定观察事实与Research交接

这是已批准统一数据通路在Trading上的实施合同。当前实现边界与验证以data-paths-implementation-2026-10-21.md为准；Trading源端、Terminal固定事实及Research账户观察审阅链路已经隔离验证；完整真实账本评估仍未实现。

## 事实与缺项

依据requirements/modules/live/accounts.md的REQ-LIV-ACC-01/02及modules/evaluation/README.md：Trading拥有柜台来源、账户执行记录和固定事实的发布；Research只读确切来源，不能改账本或发交易。现有journal.sqlite及archives保存命令意图和终态订单，不是完整资金/持仓/成交/资金流历史。当前BrokerSnapshot混合查询和推送；synchronized_ms只说明一轮查询完成，不证明原子切点。

固定对象必须保留稳定Trading Owner、账户与REAL/BROKER_SIMULATION环境、运行实例、连接代次、broker_sequence、取得时间、交易日、来源阶段、持仓已知成交核对状态，以及实际存在的资金/持仓/订单/成交。代次/序号仅定位运行观察，不充当稳定Owner；uint64以Protobuf传输、Terminal十进制字符串呈现。完整历史、结算依据、现金流、分项业务时刻、费用和估值覆盖缺项逐项明确，未知不是零。账户环境不能由柜台地址猜测。

不将LiveSnapshot原包直接发布：发布合同显式选择事实字段，排除密码、认证码、授权许可、服务连接配置和可执行控制请求。保留必要账户身份不等于导出凭据；外部报告的敏感标识范围仍由用户显式选择。

## 单一所有者与持久确认

复用已有账户状态所有者和AccountJournal串行写入机制，不建第二个任务进程或通用任务框架。固定观察是明确的只读业务取证，不发送柜台查询、重连、授权、撤单或委托。接纳时在账户状态所有者取得一次观察值；内容版本绑定规范Protobuf原件。操作ID重复只能返回原决定，不能重新冻结最新值。

操作接纳和发布的小型决定使用现有账户持久记录；有界原件放在所属Trading目录的不可变文件区。文件准备、持久发布和回执分开，先有原件并验证后才确认发布。恢复重放这些决定只恢复证据元数据，绝不重放交易。已接纳但原件丢失必须报告缺失，不能换成当前快照；发布/读取失败保留现场。原件上限与队列使用现有有界策略，不能用巨型观察填满控制通道或无限扩张账户内存。

读取已发布对象只返回精确Owner/id/version，不要求新增交易授权，不启动SDK连接。位置由既有Manager/Agent发现解析，业务载荷直连Trading。先实现同一业务节点，跨节点未具备直接传输时显式不支持；多个候选不随机选择。源离线不改Research已持有的固定输入。

## Research真实消费

先完成固定来源上下文审阅：Research持久固定原件及完整身份/版本，输出实际可证实范围、数量与缺项，不把现有回测核对算法冒称真实账户绩效。资金流、结算或估值不足时不得计算伪收益、默认无风险收益或填零。用户在Research可重复打开同一审阅结果；Trading后续变化和停止不改原件。真实绩效与结算核对算法按需求独立实现和验收。

正式输入/结果保留所属域及谱系，复用已有Research任务接纳、持久状态和产物管理机制。无删除能力前不提供Trading证据清理；以后新增删除必须先具备精确引用与并发裁决。备份需同时覆盖账户决定和文件原件并验证闭包，未接入拥有者适配器前不得称Trading完整备份。

## 可观察验收

1. 模拟来源真实Agent/Trading/Terminal链路：账户、环境、运行观察身份正确，超出JS安全整数仍精确，断线后核对状态不伪保持成功。
2. 固定操作同ID重试、来源后续变化、文件/决定阶段故障与重启不换原件；无秘密、授权恢复或任何新增SDK操作。
3. Research经发现直连取得确切对象，持久输入与结果；Trading停止后仍可打开；缺资金流/结算/估值明确证据不足。
4. 发布与读取的真实浏览器闭环、独立备份恢复和只读无副作用分别有证据；未验证边界不能由定向通过代称全系统通过。

不决定A02跨节点唯一实盘执行或A03监控失联处置，不调用真实柜台，不使用真实用户数据。正式Research完整结果物理删除保持待决。

## 当前实现及边界

Trading现有journal.sqlite/archives中的两条小型决定及永久身份索引分别确认ADMITTED/PUBLISHED；索引使用交易请求ID无法占用的内部键空间，不建立全部历史事实的进程内map。facts/staging/<id>.pb保存原件暂存，facts/objects/<version>.pb保存不可变Protobuf原件，facts/published/<id>.pb是账本发布后生成的可读回执。原件4MiB及集合4096项有界；原件不直接塞入单条64KiB的执行日志。I/O仍在既有账户串行writer，主循环只确认结果。文件失败保留原决定，不将普通证据缺失误标为交易日志损坏；日志真实失败仍遵守现有恢复边界。

显式重试依据账本确认的原版本恢复暂存/对象/可读回执，已丢失的已接纳原件不重新观察。直接读取只接受匹配已发布回执，不因对象文件存在而称成功；不启动账户、登录或恢复授权。来源状态、错误码、观察/查询/接纳/发布时间分开，资金币种当前缺少来源字段，明确列缺项而不猜CNY。

## Research账户观察审阅合同

新增ACCOUNT_REVIEW业务种类，复用现有Research任务账本、文件池、执行槽、取消/尝试令牌和持久结果；不新增服务、任务进程或调度框架。它是固定来源覆盖审阅，不是实盘绩效、结算对账或策略准入。成功完成计算与资料不足是不同维度：任务可SUCCEEDED，但业务结论明确EVIDENCE_INSUFFICIENT。

输入固定Research稳定Owner、Trading精确Object及已发布回执/完整原件、账户/环境与实际Research执行程序SHA。客户端只提交来源引用及范围，程序身份由Research确认，不能由客户端自报。经所属Agent只发现原Trading端点，载荷直接读取；先限同一业务节点，跨节点显式拒绝。无需Data服务或永久配对。重放已接纳的相同任务ID先比较原范围，不因源离线重新取数或替换版本。

输入采用现有input.pb和准备记录；外层摘要绑定所有者、来源回执/原件及程序身份。相同固定输入复用现有不可变输入机制。worker从Research已持久输入取值，不再次向Trading/Data重建；尝试、取消、发布及重启沿用当前状态机。缺失准备输入时只能显式恢复原精确版本，验证原摘要；失败保留现场，不换最新。已确认结果读取不执行新分析。

当前原生审阅只报告实际观察记录数量、资金是否存在、来源阶段、持仓已知成交核对、未确认意图及缺失依据。记录数不是去重后的历史成交量，不做跨合约求和、收益率、现金流修正、货币推断或风险建议。固定基础缺项包括完整柜台历史、资金流、结算依据、历史估值、分项时间和资金币种来源；源未就绪/恢复需求/未核对/未确认意图另列实际限制。原始记录不因报告摘要而删除。

程序原件按实际SHA在Research/programs内留存一次，使用已有持久文件机制，不把大程序或原件塞进小型任务事件。只执行当前已加载程序：固定程序身份不符时拒绝该次计算，不自动启动备份程序或升级安装。只读产物和冷备恢复仍能保留确切原件；既有任务缺失的旧程序身份不补造。

输入/结果新增account_review/account_review_result资源类型，程序为research_program；统一目录、精确谱系、独立冷备及恢复校验随可用链路同步。Trading当前不提供事实删除，Research记录确切来源并保留固定内容，不将它伪装成Data保留/解除确认；任何后续源删除能力必须先落实精确持有与并发裁决。正式Research结果物理删除继续暂停。

验收顺序：纯覆盖计算与输入/结果合同 → 原Store接纳/执行/取消/恢复 → Agent发现和直接取原件 → Native/UI提交、独立固定结果读取 → 资源/备份/恢复一致验证。至少证明提交后Trading停止仍可执行/重试/读取，ID或版本冲突不换源，资料不足不填零，已有回测/因子和Data任务合同保持。上述合同的实际交付和验证见下节；未验证部分保持明确缺口。

## Research账户观察审阅实际交付（组292—316）
