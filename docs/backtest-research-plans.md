# 固定研究计划与实际回测、人工结论

状态：组991—999已接通原计划→真实回测→独立人工结论与独立冷备；本条仍不代表完整时间验证计划、批次或模型能力。

## 依据与范围

[研究项目与可检验假设](requirements/modules/analysis/exploration.md) REQ-ANA-EDA-01要求项目组织实际实验与独立结论，失败与反例保留，事后解释不能冒充事前计划。[回测方案](requirements/modules/backtest/experiments.md) FR-BKT-EXP-01-01要求可追溯固定策略和输入，FR-BKT-EXP-01-03另有完整训练/验证计划要求。

现有ProjectDraft/HypothesisPlan/ProjectBinding、元数据journal、正式ProjectConclusion与冷备可复用；当前Store/Host/客户端只允许因子、样本和统计。本条只把既有固定研究意图真正接入新回测及正式结果判断，不把文字假设计划称为完整时间验证计划，也不实现模型/批次平台。

## 业务流程与权威

1. 保存问题、假设、机制、范围、数据需要、评价、支持/否定标准及限制，固定不可变HypothesisPlan；标准未完整时沿用探索性标记。
2. 在原回测数据/策略、资金、费用和必要风险流程中选择同Research固定计划。可与已核对逻辑包/交付共存，二者分别表达策略使用与研究意图；无计划的独立回测仍允许。
3. 实际接纳前核对Owner与精确计划，原Task/Execution/准备清单保存ProjectBinding。任务ID重放须比较计划，改计划新建实验；不得把已接纳任务的计划改成当前选项。
4. 固定项目任务列表包含真实回测的失败/取消/中断，计算成功只代表结果已产出。读取原正式结果时查看原计划，并由人单独选择支持、否定或证据不足和理由。
5. 人工结论固定backtest_result版本、输入身份、原执行程序、计划与追加修订链。结果之后才关联计划时保持retrospective，不能改写成事前计划；统计值不自动生成支持结论。
6. 原项目、计划、任务、包/草稿和结论各自生命周期保持，正式输入/结果不删除。冷备与独立恢复验证所有引用，不启动任务或恢复交易许可。

使用现有ResearchSubmit.research_plan、Task/TaskExecution.research_plan、ProjectRequest、TaskResult与资源Object，不新增独立Task/Storage服务、任务状态机或数据库。Manager/Agent仍只发现与管理进程；Data负责实际固定市场数据，不能被文字计划替代。远程未支持边界不在本条偷偷扩展。

## 验收矩阵

| 路径 | 必须验证 |
| --- | --- |
| 接纳 | 同域原计划和真实回测固定输入共同保存；错Owner/不存在/不同内容拒绝；缺模拟风险仍拒绝 |
| 幂等 | 原任务相同请求重放稳定；更改绑定计划不得复用任务ID；与固定逻辑包引用共存 |
| 发布/恢复 | 任务成功/失败/取消保持原计划，程序/数据谱系不变；准备中断恢复不能改原绑定 |
| 人工结论 | 必须读取实际成功发布原结果；同计划事前判断与事后关联可区分；追加更正不替换旧结论 |
| 客户端 | 项目进入回测草稿、原四步确认、正式结果原计划及独立人工判断；不自动运行或自动认定假设成立 |
| 冷备 | 移开合成原根独立恢复项目/原计划/实际任务/人工结论与Data依赖，缺引用拒绝，恢复不启动 |

全部测试使用隔离合成数据；白名单分组预检/审查，保留未提交改动，不提交推送部署、不用真实服务/供应商/模型/交易。正式物理删除及A02/A03待决，只暂停依赖路径。完成后按矩阵继续完整验证计划/批次与模型等核心业务，不以此称全项目已完成。
