# 模拟交易与风控

交易工作区分“模拟”和“实盘”两种会话，账户互不相通。模拟交易用数据源的历史 K 线回放；实盘通过 CTP 连接真实期货账户（见文末“实盘”）。

## 使用流程

1. 在“数据”完成历史下载。在“交易”的“历史数据集”中选择 K 线来源（分钟或日线下载）和同一合约的日线结算来源，可选交易日区间，并填写最小变动价位与合约乘数（已连接 CTP 合约目录时自动带入）。合约的交易所、代码、品种和交割月来自下载的统一标识。重复上述步骤可加入更多实际月份合约组成组合（最多 20 个，再次选择同一合约会替换它），组合内合约必须覆盖相同的交易日；模拟交易与策略合计最多 20000 根（研究回测可到 200000 根），超出时请缩小交易日区间。来源与规范化说明见 [历史数据](market-data.md)。
2. 在“交易”选择专用空目录，填写初始资金和三项风险限额，并为每个合约分别填写每手保证金与保证金率、开仓／平今／平昨的每手手续费与费率。这些参数都必须明确填写，没有隐藏默认值。保证金与手续费可按品种保存为“费率模板”（需注明来源和生效日期），之后一键填入；连接实盘账户后，也可以把券商对该账户实际收取的费率存为模板（见“实盘 → 账户费率”）；模板按生效日期追加版本，同一天不可覆盖。应用模板时固定整张版本表，会话创建后写入账本头部，不再随本机模板修改。未应用模板时，表单值作为明确的固定费率假设，从数据集首日一直适用。
3. 点“回放下一根”按时间顺序回放所有合约的 K 线（同一时刻按选择顺序），建立各合约的当前价格；选择委托合约后提交限价委托，继续回放查看成交、持仓和资金。
4. 每个交易日所有合约的最后一根 K 线回放后撤销剩余委托，点“日终结算”按各合约的数据源日线结算价一起结算，今仓转为昨仓，然后继续下一交易日。勾选“自动日终结算”后，每个交易日结束时由 Terminal 发出同样的结算命令，账本语义不变；结算失败不会自动重试，需要手动处理。
5. 关闭或退出后，选择原目录“恢复会话”，恢复委托、冻结、成交、账本和回放进度。

会话运行在独立的 `asterion-trading` 进程中，可部署在本机或远程 Linux。

## 账本语义

`core/domain/account`（`FuturesAccount`）：组合账户，一个资金账户下最多 20 个合约，单币种、整数手数。回测与模拟交易共用。

- 每个合约有自己的费用：保证金 = 手数 × 每手保证金 + 名义金额 × 保证金率；手续费同理，开仓、平今、平昨分别设置。各合约保证金相加，没有跨品种保证金优惠。名义金额 = 价格 × 手数 × 合约乘数，比例部分按分四舍五入。
- 平仓规则按交易所：上期所、能源中心需要明确平今／平昨；中金所先平今；大商所、郑商所、广期所先平昨；同一桶内先开先平。
- 权益 = 账面资金 + 各合约浮动盈亏；可用 = min(账面资金, 权益) − 持仓保证金 − 委托冻结。浮盈不增加开仓额度，一个合约的浮亏会减少所有合约的可用资金。
- 下单、撤单、成交、标记、结算都有强异常保证；成交 ID 唯一，重复回报幂等，冲突回报拒绝。

## 按交易日生效的费率

每个合约的 `cost_schedule` 必须有 1–512 个按日期递增的版本；每版记录生效日期、来源及八项保证金和手续费参数。选择不晚于当前交易日的最后一版，持续生效直到下一版；首个交易日没有适用版本则拒绝创建。日期按数据的交易日判断，不按本机时区或夜盘自然日判断。

上一交易日撤单并结算后，在下一交易日的第一个行情事件中同时更新全部合约的费用和持仓保证金，再进行行情处理。已发生的手续费和账面资金不重新计算。新保证金可能使可用资金为负；系统不自动强平或补足资金。会话快照同时返回当前费用与完整的固定版本表，恢复按原表重放。

券商查询得到的是当前账户费率，不是历史费率数据库。来源与日期需由使用者核实；没有实现按成交量分档、盘中调整、返佣或跨品种保证金优惠。旧版模板保留在原本机存储键中，需要核实后重新保存，不自动迁移。

## 撮合模型

`plugins/execution/paper`：

- 新委托只参与本合约之后的 K 线撮合，其他合约的 K 线不会使其成交。买入限价被最低价触及时以开盘价与限价中较低者成交；卖出限价被最高价触及时以较高者成交。收盘后标记权益。
- 同一根 K 线的 10% 成交量向下取整到数量步长，由按到达顺序的委托共享；不推断真实逐笔成交路径。
- 没有盘口、滑点、冲击成本、强平或自成交识别。这是估计模型，不代表真实可成交性。

## 交易前风控

`plugins/risk/order-limits`，通过 `RiskPort` 接入统一提交路径：

- 单笔委托数量上限；
- 每个合约的潜在总持仓上限（多空不抵消，在途开仓计入）；
- 整个账户的在途委托数上限。

超限时仍允许减仓。插件不可用、配置缺失或拒绝，都阻止提交。风险配置随会话持久化，恢复时按原配置重建插件；缺少配置的会话拒绝恢复。

## 策略授权

`asterion-strategy` 运行可信的 SMA 策略，每个合约独立计算均线，只输出该合约的目标持仓意图；账本、授权、风控、提交仍由交易服务负责。在“交易”中配置并授权后，策略宿主自动回放数据并把目标交给交易服务，可随时撤销授权。策略事件与意图持久化，重启时逐条重放核对。每个会话最多 20000 根 K 线。

## 持久化

每个会话一个专用目录，账本是其中的 `journal.sqlite`（`plugins/storage/sqlite`，WAL、完全同步、独占写入）。每条命令在事务提交并同步后才更新内存；提交失败时会话进入待恢复状态。日志最多 100000 条命令（另有一条头部），总正文上限 256 MiB；Bar 数与命令数分别计量，2 万根回放可容纳推进、策略目标、逐日结算和收尾命令。模拟日志引擎为 `asterion.paper-futures.v7`。日志引擎标识与当前程序不一致时拒绝恢复，不重算历史。

## 实盘

实盘会话由独立的 `asterion-trading --mode live` 进程运行（Agent 服务类型 `LIVE_TRADING`），通过 CTP 交易接口连接真实期货账户。账户状态（资金、持仓、委托、成交）以券商回报为准；会话负责券商之前的执行链。

**创建**：在“交易 → 实盘”选择专用空目录，填写交易前置地址、经纪商代码、投资者账号、AppID、三项风险限额和价格偏离上限，并从 CTP 合约目录中选择可交易合约（最多 20 个，需先在行情工作区加载目录）。合约的最小变动价位和合约乘数取自目录。目录头部记录这些信息和风控插件摘要，日志引擎为 `asterion.live-futures.v4`（格式 1，manifest 版本 2），恢复时拒绝其他标识。

**连接**：每次连接时输入交易密码和授权码。凭据只在交易服务进程内存中保存到连接结束，不写入目录、日志、快照或界面状态。连接后依次完成终端认证、登录、确认结算单、同步账户，状态变为“已就绪”。

**授权**：勾选确认账户后点“授权实盘交易”。授权绑定本次连接代次和当前交易日；包括 SDK 自动重连在内，断开、重启或交易日变化后均需要重新授权。下单在执行插件内再次核对连接代次，重连期间准备的委托不会转发到新连接。可随时撤销。

**账户费率**：账户就绪后点“查询账户费率”，向 CTP 查询每个可交易合约的保证金率（`ReqQryInstrumentMarginRate`）和手续费率（`ReqQryInstrumentCommissionRate`），即券商对本账户实际收取的费率。多空保证金不同时取较高者；手续费按合约或品种返回均可。券商未返回或查询失败的合约标为“券商未提供”，不影响交易会话。查询结果不写入交易记录，可按品种存为费率模板，来源记为“CTP 账户 经纪商/账号”，生效日期为当前交易日。

**每笔委托的检查顺序**：

1. 已授权、账户已就绪、交易日未变；
2. 合约在可交易列表中，手数和限价分别是数量步长和最小变动价位的整数倍；
3. 价格检查：向 CTP 查询该合约的当前行情（`ReqQryDepthMarketData`），限价必须在涨跌停范围内，且与参考价（最新价；当日尚无成交时为昨结算价）的偏离不超过价格偏离上限。查不到行情就拒绝。受 CTP 每秒一次的查询限制，每笔委托约多等 1 秒；
4. 风控插件（与模拟交易相同的订单限额）：总持仓取券商持仓，在途开仓取券商回报中未成交的开仓委托，再加上未确认委托；
5. 先把委托写入本机交易记录（`journal.sqlite`），成功后才发送给券商。

任一环节失败都不发送。

**断线与恢复**：交易命令断线后不重发。每次登录（包括 SDK 自动重连）都从柜台重新建立委托、成交、持仓与资金快照；旧缓存不能当作柜台确认。成交去重记录与交易所委托映射随重建清空，避免跨日编号复用混入昨日记录。断线后清除已查询费率，重新就绪后需再次查询，不能把昨日结果标作今日费率。重启后，交易记录里的委托编号只用于对上券商回报；当前交易日已记录、但券商同步后仍未报告的委托列为“未确认”。未确认委托不会重发，并继续计入在途委托额度，需要在券商端核实。同一请求编号重复提交时只确认、不再发送；授权请求的编号不能重复使用。

**限制**：只做限价单，没有条件单或撤改单；风控只有订单限额插件和价格检查。只在测试用 CTP SDK 替身上验证过，真实券商环境需要先用仿真账户（如 SimNow）核对。


仿真验收步骤与证据要求见 [券商仿真验收](acceptance/ctp-simulation.md)。
