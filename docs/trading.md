# 模拟交易与风控

实盘未开放。当前交易能力是用已发布的历史成交数据驱动的模拟交易，以及可信策略的授权运行。

## 使用流程

1. 在“数据 → 数据存档”选择一个已发布的成交数据集（单个实际月份合约，最多 10000 笔）。
2. 在“交易”选择专用空目录，填写初始资金、每手保证金与保证金率、开仓／平今／平昨的每手手续费与费率，以及三项风险限额。这些参数都必须明确填写，没有隐藏默认值。
3. 点“回放下一笔”建立当前价格，然后提交限价委托，继续回放查看成交、持仓和资金。
4. 回放结束且没有活动委托时，可以输入结算价手动结算。
5. 关闭或退出后，选择原目录“恢复会话”，恢复委托、冻结、成交、账本和回放进度。

会话运行在独立的 `asterion-trading` 进程中，可部署在本机或远程 Linux。

## 账本语义

`core/domain/account`（`FuturesAccount`）：单币种、单合约、整数手数。

- 保证金 = 手数 × 每手保证金 + 名义金额 × 保证金率；手续费同理，开仓、平今、平昨分别设置。名义金额 = 价格 × 手数 × 合约乘数，比例部分按分四舍五入。
- 平仓规则按交易所：上期所、能源中心需要明确平今／平昨；中金所先平今；大商所、郑商所、广期所先平昨；同一桶内先开先平。
- 权益 = 账面资金 + 浮动盈亏；可用 = min(账面资金, 权益) − 持仓保证金 − 委托冻结。浮盈不增加开仓额度。
- 下单、撤单、成交、标记、结算都有强异常保证；成交 ID 唯一，重复回报幂等，冲突回报拒绝。

## 撮合模型

`plugins/execution/paper`：

- 新委托只和之后的成交撮合。成交价穿过限价时以该笔价格成交；恰好等于限价时，先扣除下单时同价位的排队量。
- 同一笔成交的数量在委托间共享，不凭空增加流动性。
- 没有盘口、滑点、冲击成本、强平或自成交识别。这是估计模型，不代表真实可成交性。

## 交易前风控

`plugins/risk/order-limits`，通过 `RiskPort` 接入统一提交路径：

- 单笔委托数量上限；
- 单合约潜在总持仓上限（多空不抵消，在途开仓计入）；
- 在途委托数上限。

超限时仍允许减仓。插件不可用、配置缺失或拒绝，都阻止提交。风险配置随会话持久化，恢复时按原配置重建插件；缺少配置的会话拒绝恢复。

## 策略授权

`asterion-strategy` 运行可信的 SMA 策略，只输出目标持仓意图；账本、授权、风控、提交仍由交易服务负责。在“交易”中配置并授权后，策略宿主自动回放数据并把目标交给交易服务，可随时撤销授权。策略事件与意图持久化，重启时逐条重放核对。每个会话最多 10000 个事件。

## 持久化

每个会话一个目录，由 `plugins/storage/filesystem` 写有序日志：先写入并同步，再更新内存。日志引擎标识与当前程序不一致时拒绝恢复，不重算历史。
