# 交易与风控

> **设计与实现边界：** Terminal 发布小型代码包；Trading 从本机加载策略子进程，直接接收柜台行情、交付完整 K 线、现场预热并执行目标。独立发布包携带离线 Python 运行时，子进程有资源限制。策略委托与手动委托共用账户执行路径；真实柜台与正式部署尚待验收。见[目标架构](architecture.md#目标设计)与[开发计划](plan.md)。

交易只有一种：通过 CTP 连接期货公司柜台的账户（仿真环境如 SimNow，或实盘），见下文“CTP 交易”。没有本机模拟账户；在历史数据上验证策略见 [lab 的回测](lab.md#回测)。

回测与 CTP 交易共用同一个内置订单限额风控模块。回测另外使用下面的账本、费率和撮合规则来估计成交和资金；CTP 账户的资金、持仓和成交以柜台回报为准。

## 策略包与本机加载

策略仓库里用 `strategy.json` 明确列出要发布的代码，例如：

```json
{
  "name": "ma-cross",
  "version": "1",
  "entry": "strategies.ma_cross:MaCross",
  "runtime": "python3.12-numpy2.3.5",
  "files": ["strategies/ma_cross.py", "strategies/_rules.py"]
}
```

包最小为描述文件和一个入口文件；辅助模块按实际需要列入 `files`。只接受 1–64 个 Python 源文件、合计不超过 512 KiB，
不遍历或上传整个仓库，不包含账户、参数、行情或回测结果。路径必须在仓库内，拒绝符号链接和越界路径。
`entry` 为 `模块:类`，策略从共享模块 `asterion_strategy` 导入 `Strategy`，与研究使用同一套接口。
包不安装第三方依赖；当前支持 Python 3.12、NumPy 2.3.5，运行器使用 Protobuf 5.29.3。

Terminal 的交易页在选定账户下提供“准备策略包”：Lab 读取描述及指定文件而不导入代码，页面展示名称、版本、入口与文件列表；
“发布到此交易主机”经该账户的双向 TLS 连接上传。Trading 在后台工作线程检查并持久化，完整目录发布后才回复成功。
同名同版本再次发布明确冲突，不能覆盖；结果未知时先读取主机包列表，不自动重发。上传不会启动实例或授权交易。

包归该账户所有，存放在 `data/<账户>/strategies/packages/<名称>/<版本>/`，不读取 Terminal 的源仓库。
实例配置另外指定实例 ID、包名称与版本、实际合约（如 `SHFE/rb2610`）、周期（`1d` 或 `1m` 至 `60m`）和参数。
使用权重输出时还必须明确提供 `weight_budget` 的 `gross_units` 与 `net_units`，分别限制总绝对权重及净权重绝对值；单位为八位小数定点数（例如 `100000000` 表示 1）。预算非负，无默认值，属于实例配置，不放进策略代码包，也不代表账户授权或风险限额。
当前接口支持一个账户同时加载一个实例；另启或换包须先停止，构造期间也不接纳第二个实例。
Trading 的有界后台线程执行加载、停止和状态持久化，账户与网络状态线程不等待用户 Python 代码。

Trading 安装包包含独立 CPython 3.12.12、NumPy 2.3.5 与 Protobuf 5.29.3，解压到 `<安装目录>/runtime/python/`。
运行器从其中的 `bin/python3` 启动，从 `lib/strategy/` 加载共享接口、私有协议和运行器。
构建时按 Trading 自己的 `uv.lock` 安装锁定 wheel；运行时不包含 Lab、研究依赖、pip 或安装命令，安装与启动均不下载依赖。
缺失运行时明确报告路径，不借用系统 Python 或 Terminal/Lab。
构造成功为 `warming`，策略对象留在 Trading 的子进程里；`ready` 由策略明确报告，仍不代表授权或下单许可。
Terminal 关闭不结束子进程；显式停止或 Trading 退出会结束它，Linux 上也覆盖父进程被强制结束及策略构造卡住的情况。
策略退出记为 `failed`，不自动重启；Trading 重启把未结束实例记为 `interrupted`，保留包和配置，不恢复运行或授权。
Terminal 可从已发布版本配置实例，选择账户政策内的实际合约、周期，以及整数、小数、布尔或文本参数覆盖。整数保留完整 64 位精度，权重预算按八位小数精确传输；不导入策略代码来推断参数，也不自动补权重预算。启动前展示配置供核对，账户未同步或页面读取结果未知时不能启动；启动不授权交易。

页面每 3 秒只读主机状态，同一页面最多一个读取在途，离开页面只停止读取。显示所用配置、预热/就绪/停止/失败、已处理完整 K 线批次和最近目标；批次数不是预热百分比，目标也不是成交。读取失败保留并标记上次状态，不能据此判断服务已停止。账户和连接变化丢弃旧回复，早于启停结果的读取不能覆盖新状态。

“停止策略并撤单”须确认具体实例；请求携带实例 ID，Trading 在执行停止时核对当前实例，拒绝旧页面对其他实例的操作。停止按钮不受只读查询或包发布的等待阻塞；停止结束运行并尝试归属撤单，不平仓、不撤销账户授权。启动、停止或发布结果未知时不自动重发，先读取主机事实。暂停新增、独立平仓、完整执行监控及告警仍由 M3.3 后续工作完成。

Linux 在导入 NumPy 和策略代码前设置子进程硬上限：虚拟地址空间 1 GiB、打开文件描述符 64 个、单文件 16 MiB、禁止 core dump 和新增进程/线程。
数值库使用单线程，子进程 nice 值增加 10；构造仍由 Trading 限时 10 秒，每批输入限时 2 秒，不设置会终止长期正常策略的累计 CPU 时间上限。
超限、异常或超时使实例失败，不自动重启；账户持仓与授权保留，对该实例留下的未终结委托尝试一次撤单，回报确认前仍按实际风险处理。资源限制用于约束可信策略的错误，不构成不可信代码的安全沙箱；安装服务以非 root 用户运行。

### 实时输入、现场预热与目标记录

账户配置必须包含 `market_front`，指向该账户的 CTP 行情前置；行情连接使用该主机账户凭据与独立 SDK 线程。
它与中心 Market 无关，实例启动才订阅所选合约，结束后释放连接。策略与文件操作有独立的有界工作线程，
不会占用账户回报与健康 I/O 线程。登录超过 30 秒、订阅被拒、连接中断、队列丢失观测或时间倒退均结束实例，不自动续接旧窗口。

每次启动新建聚合窗口，不读取旧记录或历史数据；订阅返回的缓存观测若早于本次窗口启动时刻，直接排除。
分钟周期按 UTC 时间戳的固定 N 分钟边界分桶，第一桶一律跳过；后续行情进入下一桶时才确认上一桶完成。
日线按柜台 `TradingDay` 聚合，首次观察到的交易日跳过；完整交易日在下一交易日首条行情到达时交付，时间标签是该交易日北京时间零点。
因此收盘后没有后续行情时不会立即交付，日线可能延迟到下一交易日。休市或无成交时不填造 K 线，也不以本机计时器推断收盘。
多合约同一时间的 K 线一起交付，等待各合约观测越过该时间；待交付时间桶超过 128 个则结束实例。
首次订阅收到的过期闭市快照跳过；开始观察后，行情落后接收时刻超过 10 秒、超前主机时钟超过 2 秒或累计成交量异常回退均结束实例。

策略实现 `ready(ctx) -> bool`，每次 `on_bars` 后根据实际参数、历史长度与内部状态报告就绪；研究与交易共用这个接口。
未就绪时目标被丢弃，实例仍继续接收新完整 K 线；新实例从空窗口重新开始，账户继续保留原持仓和未确认委托。
Python 每批处理限时 2 秒，异常、超时或无效回复结束实例。就绪目标记录后交付账户；首个可执行目标到达时必须已授权，否则结束实例，不留存目标等待将来的授权。

`data/<账户>/strategies/runs/<实例 ID>.sqlite` 保存实例配置、实际交付的定点 K 线与每次回复的就绪状态、目标。
输入先提交再交付，回复提交后才更新公开状态；回复未知时保留没有结果的输入，不重发。
实例 ID 不可复用，重新运行使用新 ID；这样旧输入可独立回放，而不会混入下一次现场预热。

### 账户目标换算与订单规划

账户执行器调用 `apps/services/trading/strategy_orders.*` 的纯计算规划，复用回测的开平换算与 `core` 权重换手数实现。

- 权重以明确提供的账户权益、价格和合约乘数换算，支持 1–20 个合约，正数做多、负数做空，向零取整数手。总权重和净权重不得超出显式预算，余数保留为未分配金额；不缩放权重，不使用浮点金额，不隐式舍入或截断溢出。
- 手数目标只修改列出的合约；零表示平仓，省略表示不改变。`ctx.weights` 会为省略的已选合约补零，`ctx.target` 不会。合约必须在账户政策中，数量必须符合手数步长。
- 使用账户已同步的实际今昨仓，分别处理多头与空头；双向持仓不能以净额相抵掩盖风险。上期所和能源中心先平昨、再平今，其余交易所使用普通平仓，由柜台分配今昨仓。
- 一个目标批次先完成所有合约的减仓，再从新的已核对持仓规划开仓。反手期间只平原方向；部分成交按实际剩余持仓处理，不把在途数量当成已成交。
- 账户未就绪、持仓未核对，或任何合约存在在途/未确认委托时，不生成新计划。已撤销、拒绝或成交完毕的委托，仅在账户持仓同步且未知风险已解除后才不再阻塞规划。

规划层不查询行情、不预留风险、不决定委托价，也不授予发送许可。运行器向账户交付目标和本实例直接行情连接上的报价；账户执行器负责固定输入、逐笔调用规划及原有发送路径。

### 执行输入与批次推进

- 批次在调用 Python 前固定最长 10 秒的原始截止时间，行情已有年龄进一步缩短时限。排队、Python 计算、资金查询、落盘、SDK 调用和等待成交都不延长它。时限内未完成整批目标则结束实例并尝试归属撤单；新 K 线不能覆盖尚未完成的批次。
- 每个目标固定同一份直接行情：必须属于当前交易日，时间有效，最新价为正。买入用卖一、卖出用买一，所用档位必须有正价格和正数量；无档位则失败，不改用收盘价或自动追价。原有价格步长、涨跌停及偏离检查仍执行。
- 权重目标包含全部已选合约。账户主动请求资金与持仓刷新，等接纳目标之后的新资金回报及持仓核对完成，再使用 CTP `Balance`、固定最新价和政策中的合约乘数换算一次。`Balance` 已含持仓盈亏，不重复累加；后续资金变化和成交不重新放大该批次目标。
- 每次只发送一个规划分支，等该委托完全成交且持仓核对后，从当前实际持仓重新规划。全部减仓先于开仓；在途、部分成交和未知委托只等待，不视为已完成。分支撤销或拒绝会结束实例，不重新创建余量委托。
- 目标数量超过订单限额时明确失败，不自动拆单、缩量或重试。停止、撤权及账户/行情故障沿用下文处置；账户线程独立观察批次到期，运行器无需阻塞等待资金、落盘或 SDK。

### 账户侧策略委托入口

`StrategyHost` 通过 `LiveSession` 的内部 C++ 入口交付目标及直接行情；账户把规划后的委托交给原有 `submit` 路径。没有新增 Python 下单接口或远程委托接口。

- 账户完成同步后可以登记一个策略执行身份及所选合约；登记不授予交易授权。身份只在当前进程内有效，由账户签发。同名实例重新登记也不能使用原身份，Trading 重启不恢复身份或授权。
- 身份持有期间拒绝手动新增委托，撤单和撤权仍可用。登记还会阻止先前已接纳、仍在等行情或落盘的手动委托发送。运行器启动前即登记身份；账户尚未初始化、未同步或合约不在政策内时拒绝启动，发布策略包不受此限制。
- 每笔内部委托携带就绪标记、目标序号、从零开始的订单分支号和固定的单调时钟截止时间。所选合约必须属于账户政策；同一目标的分支按序接纳且共享原截止时间。重号、倒序、跳号或延长同一目标的时限均拒绝。
- 接纳时最多还有 10 秒有效期；等待队列、行情查询、持久提交与 SDK 排队不刷新它。实际发送期限取目标与柜台报价期限中的较早者。授权、价格与单位、内置限额、先记录后发送及一次性发送许可沿用原路径。
- 一个分支在开始异步处理前即被消费，失败或结果不明不能重新使用。执行失败阻止该身份继续提交，须先释放，再从新实例重新预热；账户启动归属撤单，不改变实际持仓。
- 释放身份在入口关闭尚未消费的发送许可，账户线程随后安排归属撤单并解除执行身份；落盘后发现失效的委托写入“明确未发送”记录再释放风险。已进入 SDK 的调用仍等待真实结果，不能解释为未发送或撤单成功。

委托记录与原命令同次提交 `strategy` 归属字段：实例 ID、目标序号、订单分支号。恢复读取这些归属和柜台事实，不恢复策略执行身份、不重放委托。
权重委托还保存该批次的权益、权重、换算价格和整数目标，便于按原输入复核换算，不另建订单账本。隔离验证不代表真实柜台验收完成。

### 策略停止与故障处置

运行器登记账户身份后，手动新增委托被拒绝，但授权、撤权和撤单仍可用。账户连接变化、撤权、策略委托被柜台拒绝或内部执行失败时，账户先关闭该身份的发送许可；运行器读取失败状态后结束子进程。Python 退出、处理异常或直接行情失败则由运行器释放身份，触发同一账户清理路径。Terminal 关闭不触发这些操作。

- 账户从原有委托记录保留实例归属，不另建策略订单账本。停止或故障只选该实例尚未终结的委托；手动委托和其他实例遗留风险不属于此次清理。
- 每笔选中委托至多自动尝试一次撤单，复用先持久记录、再调用 SDK 的撤单路径。先前已有撤单请求的委托不会再次自动撤单；需要再次尝试时由用户核对后显式操作。
- 行情查询等待期间，故障撤单可先执行，不被等待中的新增委托挡住。账户为单一运行器保留一个状态/释放请求槽，客户端请求排满不能遮蔽故障或阻止释放。
- 断线、撤单失败或 SDK 结果未知不解除风险，也不在重连或重启后重发。不能完成持久记录时不发出无记录的撤单；保留原委托，账户报告需要恢复。已有持仓不因实例结束而清零。
- 撤单成功仅由柜台终态回报确认；已进入 SDK 的报单仍接收迟到结果，随后按实际状态清理。策略的新授权、新实例或新连接均不能放行旧目标。
- 有序停止 Trading 时先封住发送、结束子进程并排空账户清理，再释放 SDK。进程被强杀或退出期限耗尽不能保证撤单，重启只核对柜台事实，不恢复身份、授权或取消请求。

## 交易实例与部署位置

交易主机是 Linux，一套程序装在 `/opt/asterion/trading/`，每个账户一个独立进程，
由 `asterion-trading@<账户>.service` 管理。`bin/`、`lib/` 与 `runtime/` 共用；每个实例使用自己的
`config/accounts/<账户>.json`、监听端口和 `data/<账户>/` 交易记录。
`config/logging.json` 控制日志；默认文件名为 `logs/asterion_trading-<实例>_YYYY-MM-DD.log`，
按日切分、保留 30 天，同一天重启继续追加，不按 PID 分文件。已有安装的日志配置需显式修改，升级不覆盖。
`config/tls/` 保存主机证书与私钥，账户配置指定允许连接的 Terminal 指纹。

安装脚本 `apps/services/trading/scripts/setup.sh` 提供以下操作。安装后的入口是
`sudo /opt/asterion/trading/bin/setup.sh`：

- 进入菜单即列出账户、监听地址与端口、systemd 运行状态、开机启动状态和待重启时间；选“刷新账户状态”可重新读取。
- 新增或修改账户，端口默认取未被其他账户配置占用的第一个端口；手动指定冲突端口会被拒绝。
- 停止并禁用指定实例时，先取消该实例的待重启任务，配置与交易记录保留。重新启用可通过“新增或修改账户”选择原实例。
- 程序升级须先在主机显式停止全部账户；安装器不替用户停止或启动交易。账户进程持有 `.program.lock` 共享锁，安装器取得排他锁后才替换程序与运行时，升级期间也不能启动账户。
- 安装器先在临时目录检验程序和依赖可运行，再整体替换 `bin/`、`lib/`、`runtime/`，保留配置、凭据、策略包、实例及交易记录，取消账户的待重启定时器。中断或失败保留 `.program-incomplete`，账户拒绝启动，须重新运行发布包完成安装。成功后显式启动账户、核对状态并重新授权，不恢复旧策略实例。
- 仅修改账户配置时，运行实例在北京时间工作日
  08:45–15:30、20:45–次日 02:45 内延迟到窗口结束重启；每个账户使用独立的
  `asterion-trading-restart-<账户>.timer`，修改其他账户不会覆盖它。停止的实例在明确配置启用后立即启动。
- systemd 负责开机启动和进程异常退出后的拉起，脚本不另存运行状态或增加守护进程。

定时器是 systemd 的临时任务；主机重启后，由各实例的开机启动设置决定是否启动。
启动、自动拉起和程序升级都不恢复交易授权。CTP 密码和授权码在交易主机运行安装脚本时隐藏输入，不进入配置文件或 Terminal。
每个实例分别加密存入 `/etc/credstore.encrypted/asterion-trading-<实例>/password` 与 `auth_code`，
systemd 通过 `LoadCredentialEncrypted` 解密提供给该进程；服务缺少凭据时拒绝启动。
首次配置风险政策后，以及已有交易记录的服务重启后，自动登录柜台但不恢复交易授权。
修改凭据需在主机重新运行配置脚本，服务按脚本的重启安排生效。
柜台环境 `real`／`simulation` 固定在交易记录中；标签不能代替对期货公司前置地址的核对。

交易实例的 `config/accounts/<实例>.json` 同时定义监听信息、证书白名单、CTP 账户与柜台环境，例如：

```json
{
  "bind": "0.0.0.0",
  "port": 7460,
  "terminals": ["客户端证书的64位SHA-256指纹"],
  "environment": "simulation",
  "market_front": "tcp://行情前置主机:端口",
  "broker": {
    "front": "tcp://交易前置主机:端口",
    "broker_id": "经纪商代码",
    "user_id": "投资者账号",
    "app_id": "CTP应用标识"
  }
}
```

示例中的占位值必须替换。环境只能是 `real` 或 `simulation`；密码和授权码不属于配置。
安装脚本采集这些参数，修改时显示当前值。有交易记录的实例不能更换账户或柜台环境：
脚本拒绝覆盖，直接编辑文件后服务也会对照原记录拒绝启动，并报告配置文件路径；不会改写或迁移账本。

Terminal 在“设置 → 交易连接”生成客户端证书并显示 SHA-256 指纹。
证书与私钥保存在 `terminal/data/tls/client.crt`、`client.key`，私钥不进入界面快照。
将客户端指纹写入交易实例配置的 `terminals`，再在 Terminal 添加连接名称、主机地址、端口、实例名和服务端指纹。
连接配置保存在 `terminal/data/trading-connections/`，不重复保存服务端的 CTP 账户参数。

一个交易连接对应一个账户实例。连接采用双向固定指纹 TLS，连接后读取服务端配置并显示账号、前置与环境，
即使尚未配置风控也能看到这些信息。Terminal 开通请求只设置合约范围和风险限额，不能指定或覆盖账户身份。
交易页面只列出交易服务连接；“设置 → 数据源”选择远程 Market。Trading 的执行行情由本账户主机的 `market_front` 接入，不使用桌面的 Market 连接。

启动 Terminal 只重新连接已登记的交易服务，不启动服务、不登录柜台、不恢复授权。
连接详情直接显示服务自己的健康与线程进展。编辑或删除连接前需先断开；删除连接不停止交易进程、不删除主机上的记录。
Terminal 不部署、升级、启动或备份交易实例，桌面安装包不携带交易程序。

真实柜台验收脚本 `tests/acceptance/ctp_trading.py` 使用 `--terminal-directory` 指定已配置证书的 Terminal 安装目录，
`--trading-connection` 指定保存的连接 ID。脚本读取服务端账户并核对明确指定的仿真柜台，交易凭据须事先由交易主机脚本配置；验收脚本通过 Market 读取独立行情和合约目录，不采集柜台凭据。

## 执行所有权

每个账户的交易服务独立拥有授权、执行许可、风险占用和本地账本投影。UI/Native 提交意图，策略给出目标，内置风控返回明确裁决；最终发送必须经过账户服务的统一执行链。Python 策略没有订单接口；内置风控与发送许可由 C++ 账户拥有。

柜台是实际成交、资金和持仓事实来源；重启进程、关闭窗口或停止服务 均不能视为撤单成功。实盘与回测共享适用的策略和风险语义，分别使用柜台执行与历史撮合模型。整体边界见[架构](architecture.md)。

## 账本语义

`core/include/asterion/futures/account.hpp`（`FuturesAccount`）：回测使用的组合账户，一个资金账户下最多 256 个合约，单币种、整数手数。委托价和成交价必须在最小变动价位上；逐日结算用的结算价不必（现金交割合约最后交易日的结算价是一段时间的平均价）。组合同时交易的成员最多 20 个，一条主力连续算一个成员，它的每个月份各是账户里的一个合约。

- 每个合约有自己的费用：保证金 = 手数 × 每手保证金 + 名义金额 × 保证金率；手续费同理，开仓、平今、平昨分别设置。各合约保证金相加，没有跨品种保证金优惠。名义金额 = 价格 × 手数 × 合约乘数，比例部分按分四舍五入。
- 平仓规则按交易所：上期所、能源中心需要明确平今／平昨；中金所先平今；大商所、郑商所、广期所先平昨；同一桶内先开先平。
- 权益 = 账面资金 + 各合约浮动盈亏；可用 = min(账面资金, 权益) − 持仓保证金 − 委托冻结。浮盈不增加开仓额度，一个合约的浮亏会减少所有合约的可用资金。
- 下单、撤单、成交、标记、结算都有强异常保证；成交 ID 唯一，重复回报幂等，冲突回报拒绝。

## 按交易日生效的费率

每个合约的 `cost_schedule` 必须有 1–512 个按日期递增的版本；每版记录生效日期、来源及八项保证金和手续费参数。选择不晚于当前交易日的最后一版，持续生效直到下一版；首个交易日没有适用版本则拒绝创建。日期按数据的交易日判断，不按本机时区或夜盘自然日判断。

上一交易日撤单并结算后，在下一交易日的第一个行情事件中同时更新全部合约的费用和持仓保证金，再进行行情处理。回测里组合当天一根 K 线也没有的交易日（见 [lab 的回测](lab.md#回测)）没有行情事件，费用在当天结算之前更新：费用跟交易日走，不跟 K 线走。已发生的手续费和账面资金不重新计算。新保证金可能使可用资金为负；系统不自动强平或补足资金。回测结果同时返回当前费用与完整的固定版本表。

券商查询得到的是当前账户费率，不是历史费率数据库。来源与日期需由使用者核实；没有实现按成交量分档、盘中调整、返佣或跨品种保证金优惠。

## 回测撮合模型

`core/src/futures/paper_execution.cpp`（回放日程 `replay_schedule.cpp`，权重换手数 `portfolio_targets.cpp`）：

- 新委托只参与本合约之后的 K 线撮合，其他合约的 K 线不会使其成交。买入限价被最低价触及时以开盘价与限价中较低者成交；卖出限价被最高价触及时以较高者成交。收盘后标记权益。
- 同一根 K 线的 10% 成交量向下取整到数量步长，由按到达顺序的委托共享；不推断真实逐笔成交路径。
- **滑点**：每个合约可以设“滑点 N 跳”（0–100）。每笔成交都让出 N 个当天的最小变动价位——买入按上面规则得到的价格加 N 跳成交，卖出减 N 跳；**能否成交不变**，仍然要等 K 线触及决定时的价格。委托记录里的限价是它愿意接受的最差价格（决定价 ± N 跳），成交价不会比它更差。让出的价差直接进入成交价，因此已实现盈亏、权益和按笔统计都包含它，不另记一项费用。N 跳不小于合约出现过的最低价时拒绝。
- **最小变动价位按交易日。** 数据集记着合约的最小变动价位在哪些交易日改过（lab 按交易日从竞价价格推出，见 [lab 的回测](lab.md#回测)）。每个交易日的第一根 K 线（没有 K 线的交易日是它的结算）带来当天的最小变动价位：委托价、成交价和标记价都在它上面，滑点按它计。前一交易日决定的价格不在新的最小变动价位上时，向不利于委托的方向取到它上面（买入向上、卖出向下），只在改动那天会发生。
- **涨跌停没有建模。** 回测不知道某个交易日的涨停价和跌停价：历史数据里只有昨结算价，没有涨跌停价，也没有各品种的涨跌停幅度。封涨停时买不到、封跌停时卖不掉，回测却会照常在那个价格成交买单或卖单，所以封板的那几天结果偏乐观，尤其是该平仓而平不掉的时候。这样的日子对成交活跃的品种不多，但影响往往最大。
- 滑点是固定的假设，不随波动、成交量或委托大小变化；没有盘口、排队、冲击成本、强平或自成交识别。价格“触及”决定价就算成交，等于假设排在队首。这是估计模型，不代表真实可成交性。

### 回测目标持仓到委托

策略只给出一个合约的目标持仓：正数是多单手数，负数是空单手数，0 是空仓。回测撮合用 `core/src/futures/position_target.cpp` 把目标换成委托：

- 目标与当前持仓同向：差额部分开仓或平仓（做多为买开/卖平，做空为卖开/买平）。
- 目标与当前持仓反向：这一步只平掉现有持仓，不开仓；平仓成交之后，下一次给出目标时才开对侧。因此一个合约不会同时持有多单和空单，反手至少需要两根 K 线。
- 平仓按交易所规则：上期所、能源中心分别报平昨和平今，先平昨；其它交易所报平仓，由交易所分配。分开报的两笔委托编号以 `.yesterday`、`.today` 结尾。
- 目标手数必须是数量步长的整数倍；合约若已同时持有两个方向（只可能来自手动下单），不接受目标。

开空与开多一样占用保证金、收开仓费，经过同样的风控检查；限价为产生目标的那根 K 线的收盘价。唯一的例外是主力连续的换月：搬动持仓的两笔委托挂在所在 K 线的开盘价，每根 K 线都会触及，见[回测引擎](lab.md#回测引擎)（主力连续与换月)。

## 交易前风控

领域层的订单限额（`core/include/asterion/futures/order_limits.hpp`），通过 `RiskPort` 接入统一提交路径：

- 单笔委托数量上限；
- 每个合约的潜在总持仓上限（多空不抵消，在途开仓计入）；
- 整个账户的在途委托数上限。

总持仓超限时仍允许符合单笔及在途委托限制的减仓。风险配置缺失、无效或规则拒绝都阻止提交。参数随 CTP 政策和回测运行保存，恢复读取有效参数，使用程序编译的规则；不保存或加载风控插件、算法摘要和副本。

## CTP 交易

每个 CTP 交易账户由一个独立的 `asterion_trading` 进程运行（由 systemd 管理的独立实例），通过 CTP 交易接口连接期货公司柜台。账户状态（资金、持仓、委托、成交）以券商回报为准；账户服务拥有券商之前的执行链。

**账户与开通**：“交易”页左侧列出设置里的全部 CTP 账户，右侧是所选账户的面板。可以同时打开多个账户，每个账户有自己的交易服务、交易记录、连接和授权，互不影响；切换左侧选中项只改变显示，不会断开其他账户。每个 CTP 账户对应一份活动交易记录：第一次使用时“开通交易”，填写三项风险限额和价格偏离上限，并从 CTP 合约目录中选择可交易合约（最多 20 个，可在当前表单读取目录）。记录保存在该账户的独立目录中，柜台信息和初始政策写入记录头部，后续政策变更追加独立事件；账户的经纪商代码、投资者账号、AppID 和交易前置也随之固定。日志只维护当前头部、账户清单与 SQLite 结构，恢复校验结构、账户身份、风险参数与政策修订，不积累格式或引擎版本号。每条交易命令都带账户标识、稳定账户实例 `account_id` 和政策 `policy_revision`，下单按钮显示账户名称，委托不会发到未选中的账户。

**账户记录与交易主机归属**：账户 ID 是交易主机的实例名，Terminal 的连接名称不会改变它。
交易服务以该 ID 获取交易安装目录 `data/owners/` 中的独占锁，并持久绑定原账本目录；进程退出只释放锁，
不清除绑定。账户记录保存在 `data/<实例>/journal.sqlite`，已初始化账户的日志缺失时拒绝重新开通。
柜台的经纪商代码、投资者账号、AppID 和前置地址用于连接，不拼接为另一个内部身份。
备份时需同时保管账户记录和所有权绑定；运行锁不能作为其他机器接管许可。当前不提供目录搬移或绑定重置操作。


该保证针对同一账户 ID 的执行与记录，不自动识别不同账户配置是否对应同一外部资金账户，也不阻止其他软件、操作系统用户或机器交易。不要将多份配置视为彼此独立的资金账户或风险额度；资金、持仓和外部委托以柜台同步结果核对。

**政策修订**：账户面板“风控”标签下的“账户政策”显示当前政策版本，可调整可交易合约、三项风险限额和价格偏离上限。已授权合约沿用其固定单位，新增合约从 CTP 合约目录取得规格。每次生效追加独立政策事件，不覆盖旧头部、旧政策或历史命令；无需新建账户或重建记录。

政策生效要求账户已同步、持仓已核对且没有未确认委托。所有存量持仓和在途委托涉及的合约必须继续获得授权，其单位、品种和月份不得变更；已经持有的风险不会因收紧限额而消失。服务在核对的柜台代次及风险状态版本上冻结连接，再持久记录新政策。冻结前若仍有已接纳但未应用的柜台事件，则明确拒绝，不能用旧投影通过检查。应用后保持断开、撤销原授权，需重新登录、同步并授权。提交失败要求按原日志恢复，不自动重发。旧政策版本的新命令明确拒绝；相同请求身份、原政策版本及相同内容的重试只确认原记录，不重新应用政策或发送委托。

订单限额编译进交易服务，并与回测共用同一实现。政策仅保存合约规格、限额、价格偏离参数和变更事件；没有算法选择、摘要或动态库副本。账户线程按最新持仓与在途委托检查候选政策，先关闭发送授权和连接，再持久记录政策事件；持久成功后替换有效政策。失败不采用新政策。政策修改遵循与下单相同的日志屏障。旧格式不做迁移或兼容，读取失败不会改写或删除原记录。

**连接**：交易服务读取主机上的 systemd 凭据并登录。Terminal 的连接操作不携带密码或授权码；断开后可显式请求服务用本机凭据重新登录。解密后的凭据只留在服务内存，不写入日志、交易记录、快照或界面存储。连接后依次完成终端认证、登录、确认结算单、同步账户，并从持久索引恢复当前交易日的委托归属，之后状态变为“已就绪”。归属恢复期间保持“同步中”，不能授权、修改政策或撤单。

**授权**：勾选确认账户后点“允许发送委托”。授权长期有效：断开、SDK 自动重连和交易日变化后都不需要再次授权。它只在四种情况下失效：手动撤销（任何时候都可以，包括未连接时）、修改风控政策、交易服务重启（授权只存在于服务内存，从不恢复）、交易记录进入需要恢复的状态。授权有效不等于可以发送：账户未连接或未完成同步时任何委托都被拒绝。下单在 CTP 交易适配内核对连接代次，重连前准备的委托不会转发到新连接，断线前已记录的委托也从不重发。

**账户费率**：账户就绪后点“查询账户费率”，向 CTP 查询每个可交易合约的保证金率（`ReqQryInstrumentMarginRate`）和手续费率（`ReqQryInstrumentCommissionRate`），即券商对本账户实际收取的费率。多空保证金不同时取较高者；手续费按合约或品种返回均可。券商未返回或查询失败的合约标为“券商未提供”，不影响交易会话。查询结果不写入交易记录，可按品种存为费率模板，来源记为“CTP 账户 经纪商/账号”，生效日期为当前交易日。

**每笔委托的检查顺序**：

1. 已授权、账户已连接并完成同步；
2. 合约在可交易列表中，手数和限价分别是数量步长和最小变动价位的整数倍；
3. 价格检查：向 CTP 查询该合约的当前行情（`ReqQryDepthMarketData`），限价必须在涨跌停范围内，且与参考价（最新价；当日尚无成交时为昨结算价）的偏离不超过价格偏离上限。查询必须收到成功结束标记，合约、交易日与连接代次须和当前账户一致；收到部分行后超时或报错一律拒绝。报价有效期从成功完成查询起按账户进程的单调时钟计量 10 秒，风控、写日志和发送排队使用同一个截止时间；发送前到期则拒绝，系统校时不延长有效期。这个时限衡量查询观察的新鲜度，最新成交时间可能更早，尚无成交时允许当前交易日的昨结算价。查不到行情就拒绝。受 CTP 每秒一次的查询限制，每笔委托约多等 1 秒；行情查询排在持仓、资金刷新和费率查询之前；
4. 内置风控（与回测共用的订单限额）：总持仓取券商持仓，在途开仓取券商回报中未成交的开仓委托，再加上未确认委托；
5. 先把委托写入本机交易记录（`journal.sqlite`），成功后才发送给券商。

任一环节失败都不发送。

**撤单**：撤单请求先写入交易记录，成功后才调用 SDK。SDK 接受只表示发送已受理，最终撤单状态仍以柜台回报为准；发送失败、超时或中断保留未知结果。同一请求编号重试或恢复都不会再次发送；需要先核对柜台，再显式发起新的撤单请求。

**日志自动分段**：账户使用稳定的 `account_id`，政策版本、连接和授权拥有独立生命周期。每份活动文件包含稳定账户头部及最多 100,000 条事件，序列化内容最多 256 MiB；头部和事件单条最多 64 KiB。接近文件边界时，持久化线程自动把事件封存为 `archives/record.<唯一标识>.sqlite`，保留全局事件编号和原始字节。文件先持久发布并校验，再在同一 SQLite 事务中登记分段、移走原事件行、追加新事件和命令索引；账户头部不重建。

换段不要求清空在途委托，不断开连接、不撤销授权、不改变账户或政策身份。相同命令身份和相同内容只确认原记录，不再次发送；不同内容或重复授权明确冲突。命令索引同时记录报单的终身委托编号，和意图在同一事务提交；换一个请求编号也不能复用旧委托编号。分段不清空这两种身份。确定未发送或已人工核实不存在的意图在证据写入后从内存移除，恢复时按同样顺序重放；去重由持久索引承担。恢复校验全部已登记分段的范围和摘要，并按全局顺序每页最多 64 条交给账户线程恢复状态；缺失、变更或不连续均拒绝。

分段或提交失败后保留已有数据并要求恢复。未登记的封存副本和 `pending.*` 文件不会自动复用或删除。应冷备份整个账户目录（含主数据库、`archives/` 和 `owner/`），不能只备份活动事件行。磁盘容量不足明确失败，不删除历史文件换取空间。旧格式直接拒绝，不提供续用、迁移或重建账户来绕过持久记录的入口。

**终态证据与归属恢复**：账户线程将已确认的成交完毕、撤销或拒绝结果交给日志线程，每批最多 32 笔。证据固定原委托、交易日、柜台编号、终态和累计成交量；持久成功后才移除内存意图。提交失败关闭执行能力，重启仍从原意图保留风险，不能把内存中曾看到终态当作持久完成。恢复仅重放证据，不重跑风险算法、不发送委托。

终态意图释放后，原委托身份仍保存在持久索引中。每次柜台登录完成后，由原日志线程每页最多 64 项读取当前交易日身份；同一柜台编号只恢复未被排除的最新日志身份。已核实不存在或明确未发送的排除标记与对应证据原子提交。恢复结果绑定连接代次及交易日，旧完成不进入新连接；较旧日志身份也不能覆盖较新报单身份。完整恢复前账户不宣告业务就绪。身份归属可以补充当前委托和成交投影，但不替代柜台提供的状态和数值。

终态保存、归属读页和外部持久命令共用唯一活动事务与完成槽；有排队命令时，内部批次与命令交替推进，不增加线程或无界恢复队列。启动时逐页验证委托索引、原始意图和排除证据一致，额外或缺失索引均拒绝恢复。

**报单交接**：柜台订单列表只显示真实柜台回报；SDK 返回本身不构造“已提交”或“已拒绝”的柜台订单。尚无回报的已记录意图由账户的未确认集合占用风险额度。执行适配器先生成拥有固定柜台身份和请求内容的准备对象；账户记录意图后才消费该对象，异步交给 SDK 线程。丢弃准备对象不发送。SDK 侧只允许一笔报单排队或调用；返回前不再积压已过风控的报单。若连接、敞口或报价期限变化而确定没有调用 SDK，账户追加“未发送”证据后才释放该意图，恢复和重复请求都不重发。未取得完成结果时保持未知；SDK 的迟到返回不能覆盖已经确认的柜台成交。

**SDK 生命周期**：账户适配器由一条固定 SDK 线程串行创建、初始化、调用和释放柜台 SDK。
连接请求异步接纳，实际结果由连接状态显示；更换连接必须等原 SDK 完全释放后才创建下一实例。
释放阻塞期间仍可读取状态或取消待连接请求；不为绕过阻塞创建并行 SDK，也不自动重发委托。
账户服务已有唯一账户状态线程：账户对象在该线程构建、使用和销毁，普通请求最多接纳 64 项，另保留 8 项查询与控制容量，满时明确拒绝。请求接纳与持久完成分别表达，执行返回的结果只有在命令完成后才确认。服务不再用 RPC 互斥锁承载账户状态；首次创建账户也异步等待账户线程初始化，成功后由 I/O 线程发布实例；健康通道独立观察账户处理耗时。

日志由独立写线程串行提交，账户线程不等待运行期的日志刷盘或封存文件生成；快照只显示最后确认的日志容量。一次只推进一条持久命令，其余修改请求在有界准入队列等待；日志完成事件有独立保留容量。

通过身份和请求信封校验的撤权请求进入有界队列时，立即关闭一次性报单许可并推进控制代次；断开请求和关闭账户入口也先停止尚未消费的许可。只有账户线程校验记录、政策及请求身份后才修改授权，持久记录完成后才确认撤权成功。入口失效不等于业务请求已经通过或持久完成。写盘期间被撤权的准备报单记录为明确未发送后释放占用；已经接纳但尚未执行的旧授权、旧报单也不会重新获得许可。写盘前开始的授权不能在撤权后的迟到完成中恢复权限。日志失败要求重新打开核验，服务不重发。

报价、报单调用结果和撤单调用结果均异步交付，账户线程等待期间仍处理查询与控制。账户同一时刻只推进一条持久命令，有一个例外：报单等待柜台行情查询（约 1 秒）期间尚未记录任何内容，此时针对账户已记录委托的撤单可以先执行完，再让报单继续；撤单针对的委托尚未记录时（例如正是这笔等待中的报单）仍按到达顺序排队。撤单回报会改变报单被接纳时的发送依据，所以那笔等待中的报单随后按现有规则记为未发送，需要重新提交。Terminal 对同一账户的其它命令仍然互斥；撤单、停止策略和撤销授权不受这一互斥限制，界面上也不因别的命令在途而禁用，各自只在同一个请求尚未应答时不能重复点击。撤销授权有自己的一条请求通道，不排在在途命令或已排队的撤单后面；账户服务在接纳时即关闭发送许可，应答排在在途命令之后。已经消费的发送许可不能撤回。撤权会结束当前策略并触发其归属撤单；手动委托仍须显式撤单，任何委托都不能在柜台确认前视为已撤销。命令在途期间界面照常按修订号读取快照，账户和行情的观察不因它暂停。报价在成功完成回报与 SDK 接受均成立后才可使用，过期或连接失效则结束查询；读取查询限流重试不会变成交易命令重发。SDK 返回超过五秒时，账户继续保留结果等待与风险占用，不把超时解释为拒单，也不会丢弃迟到结果。

每条修改请求在入口接纳时固定控制代次；排队、账户取件、风险判断和异步提交均不刷新它。已在撤权前接纳的授权和报单不能借用撤权产生的新代次，需由用户发起新的请求。持久完成后，账户为该准备订单签发一次性许可。许可绑定账户控制代次和订单身份，SDK 在线程中完成连接、敞口和期限检查后原子消费，随后直接调用柜台。撤权使尚未消费的许可失效；已经消费的调用保留发送中或未知结果，后续真实柜台回报仍是订单状态依据。

CTP 回调只复制供应商数据和观察时刻，交付到容量 1024 的固定队列，由账户线程按入口顺序应用。可能改变发送依据的回调在发布前原子关闭许可并标记有事件尚未处理；只有账户处理完入口前缀后才能解除标记，读取最新代次不能绕过待处理事件。报价的有效时间仍从回调观察完成时计算。回报队列溢出会停止新增报单并要求重新连接核对；已有委托不会自动撤销，具备现有身份和连接条件的撤单仍可执行。

账户线程同时拥有连接重建、查询序号、查询开始与超时、费率失败和 SDK 完成结果。SDK 线程通过一个独立保留槽交付状态操作，自己只执行供应商调用与生命周期，并在报单前检查和消费许可。账户线程不等待这个内部交接；SDK 完成和回报均唤醒账户，查询期限由账户自己的截止时间推进，不依赖供应商请求是否返回。

正常销毁先关闭新调用，账户拥有者继续消费内部交接和已经接纳的柜台事实，直到 SDK 线程完成 Release、回调生产者全部停止，再排空余下事实并卸载库。断开不会抹掉此前已收到但尚未应用的真实委托与成交，也不会把这些事实当作断开后获准的新命令。

RPC 在接纳前从协议直接生成类型化 `AccountRequest`；政策修改携带包含限额、价格偏离和合约清单的 `PolicyDefinition`。日志线程准备政策，账户线程核对当前敞口后采用。JSON 命令只保留为当前持久记录及同一请求 ID 的内容核对依据，不反解析为执行参数。

账户观察由账户线程直接构造现有 Protobuf `LiveSnapshot`，经类型化 future 交给 I/O 回复。快照是独立值，不持有账户执行权，也不随之后的授权或委托变化而改变。资金、数量和费率从 `Decimal` 直接编码；Terminal 在接收边界验证并生成界面 JSON，服务内部不再经 JSON 中转快照。

交易 RPC 已使用单条非阻塞 I/O 线程，不再为每条连接占用工作线程。仅开放 TCP，在 TLS 1.3 双向固定指纹认证通过后才交付请求。最多保有 80 条业务连接、16 条待认证连接，每条连接只推进一项请求；超出连接容量直接关闭新连接，不重放命令。请求帧上限 1 MiB，整帧读取期限 30 秒、发送期限 10 秒，握手期限 10 秒。等待账户结果不占用 I/O 线程，完成状态按 10 毫秒调度周期检查；客户端断开不等于交易命令取消。

交易进程的账户路径采用四条应用线程：客户端与健康 I/O、账户状态、日志写入、交易 SDK 调用；策略另有一个有界工作线程及一个行情 SDK 线程。健康端点与业务传输共用固定指纹 TLS 连接和 I/O 线程；由 systemd 看护。该 I/O 协调者观察异步初始化和资源停止完成。恢复期间已开放 I/O，附着请求等待同一个初始化结果，不把正在恢复的账户当成尚未创建。

正常停止先关闭新业务接纳和报单许可，继续让已接受请求完成日志、SDK 结果及最后状态读取；回执排空后由账户线程停止资源，SDK 线程负责 Release，日志线程保持到需要保存的状态完成。只有 SDK、日志和账户资源全部退出，停止完成信号才成立。整个排空与资源停止共用 400 毫秒期限；健康端点在此期间仍可查询。超时结束整个进程，不无限等待析构、不重发命令、不把已发送委托解释为撤销成功。由 systemd 向进程发送停止信号，Terminal 关闭不停止服务。关闭入口不清除 SDK 待应用回报标记。

**健康观测**：心跳分别报告客户端 I/O、账户状态、持久化/准备、初始化和当前命令的进展，以及业务就绪。各执行线程只更新自己的观察；账户即使没有柜台事件，也在不超过 500 毫秒的调度等待后自行推进。账户状态、I/O 超过 30 秒未推进，或持久化、初始化、命令处于执行中超过 30 秒，健康显示异常。空闲日志线程无需制造写入证明存活。等待超时不再设置 `recovery_required`；该字段仅表示真实的恢复故障，也不改变命令结果、授权或重发规则。

业务就绪要求柜台处于 ready、持仓已核对、当前连接的委托归属恢复完成且账户没有恢复故障；初始化完成但未连接柜台时仍等待输入。业务就绪不授予报单许可。启动恢复不阻塞 I/O，健康端点能报告初始化、账户及持久线程的实际进展。Terminal 直接读取交易服务的健康与相对进展耗时，在连接详情显示各项进展，过期账户就绪只显示待确认。

**委托身份匹配**：柜台前置/会话/引用编号与交易日共同构成委托身份。其他交易日的委托和成交回报不进入当前投影，回报缺失交易日则进入明确失败处理；不以当前登录日期补全缺失字段。历史委托不能借用新交易日的同号委托取得归属或撤单权。同日尚未获确认的旧请求所用编号被柜台重新分配时，新委托也不能替旧请求解除未知风险；核对必须同时匹配本地委托身份。已经核实不存在或确定未发送的委托不再参与重新连接时的柜台归属索引。

输入拒绝回执按原始 SDK 请求编号归属；报单同时固定调用参数和输入结构中的 `RequestID`。待确认请求保留原委托与撤单字段，确认回报后释放，重新登录清空；迟到拒绝不能借用新登录的前置或会话。首条确认回报前的撤单使用同一份原始请求。

**断线与恢复**：交易命令断线后不重发。每次登录（包括 SDK 自动重连）都从柜台重新建立委托、成交、持仓与资金快照；旧缓存不能当作柜台确认。成交去重记录与交易所委托映射随重建清空，避免跨日编号复用混入昨日记录。断线后清除已查询费率，重新就绪后需再次查询，不能把昨日结果标作今日费率。重启后，交易记录里的委托编号只用于对上券商回报；任何交易日已记录、没有持久终态或排除证据、且券商同步后仍未报告的委托列为“未确认”；换日不自动释放这部分风险。未确认委托不会重发，并继续计入在途委托额度，需要在券商端核实。在券商端确认某笔委托不存在后，可在界面将其标为“已核实”：该操作写入交易记录，此后它不再计入在途委托额度，恢复后仍然有效；只能对账户已同步、且当前确实未被券商报告的委托执行。Terminal 对实盘命令最多等待 30 秒，这是客户端等待预算，不是 SDK 或日志完成时间的保证。等待到期不能证明未发送；账户服务保留已接纳命令，客户端需要重新读取并核对结果，不能自动重发。同一请求编号重复提交时只确认、不再发送；授权请求的编号不能重复使用。

**限制**：只做限价单，没有条件单或撤改单；风控只有内置订单限额和价格检查。一个账户最多一个策略执行实例，持有策略身份时拒绝手动新增委托。自主运行规则见[交易规则](safety.md)；当前服务启动后使用交易主机的 systemd 凭据登录，柜台断开后等待 SDK 自动重连或人工重新连接。登录不恢复委托授权；服务重启后必须重新授权。当前实现仍需在真实仿真账户（如 SimNow）核对；隔离测试和旧实现的验收结论不能代替此次验收。


仿真验收步骤与证据要求见 [券商仿真验收](acceptance/ctp-simulation.md)。

成交与持仓核对期间暂停新增开仓，撤单、撤销授权和断开连接仍可执行。订单成交量不会因迟到回报减少；持仓查询期间收到新成交时必须再次查询。风险评估固定柜台敞口修订号，记录或排队期间敞口变化则拒绝发送，不自动重试。

### 创建账户的默认参数

默认参数集中定义在 `apps/services/trading/scripts/setup.sh`：监听地址、起始端口、柜台环境和 CTP 接入参数。安装包只携带程序、脚本与运行库，不携带默认配置文件。新建账户时回车采用脚本默认值，端口从默认值开始选择未被其他账户使用的端口；编辑已有账户时回车保留该账户原值。脚本将确认后的参数写入 `config/accounts/<账户名>.json`，首次安装生成 `config/logging.json`，升级不覆盖实际配置。

实例名称就是 Terminal 使用的账户名称与账户 ID，统一用于配置文件名、`data/<账户名>/`、日志前缀和 `asterion-trading@<账户名>.service`。CTP 投资者号是独立的 `broker.user_id` 字段，不要求与实例名称相同。账户名、投资者号、Terminal 证书指纹须明确填写；密码和授权码通过隐藏输入存入 systemd 加密凭据，不进入 JSON；修改已有账户时柜台身份（环境、经纪公司、投资者号、AppID、前置）没变的话可以保留原凭据，变了必须重新输入。脚本把每个文件先写到同目录的临时文件再改名，输入中断或任何一步失败都不留下临时文件，原有配置和凭据不变；升级时重写单元模板。风险政策由账户账本持久保存，变更走政策事件。
