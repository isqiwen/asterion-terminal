# 交易与风控

交易只有一种：通过 CTP 连接期货公司柜台的账户（仿真环境如 SimNow，或实盘），见下文“CTP 交易”。没有本机模拟账户；在历史数据上验证策略用回测（见 [研究任务](research.md)）。

回测与 CTP 交易共用同一个订单限额风控插件。回测另外使用下面的账本、费率和撮合规则来估计成交和资金；CTP 账户的资金、持仓和成交以柜台回报为准。

## 账本语义

`core/domain/account`（`FuturesAccount`）：回测使用的组合账户，一个资金账户下最多 20 个合约，单币种、整数手数。

- 每个合约有自己的费用：保证金 = 手数 × 每手保证金 + 名义金额 × 保证金率；手续费同理，开仓、平今、平昨分别设置。各合约保证金相加，没有跨品种保证金优惠。名义金额 = 价格 × 手数 × 合约乘数，比例部分按分四舍五入。
- 平仓规则按交易所：上期所、能源中心需要明确平今／平昨；中金所先平今；大商所、郑商所、广期所先平昨；同一桶内先开先平。
- 权益 = 账面资金 + 各合约浮动盈亏；可用 = min(账面资金, 权益) − 持仓保证金 − 委托冻结。浮盈不增加开仓额度，一个合约的浮亏会减少所有合约的可用资金。
- 下单、撤单、成交、标记、结算都有强异常保证；成交 ID 唯一，重复回报幂等，冲突回报拒绝。

## 按交易日生效的费率

每个合约的 `cost_schedule` 必须有 1–512 个按日期递增的版本；每版记录生效日期、来源及八项保证金和手续费参数。选择不晚于当前交易日的最后一版，持续生效直到下一版；首个交易日没有适用版本则拒绝创建。日期按数据的交易日判断，不按本机时区或夜盘自然日判断。

上一交易日撤单并结算后，在下一交易日的第一个行情事件中同时更新全部合约的费用和持仓保证金，再进行行情处理。已发生的手续费和账面资金不重新计算。新保证金可能使可用资金为负；系统不自动强平或补足资金。回测结果同时返回当前费用与完整的固定版本表。

券商查询得到的是当前账户费率，不是历史费率数据库。来源与日期需由使用者核实；没有实现按成交量分档、盘中调整、返佣或跨品种保证金优惠。

## 回测撮合模型

`plugins/execution/paper`：

- 新委托只参与本合约之后的 K 线撮合，其他合约的 K 线不会使其成交。买入限价被最低价触及时以开盘价与限价中较低者成交；卖出限价被最高价触及时以较高者成交。收盘后标记权益。
- 同一根 K 线的 10% 成交量向下取整到数量步长，由按到达顺序的委托共享；不推断真实逐笔成交路径。
- 没有盘口、滑点、冲击成本、强平或自成交识别。这是估计模型，不代表真实可成交性。

## 交易前风控

`plugins/risk/order-limits`，通过 `RiskPort` 接入统一提交路径：

- 单笔委托数量上限；
- 每个合约的潜在总持仓上限（多空不抵消，在途开仓计入）；
- 整个账户的在途委托数上限。

超限时仍允许减仓。插件不可用、配置缺失或拒绝，都阻止提交。风险配置随 CTP 账户记录和回测任务保存，恢复时按原配置重建插件；缺少配置的记录拒绝恢复。

## CTP 交易

## 实盘

每个 CTP 交易账户由一个独立的 `asterion-trading` 进程运行（Agent 服务类型 `LIVE_TRADING`），通过 CTP 交易接口连接期货公司柜台。账户状态（资金、持仓、委托、成交）以券商回报为准；会话负责券商之前的执行链。

**创建**：在“交易”添加命名的 CTP 账户，使用当前 CTP 账户（设置 → CTP 账户，须填有交易前置和 AppID），填写三项风险限额和价格偏离上限。创建时把柜台信息写入自己的记录，之后修改、删除或切换当前账户都不改写已创建的记录，并从 CTP 合约目录中选择可交易合约（最多 20 个，可在当前表单读取目录）。默认自动管理独立账户目录，自定义目录位于高级入口。合约的最小变动价位和合约乘数取自目录。目录头部记录这些信息和风控插件摘要，日志引擎为 `asterion.live-futures.v5`（格式 1，manifest 版本 2），恢复时拒绝其他标识。

**连接**：每次连接时输入交易密码和授权码。凭据只在交易服务进程内存中保存到连接结束，不写入目录、日志、快照或界面状态。连接后依次完成终端认证、登录、确认结算单、同步账户，状态变为“已就绪”。

**授权**：勾选确认账户后点“授权实盘交易”。授权绑定本次连接代次和当前交易日；包括 SDK 自动重连在内，断开、重启或交易日变化后均需要重新授权。下单在执行插件内再次核对连接代次，重连期间准备的委托不会转发到新连接。可随时撤销。

**账户费率**：账户就绪后点“查询账户费率”，向 CTP 查询每个可交易合约的保证金率（`ReqQryInstrumentMarginRate`）和手续费率（`ReqQryInstrumentCommissionRate`），即券商对本账户实际收取的费率。多空保证金不同时取较高者；手续费按合约或品种返回均可。券商未返回或查询失败的合约标为“券商未提供”，不影响交易会话。查询结果不写入交易记录，可按品种存为费率模板，来源记为“CTP 账户 经纪商/账号”，生效日期为当前交易日。

**每笔委托的检查顺序**：

1. 已授权、账户已就绪、交易日未变；
2. 合约在可交易列表中，手数和限价分别是数量步长和最小变动价位的整数倍；
3. 价格检查：向 CTP 查询该合约的当前行情（`ReqQryDepthMarketData`），限价必须在涨跌停范围内，且与参考价（最新价；当日尚无成交时为昨结算价）的偏离不超过价格偏离上限。查不到行情就拒绝。受 CTP 每秒一次的查询限制，每笔委托约多等 1 秒；行情查询排在持仓、资金刷新和费率查询之前；
4. 风控插件（与回测相同的订单限额）：总持仓取券商持仓，在途开仓取券商回报中未成交的开仓委托，再加上未确认委托；
5. 先把委托写入本机交易记录（`journal.sqlite`），成功后才发送给券商。

任一环节失败都不发送。

**断线与恢复**：交易命令断线后不重发。每次登录（包括 SDK 自动重连）都从柜台重新建立委托、成交、持仓与资金快照；旧缓存不能当作柜台确认。成交去重记录与交易所委托映射随重建清空，避免跨日编号复用混入昨日记录。断线后清除已查询费率，重新就绪后需再次查询，不能把昨日结果标作今日费率。重启后，交易记录里的委托编号只用于对上券商回报；当前交易日已记录、但券商同步后仍未报告的委托列为“未确认”。未确认委托不会重发，并继续计入在途委托额度，需要在券商端核实。在券商端确认某笔委托不存在后，可在界面将其标为“已核实”：该操作写入交易记录，此后它不再计入在途委托额度，恢复后仍然有效；只能对账户已同步、且当前确实未被券商报告的委托执行。Terminal 对实盘命令最多等待 30 秒，长于服务端一笔委托的最长处理时间（行情 10 秒加发送 5 秒），不会把已发出的委托误报为连接丢失。同一请求编号重复提交时只确认、不再发送；授权请求的编号不能重复使用。

**限制**：同一时间只能打开一个 CTP 交易账户。只做限价单，没有条件单或撤改单；风控只有订单限额插件和价格检查。还没有策略自动下单：策略目前只能通过回测运行。只在测试用 CTP SDK 替身上验证过，真实券商环境需要先用仿真账户（如 SimNow）核对。


仿真验收步骤与证据要求见 [券商仿真验收](acceptance/ctp-simulation.md)。
