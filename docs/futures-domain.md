# 期货领域基线与完成门槛

2026-09-20，维护者确认本领域为最高优先级。本文件规定当前建设目标、唯一职责和验收顺序；不是已实现能力声明。代码现状见末节。通用机制继续遵循 [AGENTS.md](../AGENTS.md)，领域功能由插件实现。

## 1. 身份与对象

| 对象 | 唯一含义 | 可直接下单 |
|---|---|---|
| 品种 Product | 交易所限定的产品及规格族，不含某个月份 | 否 |
| 实际合约 Contract | 交易所发行、具有明确交割年月和生命周期的一次合约实例 | 还须通过账户、交易时段及风险校验 |
| 合约角色 Role | 按指定来源或算法，在指定时点选出的主力、次主力、近月等实际合约 | 先解析并冻结实际合约 |
| 连续序列 ContinuousSeries | 按固定映射拼接实际合约行情的派生数据 | 否 |
| 指数 Index | 按指定成分、权重和算法计算的数据 | 否 |
| 价差 Spread | 明确各腿合约、方向、数量比例及单位的组合定义 | 依赖交易通道声明的组合或分腿执行能力 |

主力是角色，主连是由角色映射构造的序列；两者不能成为实际合约枚举中的另一种月份。指数、近月连续、固定月份连续与主力连续分别声明构造规则，不能只用“连续”一个标签代替。

实际合约身份包含交易所、品种、明确交割年月及发行生命周期；供应商代码与交易所报单代码是有来源和适用期间的外部标识。内部身份不从用户输入字符串直接认定存在。三位月份代码、大小写及供应商后缀由来源协议解析，年份不得按当前年份猜测；代码复用不得合并不同生命周期。跨源关联必须有证据，冲突或歧义拒绝发布。明确协议映射不是对旧项目字段的兼容别名。

上市日期、最后交易日期、交割期限分别保存；日期资料不能冒充精确交易时间。可交易截止时刻由实际合约、品种时段和特别公告共同确定。乘数、报价单位、数量单位、价格步长、币种必须明确，不能把所有供应商的 multiplier 字段按同一单位解释。

## 2. 时间与当时可知信息

沿用 [交易时间插件](trading-time.md) 的唯一时段解析：自然日、交易日、事件时间、接收时间、来源发布时间和研究可用时间分别保存。日历覆盖、夜盘开闭、品种生效时段和例外缺失时拒绝执行；不能按周一至周五推算夜盘和节假日。

所有规则与映射同时描述业务生效区间和信息可用性。今天下载的历史数据不能自动获得当年可知证明；已知时间不明必须保留未知，不能填成当日零点。探索研究可以显式声明假设，不能据此获得可部署资格。

来源修订发布新不可变版本；固定研究输入不随“最新”变动。时点查询显式给出业务时刻与信息截止时刻，不能查询最新后回填历史。

## 3. 主力与次主力映射

每套映射固定品种、角色、来源类型（供应商发布或自行计算）、来源/算法工件与参数、候选合约集合版本、输入行情版本、观测窗口、可知时间、生效区间、目标实际合约和选择证据。

自行计算必须明示排名指标、单位、同值排序、无成交/缺失数据处理、候选生命周期限制、换月阈值、连续确认次数、能否回切及次主力排除主力的规则。没有全市场统一的默认主力算法。映射缺口不得沿用上一合约掩盖，冲突不得以返回顺序消解。

利用交易日 D 的完整成交量或持仓量计算的选择只能在该输入实际可知之后生效。下一生效点必须经交易时间插件解析，不能简单加一天；当日收盘后得到的结果不得用于当日夜盘开盘（该夜盘可能在前一自然日）。

Tushare 的 [fut_mapping](https://tushare.pro/document/2?doc_id=189) 提供连续代码、日期和月份合约代码，文档未提供历史发布时间字段。因此该来源可以作为供应商历史映射证据，单凭日期不能认证盘前可知。它不能冒充本项目自行计算的主力结果。[fut_basic](https://tushare.pro/document/2?doc_id=135) 区分普通合约与主力/连续资料，接入时必须保留这一区别。

## 4. 连续序列与复权

连续序列固定实际行情版本、映射版本、交易时间版本、切换时点、拼接算法、缺口策略及复权定义。每根记录可追溯实际合约、原始价格、所用变换和切换事件。原始成交量、持仓量、结算价的单位及用途分别声明，不随价格因子一并盲目变换。

复权必须明确差值或比例、方向、锚点、重叠取价时刻与价格字段；只写“前复权”或“后复权”不足以定义算法。用未来换月因子修改历史价格的序列不能直接充当当时可知的策略输入。比例法遇到零或不适用价格必须拒绝；差值法不能用实际合约价格为正的约束拒绝合法派生负值。

复权价格只用于声明过的研究信号或展示；委托、成交、手续费、保证金、涨跌停和结算始终引用实际合约的真实价格与规则。连续行情跨月跳变不能计成持仓收益，也不能通过复权抹去换月成本。

## 5. 交易规则、持仓与资金

合约规格、时段、交易所规则、经纪商规则、账户约束分别有所有者和版本。账户实际约束不能被研究界面填写的比例静默覆盖。规则快照明确来源、适用对象、期间和可知性；适用规则不完整时不能声称正式交易可用。

持仓按账户、实际合约、多空方向维护，按场所要求区分今仓/昨仓、冻结量、可平量；净仓不能替代双向持仓。开仓、平仓、平今、平昨的命令语义与通道能力明确。费用区分开平、今昨、按手与按金额，金额计算与舍入依据固定。

结算价、收盘价、前结算价分别保存。资金账记录现金流、手续费、已实现及未实现盈亏、逐日结算、保证金占用和可用资金；成交与结算重复回报不得重复入账。多空、部分平仓、跨日持仓、入出金及撤单释放冻结资金均须可重算。

价格步长、数量步长、报单上下限、涨跌停、临时停牌、交割月限制和持仓限额按场所、品种、合约、账户及生效期间校验。缺少盘口不能假定涨跌停价可成交；保证金不足的强平意图也不能保证立即成交。

## 6. 换月与订单恢复

换月是执行计划：冻结旧、新实际合约、目标数量或风险敞口换算、触发证据、允许时间、执行次序、最大风险和失败处理。映射变更只产生计划，不直接改写持仓合约。

每条腿独立记录委托、成交、费用、滑点、保证金及状态。旧腿已平新腿未开、部分成交、拒单、断线、暂停和取消都是有效中间状态。风险先评估临时敞口；不得把两腿模拟成天然原子成交或没有成本的价格替换。

账户由单写者执行；意图持久化先于发送。订单标识、请求标识与成交标识分别去重。发送结果未知时进入待查询/对账状态，不盲目重发。断线和重启先恢复日志并核对委托、成交、持仓与资金，再开放新意图；查询失败不能伪装成空仓。

## 7. 插件归属

| 所有者 | 领域责任 |
|---|---|
| 数据插件内的合约目录能力 | 品种、实际合约生命周期、来源标识解析及不可变目录 |
| `trading_time` | 交易日历、时段、特别日和时间归属 |
| `contract_rules` | 按对象及期间生效的交易规则、来源与账户适用性 |
| 数据功能插件 | 采集、导入、固定行情及来源证据；角色映射与连续加工通过领域公开契约协作 |
| `contract_roles`（首个切片）及待实现的连续加工插件 | 固定来源角色发布与时点解析；Tushare 映射与自算选择、来源重建及发布已接通；候选证据与角色查看已实现，派生序列与其血缘仍待实现 |
| `trading` | 订单、持仓、账户资金、换月计划、执行与恢复；正式历史模拟共享此领域实现 |
| `research` | 实验、固定输入、报告和复现，不另造正式订单资金账 |

插件之间声明依赖并经公开能力读取；不跨插件直接更新所属表。身份目录不反向依赖研究或交易。供应商解释放在来源插件，核心宿主不知道主力、平今或结算公式。

## 8. 依赖顺序与验收门槛

| 顺序 | 交付内容 | 必须通过的证据 |
|---|---|---|
| F1 | 统一身份目录与时间/规则所有权 | 代码复用与来源歧义拒绝；完整更新导入、同步、覆盖、研究、UI、导出与备份引用；移除重复模型 |
| F2 | 角色映射和可知性 | 来源与自算分离；同值、缺口、生命周期、夜盘切换、未来信息拒绝；真实来源固定样本 |
| F3 | 连续加工与血缘 | 拼接、因子、锚点、缺口及跨月查询可复算；派生价格无法进入实际成交账 |
| F4 | 规则、双向持仓与订单资金账 | 今昨、费用、结算、冻结/释放、限价、保证金边界；逐事件重算相等 |
| F5 | 多合约换月与故障恢复 | 双腿部分成交/失败；重启、重复及乱序回报；未知状态对账，损益不包含虚假跳差 |
| F6 | 端到端验收 | 固定真实数据与规则证据的跨月研究、离线复现、备份恢复、冻结桌面包；模拟交易后独立进行实盘准入验收 |

每阶段必须同时记录代码实现、调用链接入、自动验证和真实来源覆盖。界面与测试工具为基础验收服务；外围产品扩展排在上述基础之后。通过历史模拟不代表经纪商实盘能力通过。

## 9. 当前审计结论与待替换项

当前已存在交易时间插件、固定规则版本和单合约日线逐日结算；仍是有限研究模型，不支持完整双向持仓、平今或真实订单生命周期。`trading/plugin.py` 明确提供未接入网关状态。角色插件已实现固定供应商声明的登记、解析和下一开盘诊断；Tushare 主力映射采集与固定来源角色发布已接通；自算排名、固定来源核验、算法制品、计算角色发布与备份已接通，历史公布时间不补造；真实供应商换月和两候选单日计算发布已验收，自算连续采集换月未验收；连续加工和真实两腿换月尚未实现。见 [角色契约](contract-roles.md)。

参考目录中重复的时段与交易规则模型已删除；目录读写、列表、前端与 Schema 已收敛为品种和合约资料，备份校验纳入目录结构及内容指纹。交易时间和费用规则由各自领域插件负责。

F1 当前身份链：目录已实现品种、完整交割年月和上市日期组成的身份，以及来源代码有效期与可知性解析，现可从固定标准同步资料发布目录，保留交割年月、最后交割日、来源版本与校验和；身份目录已移除乘数/最小价位副本。覆盖、研究提交与执行、导出、离线复现及备份恢复现已冻结并校验目录证据和逐根实际合约 ID，探索模式也不能跳过身份验证。文件导入现已在预览、提交和发布阶段验证并保存固定目录及代码映射；研究准备已通过资料依赖原子提交日线并冻结身份，重试保持原配置与单一后继；单独日线用户入口已接入显式固定资料准入；日线和结算均已接通用户与内部任务准入、采集/发布与备份校验，缺失身份的重试及补齐无法入队；规则对象、资料映射与结算证据已改为完整规范身份；研究按规范 ID 核验规则，界面选择已发布目录中的实际合约。F1 在当前已实现功能范围内通过验收，范围与证据见 [F1 身份链验收](validation/f1-identity.md)。已有用户目录与研究记录保留；不受当前契约支持时明确报错，不自动迁移或删除。

F1–F6 尚未全部实现；后续状态以代码及验收记录更新，不能以本文件存在标记完成。
