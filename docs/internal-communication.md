# 通信与运行诊断

通用通信与结构化运行诊断归 L1 固定 Rust 内核，不作为插件。当前已迁移上下文、截止时间、Call/Reply 绑定、进程收发/预算/回收、事件登记/授权/游标/恢复校验及诊断存储；L0 负责纯线协议校验。Python 保留语言/HTTP 适配与表装配；Rust 持有任务/事件 SQL，通过同一物理事务保证状态与通知原子提交。完整迁移范围见[架构](architecture.md#层级与模块)与[代码归属](engineering-structure.md#当前代码归属)。

## 当前唯一契约与分工

`contracts/communication.json` 是基础线协议的唯一源，定义 Context、Call、Reply、Fault、Event、EventPage。`scripts/generate_communication.py` 生成 Python SDK、TypeScript 和 foundation/src/wire_generated.rs；纯结构、数字及严格 JSON 校验统一位于 foundation/src/communication.rs，Python SDK 经 PyO3、Tauri 直接调用，TS 使用同一 schema 与 18 个共享用例；`--check` 检查漂移。三种语言使用同一组 `contracts/communication-cases.json` 验证合法和非法输入。当前基础版本为 1，未知版本、缺字段和多余字段明确拒绝，无旧协议分支。

业务命令/查询的参数和输出由所有者定义并进入 OpenAPI；基础协议不复制业务模型。Rust 入口实现的操作在 [services/server/openapi.json](../services/server/openapi.json) 声明，入口启动时核对声明与实际路由完全一致，集成测试按声明校验响应；仍由 Python 进程实现的操作来自其路由模型。`scripts/export_schema.py` 合并两者为 `docs/openapi.json`：同一操作不得有两个所有者，同名模型必须完全相同，引用必须可解析；前端 `schema.d.ts` 由此生成。这两层分别只有一个定义源。

- Query：读取状态，由明确所有者返回结果。
- Command：请求操作，由明确所有者校验；耗时命令进入任务系统。任务命令幂等继续由唯一 command_id 与载荷一致性校验保证，冲突拒绝；通用传输不会自动重试写操作。
- Event：已经提交的事实，按主题重放。只携带必要字段或不可变引用，不通过事件载荷传送整份行情或凭据。

机制核心负责上下文、插件登记和依赖校验、授权、事务、租约、投递顺序与恢复；业务接口、事件载荷和发布条件由插件提供。现有 Capability 是本地类型化调用契约，HTTP 的操作路由是传输绑定，没有另建一套可绕过授权的 RPC 业务入口。

## 已接入的边界

| 边界 | 实现 |
|---|---|
| TS → 服务 | 统一请求客户端生成 X-Asterion-Context；全部 HTTP 请求经薄中间件调用 Rust 入口校验与上下文绑定；HTTP 操作及错误使用 OpenAPI 契约 |
| Worker → 服务 | HTTPX 核心传输 hook；任务领取返回独立执行上下文，计算进程和后续心跳/发布继承关联 ID |
| Python 插件 → 插件 | Context.require 仍检查声明和类型；数据类能力中的调用函数绑定子上下文，业务对象与扫描迭代器不强制序列化 |
| 外部插件进程 | 单次及长会话均由 Rust 管理收发、限额、截止时间、请求匹配与释放；SDK 仅提供业务 dispatch |
| TS → Rust 原生 IPC | 所有应用自有 invoke 经统一客户端携带 Context；Rust 分派前校验结构和截止时间，生命周期操作继续向 Python 传递同一关联上下文 |
| Rust → Python 生命周期 | L1 校验 Context 并有界捕获生命周期命令；CLI 经原生绑定返回 Reply，Rust 拒绝迟到/串线响应，失败不展示任意 stderr |
| 服务 → 工作台 | 统一事件分页订阅，任务/数据发布触发重新读取状态 |

Tauri 窗口、布局和账户内存会话使用统一上下文的原生 IPC 绑定；业务参数仍由 Rust/Tauri 命令类型校验，响应关联由 Tauri 回调通道提供，不将平台窗口操作重写成后台业务 RPC。普通非数据类本地能力对象仍以其公开类接口调用，尚未逐方法增加通信上下文包装。这些是实际接入边界，不能宣称全仓每个函数调用已转换。

## 上下文与安全

Context 含协议版本、request_id、correlation_id、causation_id 和整数 deadline_ms。子调用继承关联 ID、记录父调用，并且不延长父截止时间。排队任务开始执行时获得新的执行期限，同时保留原始任务事件的关联和因果信息；客户端等待超时不会将已经入队的任务自动取消。

上下文不含权限或身份声明。HTTP 身份由 Authority 根据凭据、账户会话和已登记的路径授权确定；内部端口由插件依赖和资源声明授权。入口收到普通 HTTP 请求时建立新的根上下文，这是 HTTP 绑定，不是旧消息协议降级；收到上下文字段则完整校验，不能因格式错误改用新上下文继续执行。

截止时间在入口和调用开始时检查；进程调用还受既有墙钟时限和输出预算约束。同步业务函数不会因客户端断线被强行终止。写操作的取消、是否已经提交，必须通过任务状态和租约确认。

金额和价格由领域契约使用十进制字符串；整数限制在跨语言安全范围内，事件序号以十进制字符串传输。时间戳由领域契约使用带时区格式，交易日单独表示。载荷必须是有限、可序列化的 JSON 值。

## 进程传输与资源预算

`kernel/src/communication.rs` 是因果链和期限的唯一运行规则，`kernel/src/transport.rs` 拥有子进程、管道、帧与回收。Python ContextVar 只存放 Rust 验证后的不可变表示，调用方修改返回字典不会修改当前作用域。同步子调用继承并收紧父期限；队列任务从已提交事件建立独立执行期限，不延长已经结束的请求。有效结构的迟到回复也拒绝接受。

- HTTP 上下文上限 2,048 字节；进程请求帧上限 8,000,000 字节，含换行。单次调用的 stdout/stderr 合计受限；长会话按整个生命周期累计输出预算，不能靠逐次调用重置。
- 等待同时检查绝对期限和单调时钟预算；系统时钟回拨不能延长等待。开始、等待中、接受回复前复核授权。超时、撤销、协议错误、显式关闭和析构均回收所属进程组并等待子进程。
- 非阻塞管道按可读/可写事件唤醒；空闲管道的单次 poll 等待上限为 10ms，唤醒后复核授权，不为每条策略消息固定睡眠。这不是端到端取消时延保证。单个会话只允许一个在途调用。
- SDK 帧读取、响应结构及固定失败消息由 Rust 执行，业务处理器返回值或抛异常。插件子进程加载业务前由 Rust 设置 CPU 30 秒和文件 8MB 的 OS 上限；环境只传明确允许的变量。
- 原生生命周期调用也受期限及输出总量限制，保留安装租约文件作为 stdin。独立 supervisor 进程组不因调用返回而被回收；超时不意味着已经提交的维护动作自动撤销。

帧预算不等于任意 Python 业务对象或序列化过程的整体内存上限；宿主仍是可信本机代码模型，不是恶意代码沙箱。行情大批量应使用领域数据通道，不反复发送整批 JSON。

## 事务事件和恢复

核心表为 communication_heads、communication_events。发布接口要求与业务相同数据库的活动写事务，插件只能发布自身声明的主题。Rust 注册主题、构造事件、执行固定 SQL、分配序号并分页读取。事务票据绑定连接池、物理连接租用代次及事务代次；提交、回滚或归还连接后失效，事件发布不另开连接或自行提交。当前已接入 runtime.task.changed 和 data.version.published：任务入队、领取、进度变化、成功、失败、取消与事件原子提交（心跳和重复进度不产生刷新事件）；数据标准版本与发布事件原子提交。备份恢复的任务隔离同样产生取消事实，恢复前由 Rust 按行只读校验事件序列与游标一致性，驱动按批读取，内存只保留每个主题的末尾序号。

每个主题使用事务内锁定的 head 分配序号，锁持有到提交。因此序号较大的事务不能先提交而使读游标跳过较早事务。不同主题不承诺全局顺序；全局 auto-increment 不作为提交顺序的依据。事件载荷上限 64 KiB，批量行情走固定版本数据访问通道。

`GET /communication/events?topic=...&after=...&limit=...` 由 Rust 入口以内核事件日志实现，最多返回 500 条。`after=latest` 获取当前游标以建立快照；之后按序号重放。事件读取按主题声明的 read_path 复用现有授权，并再次通过账户访问检查；Worker 无权借此读取界面事件。主题的所有者与 read_path 由 Python 装配声明并导出到 `services/server/authorization.json`，直至发布方迁入 Rust。没有公开的任意事件发布接口。

工作台先记录各主题游标，再读取快照，避免快照与订阅建立之间漏更新。消费者刷新成功才推进本地游标，失败重试同一批；窗口重开重新建立快照。采用至少一次消费语义，不承诺 exactly-once。当前传输是有界分页轮询，没有引入 WebSocket/SSE、消息中间件或自动删除事件。尚无后台插件消费者的持久化确认、死信处理与保留期清理服务。

数据插件已有 data.sync_published hook 是参与同一写事务的业务协作，用于推进角色工作流；data.references 是引用检查。这两者不是提交后的异步广播，当前保留其原子/查询语义，不冒充已迁移的事件消费者。行情快照轮询也尚未替换成通用高频流，其背压和快照恢复属于后续实际需求。

## 结构化运行日志

`kernel/src/diagnostics.rs` 直接拥有时钟、SQLite 写入、事务修剪及读取；旧 Python SQLite 诊断实现已删除。它记录结构化标识与失败类别，不接收异常文本、调用参数、响应内容或子进程输出。业务专属诊断由所属插件解释，L4 只查询和展示。

| 记录 | 保存位置与语义 |
|---|---|
| 外部执行观察 | `.extensions/diagnostics.sqlite` 的 executions；包摘要、阶段、耗时、调用数、固定结果类别，保持现行七列事实格式 |
| 内核运行事件 | 数据目录 `.diagnostics/diagnostics.sqlite` 的 runtime_events；worker/supervisor 的固定运行错误，关联验证后的 correlation_id/request_id，无业务载荷 |

每表全局最多 200 条，单次最多读取 30 条，单数据库主文件上限 1MiB、锁等待上限 2 秒；新目录/文件权限为 0700/0600。写入、修剪在同一事务；不支持的结构或记录拒绝，不改写为另一种语义。写入失败不改变任务结果；读取失败明确报不可用，不能伪装成“没有记录”。这些记录是有限保留的运行诊断，不能用作订单、成交、资金或审计事实的权威存储。

Worker 执行失败记录对应任务的通信关联；没有取得任务时不沿用上一次任务。关联结构可以过期，记录超时不会续期或授予权限。Python `platform/diagnostics.py` 的服务状态查询与中文展示、系统 supervisor/第三方服务的 stdout/stderr 仍在各自宿主范围，没有把它们声称为已全部迁移的 Rust 日志。

## 验证与使用边界

核心机制修改的必要性：现有 hooks 和单独的进程协议无法表达统一的跨语言上下文及可恢复的事务通知。改动集中于通信、插件端口绑定、任务生命周期和传输入口；数据插件仅声明并发布自己的事实。

验证包括三语言共享契约用例、父子调用/截止时间、响应串线拒绝、事务回滚、幂等任务不重复发布事件、并发序号、真实 PostgreSQL 延迟提交顺序、事件授权、备份游标损坏拒绝、消费失败重放以及实际数据发布 API 的事件输出。桌面浏览器验证使用模拟事件源，不等同于原生打包环境联调。

当前表结构只按现行契约校验；不自动迁移或删除用户记录。未运行安装包升级、真实桌面环境重置或真实供应商请求。

### 验证记录

当次执行数量和未验证范围统一记录在[历次验证](validation/run-history.md)，旧阶段通过数字不代表当前源码。现行检查覆盖原生共享契约、上下文隔离、迟到/串线、撤销及回收、输出预算、诊断写入故障，以及真实 PostgreSQL 提交顺序和备份恢复。没有将合成来源与局部通信基准解释为真实行情、实盘或整个终端的性能验收。
