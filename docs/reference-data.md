# 期货基础数据契约（第一版）

实现：`src/asterion/data/reference.py`；JSON Schema：`docs/reference-schema.json`。
运行 `uv run python scripts/export_schema.py` 同时导出接口及基础数据契约。

## 对象与约束

- Product：交易所限定的品种 ID、名称、币种与来源版本。
- Contract：真实月份合约 ID、所属品种、明确交割年月、上市/最后交易时间、乘数、最小变动价位。郑商所三位代码的年份不靠字符串猜测，交割年月由提供方明确提供。
- SessionCalendar：按品种和版本保存交易日及完整开闭市区间；夜盘归属由交易日字段明确表达，不通过自然日或工作日推算。拒绝重复交易日与重叠时段。
- ContractRules：版本和半开生效区间，保证金比例、开仓/平仓/平今费用及平今标识，可选涨跌停比例。拒绝同一合约规则区间重叠。
- ReferenceCatalog：验证 ID 唯一性和对象引用，价格及费率使用 Decimal，时间必须带时区。

所有对象保留来源、来源版本、观察时间与本系统可用时间；可用时间不能早于观察时间。后续研究的时点选择必须同时考虑业务生效时间与系统可用时间。

## 接入边界

当前已提供模型校验、机器可读契约、不可变目录表与版本 API。数据工作区支持导入目录 JSON、分页浏览版本及合约明细；尚未接入真实数据适配器，来源声明不等于权威认证。测试中的数值仅验证结构，不作为行情或交易参数使用。现有 CSV 导入仍沿用其原有契约。

接下来由提供方适配器解析原始来源，经契约校验、版本化持久化后发布；终端只读取已发布目录。缺失日历、乘数、费用时保持缺失状态，不能用默认猜测值进入正式回测。历史修订应保留旧发布快照；本模型中的同一目录只容纳互不重叠的生效区间，跨发布时间修订需由目录快照管理。

## 版本存储与接口

`reference_releases` 保存规范化内容的 SHA-256 ID、服务端发布时间与完整目录。发布只插入，内容相同时幂等返回原版本，不覆盖旧版本。JSON 发布大小限制为 4 MB；大规模目录需后续走任务与产物发布协议。

- `POST /api/v1/reference/releases`：校验并发布 ReferenceCatalog。
- `GET /api/v1/reference/releases?limit=20&offset=0`：版本列表，limit 最大 100。
- `GET /api/v1/reference/releases/{id}`：读取明确版本的完整目录。

接口要求本机运行令牌；原生模式还要求有效账号会话。新增表按现有安装初始化机制创建，不修改旧表。当前没有可变“最新权威版本”指针，也没有自动把导入的目录参数用于回测或交易。
