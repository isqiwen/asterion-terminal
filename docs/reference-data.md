# 品种与实际合约目录

规范身份由 [instrument-catalog](../domain/instrument-catalog/src/lib.rs) 的 L2 Rust 实现提供，Python 数据类型由其 schema 生成；Schema 见 [reference-schema.json](reference-schema.json)。来源读取与证据组装仍在 Python 应用流程，持久化尚待后续数据层替换。层级见[架构](architecture.md#层级与模块)，领域验收见[期货领域基线](futures-domain.md)。

## 当前契约

目录必须显式提供 `schema_version: 2`、`inputs`、`products`、`contracts` 和 `symbols`，拒绝缺字段和未知字段。

- Product：交易所限定的规范大写品种 ID、名称、币种及来源版本。
- Contract：实际合约 ID 为 `品种ID.YYYYMM.上市日期YYYYMMDD`，例如 `SHFE.RB.202610.20251001`。交割年月和上市/最后交易日必须明确提供，不根据代码或当前年份猜测。日期不伪装成精确开收盘时间。同品种同交割月的生命周期不得重叠。`last_delivery_on` 显式提供日期或 null，未知不猜测；有值时不得早于最后交易日。乘数与最小价位由交易规则插件唯一管理，目录不重复保存。
- SourceSymbol：来源命名空间、原始代码、实际合约 ID、含首尾的有效交易日区间及独立来源证据。同一来源代码不得有重叠区间；有效期必须位于合约生命周期内。不同来源和不同年代的代码可以引用不同合约，大小写精确匹配，不自动别名化。
- ReferenceCatalog：校验 ID 唯一性、品种引用与时间顺序。信息时间必须带时区。`inputs` 保存固定标准资料版本 ID、SHA-256 和来源；人工独立编制的目录使用空列表，不冒充采集依据。

目录只负责品种与合约资料。交易日和时段由 [交易时间插件](trading-time.md) 管理，费用、保证金等由 [合约规则插件](contract-rules.md) 管理；目录不再声明或存储另一套日历和交易规则。

所有资料保留来源、版本、观察时间与系统可用时间。来源声明不代表权威认证，也不能证明历史上当时可知。

## 发布、读取与恢复

`reference_releases` 保存规范化目录的 SHA-256 ID、发布时间及完整内容。发布只插入，内容相同幂等返回原版本。文件上限 4 MB。

- `POST /api/v1/reference/releases`：校验并发布目录。
- `GET /api/v1/reference/releases?limit=20&offset=0`：列表，limit 最大 100。
- `GET /api/v1/reference/releases/{id}`：读取固定版本。
- `POST /api/v1/reference/releases/{id}/resolve`：在固定目录版本内按 `source`、`symbol`、`trading_day` 和带时区的 `information_at` 解析，返回完整实际合约及映射证据。缺失映射、无效期间或品种/合约/映射依据在信息截止时间不可知时拒绝。

接口经当前身份机制鉴权；原生模式要求有效账号会话。读取、列表与备份恢复都校验当前结构及内容指纹。错误记录明确拒绝，不自动修补、跳过或改写。界面入口为“合约资料 → 合约目录”，支持导入、版本列表、合约生命周期和来源代码映射明细。

## 从同步资料发布目录

“合约资料 → 合约目录”可以选择固定的标准合约资料版本，填写来源代码，预览后发布。也可以填写历史版本 ID；不会隐式选择更新版本。

- `POST /api/v1/reference/source/preview`：请求 `version_id` 和非空 `symbols`，只预览，不落库。
- `POST /api/v1/reference/source/publish`：同一请求，在发布时重新验证固定文件并生成目录；重复请求返回同一内容版本。
- 读取完整的当前 STANDARD `futures.contracts` schema 4；超过 10000 行或读取不完整拒绝。来源不限于 Tushare，不解释供应商后缀。
- 明确交割年月、上市与最后交易日是发布条件。允许同一来源代码对应互不重叠的不同生命周期，不从三位/四位代码推断年份。缺失信息和冲突不静默跳过。
- 目录品种标签使用标准资料中的品种代码，不从合约名称猜中文品种名。币种由来源适配器提供。最后交割日与最后交易日分别保存。
- 来源观察时间保留；目录信息可用时间不早于资料入库，不能把今天采集的资料视为历史当时已知。
- 发布校验固定输入版本、来源、类型与校验和。版本详情的引用计数包含目录；备份恢复同时验证目录输入存在、指纹匹配及源文件完整性。

Tushare 适配器保留 `d_month` 的完整 YYYYMM，并转为 YYYY-MM；缺失保留 null，非完整月份拒绝。`last_ddate` 单独映射最后交割日。[官方字段说明](https://tushare.pro/document/2?doc_id=135) 区分了这两项与最后交易日。它仍只是一种数据源。

## 已接通的身份链与边界

目录已实现完整交割年月与上市生命周期身份及有期间的来源代码映射。上市日期是身份组成部分，修订该依据会产生不同身份；不自动合并或改写已有引用。人工发布只代表输入满足契约，不代表交易所认证。

覆盖检查从固定合约资料生成并冻结目录内容、内容 ID、来源代码和信息截止时间。同源代码精确匹配；文件行情必须显式填写参考来源代码，不通过大小写或后缀猜测关联。研究（包括探索模式）必须绑定含身份目录的报告，逐根行情冻结实际 `contract_id`，并拒绝跨生命周期的单合约研究。任务执行、结果导出、离线复现和备份恢复均校验该证据，不查询最新目录。

单独日线用户入口强制选择资料并冻结身份；日线与结算具备内部提交、执行、发布和恢复门槛；规则对象固定完整规范身份，资料映射与结算预览请求使用 `contract_id`。文件导入发布、覆盖、研究、导出与恢复使用相同生命周期标识。验收范围见 [F1 身份链验收](validation/f1-identity.md)；尚未实现的正式交易对象在 F4–F6 按此契约建设。

运行 `uv run python scripts/export_schema.py` 导出接口及目录契约，再生成前端 OpenAPI 类型。

## 文件导入的身份准入

日线与日内 CSV 的 `ImportOptions.identity` 为必填：完整 `catalog`、内容指纹 `catalog_id`、`information_at`，以及非空 `bindings`（文件 `contract` → 目录 `source` / `symbol`）。工作台从已发布目录选择并显示可用来源代码；API 也可提交完整、有依据的当前目录快照，不能只提供无法验证的 ID。人工目录仍不表示来源权威认证。

每个文件代码必须且只能有一条映射，不自动匹配大小写或后缀。预览、提交、Worker 编码与服务端发布均检查逐行交易日的生命周期、证据可知性、品种及文件月码与目录完整交割年月的一致性；日内先通过时间版本确定交易日，再解析身份。资料型目录的固定输入必须存在且来源、当前类型和校验和匹配；读取源文件同时检查文件摘要。发布失败不登记快照或标准版本。

原始文件不改写。完整目录及映射随 RAW/STANDARD 的 `import_options` 保存，数据集范围 `contract_ids` 按文件逐行解析得到。覆盖检查可以另选固定核对资料，但有行情日期的实际身份必须与导入证据一致，不能通过换目录重新解释已导入的数据。版本引用统计纳入身份资料输入；恢复校验检查快照指纹、资料血缘及标准文件逐行身份。

同步与研究准备的固定身份准入见[数据源契约](data-providers.md#固定合约身份准入)。它们与文件映射共享规范生命周期身份，但不以自动匹配替代显式文件来源关联。
