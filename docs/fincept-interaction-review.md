# Fincept 实机体验与星枢交互取舍

日期：2026-09-21。对象：本机已打开的 Fincept Terminal，界面显示 v5.0.3。

本文前七节是一次实机观察及设计建议，不是已实现功能声明。星枢仍以 [AGENTS.md](../AGENTS.md)、[期货领域基线](futures-domain.md)、[界面规范](ui-style.md) 为准；后续实施记录见第八节。

## 1. 结论

最适合借鉴的是可搜索的面板入口、围绕对象的局部工具栏、研究配置与结果分区、清晰的空态下一步和可见的会话恢复。星枢应围绕“选定品种 → 核对实际合约与角色 → 更新数据 → 查看固定结果”组织这些交互。

默认工作台维持少量业务导航、一个主要内容区、按需打开的详情和统一任务入口。不要把 Fincept 的全部模块、15 组件总览、密集参数和重复状态栏搬过来。第一切片优先改善 F2 主力角色核对与更新；自由布局、更多策略和节点编排后置。

## 3. 借鉴方式

| Fincept 的可见交互 | 星枢采用方式 | 需要克制或改变的部分 |
| --- | --- | --- |
| 组件浏览器：分类 + 搜索 + 简介 | “添加面板”按已启用贡献检索；用业务名称和一句用途说明；展示不可用原因 | 不把所有插件都变成一级导航，不照搬多列大卡片；对象搜索和命令搜索分组 |
| 顶部业务入口、面板标签、局部工具栏 | 业务区承载默认工作模板；工具栏跟随当前对象，主操作只有一个 | 避免业务导航、面板名、页面标题三层重复；不让 15 个一级入口横向挤占空间 |
| 市场面板局部操作 | 表格就近提供筛选、列选择和更新状态；低频动作进入菜单 | 删除不与常用动作等权突出；不能每个区块重复整套工具栏 |
| 空态中的连接入口 | 区分“未配置来源”“没有已发布版本”“读取失败”，各给一个可执行下一步 | 不在多个空区重复展示同一连接要求；保留“导入本地文件”正式入口 |
| BUILD / RESULTS / RISK / TRADES / HISTORY | 研究以“配置 / 结果 / 运行记录”组织，结果内部再分指标、成交、校验 | 不提前堆上优化等未验收能力；无结果时提供“返回配置”按钮并保留草稿 |
| 配置旁解释单位、禁用不适用字段 | 只展示当前对象和能力需要的参数；关键单位与阻断原因靠近字段 | 不照搬长篇说明和所有资产参数；期货规则由固定规则证据提供，不能用手填乘数、统一保证金率绕过领域校验 |
| 局部 LOADING、LAST UPDATE 与全局 ONLINE | 服务连通、数据时效、任务执行、交易时段分别表述；加载留在对应区域 | ONLINE/LIVE 不能证明报价实时、完整或可交易；`--` 必须能解释是未知、缺失还是不适用 |
| 带时间的会话恢复列表 | 恢复前显示时间、面板数量、不可用扩展和恢复范围；允许保留原状态后进入新工作区 | 恢复只恢复视图与业务引用，不提交任务、不恢复下单意图，不自动迁移不支持的状态 |
| 黑底、细分隔线、等宽数字 | 继续复用星枢主题令牌、行高和语义色；主信息优先获得空间 | 不复制当前观察到的小字号、低对比度说明和密集彩色标题；不根据单次截图推导固定字号数值 |

## 4. 首个可落地切片：主力角色工作区

### 主视图

在已有角色插件内，把“版本选择器 + 诊断全文”收敛为可核对的结果表。默认列为：品种、主力实际合约、次主力实际合约、适用交易日、来源类型、状态。自行计算与供应商报告必须显式区分，不能合成一条无来源的“当前主力”。

品种名和合约简称用于阅读，完整身份可在详情复制；简称不能成为内部唯一标识。无可知性证明的报告在主视图保留“仅回顾分析”标签；缺口、冲突、来源失效不能折叠成普通详情。角色结果不授权交易。

表格中的“适用交易日”不能代替观测日或更新时间。顶部简短摘要显示当前查询范围、来源和最后一次读取时间；生效开盘及观测时间在选中行的详情展示。固定历史版本和“查询最新”必须可辨认。

### 操作路径

1. 选择品种及来源，查看已有角色结果；点击行打开详情，并保留表格位置。
2. 对已有计算版本提供“更新主力角色”。提交前的紧凑区域显示本次观测交易日、预期生效点、候选范围、连接和规则摘要；缺失必要证据时显示具体阻断原因。
3. 连接或规则需要改变时才展开配置。一次提交后显示真实阶段，例如“采集候选日线”“计算角色”；没有进度总量时不伪造百分比。
4. 主视图保留阶段、异常摘要和“查看任务”；子任务与恢复操作进入统一任务中心。刷新视图不能启动采集或计算。
5. 成功后提供“查看新结果”；固定历史查看保持原版本，“查询最新”模式才更新到新结果。失败保留最后已发布结果及其交易日，明确说明本次没有生成新结果。

这里的更新仅涵盖现有固定来源与计算版本支持的后续流程，不把按钮改名等同于已实现任意首次发布、任意历史补算或定时更新。没有版本时，只提供当前真实可用的创建/来源准备入口；尚未接通时明确说明缺什么，不显示无法完成的按钮。

### 详情与异常

详情分为“合约与生效时间”“选择依据”“固定输入与来源”三个区块。主力/次主力、来源类型、使用限制和阻断错误在主视图也能看到；候选排除、规则参数、完整版本标识、校验和、原始 JSON 按需展开。

| 状态 | 主视图文案和动作原则 |
| --- | --- |
| 无配置 | “尚未配置此来源”，进入对应来源设置并保留所选品种 |
| 无已发布结果 | 明确没有结果，不显示虚构主力；链接实际可用的准备流程 |
| 正在提交 | 主按钮忙碌，阻止重复提交；保留本次请求身份 |
| 提交响应丢失 | “正在确认提交结果”；按原请求查询/恢复，不自动创建新任务 |
| 部分采集失败 | “候选数据未齐，本次未生成新结果”；可查看失败任务，只有后端支持时才开放恢复动作 |
| 读取状态失败 | “暂时无法确认进度”；不直接标记业务任务失败 |
| 来源证据失效 | 显示阻断原因；既有结果标注不再通过当前核验，不能继续发布或执行 |

## 6. 实施顺序与验收

| 优先级 | 有界范围 | 完成证据 |
| --- | --- | --- |
| P0，服务 F2 验收 | 角色结果表、选中详情、单一更新入口、任务摘要 | 固定真实样本能核对角色/交易日/来源；来源异常与未知可知性可见；刷新或重开面板不重复提交 |
| P1，必要共享交互 | 业务内空态跳转、统一局部加载/错误/时效、任务定位 | 不丢失对象/草稿/筛选；只打开关联任务；键盘可以选行、进入详情并返回 |
| P1，实际出现需求时 | 当前契约的视图恢复与不可用面板占位 | 重开后恢复视图引用，无业务提交；状态不支持时保留原数据并报错；保存失败明确可见 |
| 后置 | 搜索式添加面板、命名工作区、聚焦模式、更广的研究布局 | 至少两个真实面板共用贡献入口；可发现、可关闭、可恢复、无业务硬编码；不抢占 F1–F6 基础实现 |

首切片建议用 1280×800 与 1440×900 两种窗口验收紧凑/舒适密度：主表可读，必要日期、来源和阻断状态不靠悬停才能获取；详情只展开一次即可查看完整证据。进入已有角色结果后，用一个主操作打开更新确认，确认区一次提交即可受理；这是目标路径，尚未实测星枢点击数。

验证至少覆盖无数据、来源未配置、证据失效、部分候选失败、响应丢失和成功发布。成功发布的真实性与跨月正确性仍按期货领域基线验收，不能用界面流畅或单元测试代替。

## 8. 维护者调整与 Dashboard 首切片

2026-09-21，维护者要求先做 Dashboard；本节更新前述实施顺序。先将已有能力组织成总览入口，再收敛主力角色子页面，不以此扩展尚未验收的期货业务。

实施前再次体验本机 Fincept Dashboard：打开 `+ ADD`，观察到 43 AVAILABLE、搜索框、分类筛选和带用途说明的组件目录；按 Escape 返回，未添加组件或保存用户布局。本切片采用分区标题栏、局部操作、总览到业务页的入口和真实空态；组件增删、拖拽及布局保存尚未实现。

实现位于内置 `overview` 插件：

- 固定数据版本、执行/排队数量、失败任务数量、历史研究环境组成简短状态区。
- 历史行情预览支持在总览切换固定版本和合约，再打开完整图表；显示来源、数据范围、交易日和非实时标识。
- 数据版本表支持按合约/来源筛选，点击在原页预览；任务区显示待关注或最近任务，完整管理复用任务中心。
- 最近完成展示任务插件提供的结果摘要；期货角色和研究提供明确入口；未接入交易网关时不显示虚构资产、持仓或收益。
- 目录读取失败保留旧记录但显示状态待确认；无结果、无匹配、加载及行情读取失败分别呈现。

依赖经插件清单声明；历史图表从市场插件公开入口复用。工作流插件传递现有快照、任务、读取状态及导航回调；机制核心没有新增 Dashboard 分派。未改后端契约，未提交采集、研究或交易任务。

验证：生产前端构建通过（仍有大 chunk 提示）；31 条前端单元测试通过；Dashboard 的固定版本预览/键盘选择/筛选/业务导航、读取失败保留记录、空态三条浏览器测试通过。1440×900 和 1280×800 截图已检查，无页面横向溢出。使用隔离 API fixture 验证交互，不代表真实来源、打包桌面或实盘验收；未安装新包替换用户应用。
