# Trading既有持久证据的领域冷备与恢复

本文件定义并记录已实现的Trading持久证据冷备链路。账户观察审阅当前交付见[固定事实交接](trading-facts-handoff.md)，整体进度见[实施矩阵](reviews/data-paths-implementation-2026-10-21.md)。不决定A02跨节点唯一执行或A03失联政策，不恢复授权、不登录、不发送委托。

## 真实范围

当前Trading拥有journal.sqlite、archives不可变事件段、声明使用的风控程序，以及facts内ADMITTED/PUBLISHED固定观察、原件与可读回执。该账本并不具备完整柜台成交/资金流/结算/估值历史；冷备只能保存实际存在的证据，不能由备份补造这些事实。旧执行主程序身份未记录时继续显示缺失，不拿当前安装程序填旧尝试。

业务Owner由所选Agent的稳定节点/服务身份确定，账户和环境由已持久非秘密头部确认；固定事实中已有的Owner必须逐一匹配，不能因移动目录重标。历史头部未记录的来源身份单独列限制，不将部署位置作为跨节点对象身份。

## 拥有权与一致切点

比较两个路径：让SQLite普通只读事务持续持有多文件备份，或让账户已有串行writer持有专用的物理账本文件租约。前者的WAL协调与文件区发布不能仅靠一次只读查询形成同一切点，且容易在备份/恢复位置创建SHM；选择后者，复用kernel FileLock，不建新服务/任务/账本。

租约放在已声明的facts侧目录，空协调文件不充当资产、引用或删除权威。AccountJournal writer在任何账本/事实写入前独占，在全部writer工作结束后释放；冷备只取得已存在租约的共享锁，锁缺失或正在写入即拒绝，不创建替代空账本。它保护同一物理目录的数据库和文件发布；已有全局账户执行锁仍负责账户绑定，二者不替代，不扩大为跨节点唯一执行保证。

冷备保持租约直到既有Cut完成预览/保存。仅在拥有者已停止、WAL/rollback日志无待恢复内容后使用既有cold_read_only。SqliteJournal内提取共同的既有结构检查，提供只读检查回调；不复制一份SQLite格式解析器，不启动AccountJournal writer、LiveSession或CTP。检查事件序列、永久命令/订单索引、归档声明和原固定事实决定；未确认或损坏状态明确保留并报告。

## 清单、依赖与不包含范围

- journal.sqlite、每个被声明的sealed事件段、固定事实的已知暂存/对象/回执和实际使用的风控工件逐项列明。拒绝未知正式文件、符号链接、身份不符与已发布原件缺失。
- ADMITTED但未发布的意图与原件按实际状态保存。原件确实缺失时标明确恢复限制，不用当前账户观察替换；PUBLISHED缺原件不称有效完整备份。
- 发布回执必须对应原账本决定、Owner/id/version、账户和环境，不能仅凭对象文件存在宣布发布。
- 不保存密码、认证码、密钥、当前有效授权许可、全局账户执行绑定、进程/租约有效状态、日志和CTP运行缓存。历史授权/撤权事件属于原账本证据，必须保留，但恢复不激活它们。非秘密账户范围及政策/原执行记录保留。恢复空租约文件不恢复任何执行许可。
- Trading可声明其真正已发布trading_facts对象，供现有跨域Cut将Research输入的精确源依赖标included。Research持有完整输入与Trading源账本恢复分别核验；缺选Source或旧原程序身份仍显示局限。

## 管理与恢复流程

沿用Terminal现有本机备份维护入口：用户选择已经停止的Trading及可选Research → 领域检查并持锁预览 → 展示账户/环境、范围、缺口、空间与原件 → 显式保存到新目的地 → 独立恢复到新目录 → 逐域结构、固定事实及依赖闭包校验。Manager/Agent只提供选中服务的稳定身份、目录及停止观察，不读或转发业务载荷，不实际停止用户服务。

恢复保持原Owner、账户/环境、操作ID与版本，不覆盖源目录，不绑定原账户到新位置、不启动程序或SDK。激活真实账户仍需独立业务流程，不能以恢复验证绕过已有绑定或授权。

## 验收与实施顺序

先补现有writer与领域冷检查的同一物理租约，再实现精确文件/回执与风险工件清单；随后复用跨域Cut、Terminal选择及独立恢复检查。测试仅隔离合成账号/事实/事件/测试风控程序：运行writer拒绝冷备，持锁期间新writer拒绝；数据/索引/目录在只读检查前后不变；多个事件段和未完成固定事实能按原状态恢复；已发布原件或索引被破坏时拒绝；Trading与Research联合切点只对确切依赖included；恢复后不登录、不恢复授权、不发委托。最终再做真实进程/浏览器闭环，而不是只验证一个文件复制工具。
