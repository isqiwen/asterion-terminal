# 数据生命周期与历史访问

本文件定义数据版本、发布、读取和保留约束，并标明迁移中的实现边界。固定 L2 `kernel/futures/data-store` 拥有数据版本与访问语义，导入采集编排属于 Rust L3 `services/data`；连续加工语义属于未来的固定 L2 `continuous`。当前同步发布、覆盖与研究准备仍有 Python 实现。唯一模块列表见[模块与层级](architecture.md#层级与模块)，替换范围见[当前代码归属](engineering-structure.md#当前代码归属)。

## 对象与存储

采用 RAW 原始、STANDARD 标准、DERIVED 加工三个语义层级。发布是版本状态，不是第四份数据；缓存、暂存和日志不属于权威版本。连续序列和研究特征分别由其领域所有者生成，不能因保存为表格就转归数据插件。

| 对象 | 职责与固定依据 |
|---|---|
| 来源/连接 | 来源能力、配置修订、凭据引用；任务固定配置，公开产物不含秘密 |
| 数据集 | 长期逻辑身份：来源、类型/schema、对象范围、频率和必要的单位/时间语义 |
| 采集运行 | 请求范围、任务/租约、分段、观测时间、原始工件和检查点 |
| 版本/分区修订 | 完整清单、父版本、分区引用、范围、行数、校验和、来源与替代关系 |
| 工件 | 不可变内容、hash、大小、格式与受限存储引用 |
| 覆盖/质量报告 | 固定输入、检查依据、逐项结果、缺口及无法确认的原因 |
| 血缘/引用 | 消费者及其必要输入版本、工件和保留理由 |

PostgreSQL 保存目录、任务及引用等元数据，大体量行情保存为不可变 Parquet。消费者通过公开能力和固定清单读取，不查询其他插件私有表、通配磁盘目录或把物理绝对路径写入研究定义。DuckDB 等分析引擎按测量需要采用，不是当前必需组件。

目标中的数据集身份不因下载起止日期改变；日期属于运行与版本覆盖。当前日线/日历/分钟已有累积系列，RAW、合约资料、结算、映射及文件导入仍是采集范围快照。当前 API 连接 ID 参与数据范围隔离；来源身份策略变更须替换完整契约，不能偷偷合并不同连接或供应商的历史记录。

标准行情使用规范实际合约身份，保留来源代码与映射。过期合约属于历史研究范围，不能只保留当前在市合约。schema、单位或时间含义变化形成新的明确系列，不向已有版本补默认值。

## 采集、发布与修订

1. 固定请求、来源配置/插件版本及分段计划，取得租约。原始资料可保留尚未解析的来源代码；可执行标准行情必须固定规范身份。
2. 每段响应先持久化原始观察，再登记检查点。成功接收不等于结构或覆盖通过；空响应、权限、限流和网络错误分别保存安全状态。凭据和远端原始错误不能进入证据或日志。
3. 标准化固定映射、schema 与代码版本，核验字段、单位、主键、合约、日期/时段和可知性。失败保留已确认的采集证据，不发布可消费版本。
4. 工件完整写入、fsync 并校验后，在有效租约和数据集并发约束内登记版本、来源边与成功状态。过期或取消租约不能发布，重试内容必须与原证据一致。

工件读写统一经 L1 `ArtifactStore`：同名只写一次，相同字节的重试幂等，不同字节拒绝；读取按清单记录的摘要和大小核验，缺失与内容变化分别报错。同步的原始证据、非累积标准表和分区索引按内容寻址存放在 `datasets/<任务>/` 下，过期租约的旧尝试只会写出新文件，不能改写已提交版本引用的字节；旧版本仍按清单记录的路径读取。清单已在数据库中登记，不再另写 `rows.json`/`manifest.json` 副本。L1 只保证字节身份，内容语义与引用关系仍归所有者；引用登记与回收尚未实现。
5. 研究或派生运行固定具体输入版本；后续发布不改写旧输入和结果。取消任务不撤销已经成功发布的版本。

当前分段观察独立于已发布 RAW 数据集，保留插件返回的声明字段，不是完整 HTTP 字节归档。续传仅复用明确前序任务或同任务先前尝试中通过重新校验的分段，保留原始观测时间；规则见[数据源与续传](data-providers.md#采集证据与续传)。

累积发布在数据集锁内读取父版本：日线/日历按月、分钟按交易日。只读取与合并本次触及的旧分区，未变分区复用原工件。相同主键按来源观测时间择新；同一观测时间内容冲突拒绝，更早响应不回滚较晚修订，未返回记录不推断删除。跨来源冲突保留各自事实。

合并、日历缺口、分区编码、索引核对和分区读取由 Rust L2 `data-store` 执行（`MergeRequest`、`read_index`、`read_partition`、`verify_version`）；Python 应用层只负责数据库锁、父版本查询、类型校验和发布登记。分区值限字符串、整数与空值，同列混用即拒绝；列类型按值确定（全空为 Null），与此前 pyarrow 写出的分区互读。父版本分区字段集合必须与本次采集一致，不一致即拒绝，不补列或丢列。索引必须与版本记录的 `partitions` 完全一致，预览、分钟核对、恢复读取和备份核验均执行此检查。

例如 V10 引用 A…H，新增月份形成 V11=A…H+I；修订 F 形成 V12=A…F2…I。固定 V11 的研究继续读 F。处理重跑固定输入、算法/代码、参数、schema、环境及随机种子；新结果不得冒充原运行。

逻辑分区与物理文件分离。压实必须写新文件和清单，不能改变旧版本所引用的内容。当前分区粒度是已实现切片，分钟大规模压实阈值仍需测量。

## 覆盖、质量与时间

事件时间、交易日、来源发布时间、本机观测时间和研究可用时间分别保存。今天下载的历史数据不能自动获得当年可知资格；来源未提供的信息保留未知。

覆盖依据固定合约生命周期、日历及日内时段。缺日历、缺身份、无权限、请求失败、空响应和确认缺口不能混为一谈；行数与首末日期不能证明中间完整，无成交和休市须有独立依据。报告绑定输入和检查规则，再次核对生成新报告，不改写原结论。

当前日线报告区分有记录、缺口、休市、生命周期外、依据不足、当日未完成和冲突。同源同步使用同连接的固定依据；文件数据显式关联外部依据并保留说明。确认缺口可手动补齐，提交时用原报告依据重查并跳过已补日期，不扩大原授权范围；成功下载仍须重新核对。文件缺口须修正并重新导入，不跨源自动补入。

分钟直接下载供应商 1/5/15/30/60 分钟，固定单实际合约、单交易日、时间版本和 bar 起止口径。1 分钟可核对预期时间戳；其他周期的供应商跨休市分段及短柱规则未验，覆盖返回 UNVERIFIED，不补零。具体接口和真实来源边界见[分钟采集](data-providers.md#多周期分钟实际合约采集)。

## 固定版本读取

数据插件当前通过 `data.versions.scan(ScanRequest)` 提供 STANDARD 日线扫描：一个固定版本、规范合约 ID 集合、交易日区间、列和 1–4096 行批次预算。非法字段、身份、范围或格式失败，不用截断冒充完整数据。研究提交及复现包的本地版本解析已使用此端口，预览仅用于展示。

扫描按清单裁剪月份、按 Parquet 日期统计裁剪行组，只解码请求列及身份/来源必需列。选中工件先流式核验完整 hash 与行数，因此解码裁剪不等于省去完整压缩字节读取。批次遵循清单及文件内顺序；消费者负责所需排序，关闭迭代器释放文件。备份证据端口不提供在线扫描。

当前研究将选中区间排序并冻结为任务行列表，仍限单合约、最多 5,000 行；大版本的小区间可运行，选区超限失败。它不等于无限流式回测，也未接通分钟研究扫描。验证见[日线扫描验收](validation/history-scan.md)。

目标批量读取应进一步支持明确的版本集合、频率、时间范围及有界资源预算。长计算由 worker 执行，任务传工件引用；不能让研究持有来源凭据或在运行中静默补数。缓存按固定版本、范围、字段及规则标识；核验缓存失效或文件改变时必须重新检查。

## 多合约历史下载

当前“数据 → 数据同步 → 批量下载”仅支持日线，复用既有同步任务、租约、发布、取消与重试。计划固定连接、交易所、合约资料、日历、代码集合及日期，按唯一实际身份的上市/最后交易日裁剪，再按月份分段；不按星期猜交易日。上限100个代码、十年、1,200个合约月份，所选资料不代表全交易所完备。

预览不入队；提交完整校验并冻结一次配置，在同一事务批量登记。相同命令和输入重发返回原任务，不同输入冲突。计划保存在首个任务载荷中，重试沿用现有任务链；刷新不会再次提交。界面恢复最近20个计划，任务中心负责进度、取消和逐项重试。

显式核对覆盖只选择本批及重试任务的成功输出，同一合约取其中最高累积修订，使用计划原日历/资料生成固定报告。不选择后续无关发布，不把部分成功显示为完整；任务变化后须重新核对，旧报告保留。身份或日历不足拒绝，空响应不补造数据。已完成离线API与浏览器模拟验证，真实供应商批量采集未验，见[历史下载验收](validation/history-downloads.md)。

## 业务目录与展示

当前业务树按交易所 → 品种 → 实际合约/角色 → 频率或类型 → 来源 → 加工阶段组织。交易所公共资料单列，无明确身份的资料进入未分类；路径键使用完整规范身份，不猜短代码年份。树是已发布版本的逻辑视图，不移动或复制磁盘文件。

目录列表、版本历史、业务目录与版本预览由 Rust 数据服务库 `services/data` 实现：入口直接提供 `/data/catalog`、`/data/catalog/{id}/versions`、`/data/hierarchy`、`/data/versions/{id}`，Python 的 `DataLibrary.list/history/hierarchy/preview` 经绑定调用同一实现。预览按记录的摘要与大小校验工件，读取分区、Parquet、来源证据与 CSV；行保持存储的列顺序，日期时间为 ISO 文本，小数为数值；工件缺失、校验和不一致或格式未知时明确拒绝。`GET /data/hierarchy` 与目录的 `directory` 过滤先于分页；多合约数据集可在多个节点引用，祖先计数去重。选中合约表示包含该合约的数据集，预览不冒充逐行过滤。角色树由角色插件公开接口贡献，数据服务不读其私有表；未实现连续版本不展示空分支。

目录按需展示当前最新版本，归档过滤在确定最新后执行，不回退旧版本假装最新；历史详情仍可读。目录查询当前遍历最新元数据，不扫描行情工件，尚无持久业务索引的规模验收。

累积日线图表是固定版本投影（`storage=version`），读取时加载必要分区；独立文件图表使用 `storage=parquet`。两者均校验当前存储契约，最多1,000行的图表查询不是研究扫描。发布检查父清单与触及分区，不能因此宣称全库巡检；备份核验全部引用工件。

## 归档、引用与恢复

当前归档单独保存状态及修订号，以CAS变更；不改写版本、文件、报告或输入指纹。相同请求重试幂等，旧窗口不能覆盖新状态。归档只是整理目录，不阻止固定ID读取或累积同步，不释放磁盘；新版本默认未归档。

归档与引用摘要由 Rust 数据服务 [lifecycle.rs](../services/data/src/lifecycle.rs) 实现，入口提供 `/data/versions/{id}/lifecycle` 与 `/archive`；不再经插件钩子收集。引用摘要固定统计：数据血缘、导入与同步身份、覆盖报告、历史计划（仅在非零时列出），以及参考发布、合约规则、合约角色（角色版本、自算版本、续算任务与同步工作流依赖）、研究任务/文档/复现包（始终列出）。规则、角色、研究的计数暂随数据服务实现，读取这些模块的表，待其迁入 Rust 后移交各自服务。引用记录无法解析（如工作流依赖的任务不存在）时明确拒绝，不按零计数。跨账户只显示计数，不泄露记录详情。它不是完整依赖闭包，也不是可删除证明。所有数据版本仍禁止永久删除，尚无并发安全的工件回收。

目标保留机制必须将研究、角色、派生结果、待执行任务及备份所需祖先纳入保护；引用登记与删除竞争需事务协调。物理字节去重统计与版本逻辑大小分开；有效数据不能按缓存TTL清理，磁盘不足不能擅自删除受保护文件。孤儿/暂存只能在宽限期与引用核验后回收。

已实现本机一致备份、新目录隔离恢复及受保护的环境切换/回滚，具体格式、安全与操作以[备份与恢复](backup-and-restore.md)为准。备份成功须有实际恢复验证，不能仅检查压缩包存在；旧记录不因设计重组被迁移、清空或覆盖。

## 性能与未完成项

- 增量合并已有120万行合成单次基准，仅证明受影响月份优化；缓存、压缩率、硬件和未测范围见[增量验收](validation/history-merge.md)，不能推广为真实下载或全系统吞吐。
- 待完成：分钟批量计划与研究扫描、连续加工接入、独立分钟质量制品、物理容量/保留规划、并发安全回收、分钟压实和千万行规模测试。
- 规模验收应记录固定硬件/构建、冷热缓存、数据/文件量、扫描字节、峰值内存、耗时与磁盘增量；合成规模与真实来源语义分别验证。
- 大版本的小范围扫描在相同批次预算下应保持有界内存；分区合并只读取触及数据体，manifest成本单列。并发发布、中断、磁盘不足、旧版本重读和恢复必须同时通过。

以上工作服务于[期货领域 F1–F6](futures-domain.md)，不另建第二套下载路径或以目录重组代替领域交付。
