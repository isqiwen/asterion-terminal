## 首条能力与选择

先做已有 CTA 的双均线规则：输入为按顺序已完整结束的收盘观察，价格量纲为一次价格；快慢窗口包含当前观察，`0 < fast < slow <= 10000`。输出必须显式声明为目标方向符号 `-1/0/+1`；零明确是平仓方向目标，预热不足则没有可决策输出，两者不能混同。此处只核对逻辑，数量、合约、成本、风险及实际成交属于后续真实回测。

比较过两条实现路径：直接创建通用规则 DSL 会同时引入解析、条件排序、状态语义及特征依赖；另建预览结果状态机会重复既有任务的接纳、取消、恢复和发布。首条选择复用当前 CTA 纯计算和 Research 原任务机制：共享同一双均线算法产生实际比较与中间证据；服务持有固定定义和样例，试算成为本域的有界任务。现阶段不称通用结构化条件、受限表达式组合、模型、事件触发或交易执行已支持。

## 固定样例与因果边界

- 虚构样例只存于 Research，不写 Data 的行情、标准数据或观察归档，不作市场表现/收益证据。试算不创建账户、不调用交易引擎，不生成真实委托。
- 每个样例须保存名称、教学/逻辑核对用途、固定定义以及 **事先明确** 的逐行预期。预期 oneof 区分预热与方向，合法零不得被遗漏字段替代；方向不在 `-1/0/+1` 明确拒绝。
- 最多 512 个观察，收盘 Decimal 明确存在；零与负数合法。虚拟完整边界时间严格递增，输入可得时间必须明确且不晚于相应决策边界；不把来源未知或未来数据补成当时可知。
- 首条只接受完整收盘观察，不模拟逐 tick、未完 K 线、事件或模型。延迟/缺失或其它字段不在能力内时定位输入并保留草稿，不静默插值、改成零或改用其它算法。
- 先持久保存固定预期，再接纳试算。预期不符是“计算完成但核对未通过”，不等于执行失败；计算异常、取消、未开始分别采用原真实任务状态，不填零或删除失败行。
- 双均线决策继续采用原精确比较；展示均值及差值是科学解释值，明确其精度，不把浮点展示用作金额或重新推断方向。实际原窗口、中间值、原方向及缺失原因在服务计算时保存，UI 只读原产物。

## 准备、任务及交接

服务复用原串行元数据 journal 和根锁，固定定义/样例操作以明确操作 ID 幂等；同 ID 不同内容冲突。试算使用原 TaskStore 固定输入及实际 Research 程序留存；未知回执查询同一任务，不能更换 ID 自动重提。重启不自动重跑，原预期、尝试及已发布产物保持不变。

规则/样例先保存，任务接纳确认其 Owner、精确内容和未弃用状态。实际使用记录不能由名称相同或事后内容相同推断。后续交回测时须固定逻辑引用、显式数量/方向映射及真实 Data、资金、成本和风险；逻辑通过不代替这些条件，旧回测不能被追认使用新逻辑。首条阶段先完成保存到真实试算与页面/恢复，再接实际回测绑定。

## 冷备与验收

冷备包含定义/样例权威、原任务/预期/结果、原程序及引用闭包。缺固定对象、错 Owner 或错程序时不完整，不能用当前内容补原证据；独立恢复不启动任务或恢复交易权限。测试仅用隔离合成根目录。

验收按同一纵向路径推进：

1. 共享现有双均线纯算法；四个虚拟观察可得到预热、预热、`+1`、`-1`，修改最后观察不改变此前结果，均值/差值来自实际计算。
2. 保存定义及事先预期、固定任务接纳/真实计算/原产物/重启；错误预期和改参数产生可区分的新证据，原失败不被覆写；零输出、暖机和错误分开。
3. Native、策略逻辑页面及真实进程/浏览器；没有隐式行情取得、账户或委托；字段错误保留草稿。补统一目录、依赖及独立冷备恢复。
4. 当前支持的逻辑再显式交接真实回测，固定引用和程序谱系可从正式结果核对。此路径完成后继续模型/完整评价等矩阵缺口，不以单均线试算代替全部规则需求。

所有修改按白名单分组，写前校验及写后审查，保留既有未提交内容；不提交、推送、部署，不操作真实数据或运行服务，不调用真实供应商/外部模型/交易。A02/A03 与正式结果物理删除仅暂停依赖路径。
