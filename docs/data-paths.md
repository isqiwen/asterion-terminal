# 统一数据通路与业务交接

状态：2026-10-21 用户批准的目标架构；不以本页宣称功能已实现。逐项状态、代码证据及验收见[实施矩阵](reviews/data-paths-implementation-2026-10-21.md)。本页细化需求的对象、保存和协议约束；实盘执行归属、监控失联政策等 A02/A03 仍须独立定案。

## 目标与不变量

默认全部在本机运行，Terminal 可显式选择其他节点。统一应用数据根目录、管理入口、对象身份、版本、引用及生命周期；不强制一个数据库或格式，不新增默认必需 Storage 服务、NAS 或数据库服务器。

业务域拥有语义和写入、发布、删除决定。跨域不得写私有库。Manager 管登记发现，Agent 管本节点进程；二者不接管业务任务、不搬运大批数据。统一资源索引可由拥有者重建，只是投影，不能作为无引用或允许删除的唯一证明。

对象采用稳定的节点、服务实例、对象及固定内容身份；显示名、安装版本、进程 PID、Socket 路径和运行代次都不是对象身份。跨节点身份不含机器绝对路径。来源修订生成新内容，旧引用保持原义；断线、重试、复制和重命名不重置研究选择历史。

## 对象目录与权威

| 域 | 对象与主要输入 | 权威输出/发布与消费方 |
| --- | --- | --- |
| Data | 来源原件、标准行情、基础材料解析、日历规则、加工定义与质量 | 原件/标准数据/质量/数据集不可变快照；Intelligence、Research、Trading只消费允许用途的固定内容 |
| Market | 来源连接、实时事件、合约订阅 | 带流身份、序号/缺口及时间的实时流；归档需明确交接 Data，关闭可选全量归档不能关闭必要决策证据 |
| Intelligence | Data材料引用、模型方案、候选、消耗与人工核验 | 核验、事件关系、发布/更正/撤回事实归 Intelligence；固定可读字节存 Data；正式消费须有发布确认与时点条件 |
| Research/分析 | 固定数据/情报、样本、假设、特征/标签定义 | 观察、选择历史、拟合及候选依据；不直接授权交易 |
| Research/策略 | 变量、规则/模型、组合预算 | 固定策略包、模型及参数、初始化与归属政策；交回测或运行准备 |
| Research/回测 | 固定策略、数据、规则、模拟及风险条件 | 实验、批次、尝试、决策、模拟成交与账本；交评估 |
| Research/评估 | 固定截止的回测/模拟/真实事实 | 指标、归因、情景、限制和报告；不改源账本；需要新模拟时回交回测 |
| Trading | 固定运行包、Market、许可情报、柜台事实、账户政策 | 真实订单、成交、资金持仓、授权与风险占用；只读固定切片交 Research；本地实时模拟与真实实例隔离 |
| 管理/界面 | 拥有者清单与观察 | Manager节点登记、Agent部署、Installer安装登记各自权威；Terminal草稿/偏好/已读不是业务权威 |

Research四个模块共享研究域的身份、谱系、事务机制和适当存储，不按 UI 模块创建四套库。计算内部特征矩阵、拟合模型与报告是 Research 产物；若要作为可独立复用的数据产品，再显式发布到 Data 并登记来源，不复制权威或隐式变成公共资产。

## 格式选择、schema 与目录

| 数据性质 | 当前选择/约束与理由 | 不采用为默认权威格式的候选 |
| --- | --- | --- |
| 事务元数据、任务/引用/发布记录 | 所属域 SQLite 事务与稳定操作身份；索引和决定同域提交；有界单写入者 | 不要求外部数据库；一个共享多域数据库会破坏写入边界 |
| 大型列式行情/特征表 | 不可变 Parquet，明确列类型、单位、Decimal精度、时间语义与范围；原有市场 Parquet 继续使用 | Arrow IPC 可用于有实际消费者的批传输，不默认作为长期仓库；CSV只作明确有损/受限交换 |
| 固定输入、结果及控制消息 | 类型化 Protobuf、领域校验和固定内容摘要；大表只放引用，不放 JSON字节数组 | 通用 JSON 任意对象不能绕过类型和业务合同 |
| 原始材料 | 保留原始字节、媒体类型、来源/时间/权限与摘要；解析产物独立引用原件坐标 | 不把PDF/HTML/图像强制转为Parquet或以OCR文本替换原件 |
| 模型与大型二进制 | Research不可变产物及类型化清单，声明算法/格式、输入schema、训练范围、依赖及兼容能力；仅支持实际算法产生的格式 | 不假定所有模型可无损转ONNX；不从序列化文件自动执行任意代码 |
| 可编辑配置与导出 | JSON用于明确schema的配置/人读清单，导出标明范围；不是唯一可恢复备份 | 导出报告不能冒充包含原输入/依赖的复现包 |

schema 是当前明确结构及能力标识，不引入内部 V1/V2 格式计数、旧格式读取器或自动迁移。不支持的记录保留文件并明确报错。内容摘要不能代替可读取的输入和领域校验；优先复用既有摘要，不增加全库扫描或重复完整性账本。

应用根沿用已配置的本机/远程节点根；正式业务位于 `<root>/services/<service>/ledger/`，运行配置位于 `<root>/config/services/<service>/`。部署登记、日志、缓存、临时数据分开；已有用户根、实例目录和数据不因本设计自动改名/搬移。

Data现有 `history/`、`tables/ledger.sqlite`、`tables/objects/` 和 `acquisition-tasks/` 保持各自用途；Research现有 `tasks.sqlite`、固定输入/结果及事件段是研究库已实现部分。新原件/模型目录只有实际能力落地时才创建。可删缓存必须可重建且不被固定对象当作唯一证据；未确认产物、备份原件和未知引用不是可自动清理缓存。

## 读取、发现与任务固定

Research可在没有Data的情况下部署、启动并读取自身结果。任务准备通过已有 Manager/Agent 查询候选与端点，按任务实际数据引用解析，不能要求永久服务配对，也不能随机取清单首项。候选唯一且满足引用/用途时可解析；多个来源需要任务已有选择或返回明确歧义。

任务接纳固定 `Data对象所有者 + 对象/快照身份 + 选择范围/schema/时间/用途 + 内容/输入摘要`，研究产物固定来源、参数、算法/插件及实际观察历史。服务发现只刷新位置，不改变这些身份；Data不可用时仅阻断确实需要它的步骤。已有完整固定内容的任务不依赖一个全局Data心跳。

本机可用受控只读句柄/路径访问已验证不可变内容，必须由拥有者解析并约束归属、长度、类型和生命周期，不打开跨域私有 SQLite。远程走同一业务合同的分页/分块数据请求；不会把本机绝对路径当远端对象地址，不静默下载替代数据、不自动换源或切换执行节点。

首期实现须明示传输支持集合：同节点IPC、远程Terminal访问同一远程节点的业务服务、跨业务节点读取分别验收。没有权限/地址解析支持的跨节点组合明确拒绝，不能仅删表单即标完成。

## 业务协议与状态

| 操作 | 请求与成功条件 | 幂等、失败与恢复 |
| --- | --- | --- |
| 发现/解析 | 服务类型、稳定拥有者/对象选择；返回经过身份核验的端点及可用状态 | 发现不接纳任务、不证明字节存在；歧义/不可达/不支持分开返回 |
| 目录/读取 | 固定身份、字段、范围、用途和分页；返回实际版本/schema/时间/完整性 | 同一查询固定版本与顺序；无数据、无权、损坏、缺依赖不同；不回退最新 |
| 准备内容 | 稳定操作身份、原件/计算产物及声明依赖；持久内容但未公开 | 相同身份查询原进度；不同内容冲突；响应丢失不制造第二份对象 |
| 登记固定引用 | 内容身份、消费者拥有者/对象、操作身份、用途 | 内容拥有者持久登记；成功前消费对象不得宣称可用；失败/未知保留待确认 |
| 确认业务对象/发布 | 固定内容与已确认引用、原准备操作 | 各业务拥有者先持久决定；Data按可查询决定公开；重复确认返回原结果 |
| 解除引用 | 消费者持久解除的证据、原关系身份 | 保留合法历史义务；未知/失败不自动释放，不以离线推定无引用 |
| 删除预览/执行 | 明确对象/操作及预览；执行时同一拥有者写入边界重新核对引用与在用状态 | 新引用与删除互斥裁决；受阻/已删除/未知明确；仅隔离测试验证物理删除 |
| 订阅 | 消费者、流、范围、起点、用途，声明最新值或逐事件连续 | 流身份/确认游标/缺口/滞后可见；慢消费者有界；暂停订阅不等于撤销已交付事实 |
| 备份准备/导出/恢复校验 | 拥有者确认的固定切点、依赖闭包、对象/文件/schema/摘要/范围清单 | 跨库和文件一起核对；未完成发布保留原状态；恢复独立目录、不覆盖现有数据、不恢复交易授权 |

错误使用现有类型化边界：invalid_request、not_found、permission_denied、conflict、unavailable、resource_exhausted、cancelled、operation_failed；额外业务原因放明确类型化字段，不解析诊断文字判断结果。操作状态需区分未受理、已受理、结果未知与终态。超时不能撤销已经开始的持久提交；查询可有限重连，副作用不盲目重试，按原操作身份核实。取消是请求，等待实际停止与持久确认；已发布内容不因取消撤回。

超时使用既有协议期限并随具体操作列出；不为新功能默许无界等待或把整个大文件塞进单帧。批次、载荷、读取/执行池、缓存与订阅均须有实际容量约束及背压，不从“最多两个任务”推导硬RSS上限。

## 跨域提交与崩溃恢复

采用业务特定的可查询提交顺序，不引入通用分布式事务平台：

1. 消费方保存准备意图/固定身份；内容方确认不可变内容和引用保留。
2. 消费方持久提交自身业务对象/发布决定；确认前不显示完整可用。
3. 内容方根据原持久决定完成公开或引用确认；双方按同一操作身份查询。
4. 任一步崩溃、回复丢失、内容方离线均保留最后确认事实与继续入口，不换内容、不重算掩盖未知。
5. 已登记引用而业务对象未提交的残留须有核对/合法解除入口，不能自动当垃圾或无期限隐藏。

Data采集发布、Intelligence发布及Research/Trading固定引用分别落实这一合同，不能把Data采集已实现的状态机冒充其它链路已完成。

## 统一管理、保留与备份

管理入口聚合各域清单、占用、引用、任务及维护状态；索引丢失可重建，不能因此丢失资产或绕过删除保护。数据/研究/账本及其最小证据按业务依赖保留，缓存/临时/诊断有独立规则，不做默认自动业务资料淘汰。

备份必须覆盖对象、事务元数据、原始文件、未完成决定、引用及算法/程序依赖闭包，声明完整/部分/受阻。活跃SQLite主文件的直接复制不算一致备份。由拥有者提供一致切点，或按明确冷备份流程停止自身写入；多个域不能拼接无共同依据的运行期文件。恢复在独立位置验证所有者、内容和依赖，保留原备份和现有数据；恢复成功不等于可重新交易。

跨域业务凭据和权限不因统一根目录而合并；秘密不进入目录摘要、对象导出、日志或普通清单。没有真实用户数据的清理/迁移演示；测试仅使用隔离目录、模拟来源和虚构账户。

## 实现顺序与非目标

先实现任务级Data解析，随后引用/发布/删除、目录与备份、消费者和UI一致性；每阶段同步协议、拥有者、调用方、测试与现行文档。完整情报、训练与其它未实现算法只定义数据合同和实际状态，不能以占位服务宣称完成。A02/A03、真实来源额度、生产部署、自动主备、透明双向同步、全局去重与任意跨节点权限不属于本次批准的自动实现内容。


## 引用登记的当前实现合同

首条实际链路为 Research 固定输入引用 Data 的分钟版本和表快照。`resource.Owner` 固定 domain/node_id/service_id，`resource.Object` 固定 kind/id/version；Research 任务的 version 为已存输入摘要。DataRetention 明确 DataOwner、消费对象与完整的版本集合；消费对象稳定身份相同而输入或版本集合变化是 conflict，不能覆盖原引用。

Data 在自身 `retentions.sqlite` 事务库保管 PREPARED/CONFIRMED 两个保留状态；两者都保护内容，不因超时或消费方离线自行释放。prepare 在内容已发布后登记，重复相同请求返回原事实；confirm 只确认同一输入的消费方提交，不改变版本或重新发布。get 按原消费对象查询，未受理与回复丢失不能混为一谈。定位和进程代次不进入主键，聚合索引丢失不解除保留。

Research 在自己的固定输入旁先保存引用准备意图，再请求 Data 保留，随后提交任务账本；执行领取前确认该持久引用。崩溃残留必须保留并可核对，不能因未见聚合索引或进程退出清理。合法解除、删除预览与执行、残留恢复入口及备份闭包另行接入同一业务状态；仅实现保留不代表这些步骤已完成。此合同不给通用客户端一个无条件解除其他域引用的接口。


合法解除必须由消费域的持久决定证明，不能接受请求方自称解除、查无任务或失联推断。Research 的未入账准备可明确放弃，其决定进入既有任务 SQLite 的 preparation_decisions；已接纳任务不能走这个入口，决定及对象身份在输入目录清理后仍保留，原身份不能复活。Data 主动查询消费方的 ReleaseDecision，再将相同保留登记置为 RELEASED；该历史行保留，重复解除幂等，再准备/确认同一已解除身份为 conflict。解除消费引用与删除 Data 自身对象是两件独立的拥有者决定。


放弃未入账准备不抹掉研究接触历史：preparation_decisions 与解除对象身份在同一事务保存原小型执行定义和固定输入摘要，输入载荷清理后仍能说明实际准备过的样本范围、候选参数、来源和谱系。历史观察记录与仍需保管原内容的引用不能混为一谈；解除保管不把样本重新标成未接触，也不宣称保留了可完整重放的已放弃实验。


### 分钟版本删除裁决与恢复

首条删除路径只覆盖 Data 自有不可变分钟版本，不包含表快照（前缀依赖必须单独处理）。预览合并具名数据集、采集任务记录及跨域引用权威；任一依赖存在即阻断。预览不是授权令牌，执行仍在同一 Data 对象队列与目录写入屏障内重新核对。活动读取完成前不能进入删除；新引用先提交则删除受阻，封存先提交则新引用、读取和重复发布均拒绝。

选择文件存储拥有者的持久封存记录，而不是只从可重建索引移除条目：先保存原 HistoryRecord、原始分钟清单及 PENDING 决定，再由有界文件线程清理载荷，最后持久确认 REMOVED。保留最小来源证据，不级联删除任务、具名数据集或研究记录。封存元数据不可用不得解释为不存在删除决定；首次封存前持久记录该权威必须存在。崩溃后同一版本可显式继续 PENDING，不能重新发布或接纳新引用。重复 REMOVED 返回同一事实。清理失败保留封存和剩余内容，不称完成。实现及测试结果以实施矩阵为准。


### 一致冷备与独立恢复的首条实现路径

先支持明确选择的本机 Data / Research 资料范围；Trading、Market、Intelligence 未接入拥有者适配器前，不得将其列入完整备份。完整指所选范围及声明依赖闭包完整，不等于全机器镜像。远程备份另需拥有者传输协议，不通过 Manager/Agent 搬运业务文件。

在在线一致切点与冷备两条路径中，首条采用需求允许的冷备：操作只接受已由使用者停止写入的资料，按稳定拥有者顺序取得各域既有所有权锁并持有至校验结束；不自动停止服务、不修改源库。最后一个锁取得时形成共同不变切点。无法取得锁、存在需要所属服务恢复的未完成 SQLite 日志或必需依赖缺失时明确受阻/部分，不能直接复制活动主库称成功。

共享文件组件只负责新目标内的持久复制、清单与字节校验；各业务域提供允许文件、固定对象/引用、未完成决定和算法依赖。Data 授权原件、凭据库、节点信任/TLS/私钥、运行套接字、持锁状态、日志及临时缓存不进入普通备份，也不读取它们的秘密内容。未知文件不得被通配复制进正式备份。程序和插件依赖必须有可核对身份及实际可恢复条件；无法满足时列为缺项。

目标必须为新的独立目录，不覆盖工作资料或已有备份。中断保留明确未完成的目标；最终清单仅在全部选择文件持久写入并校验后发布，缺少最终清单不得显示可恢复。清单只含相对位置、拥有者、对象/版本、格式、尺寸、内容摘要、依赖和排除说明，不将源机器绝对路径用作跨节点身份。

恢复先对完整清单和内容逐项校验，再写入新位置；文件机制的复制完成之后，所属域还要核对 schema、拥有者、文件/数据库关系、固定引用和位置解析，才可报告该域恢复有效。复制成功不等于业务恢复成功。已有绝对本机定位字段须通过当前域定位解析落实到新位置，不将恢复变成静默修改原资料或历史格式迁移。恢复不登记/启动服务，不重放任务、交易、授权或订单。实现结果由实施矩阵逐项记录。


分钟记录和封存证据中的绝对目录只是原本机定位，不参与跨节点内容身份。当前读取器校验其合约/来源/频率/采集叶目录后，在拥有者当前根目录下解析位置；不访问原根、不改写原发布/准备字节，也不改内容摘要。表对象本身已按内容身份在所属根下定位。恢复校验必须让原目录不可用后实际读取候选内容，不能让原件存在掩盖副本缺项。这个位置投影不是历史格式兼容或自动迁移。


当前读写协调协议需要的空锁文件按 `coordination` 结构槽位声明，必须为零字节；复制产生新 inode，不保留持锁、PID、租约或进程状态。恢复后的只读核验用这些新槽位阻止并发写入，仍不启动或登记服务。这避免了为恢复引入绕过正常所属域锁的特殊读取路径。


冷备域核验在持有停止域锁且无待恢复SQLite日志时，使用不可变数据库读取，禁止核验本身生成WAL/共享内存旁文件；在线只读连接仍保留正常WAL可见性。恢复前先验证原备份的领域schema和双边引用，再复制并核验独立候选；不得依靠删除未知旁文件使清单通过。

未完成备份的持久计划可从管理入口读取，但不算完整产物。续跑前重新通过既有Manager观测解析原稳定所有者，重新取得全部域锁并比较当前文件/对象计划；内容变化则受阻，不能套用原确认或覆盖同一路径。独立恢复中断保留候选，使用新的独立目录重试，不覆盖已有资料。容量只显示当前测量和预计内容字节，实际持久发布仍以全部复制及校验为准。

### 表快照维护的前缀存活规则

表快照不是一份独立文件，而是`tables/ledger.sqlite`的固定前缀。每次修订的Parquet对象可同时被多个快照读取；快照身份退役与对象物理回收必须分开。不能按快照SHA删除同名文件，不能删除修订行、重写哈希链或使后续快照悄悄回退到更老分区。

对某分区的修订r，设下一次相同series/exchange/period修订为n，则它在所有序号q满足`r.sequence <= q < n.sequence`的快照中可见；没有n时上界为当前头。只有这些前缀均已明确退役，且没有当前头、命名数据集、外域DataRetentions、未退役采集任务或进行中发布持有，才允许回收该对象。相同对象SHA还可能出现在别的分区/修订，必须合并其全部可见区间。单个快照退役可能释放零字节，界面必须如实报告。

退役决定应保留原快照身份、序号和哈希链证据；拒绝新引用与解除旧引用、发布及删除必须由Data同一目录裁决保护。现在分区`verify_partition`写文件与`record`发布分属文件worker和串行writer，维护实现必须覆盖整个写入至发布窗口，而不只是锁住删除瞬间。待删除对象不得在中断恢复前被新的发布再次引用，否则恢复删除会破坏新版本。冷备必须包含退役决定、原链及仍需保留的全部对象和来源证据，恢复校验不能把缺失文件当成已退役。

Data自有采集记录生命周期先行：终态才可明确退役，完整授权/尝试/输入/结果仍保存，不发起下载、不退款、不删除产出；历史查询保留该记录，活动持有查询独立排除已持久退役者。该能力不是表快照删除本身，也不能代替外域引用检查。正式Research结果物理清理仍按待决边界处理。


当前实现将表快照封存权威放在本域`tables/retirements.sqlite`，`retirements.required`阻止权威缺失时重新创建空权威。决定保存快照/序号及精确独占对象清单，先封存、再逐对象校验与回收、最后确认；失败保留PENDING，显式恢复仍核验对象不被任何可用前缀引用。只回收Parquet，不删除修订链、原始响应或独立重取观测。被封存的前缀不再接受跨域快照引用；缺失/未知权威或未提交采集必须先恢复，不能按空持有放行。

分区刷新原合同中的`TableRefreshTarget.previous_snapshot`实际上标识单个分区的修订，而不是完整视图前缀。该修订的元数据及来源证明始终保留；若仍是当前分区，它也仍可经当前头读取。完整前缀退役不能误禁这种元数据固定目标的刷新，亦不允许它变成对已退役完整视图的新引用。正式任务以自己记录的固定目标、内容摘要和结果/独立观测核验；Data持有查询与完整视图Retentions分开检查。

Data端将分区文件准备至持久发布的整个窗口持有目录写裁决，受控表读取、命名引用和跨域引用按同一屏障排序。命名数据集在实际提交时再次检查版本可用性。客户端提供快照身份输入、精确预览、当前头/本窗口草稿/命名数据集/采集/外域保留阻断、独占字节和对象清单、明确确认及封存续跑入口。单纯退役身份不承诺释放磁盘块；共享对象继续保存。存储5项、Data定向12项、TS/lint/UI159已通过，端到端正在验收，不提前宣称全链路完成。

表快照执行还绑定预览范围摘要：稳定node/service、快照ID、账本序号和排序后的独占对象清单共同确定一次确认范围。其它前缀退役后清单变化，旧确认必须冲突，重新预览后才可执行；占用字节变化不替代对象范围校验。PENDING续跑沿用原持久对象清单。清单按256条分页，索引/界面列表不成为删除权威。
