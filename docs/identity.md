# 账号与验证架构

默认采用本地账号模式，不依赖邮件服务器或云端账号管理服务器。账号保存在本机 PostgreSQL；注册、验证、登录、退出和密码重置仍经过账号 API。普通用户不承担邮件配置，登录页和设置窗口均不提供邮件配置入口。

## 当前行为

- 注册创建本地账号，然后进入验证码页面；输入任意 **6 位数字**即通过。页面明确标识本地模式，不声称已发送邮件或验证邮箱所有权。
- 密码重置同样使用本地验证。验证请求仍需对应存在的账号和有效挑战，保留过期和一次性消费；重发在本地模式立即可用。
- 密码继续使用随机盐和 scrypt；登录验证密码，未确认账号不能登录。账号会话仅保存在窗口内存，有效期 12 小时，退出或重置密码会撤销相应会话。
- 桌面后台固定要求账号会话访问数据查询、导入及任务取消接口，后台 worker 保持独立的运行凭据和租约。

## 服务边界

`identity/routes.py` 定义稳定的账号接口；`identity/service.py` 负责账号持久化、密码、挑战和会话；`identity/verification.py` 通过统一接口提供两种验证策略：

| 策略 | 发信 | 验证规则 |
| --- | --- | --- |
| LocalVerification | 不发送 | 接受任意 6 位数字 |
| EmailVerification | 通过邮件适配器发送 | 只接受正确、未过期、未消费的验证码 |

服务器配置 `ASTERION_ACCOUNT_VERIFICATION` 取值为 `local`（默认）或 `email`。客户端通过 `/account/capabilities` 获取模式以展示准确提示；客户端不能选择或降低验证策略。邮件配置接口已从用户 API 移除，SMTP 适配器留作未来服务端部署使用。

正式邮件策略保留系统安全随机验证码、HMAC 摘要存储、10 分钟有效期、5 次尝试上限和 60 秒重发间隔。发信失败回滚注册，不会自动降级到本地验证。

## 后续服务化

接入正式账号中心时，复用现有注册、验证、登录、重置和会话协议，将身份服务部署到受控服务端，由运营方管理发信凭据。当前本地账号的确认不代表邮箱所有权，迁移到正式服务时需要重新验证邮箱，不能直接信任本地确认状态。

当前所有账号共享本机工作区，尚未提供云端账号同步或多租户数据隔离。浏览器开发模式沿用运行令牌连接；桌面模式的账号要求不受此影响。

## 验证

`tests/test_identity.py` 同时覆盖本地无邮件注册/任意验证码/重置以及正式邮件的严格验证、过期、次数限制、会话撤销和 TLS 发送适配。`e2e/account.spec.ts` 覆盖两种模式的页面提示与流程。

`scripts/smoke_desktop_runtime.py` 使用临时数据目录运行打包后的 PostgreSQL、API 和 worker，通过真实 API 完成本地注册、任意验证码确认、登录及受保护的数据导入。测试不发送外部邮件，不修改用户账号。

## 同一桌面进程的多窗口会话

宿主在内存集中持有账号会话及修订号，新窗口读取并向账号 API 校验，无需重复登录。窗口每秒同步宿主状态，并每分钟重新确认后台会话有效性；退出后其他窗口清理已加载数据并回到登录页。账号会话不写入 localStorage 或磁盘。

会话更新使用比较修订号的方式避免晚到请求覆盖新的登录/退出状态。退出应用后宿主内存释放，重新启动仍需登录；关闭单个窗口不影响其他窗口的登录。
