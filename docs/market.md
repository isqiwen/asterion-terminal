# Market 行情与数据服务

> **当前实现：** Market 是一个纯 C++ 服务进程，统一实时行情、录制、历史采集与正式仓库读写；进程内以有界线程和队列分工，不附带 Python 运行时或采集子进程。C++ 仓库与固定版本读取、Tushare 与交易所采集模块、任务管理器已实现；双向证书认证及有权限的远程采集控制已实现；Terminal 数据页及 Lab 固定版本研究读取已接入；录制分钟研究版本发布已实现；部分来源和真实柜台录制仍待在线验收。模块边界见[目标架构](architecture.md#market-内部职责)，实施顺序见[开发计划](plan.md)。

`asterion_market` 是独立 Linux 服务，负责 CTP 实时接入、合约目录、事件流、当日分钟线与全市场录制，
提供多客户端读取及获准客户端的采集管理。Terminal 保存服务地址、证书指纹与自己的自选，不启动行情进程，也不保存或提交 CTP 行情凭据。
部署见[Market 录制与部署](recording.md)。历史采集由 Market 实现，[Lab](lab.md) 按固定版本读取并缓存；已有用户 Lab 仓库不会自动接管或搬动。

## 独立安装模式

`asterion_market --installation <root>` 从 `<root>/config/market.json` 读取
`bind`、`port`、`clients`、`acquisition` 和 `counter`（`market_front`、`trade_front`、`broker`、`user`、`app_id`）。
CTP 库位于 `<root>/lib/ctp-md.so` 与 `ctp-trader.so`，持久数据位于 `<root>/data`。
密码与授权码只从 `CREDENTIALS_DIRECTORY` 下的 `asterion.ctp.password` 与
`asterion.ctp.auth_code` 读取；缺失配置、库或凭据拒绝启动。日志仍由可执行文件所属安装目录的
`config/logging.json` 配置。

服务自动登录并查询目录、订阅全市场；同一条归一事件流同时更新实时状态与录制。
客户端不能登录、断开或重配柜台连接，也不能修改服务级自选列表。
每条 `watch` 请求可携带自己的 `instruments`（最多 50 个，空列表表示全市场）；
筛选只影响这一条流的返回数据，不改变供应商订阅、其他流或录制。改变筛选时新建流，首帧重新给出完整基线。
目录、行情、分钟聚合和录制文件仍由服务统一拥有，客户端只拥有筛选与游标。
客户端连接关闭只释放自己的流，不影响其他客户端和录制。服务只有独立安装入口，没有桌面子进程模式。

同一个 Market Protobuf/TLS 接口（`service_id=market-data`）在快照、持续推送、
事件流和当日分钟线之外，提供 `recording_status`、`recorded_days`、`recorded_minutes`。
历史查询使用独立的有界单线程执行器；录制写入和收盘文件合并也分别执行，
待合并日期的目录扫描与文件合并均在后台线程执行，行情状态线程只调度和读取进度。服务正常退出会保存当前未完整分钟并标记为 partial，
再次启动后可查询前一实例的录制片段。

## 仓库与固定版本读取

`apps/services/market/warehouse/` 实现六种表的分区写入和读取：日线、日历、合约、分钟线、结算参数与观测段。
沿用 Parquet 字段和 `DECIMAL(28,6)` 精度；日期、布尔值、整数和缺失值按各自类型保存。
写入拒绝超出范围或需要舍入的数值，不经浮点数转换价格。Tushare 仓库在 `<root>/data/warehouse/`，
其他来源在 `<root>/data/sources/<provider>/warehouse/`，来源之间不混用。

每个来源由一个 `Store` 拥有写入锁。内部写入器先持久化完整分区，再发布不可变版本清单，最后原子更新 `current`。
放弃尚未提交的写入不会改变当前版本；旧版本引用的文件不修改、不删除。读取直接使用指定清单，不跟随之后的 `current`。
写入器供 C++ 采集模块使用；远程只能提交有权限的采集任务，不能上传任意数据或写任意路径。

同一 Market 端口提供以下只读请求，契约位于 `protocol/proto/asterion/dataset.proto`：

| 请求 | 行为 |
| --- | --- |
| `datasets` | 分页列出已有仓库的来源及各自当前版本，不表示供应商能力目录；每页默认 64、最多 128 个来源 |
| `dataset` | 读取指定版本的分区目录，可按表和交易所筛选；每页默认 128、最多 512 个分区，响应最多 1 MiB |
| `dataset_file` | 按指定版本、分区键和字节偏移读取原始 Parquet，每块最多 1 MiB；返回总大小与文件摘要，不接受任意路径 |
| `dataset_summary` | 返回同一版本各表的分区数、行数和日期范围；合约表日期取上市日，不把范围当成连续完整覆盖 |
| `dataset_coverage` | 必须指定版本，分页返回品种 × 月份的日线天数及已存日历中的开市天数；每页默认 64、最多 128 个品种，无日历的月份保持未知 |

首次 `dataset` 查询可省略版本以取得当前版本；后续分页和文件下载必须带回该版本。
不存在的指定版本明确失败，不回退到最新版本。客户端各自持有筛选、版本和游标；重连可继续读取同一版本。
分区的 `days` 是采集日记录，不证明盘中完整性；分钟线的 `partial` 与观测段仍保留原语义。
所有仓库读取与录制历史共用有界历史执行器（一条线程、最多 8 项排队），不在实时状态或 I/O 线程扫描文件。
Terminal 数据页已经调用来源、概要与覆盖接口：先读取概要固定版本，全部覆盖分页保持该版本。
Lab 研究和行情历史图固定 Market 版本，按需下载只读缓存；录制分钟可先在 Market 发布为 `recorder` 研究版本。

## C++ 历史采集与任务

`apps/services/market/acquisition/` 直接请求供应商和交易所，不调用 Python 或另起采集进程。
来源能力由各 C++ 模块定义，不能借用另一来源的数据填补缺口：

| 来源 | 当前原生采集能力 |
| --- | --- |
| `recorder` | 本机录制分钟与观测区间发布为固定研究版本，无须额外来源配置或凭据 |
| `tushare` | 合约表、期货交易日历、日线、单合约 1 分钟线 |
| `shfe`、`ine`、`czce` | 各自交易所的日线与结算参数 |
| `dce`、`cffex`、`gfex` | 各自交易所的日线 |

交易所日线以实际上游标识区分来源；已有用户仓库不搬动、不重写。
Tushare 的官方接口为
[`fut_basic`](https://tushare.pro/document/2?doc_id=135)、
[`fut_trade_cal`](https://tushare.pro/document/2?doc_id=467) 和
[`fut_daily`](https://tushare.pro/document/2?doc_id=138) 与
[`ft_mins`](https://tushare.pro/document/2?doc_id=313)。
合约以交易所、品种和交割月标识；主力和连续代码不当作实际合约，郑商所重复年代代码按当日上市合约归属。
JSON 数字保留原始十进制文本，成交额从万元转换为元；无成交开高低与对应收盘价保持缺失。
日线和目录达到接口单次行数上限时明确拒绝，不把可能截断的回答入库。

Tushare 分钟线必须指定 `EXCHANGE/product/YYYY-MM`，按合约与交易日分区，不宣称覆盖整个交易所。
按起日向后 27 个自然日预取、每页最多 8,000 行；满页继续分页，重复或越界时间明确失败。
只缓存当前任务最近一个合约窗口。分钟结束标签转换为北京时间下的分钟起点，再存为 UTC 毫秒；
夜盘按日历归入下一个开放交易日，不能把自然日直接当交易日。成交量须为非负整数，
不将成交额推算为均价；缺失仍缺失。分钟起点标签、非整分钟或错误合约的应答拒绝入库。

Tushare 生产传输固定到 `https://api.tushare.pro`，验证服务器证书，不跟随重定向、不自动重试；
响应最多 8 MiB，请求总期限 60 秒，可取消连接与读取。一个账户的请求预算由各任务共享，
每分钟额度为 1–500；等待额度也可取消。任务记录和错误回复不含 token 或原始供应商错误文本。

交易所适配读取官方 JSON、CSV、分隔文本和郑商所早期年度 ZIP，统一保存精确十进制。
上期所、能源中心、郑商所使用 HTTPS；中金所、大商所、广期所使用其公开 HTTP 接口，均不携带账户凭据，
不自动切换域名或协议。普通文件最多 8 MiB；年度 ZIP 只读取指定成员，解压上限 32 MiB，
不将归档路径写到文件系统。同一采集任务复用最近一个年份的归档，取消或结束后释放。
保留郑商所 2015-11-12 前后的日期文件与 2010-08-24 及以前的年度归档选择规则、GB18030 解码。
TAS、EFP、期权和汇总行不混入普通期货日线。交易所日线的成交额仍为空，避免混淆各源计量单位。
上期所与能源中心保证金原值为比例，手续费比例除以 1,000；郑商所保证金百分数除以 100，
比例手续费除以 10,000，按手手续费保持元/手。这些是交易所公开参数，不是券商账户实际费率。

任务由 Market 拥有，最多两个任务并发，每个来源最多一个。任务接纳前持久化请求，
编号不可复用；任务写入 `<root>/data/acquisition/<id>.pb`，没有客户端连接身份或凭据。
状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled` 或 `interrupted`。
重启将未完成任务标为 `interrupted`，不会自动重发请求。客户端退出不会取消任务；取消需要明确的管理操作。
任务记录写入失败时查询明确报错，不能继续显示为正常运行。

日线任务先取得所需年份的日历和合约表，再按开放交易日补缺；当前年份日历重新采集。
数据按交易所和月份合并、发布版本；刷新只替换已取得数据的日期，其他日期与旧版本保留。
空回答仍是缺口，下次可以再采集；取消或失败会保存此前已取得的日线。
单独采集日历按年写入，合约表按交易所写入；不为它们重复遍历每个工作日。
任务范围以北京时间的当天为上限。分钟线、交易所日线和结算参数按工作日读取，逐个非空分区发布；
已存分区默认跳过，刷新生成新版本。404 只表示未找到发布文件、保留缺口；412、其他拒绝和解析失败使任务失败，
已经发布的数据保留。没有日历的来源不能凭工作日或空回答推断节假日与覆盖完整性。

`acquisition_sources` 返回已启用来源的可采集表、交易所，以及当前证书的 `can_manage` 权限；不返回凭据、额度或供应商配置。
已停用来源的已有仓库仍通过 `datasets` 提供读取，不因停止采集而消失。

Market 已接入 `acquisition_task` 与分页的 `acquisition_tasks` 只读请求，与仓库读取共用历史执行器。
`acquisition_start` 提交不含凭据的采集请求，`acquisition_cancel` 明确取消指定任务；两者只接受 `manage` 角色。
服务接纳后即拥有任务，连接断开不会取消任务，也不自动重发。结果未知时按原任务编号查询；重复编号明确冲突。
来源启用、限流及凭据在主机配置，不提供远程供应商配置或 token 写入接口。
隔离测试覆盖分钟分页与夜盘日期、不同格式与费用单位、取消和故障后的发布行为，
以及只读写入拒绝、双向证书错误拒绝、任务断线存续与凭据不进入回复。
research 已通过 TLS 提交上期所真实日线任务：管理客户端退出后服务继续发布版本，只读客户端可查询结果。
原生任务已读取 2026-10-30 的真实公开文件：SHFE/INE/CZCE/CFFEX/GFEX 日线分别为 301/63/243/28/48 行，
前三者结算参数分别为 301/63/243 行，均写入临时仓库；郑商所 2015-01-05、2016-12-27 日线各 134 行也已验证。
Tushare 未配置真实凭据；大商所日线与郑商所 2010 年归档当前返回 HTTP 412，不能记为在线验收通过。
Terminal 数据页直接使用 Market 的采集任务；Lab 只读已发布版本。
真实账户尚未配置，尚未正式部署。

## Terminal 连接

在“设置 → 数据源 → Market 行情服务”生成本机证书（与 Trading 共用 Terminal 身份），
将指纹在 Market 主机登记为 `read` 或 `manage`；再填写主机、端口和安装脚本显示的服务端证书指纹。
连接采用 TLS 1.3 双向固定证书指纹，不接受明文连接、未登记客户端或不匹配的服务证书。
角色来自握手验证的证书，不接受请求中的自报身份。权限配置在服务重启后生效，现有连接随重启关闭。

Terminal 将地址、服务端指纹和最多 50 个自选合约存入 `terminal/data/market.json`；
本机私钥留在 `terminal/data/tls/client.key`，不进入 UI、快照或请求。
旧的缺少证书指纹的配置明确报错，不自动修改。连接失败保留配置，界面提供重连；断开只关闭本客户端连接。
修改地址或自选不更改服务配置、供应商订阅、其他客户端或录制。
数据页直接访问保存的 Market 地址，不需要先打开实时行情或启动 Lab。界面使用生成的 Market Protobuf 类型，
通过原生层的 `market.data` 转发标准 ProtoJSON；原生层持有证书、验证回复身份，服务端按握手证书决定管理权限。
读取、采集和取消均不自动重发。页面保留本次提交的任务编号，结果不明确时可在共享任务表中核对。
只读客户端仍能查看共享任务，不能启动或取消；页面每三秒刷新数据与任务，
即使当前客户端没有发起任务，也能看到其他客户端的工作。切换来源、离开页面或关闭 Terminal 不取消服务上的任务。
Terminal 关闭时先停止接纳本机请求并结束已接纳操作，再释放应用状态，避免未完成的数据请求在析构后继续访问它。
所有采集使用 Market 主机上的来源配置和凭据，Terminal 不提供供应商凭据输入。
Lab 以本机保存的客户端证书直连这些只读接口；回测、扫描、滚动验证、因子与结果图表固定版本，
下载缓存缺失时读取原版本，不能用最新版本替代。选择「Market 录制」并填写合约和交易日后可发布录制分钟研究版本；该操作需要 manage 权限，关闭客户端不影响任务或录制。

数据页的“Market 录制监控”直接读取所连服务的录制状态：交易日、订阅数、本次启动的写入计数、
磁盘余量、最后接收与落盘时间，以及写入丢失、目录查询和文件合并错误。仅在页面打开且连接可达时轮询，
每次最多一个查询在途；换地址、换实例或断开后丢弃旧结果。失联显示状态未知，不继续展示旧的正常状态。
计数不能证明过去时段或全部合约数据完整，也不控制服务启停。

## CTP 实时行情

服务通过 `apps/services/common/market/ctp` 连接 CTP 行情前置；交易库只查询合约目录，不发送交易命令。
目录与全市场订阅由服务自动维护，客户端不能登录、断开、查询重配或修改全局订阅。

- **报价字段**：最新价、买卖一及 2–5 档、开高低、昨结算、昨收、涨跌停、持仓量及日增仓、成交量、交易日、单位均价。缺失值保持缺失，不补零。
- **事件流**：服务保留有界的有序报价事件（断档、断线和乱序都会标记），供分钟线和最近报价曲线使用。单个订阅的确认或拒绝只记录该合约的状态，不重复复制全市场订阅；会话变化仍记录完整订阅状态。

行情服务的合约目录按独立修订号发布为不可变快照。每条持续连接首先取得完整目录，后续只有目录版本变化才再次传输；重连重新取得完整目录，Terminal 拒绝无法对应当前服务实例与已持有版本的省略响应。心跳只读取连接阶段，不复制报价与目录。持续连接的首帧与订阅集合重置包含全部报价；其余帧携带前一帧序号和变化的合约行。Feed 只扫描轻量行修订号，分钟聚合有独立修订号，晚于报价生成的涨速及中断后的清空也会单独发布。Terminal 校验连续基线和合约身份，按索引更新缓存；后台发布与界面轮询均先按修订号筛选，再复制变化行。命令响应仍提供完整快照，交错到达的旧行情帧不会回退已发布状态。事件流的断档标记与容量限制保持有效。

### 当前服务线程与接入

客户端连接由一条非阻塞 I/O 线程接收和发送；请求、目录结果发布与分钟聚合由一条
行情状态线程串行处理。查询快照不再触发全市场订阅，目录修订到达后由状态线程应用乘数和订阅。
连接最多 64 条，持续推送最多 32 条；普通请求队列 64 项，心跳队列 4 项。
持续推送每次只生成一帧，发送完成后再生成下一帧，正常更新间隔 250 毫秒。慢客户端不积压待发送快照，
单帧发送超过 2 秒会断开；重新连接必须从完整基线开始。

停止时 I/O 线程关闭接入，完成已接纳回复并结束持续推送，再由状态线程释放资源。
正常退出等待资源完成；20 秒期限用尽后直接结束进程，不提前销毁仍被 SDK 使用的对象。
实时 Feed 和合约目录共用一条固定 SDK 线程，拥有动态库加载、API 创建、初始化、请求和释放。连接请求
先接纳，再通过状态报告初始化结果；旧 API 释放完成后才建立下一实例，等待期间状态与 I/O 线程继续工作。
SDK 回调只复制带实例代次和入口接收时间的固定供应商结构体；行情线程每轮至多转换 1,024 条。
原始队列最多 65,536 条，满额或入队失败时进程退出，由 systemd 重启后重新登录、订阅并继续录制；
不把丢失原始事件伪装成正常完整行情。归一报价、订阅状态、事件序号和分钟聚合均由行情线程写入。

合约目录使用增量查询：SDK 回调入队，SDK 线程每轮至多处理 1,024 条目录事件，等待供应商响应时
释放执行容量给 Feed。先过滤非期货及非活动合约，目录原始队列限于 32,768 条，最终目录最多
20,000 个活动期货合约；溢出明确失败。Feed 和目录各最多一项在途 SDK 工作，共享执行器排队容量为 2。
缓存读取、验证与写入也在 SDK 线程进行；初始化期间健康可应答，普通请求及推送首帧等待缓存完成。
损坏缓存明确报告错误且保留文件。SDK 调用或释放本身仍可能阻塞该线程，I/O 与行情状态继续推进。

实时接入由 I/O、行情状态、SDK 三条线程负责；另有历史读取、文件合并、录制写入及两条采集工作线程。线程数不随客户端连接数增长。
供应商自建线程另计。详细执行进度健康与总资源字节预算仍待补齐，物理线程数不代表全部架构验收。

### 均价

CTP 的 `AveragePrice` 在郑商所是单位均价，其他交易所是成交额／成交量（含合约乘数）。服务用合约目录中的乘数归一；乘数未知或当日无成交时不报告均价。

### 当日分钟线与 1 分钟涨速

服务从有序事件流构建每个合约当日的 1 分钟线（`core/domain/intraday_bars`）：

- 开高低收取最新价；分钟成交量是累计成交量的差值，交易日第一条观测只作为基准。
- 事件断档、断线或累计量回退时标记“曾中断”，当时正在形成的和之后的第一根分钟线标为不完整；换交易日重新开始。
- `first_observation_ms` 标明服务开始观测的时间，更早的分钟未知，不补齐。
- 1 分钟涨速 = 最新价相对同一交易日内至少 60 秒前最近一次观测的百分比；不足 60 秒或中断后为空。

当日实时序列保存在服务内存中，服务重启后从头观测；已落盘的历史仍由录制接口读取。终端通过只读命令 `market.minutes` 查询。
返回的序列写明是哪个行情服务、哪个实例观测的（`service`、`instance_id`，与快照里行情部分的同名字段一致）；查询期间行情服务的选择变了，这次查询以冲突拒绝，不把原服务的序列交给界面。分时图和分钟 K 线按“合约 + 行情服务 + 实例”认定一条序列：换了行情服务或服务重启后清空重读，同一时刻只有一个查询在途，写着别的服务的应答不采用。

### 录制

Market 内部录制器保存全市场 Tick 与分钟线，没有独立 Recorder 程序。文件格式见[行情录制](recording.md)。

### 分时横轴

分时图按 `config/futures-sessions.json` 的交易时段排布横轴，左轴价格、右轴相对昨结算百分比。未列入该配置的品种只按已观测分钟排列。
