# 终端界面

## 视觉语言

极简、科技感、未来感。信息优先，装饰让位于数据。

- **底色**：近黑的深空底（`--canvas`），面板只用 1px 发丝线和极轻的明度差分层，不用厚边框和阴影堆叠。
- **强调色**：单一冷色（青蓝）标示焦点、选中和可交互状态；涨跌红绿只用于行情数值。
- **字体**：界面用系统无衬线字体；数字统一等宽表格数字（`tabular-nums`），价格列右对齐。
- **密度**：行情表 24–26px 行高，紧凑但不拥挤；控件高度统一，圆角最小化。
- **动效**：只在状态变化时出现短促的淡入和高亮，不做装饰性动画。
- **空状态**：缺数据源或未连接时直接写明原因和下一步操作，不留空白，也不填假数据。

- **控件**：按钮、输入框、下拉框、复选框和表格只在 `src/ui/theme/style.css` 开头定义一次，
  悬停与焦点状态在同一文件末尾定义一次。控件用 `--line-strong` 描边、不填充底色；主操作
  （`.primary`）是青色描边加极淡底色，不用实心色块。组件样式只设置自身的尺寸与布局，
  不重新定义控件外观。
- **分区**：一个面板内的各段共用同一左右留白，用发丝线分隔，不各自设置外边距。

样式令牌在 `apps/clients/terminal/src/ui/theme/tokens.css`（结构线 `--line`、控件描边
`--line-strong`、输入底色 `--field`），组件样式在各插件目录。

## 结构

```
┌ 标题栏：搜索 · 应用名 ─────────────────────────────┐
│侧 │ 工作区                                        │
│栏 │                                               │
│   │                                               │
├───┴───────────────────────────────────────────────┤
│ 状态栏：服务 · 任务 · 状态时间 · 交易连接              │
└───────────────────────────────────────────────────┘
```

标题栏由界面自己绘制，不使用系统标题栏，整条可以拖动窗口：macOS 的窗口按钮嵌在它的左端；Linux 的窗口按钮画在它的右端（数量和顺序跟随桌面环境的设置，GNOME 默认只有关闭），颜色取主题的 `--canvas` 与 `--text`，系统的浅色或深色主题不影响它。Linux 上设置窗口同样如此。

侧栏工作区（⌘1–⌘6）按显示顺序排列：自选、合约、市场、数据、研究、交易。“研究”工作区有“回测”和“因子”两页，共用历史数据选择和任务记录。首次打开默认进入自选，之后恢复上次使用的工作区；设置窗口不改变这个记录。设置是独立窗口（⌘,）。

账户资金和风险在交易页查看，回测及下载进度集中在任务中心，服务异常和失败／中断任务在状态栏明确显示。点击任务进入对应业务页并收起任务中心。

## 市场（期货全景）

布局参照同花顺期货通：

- 顶部为资产行（期货；其他资产显示未接入）和分类行（期货全景、主力合约、各交易所、期货夜盘等）。右端是实时／历史切换和 `⋯` 行情设置（品种概览／全部月份、表头设置、行情连接）。未登录时页面直接显示登录表单；登录后，更换来源、清除凭据和重新加载目录收进 `⋯` 菜单的“行情连接”。“按代码添加自选”是单独的折叠项，供没有合约目录时使用。
- 左侧为分组行情表：上海商品期货（上期所＋能源中心）、郑州、大连；右侧为金融期货、广州商品期货。分组只在有合约时显示；未接入的境外行情不展示占位分组。
- 列：名称、现价、涨跌幅(结)、涨跌、1分钟涨速、持仓（成交量可在表头设置中开启）。品种概览每个品种一行，名为“品种＋主连”，实际是该品种持仓量最大的月份合约，不是拼接的连续合约；没有合约目录时列出已订阅月份。
- 右侧是上下两个图表窗格，周期为 分时／Tick／1分／5分／10分／日K／更多（周K、月K、季K、年K、历史K线）。上窗格默认分时，下窗格默认日K。

## 自选与合约

- **加入自选**：加入或移出自选的按钮在合约标题旁，市场、自选、合约三页都是同一个按钮，不经过菜单。
- **自选**：自选与最近浏览列表，右侧两个图表窗格。
- **合约**：左侧自选列表，中间是图表和同品种其他月份的一条“相关合约”，右侧报价、五档、成交明细和下单区（仅引导到 CTP 交易页）。没有数据来源的页签（资讯、外盘、社区、T 形报价、F10）不占位。
- **自选表的列**：只保留期货合约可能有的字段。尚无来源的字段（主力净额、量比、成交额、内外盘等）保留并置灰、不可排序；总市值、净利润、市盈率这类股票字段不出现。

## 交易与回测

- **交易**：左侧是全部可交易的 CTP 账户及各自状态，右侧是所选账户的面板；多个账户可以同时打开。首次使用某个账户时开通交易：账户的柜台信息始终显示在上方，分两步填写——合约与风控 → 确认创建。缺合约目录时可在当前步骤读取柜台规格，不需要先去行情页。创建不登录、不授权。此后账户面板一次只给出当前这一步：核对环境并连接柜台 → 显式允许发送委托 → 下单；未到的步骤不显示为禁用的表单。授权长期有效（撤销、修改风控政策或交易服务重启后失效），所以已授权的账户重新连接后直接回到下单这一步。下单这一步可以在“手动下单”和“策略运行”之间切换；策略运行期间下单区换成运行状态和“停止策略并撤单”，这块状态在未连接时也保持显示。账户已连接但本窗口尚未核对环境时，先单独核对环境。仿真/真实资金是用户确认的标记，不能由前置地址自动推断，也不代表柜台验证的资金性质。标记仅保留在当前窗口的账户草稿中，重开窗口须重新核对。密码与授权码不持久化。
- **日常交易**：压缩资金摘要，保留下单区。下单区是合约、开平、手数、限价，加“买入”“卖出”两个带账户名称的按钮；在输入框里按回车不会发送委托。合约已订阅行情时可一键填入最新价、买一或卖一。委托发出后自动切到委托列表。持仓、委托、成交、费率、风控用同一排标签切换，不再另设折叠项。CTP 账户身份、环境和权限保持可见，撤销授权与断开账户在同一行。离开账户只断开 Terminal，服务继续运行；断开柜台不等于撤销已有委托。
- **自选为空时**：写明原因（行情未连接，或尚未加入自选）并给出前往市场页的按钮。
- **历史数据仓库**：每个版本一行；“使用情况”“查看数据”“下载后续数据”都在所点的那一行下面展开，一次只展开一个。
- **历史下载**：表单自上而下分两段——数据源账号（凭据、每分钟请求上限、应用共享额度），然后选择合约（交易所、品种、查询月份合约、月份合约、周期）并下载。
- **因子**：只有一个因子页和一种因子任务。页面顶部选择序列从哪里来：“K 线”读取所选数据集（分钟或日 K 线），选一个合约时评价它自己，选 3 个以上时在各合约共有的 K 线上做截面评价（每个观测的 IC 与秩 IC、各段的均值和信息比率）；“日线”直接读取数据仓库里已发布的一个日线版本；窗口、预测跨度和评价方式（全样本、时间留出、滚动验证）是同一组参数，两种来源都可用。任务列在同一张分析记录里，结果在记录下方展开，同一页显示来源证据、分段评价和可翻页的样本明细。从数据页点“日线因子分析”会带着所选日线版本进入因子页并选中“日线”。
- **策略回测**（回测页）：已完成的下载可通过“用于回测”带入数据来源和所属数据服务；切换服务必须重新选择，不能因任务编号相同而复用。默认显示记录，新建按历史数据 → 参数与交易规则 → 确认运行分步填写。第二步选择[策略](strategies.md)（均线交叉、通道突破、时序动量、布林回归）并填写它的窗口、目标手数和持仓方向；窗口可以用逗号填多个值，各种组合成为候选策略，这时须填留出起始日，表单随填写显示候选个数，候选为 0 或超过 32 个时不能继续。结果页的标题写明所用（比较时为选中）的规则和窗口；做过比较的结果另有候选策略的前段得分表，以及选中策略在前段和留出段的绩效，见[参数比较与留出](backtest.md#参数比较与留出)。选择历史数据时，“本次使用的数据”始终列在最上方（可在此保存为数据集）；添加数据的三种方式——单个合约、主力连续、已保存数据集——用标签切换，一次只显示一种；提交后显示进度，完成后单独查看固定参数和结果。草稿与任务结果分开，不把编辑中的参数当成历史实验输入；中断、取消和失败记录可显式重新运行。因子分析与日线因子保留独立入口；因子分析使用同一个数据选择区，选中的主力连续作为一条序列评价（见[主力连续序列](factors.md#主力连续序列)）；三种方式版面相同——页头是方式标签、活动任务容量和服务状态三行窄条，表单全宽在上，记录与结果在下，每种方式只列出自己提交的任务。

开发版窗口标题及标题栏显示“开发环境”，其服务、账户、任务、凭据与安装版默认分开；关闭开发主窗口自动停止本机开发服务与 Agent，安装版及远程服务继续独立运行；具体目录见 [开发指南](development.md)。

## 启动与设置

每次启动先显示启动界面，自动按四步准备并逐步显示结果：服务管理器（确认程序加载，需要时升级后启动）、行情服务、数据与任务服务、交易服务；前三步失败标在所属步骤上，由用户重试。数据或任务服务被停止时，启动会重新启动选中的原配对，等待两个服务及其进程健康均就绪；尚在恢复不等于启动失败。交易服务一步为每个已开通交易的 CTP 账户启动它的服务程序并等待首个心跳，只运行程序，不登录柜台、不发送任何请求；没有已开通的账户时直接完成，某个账户的服务未能启动时作为提示列出，不阻塞进入。首次启动用应用自带的全部插件创建数据与任务配对，不要求用户选择。全部通过且没有需要提示的事项时自动进入工作台；有不阻塞进入的提示（未能启动的交易服务、无法加载的插件、上次被中断的任务）时列出它们，等用户点击「进入工作台」才进入。每次启动都重新核验服务健康，不因上次成功而跳过。界面文案把 Node Agent 称为「服务管理器」。启动不连接 CTP 前置和远程机器，不执行数据更新。设置窗口将数据源与连接部署分开。进入数据与回测因子页面时按需准备选中的本机 Data/Task 配对；失败后显式重试，不循环启动。当前页面中主动停止服务或服务失联时保留状态，由用户重试，不自动撤销停止操作。已选择远程数据服务时不自动切回本机。

- **连接与部署 → 当前运行位置**：分别显示行情、历史数据和任务服务的当前连接位置及状态；CTP 账户的独立交易服务在交易页管理。未创建的会话标记本机默认、按需启动；连接到行情进程不等于已登录柜台。
- **机器管理**：选择一台机器查看其服务。每个服务一行，行内直接给出当前状态下适用的操作（已停止的可启动，要求运行的可停止，运行中的可重启）；程序更新、端口、目录和原始诊断进入“管理服务”详情。停止、重启、更新及切换服务连接前展示目标和已知业务影响，取消不发送命令。
- **添加远程机器**：机器信息 → 初始化机器 → 核验并连接。默认只填写名称和地址；SSH 端口、专用账户和管理端口放在高级选项。本机生成公钥，管理员初始化，用户核验主机身份后再安装。
- **部署服务**：在选中的远程机器上部署行情服务或一对数据与任务服务。部署不会自动切换连接，成功后明确提示；选择“使用此服务”才切换。任务与账本不自动迁移。
- **数据源**：独立管理供应商连接和访问验证。直接填写证书的交易连接保留在部署页的高级入口，不属于默认添加机器流程。

## 多语言

支持简体中文与英文，宿主和每个插件各自提供语言资源（`src/i18n/`、`plugins/*/locales/`）。键缺失、两种语言键不一致或占位符不一致会在启动时直接报错。服务诊断以错误码在界面本地化，原始英文诊断放在详情中。

## 插件契约

`plugins/contract.ts` 定义工作区、任务和语言资源。插件声明它调用的 C++ 命令，宿主只把这些命令开放给它。插件在构建时注册，按需懒加载。

## 原生命令边界

命令名称对应实际职责，插件只声明当前使用的名称，旧综合命令不保留别名。原生入口分别位于
`native/commands_data.cpp`、`commands_task.cpp`、`commands_backtest.cpp`、`commands_factor.cpp`
和 `commands_node_data_tasks.cpp`。

| 命令 | 职责 |
| --- | --- |
| `data.datasets`、`data.dataset.*`、`data.coverage` | 历史目录、具名数据集与当前数据选择 |
| `data.minutes.page`、`data.daily.page`、`data.contracts.load` | 历史分页与供应商合约目录 |
| `data.download.*`、`data.credentials.*` | 下载定义、更新计划、授权与共享请求预算 |
| `data.history.usage` | 查询当前数据版本的跨服务引用 |
| `backtest.submit` | 提交固定回测定义 |
| `factor.submit` | 提交因子定义：序列来源（所选全部数据集的 K 线，或一个日线版本）、窗口、预测跨度和评价方式 |
| `task.page`、`task.action`、`task.result` | 任务分页、显式取消/重试与已确认结果读取 |
| `node.data_tasks.local.create`、`node.data_tasks.local.open` | 创建或打开本机固定 Data/Task 配对 |
| `node.data_tasks.attach` | 选择受管节点上的现有固定配对，接入两个独立客户端 |

服务选择不会转移状态所有权：Data 仍拥有历史版本，Task 仍拥有任务与结果，Node Agent 仍管理进程。
页面、快照与服务契约的实施及验收见[实施记录](reviews/architecture-implementation.md)。

快照用 `data` 表示历史仓库连接，`task_service` 表示任务服务连接及分页状态，
`task_result` 表示任务结果。服务类型为 `data` 与 `task`；新建默认本机配对分别使用
`historical-data` 和 `task` 实例 ID。没有旧字段或命令别名，也不改写已有实例目录。
历史行情合约列表读取 Data 的版本目录，不依赖当前任务页是否包含下载记录。


Native RPC 按数据、控制、管理分别共享 128/128/8 MiB 的序列化载荷额度；回复由最后
一个读者释放，连接结束不会提前归还解析队列仍持有的字节。到界面的编码回复另有
快照 256 MiB、命令 128 MiB 的独立保留额度，单项 JSON 编码最多 128 MiB。超额明确
返回容量错误；命令可能已执行时提示结果未知，不自动重发。上述额度约束传输与完成
队列中的序列化长度，不代表 Native、V8 或进程总内存上限。


快照在状态 owner 上固定发布修订及不可变引用；响应队列保存这些引用和查询附加字段，
由同一个响应工作展开、编码并释放临时 JSON。排队期间状态刷新不会改变旧回复的修订，
大快照不会先展开后交回 owner 等待第二次编码。
