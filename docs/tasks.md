# 任务管理

本文说明当前 `asterion_task_service` 的任务生命周期、容量、结果校验与恢复。历史数据访问由独立的 `asterion_data_service` 提供；职责以[现行架构](architecture.md)为准，历史实施与验收证据见[实施记录](reviews/architecture-implementation.md)。

已确认的目标调整见[按业务服务归属管理任务](reviews/service-owned-tasks-design.md)：下载归数据服务，
回测和因子归研究服务，Core 复用公共机制。当前运行代码尚未切换，下文仍记录实际 Task／Data 契约。

任务目录的 `instance.json` 固定保存 Task 实例与配对 Data 实例。启动和离线引用检查都先核对该身份，
再读取或恢复任务账本；错误实例、错误配对、不支持的身份格式或已有目录缺失身份均明确拒绝。
仅全新目录可以创建身份，不自动补写旧目录，不改写或删除原任务数据。


## 任务服务

`asterion_task_service` 持久化下载、回测和因子任务及其执行尝试：任务清单与活动状态日志写入当前服务目录的 `tasks.sqlite`（任务表带当前状态、尝试次数和更新时间索引），状态事件用 `type: state` 标识，固定输入保存为任务目录中的 `input.pb`，各次准备的结果文件保存为 `results/<尝试次数>.pb`；均使用原始 Protobuf 二进制和 SHA-256 校验。大输入不写入 SQLite 清单，也不展开成 JSON 字节数组。服务按自身配置决定任务并发（默认1、最多2），在自己的计算线程池执行。

- 计算状态：`queued → running → succeeded / failed`；下载验收后先进入持久 `publishing`，数据服务确认原版本已公开后才为 `succeeded`；取消运行中任务先进入 `cancel_requested`，执行返回并确认后为 `cancelled`。
- 全市场数据更新没有 `publishing`：分区由数据服务逐个校验并入库，任务结果只是这次运行的摘要，状态与计算任务相同。任务取消、失败或中断不撤回已入库的分区。它要读多少分区在运行时才知道，进度按百分比报告（`total` 固定为 100）。
- `failed`、`cancelled`、`interrupted` 可显式重试，每次重试是新的执行尝试，带独立令牌。
- 服务直接观察执行future及原子进度，不使用心跳租约；重启时运行中任务标记中断，不自动重跑。
- 结果先写入并同步，再记录完成状态和 SHA-256；只有确认完成的结果可查询。
- 同一任务 ID 重复提交相同输入返回现状，输入不同则拒绝。

| 任务 | 服务内模块 | 内容 |
| --- | --- | --- |
| [回测](backtest.md) | `backtest/` | [策略](strategies.md)回测：四条单合约规则和三条排序规则，多空 |
| [因子分析](factors.md) | `factor/` | 价格动量、期限结构、波动率三种因子；一条序列，或 3–100 条序列的截面 |

## 服务任务并发

每个Task实例启动只读`<node>/config/services/<实例>/task.json`的`task_concurrency`，
默认1、允许1–2。配置缺失或无效报告完整路径，不生成、不转换现有配置。
Data未就绪时任务留在队列。并发名额覆盖输入准备、执行和结果确认，取消后也要等计算实际返回。
Agent不维护任务额度、子进程启动记录或任务状态，Terminal的节点页只显示实际服务进程。

## 服务内执行与退出

状态/I/O线程串行管理队列、尝试、取消和持久确认；计算池执行下载、模拟和因子算法，
每项工作独占输入和算法状态，通过原子进度、future和一次结果交还状态所有者。
文件与日志池继续处理持久化，计算不能阻塞公开查询、取消和健康通道。

取消使用stop_token，只有执行返回且状态落盘后才确认。服务停止请求协作取消并保留已有产物；
升级先冻结新任务，等待正在执行的工作与发布完成，再停止服务，队列保留到下次启动。
普通进程停止仍使用RpcHost的有限排空期限，超时结束进程后由下次启动恢复为中断；升级则先等待工作结束再发停止。
线程不能被安全强杀，插件崩溃会影响所属服务；Agent监督服务进程，不把退出当作计算成功。
没有Task私有worker端点、领取/进度/完成RPC，也没有独立worker程序。

## 日志分段

活动日志达到 1,000 条事件或 4 MiB 事件正文后，在下一次状态写入前封存为
`event-segments/<序号>.pb`。先通过 `durable_file` 持久化不可变段及其目录，再在同一 SQLite
事务中登记段的 SHA-256、字节数、记录数与任务归属索引，并移出活动日志中的原行。定义、结果、任务 ID、
提交顺序、尝试编号与数据服务配对不随分段改变，不删除归档证据。

归档文件落盘后索引提交失败，原活动行仍是权威记录。恢复只接受与这些原始行逐字节一致的
下一段；不得换一份内容、重新执行任务或自动删除文件来继续。已登记段缺失、损坏、序号不连续，
或重放后的状态与任务索引不一致均拒绝恢复。段内记录保留原事件字节，按段顺序恢复每个任务
连续的事件序号；不一次读入全部日志段。

历史列表现在按持久提交序号分页，每页最多 200 条；新增提交不会移动已经取得的较早页游标。
终端显示本页历史和全部活动任务，提供“更早记录”和“最新记录”；提交新任务返回最新页。
调度、停止检查使用独立活动集合，不受当前页影响；失败与已中断统计覆盖整个任务库。

运行期间由任务状态层保管最多 1,000 个活动任务的有界元数据，派发、活动容量和尝试裁决直接使用
已确认的内存状态；SQLite 保存同事务更新的状态事件及持久投影，并按 ID 或页提供冷历史。
终态任务退出活动集合，显式重试重新占用名额，不建立覆盖全部历史的内存表。
状态变更先完成合法性检查、事件编码和内存节点分配，持久屏障成功后才发布新状态；
失败保留最后确认的活动状态并拒绝继续写入，不能把计划中的取消或完成当作已生效。
日志段归属索引只负责定位，恢复时先核对归属与实际段内容，再逐任务重放并与持久元数据比较，
只保留有界活动集合，不以快照跳过历史合法性校验。

尚未接纳的请求等待数据库时仍受 10 秒接纳期限约束；到期返回 `unavailable`，
不读取数据库或创建新变更。已接纳的文件操作和日志写入保留到工作完成，持久确认后才回复，
客户端断开或接纳期限经过不能撤销已经开始的持久写。

## 恢复与结果校验

回测结果只维护当前结构，不保存格式或引擎递增版本号。每次成交记录账户实际扣收的手续费，包含该成交消费的平今/平昨分桶；逐笔费用之和必须等于账户累计手续费。结果页按同一合约从空仓到再次空仓的一轮持仓统计净胜负，列出毛盈亏、实际费用、净盈亏；尚未闭合持仓的费用单列。该统计不重算收费规则，也不把已平仓净盈亏当作包含未平仓头寸的账户总收益。缺少逐笔费用证据的旧结果保留文件并明确拒绝读取，不迁移或按零费用显示。

日线数据通过全市场数据更新取得；已删除逐合约日线下载的任务类型、恢复与界面路径。

恢复期间提供明确标记为尚未就绪的私有心跳，Agent 保留该进程，服务在自身恢复就绪后才开始调度；业务入口在恢复完成后开放。恢复时逐个核对任务输入文件的长度和摘要、逐条重放状态事件并与索引比较，启动从只读预检到打开写连接持续持有同一把目录独占锁，不再用 SQLite 主文件/WAL 的全文件哈希检查锁交接。已有任务只在只读预检中核对一次，写端接管已验证的活动任务和序号；日志段缓存最多一段，不常驻全部历史任务元数据。恢复核对持久字节、事件和索引的一致性。输入在提交、执行准备、验收或读取结果时检查实际结构与领域约束。固定输入不合法，或总工作量与已接纳记录不一致时，尝试明确失败并离开队列，不自动重跑任务，不改写原输入；工作量不符提示 `task input does not match admitted work`。未知 Protobuf 字段、缺失字段、摘要或身份不一致均按实际错误拒绝。历史用量检查遇到不可读记录时明确失败，不跳过记录后声称检查完整。任务服务链接回测和因子引擎用于执行；完成验收与结果读取均不运行算法。每次读取检查固定输入和结果的摘要、格式、身份及领域证据；回测验收结算日期、合约、价格和汇总一致性，因子验收样本时间、评价区间和数值范围。这些检查不证明算法数值正确。算法正确性由独立算法测试和显式再次执行验证，不能把读取结果当作重跑实验。结果读取不加载风险插件；缺少可执行插件会阻止再次运行，但不抹去已保存的结果。输入和结果先持久发布，再提交数据库引用；不接受旧任务清单、含历史仓库的旧混合目录或自动迁移，拒绝时保留原文件。

表更新的完成与结果读取共用业务协议校验：显式刷新回执必须匹配固定分区、来源和快照；
新增修订核对本次 provider artifact，未变化修订保留最初入库的 artifact。
如有原始响应 observation，另外核对 Data/Task 实例、任务、尝试、供应商、当前 artifact、
选中版本和回执一致性。无数据/拒绝结果可以没有修订，普通更新不要求单分区回执。
验证只使用任务固定输入与保存证据，不访问 Data 或重新下载。错配的旧结果拒绝读取，保留原文件。

完成结果的输入读取、领域核验、序列化、摘要和持久文件写入，以及结果查询，都由有界文件池处理。
文件准备仅拥有本次尝试的不可变快照；回到状态侧后重新核对尝试令牌、租约和取消状态，
再提交带文件摘要的小状态记录。下载结果也先准备文件，随后由 Task 持久决定发布。
取消、中断或新尝试可以在旧文件准备期间生效；迟到文件不会被确认为成功，仍保留为未确认证据，
恢复不凭文件存在推断完成，也不删除这些文件。状态日志由独立串行线程写入，请求挂起等待完成；同一任务的后续变更等待前一条确认。
日志线程不裁决任务状态，状态侧收到完成后才发布活动状态并释放终态租约。有效进度报告在接纳时续租，
不会因延后的磁盘确认而重新延长租约；排队等待后先重新检查是否已经过期。
过期报告立即拒绝，不以中断记录是否已取得写入名额或完成持久化判断令牌有效性。
持久失败停止后续写入，保留最后确认值并要求恢复。当前写入队列容量为 16；
冷数据库查询与新增提交裁决等待共享连接空闲，等待时主线程继续推进其他请求。
输入核验、风险插件副本、输入文件序列化与持久保管交给 Agent 指定的 1 或 2 条文件线程，队列上限 8；
输入读取、结果读取和完成复核共用此池，各入口仍保留自己的接纳名额。
新提交先预留活动容量与提交顺序，文件准备期间其他任务可继续控制；文件持久后由日志线程登记，
状态侧确认后才公开任务。已接纳的提交完成原登记，不因客户端超时或进入静默状态丢弃。
重复提交在文件侧核对固定输入，返回当前确认状态，不覆盖核验期间发生的取消或重试。
任务服务使用一条状态与 I/O 主线程、一条日志线程及上述文件线程。
公开与健康通道共用非阻塞入口，连接限额分别为12、4；不另建请求、发布、心跳或监视线程。
主线程唯一修改任务状态、租约与发布确认；文件与 RPC 等待返回主循环，工作线程不裁决状态。
历史引用查询固定接纳时的提交序号上界，每页最多交接 200 条元数据，在文件池逐条读取输入。
SQLite 仍由单个独占连接负责；分页元数据由主线程读取，不跨线程分享查询或未提交事务。
领取在文件池校验已保管的固定输入，并将其投影为参数、数据版本引用与输入 SHA-256；
整批行情在文件线程释放，计算持有小型固定执行定义。服务计算线程通过绑定的 Data 私有端点读取
固定版本，重建输入并核对完整摘要后才运行算法；主力月份顺序及换月计划不重新选择。
数据交换有 120 秒总期限，控制线程同时保持心跳、取消观察和父进程检查。取消在当前
读取返回或超时后生效；没有整批输入回退、替代数据版本或自动重试。已保存结果仍按
Task 自有的固定实验依据核验，读取历史结果不要求 Data 在线。
启动恢复由文件线程完成，主线程同时报告 `initialized=false`；客户端与 Agent 必须等待明确就绪。
停止时先关闭业务接纳并继续推进已接纳的工作；统一排空期限为 400 毫秒，未完成则结束整个进程，
由已有持久证据恢复。不能释放仍被文件线程使用的请求局部对象后继续运行。

服务内部最多两项执行结果准备，公开结果读取另有一个名额；文件读取、固定输入与结果验证在文件池进行。输入准备30秒，结果验证5分钟，状态/I/O线程继续处理查询和取消。

## 容量与继续使用

每个任务服务最多接纳 1,000 个活动任务，包含 `queued`、`running`、`cancel_requested` 与
`publishing`。完成、失败、取消或中断后释放活动名额，固定定义、结果和数据引用继续保管；
总历史数量不再受 1,000 项限制。提交序号为 uint32，耗尽时明确拒绝，不能重置或复用身份。

新提交和显式重试都在同一个接纳边界检查活动容量；满额时拒绝，不创建新提交目录或改变原任务。
文件准备中的新提交最多预留一个名额，`active_reserved` 与已确认的 `active_used` 分开报告；
可用容量扣除两者，已确认列表和保管计数不包含尚未登记的输入。准备失败释放预留，
若已经创建文件则保留未登记目录并要求恢复；这些目录通过 `uncommitted` 单独报告。
重试沿用原任务 ID、提交顺序与固定输入；领取任务或确认领取前的启动失败时增加执行尝试。失败提交的目录保留、ID 不复用，
但不占活动名额。终端显示活动余量与保管总数，不要求通过新建仓库继续工作。

新增部署是显式创建另一个独立实例，不是容量恢复操作。部署不自动切换已有连接；任务与数据的固定
配对、历史版本与结果不会复制或重跑。停止所选本机配对后，“重试准备”启动原配对。
不要删除 `tasks.sqlite`、日志段、任务目录或历史版本来释放名额。

## 备份与恢复

备份包含[下载凭据](market-data.md#下载凭据)，应存放在限制访问的加密存储中。先停止任务服务并确认内部计算已停止，已决定的发布须完成或持久保留其未完成状态，再停止配对的数据服务和所属 Agent，复制双方完整服务目录。任务目录保管 `instance.json`、`tasks.sqlite`、`event-segments/`、固定输入、结果和算法副本；数据目录保管实例配对、`authorizations/` 固定下载授权与凭据、`budgets/` 共享下载额度政策、下载候选、发布证据、`history/` 版本与具名数据集、`tables/` 全市场数据表的登记与分区文件。Task 只保管非秘密授权引用，不持有供应商令牌。仅复制 SQLite 或单个服务目录不是完整备份；节点插件和程序等依赖也需保留。当前采用节点管理员执行的文件级冷备份，不增设在线快照、自动恢复或转换入口。隔离恢复验收状态见[实施进度](reviews/architecture-implementation.md)。


备份集须一并记录节点、Data 与 Task 的稳定身份和原配对、源绝对目录、程序/插件摘要及
文件清单。逐项核对固定输入引用的历史版本、具名数据集的版本引用、发布决定对应的
候选产物，以及下载授权引用；身份和摘要均须来自原实例。缺少任一依赖时，将该备份集
记录为“不完整”，即使任务结果仍能独立读取，也不能据此宣称可重新执行。另一实例的
同名数据、后来下载的相似数据或 Terminal 的当前令牌均不能补作原证据。

恢复使用同一绝对目录、当前支持的持久化格式和匹配的程序/插件；下载结果及数据集可能固定绝对路径，不支持任意搬移目录或修改记录实现迁移。先保留现有目录和备份原件，在停止服务的情况下恢复副本，核验文件摘要、所有者和权限后再打开。Task 检查固定输入与结果，Data 检查自己的仓库和发布证据；原运行中任务按中断恢复，排队任务在恢复派发后可能执行。启动与列表成功不代替每份结果的完整校验。

## 固定输入与新实验

输入和结果只维护当前结构，不保存内部格式或引擎递增计数。结构、身份、摘要或领域不变量不成立时明确拒绝，保留原文件，不自动迁移或提供旧格式重建入口。

因子和回测结果可以显式派生新任务，固定原快照或选择当前 Data 的明确快照。Native 重新读取原结果，Task 验证来源与固定输入；新任务使用独立身份，原实验不变。重试是同一任务的新尝试，不能替代修改参数后的新实验。具体范围见[因子分析](factors.md)和[回测](backtest.md)。

分钟下载发布和表分区更新沿各自既有提交语义；重取、来源错误、空响应及原文证据由[数据契约](market-data.md)定义，Task 保管执行状态而不推断供应商覆盖。

## 派生来源与名称备注

复用创建的因子及回测任务保存不可编辑的来源任务 ID、Task 实例 ID、来源结果摘要、数据选择（原固定或指定新快照）及所选快照。Task 在准入时核对来源类型、已完成状态和摘要；因子还按来源固定结果重建预期请求并逐字节核对。来源与新任务在同一提交事务中记录；重试同 ID 不能悄悄更换来源。此前没有记录来源的任务保持“来源未记录”，不猜测、不批量回填。

研究记录中可编辑名称和多行备注，比较列也显示名称/备注；任务 ID、计算输入及运行身份不变。名称/备注使用 Task 所有的描述修订及事件日志保存：`type: state` 表示计算状态，`type: metadata` 表示描述变更，索引与事件同事务提交。派生任务的 manifest 固定不可变来源。修订号用于并发编辑冲突检查，不是格式版本。

保存携带描述版本号；过期版本明确冲突，不覆盖他人的备注。成功只在持久写入确认后显示。失败保留工作区草稿，切换记录再回来也保留；“读取最新描述（保留草稿）”显示已保存内容并更新保存版本，用户对照后显式保存。未保存草稿是当前工作区编辑状态，不承诺应用退出后恢复。独立的描述读取不解析计算输入，描述修订与计算状态分别管理。


## 单实验固定参数与结果证据导出

导出为单个已完成因子/回测的 UTF-8 JSON 文件，格式标识 `asterion.research.evidence`、scope 为 `verified_parameter_summary_and_complete_result`。内容字段为：

- `source`：Task 实例、任务 ID、类型、执行次数、原结果 Protobuf SHA-256、已公开的原输入 SHA-256 及风险实现摘要。回测提供完整原 Input 摘要；因子接口未公开 Input 摘要，明确写为 null，不伪造或用参数摘要替代。
- `description`：导出时重新读取的名称/备注、描述版本、持久派生来源及快照选择；描述不参与计算身份。名称备注原样包含，用户不应在其中记录凭据。
- `experiment`：现有固定输入的参数及数据/快照摘要，包含策略/因子、评价边界、资格规则或费用/风险/滑点/换月等当前类型拥有的口径。
- `result`：服务核验的完整计算结果之 JSON 表示；回测另包含 Native 从原输入及结果计算的 `performance`、`trades`，各评价段保持独立。`included`、`not_included`、`limitations`、`methodology` 明确内容和口径。

导出不包含 `input.pb`、原始行情、来源表、历史归档或本地插件/可执行程序，不是脱离原服务即可独立重放的复现包。原输入/结果摘要标识服务持有的 Protobuf 字节，不是导出 JSON 的哈希；界面保存回执显示保存状态及实际 UTF-8 文件字节长度，不另生成导出文件哈希。null 统计保持未定义，缺失评价段保持不适用，未排序/合并/重新选参。

结果页点击导出后，Native 重新走已验证的 Task 结果读取路径；不直接序列化界面缓存，不导出整份 Snapshot、连接/凭据配置或不相关节点状态。当前版本不支持或输入/结果缺失时明确拒绝，不回退为不完整的“成功导出”。只保存到用户选择的新路径：先写入并同步同目录临时文件，再用不替换目标的发布方式创建最终文件；已有目标（含竞态创建）不覆盖。写入异常不自动重试；极端同步失败可能留下文件，需用户检查后选择新位置。开发隔离浏览器沿用本地下载机制，界面只称“下载已发起”；没有第三方上传。


## 比较矩阵证据导出

因子、回测的 2–3 列比较支持本地导出 `asterion.research.comparison.evidence`。`matrix` 保存界面语言、首列对照 ID、列顺序、同口径/独立列示状态、全部原因及逐行文本；文本包含矩阵中的参数/快照、费用/风险等详情节点。每列的单实验证据位于 `experiments`，沿用单实验导出 的固定参数/快照摘要、原结果及名称/备注/派生来源和摘要，保留原始结果数值。矩阵文字按界面精度显示，不能替代原结果精度。

指标状态来自实际数据对应的渲染标记，不从用户文字猜测：`defined`（包括零）、`undefined`（原 null）、`not_applicable`（不存在的评价段/不适用指标）、`missing`（该评价段应存在但缺失）、`no_observations`（分组统计无有效观测）；回测分项组用 `metric_group` 并逐项记录状态，参数及说明文本用 `display_only`。矩阵列原因与界面使用同一比较规则；它是 Terminal 比较口径/展示摘要，不伪称由服务重新计算或共同样本重算。不排名、合并或重新选参。

导出前按列重新核验服务结果、输入摘要（接口提供时）和描述版本，身份/名称备注变化则拒绝，提示重新读取比较；任一读取失败的部分矩阵不能导出为完整比较。核验后原实验不变。Native 校验列身份/顺序、矩阵宽度、状态及字段白名单，拒绝夹带无关字段；复用既有本地保存、保存回执与拒绝覆盖机制。文件依然没有 input.pb、原始行情/来源表、历史归档或插件，不是独立复现包或数字签名，不支持作为生产行情输入。


历史交付与测试证据见[审计记录](reviews/audit-progress.md)和[评审索引](reviews/README.md)。
