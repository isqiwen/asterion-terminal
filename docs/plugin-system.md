# 插件系统与当前扩展契约

更新：2026-09-20。本文描述已落地的核心机制和当前可安装扩展，不保留未实现的 manifest 草案。开发约束以 [AGENTS.md](../AGENTS.md) 为准：核心提供机制，功能由插件实现；只实现当前契约，不做旧格式迁移或协议回退。

## 核心与功能的边界

| 所有者 | 职责 |
|---|---|
| 核心平台 | 插件依赖和生命周期、能力与资源声明、存储授权和事务、任务租约、请求授权、安装完整性、进程协议、执行时限、通用声明式视图契约 |
| 功能插件 | 数据源、类型语义、配置、采集、规范化、数据发布校验、研究与账户规则、业务路由与界面 |
| 发行版装配 | 选择内置插件；批准存储表、任务类型、HTTP 请求范围和可接受扩展点 |
| 工作台外壳 | 面板承载、窗口布局、主题、键盘与鼠标反馈；不解释具体行情或研究规则 |

默认发行版包含身份、数据、研究、扩展管理及状态贡献。内置登记、上下文和资源接口见 [内置扩展接入](builtin-contributions.md)。外部扩展不会获得内置 Python 对象、数据库连接或 React/原生桥接对象。

## 当前支持范围

- 内置受信插件使用 `Plugin`、`Context`、`Activation`，依赖和资源校验在激活前完成，失败释放、逆序关闭。
- 本地 Python 插件使用固定 ZIP 工件，独立短生命周期进程执行。支持 `data.provider`、`ui.table` 和 `research.strategy`（见 [策略契约](strategy-plugins.md)）。
- 内置及外部数据源统一经过 `ValidatedProvider` 的计划准入，数据插件继续负责标准类型、证据、校验及事务发布。
- 声明式表格由可信 React 组件渲染，只接收列定义和有限的标量数据；不接受 HTML、JavaScript、任意 API URL 或原生命令。

本地插件是**用户明确认可的受信代码**，具有当前 OS 用户的文件和网络权限。进程隔离、HTTP 作用域和包 hash 不能阻止恶意 Python 代码绕开公开接口。本版本不提供恶意代码沙箱、任意原生依赖、在线插件市场或实盘交易扩展。Windows 的打包与进程约束未验收。

## 插件包

包包含 `manifest.json`、`plugin.py` 及可选纯 Python 源码/文本资源；不执行安装脚本或在线依赖安装。ZIP 不超过 16 MB，展开不超过 32 MB，最多 500 个文件；拒绝路径穿越、绝对路径、重复项、目录项、符号链接和原生二进制。

完整可运行声明见 [开发样例 manifest](../examples/plugins/calendar-source/manifest.json)，核心字段如下：

| 字段 | 当前契约 |
|---|---|
| `api_version` | 必须为 `1` |
| `id` | 点分命名空间；`asterion.*` 保留给内置发行版 |
| `version` | 精确 `数字.数字.数字`；没有范围匹配或兼容承诺 |
| `title` / `description` | 用户可读名称与说明 |
| `runtime` / `entry` | `python` / `plugin.py` |
| `trust` | `local-code`，明确用户认可的本地代码 |
| `requires` | 依赖的插件 ID → 精确版本；无依赖时 `{}` |
| `contributions` | 已批准扩展点名称 → 对应领域声明 |

未声明的字段和扩展点拒绝安装。包 SHA-256 由宿主计算，不放在包自身声明内。相同插件 ID 和版本不得重新对应不同内容，包括卸载后再次安装。依赖循环拒绝登记；启用时依赖必须存在、启用且版本一致；停用被其他启用插件依赖的插件会被拒绝。

安装目录位于当前数据根目录的 `.extensions/`：`objects/<sha256>/` 保留不可变源码和原 ZIP，`installed.json` 保存当前安装/启用回执。文件锁和原子替换保护并发写入；安装中断留下的未登记工件不执行。每次执行前重新核对包 hash、文件清单和内容。

## 用户操作与停用

1. 在“设置 → 插件”选择 ZIP，或将单个 ZIP 拖入安装区域。宿主只预检包、贡献、工件身份和依赖，不安装、不执行插件代码。
2. 确认页显示名称、版本、用途、功能与本机访问权限；插件 ID 和摘要在可展开详情中。明确点击“信任并安装启用”后，重新检查文件摘要和依赖，在同一锁内提交已启用的安装回执。
3. 取消确认不产生安装记录。依赖缺失、未启用或版本不符时显示具体插件及所需版本；当前没有在线自动下载或隐式信任依赖。
4. 成功后提示下一步：数据源配置连接、研究刷新策略、扩展打开视图。无需命令行或另行安装 Python。
5. 已安装插件仍可停用、显式信任后重新启用或移除。移除保留工件、任务输入和已发布数据。更新目前仍需停用、移除安装记录，再选新包；尚未实现在线市场或一键版本替换。

接口为 `POST /extensions/inspect`（archive）和 `POST /extensions/install`（archive、digest、trust_local_code 必须为 true）。digest 绑定用户核对的 ZIP 内容；安装时重新校验，不把预检结果当作持续有效的授权。重复提交同一工件幂等。完整性校验与依赖检查失败不写安装回执；进程中断可能留下未登记的不可变工件，但不会启用或执行它，重试仍须验证。

安装、启用、停用和移除均受工作台身份、账户解锁政策及服务端请求范围限制。回执摘要用于拒绝过期窗口的修改。停用不会把历史任务换成别的插件执行；恢复同步需显式启用对应工件或重新提交当前任务。

## 公开 SDK 与进程协议

SDK 位于 `src/asterion_plugin_sdk`，仅依赖标准库。开发时随当前源码安装，首次设置安装的项目 wheel 提供同一 SDK。用以下命令创建确定性 ZIP：

```sh
uv run python -m asterion_plugin_sdk pack examples/plugins/calendar-source /tmp/calendar-source.zip
```

输出文件必须不存在。独立仓库插件只导入 `asterion_plugin_sdk.serve`，不导入终端内部模块。样例不生成行情或交易日历，需要用户提供真实 HTTPS JSON 接口。

宿主发送单次 JSON 请求：`protocol: 1`、随机 `id`、`method` 和 `params`；插件返回相同协议和请求 ID，以及 `result`。SDK 捕获插件错误后返回固定失败消息，避免上游响应或配置秘密进入日志。每次请求/输出限制 8 MB，默认墙钟时限 30 秒，子进程另有 CPU 和输出文件限制。超时、停用、异常或错误协议会终止进程组，不留下供后续任务复用的插件对象。

环境不传递主令牌、数据库 URL、账户会话或 `PYTHONPATH`。插件只获得该次方法需要的 JSON 输入；`fetch`/`probe` 可以得到所属数据源的批准配置明文，以访问真实数据源。当前信任模型不承诺阻止该代码读取本机其他文件。外部插件使用应用专用 Python 环境；插件契约仍只承诺 SDK 与声明的可用能力。第三方额外原生依赖需要另行设计隔离环境，不向宿主隐式安装依赖。

## 数据源扩展

`data.provider` 的值符合 `data/providers/public.py` 的 `ProviderManifest`：当前 `api_version` 为 2。来源 ID 等于插件 ID 将点替换为下划线，长度不超过 41；来源版本与包版本一致，正式安装拒绝合成数据源。

| 方法 | 输入 | 返回 |
|---|---|---|
| `plan` | `request`：类型、交易所、合约、日期等 | 分段数组，每段声明 API、供应商参数、字段、返回上限以及独立的 ISO `start` / `end` |
| `probe` | `configuration` | 成功字符串；宿主显示固定成功提示，避免回显秘密 |
| `fetch` | `partition`、`configuration` | 原始记录数组 |
| `normalize` | `request`、`rows` | 对应标准类型的记录数组 |

日期分段必须有序、连续、完整覆盖请求，快照分段不得声明日期。供应商参数保持不透明；数据发布不读取 `params.start_date` 等特定供应商字段。内置 Tushare 也遵循该契约。

提交任务固定插件版本及工件摘要、类型 schema、连接及配置快照。执行和发布均重新核对固定身份；工件改变、停用或缺失即失败，不能悄悄切换实现。外部标准化结果仍通过类型、时间、记录键、原始证据和不可变发布校验，插件没有直接写入目录或任务成功状态的公开接口。

## 声明式表格

`ui.table` 声明 `id`、`title`、`columns`；列由稳定 `key` 和可读 `label` 组成。宿主调用 `view`，参数为声明的视图 ID。返回最多 1000 行，字段必须与列集合相等，单元格仅允许 null、字符串、数值和布尔值，长度不超过 2000。错误、空表和插件缺失由宿主显示。

同一个包可同时贡献数据源与表格，也可以只贡献表格。没有任意插件脚本注入工作台；新增声明式组件应在通用视图契约中定义并进行当前契约测试。

## 存储、授权和恢复

- 内置插件获得 `Storage`，只初始化和写入所属表。只读事务不能写；原始 SQL 和未授权表拒绝；数据、研究只能读取自己任务类型的记录。跨领域引用通过绑定到同一事务的只读接口统计。
- 表结构预检覆盖字段、类型、可空性、主键、唯一约束和外键，全部检查后按外键依赖创建缺失的当前表。结构不符明确失败，不自动修复或迁移用户数据库。
- 任务进度和成功状态由核心任务端口执行，每次检查任务类型、数据库归属和有效租约；与领域发布共用事务。
- 工作台业务请求使用 5 分钟有效的作用域凭证，绑定账户会话；服务端只接受发行版批准的路径与方法。作用域凭证不能申请更高权限。任务执行器采用独立派生身份，只获任务领取、心跳、失败和声明的任务接口。
- 备份校验消费只读领域证据；恢复后的任务取消与领域清理共享事务，必需操作遗漏或失败则一起回滚。

## 验证入口

`tests/test_storage_ports.py`、`test_authorization.py`、`test_extensions.py`、`test_restore_ports.py` 验证机制边界；现有数据/研究全量测试验证业务不变量。浏览器测试覆盖插件安装与信任确认、声明式视图及缺失状态。已安装环境的冒烟从无开发工具的 PATH 启动插件，验证内置 SDK、服务端作用域及停用。当前验收结果记录在 [实施进度](ROADMAP.md)。

后续新的研究方法、交易连接器、实时事件协议和不受信代码隔离，需要各自真实业务与平台验收；不能用当前按次采集协议冒充它们已完成。


## 插件运行诊断

设置 → 插件 → 运行诊断，读取当前已安装工件最近 30 条完成的调用记录。显示开始时间、单调时钟耗时、最后调用阶段、调用数和失败类别，并给出检查建议。策略会话逐根调用聚合为一条记录，一次性数据源/视图调用各记一条。记录覆盖进程调用，不意味着业务结果已经发布；停用仍可查看，换工件后按新摘要查询。

通用进程机制负责测量与固定错误码，不导入业务功能；扩展管理插件提供受账户鉴权保护的 `GET /api/v1/extensions/{id}/diagnostics` 和业务界面。记录位于数据根 `.extensions/diagnostics.sqlite`，SQLite 事务协调 API 与 Worker 并发写入，全部工件合计保留最近 200 条。写入故障不改变原操作结果；查询失败在界面显示错误。它是有限的排障记录，不是完整审计日志，也不持久化正在运行的进程状态。

仅保存工件摘要、时间、耗时、阶段、计数与宿主错误码，不保存参数、返回正文、环境变量、stderr 或异常原文。失败类别包括撤销、超时、请求/输出超限、进程退出、协议错误、启动或宿主调用失败。该诊断不改变本地受信代码的权限边界。

### 拖放与输入校验

拖放和文件选择共用预检函数，只接受单个非空 ZIP，大小上限不变。扩展名大小写均可；最终格式和完整性仍由服务端检查。多文件、空文件或格式错误显示原因，失败后可重新选择。预检及安装期间锁定重复提交；拖入文件不会绕过信任确认，取消不产生安装记录。拖入安装区域外的文件不会导致浏览器导航。

桌面设置窗口使用网页拖放事件；宿主关闭该窗口的原生拖放接管，依据 [Tauri WebviewWindowBuilder 接口](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html#method.disable_drag_drop_handler)。此配置不新增文件系统 API 权限。浏览器自动化拖放与原生构建分别验证；Finder 到打包应用的真实拖放仍需单独人工验收。
