# 机制核心与内置功能插件

当前默认发行版通过显式插件清单装配已实现功能。核心提供机制，业务实现和状态归功能插件；界面分为工作台外壳、共享控件和插件业务内容。所有改动遵守 [AGENTS.md](../AGENTS.md)。

这里描述当前可运行实现。外部数据源包安装与声明式视图的已实现范围见 [插件系统](plugin-system.md)；外部策略安装、OS 级不受信代码隔离与完整交易执行仍未交付。内置插件拥有宿主进程权限，不能作为外部代码沙箱。

## 后端

| 位置 | 职责 |
|---|---|
| `platform/plugins.py` | 当前契约检查、重复 ID 检查、依赖排序、缺失/循环依赖拒绝、激活与逆序释放 |
| `distribution.py` | 默认发行版的插件清单；唯一选择具体业务实现的后端装配层 |
| 各领域 `plugin.py` | 声明依赖与任务处理器，激活业务服务，贡献路由、诊断与备份校验 |
| `api/app.py` | HTTP 认证与错误处理、通用任务接口、诊断聚合、服务生命周期；不导入具体业务 |
| `runtime/handlers.py`、`runtime/worker.py` | 从清单重建处理器登记，领取任务、子进程计算、租约续期和发布 |
| `runtime/backup.py` | 文件完整性、隔离数据库启动和通用任务隔离；调用插件校验与隔离钩子 |

默认后端包含身份、数据、合约规则、研究、策略目录及双均线/收盘动量策略、扩展管理，以及行情/交易可用状态贡献。行情和交易的状态插件明确报告能力尚未接入，不提供交易执行。

`Plugin` 声明唯一 ID、当前 `api_version`、`requires` 和 `activate`。跨插件调用使用领域 `public.py` 中的 `Capability[T]`：明确能力 ID、提供者和端口类型；提供者声明 `provides`，消费者同时声明 `requires` 与 `consumes`，通过 `context.require(capability)` 取得类型明确的端口。宿主在激活前拒绝重复能力、归属错误、未声明提供者和缺失或类型不一致的能力。`Activation.exports` 必须与声明完全一致，实际值必须符合端口类型；校验失败释放已启动资源，不发布路由。

身份插件只导出账户校验端口；数据插件只导出版本读取与覆盖报告读取端口，研究插件通过注入的端口访问数据，不创建数据服务、不取得来源凭据或发布操作。研究插件没有跨插件导出。命名钩子的读取也需要 `observes` 声明，激活上下文不再公开完整宿主。全部必要插件激活后才发布插件路由；关闭按逆序执行且幂等，关闭后不能重新解析能力。

启动上下文只提供能力解析、资源解析与已声明钩子读取，不公开完整应用、配置或任务调度服务。插件通过 `resources` 声明 `Resource[T]`；发行版 `bootstrap_resources` 为每个插件逐项授予值。宿主在任何激活前校验完整集合、类型与重复声明，拒绝未声明资源、缺失授权、额外授权和未知插件。绑定集合按启动时快照保存，关闭后不能再次解析资源。

| 插件 | 启动资源 |
|---|---|
| 身份 | 所属表存储、数据目录、身份摘要端口、账户验证策略 |
| 数据 | 所属表存储、数据目录、数据凭据端口、仅限数据任务类型的任务端口 |
| 研究 | 所属表存储、仅限研究任务类型的任务端口；数据读取由数据插件能力提供 |
| 行情状态、交易状态 | 无启动资源 |

`TaskPort` 提供提交、批量提交、租约校验、任务进度和完成操作。提交前检查授权任务类型，批量请求全部检查后才写入；租约校验调用核心真实租约检查后再检查任务类型。不公开任务领取、全局调度或整个任务服务。异常处理器由 `Activation.exception_handlers` 声明，宿主在发布前检查冲突；身份服务不再通过应用状态暴露给其他代码，测试使用测试内实例捕获。

`STORAGE` 现在绑定领域所属表的 `Storage`，不直接交付 SQLAlchemy Engine。结构预检统一检查当前契约后按外键顺序创建表；插件只能初始化和写入所属表，只读事务禁止写入，任务表只读按领域任务类型过滤。任务完成与进度写入通过核心任务端口检查租约和数据库归属。跨领域引用统计通过同一事务的只读绑定接口完成。存储关闭或事务退出后操作失效。

这些是受信进程内协作契约，不是 SQL/OS 沙箱；Python 反射和插件自己的本机代码能力仍属于明确的信任边界。外部插件使用 [包与进程契约](plugin-system.md)，不会获得该存储对象。

凭据的加密操作由 `platform/secrets.py` 提供通用机制，领域声明用途，受信装配层派生密钥并注入操作端口。数据服务的 `Credentials`、`DataSync` 和采集函数只接收 `SecretPort`（加密、解密、快照指纹），身份服务只接收 `DigestPort`（会话摘要）；不向它们传入主密钥或暴露 cipher/key 字段。研究、行情及交易状态插件未获这些端口。

配置快照的来源、schema、修订和内容指纹验证仍由数据插件执行，原始密文处理不绕过业务校验；备份校验通过只读文件与解密端口验证密文。供应商调用仍需在内存中使用解密后的配置，不把它放进公开 API 或任务载荷。Worker 与恢复引导层目前仍属于受信代码，持有运行配置并负责创建端口；Python 进程内封装不阻止恶意代码反射，尚不能宣称密钥沙箱或任意第三方插件安全执行。

数据插件拥有目录、导入、来源配置、采集、版本发布与数据备份校验；研究插件拥有固定输入、回测、复现包、引用报告与研究备份复算；身份插件拥有账号/PIN 政策与恢复后的会话清理。核心不能解释具体行情字段、回测参数或账户规则。

### 备份校验边界

插件通过 `backup=BackupCheck(输入类型, 校验函数)` 贡献领域校验。发行版 `backup_inputs` 装配输入，核心在调用任何校验函数前检查输入集合和类型；校验结果必须是非负整数指标，重复指标明确报错。全部校验成功后才进入恢复隔离事务，不跳过失败继续启用服务。

- 身份校验只接收账户数量；研究校验通过固定查询的只读迭代器读取结果、固定输入及复算依据，不取得数据库连接或任意 SQL 接口。
- 数据校验只接收版本清单、数据目录内的 `ReadFiles` 和解密操作。文件端口仅提供读取、摘要和枚举，拒绝绝对路径、路径穿越及符号链接；不提供恢复根目录访问、文件写入或主密钥。
- 证据加载仍处于核心开启的 PostgreSQL 只读事务中；领域所有者定义固定查询，校验器只消费提取的记录。研究记录按查询迭代，避免同时复制全部输入和结果。
- 校验不会创建凭据目录或调整文件权限。文件损坏、密文解密失败或研究复算不一致会终止恢复流程，保留源备份和原状态。

### 恢复隔离边界

插件通过 `restore=RestoreStep(输入类型, 执行函数)` 声明恢复后的领域操作，发行版 `restore_inputs` 显式批准并绑定输入。核心检查全部输入集合与类型，管理同一写事务中的未完成任务取消和领域清理；身份插件只收到 `SessionReset.clear()`，执行函数不接收数据库连接或任意 SQL 接口。

身份插件拥有清理会话的固定 SQL，受信装配层在事务内将它绑定为 `RestoreScope` 操作。每个已绑定操作必须完成一次；跳过操作、执行失败或吞掉操作异常都会使核心拒绝提交，任务状态和会话一起回滚。重复调用被拒绝，成功或失败退出事务后，保留的操作也无法再次使用。已完成任务和业务记录不参与取消或清理。

该核心机制用于统一事务、必需步骤校验和操作生命周期，不识别身份插件或会话表。新增领域恢复操作通过插件声明及发行版绑定接入。恢复引导、领域 SQL 工厂与证据装配仍是受信代码；受控回调和文件路径检查不等于操作系统沙箱，也不构成对同用户代码的 OS 隔离。

### 任务执行边界

`TaskHandler.execute(context, payload)` 只接收任务输入和 `ExecutionContext`。处理器通过 `resources` 声明执行资源，发行版 `execution_resources` 显式提供绑定；缺失、额外、重复或类型错误在调用处理器前失败。执行结束后上下文关闭，不再解析资源。资源身份由 `platform/resource.py` 统一定义，核心调度不解释领域配置。

- CSV 导入和固定输入回测不获执行资源，仅计算输入。
- 同步采集获得数据目录、数据凭据操作和 `SyncReporter`。报告端口只提供进度、证据提交与断点读取，任务 ID、租约令牌和请求认证由引导层绑定；执行结束后报告端口失效。处理器不接收完整 job 记录、Settings 或通用 HTTP 客户端。
- Worker 核心负责领取、租约续期、最终发布及失败上报。插件的发布校验只收到状态码和错误详情，不能通过 HTTP 响应对象访问请求头；核心独立检查 HTTP 发布结果，插件回调不能将失败发布标记为成功。报告通道向处理器返回简化异常，不公开 HTTP 请求对象。

Worker HTTP 身份与工作台身份分离，任务接口由处理器声明授权。外部来源方法通过有时限、输出上限和请求身份校验的独立进程调用；完整配置仅在受信引导和装配层使用。当前同用户代码仍未被 OS 隔离，不能解释为恶意插件沙箱。

新增内置功能：在所属领域实现 `plugin.py`，声明依赖与贡献，再加入发行清单。普通功能不修改 HTTP 宿主、worker 分派或备份总流程。跨业务查询仍经公开接口；生命周期依赖不授予绕过鉴权或写其他插件业务表的资格。

内置功能集合在应用启动时固定，改变它需同时处理依赖清单并重建发行版。本地外部插件通过安装回执动态启用/停用；依赖检查、调用撤销和工件保留见 [插件系统](plugin-system.md)。备份校验要求当前发行版具备其业务数据对应的校验插件，不提供旧格式转换或未知插件数据的自动恢复承诺。

## 前端

| 位置 | 职责 |
|---|---|
| `extensions/plugins.ts` | 校验当前插件契约、依赖图及重复贡献，收集工作区、面板、设置、应用入口与命名扩展点 |
| `distribution.ts` | 选择默认内置插件，保持显式导航顺序 |
| `workspace/Workbench.tsx` | 导航、工具栏、内容、辅助面板和状态栏的通用界面容器 |
| `extensions/PanelHost.tsx` | 按 ID 渲染面板，处理声明的状态保留；组件卸载由 React 清理 |
| `workspace/useWindowLayout.ts` | 通用布局读取、修订冲突处理、写入队列与刷新；解析及可编辑字段由调用插件传入 |
| `plugins/*` | 业务组件、业务设置、命令、配置语义、状态和工作流 |

官方数据、市场、研究、任务、总览、交易占位、情报占位、身份、外观、维护与终端工作流均通过内置插件描述接入。工作流插件负责账号门禁、各用途的上下文装配和跨功能交互；它是默认产品体验的一部分，不是核心机制。面板及设置贡献必须声明 `scope`，通用宿主只把该 scope 对应的对象传给渲染器；缺少 scope 的资源时明确报错。各渲染器的参数类型与 scope 绑定，不接收其他用途的对象。

- 行情只读取图表状态，通过选择合约、调整停靠位置、保存视口、拆出/归并等操作协作；总览只取得目录摘要和选择操作。两者均不取得连接令牌。
- 数据与研究通过提交任务、定位数据、补数完成等操作通知工作流；不取得 `setLayout`、`setJobs` 或任意状态更新函数。工作流统一维护任务去重、导航和跨页定位。
- 外观设置只取得偏好，数据源设置取得来源配置请求客户端，本机服务设置取得服务状态与连接/启停操作；关于、备份入口、安全入口无需上下文资源。设置页不再取得完整连接对象。

数据、研究、任务组件及其子组件统一使用 `RequestClient`，接口仅包含 JSON 请求、保留原始文本的请求和不含凭据的实例标识。令牌和账户会话由受信装配层绑定，业务组件不再接收、传递令牌，也不能导入创建客户端的传输模块。工作流 `requests.ts` 声明允许的方法和路径：数据功能拥有其领域路径；研究对数据模块只有目录读取、覆盖检查、补数和重试等指定操作；任务视图只读采集证据并调用重试。传输机制不识别业务名称。

请求发送前检查路径和方法，拒绝路径穿越、编码路径及越界地址，禁止重定向。客户端绑定创建时的账户会话与地址，账户/地址变化后旧客户端拒绝调用及返回旧响应；连接变化或组件卸载撤销客户端并取消在途请求。取消不保证服务器已经接受的操作回滚，业务幂等与服务端鉴权仍然必须执行。复现包使用原始文本接口，避免数字重新序列化破坏校验。

TypeScript 字段仍是协作约束；业务请求另通过服务端作用域凭证执行，绑定账户会话、5 分钟有效期及发行版批准的路径和方法，不能申请更高权限。身份、启动、诊断和备份引导保留可信工作台权限。外部界面只贡献声明式表格，不获得内部上下文、任意 React 代码或原生桥。

任务中心只理解通用任务状态。数据与研究插件通过 `tasks.views` 提供任务名称、结果展示；数据插件另外提供采集详情和重试操作。设置分类及内容由各插件登记，设置窗口负责统一承载，不按业务分类硬编码内容。

新增已有工作区的面板时登记面板 ID 和分类；新增设置页时登记 ID、名称、排序与渲染器。核心界面不需要新增业务条件分支。各功能复用共同主题和控件反馈，不自行创建不一致的窗口框架。复杂业务界面由插件提供，普通配置优先使用声明式字段和公共渲染方式。

视图状态由终端工作流插件定义；外部声明式表格由“设置 → 插件”的按需视图入口统一承载，任意第三方面板树不在当前协议内。不可用工作区保留记录并显示明确占位，用户可以切换到已登记工作区。

## 原生窗口

Rust 的 `workspace.rs` 只负责窗口、持久化修订、分组同步及拆分归并机制。`WindowProfile` 由 `distribution.rs` 注入；当前 `plugins/workflow.rs` 声明默认状态、字段校验、联动/归并字段、拆出规则和标题。核心不包含合约、快照、行情视口或业务工作区名称的分支。

该原生贡献仍随应用编译，外部插件不能自行注入 Rust 代码。新业务状态的持久化契约必须在所属插件的前端和原生策略中同步修改，直接更新当前规范，不保留历史格式分支。

- 全量后端 374 项通过，使用隔离 PostgreSQL；前端单元 23 项通过。浏览器 38 个独立场景通过（36 个 mock 场景与 2 个真实 API/worker 场景）；原生 Rust 代码本轮未改动，此前 8 项通过。
- OpenAPI 与 TypeScript 类型已按作用域授权、插件管理和分段日期契约重新生成；TypeScript/Vite、Pyright、Ruff 通过。Vite 仍提示主包超过 500 kB；Python 测试存在两项依赖弃用提示。

macOS 桌面包已重建至 `release/Asterion_Terminal.app`，冻结 PostgreSQL/API/worker 冒烟通过，覆盖独立插件安装、内置 SDK、声明式视图、作用域授权与停用，以及正式 worker 运行外部数据源、发布固定工件来源、备份与隔离恢复。应用签名检查通过。完整证据见 [核心与插件验收](validation/core-plugins.md)。

本轮未手工重启用户工作台或操作真实账户。上述测试证明当前本地受信插件契约，不构成真实行情、实盘交易、恶意代码 OS 沙箱或其他平台分发验收。

### 合约规则插件

`asterion.contract_rules` 拥有 `contract_rule_versions` 表、不可变规则登记 API 和公开 `contract_rules.read` 能力。研究插件声明依赖，发行版装配提供独立 Storage 授权；核心机制未变。前端规则编辑器和只读依据视图由规则插件公开，研究工作区通过声明依赖消费。规则存储参与插件备份核验，规则快照参与研究输入指纹及跨环境复现。

合约规则插件现声明 `asterion.data` / `data.versions` 依赖。供应商代码和报价单位解释属于数据源适配器；规则插件只消费标准资料，不按数据源 ID 分派、不拼接供应商后缀。规则新增 `data.references` 钩子报告对资料版本的引用，既有核心存储、任务、授权和备份机制不变。

## 研究策略贡献

独立策略插件导出 `Strategy` 能力，目录插件按声明依赖聚合，研究插件消费目录；Worker 通过 `STRATEGY_RESOURCE` 使用同一装配清单。策略只返回逐根收盘的做多/空仓意图，研究引擎负责成交与账户计算。详见 [策略插件](strategy-plugins.md)。

### 安装预检与原子启用

扩展管理插件负责确认页、上传、信任确认与使用提示；核心 Packages 提供通用 inspect 和带 enabled 参数的 install。此次核心扩展用于避免分别安装、启用导致半完成用户状态：在文件锁内重验依赖、工件身份和当前状态后一次原子替换回执。检查逻辑不识别数据源或策略 ID。低层禁用安装仍用于包管理和依赖契约验证；产品安装接口只接受核对摘要且明确确认信任的安装并启用操作。未登记工件不能获得执行授权。

角色诊断界面由 `plugins/contract_roles` 贡献 `roles.diagnostics` 面板；数据工作区通过显式插件依赖引用该面板，工作流装配提供显式授权的角色列表、采集计划、批量提交、进度和数据源只读请求端口。业务查询、候选解释和表格均归角色插件，通用外壳不识别角色业务。

数据插件通过 `data.sync_dependencies` 提供无凭据的同步依赖投影和事务内固定版本读取，发布完成时发送事务内 `data.sync_published` 通知。角色插件拥有订阅工作流与续算入队规则。跨插件原子写入使用 `Storage.join`，各插件仍只能写已授权的自身表；只读 `borrow` 不变。

数据插件提供 `data.daily_sync_batch`，拥有供应商日线能力解析、逐候选同步准入及配置冻结；角色插件声明消费该能力，拥有候选推导与批量衔接入口。复用既有任务批量提交和事务加入机制，本次没有修改核心调度或增加数据源特判。

## Dashboard 组件贡献

`dashboard.widgets` 通过现有扩展登记入口发布，公开契约位于 `apps/terminal/src/plugins/overview/public.ts`。每个贡献声明稳定 ID、标题、用途、分类、默认宽度、主区/侧栏位置和渲染器。业务插件依赖 `asterion.overview` 的公开契约；overview 不反向依赖具体业务实现。默认发行版排列位于 `apps/terminal/src/distribution.ts`。

- market：历史行情、自选期货行情、板块热力图。
- trading：资产、持仓、当日盈亏、保证金、风险指标与走势。
- intelligence：新闻公告、情绪、利率信用。
- data / tasks：数据版本、任务、完成记录与 Pulse。
- overview：目录、视图布局和角色/研究导航入口。

卡片可独立排列，不等于每张卡片必须独立打包成插件。当前为可信内置 React 贡献，尚未提供第三方安装或进程隔离。账户与资讯类组件的数据能力未接入，空态不代表后端业务完成。

### 当前默认组合（覆盖上述初版组件清单）

行情插件以 `market.history` 提供合约切换和图表整合卡，热力图保留可选。交易插件提供账户概览、持仓、风险概览，账户缺失时通过 `unavailable` 分组贡献单一接入提示；`defaultVisible` 声明默认选择。情报组件全部可选。任务插件仅提供提醒，完整任务及结果回到任务中心；数据版本回到数据工作区。原独立重复卡片和总览导航卡已删除，无别名映射。布局记录中的不可用引用保留至用户明确移除或重置。

账户与持仓合并为 `trading.portfolio`，`trading.positions` 独立贡献已删除。默认贡献为行情、账户与持仓、风险概览三项。移除 `unavailable` 分组隐藏契约；无数据时照常渲染业务组件的明确空态。

总览实时行情贡献为 `market.quotes`，历史预览贡献已删除（历史图表仍在市场工作区）。工作区可通过通用 `objectTools` 声明需要对象控件，当前仅市场贡献启用。默认总览没有全局合约选择上下文。

DashboardWidget 可声明 column 为 primary/secondary；未声明的贡献进入通栏区域。DashboardLayout.items 的可选 column（primary/secondary/full）是用户显式位置覆盖，不存在时采用贡献声明。声明与持久化均验证枚举；位置变化仅保存时落盘。DashboardTable 是 overview 的公开展示控件，提供固定表头、数字列与有界滚动，不负责行情或账户数据来源。

`asterion.connections` 管理连接档案、用途隔离的加密凭据、单活动会话、命名配置切换和统一连接设置。`asterion.connector.ctp` 经声明的 `connections.connectors` hook 提供 CTP 贡献，目录在所有插件激活后的生命周期启动阶段校验并冻结。默认发行版显式绑定贡献归属，不在核心加入接入 ID 分支。

`asterion.market` 通过连接公开能力管理每个连接的行情、自选和候选目录，并提供只读合约名称投影。`asterion.trading` 直接消费连接能力查询账户，仅从 market 读取展示名称，不经行情会话访问账户。账户、资金占用和风险 UI 复用统一业务组件；CTP 不贡献 UI。详见 [连接架构](broker-connections.md) 和 [使用与验证边界](simnow.md)。
