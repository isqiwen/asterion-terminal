# Warehouse 数据服务

`asterion_warehouse` 是 Linux 上的一个 C++ 服务，只做一件事：采集并整理历史数据，用固定接口提供一份带版本的数据。它不连接柜台，不持有任何柜台凭据。多个 Terminal 和 Lab 共享它的数据。安装和配置见 [Warehouse 部署](deployment.md)。

开发者从[Warehouse 架构与通信图解](architecture.md)开始：模块边界、核心类关系、采集发布和代码阅读路线。

## 仓库与固定版本

仓库模块（`apps/services/warehouse/`）管理日线、交易日历、合约、分钟线、结算参数和历史报价单位。历史报价单位保留八位小数，其他价格和数量保留六位，写入拒绝需要舍入的数值。内部按来源分开保存：Tushare 在数据目录（见[配置](deployment.md#配置)）的 `warehouse/`，其他来源和合成结果在 `sources/<来源>/warehouse/`。

- **统一数据**：客户端只看到这一份，按版本读取，不选择也不依赖来源。Warehouse 在启动时固定各来源的版本，之后只在采集任务结束时（成功、失败或取消）纳入该任务提交的版本，后台合成与重试都读取这些固定版本，运行中任务的批次不会提前公开。相邻任务的结束通知可以合并。每个分区整块来自一个来源，Warehouse 内部的清单记录来源，只用于追溯，不发给客户端；文件以硬链接引用来源的文件，不另占空间。来源没有变化时不产生新版本。

| 表 | 来源顺序（前面的优先，后面的只补缺） |
| --- | --- |
| 日线 | Tushare → 上期所、能源中心、郑商所、大商所、中金所、广期所 → 新浪财经 |
| 分钟线 | Tushare → 新浪财经 |
| 合约表、交易日历 | Tushare |
| 结算参数 | 上期所、能源中心、郑商所 → Tushare |
| 历史报价单位 | 郑商所 → 国泰君安期货 |

规则只维护一处（`warehouse/composition.cpp` 的 `sources_of`）。理由：Tushare 历史完整、各交易所口径一致；公开来源只填它缺的部分。结算参数相反，交易所文件是原件，Tushare 只补交易所没有的部分。
- 写入先完成分区文件，再发布不可变的版本清单，最后切换 `current`。旧版本的文件不改不删，所以读取一个固定版本不受之后的采集影响。版本清单只列分片（每个表、交易所、月份一片，`shards/<sha256>.json`，按内容命名），一次提交只写它改动的月份，顶层清单只记录分片引用。
- 只读请求见[通信协议](../protocol.md#8-warehouse)：版本、文件、摘要和覆盖。
- 第一次查询可以不指定版本，之后的分页和下载必须带回同一版本；指定的版本不存在就失败，不改读最新版本。
- 日期覆盖表示已有分区。
- **新鲜度与缺口**：摘要按该版本的交易日历，给出日线、分钟线、结算参数和历史报价单位应有的最新交易日（截至北京时间昨天的最后一个开市日；分钟线的合约在摘牌日为止），以及从每个交易所（分钟线按合约）的第一天起缺少的开市日数。没有交易日历的交易所不计缺口。理由：只有交易日历能区分“没开市”和“没采到”。

### 历史最小变动价位

Warehouse 的 `price_ticks` 表保存交易所、品种、交割合约、最小变动价位、来源网址以及有效交易日区间 `[effective_from, effective_until)`。交割合约为空表示适用于该品种各交割月；价格单位与合约的报价单位一致。

- **采集与补齐**：每个任务只取一张表。Terminal 提交日线、分钟线或结算参数时，同时提交相同交易所和日期范围的报价单位任务；再次提交会补齐参数缺口。
- **来源**：郑商所使用官方每日参考 XML 的 `TckSz`；上期所、能源中心、大商所、中金所、广期所使用国泰君安期货[历史交易日历](https://www.gtjaqh.com/pc/calendar)的品种报价单位，来源标为 `gtja`。理由：交易所的部分历史合约表没有价位字段，期货公司报表保留了按交易日生效的数值。
- **历史缺口**：每份报表只覆盖对应交易日，不向前后日期延用。国泰君安期货的早期报表可能没有价位列，例如 2020-06-01；更早日期也可能没有档案。缺口保持缺失，Tushare 合约快照不用于填补历史。
- **查看与重采**：Terminal 展示采集任务、覆盖和参考表，可按日期查看数值、有效区间与来源，也可单独重采“历史报价单位”。数据自动进入固定版本；重新采集不改变已有回测版本。参数缺失或同日数值冲突时，该区间不能回测。

## 历史采集

`apps/services/warehouse/acquisition/` 直接请求供应商和交易所，不用 Python：

| 来源 | 内容 |
| --- | --- |
| `tushare` | 合约表、交易日历、日线、单合约 1 分钟线、结算参数（[`fut_basic`](https://tushare.pro/document/2?doc_id=135)、[`fut_trade_cal`](https://tushare.pro/document/2?doc_id=467)、[`fut_daily`](https://tushare.pro/document/2?doc_id=138)、[`ft_mins`](https://tushare.pro/document/2?doc_id=313)、[`fut_settle`](https://tushare.pro/document/2?doc_id=141)） |
| `shfe`、`ine`、`czce` | 各自交易所的日线和结算参数；`czce` 另提供历史报价单位 |
| `dce`、`cffex`、`gfex` | 各自交易所的日线 |
| `gtja` | 国泰君安期货交易日历中的上期所、能源中心、大商所、中金所、广期所历史报价单位 |
| `sina` | 新浪财经公开行情的日线和 1 分钟线，最后一个补缺来源；中金所不在这个接口上 |

- 供应商和交易所采集截止到前一天，避免将尚未结束的交易日作为完整分区保存。
- 新浪财经按合约回答：某天的日线按 Tushare 合约表里当天在市的合约逐个读取；没有合约表就不取，否则这一天看似完整却缺了之后到期的合约；分钟线只能回溯约两个交易日，一次回答的最早一天可能不全，标为 `partial`。请求限速每分钟 60 次，理由：它会封禁高频访问。夜盘归入下一个工作日。
- 郑商所结算参数表从 2016 年起可读。2022-11-07 之前的表没有“手续费收取方式”，按每手收费读取，理由：该列加入当天全部为绝对值，第一个比例收费到 2023-07-20 才出现。2017-06-22 及以前的平今手续费只有“减半”标志，Y 取一半、N 取全额。上期所和能源中心 2024-07-22 之前的文件没有平今手续费，这两列入库为缺失。郑商所 2015-09-30 及以前的文件只有保证金、没有手续费，不采集。理由：缺失的历史费用不用零值、当前费率或推算代替。Tushare 结算参数按其文档示例的单位读取：保证金率为小数，手续费率为千分之，每手手续费为元；保证金率不小于 1 的表拒绝入库。它的平今字段 `offset_today_fee` 没有说明是费率还是每手金额，平今两列入库为缺失，所以来自 Tushare 的参数暂时不能用于回测。
- 来源仓库保持各自数据，只在 Warehouse 内部使用；跨来源选择仅在合成时进行。数字保留原始十进制文本；没有成交时开高低保持缺失；接口返回行数达到上限时拒绝入库，避免截断。
- Tushare 分钟线按合约和交易日分区；夜盘归入下一个开放交易日。请求不自动重试，同一账户的请求额度由各任务共享（每分钟 1–500 次）。
- 交易所文件包括 JSON、CSV、分隔文本和郑商所早年的年度 ZIP（GB18030 编码）。当前适配器通过 HTTPS 请求上期所、能源中心、郑商所，通过 HTTP 请求中金所、大商所、广期所的公开接口。交易所公布的保证金和手续费参数不是券商的实际费率。
- **任务范围**：日历和合约表按交易所和日期区间采。日线、结算参数和历史报价单位可以按交易所和区间采，也可以按品种或合约采；分钟线只按品种或合约采。品种或合约不填日期时，Warehouse 从合约表（每次先刷新）取各合约的上市日和摘牌日；填了日期就取两者的交集。按品种或合约采日线、结算参数和报价单位时，仍然整天取所在交易所的全部合约，理由：来源按交易所和交易日发布，一次请求本来就带着当天全部合约，而按交易日存储才能对照日历判断是否采齐。
- **任务**：由 Warehouse 管理。一个任务取一张表，按上表的顺序依次经过各来源，只取前面来源没有的分区；某个来源失败时，后面的来源照常补缺，任务最后标为失败并显示原因，已取得的数据保留。任务逐个执行，最多排队 16 个。状态使用 `TaskState` 枚举，显示为等待、运行、完成、失败、取消和中断。客户端断开不取消任务；重启后未完成的任务标为中断，不自动重发。
- 日线任务先取得日历和合约表，再按开市日补缺，按交易所和月份写入来源仓库。分钟线、交易所日线、结算参数和历史报价单位逐日读取，按批写入来源仓库；取消或失败时已取得的数据照样保留，并在任务结束时进入统一数据。空响应和 HTTP 404 记为缺口，下次可以再采；HTTP 412、其他拒绝和解析失败使任务失败。
- 来源的启用、额度和凭据只在主机上配置。

## Terminal 和 Lab 的连接

- 在“设置 → 关于”复制本机客户端证书指纹（Terminal 第一次启动时生成，与交易主机登记的是同一个），登记到 Warehouse 主机，再填写主机、端口和服务端证书指纹。连接是 TLS 1.3 双向固定指纹；登记的客户端都能读取数据和管理采集，因为它们属于同一个使用者，采集只追加新版本。
- Terminal 在 `terminal/data/warehouse.json` 保存地址和服务端指纹，私钥在 `terminal/data/tls/client.key`。修改地址不影响服务和其他客户端。
- 数据页直接读取 Warehouse 的版本、覆盖和采集任务（新的在前，按页读取，支持查看更早任务），定期刷新；也能看到其他客户端提交的任务。读取、采集和取消都不自动重发。
- Lab 用同一份客户端证书读取固定版本，见 [Lab](../lab/README.md#固定数据版本)。

## 从协议开始接入

消息格式、命名规则和全部操作见[通信协议](../protocol.md)。

- 启动采集用 `start_acquisition`，只说要哪张表、哪些交易所或合约、哪段日期，记住自己生成的任务 ID；返回只表示已接纳，查询 `get_acquisition_task` 才能知道结果。回复丢失时先按 ID 查询，重复提交同一 ID 返回冲突。
- 读取数据先用 `get_dataset_version`（版本留空）取得当前版本，之后的分页和下载都带这个版本；下载完成后核对整个文件的 SHA-256。
