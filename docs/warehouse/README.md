# Warehouse 数据服务

`asterion_warehouse` 是运行在 Linux 主机上的单一 C++ 服务，专注历史数据采集与版本化管理，并通过固定接口向客户端提供统一数据集。它不连接柜台，不持有任何柜台凭据，供多个 Terminal 与 Lab 共享。安装与配置见[Warehouse 部署](deployment.md)。

开发者可先阅读[Warehouse 开发者导读](architecture.md)，了解模块边界、核心类关系、采集发布流程与代码入口。

## 仓库与固定版本

Warehouse（`apps/services/warehouse/`）统一管理九张表：日线、分钟线、交易日历、合约表、结算参数、历史报价单位、仓单、会员持仓与库存周报。历史报价单位保留 8 位小数，其余价格与数量保留 6 位，写入时拒绝需要舍入的数值。服务内部按来源分仓存储：Tushare 位于数据目录（见[配置](deployment.md#配置)）的 `warehouse/`，其余来源与合成结果位于 `sources/<来源>/warehouse/`。

- **统一数据与来源优先级**：客户端只读取合成后的统一研究数据集，按固定版本访问，不感知也不选择底层来源。Warehouse 启动时固定各来源版本，之后仅在采集任务结束（成功、失败或取消）时纳入该任务提交的版本，运行中任务的中间批次不提前公开（相邻任务的完成通知可合并）。每个分区整块来自单一来源，内部清单记录来源供追溯但不暴露给客户端；分区文件通过硬链接复用来源文件，零拷贝且不额外占盘；来源无变化时不生成新版本。

| 表 | 来源顺序（前者优先，后者只补缺） |
| --- | --- |
| 日线 | Tushare → 上期所、能源中心、郑商所、大商所、中金所、广期所 → 新浪财经 |
| 分钟线 | Tushare → 新浪财经 |
| 合约表、交易日历 | Tushare |
| 结算参数 | 上期所、能源中心、郑商所、广期所 → Tushare |
| 历史报价单位 | 内置核验表（`verified`） → 郑商所 → 国泰君安期货 |
| 仓单 | 上期所、能源中心公开原件 → Tushare |
| 库存周报 | 上期所 → Tushare |
| 会员持仓 | 上期所、能源中心、广期所官网 → Tushare（其余交易所） |

来源规则唯一维护在 `composition.cpp` 的 `sources_of()`。理由：行情优先采用结构统一的 Tushare，公开来源补缺；结算参数相反，以交易所原件为准、Tushare 补缺；最小变动价位极少变更，直接使用经核验的内置生效区间表，公开来源仅做每日增量核验。

- **不可变版本与分片清单**：写入先落盘 Parquet 分区文件，再写入不可变版本清单，最后原子切换 `current`。采集绝不改写已发布文件，保留的固定版本不受后续采集影响，废弃快照通过离线 GC 清理。版本清单按“表 / 交易所 / 月份”拆分为内容寻址分片（`shards/<sha256>.json`），单次提交仅写变动月份的分片并在顶层清单记录引用；读取时校验顶层清单与分片摘要，不符即中止。`tests/warehouse/fixtures/record-format/` 固定了两版本六表的落盘样本以防格式回退。
- **固定版本只读契约**：接口清单见[通信协议](../protocol.md#8-warehouse)。首次请求可省略版本号以取得当前版本，后续分页与分区下载必须携带同一版本号；指定版本不存在时直接失败，不回退到最新版。
- **合约级覆盖统计**：开市日范围自上市日起算至下市日或昨日（取较早者）。首尾已有数据之间缺少的开市日记为缺口，最后已有日之后记为待更新，首个已有日之前不计缺口，来源确认无数据的日子单独计数。理由：研究的基本单位是合约，仅看品种会掩盖单个合约的缺口。
- **新鲜度与缺口**：摘要按当前版本的交易日历，给出日线、分钟线、结算参数、仓单与会员持仓应有的最新交易日（截至北京时间昨日的最后一个开市日；分钟线合约止于摘牌日），并统计各交易所（分钟线按合约）自首日起缺失的开市日数。无日历的交易所不计缺口；登记为“来源无数据”的开市日单独计数，不计入缺口；库存周报仅展示已有报告的日期范围。理由：日频缺口依据交易日历判定，周报不要求每日出报。
- **数据质量自检**：使用 Lab Python 运行时执行 `build/electron-resources/python/bin/python3 -I -B -m asterion_lab.audit --warehouse-dir <数据目录>`（或 `--lab-dir <lab数据目录>`），对指定固定版本自动执行交叉校验：覆盖缺失交易日（跳过已登记来源无数据分区）、分钟合计量与日线成交量比对（附来源标注）、OHLC 合法性、收盘/结算及相邻日/分钟跳变与异常持仓跳变扫描；发现异常返回非零退出码，并支持导出 JSON 报告。
- **离线垃圾回收（GC）**：停服后以服务账户执行 `sudo -u <服务账户> /opt/asterion/warehouse/bin/asterion_warehouse gc [--data-dir <数据目录>] [--keep-last 5] [--keep-source-last 1] [--keep-version <sha256>] [--keep-file <清单>] [--apply]`（默认干跑不删除；省略 `--data-dir` 时读取 `config/warehouse.json` 的 `data` 路径，不依赖 systemd 凭据）。命令持 `warehouse.lock` 独占锁校验保留清单、分片摘要与 Parquet 文件存在性后，按“版本清单 → 分片 → Parquet 文件”的顺序安全回收无引用旧数据，保护最新与显式固定版本（版本历史翻页遇到已清理父版本时自动截断）。
- 开发期若无需保留旧快照，可在采集与研究结束后以 `--keep-last 1 --keep-source-last 1 --apply` 仅保留当前统一版本及各来源当前版本，Lab 本地旧缓存亦可随时删除。

### 中金所早期日历

Tushare 的 CFFEX 2010～2014 年日历仅返回开市日。正式上市后未返回的日期与中金所公告的周末及节假日休市完全一致，不应据此补采行情（理由：缺少休市行不等于缺少交易日）。[2010-04-16 正式交易之前](http://www.cffex.com.cn/cn/jystz/20100331/10718.html)的记录属于上市前区间，研究范围仍按合约上市日截断。

休市口径依据中金所[2010 年劳动节](http://www.cffex.com.cn/cn/jystz/20100427/10715.html)、[端午节](http://www.cffex.com.cn/cn/jystz/20100602/10733.html)、[中秋及国庆](http://www.cffex.com.cn/cn/jystz/20100917/13115.html)，以及 [2011](http://www.cffex.com.cn/cn/jystz/20101229/14637.html)、[2012](http://www.cffex.com.cn/cn/jystz/20111229/16211.html)、[2013](http://www.cffex.com.cn/cn/jystz/20121228/16922.html)、[2014](http://www.cffex.com.cn/cn/jystz/20131226/17482.html) 年休市公告。

### 历史最小变动价位

`price_ticks` 表记录交易所、品种、交割合约、最小变动价位、来源网址及生效交易日区间 `[effective_from, effective_until)`。交割合约为空表示适用于该品种全部交割月，价格单位与合约报价单位一致。

- **内置核验表**：Warehouse 启动时读取 `config/exchange_rules.json` 中经官方公告核验的六家交易所生效区间，幂等写入 `verified` 内部来源并合成至统一数据集。采集行情与每日更新无需逐日抓取外部网页，离线或公开门户受限时仍覆盖完整历史。
- **公开来源增量核验**：开启每日更新后，Warehouse 每日核对各交易所最近一个开市日（理由：新品种或最小变动价位调整会在之后的交易日持续出现，不必逐日回溯）。郑商所读取官方每日参考 XML 的 `TckSz`，其余五所读取国泰君安期货[历史交易日历](https://www.gtjaqh.com/pc/calendar)中的报价单位，与 `config/exchange_rules.json` 中当日生效的规则逐项比对，优先采用合约专属规则，其次采用品种通用规则：一致时不重复落盘；发现未登记新品种或数值变更时任务明确失败并指出品种与日期，提示更新规则文件。
- **查看与准入**：Terminal 在“数据 → 浏览 → 历史报价单位”按生效日起始时间降序展示数值、区间与来源，按合约筛选时同时展示该合约及同品种通用规则；区间内参数缺失或同日数值冲突时禁止回测，因子评价不依赖最小变动价位。

### 仓单、会员持仓与库存周报

| 表 | 来源与范围 | Tushare 权限 |
| --- | --- | --- |
| `warehouse_receipts` | 上期所与能源中心优先读官网仓单日报，缺原件及其他商品交易所用 [`fut_wsr`](https://tushare.pro/document/2?doc_id=140) | 需 2000 积分 |
| `member_positions` | 上期所、能源中心、广期所读官网合约排名；其余交易所用 [`fut_holding`](https://tushare.pro/document/2?doc_id=139) 读取会员成交量、多空持仓及变化 | 需 2000 积分 |
| `inventory` | 上期所优先读官网库存周报，缺原件及能源中心用 [`fut_inv_weekly`](https://tushare.pro/document/2?doc_id=495)，记录库存、仓单量、可用库容及各自变化 | 需 5000 积分 |

- **请求粒度与权限检查**：三表按交易所与报告日分区。Tushare 仓单与库存按当日存续品种逐个请求，会员持仓按存续品种与四位年月合约分别读取（保留品种汇总与合约排名）。理由：只查品种会漏掉合约明细，按整所分页则会出现跨页重复与漏数。触及接口返回上限时拒收，权限不足时任务报错；权限与覆盖按[真实研究数据验收](../acceptance/research-data.md#仓单会员持仓与库存)核对。
- **上期所与能源中心原件**：
  - 仓单日报读取仓库明细并排除重复合计，上日数量由当日数量减增减量推算；早年未给品种代码时按原报名称识别，报告日、单位与更新时间取原报。理由：Tushare 部分历史仓单遗漏整批仓库，官网原件完整且可与后备源互补。
  - 上期所库存周报读取仓库明细并排除重复合计，保留燃料油独立分表品级；黄金仅存一条汇总，库存与仓单量及增减相同、库容留空（理由：原报注明黄金库存即已注册标准仓单量）。原报空值保持为空。仓单与库存品种名称中的“仓库/厂库”拆存至 `warehouse_type`（未标明则留空），理由：同日同地点可能同时存在仓库与厂库记录，仅凭仓库名无法区分。
  - Tushare 将能源中心仓单与库存归在 `SHFE` 下，入库时按品种重新归属 `INE`；国际铜与沪铜在 Tushare 共用代码 `CU`，按原报产品名称“铜(BC)”归入 `INE/bc`，其余归入 `SHFE/cu`。
- **广期所会员排名**：先从[官网](http://www.gfex.com.cn/gfex/rcjccpm/hqsj_tjsj.shtml)品种列表取得当日公布排名的合约，再分别读取三张排名榜。理由：Tushare 采集结果遗漏早期碳酸锂合约。
- **字段归属与合并口径**：
  - Tushare 仓单与库存保留原 `unit` 及仓库明细/小计/合计/总计标签，聚合前须筛选同一层级与单位；年度、编号等标签统一存为文本以保留前导零。
  - 会员持仓的 `contract` 仅在来源明确给出交割合约时填写，品种汇总行留空；郑商所汇总代码 `PTA` 归为品种 `ta`。上期所、能源中心、广期所按合约与会员合并成交量、多头、空头三榜，未上榜一侧留空（理由：三榜同排名未必是同一会员，而 Tushare 会把部分未上榜填为零），榜单合计不作为会员入库。上期所品种汇总中的会员类型汇总单独保留，混入的能源中心品种排除；早年合约行中的类型汇总及仅合计活跃月的 `*actv` 不入库（避免按合约求和重复计数或误作全品种总量）；早年无报告日的文件按请求日期归属。来源正常返回空榜时按“来源无数据”处理，不伪造零持仓。套保压力研究另需商业套保者分类数据。
- **观测时间与可追溯性**：`day` 为报告对应日期；`published_ms` 保存来源明确提供的发布时间（上期所、能源中心取原报 `update_date` 北京时间转 UTC，广期所与 Tushare 未提供时留空）；`observed_ms` 为 Warehouse 收到响应的 UTC 毫秒时间戳。补采历史不得用报告日冒充发布时间；重采修订报告生成新版本，旧版本保留原观测。理由：历史研究必须区分报告日期、信息可知时点与事后修订。
- **浏览与研究读取**：结算参数与三张基本面表在 Terminal“数据 → 浏览”均从最新日期往回翻页，服务端按日分片跳过早先分区，仅读取当前页涉及的报告日。Warehouse 随行情自动补齐三张基本面表；Lab 可通过 `Dataset.read` / `Dataset.query` 按报告日读取固定版本同名表，外部数据的可用时点对齐与策略输入按[开发计划](../plan.md)推进。

## 历史采集

`apps/services/warehouse/acquisition/` 直接用 C++ 请求数据源与交易所，采集截止至前一个交易日，避免把未收盘的当日存为完整分区。

```mermaid
flowchart LR
  Task["采集任务"] --> Prereq["按表补齐前置: 日历、合约表、结算参数、日线"]
  Prereq --> Fetch["按表来源顺序逐源补缺"]
  Fetch --> Src["写入来源仓库 (Parquet 分区)"]
  Src --> Compose["任务结束后后台合成 (硬链接，零拷贝)"]
  Compose --> Publish["写入不可变版本清单并切换 current"]
```

### 来源与限速

| 来源 | 内容 | 限速 | 特殊边界 |
| --- | --- | --- | --- |
| `tushare` | 合约表（[`fut_basic`](https://tushare.pro/document/2?doc_id=135)）、日历（[`fut_trade_cal`](https://tushare.pro/document/2?doc_id=467)）、日线（[`fut_daily`](https://tushare.pro/document/2?doc_id=138)）、涨跌停价（[`ft_limit`](https://tushare.pro/document/2?doc_id=368)）、1 分钟线（[`ft_mins`](https://tushare.pro/document/2?doc_id=313)）、结算参数（[`fut_settle`](https://tushare.pro/document/2?doc_id=141)）、[仓单、会员持仓与库存周报](#仓单会员持仓与库存周报) | 1–500 次/分（全局共享） | 分钟线按合约与交易日分区，夜盘归入下一开市日；日线按 7 日窗口缓存 `ft_limit` 写入 `lower_limit`/`upper_limit`（触达 4000 行上限自动缩为单日，无 `ft_limit` 权限时留空）；不自动重试；触及返回上限即拒收防截断 |
| `shfe`、`ine`、`czce`、`gfex` | 各自交易所日线与结算参数；`shfe`/`ine` 另供仓单；`shfe`/`ine`/`gfex` 另供会员持仓；`shfe` 另供库存周报；`czce` 另供历史报价单位 | `gfex` 跨任务共享 2 秒间隔，其余各 45 次/分 | `shfe`/`ine`/`czce` 使用 HTTPS，`gfex` 使用 HTTP；广期所突发连发会被拒，须均匀限速；早年郑商所为 GB18030 年度 ZIP |
| `dce`、`cffex` | 各自交易所日线 | 各 45 次/分 | HTTP 公开接口，高频访问易被门户拦截或断连 |
| `gtja` | 上期所、能源中心、大商所、中金所、广期所历史报价单位 | 45 次/分 | 连续约 60 次请求会被服务端断连 |
| `sina` | 日线与 1 分钟线（末级补缺源，不含中金所） | 60 次/分 | 依赖 Tushare 合约表逐合约抓取（无合约表不取）；无成交零值入库为缺失；分钟线仅回溯约 2 个交易日，首日标 `partial` 不重取；夜盘归下一工作日 |

- 各来源仓库彼此独立、仅存内部，跨来源优选只在后台合成阶段发生。数值保留原始十进制文本；日线中为零的开高低记为缺失，三者全缺失时收盘亦留空，结算价与成交量照录（理由：执行回放需要真实的当日日内价格）。交易所公布的保证金与手续费均不含期货公司加收。
- 来源启用、频控与凭据仅在服务主机配置。

### 结算参数口径与历史边界

| 交易所 | 来源与口径 | 历史边界与特殊规则 |
| --- | --- | --- |
| 郑商所 | 官网原件优先，Tushare 补缺（比例费率为万分比，每手为元） | 2016 年起可读，2015-09-30 及以前无手续费不采；2022-11-07 前无“收取方式”列，按每手读（首个比例收费见于 2023-07-20）；2017-06-22 及以前平今仅给减半标志（`Y` 减半、`N` 全额）；Tushare 三位合约代码按交易日补齐十年位 |
| 上期所、能源中心 | 官网原件优先，Tushare 补缺（比例费率为千分比，每手为元） | 2024-07-22 之前官网原件无平今手续费，入库为缺失（不用零值或推算替代） |
| 广期所 | 统一取自官网接口 | 不使用 Tushare 结算参数 |
| 中金所 | Tushare（保证金率为百分数，如 `TS` `0.5` → `0.005`） | 比例与每手两列填同一数值：国债（`ts`/`tf`/`t`/`tl`）按元/手解析，股指（`if`/`ih`/`ic`/`im`）按万分比解析；平今字段按普通手续费的百分比换算（[交易所原表](http://www.cffex.com.cn/sj/jscs/202611/23/20261123_1.csv)中股指 `1000%` 即普通手续费的 10 倍），缺失留空 |
| 大商所 | Tushare（保证金率为小数；按 `config/exchange_rules.json` 的 `dce_settlement_fees` 解析计费单位） | `trading_fee_rate` 为空且元/手与万分比混填在 `trading_fee`（不含独立日内开仓费）；未登记品种、日期越界或无法唯一判定单位时整日拒收（`verified_through` 记录上次人工核对日期，不阻断日常自动更新）；`offset_today_fee` 同口径解析，缺失留空 |

- Tushare 其余交易所保证金率均为小数；换算后 `≥ 1` 的记录拒收入库。
- 大商所 23 个品种的计费单位已核对至 2026-11-17（15 个按手数、8 个按成交金额，费率数值仍取当日结算参数），依据[华金期货 7 月 10 日表](https://www.huajinqh.com/UserFiles/upload/file/20260709/手续费标准表20260710.pdf)、[大商所 9 月原木/胶合板/纤维板通知](https://www.ghlsqh.com.cn/company/news/show-28785.html)与[申银万国 11 月 16 日公示](https://www.sywgqh.com.cn/Pc/Aboutus/Public_Info/history_fee/132274.html)。

### 任务范围与调度规则

| 任务类型 | 指定范围 | 自动前置依赖 | 说明 |
| --- | --- | --- | --- |
| 日历、合约表 | 交易所 + 日期区间 | 无 | 仅采该表 |
| 结算参数、历史报价单位 | 交易所 + 区间，或品种/合约 | 无 | 按品种/合约请求时仍整日采集所在交易所全部合约 |
| 日线 | 交易所 + 区间，或品种/合约 | 交易日历 → 合约表 → 结算参数 | 同上；理由：来源按交易所整日发布，按日存储才能对照日历判齐 |
| 分钟线 | 仅品种或合约 | 交易日历 → 合约表 → 结算参数 → 日线 | 不填日期时先刷新合约表并取合约存续期，填日期则取交集 |
| 仓单、会员持仓、库存周报 | 交易所 + 区间，或品种/合约 | 交易日历 → 合约表 | 按交易所整日采集 |

- **队列与优先级**：任务串行执行，队列上限 16 个。日线与分钟线优先调度，其余任务在完成当前分区后让行，待行情任务结束后从断点继续（理由：首次回补基本面可能耗时数小时，不应阻塞行情采集；让行前已提交的批次可随行情任务一并合入统一数据集）。状态遵循 `TaskState`（等待、运行、完成、失败、取消、中断）。取得日历与合约表后即预估本次全部分区总数（含前置表，同一分区多源补缺只计一次）。客户端断线不取消任务；服务重启后未完成任务标为中断，不自动重跑。
- **逐日读取与失败处理**：仅请求开市日（有日历按日历，无日历按工作日），分批落盘来源仓库。某源出现断连、凭据失效、权限拒绝或限流时，本任务不再重试该源，后续来源继续补缺；空响应与 HTTP 404 记为缺口，HTTP 412、请求拒绝或解析错误使任务标为失败。取消或失败时，此前已落盘的批次照常保留并在任务结束时进入统一数据集。
- **来源无数据**：单表完成且无来源报错或取消时，若某分区全部支持来源均返回空且按日历已过 2 个交易日，写入 `acquisition/empty-<表>.txt`（不进数据集、后续跳过，重采有数后自动移除）。理由：区分来源本无数据与节假日/延迟发布，同时避免空分区误导研究。无日历的交易所不作此判定。
- **更新到最新**：按已入库交易所补齐日线、未摘牌合约分钟线及缺失结算参数至[应有最新交易日](#仓库与固定版本)，并回补已存区间内的非空缺口；对已存分钟线的品种，从其最早已采分钟日按日线持仓量与摘牌规则重建只向后换月的主力序列，新主力从换月前一日自动纳入分钟线更新，首个主力从采样首日补起（已覆盖区间不重复建单，跨年先补日历）。单独采集远月不改变主力判定。未采过行情的交易所不自动补，同表已有排队或运行任务时跳过。支持每日按配置的北京时间自动触发，也可由客户端随时手动触发。
- **合约表自动维护**：开启每日更新时，Warehouse 启动后自动补齐缺合约表的交易所，每日更新时再刷新全部交易所（理由：品种目录来自合约表，不应要求用户先手动采集）。运行时展示为后台更新，成功后不留任务记录，仅失败时通知并在下次启动或每日更新重试。
- **基本面自动跟随行情**：每日更新与“更新到最新”会为各交易所补齐其已有行情日期范围内缺失的仓单、会员持仓与库存周报，排在行情任务之后（理由：基本面为行情配套数据，不需单独发起采集，且长耗时历史回补不能阻塞行情）。同任务内各交易所或合约均从自身首个缺口起采（前置步骤同此），不把数据补到已采区间之前。库存周报逐开市日查询并沿用来源无数据规则，不预设节假日前后发报日；未正常结束时，部分空响应提示“周报按报告日提供”，全空提示“没有新周报”，均不计入日频无数据计数（理由：非报告日无周报属常态）。

## Terminal 和 Lab 的连接

- 在 Terminal“设置 → 关于”复制客户端证书指纹（首次启动生成，与 Market、Trading 共用同一身份），登记至 Warehouse 主机，再在“设置 → 数据服务”填写主机、端口与服务端证书指纹。连接采用 TLS 1.3 双向固定指纹；已登记客户端均可读取数据和管理采集（采集只追加新版本，不破坏已有版本）。
- Terminal 在 `terminal/data/warehouse.json` 保存地址与服务端指纹，私钥位于 `terminal/data/tls/client.key`，修改地址不影响服务及其他客户端。
- 数据页直连 Warehouse 拉取摘要、覆盖、版本历史与采集任务列表（按新到旧分页，支持查看更早任务）并定时刷新，可同步查看其他客户端提交的任务；读取、采集、更新与取消均不自动重发。
- Lab 使用同一客户端证书按固定版本读数，见[固定数据版本](../lab/README.md#固定数据版本)。

## 从协议开始接入

完整消息格式、命名规范与操作清单见[通信协议](../protocol.md)。

- 发起采集调用 `start_acquisition`，指定表、交易所或合约及日期区间，并由调用方生成唯一任务 ID；返回成功仅表示任务已接纳，进度与结果通过 `get_acquisition_task` 查询。回复丢失时须先按 ID 查询，重复提交同一 ID 返回 `CONFLICT`。
- 读取数据先调用 `get_dataset_version`（版本留空）取得当前版本号，后续分页与分块下载均携带该版本号；分区下载完成后须核对整文件 SHA-256。
