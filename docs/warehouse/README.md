# Warehouse 数据服务

`asterion_warehouse` 是 Linux 上的一个 C++ 服务，只做一件事：采集并整理历史数据，用固定接口提供一份带版本的数据。它不连接柜台，不持有任何柜台凭据。多个 Terminal 和 Lab 共享它的数据。安装和配置见 [Warehouse 部署](deployment.md)。

开发者从[Warehouse 架构与通信图解](architecture.md)开始：模块边界、核心类关系、采集发布和代码阅读路线。

## 仓库与固定版本

仓库模块（`apps/services/warehouse/`）管理日线、交易日历、合约、分钟线、结算参数、历史报价单位、仓单、会员持仓和库存周报。历史报价单位保留八位小数，其他价格和数量保留六位，写入拒绝需要舍入的数值。内部按来源分开保存：Tushare 在数据目录（见[配置](deployment.md#配置)）的 `warehouse/`，其他来源和合成结果在 `sources/<来源>/warehouse/`。

- **统一数据**：客户端只看到这一份，按版本读取，不选择也不依赖来源。Warehouse 在启动时固定各来源的版本，之后只在采集任务结束时（成功、失败或取消）纳入该任务提交的版本，后台合成与重试都读取这些固定版本，运行中任务的批次不会提前公开。相邻任务的结束通知可以合并。每个分区整块来自一个来源，Warehouse 内部的清单记录来源，只用于追溯，不发给客户端；文件以硬链接引用来源的文件，不另占空间。来源没有变化时不产生新版本。

| 表 | 来源顺序（前面的优先，后面的只补缺） |
| --- | --- |
| 日线 | Tushare → 上期所、能源中心、郑商所、大商所、中金所、广期所 → 新浪财经 |
| 分钟线 | Tushare → 新浪财经 |
| 合约表、交易日历 | Tushare |
| 结算参数 | 上期所、能源中心、郑商所、广期所 → Tushare |
| 历史报价单位 | 内置核验表（`verified`） → 郑商所 → 国泰君安期货 |
| 仓单 | 上期所、能源中心公开原件 → Tushare |
| 库存周报 | Tushare |
| 会员持仓 | 上期所与能源中心官网；其他交易所用 Tushare |

规则只维护一处（`warehouse/composition.cpp` 的 `sources_of`）。理由：行情优先使用结构统一的 Tushare 接口，公开来源补齐缺口。结算参数相反，交易所文件是原件，Tushare 只补交易所没有的部分；最小变动价位属于极少变动的交易所合约规格，直接采用经核验的生效区间表，公开来源仅用于增量核验。
- 写入先完成分区文件，再发布不可变的版本清单，最后切换 `current`。旧版本的文件不改不删，所以读取一个固定版本不受之后的采集影响。版本清单只列分片（每个表、交易所、月份一片，`shards/<sha256>.json`，按内容命名），一次提交只写它改动的月份，顶层清单只记录分片引用。读取时核对顶层清单与分片的内容摘要，内容与版本号不符时停止读取。`tests/warehouse/fixtures/record-format/` 固定一份两版本六表落盘样本防格式回退。
- 只读请求见[通信协议](../protocol.md#8-warehouse)：版本、文件、摘要和覆盖。
- 第一次查询可以不指定版本，之后的分页和下载必须带回同一版本；指定的版本不存在就失败，不改读最新版本。
- 日期覆盖表示已有分区。覆盖按合约统计：开市日从上市日算到下市日或昨天，首尾已有数据之间缺的是缺口，最后一个已有日之后是待更新，第一个已有日之前不算缺口，来源确认无数据的日子单独计数。理由：研究的基本单位是合约，只看品种会漏掉单个合约的缺口。
- **新鲜度与缺口**：摘要按该版本的交易日历，给出日线、分钟线、结算参数、仓单和会员持仓应有的最新交易日（截至北京时间昨天的最后一个开市日；分钟线的合约在摘牌日为止），以及从每个交易所（分钟线按合约）的第一天起缺少的开市日数。没有交易日历的交易所不计缺口；记为来源无数据的开市日单独计数，不算缺口。库存周报只显示已有报告的日期范围。理由：日频缺口依据交易日历，周报不要求每个交易日都有报告。
- **数据质量自检**：使用已准备的 Lab Python 运行时执行 `build/electron-resources/python/bin/python3 -I -B -m asterion_lab.audit --warehouse-dir <数据目录>`（或 `--lab-dir <lab数据目录>`），对指定固定版本执行自动交叉校验，涵盖缺失交易日（跳过已登记来源无数据的分区）、分钟合计量与日线成交量核对（附来源标注）、OHLC 合法性、收盘/结算与相邻日/分钟价格跳变以及异常持仓跳变扫描，发现异常返回非零退出码并可导出 JSON 报告。
- **孤立数据块清理（GC）**：停服后以服务运行账户执行 `sudo -u <服务账户> /opt/asterion/warehouse/bin/asterion_warehouse gc [--data-dir <数据目录>] [--keep-last 5] [--keep-source-last 1] [--keep-version <sha256>] [--keep-file <清单>] [--apply]`（默认干跑不删除，`--data-dir` 省略时直接读取 `config/warehouse.json` 的 `data` 路径，不依赖 systemd 凭据），持 `warehouse.lock` 互斥锁校验保留版本清单与分片摘要及 Parquet 文件存在性后，按“版本清单 → 分片 → Parquet 文件”的顺序安全回收重采替换下来的无引用旧数据，并保护最新及显式固定的版本（版本历史浏览遇到已清理的父版本时自动截断停止）。

### 历史最小变动价位

Warehouse 的 `price_ticks` 表保存交易所、品种、交割合约、最小变动价位、来源网址以及有效交易日区间 `[effective_from, effective_until)`。交割合约为空表示适用于该品种各交割月；价格单位与合约的报价单位一致。

- **内置核验表**：Warehouse 启动时从 `config/exchange_rules.json` 读取经官方公告核验的六家交易所品种历史最小变动价位生效区间，幂等写入内部 `verified` 来源仓库并在合成时纳入统一研究数据集。采集日线、分钟线及每日自动更新无需逐日抓取外部网页，离线或公开门户拦截时仍覆盖全部历史区间。
- **公开来源增量核验**：单独运行 `price_ticks` 任务时，郑商所读取官方每日参考 XML 的 `TckSz`，上期所、能源中心、大商所、中金所、广期所读取国泰君安期货[历史交易日历](https://www.gtjaqh.com/pc/calendar)中的品种报价单位，与 `config/exchange_rules.json` 逐项核对：一致时不重复写入逐日分区；出现未登记新品种或最小变动价位变更时任务明确失败并指出品种与日期，提醒更新 `config/exchange_rules.json`。
- **查看**：Terminal 在“浏览 → 历史报价单位”按日期区间展示数值、生效区间与来源；参数缺失或同日数值冲突时，该区间不能回测。因子评价不涉及委托撮合，不校验最小变动价位。

### 仓单、会员持仓与库存周报

| 表 | 数据与范围 | Tushare 权限 |
| --- | --- | --- |
| `warehouse_receipts` | 上期所与能源中心优先读取官网仓单日报，缺少原件时及其他商品交易所用 [`fut_wsr`](https://tushare.pro/document/2?doc_id=140) | Tushare 需 2000 积分 |
| `member_positions` | 上期所与能源中心读取官网公开的合约排名；其他交易所用 [`fut_holding`](https://tushare.pro/document/2?doc_id=139) 读取会员成交量、多空持仓及变化 | Tushare 需 2000 积分 |
| `inventory` | [`fut_inv_weekly`](https://tushare.pro/document/2?doc_id=495)：上期所及能源中心品种的库存周报，保留库存、已制成仓单的数量、可用库容及各自变化 | 5000 积分 |

三表按交易所、报告日保存。Tushare 仓单与库存每日按合约表中存续的品种分别请求；会员持仓按存续品种和合约分别读取，保留品种汇总与合约排名，合约代码使用四位年月。理由：只查品种会遗漏合约明细，整所分页响应则存在跨页重复和漏数。达到接口返回上限时拒收，权限不足时任务显示来源错误，账户权限与历史覆盖按[真实数据验收](../acceptance/research-data.md#仓单会员持仓与库存)核对。

上期所与能源中心的公开仓单日报按仓库明细读取，排除重复合计；上日数量为当日数量减增减量。两所品种分别归属，早年未给品种代码时按原报名称识别，数量单位和更新时间取原报。理由：Tushare 的部分历史报告遗漏整批仓库，采用完整原件补齐；没有公开原件的日期继续按来源顺序补缺。

Tushare 的能源中心仓单按其品种查询上期所报告，库存周报同样接受上期所标记，入库仍归属 `INE`；理由：Tushare 将这些能源中心报告归在 `SHFE` 下。

国际铜仓单与沪铜共同查询 `CU`，按来源的产品名称“铜(BC)”归入 `INE/bc`，其余铜记录归入 `SHFE/cu`；理由：Tushare 为两种铜仓单返回相同产品代码。

Tushare 仓单与库存数量保留来源的 `unit`，仓库明细、小计、合计和总计保留原标签，聚合前须选择同一层级与单位。年度等标签统一存为文字，兼容来源返回的数字，保留字符串编号的前导零。

会员持仓中的 `contract` 只在来源明确给出交割合约时填写，品种汇总行保持为空；郑商所汇总代码 `PTA` 归为品种 `ta`。上期所与能源中心按合约、会员合并成交量、多头和空头三张排名榜，未上榜的一侧为空，榜单合计不作为会员；理由：三个榜单的同一排名可能属于不同会员。上期所品种汇总里的会员类型汇总单独保留，混在原报中的能源中心品种排除；早年合约行里的类型汇总和只合计活跃月份的 `*actv` 不入库，理由：前者会在按合约求和时重复计数，后者不是品种总量。早年文件没有报告日时按请求日期归属。采用原报是因为 Tushare 将上期所部分未上榜数值填为零。套保压力研究另需商业套保者分类数据。

`day` 是报告所对应的日期；`published_ms` 保存来源明确提供的报告时间，上期所与能源中心采用原报的 `update_date`（北京时间转 UTC），Tushare 三个接口未提供时保存为空；`observed_ms` 是 Warehouse 收到该响应的 UTC 毫秒时间。历史补采不能用报告日期替代历史发布时间。重采修订报告会产生新版本，旧版本保留原观测。理由：历史研究需要区分报告日期、信息何时可知与后来修订。

Terminal 在“数据 → 浏览”的三张表中按日期查看，Warehouse 跟随行情自动补齐。Lab 的 `Dataset.read` 与 `Dataset.query` 可读取固定版本的同名表，日期筛选使用报告日。外部数据的策略输入与按可用时点对齐另按[开发计划](../plan.md)实施。

## 历史采集

`apps/services/warehouse/acquisition/` 直接用 C++ 请求供应商与交易所，截止到前一个交易日（避免将未收盘的当日保存为完整分区）。

```mermaid
flowchart LR
  Task["采集任务"] --> Prereq["按表补齐前置: 日历、合约表、结算参数、日线"]
  Prereq --> Fetch["按表的来源顺序逐源补缺"]
  Fetch --> Src["写入来源仓库 (Parquet 分区)"]
  Src --> Compose["任务结束后后台合成 (硬链接，零拷贝)"]
  Compose --> Publish["写入不可变版本清单并切换 current"]
```

| `dce`、`cffex` | 各自交易所日线 | 各 45 次/分 | HTTP 公开接口；高频请求会被门户拦截或断开 |
| `gtja` | 上期所、能源中心、大商所、中金所、广期所历史报价单位 | 45 次/分 | 连续约 60 次请求会被断开连接 |
| `sina` | 日线与 1 分钟线（最后补缺源，不含中金所） | 60 次/分 | 按 Tushare 合约表逐合约读（无合约表不取）；无成交零值入库为缺失；分钟线仅回溯约 2 个交易日，首日标 `partial` 不再重取；夜盘归下一工作日 |

- 来源仓库彼此独立，只在内部保存；跨来源选择只发生在后台合成阶段。数字保持原始十进制文本，无成交时开高低保持缺失。交易所公布的保证金和手续费不含期货公司加收。
- 来源的启用、额度和凭据只在主机上配置。

### 任务范围与调度规则

| 任务类型 | 指定范围 | 自动前置依赖 | 说明 |
| --- | --- | --- | --- |
| 日历、合约表 | 交易所 + 日期区间 | 无 | 仅取该表 |
| 结算参数、历史报价单位 | 交易所 + 区间，或品种/合约 | 无 | 按品种/合约请求时仍整天取所在交易所全部合约 |
| 日线 | 交易所 + 区间，或品种/合约 | 交易日历 → 合约表 → 结算参数 | 同上；理由：来源按交易所整日发布，按日存储才能对照日历判齐 |
| 分钟线 | 仅品种或合约 | 交易日历 → 合约表 → 结算参数 → 日线 | 不填日期时先刷新合约表并取合约存续期，填日期则取交集 |
| 仓单、会员持仓、库存周报 | 交易所 + 区间，或品种/合约 | 交易日历 → 合约表 | 按交易所整日采集 |

- **队列与状态**：任务逐个执行，最多排队 16 个；状态为 `TaskState`（等待、运行、完成、失败、取消、中断）。取得日历与合约目录后即预统计本次全部按日分区总数（含前置表，同一分区多源补缺只计一次）。客户端断开不取消任务；服务重启后未完成任务标为中断，不自动重发。
- **逐日读取与失败处理**：只请求开市日（有日历按日历，无则按工作日），按批落盘来源仓库。某源在连接不可用、凭据失效、权限拒绝或限流时，本任务不再重试该源，后续源照常补缺；空响应和 HTTP 404 记为缺口，HTTP 412 / 拒绝 / 解析失败使任务标为失败。取消或失败时已取得的数据照常保留并在任务结束时进入统一数据。
- **来源无数据**：单表完成且无来源失败/取消时，若某分区所有支持来源均为空，且按日历已过两个交易日，记入 `acquisition/empty-<表>.txt`（不进数据集，后续跳过；重采成功即删除记录）。理由：区分来源本无数据与节假日/晚发布，同时避免空分区误导研究。无日历的交易所不作此判断。
- **更新到最新**：按已入库交易所补齐日线、未摘牌合约分钟线与缺失结算参数到[应有最新交易日](#仓库与固定版本)，同时回补已存区间内的非空缺口；对已存分钟线的品种，按日线持仓量与摘牌规则识别换月后的新主力合约并从换月前一日自动纳入分钟线更新（日线更新已覆盖区间不重复建单；跨年先补日历）。未采过行情的交易所不自动补，同表已有排队或运行任务时跳过。每天按配置的北京时间自动执行，客户端也可随时触发。
- **合约表自动维护**：开启每日更新时，Warehouse 启动后补齐缺合约表的交易所，每天更新时再刷新全部交易所。理由：品种列表来自合约表，不应让用户先手动采集。成功时不进入最近活动，失败才通知，下次启动或每日更新时重试。
- **基本面自动跟随行情**：每日更新和“更新到最新”为每个交易所补齐其已有行情日期内缺失的仓单、会员持仓和库存周报，排在行情任务之后。理由：这些是行情的配套数据，不应单独采集；首次补历史可能持续数小时，不能挡住行情。同一任务的起始日取各交易所中最早的缺失日。周报逐开市日查询并沿用来源无数据规则，不预设节假日前后的发布日期。采集活动将部分空响应提示为“周报按报告日提供”，全部为空时提示“没有新周报”，都不计入日频无数据分区数；理由：非报告日没有周报是正常情况，但要看得出这次没有存下周报。

## Terminal 和 Lab 的连接

- 在“设置 → 关于”复制本机客户端证书指纹（Terminal 第一次启动时生成，与交易主机登记的是同一个），登记到 Warehouse 主机，再填写主机、端口和服务端证书指纹。连接是 TLS 1.3 双向固定指纹；登记的客户端都能读取数据和管理采集，因为它们属于同一个使用者，采集只追加新版本。
- Terminal 在 `terminal/data/warehouse.json` 保存地址和服务端指纹，私钥在 `terminal/data/tls/client.key`。修改地址不影响服务和其他客户端。
- 数据页直接读取 Warehouse 的摘要、覆盖、版本和采集任务（新的在前，按页读取，支持查看更早任务），定期刷新；也能看到其他客户端提交的任务。读取、采集、更新和取消都不自动重发。
- Lab 用同一份客户端证书读取固定版本，见 [Lab](../lab/README.md#固定数据版本)。

## 从协议开始接入

消息格式、命名规则和全部操作见[通信协议](../protocol.md)。

- 启动采集用 `start_acquisition`，只说要哪张表、哪些交易所或合约、哪段日期，记住自己生成的任务 ID；返回只表示已接纳，查询 `get_acquisition_task` 才能知道结果。回复丢失时先按 ID 查询，重复提交同一 ID 返回冲突。
- 读取数据先用 `get_dataset_version`（版本留空）取得当前版本，之后的分页和下载都带这个版本；下载完成后核对整个文件的 SHA-256。
