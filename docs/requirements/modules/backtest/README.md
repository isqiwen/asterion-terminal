## 已确认的模块划分

回测是数据、情报、分析、策略之后的第五个独立核心业务模块。当前保留两个子模块：**回测设计与实验管理、交易与账户模拟**。独立评估模块统一承接绩效、风险分析和验证结论。分类按使用者任务与结果责任划分，不等同于菜单、服务进程或插件拆分。订单与成交、交易成本、资金与持仓属于第二个子模块的内部能力。

| 子模块             | 核心任务                         | 输入                             | 唯一负责的结果                         |
| ------------------ | -------------------------------- | -------------------------------- | -------------------------------------- |
| 回测设计与实验管理 | 固定条件、安排验证、控制运行     | 策略包、数据、历史规则、验证问题 | 方案、批次、逐次运行与完整尝试记录     |
| 交易与账户模拟     | 按历史信息执行策略并模拟交易账户 | 固定方案与当时可见事件           | 订单、成交、持仓、资金、结算与风险事实 |

## 从方案到证据的操作闭环

选择固定策略与数据 → 设定区间、成交/账户/风险条件 → 安排验证与预算 → 检查并提交 → 观察运行 → 检查事件、成交与账本 → 交给[评估模块](../evaluation/README.md)评价绩效、风险与稳健性 → 保存结论或提出新实验。

创建或修改实验不自动运行；成功回测不自动形成合格候选、授予实盘权限或启动交易。需要改策略时返回[策略逻辑构建](../strategy/logic.md)或[组合与仓位管理](../strategy/portfolio.md)，选择结果通过[策略管理与交付](../strategy/delivery.md)固定。新策略内容不能继承旧内容的验证证据。

## 与其他模块的边界

| 相邻模块 | 对方负责                                       | 回测负责                                                     |
| -------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 数据     | 采集、清洗、质量、可得时间、固定快照和规则资料 | 核对模拟所需覆盖与精度，绑定实际输入，不在运行中偷换数据     |
| 分析     | 探索数据、构建变量、评价特征/因子              | 使用固定变量定义驱动历史模拟                                 |
| 评估     | 绩效、风险、稳健性及综合结论                   | 交付固定实验、逐次状态与模拟事实，接受显式补充实验草稿       |
| 策略     | 逻辑、模型、训练定义、参数与目标仓位政策       | 历史时钟、逐折实际训练/预测、模拟成交与实际模拟仓位          |
| 实盘交易 | 真实授权、订单、账户和运行控制                 | 独立模拟账户及证据，绝不向真实账户发送订单                   |
| 系统     | 通用任务、计算资源与记录机制                   | 实验业务条件、批次关系和结果语义，不另建通用调度系统         |

## 必须保持的约束

1. 固定输入包括策略内容、模型/训练定义、参数、数据快照、历史规则、模拟算法及必要风险。参数搜索生成独立配置，不回写策略包。
2. 历史发生时间与可得时间分开，模型和拟合只使用当时可得资料；收盘后形成的信号不提前成交。
3. 成交模型受数据精度限制，分钟线不提供真实队列或分钟内路径；未知条件显示限制或拒绝，不假装精确。
4. 账本只有一个事实来源。成本归因不能重复扣减；保证金释放不是收入，结算盈亏不得再次计入。
5. 所有回测都要求必要风险配置和可用能力；研究模拟不要求实盘授权。缺失费用不默认零，显式研究假设需完整标识。
6. 完整、失败、取消和部分结果分开。订单因风险拒绝不必然使实验失败；依赖或引擎失效不能伪装为完整运行。
7. 只比较有明确口径的结果。重复试验不能增加独立样本，已经参与选择的验证信息不能重新变为未使用资料。

## 本次详细设计范围与待评审边界

以期货、单一记账币种、空仓初始账户及无外部资金出入作为本次交付版的明确模拟范围；多品种和多策略共享资金按已定义策略组合模拟。实物交割、跨币种换算和任意历史持仓导入不在本次范围；不支持条件明确拒绝。订单、模型与容量按交付范围编制；真实市场规则须核验，研究及风险参数须显式配置，不能从案例推导生产默认值。

当前实际入口仍为“研究 → 回测”；两个子模块是当前目标业务组织。新工作台只提供字段、动作、状态与验收设计，实际界面图保留已有截图；没有完整回测结果实拍的部分不能宣称已经验证。

## 事件输入的历史可得性

使用情报事件时固定数据集合及实际历史/事后研究模式。实验时刻只消费该模式明确允许的内容，09:10才发布的结构化情报不能提前至09:00。来源公开时间、系统获取和实际处理时间均保留；今天使用模型重处理历史文章不构成当时系统可用证据，相关限制随结果交评估。

## 回测中的风险配置和模拟

回测自行提供风险参数配置与结果检查入口，不要求进入独立风控中心。实验固定模拟规则、参数及可用风险插件；缺配置或能力时拒绝运行。账户模拟按[共用交易约束](../../product.md#execution-risk-semantics)检查订单、资金、保证金、持仓与在途占用，记录阈值触发和实际模拟处置结果。规则定义可复用，实盘账户状态与可变额度不能被模拟任务共享或改变。

## 与配置、调度和通知的交接

回测拥有固定实验条件、风险配置、任务状态和模拟结果。定时批次必须限定范围和预算，每次触发仍检查数据与风险插件；已受理不等于实验完成，日志清理不删除实验产物。失败通知的已读不将实验改为成功。具体公共分工见[运行支撑边界](../../product.md#operational-support-boundaries)。

风险要求分别由策略预算、回测模拟账户、评估风险分析和实盘账户准入承担；没有独立风险业务模块。共用风险算法能力不拥有独立真实账户额度。

## 回测交付范围

以下是本次交付版采用的设计规格，源于用户授权完善文档；不冒称已经逐项获得用户确认或已经实现。具体部署资料按[交付与验收](../../delivery.md)核验。模块内通用“支持的方法/来源”以此有限集合及显式能力检查为准。

| 能力 | 必须交付的行为 | 限制与拒绝条件 |
| --- | --- | --- |
| 实验范围 | 1分钟及日线驱动，单币种人民币、空仓初始账户、显式初始资金；无外部出入金、不模拟实物交割；支持单真实合约及显式换月映射的多合约组合。 | 到期前停止开仓/按已声明计划退出；无可执行价格或有效换月资料时实验不完整，不按结算价假完成平仓。 |
| 时序与成交 | 策略只能在完整K线结束后决策，订单最早从下一根K线可观察边界生效；支持市价模拟、限价与撤单，日内有效和明确取消。相同时点按已固定事件顺序；无法识别的触达顺序采用保守假设并披露。 | 真实柜台没有市价能力时不映射为市价实盘。零成交量、涨跌停与价格限制影响成交；无订单簿数据不声称队列精确。 |
| 容量与成本 | 成交不超过用户配置的该K线成交量参与上限；不足形成部分成交，剩余继续或到期。支持按手/成交金额费率、开/平今/平昨差异、固定跳数滑点及可选成交量冲击插件。 | 费率、保证金、乘数、步长和舍入按合约与生效时间配置；无来源证据时必须显式标为研究假设，缺必需值拒绝运行。不得重复扣除已体现在成交价的滑点。 |
| 账户与风险 | 逐笔持仓、现金、手续费、保证金、结算及冻结流水可核对；必要风险插件与配置先检查。保证金不足拒绝新增；强制处置须采用事前明确政策并保留未成交结果。 | 假定所有强平都成功或将缺失结算价用零替代均禁止；期末未平仓按已声明估值口径报告，不伪造退出成交。 |
| 验证与批量 | 固定留出与滚动前推两种计划；参数笛卡尔有限网格，默认单任务执行、最多2项研究并行，默认批次上限100次且提交前预览总量。允许用户明确降低额度。 | 训练不读验证数据；训练、验证和失败全部留痕。相同确定性输入逐笔结果及Decimal账本精确一致；浮点分析按已声明绝对/相对容差核对，不允许容差掩盖订单差异。 |
