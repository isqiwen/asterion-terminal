**模块目标：** 明确账户、环境、策略和授权，管理真实运行、订单成交、账户政策与资金持仓，执行必要的准入及运行限制。

**职责边界：** 拥有真实账户事实、账户风险政策、统一准入与执行及运行限制；策略定义归策略，研究评价归评估，仿真或模拟不得混称实盘。

目标入口为**实盘 → 准备与运行 / 订单与成交 / 账户与核对**，具体视图见[界面设计总览](../../common/ui-designs.md#target-navigation)。一级和二级导航分别对应本模块与子模块。实际入口段落只记录实现证据。

## 已确认的模块划分

第七个核心业务模块为**实盘交易（Live Trading）**，界面可简称 Live / 实盘。下设**实盘准备与运行管理、订单执行与成交管理、账户管理与交易核对**。它承接策略与评估结果，将明确授权的意图作用于真实账户；并不意味着上游模块的结果可以自动进入实盘。

| 子模块             | 核心问题                                             | 主要结果                                                   |
| ------------------ | ---------------------------------------------------- | ---------------------------------------------------------- |
| 实盘准备与运行管理 | 在哪个账户、什么范围内运行，当前是否真正运行或停止？ | 账户环境、固定方案、授权与启停、预警限制及恢复、行情上下文 |
| 订单执行与成交管理 | 意图是否被接纳、成交了多少、剩余订单怎样处理？       | 逐笔准入、在途占用、委托成交及未知结果核对                 |
| 账户管理与交易核对 | 实际资金和持仓是什么，记录能否与来源核对？           | 账户政策及生效、资金持仓、费用结算与核对证据               |

原有行情、自选、图表与订阅要求归入实盘准备中的交易上下文，不因目录调整删除。行情采集与数据存储仍归数据；跨业务图表交互遵循通用规范。本次没有新增Visual业务模块，行情观察也不要求用户先取得交易权限。

## 实盘、仿真与本地模拟

| 环境                | 发生什么                                 | 不可混同的边界                                           |
| ------------------- | ---------------------------------------- | -------------------------------------------------------- |
| 实盘账户            | 指令发往真实交易账户，影响真实资金和持仓 | 要求明确授权、账户风险与统一执行路径                     |
| 仿真账户            | 指令发往明确标识的仿真柜台或测试账户     | 必须标仿真；它的授权、订单和业绩不能沿用或计入实盘       |
| 本地模拟 / 历史回测 | 在声明的模拟条件下生成模拟事实           | 无真实交易指令；必要风险不可缺，不以实盘授权作为运行前提 |

Live的业务主对象是真实账户。仿真准备可以复用账户和运行机制，但所有操作持续显示实际环境。账号名称、颜色或所在页面不足以证明环境，必须能核对连接目标与账户身份。切换环境不转移授权，不重定向既有订单，不把仿真结果当实盘业绩。

## 与其他模块的交接

| 对端                           | 对方负责                                         | Live负责                                                   |
| ------------------------------ | ------------------------------------------------ | ---------------------------------------------------------- |
| 数据                           | 行情来源、历史资料、质量与时间语义               | 展示行情时效，依据真实条件判断交易上下文是否可用           |
| 分析与策略                     | 特征、逻辑、模型、组合分配和固定策略包           | 使用固定定义创建实例；修改返回所属模块，不现场复制策略算法 |
| 回测                           | 历史模拟、执行条件、批次和模拟账本               | 准备需要验证的场景，引用其证据，不另算历史模拟结果         |
| 评估                           | 绩效、风险分析、稳健性、跨环境归因和报告         | 提供固定真实事实，审阅证据；评价通过不授予交易权限         |
| 本模块的账户、订单与运行子模块 | 分别管理账户政策、逐笔准入与占用、运行限制及处置 | 所有真实意图走统一检查与执行，账户限制独立于策略预算       |
| 系统                           | 连接机制、服务生命周期、任务和诊断               | 明确业务运行状态、授权和停止结果；窗口状态不代表交易状态   |

## 从准备到核对的闭环

确认环境和账户 → 读取固定策略与评估依据（手动交易核对完整意图） → 检查行情、资金、持仓、在途与风险 → 独立授权 → 明确启动或提交 → 观察订单与实际成交 → 核对账户 → 必要时独立暂停、撤单、平仓或停止 → 处理残余风险与结算差异。

只维护当前实例、账户和订单事实，不因用户切换页面改变归属。策略预算、实际资金、目标仓位、实际持仓和在途量分别表达。停止新意图不消灭之前发出的订单，连接恢复不构成重发授权。

## 界面与确认范围

实盘/仿真文字、账户身份和关键状态在有交易后果的页面持续可见。行情查看、账户查询、授权、启动、提交和成交是不同状态，不能压缩成一个绿色“已连接”。拟议布局沿用现有Terminal风格，已有实拍图保持原样；新增准备与运行工作台的完整字段和动作仍待实现验收。

三个子模块和实盘定位已确认；订单、运行、授权和容量按本章交付范围编制；具体机构与真实账户能力按GATE-TRADE取得证据。现有截图、文档案例与模拟通过均不能作为真实柜台验收完成的证明。

## 账户限制纳入现有业务操作

账户风险政策归账户管理与交易核对，逐笔准入与占用归订单执行与成交管理，预警/限制/恢复归实盘准备与运行管理。相关主题与案例在本模块唯一维护；不另设风险控制模块或独立风控中心。

账户配置、订单详情与运行详情相互跳转。风险限制覆盖手动和策略入口，策略预算不能替代账户政策，报告也不直接产生处置权限。共用定义见[共用交易约束](../../product.md#execution-risk-semantics)；配置、检查及运行限制分别有清晰状态与验收，不因重编需求而减少必要检查。

## 实盘交付范围

以下是本次交付版采用的设计规格，源于用户授权完善文档；不冒称已经逐项获得用户确认或已经实现。具体部署资料按[交付与验收](../../delivery.md)核验。模块内通用“支持的方法/来源”以此有限集合及显式能力检查为准。

| 能力 | 必须交付的行为 | 限制与拒绝条件 |
| --- | --- | --- |
| 市场观察 | 行情总览、自选、合约图表及来源状态；按来源实际能力显示盘口档位、成交及时间，不要求先创建交易账户。 | 行情权限与交易权限独立；休市/断流/未知时间不能同为正常绿色；交易只允许真实月份合约。 |
| 模式及账户 | CTP兼容期货柜台的外部仿真及真实账户、本地实时模拟；各自独立身份与账本，单币种人民币。账户来源能力和实际规则在准入表逐项核验。 | 支持不是对所有柜台的泛化承诺；不支持字段/状态映射拒绝启用该能力，真实交易验证与仿真证据分别保存。 |
| 授权及连续运行 | 明确账户、环境、策略包、政策及执行位置后分别授予账户发送和实例运行权限；持续有效直至撤销或适用条件变化。正常日切重新核对规则、余额及在途，授权仍有效不等于立即可发送。 | 连接断开阻断发送；策略/政策实质变更、执行归属变化或未知订单未核清时要求重新审查；恢复从当前目标重新判断，不补发旧命令。 |
| 订单与核对 | 当前真实发送支持柜台确认可用的限价、开仓/平今/平昨、当日有效和撤单；用户提交前确认账户、合约、方向、价格及手数。保留意图、外部订单/成交身份、部分成交及撤单失败。 | 不自动降级订单类型，不以撤单申请当终态；同一外部成交去重，修正保留依据与调整记录；无法关联的结果不得释放风险占用。 |
| 风险与执行归属 | 账户必配单笔手数、合约/账户潜在持仓或名义敞口、资金/保证金占用、价格偏离及日内损失/回撤基准、输入有效期和恢复条件；数值不提供可交易默认。 | 缺项、插件不可用、状态陈旧或必要写入失败拒绝新增发送；安全查询与经独立条件校验的撤单保留。一个账户一个执行归属，远程失联不自动接管。 |
| 模拟与准备验收 | 本地模拟使用真实行情、显式模拟初始资金及固定撮合/费用/风险；进入真实运行前要求完整连续交易日、跨日持仓核对、部分成交/撤单/断线和停止恢复的仿真证据。 | 至少覆盖一次完整交易日及下一个交易日开市核对；这只是行为验收，不代表策略盈利或风险适当。真实登录和委托由用户另外明确授权。 |
