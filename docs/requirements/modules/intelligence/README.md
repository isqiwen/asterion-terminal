产品需求规格 · 2026-10-20。本页定义目标业务、字段、操作、边界和可观察验收条件；按功能与界面编号关联跨模块流程。

**模块目标：** 把来源材料转为带证据、时间语义和核验状态的结构化情报，供研究、事件跟踪与策略输入使用。

**职责边界：** 数据负责采集、基础解析及统一存储访问；情报负责语义加工、核验、事件组织与发布；分析检验预测价值，策略定义决策，情报不下单。

目标入口为**情报 → 信息提取 / 情报核验 / 事件服务**，具体视图见[界面设计总览](../../common/ui-designs.md#target-navigation)。一级和二级导航分别对应本模块与子模块。各界面在本模块内承载相应任务，跨模块入口保留调用方上下文。

## 已确认的定位与子模块

情报（Intelligence）是第二个核心业务模块，位于数据之后、分析之前。它处理非结构化及半结构化材料的业务含义，产出可追溯、可检索、可分析的结构化情报。目录按“数据 → 情报 → 分析 → 策略 → 回测 → 评估 → 实盘交易”阅读；顺序体现理解业务的路径，不要求每条数据串行经过全部模块。

三个子模块已确认：信息提取、情报核验、事件服务。LLM从需求阶段纳入，但不另立AI模块；无需语义加工的供应商标准库存、产量或经济指标可直接从数据进入分析。用户已确认业务目标与职责；本次格式、核验与交互规格在交付范围中明确，模型与费用为显式运行配置，服务商须取得外部准入证据。

## 数据与情报的责任矩阵

| 对象或工作                                       | 唯一业务责任方     | 对方如何使用                                                       |
| ------------------------------------------------ | ------------------ | ------------------------------------------------------------------ |
| 来源授权、获取任务、原件、发布时间与获取记录     | 数据接入与采集     | 情报提出材料需求并引用已取得原件，不建立第二套采集与原件库         |
| 文件解码、正文/OCR/表格读取、完整性与可读范围    | 数据加工与质量     | 情报在可读范围上解释实体、数字含义和事件，不把文本读出当作语义核验 |
| 通用实体标识、单位、合约与日历资料               | 数据管理与服务     | 情报负责本次匹配判断和证据；资料缺失回数据补充，不另建合约字典     |
| 候选陈述、语义提取任务、模型处理记录             | 情报信息提取       | 数据统一保存及提供访问，不改变任务的业务完成含义                   |
| 字段解释、实体映射判断、来源冲突、核验与发布决定 | 情报核验           | 数据只按有权业务流程提供保存与访问，不能自行放行候选               |
| 事件身份、演变关系、时点语义、订阅条件           | 情报事件组织与服务 | 数据提供交付和固定集合；分析或策略按用途使用                       |
| 因子定义、预测价值、统计有效性                   | 分析               | 情报提供证据与时间明确的输入，不给未经检验的交易结论               |
| 交易决策与目标仓位                               | 策略               | 已发布情报只是受约束输入，不携带账户执行权限                       |
| 实际执行、账户授权及风险阻断                     | 实盘               | 情报更新或撤回不自动下单、撤单或平仓                               |

统一存储与访问不等于统一业务所有权。原件保持固定内容，目录可展示不同模块的状态但不能成为第二个状态拥有者。数据发布研究快照的机制也不能替代情报的证据核验：正式消费同时满足情报发布条件和相应的数据用途条件。

## 交接内容与失败语义

| 交接                  | 必要内容                                                              | 完成判断与失败处理                                                           |
| --------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 数据 → 情报           | 材料及内容标识、来源、发布时间/获取时间、访问限制、解析记录、可读范围 | 材料取得后可处理；缺页标明部分，不改称采集失败；无可读内容则阻断提取         |
| 提取 → 核验           | 候选字段、陈述类型、原文定位、模型/方法记录、缺失及处理限制           | 结构通过只允许进入核验；证据不足保留待核验                                   |
| 核验 → 统一保存与访问 | 已确认内容、核验依据、发布决定、关联事件、可用时间                    | 保存确认成功才显示发布可用；失败保留已核验待发布，重复请求不重复建立记录     |
| 情报 → 分析/策略      | 已发布内容、变化身份、证据、时点、质量限制及固定集合                  | 消费身份和缺口可核对；缺失、延迟不能默认为零事件；执行仍走独立策略及风控路径 |

下载成功、解析成功、提取成功、核验通过、发布成功、交付成功和交易执行成功分别表达。公共任务中心提供进度观察和跳转，不重复维护各业务状态。

## 完整操作示例

1. 在数据来源登记获授权公告源，取得某工厂检修公告和附件；查看来源、内容标识、时间及可读页。
2. 在情报材料列表选择原件与提取规范，预览模型发送范围及预算后执行。
3. 对照原文核对“计划、下月、两周、约三万吨”，不补出具体开工日或确定价格方向。
4. 核对工厂实体与数量单位；同名主体或冲突报道进入复核。满足明确发布条件后保存并发布。
5. 在事件库查看时间线及证据，按实际可得时点固定研究输入；在分析中构建变量并检验，不直接交易。
6. 收到取消或数量更正公告时关联后续变化，订阅给出更正提醒，既有研究保持原引用。

配套完整旅程见[材料到发布和研究](../../workflows/README.md#jrn-031)、[更正与时点查询](../../workflows/README.md#jrn-032)、[模型失败、重处理与质量检查](../../workflows/README.md#jrn-033)。各主题配具体结果案例图，用于说明输入、处理和预期结果。

## LLM能力与边界

LLM用于上下文理解、字段提取、实体关联建议、矛盾识别、引用摘要及自然语言查询。确定性字段类型检查、量纲换算、时间过滤、权限和发布状态必须有明确规则。模型自报置信度仅为辅助信息，不能独立决定发布。未配置发布规则时不默认放行。

原文中的指令作为待分析内容，不改变系统规则或调用交易、凭据、任意文件/网络工具。任务仅发送必要且获允许的材料，显示模型与提供方；无合法外发条件时阻断，不静默换服务。模型凭据本地输入并保护，不能进入普通配置、聊天、报告或日志。

记录实际模型身份、提示与规范固定内容、输入标识、参数、处理时间、输出和已知消耗。处理可追溯不保证生成结果逐字重现。历史重处理保留实际处理时间及模型知识污染限制，不宣称提示词能完全消除事后知识。

## 范围与界面说明

情报范围覆盖获授权公告、资讯与研报中的事件和数值情报；不默认引入全网爬取、社交舆情、自动投资建议或任意代理工具执行。来源能力、支持格式、模型身份、处理预算和性能条件须逐项明确。算法与模型提供方通过插件实现，核心维护任务、契约和证据机制；本需求不直接规定新进程或数据库。

六项界面分别承载材料提取、方案评测、标准化、证据发布、事件时点查询和订阅。原文证据、候选字段、复核结论、事件时间线和交付状态保持相同对象上下文；布局遵守统一的Terminal表格、详情及状态规范。

## 与配置、调度和通知的交接

情报拥有模型处理方案、材料使用范围、预算、证据和订阅条件。周期处理可交系统调度触发，但外发和费用检查仍在情报执行；模型处理记录不是普通诊断日志。情报决定事件更新及冲突状态，通知已读或静音不更改证据或发布状态。具体公共分工见[运行支撑边界](../../product.md#operational-support-boundaries)。

## 情报交付范围

以下定义产品必须支持的能力集合及明确边界。具体来源、材料与运行配置按[交付与验收](../../delivery.md)准备；模块内“支持的方法/来源”以本表和明确的能力检查为准。

| 能力 | 必须交付的行为 | 限制与拒绝条件 |
| --- | --- | --- |
| 材料及结构 | 支持获授权中文/英文HTML、纯文本、文本型PDF和来源结构化表格；事件类型包括供给/产能变化、库存变化、政策与交易规则变化。结构含主体、品种/产品、地区、事件类型、事实/观点、时间、数值与单位、证据位置。 | 扫描件、音视频和无法抽取的图表明确不支持，不借LLM补原文。事实字段可缺失，但须给缺失原因和证据范围。 |
| 方法与LLM | 支持确定性解析和可配置LLM提取；每次处理固定材料、结构、模型标识、参数、提示及实际处理时间。模型无直接交易、文件写入或工具执行权。 | 模型来源及允许外发材料由用户显式配置；默认不外发。调用次数、每次输入量和总费用上限必填，费用不可估时必须先人工批准范围。 |
| 核验与发布 | 实体按基础资料精确匹配或人工映射；单位保留原单位及转换依据；冲突、缺核心字段、证据不支持均不可发布。默认人工发布。 | 自动发布仅限配置了完整门槛的确定性来源规则；LLM自由文本提取必须人工核验。不把置信分数作为事实概率。 |
| 评测 | 维护固定人工标注集合，按事件类型/来源分层，并按底层事件族隔离开发与独立评测；同一事件的原文、转载和修订不得跨两集合；统计字段准确、完整、证据支持、拒答和无依据输出，报告分母与失败样本；不同模型/提示在同一集合比较。 | 发布样本的必需字段、证据支持和实体时间一致性必须全部通过；模型平均成绩不能覆盖单条失败；关键字段全对、样本充分性、标注争议与评测集是否被调优使用均可检查。标注集合由真实获授权材料建立，不虚构已测准确率。 |
| 服务 | 结构化字段过滤、按事件时间及当时可得时间查询、事件更正/撤回、订阅和应用内提醒；自然语言仅生成可审阅查询条件与带证据回答。 | 严格历史模式只使用证据支持的当时版本；现在重处理的旧材料作为事后研究标记，不能进入严格历史池；前向观察保留实际取得、处理和人工核验延迟。订阅断档先显示缺口，再显式补取。 |
