## 安装、升级、启动与卸载的责任

安装维护由独立的 Asterion Installer 图形程序负责；桌面安装到当前用户，不要求管理员权限。
远程 Linux 主机的首次系统准备需要该主机管理员授权，权限边界见下文远程节点维护方案。
比较过系统安装器脚本与独立维护窗口：前者适合单次文件分发，但难以统一展示业务阻塞、
用户确认和卸载保留范围；本项目采用现有 Electron 窗口与原生维护执行器，复用节点服务机制。
安装包携带完整 Terminal，不在安装时下载业务程序或依赖，不增加独立业务客户端。

### 默认单机完整运行

默认安装交付可在本机独立运行的完整系统：Terminal、Manager、Agent、行情、交易、数据、
研究服务及所需插件；回测、因子由 Research 内部执行，下载由 Data 内部执行，不新增独立 Task 进程。没有远程机器或远程 Linux 部署
资源时，本机功能仍然可用；远程节点仅用于用户明确选择的部署位置和计算资源扩展。
“完整”指业务能力完整，不代表自带市场数据、账户、行情授权或交易权限。

| 对象 | 默认行为 |
| --- | --- |
| Manager、Agent | 安装与升级后立即启动并确认就绪，分别由 OS 监督 |
| 本机行情、Data、Research | 首次工作台准备默认本机行情；Data/Research由业务流程经Manager请求Agent按需创建或启动，恢复已声明运行的部署。数据来源按任务发现并固定版本，不永久配对，业务直接使用本机Unix Socket。已明确停止的默认行情部署保留停止意图，不妨碍独立Data/Research工作 |
| 交易服务 | 按已配置账户隔离；恢复已有记录可以启动服务进程，但不自动登录柜台、授权交易或重发订单；新账户按交易流程显式创建 |
| 任务执行 | 所属服务按自身配置选择已接受任务，在内部有界线程池或异步I/O中执行；Agent不参与任务调度 |
| 远程节点 | 初始为空；用户在 Terminal 添加节点、部署服务并明确选择使用位置，不自动迁走本机工作 |

默认本机服务程序从安装包本机 `native/` 资源选择，不从远程 Linux 包解析。
安装包仍携带以后部署远程节点所需的资源，但本机运行不检查或依赖远程包。
节点登记、服务部署及运行意愿由原拥有者持久化；重启恢复已确认的状态，不要求每次重新部署。
验收应在远程资源目录不存在、没有远程登记的隔离环境下覆盖本机服务启动、Data/Research独立部署与任务级来源、
服务内任务按需运行和管理进程重启后的部署恢复；行情和交易链路使用测试专用 SDK 验证，
不把模拟柜台验收宣称为真实账户实盘验证。

| 操作 | 责任与行为 |
| --- | --- |
| 安装 | 将程序部署到用户应用目录；向节点 `config/` 复制缺少的默认配置，保留已有文件；创建缺少的本机身份；分别注册 Agent 和 Manager 用户服务及应用启动入口。程序准备和安装登记完成后释放进程锁，立即通过系统服务管理器启动本机 Agent 与 Manager，无需等待打开 Terminal 或下次登录操作系统。 |
| 升级 | 用户先结束任务、处理交易并停止本机业务服务，关闭 Terminal；安装器通过已安装的执行器检查其自身 Manager，停止空闲 Agent 与 Manager；替换完整程序，Agent 离线准备当前本机业务服务的程序引用，再注册服务。保留配置和全部业务资料，不迁移历史领域格式。 |
| 修复 | 使用与已登记版本相同的完整安装包，在同样的停机条件下重新部署程序并恢复服务注册与应用入口。安装登记仍在但程序文件缺失时也可修复。保留现有配置与身份，不回填或重置策略、不修复业务数据。 |
| 启动 | Terminal 连接或启动已注册 Manager；Manager 管理本机 Agent 连接，OS 独立监督两者。启动不安装、不补写配置、不执行升级。 |
| 卸载 | 在同样的停机条件下移除应用文件、应用启动入口及两个用户服务的注册。“保留配置与业务数据”默认勾选；用户取消勾选并确认后，删除本机节点资料与本机连接登记。卸载不代表撤单或平仓。 |

“首次”以当前用户的安装登记和目标目录为准，不以某个安装包第一次运行为准。
首次安装立即启动与后续操作系统账户登录自启共用同一组用户服务；关闭安装器不停止它们。
首次安装与升级在系统启动请求后，通过 Manager 快照等待本机 Agent 在线且状态为 READY，
最多等待 30 秒。Manager 尚未建立本机连接、Agent 初始化中均不能报告完成；远程节点的
在线状态不能代替本机就绪。Agent 初始化失败立即报告具体原因，超时显示最后观察原因及
节点日志目录；已取得进程 PID 时同时显示各进程日志路径。仅轮询只读状态，不重放管理命令。
启动请求或就绪确认失败必须报告，不能显示安装流程完成；已经发布的应用与安装登记保留，
后续可由 Terminal 再请求启动或使用安装器修复。此时不回滚或重新标记为未完成的程序发布。
升级在本机发布完成后也启动 Agent 与 Manager，再完成远程节点确认；修复保留停机维护流程。
两者均不在注册服务时提前启动。
采用安装后的维护模式交互：未安装仅显示安装；同版本进入维护界面，提供修复与卸载；
新版本提供升级与卸载；旧安装包提示禁止降级，修复置灰，仍允许卸载。没有可选组件，
不展示“修改组件”。安装成功后进入维护界面，卸载成功后回到安装界面，每次执行均重新确认。
版本采用 CMake 的三段数字发行版本，按数字比较（例如 0.10.0 高于 0.2.0），不按字符串排序。
判定归原生执行器，操作提交后持有安装锁重新判断，界面消费判定结果，不复制版本比较算法。
这属于发行操作选择，不增加源树哈希、内容扫描、协议兼容版本门槛或自动修复。
初始状态尚未读出、存在目录冲突或进程未停止时禁止操作。
缺少安装包时禁止安装、升级和修复，但仍可卸载；已安装且无未完成操作时可打开 Terminal。
安装登记在节点目录的 `installation.json`，属于安装器状态，不属于只读策略配置。
中断或失败保留未完成操作及其目标版本；界面显示具体原因及日志入口，仅提供继续该操作，
重新部署必须使用同目标版本安装包，不能将已发布文件的升级误判为修复，也不能换包继续。
登记版本在未完成操作时表示操作目标，不冒充实际已发布版本。由用户修正后明确继续，
普通启动拒绝未完成安装。没有自动回滚、旧版本并存、降级或静默迁移。

资料保留选项仅用于卸载；安装、升级、修复始终保留资料。取消保留后，界面列出节点目录和
连接登记目录，明确本机配置、节点身份与连接密钥、账户设置、任务、行情数据、交易记录将永久
删除；远程机器资料、系统钥匙串凭据与目录外导出文件不在删除范围内。改变保留选项会清除
此前的执行确认，用户须按新的范围重新确认。开始卸载后登记该选择，中断后继续使用同一选择，
不允许将已部分删除误报为保留成功。删除失败保留未完成记录及具体错误，已删除内容不会恢复。
诊断日志与正在持有的进程锁文件保留，以便定位失败并维持互斥；卸载完成后移除安装登记。

应用位置固定为 Linux `~/.local/opt/asterion-terminal`、macOS
`~/Applications/Asterion Terminal.app`；节点位置继续采用该平台的用户数据目录。
Linux 使用 systemd 用户服务，macOS 使用 LaunchAgents。维护执行器日志归入节点公共
`logs/`，以 installer 进程身份命名；离线准备仍是 Agent 的运行模式，写 Agent 日志。
界面展示已安装版本、包版本、应用路径、数据路径、实际操作进度和失败原因，支持中英文。

图形安装器统一提供本机与远程维护，远程执行复用 Manager 的 SSH 能力，流程如下。
代码接入与隔离测试不代表真实远程 SSH／systemd 或发行包验收完成。

验收应覆盖安装→修复／升级→卸载的数据保留、降级拒绝、运行进程阻止维护、失败后显式继续、普通启动不更新，
以及两平台的真实用户服务注册与发行包；模拟文件测试不能代替系统服务或签名发行验收。

## 远程节点安装、升级与卸载方案

对象仅为已授权的 Linux x86_64 节点。每个平台仍交付一个
图形安装包，包内携带远程 Agent、业务服务、插件和必要维护资源。安装器展示本机与远程
节点的实际状态、操作范围、资料保留选择和逐节点结果；远程维护由 Manager 执行。

比较两种方案：安装器直接建立自己的 SSH／Agent 管理关系，会重复节点登记和生命周期
所有权；安装器复用 Manager 管理远程节点，可以沿用已有身份、连接登记及 SSH 能力。
采用后者。安装器不成为第二个节点管理器，也不要求在服务器部署另一个图形界面。

### 职责与维护边界

Manager 和 Agent 的稳定性目标是保持职责精简、减少随业务变化而修改的需要，不承诺永远
不更新，也不因此移除独立安装维护入口。首次部署时它们尚不存在，自身停机替换及损坏
程序修复仍需要独立执行器与操作系统服务管理器。安装器可保持精简，但不能成为第二套
管理进程；其执行器只通过协议调用 Manager，离线准备通过独立 Agent 子进程执行，
不得将 Manager 或 Agent 的进程实现链接进安装器。

| 组件 | 责任 |
| --- | --- |
| Installer | 展示维护清单与影响，取得确认，调用本机已安装维护执行器，最后完成本机应用替换。 |
| 已安装维护执行器 | 使用自身发行的本机协议联系 Manager，衔接远程维护与本机停机；不另建远程登记。 |
| Node Manager | 唯一远程维护协调者；读取既有节点登记，准备包、检查维护条件、通过 SSH 控制远程主机维护，记录逐节点进度。 |
| Node Agent | 检查本机业务进程并阻止维护期间的新启动；负责业务服务部署与离线程序引用准备。业务停止条件仍由对应服务确认。 |
| 远程主机维护工具与 systemd | 在授权范围内停止、替换、注册和移除指定节点 Agent；Agent 不自行覆盖运行中的可执行文件。 |

延续现有远程权限模型：管理员首次准备专用 `asterion` 用户、SSH 公钥和受限的
`asterion_host` 工具，节点部署到 `/var/lib/asterion/nodes/<node-id>/`，由系统级 systemd
服务以该专用用户运行。桌面“当前用户安装”不等于远程主机无需管理员准备。Terminal 节点管理应展示
可审查的初始化步骤与结果；不保存管理员密码、不赋予 Manager 任意 root 命令权限。
受限工具的权限或实现需要改变时，由管理员显式更新，不能允许普通节点用户上传任意程序
后要求以 root 执行。普通程序升级使用已授权的受限动作，不重复初始化主机。

### 安装

1. 默认安装仅部署本机，不创建远程节点。用户以后在 Terminal 节点管理页添加远程机器，
   由 Manager 完成登记和部署；安装器只维护既有登记，不提供新增节点或部署业务服务入口。
2. Manager 核对 SSH 主机身份、平台、主机准备结果和指定节点目录归属，建立节点身份并
   上传随安装包提供的资源。不得接管无登记的现有目录或覆盖其他节点。
3. 首次复制缺少的默认配置，部署 Agent，注册并启动独立 systemd 服务；通过 mTLS 确认
   实际 Agent 身份与运行状态后才报告安装完成。
4. 用户选择的业务服务通过 Agent 部署；安装成功不自动授权交易或提交任务。无需远程资源
   的用户可以只安装本机。

### 节点与服务变更的持久化

用户在 Terminal 中添加节点、部署服务或修改运行意愿后，管理操作必须由拥有者持久化，
后续升级、卸载从这些登记读取实际范围，不依赖窗口内存或用户再次输入节点清单。

| 内容 | 持久化位置与责任 |
| --- | --- |
| 运行策略 | `<node>/config/`，首次复制仓库默认文件；启动只读，部署管理不改写策略 |
| 远程节点及非秘密 SSH 连接信息 | Manager 的登记目录：安装版 `~/.asterion/nodes/<id>/enrollment.json`、`ssh.json`；开发版 `<node>/enrollments/<id>/` |
| 服务实例、程序、插件和运行意愿 | 各 Agent 的 `<node>/services/<实例>/service.json`；远程 `<node>` 为 `/var/lib/asterion/nodes/<id>/state` |
| 未完成维护 | Manager 登记目录的 `.maintenance.json` 和目标 Agent 自己的维护状态；本机发布另存 `installation.json` |

这些是管理操作拥有的持久状态，不是第二套手工配置，也不复制到安装器自建清单。
升级保留上述登记与业务资料；卸载按明确范围和保留选择处理。连接密钥继续使用受保护的
身份存储，粘贴 SSH 私钥只存在本次维护会话，不写入普通配置或日志。

### 整体升级

采用明确停机升级，首期不做滚动升级或任意版本混用。一次整体升级覆盖本机及该 Manager
登记的全部远程节点；先展示完整清单，不以“仅本机成功”冒充整体完成。

1. 用户打开新安装包。通过已安装维护执行器，由旧 Manager 核对所有节点的连接、SSH
   维护权限及目标资源，预先上传待发布资源。任何节点离线或条件不满足，均在替换前阻止
   整体升级；不自动跳过、删除登记或强制停止未知业务。
2. 用户处理交易、结束任务并停止相关业务服务。旧 Manager 与旧 Agent 确认安全停机，
   持久记录维护状态并禁止新业务启动；窗口退出、管理连接中断或机器重启不能解除该状态。
   不用资源预算或估算的空闲状态替代实际服务状态。
3. 旧 Manager 通过 SSH 调用受限主机工具，停止远程 Agent，替换程序。新 Agent 以离线
   准备模式更新既有业务服务的程序引用，保留配置、身份和业务数据。发布完成的远程 Agent
   保持停止，系统服务不能在重启后提前启动业务。
4. 全部远程节点准备完成后，停止本机空闲 Agent 和旧 Manager，替换本机程序。安装器
   通过已安装执行器完成旧协议交接，不让新安装器直接解释旧 Agent 的业务协议。
5. 本机程序准备、服务注册和安装登记完成后，释放进程锁，通过系统服务管理器启动本机新
   Agent 与新 Manager。随后由新 Manager 通过 SSH 启动远程新 Agent，完成同发行管理连接及服务程序检查。
   全部节点确认后结束维护。业务服务由用户显式启动，交易与任务按原有业务规则恢复，
   不自动重发交易指令或重新提交任务。

跨发行只保留安装维护所必需的小范围调用约定（动作、目标资源位置、结果），不承诺所有
业务协议永久向后兼容。已安装执行器联系同发行 Manager；Agent 停止后的替换走 SSH 与
OS 服务边界，新 Manager 只在远程程序更新后连接 Agent。项目尚未发布，当前应一起完成
这套契约；首发前明确实际支持的升级范围，不增加历史协议分支、旧数据读取器或迁移入口。

Manager 在既有登记状态下保存本次目标与逐节点进度；远程节点保存自己的维护状态和发布
结果。本机安装登记仍只负责本机文件发布，不能成为第二份节点注册表。复用现有制品选择
与完整性边界，不新增源树扫描或装饰性摘要。

升级不是跨机器原子事务。中途断网、断电或进程退出时，明确显示哪些节点未替换、已准备
或待确认；保持维护状态，保留 SSH 管理资料。用户排除原因后用同目标安装包显式继续，
从已有执行结果继续，不自动回滚、恢复业务或盲目重试未知结果。本机替换失败按本机未完成
安装继续；新 Manager 接管既有维护记录后完成远程启动与确认。SSH 不可达或程序损坏到
无法取得安全停机证据时，阻止自动流程，给出主机侧人工修复步骤，不以强杀代替确认。

### 卸载

安装器明确提供“仅卸载本机”“卸载所选远程节点”“卸载本机及全部远程节点”三种范围。
远程卸载先完成业务停机确认，再由 Manager 经 SSH 停止并注销对应 Agent 系统服务、移除
该节点程序。Agent 停止不能直接视为任务已结束、订单已撤销或账户已平仓。

每个被卸载节点的“保留配置与业务数据”默认勾选；取消时展示该机器与准确目录并另行确认。
保留资料时保留身份与重装所需登记，但显示为已卸载，不能显示在线；选择删除时仅删除该
节点拥有的资料。不得删除其他节点、共享的专用账户、主机 SSH 配置或受限维护工具。
系统钥匙串与目录外资料不在自动删除范围内。

联合卸载先处理远程，远程结果确认后再卸载本机。离线节点保持未完成，本机 Manager、
必要连接密钥与维护记录不能先删除。仅卸载本机允许远程继续运行，但必须明确展示这一
影响并保留远程管理所需的连接登记与身份；若要求一并清除这些资料，必须先完成对应远程
节点卸载。不能无提示地留下仍运行但失去本机管理凭据的节点。

### 主机工具与运行状态

远程节点通过受限主机工具 `asterion_host` 提供检查、能力查询、安装、停机、启动和注销动作；
程序发布以非特权节点用户执行。Manager 在既有登记目录的 `.maintenance.json` 保存整体
进度，节点 `state/maintenance.json` 保存 Agent 的启动冻结状态，节点根目录的
`maintenance-operation.json` 保存本机发布结果。它们都是运行状态，不属于只读配置。
安装器提供节点清单、逐节点进度、安装与卸载确认、本机和远程联合卸载、SSH 信息维护及
失败详情。升级先准备全部远程节点，完成本机程序发布后再确认远程启动。同版本修复只修复本机，不因远程节点离线而阻止修复。
SSH 配置只保存连接元数据；粘贴的私钥仅在本次安装器会话内保留，退出后再次提供。
持有已有公钥授权的主机 SSH 管理密钥独立于所卸载节点的 mTLS 身份，保留供再次连接主机；
全部远程卸载后，清除本机资料才会删除其本机 SSH 管理资料。

验收至少覆盖首次远程安装、整体升级、指定节点卸载及两种资料选择、离线节点阻止替换、
中途失败显式继续、机器重启不提前恢复业务、Agent 替换不依赖新旧协议混用、联合卸载
失败不先删除本机管理资料。除低层状态与界面测试外，必须使用隔离 Linux 主机验证真实
SSH、受限权限和 systemd；未完成该验收不能标记远程维护已交付。

## 配置对象与生效责任

| 配置类别                  | 编辑与确认位置                                               | 系统入口作用                                 |
| ------------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| 语言、显示密度、涨跌配色  | 偏好设置，即时保存                                       | 展示实际偏好，不增加统一保存步骤             |
| 节点、连接、插件          | 系统管理对应对象                                             | 说明检查、采用状态和重连/重启影响            |
| 数据源及采集范围          | 数据                                                         | 跳转并查询真实状态，不复制独立可编辑定义     |
| 模型提供方/凭据与情报方案 | 系统管理提供连接和凭据机制，情报决定模型方案、发送内容和预算 | 凭据本地处理；业务使用限制由情报核验         |
| 策略参数与组合约束        | 策略                                                         | 引用固定内容，变更形成新的明确条件           |
| 回测条件与模拟账户政策    | 回测                                                         | 固定实验条件，运行仍检查风险能力             |
| 真实账户限额与授权        | 实盘                                                         | 编辑及生效由账户负责，保存设置不等于授权交易 |

系统只统一发现和查询，不为方便展示复制另一套可独立生效的业务配置。对象需记录所属模块、实际内容身份、有效状态和读取时间。保存、检查、生效、运行采用分别解释；未取得远程确认时保持待核实，不自动回滚、重启或放宽规则。

影响范围在操作前可见：已运行任务、固定研究快照和账户授权不能被新草稿静默改写。凭据保存遵守既有允许类别与本机安全存储规则，普通配置及导出中只含允许的引用。

## REQ-SYS-SET-01 完成安装、首次准备并理解可用范围

**领域：** 系统管理 / 安装与配置　 **建议优先级：** P1核心必要　 **需求状态：** 开发前设计规格（具体决定与运行配置见本条DEC）

个人使用者应能判断自己的电脑是否受支持，并完成首次使用所需的准备。准备结果须说明哪些工作已具备条件、哪些仍缺少资料或授权，避免把安装成功误认为已经可以研究或交易。

**使用者与场景：** 首次安装、换电脑或重新配置工作环境的个人期货使用者。

**触发条件：** 使用者首次打开软件，或主动检查使用条件。

### 前置条件

- 设备属于 macOS Apple Silicon 或 Linux x86_64 桌面范围。
- 使用者有权选择本地资料保存位置，并能取得所需数据或账户的合法使用权限。

| ------------ | -------------------------------- | ------------------------------------------ |
| 工作资料位置 | 研究资料和业务记录的本地保存位置 | 须具备读写条件；不得自动覆盖已有资料。     |
| 使用意图     | 本地研究、本地交易或使用远程资源 | 允许稍后补充；选择意图不等于获得交易授权。 |

### 正常操作与反馈

1. 使用者确认设备范围并选择资料位置。
2. 系统检查保存条件和已选择用途需要的准备项。
3. 使用者按说明补齐数据访问或账户条件，也可暂时跳过。
4. 系统列出可用任务、缺失条件及其影响。
5. 使用者进入已具备条件的工作，之后可重新检查。

### 业务规则

- 本地独立工作不以配置远程 Linux 资源为前提。
- 研究与实盘分别判断准备状态，不得用单一成功标志掩盖交易缺项。
- 缺少行情来源时明确不可取得行情，不使用示例行情填补。
- 不支持的设备须说明范围；不得宣称可以正常工作。
- 首次准备不自动提交订单，也不默认开启交易权限。

### 输出与状态影响

- 可用范围与缺失条件清单。
- 使用者明确选择的资料位置和使用意图。

### 异常与继续方式

| 发生什么         | 应怎样表现                                         | 使用者如何继续               |
| ---------------- | -------------------------------------------------- | ---------------------------- |
| 资料位置不能写入 | 阻止创建资料并说明原因。                           | 选择可写位置后重新检查。     |
| 数据授权尚未提供 | 标明相关数据任务不可用，保留其他已满足条件的工作。 | 补齐授权后重新检查对应项目。 |

**虚构案例条件：** 虚构案例：支持的 Mac 已有资料目录和数据权限，尚未配置交易账户，也没有远程资源。

1. 选择本地研究并完成条件检查。
2. 查看研究、交易和远程资源的独立结果。

**预期结果：**

- 本地研究可开始；交易缺少账户及授权；远程资源显示未配置且不阻止本地研究。

### 详细功能

<a id="fr-sys-set-01-01"></a>

### FR-SYS-SET-01-01 核对设备支持范围与首次可用条件

**目标与结果：** 使用者在投入配置前确认设备受支持，并看懂安装成功与工作可用的区别。准备检查分别说明本机条件、研究条件和交易条件，不把缺少远程资源当作本地阻断。

**触发：** 首次打开进入准备页，或从工作总览选择重新检查。

**输入与约束：** 读取设备平台和可用存储；用户选择使用意图。支持 macOS Apple Silicon、Linux x86_64；不预选实盘授权。

**目标操作与反馈：**

1. 查看设备与平台检查结果及其依据。
2. 选择研究与交易用途，查看各自需要补齐的条件。
3. 点击重新检查，仅更新检查结果并显示检查时间。

**异常与边界：**

- 不支持的平台显示具体范围，不能呈现全部准备完成。
- 某项检查失败保留其他结果；重试不自动登录或发出交易。

**验收条件：**

- **FR-SYS-SET-01-01-AC01**：无远程资源而本地条件齐备时，本地研究仍可进入。
- **FR-SYS-SET-01-01-AC02**：交易授权缺失时显示对应缺项，准备检查不能使交易变为已授权。

**界面对应：** [UI-SYS-SET-01 首次准备](#ui-sys-set-01)；[UI-SYS-RUN-01 个人工作总览](tasks-nodes.md#ui-sys-run-01)。

<a id="fr-sys-set-01-02"></a>

### FR-SYS-SET-01-02 选择工作资料位置并保护已有内容

**目标与结果：** 使用者明确知道研究资料与操作记录保存在哪里，确认写入能力和空间。已有目录不是可任意初始化的空白空间，选择位置不能悄悄覆盖原有内容。

**触发：** 首次准备中的资料位置选择，或工作总览打开当前资料信息。

**输入与约束：** 输入或选择本地资料位置；候选初始值为空并提示选择。显示是否存在内容、可写性和可用空间，不收集凭据。

**目标操作与反馈：**

1. 选择目录后预览可写性与现有资料概况。
2. 存在资料时明确选择打开可识别资料或另选位置。
3. 确认后显示最终工作位置和保存结果。

**异常与边界：**

- 只读位置明确指出无法写入，原有内容保持不变。
- 资料不受支持或损坏时拒绝打开，不自动清空或转换。

**验收条件：**

- **FR-SYS-SET-01-02-AC01**：选择有内容目录时，确认前不会写入或替换已有研究。
- **FR-SYS-SET-01-02-AC02**：无法写入时保留已输入路径并可重新选择，不能显示准备成功。

**界面对应：** [UI-SYS-SET-01 首次准备](#ui-sys-set-01)；[UI-SYS-REC-01 资料、备份与恢复](records.md#ui-sys-rec-01)。

<a id="fr-sys-set-01-03"></a>

### FR-SYS-SET-01-03 按研究与交易分别完成准备清单

**目标与结果：** 同一人需要并行准备研究与实盘，清单应分别表达数据、账户、风险和授权条件。未准备的一类能力不能掩盖另一类的可用结果，也不能通过总进度暗示可以交易。

**触发：** 首次准备选择研究与交易并重，或总览点击待补齐条件。

**输入与约束：** 清单读取合法数据来源、工作位置、账户身份、交易授权和风险可用性；缺项没有默认通过值。

**目标操作与反馈：**

1. 展开研究清单并进入来源配置补充真实数据条件。
2. 返回准备页重新核对研究条件，再查看交易缺项。
3. 进入账户授权页补齐条件后返回，只更新有可靠结果的项目。

**异常与边界：**

- 来源连接正常但无访问权限仍显示数据不可用。
- 账户已登录但风险缺失时禁止交易入口转为可提交。

**验收条件：**

- **FR-SYS-SET-01-03-AC01**：研究可用、交易缺风险时，两项状态分别可见。
- **FR-SYS-SET-01-03-AC02**：点击缺项携带对应上下文进入配置，返回后未确认项仍保留未完成说明。

**界面对应：** [UI-SYS-SET-01 首次准备](#ui-sys-set-01)；[UI-DAT-ACQ-01 数据来源与连接](../data/acquisition.md#ui-dat-acq-01)；[UI-LIV-RUN-01 账户连接与交易授权](../live/operations.md#ui-liv-run-01)。

### FR-SYS-SET-01-04 完成准备后进入明确的工作入口

**目标与结果：** 使用者完成必要准备后能够直接进入研究项目或市场观察，并知道随后哪些操作仍需要独立授权。首次准备可以稍后继续，跳过选项不能伪装成已满足条件。

**触发：** 首次准备页选择进入工作总览、开始研究或查看行情。

**输入与约束：** 使用意图和各项准备状态；研究与交易并重为本草案定位，不替使用者默认创建账户或策略。

**目标操作与反馈：**

1. 查看准备结果摘要及可用入口。
2. 选择稍后补齐非当前必需项，保存已经明确的普通偏好。
3. 进入目标工作，保留来源、资料位置与缺项提示的上下文。

**异常与边界：**

- 没有可用数据时允许查看空工作空间，但取数或实时行情明确不可用。
- 离开未保存设置时选择保存、放弃或继续编辑，不能直接丢失。

**验收条件：**

- **FR-SYS-SET-01-04-AC01**：跳过交易准备后可进入研究入口，交易仍未获授权。
- **FR-SYS-SET-01-04-AC02**：再次打开准备页能看到已保存位置和真实检查结果，不重新要求填写已保存普通资料。

<a id="fr-sys-set-01-05"></a>

### FR-SYS-SET-01-05 核对安装产物和支持环境

**目标与结果：** 安装前后都能确认运行的是预期产品及受支持平台。

**触发：** 安装、替换安装产物或首次打开。

**输入与约束：** 发行说明中的平台/架构/系统最低要求、可信来源与产物身份、资料位置和现有安装状态；具体发行渠道待评审。

**目标操作与反馈：**

1. 核对macOS Apple Silicon或Linux x86_64桌面及系统条件，说明包来源和验证结果。
2. 安装或显式替换前列出服务、资料及活动工作影响；存在活动交易时先进入账户处置，不能由安装动作隐式重启。
3. 安装后显示实际产物身份和准备检查入口，本地使用不要求Linux服务包。

**异常与边界：**

- 不支持的系统或无法通过产物完整性检查时停止安装，不关闭系统保护来继续。
- 不支持既有持久资料时明确拒绝打开并保留文件，不自动迁移或删除。

**操作案例：** 用户只有Mac并选择本地运行，准备页显示远程未配置且不阻塞本地能力。

**验收条件：**

- **FR-SYS-SET-01-05-AC01**：Mac本地研究安装完成无需下载或部署远程Linux服务才能进入准备。

<a id="fr-sys-set-01-06"></a>

### FR-SYS-SET-01-06 维护插件并明确卸载影响

**目标与结果：** 插件能力变化和卸载不会在用户不知情时改变运行或丢失资料。

**触发：** 启用、停用、替换插件或卸载软件。

**输入与约束：** 插件身份及兼容能力、依赖它的任务/策略/存储、活动服务与资料目录；插件是可信进程内代码，不宣称沙箱隔离。

**目标操作与反馈：**

1. 列出插件来源、可用能力及依赖；不匹配当前接口的插件明确不可用。
2. 停用/替换前显示影响，活动运行使用的必要能力必须先完成业务停止确认；缺风险能力不得继续新执行。
3. 卸载前区分客户端、后台服务、用户资料与安全存储，说明服务是否继续；仅按明确范围处理并报告结果，删除资料另行确认。

**异常与边界：**

- 未知停止状态不能视为维护已安全完成，不自动杀死远程运行。
- 卸载默认保留用户资料；不把删除客户端解释为账户已平仓。

**操作案例：** 准备停用策略依赖插件时看到一个远程运行，先回到运行页核对停止；远程失联时维护仍显示未满足前提。

**验收条件：**

- **FR-SYS-SET-01-06-AC01**：在用风险插件不能通过设置页停用而让原实例绕过风险继续发送。
- **FR-SYS-SET-01-06-AC02**：只移除客户端的结果明确剩余服务与资料位置，不静默删除账本。

**界面对应：** [UI-SYS-SET-02](#ui-sys-set-02)；[UI-SYS-RUN-03](tasks-nodes.md#ui-sys-run-03)。

## REQ-SYS-SET-02 按配置归属维护设置并确认实际生效

**领域：** 系统管理 / 安装与配置　 **建议优先级：** P1核心必要　 **需求状态：** 开发前设计规格（具体决定与运行配置见本条DEC）

### 目标与场景

让用户通过统一入口找到配置，明确配置由谁维护、影响什么对象及是否真正生效。

**使用者与场景：** 兼顾期货研究、实盘和运行维护的个人用户。

**触发条件：** 从配置入口选择明确对象，查看责任模块和当前有效状态。

### 前置条件

- 对象、所属业务模块和允许操作的范围明确。
- 涉及运行、费用或资料变更的条件已由用户明确配置；案例仅供评审。

### 输入与含义

| 输入           | 含义与单位                                                 | 约束                                                               |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| 配置对象       | 系统/节点/服务/插件或业务对象身份、所属模块                | 系统配置由系统管理维护；来源、策略、实验、账户政策回所属业务编辑。 |
| 配置内容与状态 | 当前有效值、待提交内容、保存结果、采用的配置身份与生效条件 | 界面不另存一份可独立生效的业务配置；既有固定实验保留所用内容。     |
| 凭据引用       | 本地凭据管理入口及脱敏身份                                 | 不在配置正文或导出中保存秘密，保存类别遵守既有凭据规则。           |

### 正常操作与反馈

1. 从配置入口选择明确对象，查看责任模块和当前有效状态。
2. 进入相应模块编辑，预览字段、影响范围及生效方式。
3. 按该类配置的规则保存或确认，查看实际结果与待生效条件。
4. 返回统一入口刷新真实状态，必要时查看记录或继续处理。

### 业务规则

- 统一入口提供索引、对象状态和跳转，不维护第二份账户或策略配置。
- 语言、密度等显示偏好即时保存；策略草稿、回测方案、账户限额遵守各自固定和生效流程，不强加通用保存按钮。
- 保存成功、业务规则检查通过和实际生效分开；需要重新连接或重启时先解释对象与影响，不能自动重启交易服务。
- 新配置不静默改变已提交任务、固定策略包或现有授权范围；采用条件由业务模块声明。
- 远程对象不可达时可保存明确标识的草稿，但不能显示远程已采用；无真实反馈不得宣称生效。

### 输出与状态影响

- 让用户通过统一入口找到配置，明确配置由谁维护、影响什么对象及是否真正生效。
- 可追溯的操作结果、责任归属、时间与异常说明。

### 异常与继续方式

| 发生什么               | 应怎样表现                                     | 使用者如何继续                                   |
| ---------------------- | ---------------------------------------------- | ------------------------------------------------ |
| 配置保存或应用失败     | 保留可确认的有效值和编辑内容，显示具体失败阶段 | 恢复对应条件后显式再提交，不以刷新页面冒充成功。 |
| 修改期间有效配置已变化 | 提示当前内容与基准差异，不覆盖另一已生效决定   | 重新核对差异与影响后确认。                       |

**预期结果：**

**窗口与空间：** 使用主窗口内的模块配置工作区；分类、只读对照和查询结果区域独立滚动，保留模块导航与主要动作。凭据及配置编辑转所属业务页面。

**状态设计范围：** 只采用下方状态表及关联FR适用于本页的状态；缺失值、来源时效、阻断原因与可执行下一步必须明确。字段与动作按本页交付约定核对。

### 目标操作规格

1. 按类别、责任模块、对象和生效状态定位配置。
2. 对照已保存、生效及运行采用的内容和读取时间，查看影响。
3. 进入唯一责任模块独立编辑或应用，返回后查询同一对象的生效状态。

**操作案例：** 账户上限生效5手、草稿3手时，两值分别可见；查询没有反馈仍保留原有效值与待核实标记。

### 业务验收要求

- **UI-SYS-SET-02-AC01**：有效5手与草稿3手同时可见。
- **UI-SYS-SET-02-AC02**：即时语言设置不被改成统一保存流程。
- **UI-SYS-SET-02-AC03**：无反馈不声称远程已生效。

### 字段与操作交付约定

本页是配置索引与只读对照。业务配置只在其所属页面编辑；索引不能保存、应用或复制第二份可生效的配置。

#### 用户输入

| 字段 | 类型、默认值与必填条件 | 合法范围及变更影响 |
| --- | --- | --- |
| 类别 / 责任模块 | 单选筛选，默认全部；可选 | 类别取偏好、来源、节点、插件、业务配置；责任模块取已登记模块，仅改变列表 |
| 对象 / 节点 / 环境 | 对象选择，默认全部可读范围；可选 | 从调用页面进入时预置其固定身份；显示明确筛选条件，不扩展到其他账户 |
| 生效状态 | 多选筛选，默认全部；可选 | 未配置、草稿、待生效、已生效、失败、待核实；这些是筛选值，不是可编辑业务状态 |
| 搜索 | 文本，默认空，0—200字符；可选 | 匹配对象名称或非秘密标识，不搜索或展示秘密值 |

#### 只读展示

| 信息 | 来源与含义 | 缺失或陈旧时 |
| --- | --- | --- |
| 配置身份、唯一责任模块 | 所属模块给出的对象、内容身份与维护入口 | 无责任入口说明不可维护原因，不在索引临时新建一份 |
| 已保存值 / 生效值 / 运行采用值 | 分栏展示各自内容身份、采用对象及时间；秘密只显非秘密引用 | 未确认生效时保留已知有效值与读取时间，不能把草稿当生效 |
| 影响与待处理条件 | 是否需重连、重启、再次授权，受影响任务或账户 | 影响未知时引导责任页核对，不自动重启或放宽规则 |

#### 按钮与动作

| 动作 | 启用条件 | 结果及失败反馈 |
| --- | --- | --- |
| 查询生效 | 选中可查询对象；同次查询进行中不重复 | 更新来源、读取时间及状态；不可达时保留最后可靠值并标待核实 |
| 转所属配置 | 选中对象有维护入口 | 携带对象、节点、环境及返回地址跳转；在责任页独立保存/生效，返回后重新查询 |
| 查看影响 / 失败详情 | 有对应证据或结果 | 展示差异、采用范围及错误，不执行应用、恢复或重启 |
| 清除筛选 | 任一筛选偏离默认 | 恢复全部可读范围；不清除配置内容 |

#### 适用状态与离开

| 状态 | 页面行为 |
| --- | --- |
| 首次未配置 | 按类别提供所属模块的配置入口；不生成示例配置 |
| 筛选无匹配 | 展示筛选摘要及清除入口；与无权限、不可达分别呈现 |
| 读取中 / 待生效 / 失败 | 分别显示读取请求、业务生效状态和错误；查询失败不撤销已保存草稿 |
| 待核实 / 基准冲突 | 显示最后读取时间及冲突内容，转责任页重新核对，不能在索引强制覆盖 |

离开只读索引不要求保存或放弃；会话内返回恢复筛选、选中配置和滚动位置。由责任页面返回时核对同一对象，禁止用新对象替代旧对象的状态。
