需求交付版 · 2026-10-18。细化规格已编制，用户逐项签认与产品验收分别记录；目标设计不代表已经实现，实际入口与差距见本页界面对应。

**模块目标：** 从真实来源取得行情、历史及情报原始材料，按明确规则加工并统一保存访问，为研究和实时业务提供可复核输入。

**职责边界：** 数据拥有来源获取、基础解析、通用资料和统一保存访问；语义提取、证据核验及情报发布决定归情报；不产生策略信号、账户授权或风险处置。

目标入口为**数据 → 接入与采集 / 加工与质量 / 管理与服务**，具体视图见[界面设计总览](../../common/ui-designs.md#target-navigation)。一级和二级导航分别对应本模块与子模块。实际入口段落只记录实现证据。

## 1. 已确认的模块划分与设计目标

数据模块划分为且仅划分为三个一级子模块：**数据接入与采集、数据加工与质量、数据管理与服务**。这是用户已确认的需求组织方式；各项细化行为、支持范围与数值目标按本次交付版编制。业务职责由个人期货量化任务推导；目标导航与模块对应，视觉与控件延续实际软件，实际截图单独说明实现差距。功能需求中尚未实现的步骤保留为待实现要求，不据此虚构现有页面。

详细阅读：[接入与采集](acquisition.md#data-acquisition-design) · [加工与质量](processing.md#data-processing-design) · [管理与服务](management.md#data-management-design) · [实际入口与拟议设计](#data-ui-design) · [交接及验收](#data-handoff-acceptance)。

| 子模块         | 用户要解决的问题                         | 负责的结果                                             | 不承担的职责                                       |
| -------------- | ---------------------------------------- | ------------------------------------------------------ | -------------------------------------------------- |
| 数据接入与采集 | 从哪些合法来源，取得哪些实时或历史数据？ | 已核验来源能力；明确范围的观测、采集结果、消耗及缺口   | 不以下载完成证明质量合格；不决定策略信号与交易动作 |
| 数据加工与质量 | 数据应按什么规则转换，能否满足指定用途？ | 标准数据、聚合与连续序列、质量报告、加工依据           | 不覆盖来源事实；不承担因子拟合、标签生成或策略研究 |
| 数据管理与服务 | 有什么数据，如何保存、固定、查找与使用？ | 基础资料、目录、存储、数据集与快照、历史查询和实时分发 | 不重复实现采集及加工规则；不把查询权限当作交易授权 |

基础资料是“数据管理与服务”的内部能力，包含品种、合约、来源代码映射、交易日历、交易时段与生效规则，不构成第四个一级子模块。质量与追溯是贯穿全程的要求，也不增加一级模块。

同一模块可以有多个页面，页面也可以调用其他模块的能力。该划分不要求三个进程、三个数据库或三个插件；部署、存储格式及实现技术另行设计。提供方与存储实现遵守项目的插件边界，核心只提供所需机制。

## 3. 数据对象与唯一归属

| 对象             | 业务含义                                 | 负责管理的子模块 | 必须保留的信息                                                     |
| ---------------- | ---------------------------------------- | ---------------- | ------------------------------------------------------------------ |
| 来源与能力       | 哪个提供方允许取得什么数据               | 接入与采集       | 来源身份、类别、粒度、范围、权限、限额与费用依据；秘密不在普通配置 |
| 采集计划及结果   | 一次或持续采集的范围与实际结果           | 接入与采集       | 明确范围、留存选择、确认、成功与未完成范围、观测与中断记录         |
| 加工定义及结果   | 针对固定输入执行的确定变换               | 加工与质量       | 规则内容、输入与基础资料身份、输出、计数及失败范围                 |
| 质量报告         | 对指定输入和范围所能作出的判断           | 加工与质量       | 规则、证据、问题位置、可判断与未知范围、检查时间                   |
| 基础资料         | 合约身份和时间、单位、规则依据           | 管理与服务       | 合法来源、适用范围、生效区间、修订及可获得时间证据                 |
| 数据内容与目录   | 原始记录、标准数据和派生序列的存放与检索 | 管理与服务       | 内容身份、来源、范围、位置、层次、实际保存状态及关联质量报告       |
| 数据集草稿及快照 | 为一个用途组织并固定的数据输入           | 管理与服务       | 成员、范围、依赖、用途条件、质量限制、不可变内容身份               |
| 访问与订阅       | 某消费方读哪一份历史数据或哪一路实时数据 | 管理与服务       | 消费方、对象、模式、范围、语义、时效及实际访问状态                 |

采集和加工通过统一保存能力提交结果，不各自维护独立目录。质量报告由加工与质量产生，目录和查询引用同一份报告。通用任务中心提供排队、进度与取消展示；数据页面负责解释本业务范围及结果，不再建立第二套任务状态。

## 4. 目标业务流程与状态（未实现步骤不得作为当前操作指引）

### 4.1 历史数据用于量化研究

1. 选择来源并确认历史权限与粒度。
2. 选择合约、日历和日期口径，预览已有覆盖、增量或补缺范围、额度及费用。
3. 确认后执行取数，逐范围报告已取得、失败、空响应和未执行。
4. 固定来源记录及基础资料，预览清洗对齐与聚合规则，再显式加工。
5. 核对质量报告；不足范围补采或调整用途，不以接受警告绕过必要条件。
6. 建立数据集草稿，检查成员和依赖后发布固定快照。
7. 研究或回测明确选择快照，保存数据身份、时间口径和限制；其余实验与风险条件在所属模块检查。

详细跨页操作见 [JRN-001](../../workflows/README.md#jrn-001)。其中6条来源、1条重复、5条标准输出的具体案例见本章加工页及案例图。

### 4.2 实时数据用于观察与策略

1. 核对来源、订阅类别、合约权限、时段与留存选择。
2. 预览影响与消耗，确认采集；逐对象区分订阅被受理与实际收到数据。
3. 完成必需的身份、单位和时间检查后提供实时分发；留存按显式配置执行，不等待历史快照发布。
4. 断流或保存失败时分别报告时效、连续性和未保存范围。数据消费方获得这些状态，由其业务规则决定处置。
5. 恢复后核对新观测，保留尚未解决的中断区间；补采另建明确计划。
6. 解除某个消费方订阅只影响该消费方。停止整个采集计划要列出全部影响，不隐含撤单、平仓或停止交易。

详细跨页操作见 [JRN-002](../../workflows/README.md#jrn-002)。仅提供最新报价的显示需求与逐事件连续的策略需求必须区分，不能静默降级后仍声称满足后者。

### 4.3 状态不能混用

| 对象     | 状态变化                                                                | 不能推导的结论                                                   |
| -------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 历史计划 | 草稿 → 已预览 → 已确认 → 执行中 → 完成 / 部分完成 / 失败 / 已取消       | 请求完成不表示样本完整；取消申请不表示实际停止                   |
| 实时采集 | 未启用 → 建立中 → 已订阅 → 有新观测；可能进入中断、权限拒绝、停止待确认 | 连接正常不表示所有合约有权限；恢复不表示历史缺口已补齐           |
| 留存     | 未启用 / 保存中 / 保存失败 / 已停止                                     | 分发正常不证明保存成功；保存成功不证明质量合格                   |
| 加工     | 草稿 → 预览 → 已确认 → 执行中 → 完成 / 部分失败 / 失败 / 已取消         | 完成不表示已发布，也不自动满足任意研究用途                       |
| 质量     | 未检查 / 检查中 / 已形成报告                                            | 报告形成后仍可包含缺口、冲突、异常或未知；不能用单个绿色标记概括 |
| 数据集   | 草稿 → 检查中 → 可发布 → 发布中 → 已发布；失败保留未发布对象            | 已发布不意味着适用于所有研究；限制和用途条件继续随数据提供       |

## 5. 共同规则与异常处理

| 规则                   | 具体要求                                               | 验收例子                                                 |
| ---------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| 来源事实与加工结果分开 | 原始记录保持可追溯，加工输出独立保存；更正须有来源依据 | 去掉1条重复后，仍能追溯6条原始记录与排除原因             |
| 同一身份和语义         | 合约、单位、时区、交易日、周期端点、累计量口径统一解释 | 同代码不同市场不合并；夜盘按已核验日历归属               |
| 历史可得性             | 区分事件时间、公布或可得证据、取得时间和交易日         | 公布时间未知时，不能用今天下载时间证明过去已知           |
| 缺失与零值             | 未提供、无权限、无成交、休市、断流与真实零分别表达     | 来源空响应不会自动补价格零或完整K线                      |
| 固定实验输入           | 实验引用具体内容快照及依赖，不引用会变化的“最新”       | S2发布后，原实验仍读S1；S1失去访问时明确失败             |
| 完整性按范围判断       | 日期覆盖、日内连续、字段完整和用途可用分别说明         | 已覆盖9/10合约日不能显示完整；未知日历不能计算确定完整率 |
| 失败不隐藏副作用       | 费用、已保存范围、未执行范围和未知结果分别报告         | 取消下载后保留已消耗额度和已取得记录                     |
| 删除保护               | 删除先核对依赖；有引用或在用对象拒绝删除               | 删除S1时列出实验甲，不提供静默级联删除                   |

| 发生位置 | 具体异常                     | 用户看到什么                           | 如何继续                                         |
| -------- | ---------------------------- | -------------------------------------- | ------------------------------------------------ |
| 采集     | 额度用尽或权限不足           | 按对象列成功、未执行、消耗及原因       | 补足条件后为剩余范围新建计划，重新预览确认       |
| 实时     | 断流后恢复                   | 新观测和未解决缺口同时可见             | 核对来源连续性或显式补采；不自动重发交易         |
| 基础资料 | 代码多义、规则冲突或日历缺失 | 原来源并列，相关计算未知或不可用       | 取得可靠资料后形成新修订；不猜测身份             |
| 加工     | 规则错误、取消或部分失败     | 原始记录保留，输出未发布，失败范围明确 | 修改规则重新预览或从已确认输入新建任务           |
| 存储     | 空间不足、位置不可访问       | 写入失败、已保存范围及未保存起点       | 用户处理空间与访问后显式继续；不自动删除或换位置 |
| 发布     | 依赖缺失或必要质量条件不满足 | 草稿保留并列阻断项，快照未发布         | 补齐指定依赖或合理调整用途条件后重查             |
| 查询     | 指定快照损坏、缺失或不可访问 | 明确对象与错误；没有代替结果           | 恢复指定资料或显式选择另一份输入创建新实验       |

## 6. 与其他业务的边界

研究模块定义研究样本和连续规则选择、因子与标签、训练拟合、实验设计及用途必要条件；数据模块执行已明确的数据规则并交付输入和证据。行情页面展示行情与图表；采集模块拥有来源采集，服务能力拥有消费方订阅。交易与风控拥有执行授权、持仓及异常处置，数据模块只报告数据事实和可用性，不能代替交易决策。

本轮不增加数据采购、团队权限、外部公共数据API、任意文件导入、自动跨节点接管或新的客户端。方法、质量及留存按交付范围编制，实际数据源按准入核验，时效门槛由用途配置，示例数值不作为上线默认值。

| 研究输入与仓库数据查看                        | 已有版本使用、查看、保存当前选择及使用已保存数据集；保存动作仅核对源码 | 补充统一发布检查、可得证据和用途限制；返回原数据版本                      | 无匹配/无权限/未保存/损坏分开；不自动换输入                          |
| 任务中心底部抽屉                              | 通用任务进度、结果与取消                                               | 数据结果链接回对应计划、版本或加工报告                                    | 页面和抽屉使用同一任务状态；返回后筛选及选中对象保留                 |

### 7.1 共用布局与操作约束

- 列表负责选择对象，详情负责解释该对象，确认区负责范围/消耗/影响。只在用户需要决定的地方展示信息，不把内部命令名、摘要算法或进程细节堆进主表。
- 表格中的未知数值显示“—”，原因在相邻状态或详情中解释，不长期放置面向开发者的提示口号。名称缺失允许代码作为显示文字，不能用它猜测合约身份。
- 查询和查看不产生业务写入；下载、加工、发布和删除的按钮名称应说明动作。确认期间显示提交状态，提交结果不明先核对原操作，不能重复发起。
- 切换输入使对应预览失效；未提交草稿离开时明确保留或放弃。后台任务已提交后，离开页面只改变展示，不改变任务生命周期。
- 下拉项采用已有统一样式、不透明弹层和优先向下/空间不足向上的行为；禁用选项说明具体能力或前置条件，不隐藏不可用原因。
- 列表筛选、详情和确认区域在窄窗口内仍可操作；长记录使用表格自身滚动，不使整页横向溢出。键盘焦点、加载中、失败重查和空结果均需能辨认。

### 7.2 三条目标操作路线

| 使用任务                 | 操作路线                                                                          | 必须交付的完成证据                                           |
| ------------------------ | --------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 准备规则策略研究输入     | 来源 → 全市场资料 → 合约历史下载 → 仓库选版本 → 加工/质量检查 → 固定数据集 → 研究 | 来源范围、加工规则、固定内容、时间口径和质量限制；见 JRN-001 |
| 为实时策略提供数据并留存 | 市场来源 → 采集范围/留存确认 → 消费方订阅 → 到达/保存监控 → 中断核对 → 显式补采   | 每个消费方与上游依赖、已保存范围、缺口及恢复证据；见 JRN-002 |
| 复核修订并维护资料       | 仓库检索 → 比较新旧内容 → 查看引用 → 形成新输入或保留旧实验 → 检查删除依赖        | 差异范围、受影响实验、选择结果及实际维护结果；见 JRN-003     |

多因子研究在第一条路线中同时选择日行情与所需表数据，按可得时点对齐；因子计算和组合权重在研究模块继续。不能为了使用多因子就另建一套下载、目录或快照体系。

## 8. 模块交接、验收与待定参数

### 8.1 每次交接必须明确的内容

| 从哪里到哪里             | 交接内容                                       | 接收方何时可以继续                                       |
| ------------------------ | ---------------------------------------------- | -------------------------------------------------------- |
| 采集 → 保存              | 来源语义、范围、原始内容、取得证据及未完成范围 | 管理与服务确认实际持久保存；未保存内容不能宣称可重复读取 |
| 保存 → 加工              | 固定内容身份、基础资料、规则和用途             | 必要输入可读取且含义可解释；缺失部分明确阻断相应输出     |
| 加工 → 管理              | 独立输出、分阶段计数、依赖、质量报告           | 收到完整结果清单；加工完成不自动等于已发布               |
| 管理 → 研究/回测         | 固定快照、成员、字段与时间语义、质量和可得限制 | 消费业务必要条件满足并保存输入身份                       |
| 实时采集 → 分发 → 消费方 | 观测及身份、事件/接收时间、来源状态和连续性    | 按订阅语义提供；状态异常同步传递，不自动恢复交易动作     |
| 管理 → 维护流程          | 内容、目录、引用和活动使用情况                 | 能确定影响及必要依赖；执行前再次核对，不能静默清除引用   |

三个业务子模块不一一对应当前进程。现有行情服务承担实时连接与观测，数据服务承担历史保存与访问，任务服务拥有异步执行状态，Agent拥有进程生命周期。详细工程设计必须保持这些事实的唯一归属；本章不要求为三个子模块新建三个服务，也不改变核心与插件的边界。

## 与情报的协作

数据也管理非结构化材料，情报也产出结构化内容；边界按业务职责而不是文件格式划分。[情报模块](../intelligence/README.md)负责语义提取、证据核验、事件关系及发布决定，数据保留来源、原件、基础解析和统一存储访问。数据采集成功不代表情报处理成功，正式情报发布还须通过情报规则。

| 数据子模块 | 交付给情报                                         | 不承担的职责                           |
| ---------- | -------------------------------------------------- | -------------------------------------- |
| 接入与采集 | 获授权原件、来源时间、获取时间、内容标识与失败范围 | 不根据标题或下载成功判断事件成立       |
| 加工与质量 | 解码/OCR/正文表格、定位、完整性和可读范围          | 不解释数量是否减产、不判断利多利空     |
| 管理与服务 | 通用身份、统一保存访问、固定集合和依赖保护         | 不自行改变情报核验、事件合并和发布状态 |

结构清晰的供应商库存、产量或经济指标可直接经数据进入分析，无须绕行LLM。统一存储不意味着数据拥有全部业务语义。完整交接见[材料到情报与研究](../../workflows/README.md#jrn-031)。

## 与配置、调度和通知的交接

数据拥有来源授权用途、采集范围、质量规则和材料记录。定时采集由数据定义任务与输入范围，系统只触发并记录；每次执行检查权限、额度及当前来源条件。中断和质量告警由数据确认，通知中心只呈现。具体公共分工见[运行支撑边界](../../product.md#operational-support-boundaries)。
