## 确认的范围与组织

策略是数据、情报、分析之后的第四个核心业务模块，三个子模块为策略逻辑构建、组合与仓位管理、策略管理与交付。回测是第五个独立核心业务模块。此处按业务职责划分，不要求当前软件立即出现同名菜单，也不决定服务进程或插件数量。

| 子模块         | 负责的问题                 | 主要对象                                           | 交付                                 |
| -------------- | -------------------------- | -------------------------------------------------- | ------------------------------------ |
| 策略逻辑构建   | 根据什么信息作出什么决策？ | 规则、模型训练方案、预测映射、事件、状态、混合逻辑 | 固定决策定义与训练/试算证据          |
| 组合与仓位管理 | 各策略和品种应该持有多少？ | 组合政策、预算、目标敞口、手数、调仓条件           | 目标持仓和调整意图                   |
| 策略管理与交付 | 后续使用的是哪份明确内容？ | 策略包、参数方案、依赖、限制、证据和交付引用       | 回测或交易准备草稿所引用的固定策略包 |

规则和模型是逻辑构建的两种方式，可以混合。它们共用组合和交付能力，不建立两套互不兼容的策略路径。策略不强制采用模型或优化器，简单规则可以直接配固定手数，但仍须声明数据时点、输出和约束。

## 与数据、分析、回测、交易的边界

| 对端     | 策略拥有的责任                             | 对端拥有的责任                                            |
| -------- | ------------------------------------------ | --------------------------------------------------------- |
| 数据     | 说明输入能力、时间和固定引用               | 来源、清洗对齐、存储、分发及引用保护                      |
| 分析     | 引用特征与标签，将其用于决策或模型训练     | 探索、变量定义、诊断性评价与筛选证据                      |
| 回测     | 提供策略内容、参数空间、训练程序和组合政策 | 历史时钟、成交与账户模拟、费用/保证金/必要风险及运行证据  |
| 实盘交易 | 交付固定策略并定义决策和目标生成逻辑       | 账户权限、实例启动/停止、实际订单成交、状态核对和运行控制 |
| 评估 | 交付固定目标及归属政策，引用评价结论 | 绩效、归因与完整验证结论；不授予真实账户权限 |
| 系统     | 提供训练等任务的业务配置与结果语义         | 节点、资源调度、进程与取消/终态查询机制                   |

分析中的辅助拟合只用于变量诊断；作为策略依赖、会在后续决策时预测的模型由本模块管理。特征变换定义复用分析能力，拟合实例按本次训练计划生成。回测中的滚动训练由历史时钟触发同一训练定义，每个产物绑定真实训练截止与可用时点，不能直接拿全期训练的模型回看早期行情。

历史回测和交易运行都消费相同策略定义。交易模块负责运行控制，不再编写另一套策略公式。完整性检查、历史验证结论和当前交易许可各有责任方，交付记录不得将它们合并成一个“可以实盘”的状态。

## 统一对象与生命周期

| 对象       | 必须记录                                             | 生命周期与边界                           |
| ---------- | ---------------------------------------------------- | ---------------------------------------- |
| 逻辑定义   | 内容、输入输出、事件、状态、单位和参数约束           | 草稿可编辑；固定内容不回写               |
| 模型产物   | 算法、特征顺序、处理链、训练样本、截止时点和拟合参数 | 产物只代表指定训练结果，不随同名方案改变 |
| 参数方案   | 类型、单位、范围、约束和具体取值                     | 方案可比较；固定候选引用具体值           |
| 组合政策   | 信号语义、资金基准、预算、取整、调仓与约束           | 生成目标，不拥有实际订单和账本           |
| 策略包     | 逻辑、模型、特征、参数、组合和状态约定的固定依赖     | 固定后只读；派生新候选而非原地替换       |
| 证据与交付 | 试算、训练、分析、回测及目标草稿引用                 | 证据绑定实际包；交付不自动运行或授权     |

模型不是必填项，纯规则包无需伪造空模型；有明确目标持仓逻辑的简单策略可以使用明确的直接目标政策，无需为形式新增优化算法。固定包不包含凭据，也不持有可复用的交易授权。

## 正常操作与异常

1. 从分析选择变量和研究问题；选择规则、模型或混合方式。
2. 声明决策时刻、可得输入、输出语义、状态与退出规则。
3. 规则完成固定样例试算；模型按时间计划训练并固定产物；混合方式检查组合分支。
4. 配置组合、预算、目标手数和调仓政策，核对单位和风险限制。
5. 组装并检查策略包，确认固定依赖和适用范围。
6. 交付回测草稿，由回测模块配置环境和执行模拟，再由评估模块形成验证结论。
7. 如需模拟或实盘，携带固定策略与证据进入独立交易准备、授权和启动流程。

草稿可带缺项保存；校验失败定位具体依赖并保留输入；训练排队、运行、取消中与终态分别显示；失联不自动重试；固定包只读，参数修改产生新候选。无效预测不会自动变零信号，未知在途不会当零计算差额。实际运行的暂停、撤单、平仓和恢复都在交易流程独立确认。

## 界面与案例入口

拟议交互包括规则/混合逻辑工作区、模型训练与预测映射、组合与仓位政策、候选交接检查和策略包管理。它们是5项界面规格，不要求增加5个顶层菜单。沿用当前Terminal风格；已核对截图仍代表原有研究或交易入口，缺少的工作台标为待设计。

- [规则试算与批量验证](../../workflows/README.md#jrn-016)：原有规则路径，回测步骤已引用独立回测模块。
- [多因子与组合运行](../../workflows/README.md#jrn-017)：策略形成目标，交易核验权限并控制运行。
- [模型与混合策略交付](../../workflows/README.md#jrn-022)：训练、预测映射、组合、固定包到回测。
- [参数修改与固定交付](../../workflows/README.md#jrn-023)：新候选不覆盖旧回测或替换已有运行。

算法与规则编辑形式按下列交付范围编制，运行预算与参数按字段约束显式填写，不用案例参数代替用户选择。优先保证输入当时可得、模型训练边界、输出语义、固定引用与风险边界可复核。

## 独立评估的交接

完整策略、组合和账户的绩效、风险分析及可靠性结论统一由[评估模块](../evaluation/README.md)负责。分析保留特征与因子的评价，策略保留逻辑、模型和组合定义；不能用局部变量证据替代完整策略验证。

## 情报作为策略输入

策略可选择已发布事件或经分析形成的特征，并明确可用时间、更新频率、缺失、延迟和更正处理。情报提醒不是交易信号的默认实现，也不授予账户执行权限；自然语言摘要不能直接变成订单。策略定义输入及决策，实盘负责统一准入与执行路径。

## 策略约束与账户限制

风险需求随业务归属维护，不单设风险控制模块。策略定义预算、仓位与集中度、止损等逻辑及触发后的目标行为；实盘账户政策构成独立执行限制。策略允许的意图仍可能被账户拒绝。共用定义见[共用交易约束](../../product.md#execution-risk-semantics)，规则通过固定策略包和实验条件交接，不创建另一套账户状态。

## 与配置、调度和通知的交接

策略参数、组合预算及定时调仓条件属于策略定义。实际调仓由实盘运行按授权和实时账户条件执行，不交系统调度直接重放交易指令；编辑系统计划不能改变固定策略或账户限额。具体公共分工见[运行支撑边界](../../product.md#operational-support-boundaries)。

风险要求分别由策略预算、回测模拟账户、评估风险分析和实盘账户准入承担；没有独立风险业务模块。共用风险算法能力不拥有独立真实账户额度。

## 策略交付范围

以下是本次交付版采用的设计规格，源于用户授权完善文档；不冒称已经逐项获得用户确认或已经实现。具体部署资料按[交付与验收](../../delivery.md)核验。模块内通用“支持的方法/来源”以此有限集合及显式能力检查为准。

| 能力 | 必须交付的行为 | 限制与拒绝条件 |
| --- | --- | --- |
| 规则及状态 | 结构化规则编辑与表达式，支持K线收盘、已核验事件、定时调仓触发，以及入场/退出/目标调整；提供比较、逻辑、阈值、交叉和有限状态条件，错误定位到规则/字段。 | 条件不执行任意系统脚本；状态初始化、输入缺失、事件重复与停止行为必需定义。规则与模型统一生成目标意图，不直接调用柜台。 |
| 模型策略 | 至少支持线性回归、岭回归训练与预测；固定特征顺序、标签、训练窗口、预处理、超参数与随机源；预测通过显式阈值或排名转为信号/目标。 | 模型更新由显式新训练任务完成，不热替换运行包；更换模型重新验证及授权。算法实现由可信插件承担。 |
| 混合逻辑 | 规则可作为模型准入过滤、预测后处理及退出条件；按固定顺序输出带原因的唯一目标。 | 规则冲突无默认优先级，需明确顺序或拒绝固定；空预测不得悄悄当成零信号。 |
| 组合与仓位 | 支持固定手数、按权益比例、等权和固定权重组合、波动率缩放；显式总预算、单成员上限、方向及名义敞口基准。整数手数向零取整，余量留现金并展示。 | 波动率无有效值时不可生成该方法目标；不自动重新分配余量、不把保证金当损失。用户须填写风险限额，案例数值不作为默认。 |
| 调仓与归属 | 定时、目标变化阈值两种触发；实际持仓加可信在途后计算剩余目标。一个账户同时仅一套拥有执行权的策略/组合实例；组合可含多个内部成员。 | 同账户手动新增委托先暂停自动新增并核对在途；外部人工成交进入待分配核对。当前不支持两套独立策略实例争夺同一真实账户或默默净额。 |
| 交付及验证 | 策略包固定逻辑、参数、模型、状态初始化、仓位政策、输入及能力依赖；有限参数组命名、标签和逐字段差异。转运行须有逻辑样例、独立留出、成本及压力评价、模拟核对与人工决定。 | 验证条件必须在试验前定义；没有通用盈利通过线。修改内容派生新包，旧结果和运行包不被覆盖；目的环境逐项核对能力。 |

## 模型与仓位计算的明确口径

线性回归最小化训练样本残差平方和；岭回归在相同损失上增加alpha乘系数平方和，alpha为显式非负参数，截距不参与惩罚。是否拟合截距、特征标准化和训练样本权重均固定在方案内；当前不提供自动搜索最优alpha。参考[scikit-learn Ridge目标函数](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)核对定义，具体算法仍由可信插件实现。没有足够有效样本或数值求解未收敛时训练失败，不能发布空模型；预测输出必须经过已定义的信号映射和仓位规则。

名义目标金额由选定资金基准乘有符号权重得到；目标手数为名义目标除以有效价格与合约乘数后向零取整。要求资金基准、价格及乘数可用且适用；余量单独显示，不自动分配。固定手数方法不借该金额公式推断预算。调仓差额=目标手数−已核对实际手数−可信在途净变化；开平拆分仍核对今昨仓、可平量及账户政策。

验收小例仅用于算术：基准100000、权重0.2、价格100、乘数10，目标20手；实际12、可信在途+3，剩余目标+5。若在途未知则不计算可执行差额。手续费、保证金和账户风险按独立配置检查，20手不代表允许发送数量或推荐仓位。
