## 交付内容与范围

完整范围是七个核心业务模块、系统管理和通用规范，不以“核心功能先做”排除已经定义的模型策略、多因子、情报、量化运行或恢复能力。每个模块README末尾的“交付范围”规定有限的方法集合与不支持范围，子模块正文维护详细FR、字段、流程和AC。本文件规定如何交接、核验和决定是否交付完成，不重复维护业务规则。

| 资料 | 用途 | 当前状态 |
| --- | --- | --- |
| 产品定位与八个模块目录 | 使用者、范围、责任和有限能力集合 | 已编制；方法选择接受评审，不冒称已实施 |
| REQ / FR / UI / JRN正文 | 输入、行为、异常、案例、界面与流程 | 逐项有唯一归属和链接 |
| 目标布局、关键状态图 | 要做成的页面和阻断/恢复方式 | 目标设计；不能当作软件截图或运行证据 |
| 实际截图及浏览页 | 当前实现差距、已有视觉与交互基线 | 保留原实拍及核对范围 |
| 决定与配置登记 | 区分已编制设计、用户必填配置和外部准入 | 88项均有明确处置，不再混为无答案的问题 |
| 全量追踪表 | FR到主题、UI、AC与关联旅程的定位 | 由正文生成；关联不等于测试通过 |
| 非功能基线、接口和对象约定 | 环境、负载、测量、跨模块交付和故障行为 | 可转化为测试；数值目标未实测 |
| 图文阅读版 | 汇总离线阅读和编号搜索 | 由Markdown与SVG生成，禁止反向改写正文 |

优先级表示安全和实现依赖，不是删减交付范围的许可。未实现但属于范围的功能记为“未完成”；能力有限或外部来源不支持时，必须按规格明确拒绝，不能用假数据或静默替代使演示看似完整。

## 外部准入与现场配置

这些项需要真实环境、证据或账户拥有者选择，文档编写不能代填。它们是软件启用/发布的输入条件，不是开放式产品需求。当前均**未核验**；未通过时只阻断受影响能力，不能宣布整个产品通过验收。

| 准入项 | 责任与需交付的资料 | 通过标准 | 未满足的行为 |
| --- | --- | --- | --- |
| GATE-DATA 来源与市场 | 接入负责人登记提供方、授权用途、市场/品种、频率/历史范围、日历规则、生效证据、费用配额和时点字段 | 用真实获授权样本验证查询/订阅、缺口、限额和规则；与能力清单逐项一致；不把来源未提供字段算作已支持 | 禁用依赖缺项的取数或执行；展示具体范围和补齐入口 |
| GATE-INT 模型与材料 | 使用者选择允许处理/外发的材料、模型位置、费用上限；接入负责人保存脱敏调用和标注核验记录 | 无外发授权不得发送；模型失效/结构错误/证据不足均按规范失败；标注集及实际质量可复核 | 允许保留材料和人工核验；不自动发布LLM结果或伪造模型完成 |
| GATE-TRADE 柜台与账户 | 使用者本地配置仿真/真实环境、身份、政策；验收人记录柜台字段、订单能力、查询及结算证据 | 仿真完成部分成交、撤单、未知结果、跨日、归属冲突和记录失败的隔离验证；真实环境另行取得明确授权和实际核对证据 | 无授权/风险/唯一归属不发送；仿真通过不能替代真实账户许可 |
| GATE-RELEASE 安装与设备 | 发行负责人给出macOS Apple Silicon和Linux x86_64支持版本、产物身份、依赖、签名/校验、参考硬件及测试报告 | 两桌面实际安装/启动/卸载及资料保留、Linux节点运行、质量基线均有结果；软件包与验证源码/依赖身份相符 | 不能声明支持未经验证的平台版本或节点；保留用户原文件，拒绝不支持格式 |

用户在启用业务时填写的必需配置包括来源访问用途与预算、样本/验证计划、账户风险限额、运行模式与授权、调度时区和保留规则。字段必须有类型、单位、合法范围和明确缺失反馈；没有可交易默认限额、默认付费授权或默认实盘许可。配置完成记录“谁、何时、对象、实际内容和作用范围”，秘密只保留安全存储引用或会话输入。

## 验收顺序与证据

| 阶段 | 环境和检查 | 必需证据与判定 |
| --- | --- | --- |
| 文档交接 | 正文、编号、链接、决定、UI入口及图稿，规则与模型两条主线人工推演 | 文档检查报告、评审意见及具体范围；只能判定文档可交接 |
| 领域与接口 | 隔离固定夹具，精确账本/时点/状态及外部输入拒绝 | 每个FR的全部AC对应预期/实际结果；交易、数据与服务逻辑在C++层验证，算法另保留固定数值对照 |
| UI与交互 | 组件环境，中文/英文、键盘、窗口缩放及各页规定的异常 | 字段错误、可用动作、保存/取消、未知状态及返回截图/记录；不能以静态图代替实际操作 |
| 连续业务 | 项目隔离E2E环境与已核验来源，执行42条JRN | 每步的已有对象、操作、输出身份及分支；规则策略和多因子均从无研究成果开始完成闭环 |
| 模拟与外部联调 | 本地实时模拟、外部仿真柜台分开；至少一次完整交易日及次日开市 | 模式、时点、在途、账本与结算证据；故障只在隔离环境注入，不对真实账户制造故障 |
| 质量与发行 | 两支持桌面及Linux节点，按非功能负载与安装矩阵 | 原始采样、分位数、失败/超时数、资料校验和产物身份；外部网络耗时单列 |
| 用户交付验收 | 使用者依照目标路径执行任务并审阅未决限制 | 用户签认范围、日期及明确保留项；本次编写不能替代签认 |

测试执行遵守仓库入口：产品E2E仅用`pnpm run test:e2e`或`pnpm run test:e2e:journeys`。纯文档浏览检查与产品E2E分开记录。只有运行过的用例才记实际结果，源码阅读、链接检查、模拟和真实柜台证据不相互替代。

### 验收结果记录格式

每次运行至少记录：FR及具体AC/JRN步骤、代码/构建/插件身份、平台和设备、来源/账户环境（脱敏）、固定输入及前提、执行时间、预期、实际、证据文件、通过/失败/受阻/未执行、缺陷链接和复验结果。领域数值检查记录计算口径；非功能记录负载及原始样本。一次组件测试可覆盖多项AC，但须列出对应断言，不能自动按UI关联推定覆盖全部FR。

- **阻断缺陷**：错误发单、越权、未知结果重发、账本/资料损坏、错误时点研究被当作严格验证；修复并复验前不得交付受影响范围。
- **严重缺陷**：核心旅程无法完成、关键指标或字段错误、缺失必要异常/恢复路径、质量基线不达标；不能仅备注后放行。
- **一般缺陷**：不改变业务结果且有明确可操作替代的呈现问题；交付前由用户明确接受保留项和修复安排，不由作者自行视为通过。

## 完成判据与变更

文档可交接要求：范围有限且有责任人角色；所有FR有AC和UI去向；所有UI有目标入口、布局、字段/动作/关键状态和案例；旅程前提输出可闭合；88项决定各有明确处理；非功能可测；无断链或冲突。软件可交付还要求：范围内功能全部完成、准入通过、对应AC及42条旅程和非功能基线有真实结果、没有未解决阻断/严重缺陷、产物身份一致并由用户确认。

修改需求时在唯一正文中修改理由、内容与生效范围，同步受影响FR/UI/JRN/AC、图稿及准入条件；Git保存历史。编制者提案、用户确认、实现和验收为四个独立事实，不新增多套旧版需求。用户未签认的具体设计可以用于评审与估算，但不能把“文档齐备”描述成“产品已获最终批准”。

生成命令：`pnpm run docs:requirements`；检查命令：`pnpm run docs:requirements:check`。派生文件为`requirements.html`、`decisions.md`与`traceability.md`；修改决定时编辑所属需求正文的DEC记录，不修改索引。目标SVG是维护源；实际截图只能由真实界面核对后替换。
