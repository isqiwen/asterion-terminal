# 界面设计阅读与操作指南

[需求总纲](../README.md) · [界面设计总览](ui-designs.md) · 目标界面浏览（生成文件 `prototype.html`） · [跨模块流程](../workflows/README.md)

本页说明目标工作台怎样组织、用户怎样完成页面操作，以及如何阅读58项UI设计。页面图中的账户、合约和数值是设计案例；字段约束及动作后果以对应UI正文为准。

## 工作台导航

| 一级入口 | 二级任务 | 页面间应保留的上下文 |
| --- | --- | --- |
| 数据 | 接入与采集；加工与质量；管理与服务 | 来源、数据对象、品种/合约、范围、频率、运行位置 |
| 情报 | 信息提取；情报核验；事件服务 | 材料、候选/事件身份、处理方法、可得时点与发布状态 |
| 分析 | 探索与统计；特征与因子；有效性与筛选 | 研究身份、固定输入、样本角色、标签与拟合身份 |
| 策略 | 逻辑构建；组合与仓位；管理与交付 | 候选、固定内容、参数、决策时钟、组合与风险边界 |
| 回测 | 设计与实验；交易与账户模拟 | 实验、策略包、数据、时序、费用、规则及任务身份 |
| 评估 | 绩效与归因；风险与压力；稳健性与综合评价 | 事实来源、模式、期间、口径、比较对象及结论限制 |
| 实盘 | 准备与运行；执行与成交；账户与核对 | 账户、环境、执行节点、授权、意图/订单和风险状态 |
| 系统管理 | 安装配置；任务与节点；资料诊断与导出 | 节点、任务/记录身份、过滤范围及操作归属 |

任务、通知与连接状态为全局入口。系统管理位于主导航底部。页面、详情抽屉、确认对话框和独立设置窗口各有明确用途；58项UI是操作界面的规格单位，不要求全部建成独立窗口。具体承载形态见[总览](ui-designs.md)。

## 一项UI规格应怎样阅读

1. **入口与前提**：从哪个导航或上下文动作进入；必须已经选择哪些对象；缺前提时怎样补齐。
2. **布局与只读信息**：主区、筛选区、详情区及状态区分别展示什么；金额、时点、来源及状态来自哪个业务对象。
3. **可编辑输入**：每个字段的类型、单位、必填条件、默认值、合法范围、依赖与修改后果；默认“未选择”不能变成隐含授权。
4. **操作按钮**：点击前条件、触发动作、确认内容、进行中反馈、完成结果及失败路径；按钮和只读信息不能混入输入校验表。
5. **状态与返回**：空、加载、失败、过期、部分、待核对及禁用状态；返回原任务时保留哪些筛选和草稿。
6. **验收与图稿**：以图理解信息层级，以UI-AC检查操作和反馈，以关联FR检查业务结果。

## 编辑、提交与长任务

| 用户动作 | 目标行为 | 不应混淆的结果 |
| --- | --- | --- |
| 修改字段 | 保留草稿并标记未保存；依赖变化使相关预览或校验失效 | 编辑值与已生效值 |
| 保存草稿 | 校验可保存范围，成功返回对象身份；失败保留输入 | 草稿与固定/发布/已授权对象 |
| 固定或提交 | 校验必需字段、输入身份及能力；成功显示明确对象或请求身份 | 请求受理与任务最终完成 |
| 返回或关闭编辑页 | 有未保存变化时提供继续编辑、保存草稿或放弃修改；只读返回不弹确认 | 关闭页面与停止后台任务 |
| 取消长任务 | 展示取消请求与最终停止；已有产物按完整性保留 | 请求取消与已经取消 |
| 结果未知后继续 | 查询原请求；已接纳则回到原任务，明确失败后才允许独立新尝试 | 网络重试与再次执行业务 |

即时生效的偏好应在控件附近明确保存结果和失败恢复方式；不套用草稿提交语义。真实交易、删除资料、外发材料与付费执行的确认须说明具体对象、范围及后果。

## 关键状态的使用方法

空状态应说明可开始的动作；加载状态保留选择并标记数据尚未可用；失败状态保留输入和原因；陈旧数据展示最后有效时间及依赖操作的限制；部分结果列明完成、失败与缺失部分；交易结果未知时展示原意图和查询入口。

状态不能仅由颜色表达。全局断线提示与局部数据时效共同显示；“通知已读”只改变阅读状态。恢复连接、关闭提示、切换页面不能解除账户限制或自动重新发送交易命令。关键状态图见[界面总览](ui-designs.md)，完整行为见[交互规范](interaction.md)和各UI条目。

## 典型连续操作

- **研究**：数据中固定输入 → 分析中定义样本及因子 → 策略中形成逻辑与仓位 → 回测中固定实验 → 评估中解释结论。每次交接使用对象身份并保留来源链接。
- **情报**：导入材料 → 提取候选 → 对照证据核验 → 发布带可得时间的事件 → 供研究或已声明的策略消费。模型返回不能直接成为真实订单。
- **交易**：选择账户和环境 → 检查准备与风险 → 明确授权 → 提交意图 → 核对订单、成交及资金持仓。暂停新增、撤单、平仓、停止实例是独立动作。
- **故障处理**：从通知或任务定位业务对象 → 查看最后事实及未知范围 → 查询或修复前提 → 显式恢复。无法确认旧执行者已失效时不得由新节点接管交易。

逐步输入、输出和异常分支见[42条业务旅程](../workflows/README.md)。跨页上下文不能沿用到不同账户、模式或固定内容而不重新检查。
