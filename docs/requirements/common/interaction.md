## UI设计在需求文档中的位置

UI设计是需求说明的组成部分。一级导航对应数据、情报、分析、策略、回测、评估、实盘七个模块，二级导航对应子模块；系统管理位于底部辅助区，任务、通知和连接状态为全局入口。页面内的对象列表、编辑、结果与详情共享同一业务上下文。

每项UI在所属子模块唯一维护，关联FR、JRN和AC；本节定义跨页面的视觉、字段及交互约定。图稿是目标布局与业务状态的示意，案例数值必须标明为虚构输入。

| 每项UI规格应包含 | 具体内容 |
| --- | --- |
| 页面目的与任务 | 用户要完成的任务、关联FR、完成后得到的对象或结果 |
| 入口与返回 | 导航入口、上游对象身份、账户/模式/节点上下文、返回位置与保留内容 |
| 信息布局 | 标题、筛选、主内容、详情、主要动作、反馈的位置与相邻页面关系 |
| 用户输入 | 每个可编辑字段的名称、类型、单位、候选集合或范围、默认值、必填条件、校验与修改影响 |
| 只读展示 | 来源、业务含义、更新时间、缺失原因和是否可跳转，不将只读事实画成输入框 |
| 动作 | 按钮启用条件、确认内容、接纳与完成反馈、失败/未知后允许动作 |
| 适用状态 | 区分首次空、筛选空、加载、部分、受阻、已知失败、结果未知和陈旧；不适用状态注明理由 |
| 取消与离开 | 关闭界面、丢弃编辑、取消任务、撤销业务请求分别定义；说明秘密处理和跨模块返回 |
| 页面图与案例 | 主要布局、会改变用户选择的关键状态、一次完整操作前后的变化 |
| 验收判据 | 给定对象与条件、动作、预期业务结果、页面反馈和可继续路径 |

表格不得把“取消”“详情”“通知内容”等区域标题冒充用户输入字段；只读页面不套用“补齐必填项”“保存草稿”的表单流程。数字参数只有在方法、单位和适用范围确定后才允许编辑；没有运行默认值的必填业务参数保持为空，案例不能填入真实草稿。

## 统一视觉与交互规范

目标为信息优先的深色技术终端，避免厚阴影、装饰卡片和每个模块各自一套视觉。以下定义独立于软件源码，是页面与图稿共用的设计依据。

| 方面 | 目标规范 |
| --- | --- |
| 基础色 | 画布 #06080B，面板 #0B0E13，输入背景 #11161D，边框 #2A3543，分隔线 #1A212B |
| 文字与反馈 | 主文字 #EEF4FB，正文 #C5CCD6，辅助文字 #7C8796；青蓝 #38D6F2 表示可操作/选中/焦点，警告 #EDB966，错误 #F16B76；状态同时提供文字，不只靠颜色 |
| 字体与数字 | 使用系统无衬线中文/西文字体，数值采用等宽数字；正文紧凑14px、舒适15px，说明不小于12px，页面标题20–24px；金额与价格右对齐 |
| 尺度 | 以4px为间距步长；紧凑控件28px、表格行28px，舒适控件32px、表格行36px；控件圆角2–4px、边框1px |
| 主操作 | 青蓝描边及淡底，单一主要动作；危险操作同时显示对象及后果，不默认获得焦点 |
| 输入与只读 | 可编辑字段有标签与输入边框；只读事实用文本/数值行并显示来源与时点；缺失显示“—”和原因，未知不填0 |
| 下拉与浮层 | 不透明背景，选中/悬停/焦点/禁用可辨；优先下开、空间不足向上，长列表局部滚动；Esc取消当前选择并返回触发控件 |
| 导航与布局 | 标题栏、窄侧栏、模块工作区和底部状态区；偏好使用独立窗口，任务/通知使用抽屉，凭据/导出使用上下文对话框 |
| 保存方式 | 偏好选择即保存；业务定义显式保存草稿；发布、启动、授权、删除分别确认；展示值改变不能直接执行交易 |
| 窗口适配 | macOS Apple Silicon与Linux x86_64桌面；1280×800及1920×1080下关键账户、模式、限制与动作可达；表格局部横向滚动，详情可收拢并可恢复 |
| 文案与可访问性 | 中英文含义一致，错误指出对象、原因和下一步；键盘顺序跟随阅读顺序，弹层内焦点受控，关闭后返回原控件 |

### 设计一致性检查

- 每页图稿与正文使用同一目标入口、字段名称及主要动作；不能把区域框数量当作功能完整性的证据。
- 页面仅描述适用状态：列表选择不形成业务草稿，信息查询失败不要求用户“修正只读值”，关闭抽屉不取消任务。
- 检查中英文长文本、键盘焦点、两种密度、窗口缩放和必要数值精度；失联/陈旧必须保留最后可靠时点。
- 交易页面持续显示账户、环境、授权和必要限制，停止、撤单、平仓分别说明后果；视觉切换不改变业务状态。

## 公共通知与业务告警

通知中心是公共呈现入口，不是新业务模块。数据负责来源中断和质量问题，情报负责事件订阅及证据冲突，研究模块负责实验失败与结果提示，实盘负责账户风险事件，系统负责运行与调度异常；每个来源负责触发证据、活动/解除状态及处理入口。

通知维护未读/已读、提醒渠道及允许的静音偏好。通知渠道交付失败不改变业务结果；用户已读不表示问题解决；来源失联时保留最后状态并标明待核实。事件身份用于关联重复投递，实质变化保留更新，不能只按标题或文本合并。

实盘风险触发后先按政策阻断，与是否通知成功无关。应用内保留事件与业务跳转，风险状态在实盘持续可见；标记已读、清除筛选、静音或关闭窗口均不能解除账户限制。需要恢复、撤单或其他操作时进入所属业务独立确认。

通知渠道范围为应用内及本机桌面提醒，不包含邮件、聊天或第三方推送。实盘以有人值守为使用条件：关闭窗口后后台可继续，但不构成离线监控或离机提醒承诺。关闭时说明活动账户、仍可能成交的订单及通知可达条件；通知失败不解除业务限制。渠道、聚合和保留规则见本页DEC及系统交付范围。

## REQ-COM-UX-01 一致理解语言、时间和数值并可用键盘操作

**领域：** 通用规范 / 界面交互与数值表达　 **建议优先级：** P1核心必要　 **需求状态：** 开发前设计规格（具体决定与运行配置见本条DEC）

### 目标与场景

语言与显示偏好应帮助使用者理解研究和交易信息，而不会改变业务含义。涉及时间、金额和数量时必须保留口径，常用操作应可通过键盘完成并清楚呈现当前位置。

**使用者与场景：** 在中文或英文环境下查看跨时区资料，并使用键盘工作的个人使用者。

**触发条件：** 修改偏好、比较资料或通过键盘完成日常操作。

### 前置条件

- 业务数据具有明确的时间和单位含义。
- 使用者可以查看当前显示偏好。

### 输入与含义

| 输入           | 含义与单位                           | 约束                                                         |
| -------------- | ------------------------------------ | ------------------------------------------------------------ |
| 界面语言       | 中文或英文展示                       | 切换语言不改动合约标识、原始业务值或账户身份。               |
| 显示时区与格式 | 时间展示时区和数值分组、小数显示方式 | 不能改变交易日归属或计算精度；高风险确认保留必要单位与精度。 |

### 正常操作与反馈

1. 使用者查看当前语言、时区和格式。
2. 选择新偏好并查看同一案例的显示变化。
3. 确认后相关内容采用一致口径。
4. 通过键盘在可操作项目间移动并识别焦点。
5. 完成选择、确认或取消，系统保留清晰反馈。

### 业务规则

- 中文与英文表达同一业务含义，缺少翻译不能直接暴露不可理解的标识。
- 业务时间显示时区；交易日与日历日期分别表达。
- 显示舍入只影响展示，不能改写价格、金额及计算结果。
- 未提供的数据与零值明确区分，负数不依赖颜色单独表达。
- 键盘焦点可见；弹出选择支持选择、取消和返回原操作位置。
- 危险确认不能由偏好切换、焦点移动或误触默认键直接代替。

### 输出与状态影响

- 一致生效的显示偏好。
- 可理解且可键盘访问的关键操作反馈。

### 异常与继续方式

| 发生什么             | 应怎样表现                       | 使用者如何继续                   |
| -------------------- | -------------------------------- | -------------------------------- |
| 时间缺少可靠时区信息 | 标明时间口径未确认，不猜测转换。 | 取得明确口径后再作跨时区比较。   |
| 输入格式无法明确解释 | 指出无法解析的输入，不猜测数值。 | 使用者按展示的格式说明重新输入。 |

### 案例：时区转换不改变业务时间

**虚构案例条件：** 虚构案例：同一事件为案例日 T 01:30 UTC，即 T 日 09:30 UTC+08:00；数值 1234.50 为案例金额，另一项数值未提供。

1. 从 UTC 显示切换为 UTC+08:00。
2. 切换语言和数值分组显示。

**预期结果：**

- 同一事件变为 09:30；金额仍为 1234.50；未提供项不变成 0。

![偏好改变展示，业务含义保持一致](../examples/req-com-ux-01.svg)

| 编号               | 给定                      | 当               | 则                                           |
| ------------------ | ------------------------- | ---------------- | -------------------------------------------- |
| REQ-COM-UX-01-AC01 | 事件时间为 T 日 01:30 UTC | 切换到 UTC+08:00 | 显示 T 日 09:30，并标明时区，事件身份不变。  |

### 决定与配置约束

<a id="dec-com-ux-01-01"></a>

- **DEC-COM-UX-01-01**：**规格决定**。简体中文和英文；时间保存原始时区，行情显示交易所时区，任务显示计划时区，均明确标识。macOS Cmd/Linux Ctrl加1—7对应业务模块，偏好Cmd/Ctrl+,；Tab/Shift+Tab、Enter、Esc遵守控件语义，不新增语言。

### 详细功能

<a id="fr-com-ux-01-01"></a>

### FR-COM-UX-01-01 选择并即时保存中英文显示偏好

**目标与结果：** 语言选择只改变界面文字，不改变账户、合约、价格或授权含义。采用每项选择即保存的方式，不增加保存/放弃按钮。

**触发：** 系统管理 → 安装与配置 → 偏好设置 → 语言。

**输入与约束：** 简体中文和English两个选项；初始读取已保存语言；首次默认简体中文。

**目标操作与反馈：**

1. 展开语言下拉菜单。
2. 选择简体中文或English，界面随选择更新并即时保存。
3. 核对关键按钮语言和业务身份；保存失败时读取明确提示。

**异常与边界：**

- 翻译缺失时明确显示未能完整应用，不将内部标识冒充正常文字。
- 语言切换不清空研究草稿，也不修改待确认委托内容。

**验收条件：**

- **FR-COM-UX-01-01-AC01**：选择英文后关键按钮和说明保持一致，账户和合约身份不变。
- **FR-COM-UX-01-01-AC02**：Esc关闭未确认的菜单选择时保留原值；已选定的语言无需再点保存。

**界面对应：** [UI-COM-UX-01 偏好设置](#ui-com-ux-01)；[UI-SYS-SET-01 首次准备](../modules/system/setup.md#ui-sys-set-01)。

<a id="fr-com-ux-01-02"></a>

### FR-COM-UX-01-02 区分显示时区与业务交易日

**目标与结果：** 使用者可按习惯阅读时间，同时知道事件发生、接收与交易日的不同口径。时区偏好只改变展示，不重算交易归属或把未知时间猜成确定事实。

**触发：** 在偏好设置选择通用显示时区，或查看事件时间详情。

**输入与约束：** 时区初始候选来自系统时区并明确显示；事件原时区和交易日由可靠来源提供，缺失值没有猜测默认。

**目标操作与反馈：**

1. 选择目标时区并查看同一事件的前后对照。
2. 确认显示时区后即时保存，相关时间字段显示适用口径；行情与任务继续明确使用交易所或计划时区。
3. 在事件详情同时查看原始时间依据与交易日。

**异常与边界：**

- 来源时间没有可靠时区时标为口径未确认，禁止伪造转换。
- 跨午夜后的日历日期改变不自动改变来源确认的交易日。

**验收条件：**

- **FR-COM-UX-01-02-AC01**：T 日 01:30 UTC 转为 UTC+08 后为 T 日 09:30，事件身份不变。
- **FR-COM-UX-01-02-AC02**：夜盘示例的交易日保持来源给定值，并与显示日历日期分别标注。

**界面对应：** [UI-COM-UX-01 偏好设置](#ui-com-ux-01)；[UI-SYS-REC-02 事件与诊断](../modules/system/records.md#ui-sys-rec-02)。

<a id="fr-com-ux-01-03"></a>

### FR-COM-UX-01-03 明确数值单位、精度和缺失状态

**目标与结果：** 研究和交易必须能够区分有效零值、负值、未提供与失效信息。显示格式应改善阅读，同时保留价格、金额和数量的实际精度，不能影响风险判断和真实委托。

**触发：** 在偏好设置选择数字分组和金额展示小数位，或查看行情、账户和导出中的数值。

**输入与约束：** 候选分组格式和金额展示位数需与字段精度一致；没有来源值显示缺失，价格精度不能由统一金额格式强制覆盖。

**目标操作与反馈：**

1. 查看金额、价格、数量、零值和缺失值示例。
2. 修改显示偏好后检查单位、负号与必要精度。
3. 确认选择即保存并应用到显示，关键确认仍展示完整有效价格和数量。

**异常与边界：**

- 解析不明确的数值输入明确拒绝，不猜测逗号含义。
- 颜色不能独自表达亏损或异常；缺失不能格式化为零。

**验收条件：**

- **FR-COM-UX-01-03-AC01**：1234.50 可显示为 1,234.50，但真实数值与计算结果不变。
- **FR-COM-UX-01-03-AC02**：零金额与未提供金额外观可区分，负数带符号且不只依赖颜色。

**界面对应：** [UI-COM-UX-01 偏好设置](#ui-com-ux-01)；[UI-SYS-REC-03 导出资料](../modules/system/records.md#ui-sys-rec-03)。

<a id="fr-com-ux-01-04"></a>

### FR-COM-UX-01-04 统一选择菜单的可读背景和展开位置

**目标与结果：** 语言、显示密度、涨跌配色及筛选等选择菜单应具有一致、清晰的展开状态。菜单覆盖内容时仍然可读，位置按可用空间决定，选项较多时在菜单内部滚动而不遮住操作依据。

**触发：** 点击或键盘展开偏好、资源和任务筛选中的选择项。

**输入与约束：** 选择值与候选列表来自对应字段；默认向下展开，只有下方空间不足时向上，均受可见工作区限制。

**目标操作与反馈：**

1. 打开菜单后以不透明表面、边界和可见选中项展示。
2. 移动或键盘选择选项，长列表在限定高度内滚动。
3. 确认后更新字段并收起；取消后保留原值和触发位置焦点。

**异常与边界：**

- 上下都不足时限制菜单高度并内部滚动，不能把选项放到窗口外。
- 禁用项保留原因且不可选；菜单遮挡下的按钮不能被穿透点击。

**验收条件：**

- **FR-COM-UX-01-04-AC01**：菜单展开后底层文字不会透过背景干扰选项阅读。
- **FR-COM-UX-01-04-AC02**：下方有足够空间时向下，不同选择框仅因空间差异向上，当前选中项始终可定位。

**界面对应：** [UI-COM-UX-01 偏好设置](#ui-com-ux-01)；[UI-SYS-RUN-02 任务中心](../modules/system/tasks-nodes.md#ui-sys-run-02)；[UI-SYS-RUN-03 运行资源](../modules/system/tasks-nodes.md#ui-sys-run-03)。

<a id="fr-com-ux-01-05"></a>

### FR-COM-UX-01-05 通过键盘完成导航并保持可见焦点

**目标与结果：** 常用桌面操作应能在不使用鼠标的情况下完成。焦点顺序与页面阅读顺序一致，用户能知道正在操作什么，关闭弹层后不会失去上下文或意外触发交易。

**触发：** 使用 Tab、方向键、回车或 Esc 在页面、表单和选择菜单中操作。

**输入与约束：** 初始焦点落在页标题后的首个主要可操作项；危险操作不默认获焦。快捷键集合属设计草案，不覆盖输入中的编辑键。

**目标操作与反馈：**

1. 用 Tab 顺序经过导航、主要内容和页内操作。
2. 在选择菜单内用方向键移动并以回车确认，Esc 取消。
3. 关闭对话框后回到触发控件，继续完成原任务。

**异常与边界：**

- 交易输入框回车不直接发送真实委托。
- 不可用操作可说明原因，焦点不可跳入隐藏背景或被永久困住。

**验收条件：**

- **FR-COM-UX-01-05-AC01**：无需鼠标可以选择语言、取消修改并返回原选择框。
- **FR-COM-UX-01-05-AC02**：弹层开启时焦点限定其有效范围，关闭后回到触发处且焦点可见。

**界面对应：** [UI-COM-UX-01 偏好设置](#ui-com-ux-01)；[UI-SYS-SET-01 首次准备](../modules/system/setup.md#ui-sys-set-01)；[UI-SYS-REC-01 资料、备份与恢复](../modules/system/records.md#ui-sys-rec-01)。

### FR-COM-UX-01-06 离开未保存草稿前作明确选择

**目标与结果：** 对确实具有待保存草稿的备份、导出方案，离开时明确保存、放弃或继续编辑。偏好设置为即时保存，不适用此草稿流程；秘密输入取消即清除，不能作为普通草稿保存。

**触发：** 修改备份或导出方案的普通草稿后离开；不适用于即时保存的偏好下拉项。

**输入与约束：** 草稿与已保存值分别记录；秘密字段不进入普通草稿恢复，业务委托确认按交易要求独立处理。

**目标操作与反馈：**

1. 编辑后显示未保存状态和保存入口。
2. 尝试离开时展示涉及的设置及三个明确选项。
3. 选择保存并成功后继续离开，放弃恢复原值，继续编辑保留现场。

**异常与边界：**

- 校验或保存失败时留在原页并指向问题字段，不执行原跳转。
- 没有改动时不显示多余离开确认；运行中的后台任务不因离开草稿停止。

**验收条件：**

- **FR-COM-UX-01-06-AC01**：有待保存的备份或导出草稿时，离开须作明确选择；即时保存的偏好不增加离开确认。
- **FR-COM-UX-01-06-AC02**：放弃只清除本次草稿，已保存设置及后台任务状态保持不变。

**界面对应：** [UI-SYS-REC-01 资料、备份与恢复](../modules/system/records.md#ui-sys-rec-01)；[UI-SYS-REC-03 导出资料](../modules/system/records.md#ui-sys-rec-03)；[UI-SYS-RUN-01 个人工作总览](../modules/system/tasks-nodes.md#ui-sys-run-01)。

### FR-COM-UX-01-07 危险动作明确对象后再确认

**目标与结果：** 删除资料、移除保存凭据及停止本地运行具有不同后果，确认应精确到所选对象与影响。用户能够安全取消，确认按钮不得依赖模糊的“确定”或默认焦点造成误操作。

**触发：** 选择删除资料、移除凭据保存项或停止本地运行等有明确后果的动作。

**输入与约束：** 从已选择对象生成身份、数量和后果摘要；危险动作不继承其他对象的旧确认，批量对象数量必须可见。

**目标操作与反馈：**

1. 查看确认标题中的具体动作与对象。
2. 阅读将删除、保留或仍可能继续发生的内容；资料删除须先通过引用与活动使用检查。
3. 选择明确命名的动作后执行，或取消回到原对象。

**异常与边界：**

- 对象范围变化后原确认失效，必须重新核对；被引用或活动使用的资料不能通过确认强制删除。
- Esc 取消；初始焦点放在返回或安全说明处，不以默认回车执行危险操作。

**验收条件：**

- **FR-COM-UX-01-07-AC01**：删除研究甲的确认不能用于稍后新增选中的研究乙。
- **FR-COM-UX-01-07-AC02**：取消停止本地运行时不发出停止动作，重新确认后实际影响有结果反馈。

**界面对应：** [UI-SYS-REC-01 资料、备份与恢复](../modules/system/records.md#ui-sys-rec-01)；[UI-COM-SEC-01 凭据与访问用途](security.md#ui-com-sec-01)；[UI-SYS-RUN-03 运行资源](../modules/system/tasks-nodes.md#ui-sys-run-03)。

## REQ-COM-UX-02 统一查看通知并保持业务告警与处置独立

**领域：** 通用规范 / 界面交互与数值表达　 **建议优先级：** P1核心必要　 **需求状态：** 开发前设计规格（具体决定与运行配置见本条DEC）

### 目标与场景

让用户在通知中心看到需要关注的事件，知道来源、状态和处理入口，且不让通知设置改变业务安全行为。

**使用者与场景：** 兼顾期货研究、实盘和运行维护的个人用户。

**触发条件：** 业务模块确认事件或告警并执行其必要控制，独立产生可追溯通知。

### 前置条件

- 对象、所属业务模块和允许操作的范围明确。
- 涉及运行、费用或资料变更的条件已由用户明确配置；案例仅供评审。

### 输入与含义

| 输入     | 含义与单位                                             | 约束                                                               |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| 业务事件 | 来源模块、对象、事件身份、严重程度、触发证据与发生时间 | 业务模块决定产生、更新及解除，不能从任意日志级别推断必须阻断交易。 |
| 通知状态 | 未读/已读、渠道尝试、静音偏好、最后同步时间            | 已读和静音属于呈现状态，不等于事件解除或风险恢复。                 |
| 处置引用 | 相关业务页面、权限和下一步                             | 通知仅导航或标记阅读，不越过所属模块的操作确认。                   |

### 正常操作与反馈

1. 业务模块确认事件或告警并执行其必要控制，独立产生可追溯通知。
2. 在通知中心按来源、对象、严重程度和未读状态查看。
3. 打开详情核对触发证据，跳转对应业务处理。
4. 标记已读或调整允许的提醒方式；真实解除状态随业务确认更新。

### 业务规则

- 事件、告警和强制控制并非同义；任务完成可通知，风险达到限制须由实盘执行阻断，不等待用户读消息或通知送达。
- 业务拥有活动/解除/待核实状态；通知拥有未读/已读及渠道结果，静音与已读不能解除业务限制。
- 桌面通知权限被拒或服务失败时，通知中心保留记录并说明渠道状态；只确认交给通知服务不能冒称用户已读。
- 同一事件身份的重复投递不形成多个独立事件，实质变化保留发生次序和新时间；不能按相同文字吞掉不同事件。
- 必要风险状态在业务页面持续可见；静音只影响允许的声光/弹出方式，不隐藏关键限制、日志或处置入口。
- 来源离线时显示最后状态和时效未知，不能自动标为解除。
- 通知限于应用内及本机桌面；用户须能访问这些渠道并履行实盘值守，不能把后台继续解释为离机监控。

### 输出与状态影响

- 让用户在通知中心看到需要关注的事件，知道来源、状态和处理入口，且不让通知设置改变业务安全行为。
- 可追溯的操作结果、责任归属、时间与异常说明。

### 异常与继续方式

| 发生什么         | 应怎样表现                             | 使用者如何继续                             |
| ---------------- | -------------------------------------- | ------------------------------------------ |
| 桌面通知权限拒绝 | 中心保留事件并显示该渠道未送达或未启用 | 用户可调整权限；业务控制继续执行。         |
| 事件来源无法联系 | 保留最后已知状态及时间，标记待核实     | 恢复后向原业务查询，不因消息已读自动解除。 |

### 案例：静音和已读不能解除风险暂停

**虚构案例条件：** 虚构案例：账户权益97000相对基准100000达到3%暂停条件。桌面提醒被拒，用户随后在通知中心标记已读并静音。

1. 实盘先按规则暂停新增风险。
2. 通知中心显示告警与渠道失败。
3. 标记已读和静音后查看账户状态。

**预期结果：**

- 账户持续暂停新增风险，告警已读不解除。
- 应用内保留一个事件；相同事件重复到达不增加第二个告警。

## UI-COM-UX-01 偏好设置

**业务目标：** 设置语言、时区和数值显示，并通过实际示例理解键盘、下拉菜单与保存行为；显示偏好不改变业务事实。

### 页面形态与目标布局

**规格范围：** 本条定义目标布局、字段、动作和业务状态，设计图与以下操作规则共同作为开发依据。

**界面形态：** 独立设置窗口内页。

**目标到达路径：** 系统管理 → 安装与配置 → 偏好设置。从业务详情进入时携带固定对象身份和返回位置。

| 区域 | 要显示的内容 |
| --- | --- |
| 顶部上下文 | 偏好设置 |
| 列表、分类或步骤区 | 偏好分类及返回安装与配置 |
| 主要工作区 | 语言 / 密度 / 配色 / 时区 / 数值显示 |
| 选中项详情或检查区 | 即时保存结果 / 失败原因 |
| 主要动作区 | 选择即保存 |

![UI-COM-UX-01 偏好设置目标布局](../designs/ui-com-ux-01.svg)

**区域联动与返回：** 输入、只读展示与动作按下方分表定义；选中对象、查询条件及返回位置保持一致，导航不隐式执行业务。保存、取消及离开适用本页的具体规则。

**窗口与空间：** 使用独立偏好窗口，正文区域必要时滚动；每项选择、即时保存反馈和返回入口保持可达，不重复主窗口侧栏。

**状态设计范围：** 只采用下方状态表及关联FR适用于本页的状态；缺失值、来源时效、阻断原因与可执行下一步必须明确。字段与动作按本页交付约定核对。

### 目标操作规格

1. 打开独立偏好窗口，查看逐项保存值和显示样例。
2. 用菜单或数值控件确认单项选择，该项即时保存并显示生效或失败。
3. Esc只取消未确认菜单候选；关闭窗口返回原工作区，不增加统一保存流程。

**操作案例：** 切换语言、时区或金额格式后，账户金额、交易日和计划执行时刻保持原业务含义。

### 业务验收要求

- **UI-COM-UX-01-AC01**：语言、密度、配色、时区及数值显示项按本页列出的候选与默认值展示，确认选择即保存，不增加统一保存/放弃按钮。
- **UI-COM-UX-01-AC02**：菜单展开不透明，优先向下，空间不足向上或滚动；Esc关闭且不改变选择。
- **UI-COM-UX-01-AC03**：偏好保存失败明确保留原生效值与失败选择；改变时区或数值格式不改变交易日、业务数值与调度规则，离开不触发普通草稿确认。

### 字段与操作交付约定

本页仅编辑显示偏好。每项选择即保存，不设置统一保存/放弃按钮；已保存值和本次保存结果逐项展示。

#### 用户输入

| 字段 | 类型、首次默认与必填条件 | 合法范围及变更影响 |
| --- | --- | --- |
| 语言 | 简体中文 / English单选，默认简体中文；必有一项 | 确认选择即保存；不改对象身份、交易含义或未提交业务草稿 |
| 显示密度 | 紧凑 / 舒适单选，默认紧凑；必有一项 | 只改变间距和行高，遵循公共视觉尺寸 |
| 涨跌配色 | 红涨绿跌 / 绿涨红跌，默认红涨绿跌；必有一项 | 正负号、方向文字同时保留，颜色不代替业务状态 |
| 通用显示时区 | 可搜索IANA时区单选，初始候选为系统有效时区；必有明确值 | 系统时区不可识别时要求选择；行情仍标交易所时区、任务仍标计划时区，通用偏好不能改交易日或调度规则 |
| 数字分组 | 开/关，默认开 | 只改变显示，如1234.50与1,234.50；不接受歧义数字解析 |
| 金额展示小数位 | 整数0—8，默认2 | 仅一般摘要显示；确认、账本详情和导出保留所需精度，合约价格按报价精度，手数不因此变小数 |

#### 只读展示

| 信息 | 来源与含义 | 缺失或失败时 |
| --- | --- | --- |
| 展示样例 | 明确标为样例的正负金额、零、缺失值及同一事件时间 | 缺失值显示“—”及原因，不能格式化成0 |
| 每项保存与生效状态 | 已保存选择、生效选择、保存中或失败及原因 | 失败保留原生效值与本次失败选择，不标已保存 |
| 时间口径说明 | 原始时区、交易所时区、计划时区和交易日的作用 | 来源时区未知时不虚构转换 |

#### 按钮与动作

| 动作 | 启用条件 | 结果及失败反馈 |
| --- | --- | --- |
| 确认控件选择 | 值合法且该项无未决保存 | 只提交该偏好，显示保存中和结果；不能改变订单、风险、数据或策略参数 |
| 重试本项保存 | 上次保存明确失败且值仍合法 | 重试相同偏好；若结果未知先读取已保存值，不猜测成功 |
| 关闭 / 返回安装与配置 | 始终可用 | 返回原触发位置，不增加保存/放弃；失败项下次仍显示真实已保存值 |
| Esc关闭下拉 | 下拉已展开 | 不采用未确认候选，收起并恢复触发控件焦点；已确认保存不被撤销 |

#### 适用状态与离开

| 状态 | 页面行为 |
| --- | --- |
| 首次无个人偏好 | 展示上表明确默认，不能显示任意案例选择；没有“无记录/创建对象”流程 |
| 菜单展开 / 焦点 / 禁用 | 不透明背景，优先向下、空间不足向上或局部滚动；不可用项说明原因 |
| 保存中 / 保存失败 | 逐项反馈，其他无依赖偏好可操作；失败不清空业务草稿 |
| 翻译或时区不可用 | 提示具体字段不能完整应用，保留最后有效选择，不把内部标识当正常译文 |

离开只关闭偏好窗口，不撤销已保存选择，也不将失败选择当已保存。选择时区后的对照同时保留原始时间口径；任何显示变化均不修改业务数值、事件身份、交易日与调度时刻。

## UI-COM-UX-02 通知中心

**业务目标：** 让用户在通知中心看到需要关注的事件，知道来源、状态和处理入口，且不让通知设置改变业务安全行为。

### 页面形态与目标布局

**规格范围：** 本条定义目标布局、字段、动作和业务状态，设计图与以下操作规则共同作为开发依据。

**界面形态：** 底部抽屉视图。

**目标到达路径：** 底部状态区 → 通知中心。从业务详情进入时携带固定对象身份和返回位置。

| 区域 | 要显示的内容 |
| --- | --- |
| 顶部上下文 | 未读 / 来源 / 业务状态 |
| 列表、分类或步骤区 | 通知列表 / 阅读状态 |
| 主要工作区 | 通知内容 / 时间 / 对象 |
| 选中项详情或检查区 | 仍有效限制 / 业务处置入口 |
| 主要动作区 | 标记已读 / 转业务处置 |

![UI-COM-UX-02 通知中心目标布局](../designs/ui-com-ux-02.svg)

**区域联动与返回：** 输入、只读展示与动作按下方分表定义；选中对象、查询条件及返回位置保持一致，导航不隐式执行业务。保存、取消及离开适用本页的具体规则。

**窗口与空间：** 从底部展开并保留原工作区；列表及详情独立滚动，关闭抽屉不取消业务，返回所属业务时收起抽屉。

**状态设计范围：** 只采用下方状态表及关联FR适用于本页的状态；缺失值、来源时效、阻断原因与可执行下一步必须明确。字段与动作按本页交付约定核对。

### 目标操作规格

1. 从底部状态区打开通知，按阅读、级别、来源、对象和时间筛选。
2. 选中通知查看只读正文、证据、阅读状态及独立的业务限制状态。
3. 可标记已读或调整允许的提醒偏好；实际处置进入责任模块，返回再查询状态。

**操作案例：** 账户暂停通知被标已读或桌面提醒失败时，账户暂停仍生效，通知内不能直接恢复交易。

### 业务验收要求

- **UI-COM-UX-02-AC01**：3%暂停在通知失败和已读后仍生效。
- **UI-COM-UX-02-AC02**：同一事件重复到达不增加独立告警。
- **UI-COM-UX-02-AC03**：业务解除和通知已读分别可见，未引入直接发单入口。

### 字段与操作交付约定

本页为通知查询抽屉。通知正文、触发证据及业务限制只读；阅读状态和提醒偏好可调整，处置进入原业务模块。

#### 用户输入

| 字段 | 类型、默认值与必填条件 | 合法范围及变更影响 |
| --- | --- | --- |
| 阅读状态 | 全部 / 未读 / 已读，默认全部；可选 | 仅筛选通知，未读不等于严重或仍未解除 |
| 级别 / 来源 / 对象 | 枚举筛选及对象选择，默认全部可读范围；可选 | 级别为信息、警告、阻断；不允许修改某条通知的业务级别 |
| 时间范围 | 起止时间，默认最近一日，必填查询条件 | 起点早于终点，时区明确；过滤按通知发生时间，详情另显最近更新时间 |
| 桌面提醒 | 开关，默认关闭 | 开启需系统权限；权限拒绝显示不可达，应用内通知仍记录 |
| 非关键提醒静音 | 关闭 / 15分钟 / 1小时 / 至本次会话结束，默认关闭 | 只针对选择的允许静音来源；关键风险、阻断与业务限制始终保留，不暂停风控或清除事件 |

#### 只读展示

| 信息 | 来源与含义 | 缺失或陈旧时 |
| --- | --- | --- |
| 通知身份、正文、级别、对象 | 原来源事件及触发证据，不是编辑框 | 内容不可读取显示具体原因，不要求用户填写通知正文 |
| 阅读 / 业务状态 | 未读/已读与活动/已解除/待核实分栏 | 未读转已读不推断解除；业务状态更新必须有来源依据 |
| 首次/最近时间、重复次数 | 同一事件合并记录，保留更新和计数 | 重复到达不增加独立告警，未知关联不能猜测合并 |
| 提醒渠道与同步时间 | 应用内记录、桌面权限/交付状态、最近业务核对 | 桌面失败不影响原业务限制，来源不可达显示最后时间 |

#### 按钮与动作

| 动作 | 启用条件 | 结果及失败反馈 |
| --- | --- | --- |
| 查看详情 / 查询业务状态 | 选中通知且来源可定位 | 读取原事件及业务状态；失联保留待核实，不新建业务请求 |
| 标记已读 | 选中未读通知 | 仅更新阅读状态，失败保留未读；不解除账户限制、不确认业务处置 |
| 转业务处置 | 有明确对象与责任入口 | 携带事件、对象、证据及返回位置进入原模块；通知内没有发单、恢复交易或撤单按钮 |
| 调整提醒偏好 | 偏好值合法且允许该类型调整 | 即时保存渠道/静音选择；拒绝权限时说明应用内仍可查看 |
| 清除筛选 / 关闭 | 始终可用 | 仅改变展示，关闭不消除事件或解除限制 |

#### 适用状态与离开

| 状态 | 页面行为 |
| --- | --- |
| 无通知 / 筛选无匹配 | 分别说明没有已记录通知和被筛选排除；提供清除筛选，不提供“创建通知” |
| 加载中 / 来源不可达 | 保留已知通知和最后核对时间，限制仍可见；不把失联显示为空 |
| 通知已读但业务活动 | 阅读标记改变，活动限制和业务处置入口持续显示 |
| 业务解除 / 桌面提醒失败 | 分别显示解除依据和渠道失败，二者互不替代 |

通知没有业务草稿，离开不出现保存/放弃；提醒偏好按即时保存规则处理。返回恢复筛选及事件身份并查询业务状态。应用内和桌面提醒只在相应环境可达时有效，不构成离机或远程告警服务。
