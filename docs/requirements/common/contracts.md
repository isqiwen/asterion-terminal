# 业务对象、时间与交接约定

[通用规范](README.md) · [产品责任表](../product.md#functional-scope-contract) · [交付验收](../delivery.md)

本页约定业务可观察契约，不指定数据库或新增服务。核心提供机制，来源、存储、策略和风险算法由插件提供；跨进程传输遵循项目Protobuf契约，界面字段不是另一个事实来源。

<a id="object-contract"></a>

## 共同对象字段

| 字段 | 含义与类型 | 必需约束 |
| --- | --- | --- |
| 对象身份 | 不透明唯一标识；名称是可编辑显示值 | 重命名不改变身份；引用不得靠显示名称猜测；名称缺失可显示代码 |
| 内容身份及依赖 | 固定内容摘要、来源对象和实际引用 | 固定快照/策略/结果不可被新修订覆盖；摘要相同不免除领域内容检查 |
| 所属位置与模式 | 运行节点；历史、本地模拟、柜台仿真或实盘枚举 | 模式和账户在关键页面始终可见，不能复用不同模式的授权或账本 |
| 时间与范围 | 原始事件时间、来源发布时间、取得/处理/发布时点及其时区/精度 | 未知值为空并带原因；严禁用处理时点补造来源可得时间 |
| 完整性与质量 | 完整/部分/不可判定及覆盖、缺口、错误依据 | 数据缺失和零不同，部分结果不可宣称完整完成 |
| 操作身份及状态 | 一次意图、请求、执行尝试、外部结果的各自身份 | 断线后查询原身份，不创建“重试”掩盖受理未知；新尝试需独立记录 |
| 来源与权限用途 | 提供方、适用授权范围、证据及非秘密引用 | 跨用途消费重新核对；材料文本不具有指令权限 |

### 数值、时间与空值

价格和金额以十进制定点语义传递、保存和比较，步长、乘数、币种、精度、舍入与生效时间一起解释；统计浮点不作为账本权威值。委托手数为正整数，方向/开平独立枚举；目标及净持仓数量按其语义可为有符号整数或0；权重、比率和百分数必须在字段旁标单位，禁止将0.2与20%混用。展示“—”须能查看未提供、不可计算、无权限、未完成或陈旧原因，不回填0。

时间区间统一描述为包含起点、不包含终点；按交易日选择的页面显示映射后的实际时段及夜盘归属。来源同刻多事件按已声明序号/规则排序，不猜测纳秒精度。严格历史消费时点不得早于所有必需输入实际可得时点；修订、LLM重处理和新发布不能改写旧实验已用内容。

<a id="handoff-contract"></a>

## 跨模块交接清单

| 交接 | 提交方必须提供 | 接收方必须检查 | 失败与返回 |
| --- | --- | --- | --- |
| 数据→情报 | 原文身份、来源/权限、原始字节位置、获取时间、解析状态 | 材料类型、外发许可、结构与处理预算 | 保留材料，返回缺项；不能生成虚构提取成功 |
| 数据/情报→分析 | 固定输入、字段/单位/时间、质量与发布/撤回状态 | 样本资格、时点模式、预热/标签边界 | 可保存受阻研究；不偷换数据或丢失排除项 |
| 分析→策略 | 定义、候选、样本/拟合、选择记录与限制 | 信号含义、可用时点、逻辑/仓位缺项 | 形成草稿，不直接产生订单或运行授权 |
| 策略→回测 | 固定包、参数、初始化、依赖与消费能力 | 数据/模型/算子、模拟时序、成本、风险完整 | 缺项定位到原规则/字段，不自动换算法 |
| 回测/实盘→评估 | 固定截点、模式、账户/事件/订单/资金事实、完整性 | 口径、期间、现金流、样本与可比性 | 部分可显示事实，不发布无依据最终结论 |
| 评估/策略→实盘 | 固定候选、独立验证/模拟证据、账户用途 | 授权、风险、唯一执行归属和实时条件 | 准备可保存但不启动；评估合格不等于交易授权 |
| 业务→系统调度 | 固定任务或明确范围规则、位置、用途/预算、日历 | 触发身份、重叠/漏触发政策和当前能力 | 触发与受理未知分开；不补发交易指令 |

交接确认仅说明接收方已保存该对象/请求，不表示计算或交易完成。展示相同对象的多个页面共享唯一业务状态；迟到回复不得覆盖更晚事实。已被引用的对象删除前展示依赖并拒绝破坏性删除，修改采用新内容身份；不支持旧持久格式时保留原文件并明确拒绝，不迁移或清空。

<a id="lifecycle-contract"></a>

## 状态与故障语义

| 对象 | 可观察过程 | 不能混为同一状态 |
| --- | --- | --- |
| 编辑草稿 | 编辑→校验失败/可固定→保存确认→固定；修改固定对象派生草稿 | 界面选中、保存成功、已发布、可执行 |
| 异步任务 | 草稿→提交中→已受理/受理未知→排队→运行→完整完成/部分结果/失败；取消请求独立等待停止 | 请求已收到、已取消、部分产物、最终完成 |
| 情报 | 原文→候选→待核验/冲突→发布；更正/撤回留下后继事件 | 模型返回、证据支持、人工确认、历史可得 |
| 实盘订单 | 意图→准入拒绝或可靠接纳→外部发送→未知/确认→部分成交/全部成交/撤成/拒绝 | 发送成功、柜台已接纳、撤单申请、已成交、额度释放 |
| 实例运行 | 准备→就绪→授权启动→运行→限制/暂停新增→核对→显式恢复或停止 | 窗口关闭、停止新意图、全部撤单、全部平仓、服务退出 |

提交前关键记录写入失败不得向外发送；提交后响应丢失显示原意图待核对，不自动再造意图。外部更正只追加可追溯修正。冻结账本、时点或执行归属不确定时，读取已知事实仍可用，但依赖不确定事实的新增风险操作阻断。停新增并不取消在途委托；查询、撤单、减仓都按各自有效信息和权限判断。

### 外部接口的最小证据

数据提供方须证明分页/范围语义、合约映射、单位/时区、修订、权限、限流及费用；柜台须证明账户环境、订单/成交关联、查询覆盖、终态、日切及结算口径；LLM提供方须说明模型身份、输入上限、费用和超时/拒答结构；节点须核验身份信任及实际能力。每类至少保留成功、缺权限、超限、输入不支持、连接中断和结果未知的脱敏记录。未验证行为明确列为不可用，不从一个提供方推断另一个。


<a id="decision-clock-contract"></a>

## 决策时钟与可得信息

规则、模型和混合策略采用固定策略包声明的完整bar边界作为决策时钟。情报事件、定时触发和账户反馈在取得后先记录，最早在不早于其可得时点的首个完整决策边界消费；事件发生时间不能用来提前消费。边界内多事件按可得时间、稳定来源流身份、同流顺序号、唯一变化/记录身份排序，并保存排序依据。来源顺序号仅在同一来源流内比较；同一事件的多次更正须有不同变化身份。跨来源的次级排序只保证可重复，不表示已知真实因果先后；来源没有顺序号时使用稳定变化身份，不得虚构精度或来源事实。

一次边界的业务次序为：

1. 纳入此前订单在该边界已可得的执行事实、账户变动及适用结算规则。历史bar模拟可在此确定刚结束bar的模拟成交和容量；外部交易仅接纳已有确切反馈，不假定订单必然终态。
2. 发布完整bar及截至该边界可得的事件，形成固定输入与账户状态截点。
3. 按固定策略与状态执行一次决策，记录输出目标、无动作、拒绝或失败及其原因。
4. 对新意图逐笔检查授权、规则、资金与在途占用；通过后才进入执行。历史模拟的新订单和撤单最早作用后续bar，不能倒灌刚结束bar。

模拟中使用下一bar开盘价作为价格假设，并不意味着开盘时已知该bar全量成交量。若容量使用完整bar成交量，成交确定和反馈须到该bar结束才对策略可见。具体撮合、费用和同刻顺序以[交易与账户模拟](../modules/backtest/simulation.md)为准。真实订单回报接纳、独立账户风控和紧急处置持续运行，不等待策略边界。

<a id="decision-evidence-contract"></a>

## 最小决策证据与可选数据归档

每次策略决策都应生成最小证据，包括产生订单、保持原目标、无动作和拒绝的情况。最低内容为：决策身份与边界、运行模式、输入值或可保留且可解析的不可变引用、实际可得时点及消费顺序、策略/模型/参数和风险规则内容身份、决策前状态及状态转移、输出目标或拒绝/失败原因、后续意图的关联身份。单独内容摘要不能代替可读取的输入；保存原始行情的开关不能关闭这些证据。

原始tick、消息全文或额外观测序列的长期归档是单独的容量与留存配置，可按数据模块规格关闭。最小决策证据须随引用它的研究、运行和账户记录保留；清理应检查依赖。证据保存失败时，依赖该证据的新增风险意图应被阻断，并保留最后可靠状态和恢复入口。已有委托仍按真实反馈核对；不得通过无记录旁路发送新的交易命令。

复核报告应区分“重算决策所需输入完整”“原始市场全过程完整”和“只能核对局部事实”。没有保存原始市场全过程时，不承诺重建所有市场微观事件，但必须能解释记录内每次策略决策的依据。

<a id="attended-operation-contract"></a>

## 运行监控与退出

真实量化交易按有人值守定义。启动前应确认监控位置、账户与执行节点，以及预先登记的柜台官方紧急处置渠道。关闭桌面窗口不自动停止服务、撤单或平仓；退出提示须展示运行实例、未决订单、持仓和必要下一步。

使用者离开监控前应暂停新增风险，并明确处理或接受显示的在途订单和持仓状态。无法通过本软件安全处置时，应按预登记渠道联系柜台或使用其正式工具；处置后返回核对真实账户事实，不自动恢复运行。通知送达不作为风控动作前提，也不把远程节点等同于无人值守交易承诺。采集、研究和资料维护等非交易计划任务仍可按其凭据与预算条件调度。

<a id="reference-protection-contract"></a>

## 引用、删除与研究连续性

被数据快照、固定策略、实验、报告、决策证据或账户记录引用的资料，不得破坏性删除。删除预览须展示有效依赖和阻断原因；使用者确认不能覆盖依赖保护。仅在依赖按各自合法生命周期解除、保留义务满足后，才允许重新预览并执行删除。修改固定内容产生新对象，名称变化不解除关联。

研究的选择历史应随实际样本、衍生输入和候选关系保留。复制研究、新建项目、重命名或派生快照不能把已用于筛选的数据重新标成未接触样本；无法证明独立性时应标记限制，并要求新的独立验证区间。方法选择、参数调整和因观察结果发生的改变均记录在研究选择历史中。
