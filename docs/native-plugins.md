# 原生插件 SDK

原生插件是可信的进程内动态库。Kernel 负责发现、版本检查、实例生命周期和装载句柄；服务按能力调用插件；供应商、算法和存储实现留在 `plugins/`。这不是沙箱，插件能使用宿主进程的权限，安装前应审查其来源。

## 当前交付边界

统一装载器接受 data、strategy、risk、execution、storage、tool 六类能力。当前正式开放并已接入生产调用链的能力是 `asterion.history.v1`（来源发现、合约目录、分钟线、日线）、`asterion.history.connection.v1`（连接配置与访问验证）及 `asterion.risk.pre-trade.v1`（交易前风控）。Tushare 已使用这一 ABI，由数据服务和下载工作进程动态加载，服务不再静态链接 Tushare。

订单限额风控已由 CTP 交易和回测动态装载。现有 CTP、策略、执行、文件存储和分析工具的业务接口仍使用仓库内 C++ 接口与静态目标，尚未全部迁移到动态 ABI。六类标签不代表已发布六套业务 SDK。实时订阅、交易执行、风险状态恢复等能力应结合现有用例分别定义类型化协议和契约测试后再迁移；不能把尚未实现的能力声明为可用。Terminal 的 TypeScript 工作区插件继续使用它自己的 UI 契约。

## 插件结构和构建

公共头文件位于 `bindings/plugin/include/asterion/plugin/`：

- `abi.h`：唯一导出入口、描述信息、能力目录、创建、启动、停止、销毁、查询。
- `history.h`：历史数据类型与函数表。
- `history_connection.h`：当前历史来源的凭据策略、请求限制与结构化访问验证。
- `risk.h`：期货交易前风险上下文、明确拒绝原因与同步评估函数表。
- `sdk.hpp`：可选的 C++ 异常屏障和配置读取助手。使用纯 C 时不需要它。

第三方只需要这些头文件和自身供应商依赖，不需要链接 Asterion Core、Protobuf、Node 或 UI。使用本机工具链编译为 `.dylib`，远程服务编译为 Linux x86_64 `.so`。一个动态库可以发布多个来源或多个能力；每种能力只声明确实实现的版本。

导出 `asterion_plugin_entry_v1(uint32_t host_abi, uint32_t host_struct_size)`，检查两个参数后返回只读 `AstPluginV1`。入口之外的符号应隐藏。描述信息必须包含稳定且唯一的插件 ID、实现版本、匹配的平台，以及非空能力目录。每个能力有稳定 ID、版本号和种类。

用 `create` 在插件内分配对象，用同一插件的 `destroy` 释放；失败必须清空输出指针。`query` 检查能力 ID、版本和函数表大小；未知能力返回 `AST_UNSUPPORTED`。`start` 可以失败，宿主随后调用 `stop` 清理部分启动状态。`stop` 必须可重复、安全且不抛异常；`destroy` 负责所有剩余资源。宿主持有实例期间动态库不会卸载。

ABI v1 精确匹配结构大小和版本，不兼容未知布局。新增能力可以发布新的函数表版本；破坏公共入口布局必须提升 ABI 主版本。实现版本用于标识实现，不能代替 ABI 检查。当前没有热替换或跨插件依赖解析；插件必须自包含其非系统依赖。更新需要停止服务及其工作进程、部署完整插件集合后重新启动。

## 历史数据契约

元数据实例通过空配置创建，可在未启动、没有凭据时调用 `sources`。实际访问实例传入 `source` 和 `credential` 两个设置；插件必须复制需要保留的值。宿主不记录凭据。凭据目前是至多 256 字节的单个字符串；需要多字段鉴权的供应商应在插件中定义该字符串的格式，不能把密码写入数据文件或错误信息。

每个来源声明独立 ID、显示名称、归一化版本、时区、时间戳含义、交易所、周期、请求速率上限和是否需要凭据。来源存在只说明接口可用，不表示账户已购买供应商权限。按来源声明分钟周期或日线，不能在同一来源混用不同时间轴；分钟与日线可以由同一动态库分别发布。

当前领域支持中国六个期货交易所、`Asia/Shanghai`、每分钟最多 500 次请求和 1–1440 分钟周期；日线周期编码为 0。超出当前领域能力明确拒绝，不能通过改写供应商代码伪装为已支持。

| 内容 | 约定 |
| --- | --- |
| 合约身份 | 交易所 / 小写品种 / 完整交割月 `YYYY-MM`，例如 `SHFE/cu/2024-03` |
| 供应商代码 | `source_instrument` 单独保存，不能替代统一身份 |
| 金额、价格、数量 | 有符号 int64，缩放因子 `10^8`；禁止 double 作为权威值 |
| 时间 | UTC 纳秒或 `YYYY-MM-DD` 交易日；查询起止均包含 |
| 时间戳语义 | `bar_end`、`provider_label` 或 `trading_day`；不能把未知标签伪装为收盘时刻 |
| 单位 | 金额为报价货币，数量/持仓量为手；供应商必须归一化 |
| 缺失值 | 通过可空指针或显式 presence 标记表达；不得补零冒充实际数据 |
| 返回 | 同步回调逐行交付，单次最多 10,000 行；按时间严格递增、唯一且处于查询范围内 |
| 生命周期 | 行字段只在回调期间有效，宿主立即复制；回调结束后不得异步继续发数据 |
| 取消 | 定期检查 `AstCancellation`；停止发出数据，返回 `AST_CANCELLED` |
| 回调失败 | 立即停止，并原样返回回调的非 OK 状态；不能吞错后返回成功 |

合约目录需要真实上市/退市日期、完整交割月和映射代码。分钟线可缺少交易日，不能从夜盘自然日猜测；日线必须携带真实交易日期。供应商的量纲、交易所别名、编码、复权或调整规则全部在适配器中处理。改变这些规则必须提升归一化版本，防止历史文件被当作同一语义继续写入。

请求速率由下载任务限制，来源声明的上限也必须在提交时检查；插件还需处理账户实际限额、网络超时和供应商错误。能力接口失败返回 `AstStatus`，服务转成跨进程 `ErrorCode`。任何 C ABI 函数以及回调都不得抛异常；C++ 实现使用 `noexcept` 和 `sdk::boundary`。异常内容不跨边界，以免泄露凭据或供应商响应。

## 安装、部署与验证

直接启动服务时使用绝对路径 `--plugin-directory /absolute/path/plugins`。默认目录是可执行程序旁的 `plugins/`，也可通过 `ASTERION_PLUGIN_DIRECTORY` 显式设置；不从工作目录或 PATH 搜索。目录中的所有 `.dylib` / `.so` 都按原生插件检查，不能在里面放供应商辅助共享库。重复 ID、符号缺失、ABI/平台不匹配、损坏模块和符号链接都会拒绝加载，不会悄悄跳过。

Terminal 开发构建将插件放在 `build/Debug/plugins/`，桌面构建复制到 `build/electron-resources/native/plugins/`。通过设置页创建数据服务时，NodeClient 只上传勾选的插件。Node Agent 将 SHA-256 集合写入服务配置，在子进程（`asterion-node-agent --inspect-plugin`）中读取插件描述，校验 ABI、平台和重复标识后安装到服务自己的版本目录；Agent 进程本身不加载插件。程序更新保留当前插件集合；插件变更通过独立命令保存。数据服务使用保存的集合，新下载及回测任务固定各自需要的动态库摘要。替换插件不会自动改写已有历史数据或正在运行的服务。发行包的 Linux 清单包含 Tushare 和订单限额风控动态库，打包校验覆盖其 SHA-256 和目标架构。

纯 C 契约夹具位于 `tests/native-plugin/`，仅用于测试，不能安装到生产目录。它独立编译，不链接 Core，可用于确认第三方编译流程和回调生命周期：

```sh
cmake -S tests/native-plugin -B build/plugin-sdk-check
cmake --build build/plugin-sdk-check
cmake --build build/Debug
ctest --test-dir build/Debug -R 'NativePlugin|NativeHistoryPlugin' --output-on-failure
```

实际供应商实现参考 `plugins/data/tushare/native_plugin.cpp`。新增来源不需要修改 Core、数据服务分支或 UI 来源列表：数据服务从插件读取能力，经 Protobuf 返回 Terminal。历史目录和存储仍使用统一身份、来源与归一化版本，供应商私有代码不进入通用路径规则。

服务配置为 v3，插件摘要集合参与服务修订号。

## 在 Terminal 中管理插件

进入「设置 → 插件」，原生插件目录显示动态库的真实 ID、实现版本、能力和可用状态。损坏的动态库单独显示错误；同 ID 的不同实现版本可以并存，每个服务只能显式选择其中一个；相同 ID 与版本出现多个副本时标记为冲突。目录只在打开页面或点击刷新时读取。

应用自带的插件（数据源、风控）是必需的：首次启动用全部自带插件创建本机数据服务，之后每个自带插件始终保留一个启用的版本，界面和 Terminal 原生层都拒绝把它清空。用户自行安装的插件是可选的，在插件管理页勾选。若本机尚无数据服务，也可以在插件管理页点击「创建数据服务」，默认同样包含全部自带插件。已保存为停止状态的数据服务不会因再次打开 Terminal 自动启动。

已有服务：停止服务及其工作进程，修改「启用的研究插件」，点击「保存插件配置」，再手动启动。保存带有服务修订号，其他窗口修改了服务后，旧清单会被拒绝。运行中、维护中、有未结束工作进程时不能保存。插件集合持久化到服务配置，配置保存本身不会启动服务。

更新服务程序不会重新扫描并启用所有插件，也不会切换插件版本。新版插件需要显式重新选择并保存。原始动态库从本机目录移除后，服务已经部署的版本仍保留；页面将它显示为「已部署版本（本机目录中不存在）」，允许保留或禁用。禁用数据源不删除其历史文件、任务或已上传的插件文件。

此页目前管理本机数据服务。远程服务仍保留自己的插件集合，程序更新也会保留该集合；远程插件选择界面和依赖解析尚未开放。可复用凭据连接独立管理，不进入插件启用清单。插件是可信代码，读取动态库的描述信息也会执行其装载初始化逻辑。

## 实现职责

Terminal 的 `native/plugin_catalog.*` 负责读取动态库目录和解析用户选择，以 `PluginCatalog`、`PluginArtifact`、`PluginSelection` 传递结果；JSON 仅在生成界面快照时构造。`native/node_snapshot.*` 负责节点状态的展示序列化，NodeClient 和部署命令直接使用类型化节点状态及服务种类。`ServiceDeployment`、`ServiceUpdate` 明确列出目标平台、程序、插件、目录和修订号，部署与升级共用 `native/service_programs.*` 的程序路径解析。

Agent 的 `plugin_artifacts.*` 负责摘要验证、重复身份检查和服务插件目录发布；`service_configuration.*` 负责服务配置的读取、持久化与修订号计算，进程对象仍由 Agent 持有。配置仍为 v3，修订号和插件目录摘要算法保持不变。Terminal 启动页和设置页共用 `src/host/native-plugins.ts` 的能力筛选与选择操作；服务端始终重新验证选择。

## 数据源凭据

历史数据插件可实现 `bindings/plugin/include/asterion/plugin/history_connection.h` 中的 `asterion.history.connection.v1` 能力。接口按当前真实用例声明凭据的中英文标签、是否必填、长度上限、是否允许本机保存，以及请求速率的默认值和上限。宿主不按 Tushare 名称猜测设置。密码类凭据必须禁止保存。未实现此能力的插件仍可通过历史能力接收任务凭据，但不能保存凭据。

一个供应商（一个数据源插件）只有一份凭据，它的所有数据源共用。「设置 → 数据源」按供应商列出卡片：是否已设置、每分钟请求上限和验证结果。保存后立即验证，按数据源分别报告合约目录和历史接口的成功、无效凭据、权限不足、限流、网络错误或失败；成功只说明接口接受请求，不保证某个时间范围有数据。凭据和请求上限必须同时满足该供应商各数据源中最严格的限制。

下载页不选择凭据：供应商已设置凭据时直接使用，并采用其请求上限；未设置时为本次查询和下载临时输入，提交后清空。

设置保存在本机 Agent 目录的 `data-providers/<插件 ID>.json`，只含请求上限和是否记住。默认凭据只驻留当前 Terminal 进程内存，关闭应用后需重新输入。用户勾选保存且插件允许时，令牌保存在 macOS 登录钥匙串（服务名 `me.asterion.terminal.data-connection`，仅本机、解锁时可用），由签名稳定的辅助程序 `asterion-keychain` 读写。清除会同时删除钥匙串条目。界面快照不返回凭据。

提交任务时解析并复制当时的凭据，任务使用自己的受保护凭据文件。更改或清除供应商凭据不影响已提交任务；同一任务 ID 重复提交也不替换原凭据。令牌过期后的旧任务不会自动改用新凭据，应显式建立新任务。该设置属于本机 Terminal，不向远程节点自动同步。


### 安装、版本选择与卸载

设置页的「安装原生插件」先说明动态库会执行本机代码，用户确认信任后选择 `.dylib` 文件。预览显示 ID、实现版本、能力及 SHA-256；确认安装时再次验证摘要、ABI 和当前平台，然后原子发布到本机 Agent 目录的 `plugins/`。不修改应用包内自带插件，也不覆盖同 ID 同版本。并存版本必须使用不同实现版本号。

插件目录合并显示应用自带版本和用户安装版本。勾选同 ID 的另一个可用版本会替换本次编辑中的选择，保存仍要求服务停止且修订号一致。同一自带插件另有用户安装的版本时，默认启用自带版本，用户可改选另一版本，但不能两个都不选。无原始文件的已部署版本仍显示其摘要；切换时应显式取消保留它。

卸载只提供给用户安装的副本，确认界面说明保留已部署服务、任务和历史数据。损坏的用户副本仍可根据已查看的文件名与当前摘要移除；查看后再次变化的文件会拒绝删除。卸载不会停止服务，也不会删除 Agent 已保存的服务副本；要停用该插件，需另行停止服务、取消选择并保存。应用自带插件不能停用，也不直接删除安装包文件。当前不自动下载依赖、更新插件或解析第三方动态库依赖。


### 任务固定插件版本

下载任务清单 v3 记录创建时数据源动态库的 SHA-256。Agent 从任务派发消息取得这个摘要，为工作进程单独装载任务固定的副本；不能用服务当前选择覆盖它。工作进程领取任务后再次校验实际装载摘要。切换服务版本、卸载用户目录副本、任务重试和服务重启都不修改该绑定。缺少或损坏固定副本时拒绝执行，不回退到另一个版本。

服务插件清单描述新任务可使用的来源；历史任务可以继续使用已保留的旧副本，这与禁用新任务的数据源分别处理。

## 交易前风控动态插件

`risk.h` 的 `asterion.risk.pre-trade.v1` 是同步、无内部账户状态的评估契约。宿主提供期货身份、报价货币、价格与数量步长、合约乘数、委托、开平仓方向、总持仓、未成交开仓数量及活动委托数。所有 Decimal 值均为缩放 `10^8` 的 int64。账户和未成交委托仍由统一执行链管理，插件不能自行提交交易。

`evaluate` 必须返回 `AST_OK` 并明确写入一个已定义决策。错误状态、未写输出、未知决策以及未启动实例均不能放行。插件异常必须在 C ABI 内转成状态码。当前实际实现为 `asterion.risk.order-limits`，创建参数必须显式包含 `max_order_quantity`、`max_gross_quantity` 和 `max_working_orders`；不默认补全，也不静态回退。示例见 `plugins/risk/order-limits/native_plugin.cpp`，故障契约测试使用独立编译的纯 C 夹具。

数据服务可在插件管理页启用风控能力；提交回测时必须恰好有一个风控插件。任务清单 v3 保存 `risk_artifact`，任务目录保存 `risk-plugin.dylib`（Linux 为 `.so`）；Agent 按固定摘要启动工作程序，结果复核使用任务自有副本。读取已缓存结果也会重新校验算法文件，损坏或缺失时明确拒绝。

创建 CTP 交易账户的服务时部署随应用提供的订单限额动态库。创建交易记录时将副本保存到记录目录的 `plugins/`，头部记录 `risk_artifact`；恢复只使用该副本，不使用当前默认版本。CTP 交易记录的日志引擎为 `asterion.live-futures.v5`；回测引擎为 v8。插件升级、卸载原始安装文件不会替换已有账本和任务的算法。

当前 CTP 交易和回测仍使用订单限额的既有配置表单，没有开放任意风控配置编辑器或多风控组合。该 ABI 也不声明有状态风控的快照能力；新增算法需要围绕实际配置和恢复语义扩展契约。

## 其他现有插件的迁移顺序

现有代码检查后的下一步顺序如下；这里记录实际调用与恢复约束，不声明尚未实现的 ABI。

| 插件 | 当前入口 | 动态化前必须闭合的边界 |
| --- | --- | --- |
| SMA 策略 | `StrategyPort::on_bar`；回测直接调用 `MovingAverage` | 迁移时需要先定义策略状态的事务契约；不能把共享动态实例的复制当作状态快照 |
| 存储 | `SqliteJournal`、任务索引、历史数据仓库 | 明确锁、原子发布、读取校验与失败恢复的所有权；不能因切换后端自动搬迁现有数据 |
| CTP 与执行 | 行情订阅、授权与统一执行链 | 供应商回调寿命、连接取消、订单归属与恢复；账户授权和风控始终由统一执行链强制执行 |
